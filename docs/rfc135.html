Response to NWG/RFC #110

RFC 135

NWG/RFC 110への返答

Abstract

概要

(Conventions for Using an IBM 2741 Terminal as a User Console for Access to Network Server Hosts)

（ネットワークのサーバーホストにアクセスするためのユーザーコンソールとしてIBM 2741端末を使うための規約）

I would like to propose the following conventions to replace the ones proposed in RFC #110. The original conventions suffer from lack of consideration of the correspondence 2741 and what I feel are inconsistencies and considerable difficulty of use. (The 2741 terminal with correspondence keyboard does not have all of the standard characters, notably:

RFC #110で提案された規約に代わるものとして、次の規約を提案したいと思います。元の規約は、コレスポンデンス（correspondence）型の2741への配慮が欠けており、また私の見るところ、一貫性がなく、使うのがかなり難しいという問題があります。（コレスポンデンスキーボードを備えた2741端末には、標準的な文字のすべてがあるわけではありません。特に次の文字がありません。

      less than       <
      greater than    >
      logical not    [1]
      vertical bar    |

      less than       <
      greater than    >
      logical not    [1]
      vertical bar    |

Thus we must not use any of these characters in our conventions if we wish to support the correspondence 2741.)

したがって、コレスポンデンス型の2741をサポートしたいのであれば、規約ではこれらの文字をまったく使ってはいけません。）

The dedication of certain characters to special functions involves a trade-off: the convenience of having the function as a single key versus the inconvenience of having to use two keys to enter the character as data. I believe that only two of the special functions listed in RFC #110 justify the dedication of a key: the "character escape" function and the "character delete" function. For the "character escape" function I recommend the cent sign [2], as this character is on both the regular and correspondence 2741 terminals and is not in the ASCII character set. For the "character delete" function I recommend the backspace key for obvious reasons. While there is some need to be able to enter the character "backspace" (as for underscoring output etc.,) I feel that the trade-off mentioned above clearly indicates a single key "character delete" would be much more valuable than a single key "backspace" and a two key "character delete."

特定の文字を特殊機能に割り当てることには、トレードオフがあります。その機能を1つのキーで使える便利さと、その文字をデータとして入力するのに2つのキーを使わなければならない不便さとのトレードオフです。RFC #110に挙げられた特殊機能のうち、キーを割り当てるに値するのは「文字エスケープ（character escape）」機能と「文字削除（character delete）」機能の2つだけだと考えます。「文字エスケープ」機能にはセント記号[2]を推奨します。この文字は通常型とコレスポンデンス型の両方の2741端末にあり、ASCII文字集合には含まれないからです。「文字削除」機能には、理由は明らかなのでバックスペースキーを推奨します。「バックスペース」という文字を入力できる必要も多少はありますが（出力に下線を引く場合など）、上で述べたトレードオフからすると、1つのキーで「文字削除」ができるほうが、1つのキーで「バックスペース」を入力でき、「文字削除」に2つのキーを使うよりもはるかに価値があるのは明らかだと思います。

For the other special functions I recommend two key combinations, consisting of "character escape" [2] and a key to define the function. These are summarized below:

その他の特殊機能には、「文字エスケープ」[2]と機能を決めるキーとの、2つのキーの組み合わせを推奨します。以下にまとめます。

      character escape        [2]
      character delete        backspace
      system delete           [2]$
      line delete             [2]# or [2]#NL
      logical line end        [2];
      line continuation       [2]NL
      ASCII control           [2]@

      character escape        [2]
      character delete        backspace
      system delete           [2]$
      line delete             [2]# or [2]#NL
      logical line end        [2];
      line continuation       [2]NL
      ASCII control           [2]@

The option in "line delete" is to allow the user to enter a new line (NL) immediately after the "line delete" to line up margins without entering a null line; to enter a null line after a "line delete" would require two NL characters.

「行削除（line delete）」の選択肢は、ユーザーが「行削除」の直後に改行（NL）を入力して、空行を入力することなく左端をそろえられるようにするためのものです。「行削除」の後に空行を入力するには、NL文字が2つ必要になります。

The two new functions defined above, "line continuation" and "ASCII control," are used as follows. The "line continuation" is used to enter a line which is longer than the 2741 carriage (or the margin placement) will permit. It can be looked on as the complement of the "logical line end" in that is allows you to enter one logical line on several physical lines.

上で新しく定義した2つの機能、「行継続（line continuation）」と「ASCII制御（ASCII control）」は次のように使います。「行継続」は、2741のキャリッジ（またはマージンの設定）で許される長さよりも長い行を入力するために使います。1つの論理行を複数の物理行で入力できるという点で、「論理行末（logical line end）」を補完するものと見ることができます。

The use of the "ASCII control" function requires some background. There are of course many characters in ASCII which are keyed as combinations of "control" and another key. The "character escape" function may be used to handle these control characters as follows: a "character escape" followed by a letter will be the equivalent of the ASCII "control" "letter", written as Xc (where X is the letter). This will greatly simplify the conventions for users, as they will simply key "[2]A" where they are used to using Ac and so forth. For completeness, however, there needs to be a way to key the additional control characters which require both "control" and "shift" in addition to a letter (such as ESC, which is SHIFT Mc). Further it is desirable that a more mnemonic system be provided for the non-Teletype user, who knows he wants a LF but does not know that it is a Jc. To satisfy both of these needs I recommend the "ASCII control" special function, which is used to enter any of the ASCII control character as "[2]@" followed by the standard two or three character abbreviation. Thus "escape" would be [2]@ESC, "line feed" would be [2]@LF, and so forth. The use of the variable length abbreviation does not introduce any ambiguity, although from an implementation standpoint it may be advantageous to use the two character abbreviation proposed in RFC #110.

「ASCII制御」機能を使うには、少し背景知識が必要です。言うまでもなく、ASCIIには「コントロール」と別のキーとの組み合わせで入力する文字がたくさんあります。「文字エスケープ」機能を使えば、これらの制御文字を次のように扱えます。「文字エスケープ」の後に英字が続くと、ASCIIの「コントロール」＋「英字」と同等になり、これをXc（Xは英字）と書きます。こうすればユーザーにとって規約がずっと簡単になります。いつもAcなどと入力しているところで、単に「[2]A」と入力すればよいからです。ただし完全を期すには、英字に加えて「コントロール」と「シフト」の両方を必要とするその他の制御文字（SHIFT McであるESCなど）を入力する方法が必要です。さらに、LFを入力したいことはわかっていても、それがJcであることは知らないテレタイプ（Teletype）以外の利用者のために、もっと覚えやすい方式を用意するのが望ましいです。これら両方の要求を満たすために、「ASCII制御」特殊機能を推奨します。これは、「[2]@」に続けて標準的な2文字または3文字の略号を入力することで、任意のASCII制御文字を入力するのに使います。したがって「エスケープ」は[2]@ESC、「ラインフィード」は[2]@LFなどとなります。可変長の略号を使ってもあいまいさは生じませんが、実装の観点からは、RFC #110で提案された2文字の略号を使うほうが有利かもしれません。

Finally we must be able to enter the eight ASCII graphics which do not appear on either 2741 terminal, as well as the "cent sign" and "backspace" themselves (without their special functions). For these I recommend the following:

最後に、どちらの2741端末にもない8つのASCII図形文字と、（特殊機能としてではなく）「セント記号」と「バックスペース」そのものを入力できなければなりません。これらには次のものを推奨します。

      [2](            for     [
      [2])            for     ]
      [2]6            for     {
      [2]9            for     }
      [2]/            for     \
      [2]'            for     '
      [2]"            for     ^
      [2]-            for     ~
      [2][2]          for     [2]
      [2]backspace    for     backspace

      [2](            for     [
      [2])            for     ]
      [2]6            for     {
      [2]9            for     }
      [2]/            for     \
      [2]'            for     '
      [2]"            for     ^
      [2]-            for     ~
      [2][2]          for     [2]
      [2]backspace    for     backspace

Note that the characters "<" and ">" do not appear on the correspondence 2741 and hence should not be used.

「<」と「>」の文字はコレスポンデンス型の2741にはないため、使うべきではないことに注意してください。
