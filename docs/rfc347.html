RFC 347

Echo Process

RFC 347

エコープロセス

Abstract

概要

I suggest that for debugging and measurement purposes those hosts which are willing implement an "Echo" process. This echo process would listen for a request for connection and execute the Initial Connection Protocol (ICP) as specified in NIC 7104 the "Current Network Protocols" notebook. Upon completion of the ICP the echo process would wait for data from the network. When the data is received from the network it is echoed at once, (and the buffer space is re-allocated). By echoed I mean that the data received is sent back over the network, bit for bit with no modification by the echo process. The echo process is terminated by closing the network connections. Note that BBN-TENEX has had such an echo process available for use for a long time.

デバッグと測定のために、その意思のあるホストは「Echo」プロセスを実装することを私は提案します。このエコープロセスは、接続要求を待ち受け、NIC 7104の「Current Network Protocols」ノートに規定されたInitial Connection Protocol（ICP）を実行します。ICPが完了すると、エコープロセスはネットワークからのデータを待ちます。ネットワークからデータを受信すると、ただちにそれをエコーします（そしてバッファー領域を再割り当てします）。ここでエコーするとは、受信したデータを、エコープロセスによる変更を一切加えずに、1ビットも違えずネットワーク経由で送り返すことを意味します。エコープロセスは、ネットワーク接続を閉じることで終了します。なお、BBN-TENEXでは、このようなエコープロセスが以前から利用可能になっています。
