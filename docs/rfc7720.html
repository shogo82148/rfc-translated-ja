RFC 7720

DNS Root Name Service Protocol and Deployment Requirements

RFC 7720

DNSルートネームサービスのプロトコルと展開の要件

Abstract

概要

The DNS root name service is a critical part of the Internet architecture. The protocol and deployment requirements for the DNS root name service are defined in this document. Operational requirements are out of scope.

DNSルートネームサービスは、インターネットアーキテクチャーの重要な部分です。この文書では、DNSルートネームサービスのプロトコルと展開の要件を定義します。運用上の要件は対象外です。

1. Introduction

1. はじめに

[RFC2870] discusses protocol and operational requirements for root name servers for the Internet's domain name system (DNS) protocol [RFC1035]. Since its publication, both protocol and operational requirements have evolved. It makes more sense now to separate the two sets of requirements into two separate documents. This document only defines the protocol requirements and some deployment requirements. The operational requirements that were defined in RFC 2870 have been removed. Operational requirements are now defined by the Root Server System Advisory Committee of ICANN and are documented in [RSSAC-001].

[RFC2870]は、インターネットのドメインネームシステム（DNS）プロトコル[RFC1035]のルートネームサーバーに対するプロトコルと運用の要件について論じています。その発行以来、プロトコルの要件と運用の要件はどちらも進化してきました。現在では、この2組の要件を2つの別々の文書に分けるほうが理にかなっています。この文書では、プロトコルの要件と、展開の要件の一部だけを定義します。RFC 2870で定義されていた運用上の要件は削除されました。運用上の要件は現在、ICANNのルートサーバーシステム諮問委員会（Root Server System Advisory Committee）によって定義され、[RSSAC-001]に文書化されています。

The root servers are authoritative servers of the unique [RFC2826] root zone (".") [ROOTZONE]. They currently also serve the root-servers.net zone. Some also serve the zone for the .arpa top-level domain [ARPAZONE] [RFC3172]. This document describes the external interface of the root name servers from a protocol viewpoint of the service. It specifies basic requirements for the Internet that DNS clients meet when interacting with a root name service over the public Internet.

ルートサーバーは、一意な[RFC2826]ルートゾーン（「.」）[ROOTZONE]の権威サーバーです。ルートサーバーは現在、root-servers.netゾーンも提供しています。一部のルートサーバーは、.arpaトップレベルドメインのゾーン[ARPAZONE] [RFC3172]も提供しています。この文書では、サービスのプロトコルの観点から、ルートネームサーバーの外部インターフェイスを説明します。また、DNSクライアントが公衆インターネット経由でルートネームサービスとやり取りするときに満たされる、インターネットにとっての基本的な要件を規定します。

The keywords MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, MAY, and OPTIONAL, when they appear in this document, are to be interpreted as described in BCP 14, [RFC2119].

この文書において、キーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、「要求されています（REQUIRED）」、「することになります（SHALL）」、「することはありません（SHALL NOT）」、「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、「推奨されます（RECOMMENDED）」、「してもよいです（MAY）」、「選択できます（OPTIONAL）」が現れた場合は、BCP 14 [RFC2119]で説明されているように解釈されるものとします。

2. Protocol Requirements

2. プロトコルの要件

This section describes the minimum high-level protocol requirements. Operative details are documented in [RSSAC-001].

このセクションでは、高レベルのプロトコルの最低限の要件を説明します。運用の詳細は[RSSAC-001]に文書化されています。

The root name service:

ルートネームサービスは次のとおりです。

  • MUST implement core DNS [RFC1035] and clarifications to the DNS [RFC2181].
  • MUST support IPv4 [RFC791] and IPv6 [RFC2460] transport of DNS queries and responses.
  • MUST support UDP [RFC768] and TCP [RFC793] transport of DNS queries and responses.
  • MUST generate checksums when sending UDP datagrams and MUST verify checksums when receiving UDP datagrams containing a non-zero checksum.
  • MUST implement DNSSEC [RFC4035] as an authoritative name service.
  • MUST implement extension mechanisms for DNS (EDNS(0)) [RFC6891].
  • コアDNS[RFC1035]と、DNSの明確化[RFC2181]を実装しなければなりません（MUST）。
  • DNSの問い合わせと応答の転送に、IPv4[RFC791]とIPv6[RFC2460]をサポートしなければなりません（MUST）。
  • DNSの問い合わせと応答の転送に、UDP[RFC768]とTCP[RFC793]をサポートしなければなりません（MUST）。
  • UDPデータグラムを送信するときにはチェックサムを生成しなければなりません（MUST）。また、ゼロでないチェックサムを含むUDPデータグラムを受信するときにはチェックサムを検証しなければなりません（MUST）。
  • 権威ネームサービスとして、DNSSEC[RFC4035]を実装しなければなりません（MUST）。
  • DNSの拡張メカニズム（EDNS(0)）[RFC6891]を実装しなければなりません（MUST）。

3. Deployment Requirements

3. 展開の要件

The root name service:

ルートネームサービスは次のとおりです。

  • MUST answer queries from any entity conforming to [RFC1122] with a valid IP address.
  • MUST serve the unique [RFC2826] root zone [ROOTZONE].
  • [RFC1122]に準拠し、有効なIPアドレスを持つあらゆる主体からの問い合わせに応答しなければなりません（MUST）。
  • 一意な[RFC2826]ルートゾーン[ROOTZONE]を提供しなければなりません（MUST）。

4. Security Considerations

4. セキュリティーに関する考慮事項

This document does not specify a new protocol. However, the root name service is a key component of the Internet architecture and play a key role into the overall security of the Internet [RFC2826]. Specific security considerations on the DNS protocols are discussed in their respective specifications. The security considerations on the operational side of the root name servers are discussed in [RSSAC-001].

この文書は新しいプロトコルを規定するものではありません。しかし、ルートネームサービスはインターネットアーキテクチャーの重要な構成要素であり、インターネット全体のセキュリティーにおいて重要な役割を果たします[RFC2826]。DNSプロトコルに関する個別のセキュリティーの考慮事項は、それぞれの仕様で論じられています。ルートネームサーバーの運用面でのセキュリティーの考慮事項は、[RSSAC-001]で論じられています。
