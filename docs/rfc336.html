RFC 336

Level 0 Graphic Input Protocol

RFC 336

レベル0グラフィック入力プロトコル

Abstract

概要

At its meeting on April 16-18 the network Graphics working group began to consider the definition of levels of protocol for graphic Input Protocol. The following describes the Level 0 graphics input protocol.

4月16日から18日にかけて開かれた会合で、ネットワークグラフィックスワーキンググループは、グラフィック入力プロトコル（graphic Input Protocol）のプロトコルレベルの定義について検討を始めました。以下では、レベル0のグラフィックス入力プロトコルについて説明します。

The philosophy guiding the establishment of this protocol is the same as suggested in RFC #178, "Network Graphic Attention Handling." Briefly, all input will be described by type, origin, and length, followed by the actual data.

このプロトコルを策定するうえでの指針となる考え方は、RFC #178「Network Graphic Attention Handling」で提案されたものと同じです。簡単に言うと、すべての入力は種類、発生元、長さによって記述され、その後に実際のデータが続きます。

Only two types of input are defined at Level 0: text and simple position.

レベル0で定義する入力の種類は、テキストと単純な位置の2つだけです。

Text Input

テキスト入力

Text input will be conveyed in the following format:

テキスト入力は次の形式で伝えます。

     TEXTIN : DEVICE : COUNT: Text String

     TEXTIN : DEVICE : COUNT: Text String

TEXTIN is a protocol code indicating the nature of this input string. For the present this code is defined to be 1.

TEXTINは、この入力文字列の性質を示すプロトコルコードです。現時点では、このコードは1と定義します。

DEVICE is a code indicating the device from which the input originated. The following codes are presently defined:

DEVICEは、入力の発生元のデバイスを示すコードです。現在、次のコードが定義されています。

  • 0 - unspecified device
  • 1 - primary keyboard
  • 2 - tablet
  • 3 - mouse
  • 4 - joystick
  • 5 - lightpen
  • 6 - cursor
  • 7 - keyset
  • 8 - mouse & keyset
  • 0 - 特定されていないデバイス
  • 1 - 主キーボード
  • 2 - タブレット
  • 3 - マウス
  • 4 - ジョイスティック
  • 5 - ライトペン
  • 6 - カーソル
  • 7 - キーセット
  • 8 - マウスとキーセット

Count is an integer number indicating the number of characters (bytes) which follow.

Countは、後に続く文字（バイト）の数を示す整数です。

Text String is a string of "Count" bytes of characters in network ASCII.

Text Stringは、ネットワークASCIIの文字からなる「Count」バイトの文字列です。

Position Input

位置入力

Simple position data will be conveyed in the following format:

単純な位置データは次の形式で伝えます。

     POSIT : DEVICE : COUNT : x : y

     POSIT : DEVICE : COUNT : x : y

POSIT is a protocol code indicating that this string contains position data. For the present this code is defined to be 2.

POSITは、この文字列に位置データが含まれていることを示すプロトコルコードです。現時点では、このコードは2と定義します。

DEVICE is a code indicating the input device on which this data was generated. The codes are as defined above.

DEVICEは、このデータが生成された入力デバイスを示すコードです。コードは前述の定義のとおりです。

COUNT is an integer number indicating the number of bytes of data which follow. This includes data for both x and y coordinates. Thus, the number of bytes of x coordinate data is COUNT divided by 2. At level 0, COUNT should always be 4, since at this level all coordinates are expressed in 2 bytes of data.

COUNTは、後に続くデータのバイト数を示す整数です。これにはx座標とy座標の両方のデータが含まれます。したがって、x座標データのバイト数はCOUNTを2で割った値になります。レベル0では、すべての座標を2バイトのデータで表すので、COUNTは常に4であるべきです。

x and y coordinate data are represented as signed fractions in the same fashion that position data is represented in the Level 0 graphic output protocol.

x座標とy座標のデータは、レベル0のグラフィック出力プロトコルで位置データを表すのと同じ方法で、符号付きの小数として表します。

It should be emphasized that input data from a level 0 graphics user which is not in a format described above should be sent on a different link than the graphics input link. This may be desirable for certain applications to avoid the overhead of the protocol.

レベル0のグラフィックスユーザーからの入力データのうち、上で説明した形式に従わないものは、グラフィックス入力リンクとは別のリンクで送るべきであることを強調しておきます。用途によっては、プロトコルのオーバーヘッドを避けるためにこれが望ましい場合もあります。
