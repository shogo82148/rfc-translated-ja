RFC 7017

IMAP Access to IETF Email List Archives

RFC 7017

IETFメーリングリストのアーカイブへのIMAPアクセス

Abstract

概要

The IETF makes heavy use of email lists to conduct its work. This often involves accessing the archived history of those email lists. Participants would like to have the ability to browse and search those archives using standard IMAP clients. This memo captures the requirements for providing a service that would allow such browsing and searching, and it is intended as input to a later activity for the design and development of such a service.

IETFは、その作業を進めるためにメーリングリストを多用しています。そのため、メーリングリストのアーカイブされた履歴にアクセスすることがよくあります。参加者は、標準的なIMAPクライアントを使ってこれらのアーカイブを閲覧・検索できることを望んでいます。このメモは、そのような閲覧と検索を可能にするサービスを提供するための要件をまとめたものであり、そのようなサービスを設計・開発する後の活動への入力となることを意図しています。

1. Introduction

1. はじめに

The IETF makes heavy use of email lists to conduct its work. This often involves accessing the archived history of those email lists. Requirements for improved web-based browsing and searching of these archives are captured in [RFC6778]. Participants would like to have the ability to browse and search those archives using standard IMAP clients. This memo captures the requirements for providing a service that would allow such browsing and searching, and it is intended as input to a later activity for the design and development of such a service.

IETFは、その作業を進めるためにメーリングリストを多用しています。そのため、メーリングリストのアーカイブされた履歴にアクセスすることがよくあります。これらのアーカイブをWebベースで閲覧・検索する機能を改善するための要件は、[RFC6778]にまとめられています。参加者は、標準的なIMAPクライアントを使ってこれらのアーカイブを閲覧・検索できることを望んでいます。このメモは、そのような閲覧と検索を可能にするサービスを提供するための要件をまとめたものであり、そのようなサービスを設計・開発する後の活動への入力となることを意図しています。

2. Requirements for IMAP Access to Archived IETF Lists

2. アーカイブされたIETFメーリングリストへのIMAPアクセスの要件

Many participants would prefer to access the list archives using IMAP [RFC3501]. Providing this access while meeting the following requirements will likely require an IMAP server with specialized capabilities.

多くの参加者は、IMAP[RFC3501]を使ってメーリングリストのアーカイブにアクセスしたいと考えています。次の要件を満たしつつこのアクセスを提供するには、特別な機能を備えたIMAPサーバーが必要になるでしょう。

  • The system should expose the archive using an IMAP interface, with each list represented as a mailbox.
  • This interface must work with standard IMAP clients.
  • The interface should allow users that have provided credentials to each have their own read/unread marks for messages. Allowing other annotation is desirable. The implementation should consider taking advantage of the IMAP extensions for ANNOTATE [RFC5257] and METADATA [RFC5464].
  • It must be possible for administrators to set per-user storage quotas, limiting the space a user can consume with annotations.
  • The interface must not allow users to modify the underlying message or metadata other than the read/unread marks and annotations described above. Specifically, users must not be able to delete or insert messages, or move them between mailboxes in the archive. (Clients will, of course, be able to make local copies of messages from the archive.)
  • The interface must have server-side searching enabled and should scale to support multiple simultaneous extensive searches. The server should provide the enhanced search capabilities described in [RFC6778]. The implementation should consider taking advantage of the extensions defined for IMAP SORT and THREAD [RFC5256], multimailbox search [RFC6237], and fuzzy search [RFC6203].

  • When the system requires credentials, it must use the datatracker's authentication system.

    • While the vast majority of archived lists have an open access policy, some archived lists have restricted archives. The system must make it possible to limit access to a restricted archive based on login credentials.
    • The system must allow access to open archives with or without providing credentials. Specifically, the system will allow anonymous access using the Simple Authentication and Security Layer (SASL) ANONYMOUS mechanism [RFC4505] or a LOGIN command with a special username (such as "anonymous") determined by the administrator.
  • システムは、各メーリングリストを1つのメールボックスとして表すIMAPインターフェイスを使って、アーカイブを公開すべきです。
  • このインターフェイスは、標準的なIMAPクライアントで動作しなければなりません。
  • このインターフェイスは、クレデンシャル（credential）を提示したユーザーがそれぞれ、メッセージの既読・未読マークを個別に持てるようにすべきです。その他の注釈（annotation）を付けられることが望ましいです。実装は、ANNOTATE[RFC5257]とMETADATA[RFC5464]のIMAP拡張を活用することを検討すべきです。
  • 管理者は、ユーザーごとのストレージクォータを設定して、ユーザーが注釈で消費できる容量を制限できなければなりません。
  • このインターフェイスは、上で述べた既読・未読マークと注釈以外に、元のメッセージやメタデータをユーザーが変更できるようにしてはなりません。具体的には、ユーザーがメッセージを削除したり挿入したり、アーカイブ内のメールボックス間で移動したりできてはなりません（もちろん、クライアントはアーカイブのメッセージのローカルコピーを作成できます）。
  • このインターフェイスは、サーバー側の検索を有効にしなければならず、複数の大規模な検索を同時に処理できるようにスケールすべきです。サーバーは、[RFC6778]で説明されている拡張検索機能を提供すべきです。実装は、IMAPのSORTとTHREAD[RFC5256]、複数メールボックスの検索[RFC6237]、あいまい検索[RFC6203]のために定義された拡張を活用することを検討すべきです。

  • システムがクレデンシャルを要求する場合は、datatrackerの認証システムを使用しなければなりません。

    • アーカイブされたメーリングリストの大多数はオープンなアクセスポリシーを持っていますが、一部のメーリングリストではアーカイブが制限されています。システムは、ログインのクレデンシャルに基づいて、制限されたアーカイブへのアクセスを制限できるようにしなければなりません。
    • システムは、クレデンシャルの提示の有無にかかわらず、オープンなアーカイブへのアクセスを許可しなければなりません。具体的には、システムは、SASL（Simple Authentication and Security Layer）のANONYMOUSメカニズム[RFC4505]、または管理者が決めた特別なユーザー名（"anonymous"など）を指定したLOGINコマンドによる匿名アクセスを許可します。

3. Internationalized Address Considerations

3. 国際化アドレスに関する考慮事項

The implementation should anticipate internationalized email addresses as discussed in the following three documents: [RFC6532], [RFC6531], and [RFC6855]. There is no firm requirement at this time.

実装は、次の3つの文書で議論されている国際化電子メールアドレスを想定しておくべきです：[RFC6532]、[RFC6531]、[RFC6855]。現時点では確定した要件はありません。

4. Security Considerations

4. セキュリティーに関する考慮事項

Allowing IMAP as an interface for browsing and searching the archives of IETF email lists does not affect the security of the Internet in any significant fashion.

IETFメーリングリストのアーカイブを閲覧・検索するためのインターフェイスとしてIMAPを許可しても、インターネットのセキュリティーに大きな影響はありません。

Searching can be input/output (I/O) and CPU intensive. Clients that make local copies of all messages in a mailbox can also present an I/O burden, particularly when synchronizing for the first time. The implementors of this interface should consider the potential for maliciously crafted searches attempting to consume a damaging amount of resources. The implementors should consider the potential for denial-of-service attacks through making many connections to the interface. The implementors should consider ways to rate limit I/O due to making local copies of messages.

検索は、入出力（I/O）とCPUの負荷が高くなる場合があります。メールボックス内のすべてのメッセージのローカルコピーを作成するクライアントも、特に初回の同期時には、I/Oの負担となる可能性があります。このインターフェイスの実装者は、悪意を持って作成された検索が有害な量のリソースを消費しようとする可能性を考慮すべきです。実装者は、インターフェイスに多数の接続を張ることによるサービス拒否攻撃の可能性を考慮すべきです。実装者は、メッセージのローカルコピーの作成によるI/Oをレート制限する方法を検討すべきです。

Storing read/unread marks and other annotations requires potentially unbounded storage space. The implementors of this interface should consider the potential for maliciously crafted annotations attempting to consume a damaging amount of storage space. The implementors should consider making it easy to alert the administrator when a user begins consuming exceptional amounts of space.

既読・未読マークやその他の注釈を保存するには、潜在的に際限のないストレージ容量が必要です。このインターフェイスの実装者は、悪意を持って作成された注釈が有害な量のストレージ容量を消費しようとする可能性を考慮すべきです。実装者は、ユーザーが例外的な量の容量を消費し始めたときに、管理者へ簡単に警告できるようにすることを検討すべきです。
