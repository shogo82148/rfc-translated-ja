RFC 8734

Elliptic Curve Cryptography (ECC) Brainpool Curves for Transport Layer Security (TLS) Version 1.3

RFC 8734

トランスポート層セキュリティー（TLS）バージョン1.3のための楕円曲線暗号（ECC）Brainpool曲線

Abstract

概要

Elliptic Curve Cryptography (ECC) Brainpool curves were an option for authentication and key exchange in the Transport Layer Security (TLS) protocol version 1.2 but were deprecated by the IETF for use with TLS version 1.3 because they had little usage. However, these curves have not been shown to have significant cryptographical weaknesses, and there is some interest in using several of these curves in TLS 1.3.

楕円曲線暗号（Elliptic Curve Cryptography: ECC）のBrainpool曲線は、トランスポート層セキュリティー（Transport Layer Security: TLS）プロトコルのバージョン1.2では認証と鍵交換の選択肢の1つでしたが、ほとんど使われていなかったため、IETFによってTLSバージョン1.3での使用は非推奨とされました。 しかし、これらの曲線に暗号学的な重大な弱点があることは示されておらず、TLS 1.3でこれらの曲線のいくつかを使用することにはある程度の関心が寄せられています。

This document provides the necessary protocol mechanisms for using ECC Brainpool curves in TLS 1.3. This approach is not endorsed by the IETF.

この文書は、TLS 1.3でECC Brainpool曲線を使用するために必要なプロトコルメカニズムを提供します。 このアプローチはIETFによって承認されたものではありません。

1. Introduction

1. はじめに

[RFC5639] specifies a new set of elliptic curve groups over finite prime fields for use in cryptographic applications. These groups, denoted as ECC Brainpool curves, were generated in a verifiably pseudorandom way and comply with the security requirements of relevant standards from ISO [ISO1][ISO2], ANSI [ANSI1], NIST [FIPS], and SECG [SEC2].

[RFC5639]は、暗号アプリケーションで使用するための、有限素体上の新しい楕円曲線群のセットを規定しています。 ECC Brainpool曲線と呼ばれるこれらの群は、検証可能な疑似ランダムな方法で生成されており、ISO [ISO1][ISO2]、ANSI [ANSI1]、NIST [FIPS]、SECG [SEC2]の関連する標準のセキュリティー要件に準拠しています。

[RFC8422] defines the usage of elliptic curves for authentication and key agreement in TLS 1.2 and earlier versions, and [RFC7027] defines the usage of the ECC Brainpool curves for authentication and key exchange in TLS. The latter is applicable to TLS 1.2 and earlier versions but not to TLS 1.3, which deprecates the ECC Brainpool curve IDs defined in [RFC7027] due to the lack of widespread deployment. However, there is some interest in using these curves in TLS 1.3.

[RFC8422]は、TLS 1.2以前のバージョンにおける認証と鍵合意のための楕円曲線の使用法を定義しており、[RFC7027]は、TLSにおける認証と鍵交換のためのECC Brainpool曲線の使用法を定義しています。 後者はTLS 1.2以前のバージョンには適用できますが、TLS 1.3には適用できません。 TLS 1.3では、広く展開されていないことを理由に、[RFC7027]で定義されたECC Brainpool曲線のIDが非推奨とされています。 しかし、TLS 1.3でこれらの曲線を使用することにはある程度の関心が寄せられています。

The negotiation of ECC Brainpool curves for key exchange in TLS 1.3, according to [RFC8446], requires the definition and assignment of additional NamedGroup IDs. This document provides the necessary definition and assignment of additional SignatureScheme IDs for using three ECC Brainpool curves from [RFC5639].

[RFC8446]によれば、TLS 1.3で鍵交換のためにECC Brainpool曲線をネゴシエートするには、追加のNamedGroup IDの定義と割り当てが必要です。 この文書は、[RFC5639]の3つのECC Brainpool曲線を使用するために必要な、追加のSignatureScheme IDの定義と割り当てを提供します。

This approach is not endorsed by the IETF. Implementers and deployers need to be aware of the strengths and weaknesses of all security mechanisms that they use.

このアプローチはIETFによって承認されたものではありません。 実装者や展開者は、自らが使用するすべてのセキュリティーメカニズムの長所と短所を認識しておく必要があります。

3. Brainpool NamedGroup Types

3. Brainpool NamedGroup型

According to [RFC8446], the "supported_groups" extension is used for the negotiation of Diffie-Hellman groups and elliptic curve groups for key exchange during a handshake starting a new TLS session. This document adds new named groups for three elliptic curves defined in [RFC5639] to the "supported_groups" extension, as follows.

[RFC8446]によれば、新しいTLSセッションを開始するハンドシェイクにおいて、鍵交換のためのDiffie-Hellman群と楕円曲線群のネゴシエーションには"supported_groups"拡張が使用されます。 この文書は、[RFC5639]で定義された3つの楕円曲線のための新しい名前付きグループを、次のように"supported_groups"拡張に追加します。

        enum {
             brainpoolP256r1tls13(31),
             brainpoolP384r1tls13(32),
             brainpoolP512r1tls13(33)
        } NamedGroup;

        enum {
             brainpoolP256r1tls13(31),
             brainpoolP384r1tls13(32),
             brainpoolP512r1tls13(33)
        } NamedGroup;

The encoding of Ephemeral Elliptic Curve Diffie-Hellman (ECDHE) parameters for sec256r1, secp384r1, and secp521r1, as defined in Section 4.2.8.2 of [RFC8446], also applies to this document.

[RFC8446]のSection 4.2.8.2で定義されている、sec256r1、secp384r1、secp521r1に対するエフェメラル楕円曲線Diffie-Hellman（ECDHE）パラメーターのエンコーディングは、この文書にも適用されます。

Test vectors for a Diffie-Hellman key exchange using these elliptic curves are provided in Appendix A.

これらの楕円曲線を使用したDiffie-Hellman鍵交換のテストベクターは、Appendix Aに示します。

4. Brainpool SignatureScheme Types

4. Brainpool SignatureScheme型

According to [RFC8446], the name space SignatureScheme is used for the negotiation of elliptic curve groups for authentication via the "signature_algorithms" extension. Besides, it is required to specify the hash function that is used to hash the message before signing. This document adds new SignatureScheme types for three elliptic curves defined in [RFC5639], as follows.

[RFC8446]によれば、SignatureScheme名前空間は、"signature_algorithms"拡張を介した認証のための楕円曲線群のネゴシエーションに使用されます。 さらに、署名の前にメッセージをハッシュするために使用するハッシュ関数を指定する必要があります。 この文書は、[RFC5639]で定義された3つの楕円曲線のための新しいSignatureScheme型を、次のように追加します。

        enum {
             ecdsa_brainpoolP256r1tls13_sha256(0x081A),
             ecdsa_brainpoolP384r1tls13_sha384(0x081B),
             ecdsa_brainpoolP512r1tls13_sha512(0x081C)
        } SignatureScheme;

        enum {
             ecdsa_brainpoolP256r1tls13_sha256(0x081A),
             ecdsa_brainpoolP384r1tls13_sha384(0x081B),
             ecdsa_brainpoolP512r1tls13_sha512(0x081C)
        } SignatureScheme;

6. Security Considerations

6. セキュリティーに関する考慮事項

The security considerations of [RFC8446] apply accordingly.

[RFC8446]のセキュリティーに関する考慮事項が同様に適用されます。

The confidentiality, authenticity, and integrity of the TLS communication is limited by the weakest cryptographic primitive applied. In order to achieve a maximum security level when using one of the elliptic curves from Table 1 for key exchange and/or one of the signature algorithms from Table 2 for authentication in TLS, parameters of other deployed cryptographic schemes should be chosen at commensurate strengths, for example, according to the recommendations of [NIST800-57] and [RFC5639]. In particular, this applies to (a) the key derivation function, (b) the algorithms and key length of symmetric encryption and message authentication, and (c) the algorithm, bit length, and hash function for signature generation. Furthermore, the private Diffie-Hellman keys should be generated from a random keystream with a length equal to the length of the order of the group E(GF(p)) defined in [RFC5639]. The value of the private Diffie-Hellman keys should be less than the order of the group E(GF(p)).

TLS通信の機密性、真正性、完全性は、適用される暗号プリミティブのうち最も弱いものによって制限されます。 TLSにおいて、鍵交換にTable 1の楕円曲線のいずれかを使用する場合、または認証にTable 2の署名アルゴリズムのいずれかを使用する場合、あるいはその両方の場合に最大のセキュリティーレベルを達成するには、展開されている他の暗号方式のパラメーターを、たとえば[NIST800-57]や[RFC5639]の推奨に従って、同等の強度で選択すべきです。 これは特に、(a)鍵導出関数、(b)共通鍵暗号とメッセージ認証のアルゴリズムと鍵長、(c)署名生成のアルゴリズム、ビット長、ハッシュ関数に当てはまります。 さらに、Diffie-Hellmanの秘密鍵は、[RFC5639]で定義された群E(GF(p))の位数の長さと等しい長さのランダムなキーストリームから生成すべきです。 Diffie-Hellmanの秘密鍵の値は、群E(GF(p))の位数より小さくすべきです。

When using ECDHE key agreement with the curves brainpoolP256r1tls13, brainpoolP384r1tls13, or brainpoolP512r1tls13, the peers MUST validate each other's public value Q by ensuring that the point is a valid point on the elliptic curve. If this check is not conducted, an attacker can force the key exchange into a small subgroup, and the resulting shared secret can be guessed with significantly less effort.

曲線brainpoolP256r1tls13、brainpoolP384r1tls13、brainpoolP512r1tls13のいずれかでECDHE鍵合意を使用する場合、ピアは、互いの公開値Qが楕円曲線上の有効な点であることを確認することで、その公開値Qを検証しなければなりません（MUST）。 このチェックを行わない場合、攻撃者は鍵交換を小さな部分群に強制でき、その結果得られる共有秘密を大幅に少ない労力で推測できるようになります。

Implementations of elliptic curve cryptography for TLS may be susceptible to side-channel attacks. Particular care should be taken for implementations that internally transform curve points to points on the corresponding "twisted curve", using the map (x',y') = (x*Z^2, y*Z^3) with the coefficient Z specified for that curve in [RFC5639], in order to take advantage of an efficient arithmetic based on the twisted curve's special parameters (A = -3). Although the twisted curve itself offers the same level of security as the corresponding random curve (through mathematical equivalence), arithmetic based on small curve parameters may be harder to protect against side-channel attacks. General guidance on resistance of elliptic curve cryptography implementations against side-channel attacks is given in [BSI1] and [HMV].

TLSのための楕円曲線暗号の実装は、サイドチャネル攻撃に対して脆弱である可能性があります。 ツイスト曲線の特殊なパラメーター（A = -3）に基づく効率的な演算を利用するために、[RFC5639]でその曲線に対して規定された係数Zを用いた写像 (x',y') = (x*Z^2, y*Z^3) によって、曲線上の点を対応する「ツイスト曲線（twisted curve）」上の点に内部で変換する実装には、特に注意を払うべきです。 ツイスト曲線自体は（数学的な同値性により）対応するランダム曲線と同じレベルのセキュリティーを提供しますが、小さな曲線パラメーターに基づく演算は、サイドチャネル攻撃から保護するのがより難しい場合があります。 サイドチャネル攻撃に対する楕円曲線暗号実装の耐性に関する一般的なガイダンスは、[BSI1]と[HMV]に記載されています。

Appendix A. Test Vectors

Appendix A. テストベクター

the x-coordinate of the public key of party B

the y-coordinate of the public key of party B

the x-coordinate of the shared secret that results from completion of the Diffie-Hellman computation, i.e., the hex representation of the premaster secret

Diffie-Hellman計算の完了によって得られる共有秘密のx座標、すなわちプリマスターシークレットの16進数表現
