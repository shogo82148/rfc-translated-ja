RFC 2349

TFTP Timeout Interval and Transfer Size Options

RFC 2349

TFTPのタイムアウト間隔と転送サイズのオプション

Abstract

概要

The Trivial File Transfer Protocol [1] is a simple, lock-step, file transfer protocol which allows a client to get or put a file onto a remote host.

Trivial File Transfer Protocol [1]は、クライアントがリモートホストとの間でファイルを取得または配置できる、単純でロックステップのファイル転送プロトコルです。

This document describes two TFTP options. The first allows the client and server to negotiate the Timeout Interval. The second allows the side receiving the file to determine the ultimate size of the transfer before it begins. The TFTP Option Extension mechanism is described in [2].

この文書は、2つのTFTPのオプションについて説明します。1つ目は、クライアントとサーバーがタイムアウト間隔をネゴシエートできるようにします。2つ目は、ファイルを受信する側が、転送が始まる前に転送の最終的なサイズを判断できるようにします。TFTPのオプション拡張のメカニズムは[2]で説明されています。

Timeout Interval Option Specification

タイムアウト間隔オプションの仕様

The TFTP Read Request or Write Request packet is modified to include the timeout option as follows:

TFTPの読み出し要求または書き込み要求のパケットは、次のようにタイムアウトオプションを含むように変更されます。

      +-------+---~~---+---+---~~---+---+---~~---+---+---~~---+---+
      |  opc  |filename| 0 |  mode  | 0 | timeout| 0 |  #secs | 0 |
      +-------+---~~---+---+---~~---+---+---~~---+---+---~~---+---+

      +-------+---~~---+---+---~~---+---+---~~---+---+---~~---+---+
      |  opc  |filename| 0 |  mode  | 0 | timeout| 0 |  #secs | 0 |
      +-------+---~~---+---+---~~---+---+---~~---+---+---~~---+---+
opc
The opcode field contains either a 1, for Read Requests, or 2, for Write Requests, as defined in [1].
filename
The name of the file to be read or written, as defined in [1]. This is a NULL-terminated field.
mode
The mode of the file transfer: "netascii", "octet", or "mail", as defined in [1]. This is a NULL-terminated field.
timeout
The Timeout Interval option, "timeout" (case in-sensitive). This is a NULL-terminated field.
#secs
The number of seconds to wait before retransmitting, specified in ASCII. Valid values range between "1" and "255" seconds, inclusive. This is a NULL-terminated field.
opc
opcodeフィールドには、[1]で定義されているように、読み出し要求の場合は1、書き込み要求の場合は2が含まれます。
filename
[1]で定義されている、読み出しまたは書き込みを行うファイルの名前。これはNULLで終端されたフィールドです。
mode
[1]で定義されている、ファイル転送のモード（「netascii」、「octet」、または「mail」）。これはNULLで終端されたフィールドです。
timeout
タイムアウト間隔オプション「timeout」（大文字と小文字を区別しない）。これはNULLで終端されたフィールドです。
#secs
ASCIIで指定される、再送信するまでに待つ秒数。有効な値は「1」から「255」秒までの範囲（両端を含む）です。これはNULLで終端されたフィールドです。

For example:

たとえば:

      +-------+--------+---+--------+---+--------+---+-------+---+
      |   1   | foobar | 0 | octet  | 0 | timeout| 0 |   1   | 0 |
      +-------+--------+---+--------+---+--------+---+-------+---+

      +-------+--------+---+--------+---+--------+---+-------+---+
      |   1   | foobar | 0 | octet  | 0 | timeout| 0 |   1   | 0 |
      +-------+--------+---+--------+---+--------+---+-------+---+

is a Read Request, for the file named "foobar", in octet (binary) transfer mode, with a timeout interval of 1 second.

は、「foobar」という名前のファイルについての、octet（バイナリー）の転送モードで、タイムアウト間隔が1秒の読み出し要求です。

If the server is willing to accept the timeout option, it sends an Option Acknowledgment (OACK) to the client. The specified timeout value must match the value specified by the client.

サーバーがタイムアウトオプションを受け入れる意思がある場合、サーバーはクライアントにオプション確認応答（OACK）を送信します。指定するタイムアウトの値は、クライアントが指定した値と一致しなければなりません。

Transfer Size Option Specification

転送サイズオプションの仕様

The TFTP Read Request or Write Request packet is modified to include the tsize option as follows:

TFTPの読み出し要求または書き込み要求のパケットは、次のようにtsizeオプションを含むように変更されます。

      +-------+---~~---+---+---~~---+---+---~~---+---+---~~---+---+
      |  opc  |filename| 0 |  mode  | 0 | tsize  | 0 |  size  | 0 |
      +-------+---~~---+---+---~~---+---+---~~---+---+---~~---+---+

      +-------+---~~---+---+---~~---+---+---~~---+---+---~~---+---+
      |  opc  |filename| 0 |  mode  | 0 | tsize  | 0 |  size  | 0 |
      +-------+---~~---+---+---~~---+---+---~~---+---+---~~---+---+
opc
The opcode field contains either a 1, for Read Requests, or 2, for Write Requests, as defined in [1].
filename
The name of the file to be read or written, as defined in [1]. This is a NULL-terminated field.
mode
The mode of the file transfer: "netascii", "octet", or "mail", as defined in [1]. This is a NULL-terminated field.
tsize
The Transfer Size option, "tsize" (case in-sensitive). This is a NULL-terminated field.
size
The size of the file to be transfered. This is a NULL- terminated field.
opc
opcodeフィールドには、[1]で定義されているように、読み出し要求の場合は1、書き込み要求の場合は2が含まれます。
filename
[1]で定義されている、読み出しまたは書き込みを行うファイルの名前。これはNULLで終端されたフィールドです。
mode
[1]で定義されている、ファイル転送のモード（「netascii」、「octet」、または「mail」）。これはNULLで終端されたフィールドです。
tsize
転送サイズオプション「tsize」（大文字と小文字を区別しない）。これはNULLで終端されたフィールドです。
size
転送されるファイルのサイズ。これはNULLで終端されたフィールドです。

For example:

たとえば:

      +-------+--------+---+--------+---+--------+---+--------+---+
      |   2   | foobar | 0 | octet  | 0 | tsize  | 0 | 673312 | 0 |
      +-------+--------+---+--------+---+--------+---+--------+---+

      +-------+--------+---+--------+---+--------+---+--------+---+
      |   2   | foobar | 0 | octet  | 0 | tsize  | 0 | 673312 | 0 |
      +-------+--------+---+--------+---+--------+---+--------+---+

is a Write Request, with the 673312-octet file named "foobar", in octet (binary) transfer mode.

は、673312オクテットの「foobar」という名前のファイルについての、octet（バイナリー）の転送モードでの書き込み要求です。

In Read Request packets, a size of "0" is specified in the request and the size of the file, in octets, is returned in the OACK. If the file is too large for the client to handle, it may abort the transfer with an Error packet (error code 3). In Write Request packets, the size of the file, in octets, is specified in the request and echoed back in the OACK. If the file is too large for the server to handle, it may abort the transfer with an Error packet (error code 3).

読み出し要求パケットでは、要求でサイズ「0」が指定され、OACKでファイルのオクテット単位のサイズが返されます。ファイルがクライアントにとって扱えないほど大きい場合、クライアントはErrorパケット（エラーコード3）で転送を中止できます。書き込み要求パケットでは、要求でファイルのオクテット単位のサイズが指定され、OACKでそれが返されます。ファイルがサーバーにとって扱えないほど大きい場合、サーバーはErrorパケット（エラーコード3）で転送を中止できます。

Security Considerations

セキュリティーに関する考慮事項

The basic TFTP protocol has no security mechanism. This is why it has no rename, delete, or file overwrite capabilities. This document does not add any security to TFTP; however, the specified extensions do not add any additional security risks.

基本的なTFTPプロトコルには、セキュリティーのメカニズムがありません。そのため、名前の変更、削除、またはファイルの上書きの機能がありません。この文書はTFTPにセキュリティーを追加しませんが、規定された拡張は追加のセキュリティー上のリスクをもたらしません。
