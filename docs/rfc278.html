RFC 278

Revision of the Mail Box Protocol

RFC 278

メールボックスプロトコルの改訂

Abstract

概要

The file transfer committee met and discussed the Mail Box Protocol RFC 221, NIC 7612. The potential utility for the mechanism was confirmed and a couple of changes suggested. We first give the changes and then restate the Protocol.

ファイル転送委員会は会合を開き、メールボックスプロトコル（Mail Box Protocol、RFC 221、NIC 7612）について議論しました。この仕組みが役に立ちそうであることが確認され、いくつかの変更が提案されました。まず変更点を示し、そのあとでプロトコルをあらためて述べます。

CHANGES

変更点

  1. The Mail Box Protocol is only to allow ASCII stings of text formatted for a network standard line printer rather than allowing other data types.
  2. A new command is to be added to the File Transfer Protocol called "Append With Create" which appends to a file if the file exists, and creates a file if it does not exist.

  3. The standard path name for the mailbox is to be, using conventional metalanguage symbols,

    "MAIL" <separator> ("PRINTER"/<ident>)

    <separator> is the ASCII GS, octal 035. The semantics of the above are the following:

    <ident> is a NIC IDENT

    "MAIL" <separator> "PRINTER" would be interpreted by the receiving site as meaning Append With Create the transmitted file to a bulk mail file to be printed or directly output it to a printer.

    "MAIL" <separator> <ident> would be interpreted to mean either

    1. The same as "MAIL" <separator> "PRINTER" i.e., ignore <ident> or
    2. Append With Create the following file to a file specifically for the person designated by <ident> for either online access or printing or both.
  1. メールボックスプロトコルでは、他のデータ型は許さず、ネットワーク標準のラインプリンター向けに書式を整えたテキストのASCII文字列だけを許すこととします。
  2. ファイル転送プロトコル（File Transfer Protocol）に「Append With Create」という新しいコマンドを追加します。このコマンドは、ファイルが存在すればそのファイルに追記し、存在しなければファイルを作成します。

  3. メールボックスの標準のパス名は、慣用のメタ言語の記号を使うと次のとおりとします。

    "MAIL" <separator> ("PRINTER"/<ident>)

    <separator>はASCIIのGS（8進数で035）です。上記の意味は次のとおりです。

    <ident>はNICのIDENTです。

    "MAIL" <separator> "PRINTER"は、受信サイトでは、送信されたファイルを印刷用の一括メールファイルにAppend With Createするか、そのファイルを直接プリンターに出力するという意味に解釈されます。

    "MAIL" <separator> <ident>は、次のどちらかの意味に解釈されます。

    1. "MAIL" <separator> "PRINTER"と同じ。つまり、<ident>を無視する。または
    2. 続くファイルを、<ident>で指定された人専用のファイルにAppend With Createし、オンラインでのアクセス、印刷、またはその両方に使えるようにする。

The problem of delivering mail to TIPs was discussed.

TIPへのメールの配送の問題についても議論しました。

At the moment TIPs support only the Telnet Protocol, but it is planned to support the Data Transfer Protocol. TIPs will have an ASCII line printer available as an optional device. People desiring to send a mail item to a TIP with a printer can open a standard published socket and transmit to it with Telnet Protocol now, later also with the Data Transfer Protocol. The NIC's plans with regard to TIPs is not to do automatic network delivery to them. Messages to people using TIPs can be sent to them through the NIC and will be delivered as with everyone else directly to the person's initial file at the NIC. The TIP user can read the item online or obtain a hardcopy at his terminal with the Output Device Teletype command of NLS.

現時点では、TIPはTelnetプロトコルしかサポートしていませんが、データ転送プロトコル（Data Transfer Protocol）もサポートする予定です。TIPでは、オプションの装置としてASCIIのラインプリンターを利用できるようになります。プリンターを持つTIPにメールアイテムを送りたい人は、公開されている標準のソケットを開き、今はTelnetプロトコルで、のちにはデータ転送プロトコルでも、そこに送信できます。TIPに関するNICの計画では、TIPへの自動的なネットワーク配送は行いません。TIPを使っている人へのメッセージはNIC経由で送ることができ、他の人と同様に、NICにあるその人の初期ファイルに直接配送されます。TIPのユーザーは、そのアイテムをオンラインで読むことも、NLSのOutput Device Teletypeコマンドで自分の端末でハードコピーを得ることもできます。

MAIL BOX PROTOCOL

メールボックスプロトコル

The Mail Box Protocol will use established network conventions, specifically the Network Control Program, Initial Connection Protocol, Data Transfer Protocol, and File Transfer Protocol (as described in current Network Protocols, NIC 7104).

メールボックスプロトコルは、確立されたネットワークの規約、具体的には、ネットワーク制御プログラム（Network Control Program）、初期接続プロトコル（Initial Connection Protocol）、データ転送プロトコル、ファイル転送プロトコル（現行のNetwork Protocols、NIC 7104に記述されているもの）を使います。

The transmission is to be Network ASCII. The standard receiving mail printer is assumed to have a print line 72 characters wide, and a page of 66 lines. The new line convention will be carriage return (Hex per the Telnet Protocol, RFC 158, NIC 6768. The standard printer will accept form feed character (Hex '0C') (Octal '014') as meaning move paper to the top of a new page.

送信はネットワークASCIIで行います。標準の受信用メールプリンターは、印字行の幅が72文字、1ページが66行であると想定します。改行の規約はキャリッジリターン（16進数で、TelnetプロトコルのRFC 158、NIC 6768に従います。標準のプリンターは、フォームフィード文字（16進数で'0C'）（8進数で'014'）を、用紙を新しいページの先頭まで送るという意味として受け付けます。

It is the sender's responsibility to control the length of the print line and page. If more than 72 characters per line are sent, or if more than 66 line are sent without a form feed, then the receiving site can handle these situations as appropriate for them. These conventions can be changed by control codes as described below. At the head of the message or document sent there is to be two copies of an initial address string each terminated by a form feed. This address string is to contain the sender's name and address, and the receiver's name and address formatted in some reasonable, easy-to read form for a clerk to read and distribute. Comments could also be included in the address string. The requirements for two copies are to make one readable from a fan fold paper stack without effort.

印字行とページの長さを制御するのは送信者の責任です。1行に72文字を超えて送られた場合や、フォームフィードなしで66行を超えて送られた場合は、受信サイトはそれぞれの状況を自分たちに適したやり方で処理できます。これらの規約は、後述する制御コードで変更できます。送るメッセージや文書の先頭には、初期アドレス文字列を2部置き、それぞれをフォームフィードで終端します。このアドレス文字列には、送信者の名前とアドレス、および受信者の名前とアドレスを、事務員が読んで配布できる程度に適度で読みやすい形式で含めます。アドレス文字列にコメントを含めることもできます。2部必要なのは、扇状に折りたたまれた用紙の束から、苦労せずにどちらか一方を読めるようにするためです。

Initial Connection

初期接続

Initial Connection will be as per the Official Initial Connection Protocol, Document #2, NIC 7101, to the standard File Transfer socket #3.

初期接続は、公式の初期接続プロトコル（Official Initial Connection Protocol、Document #2、NIC 7101）に従い、標準のファイル転送ソケットである#3に対して行います。

File Transfer

ファイル転送

The mail item (file) to be transferred would be transferred according to the File Transfer Protocol.

転送するメールアイテム（ファイル）は、ファイル転送プロトコルに従って転送します。

As per the File Transfer Protocol, a file (mail item) can be sent in more than one data transaction as defined in the Data Transfer Protocol. End of file is indicated by the file separator (as defined in Data Transfer Protocol) or by closing the connection.

ファイル転送プロトコルにあるとおり、ファイル（メールアイテム）は、データ転送プロトコルで定義されている複数のデータトランザクションに分けて送ることができます。ファイルの終わりは、（データ転送プロトコルで定義されている）ファイル区切り文字か、コネクションを閉じることで示します。

トランザクションの順序

必要な基本操作はAppend With Createだけです。

データ型のデフォルトはネットワークASCIIです。標準のラインプリンターのデフォルトは上で定義したとおりです。その他の制御トランザクションも使えます。

ERROR CODES

エラーコード

All error codes defined in the file Transfer Protocol could be returned.

ファイル転送プロトコルで定義されているすべてのエラーコードを返すことができます。
