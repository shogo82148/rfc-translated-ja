RFC 408

NETBANK

Abstract

概要

The following idea for a protocol (or service) is offered as an aid to network use for new users:

新しいユーザーがネットワークを利用する際の助けとして、プロトコル（またはサービス）に関する次のアイデアを提案します：

a single billing and account creation and validation system, so that a manager of a "goal oriented project" could:

単一の課金・アカウント作成・検証システムです。これにより「目標指向プロジェクト」の管理者は次のことができます：

  • authorize a set of user's ids to gain access to and utilize resources at the entire or a specified subset of the server hosts.
  • create a set of accounts which the users will expend, and which will be used as the breakdown for a single bill to be presented to the project manager.
  • 一連のユーザーIDに対して、すべてのサーバーホスト、または指定した一部のサーバーホストにアクセスし、その資源を利用することを認可します。
  • ユーザーが消費していく一連のアカウントを作成します。これらのアカウントは、プロジェクトの管理者に提示される単一の請求書の内訳として使われます。

the idea is that the project manager would be required to go through the initialization process of introducing himself, verifying the existence of funding, etc. only once, and,

このアイデアでは、プロジェクトの管理者は、自己紹介や資金があることの確認などの初期手続きを一度だけ済ませればよくなります。また、

the idea would also encourage server hosts to implement systems for which usage might be projected to start at low levels and grow, by allowing funded hacking by project members in a controlled manner.

このアイデアは、プロジェクトのメンバーが資金を得て管理された形でハッキングできるようにすることで、利用量が低い水準から始まり増えていくと見込まれるようなシステムをサーバーホストが実装することも後押しします。

this would require an option at login for the prospective user to indicate the server should check the "netbank" facility at the system currently hosting it.

これを実現するには、利用しようとするユーザーが、現在「netbank」機能をホストしているシステムで同機能を確認するようサーバーに指示できる、ログイン時のオプションが必要になります。
