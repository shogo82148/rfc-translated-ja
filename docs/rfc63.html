RFC 63

Belated Network Meeting Report

RFC 63

遅ればせながらのネットワーク会議報告

Abstract

概要

On 8 May 1970, a Network Working Group meeting was hosted at Lincoln Labs. The topics under discussion were:

1970年5月8日、Lincoln LabsでNetwork Working Groupの会議が開かれました。議題は次のとおりです：

  1. Lincoln Lab's Local Interaction Language (LIL)
  2. Records, Messages, and Format in HOST-HOST information exchange.
  3. Miscellaneous gripes
  1. Lincoln LabのLocal Interaction Language（LIL）
  2. ホスト間（HOST-HOST）の情報交換におけるレコード、メッセージ、フォーマット
  3. その他の不満

The first topic is thoroughly summarized in Lincoln Lab's Semi annual Technical Summary titled "Graphics", dated May 31, 1970 (document id. ESD-TR-70-151).

1つ目の議題については、Lincoln Labの半期技術概要（Semi annual Technical Summary）「Graphics」（1970年5月31日付、文書ID ESD-TR-70-151）に詳しくまとめられています。

The second topic involved considerable discussion of NWG/RFC #42 in which it was proposed that all messages be preceded by an 8-bit type byte which would declare the format of the message which followed.

2つ目の議題では、NWG/RFC #42についてかなりの議論がありました。NWG/RFC #42では、すべてのメッセージの前に、後続のメッセージのフォーマットを示す8ビットのタイプバイトを置くことが提案されています。

The following decisions were reached:

次のことが決まりました：

  1. Records may begin anywhere within a message.
  2. The first 8 bits of a record are reserved for type information.
  3. The first transmission on a connection starts a record.
  1. レコードは、メッセージ内のどこから始まってもかまいません。
  2. レコードの最初の8ビットは、タイプ情報のために予約されています。
  3. 接続上の最初の送信は、レコードの開始となります。

Type 0 is agreed to mean that the transmission that follows consists of an arbitrarily long record, and that no further type bytes will be present.

タイプ0は、後続の送信が任意の長さの1つのレコードからなり、それ以上タイプバイトが現れないことを意味する、ということで合意しました。

The notions of messages and records are independent of the flow-control protocol. Thus the receipt of a message does not carry any semantic importance. The receipt of a record, however, may initiate some interpretation process.

メッセージとレコードという概念は、フロー制御プロトコルとは独立しています。したがって、メッセージを受信したことには意味上の重要性はありません。一方、レコードを受信したことによって、何らかの解釈処理が始まることはあります。

After some discussion, the proposals in NWG/RFC #42 were permuted as follows:

いくらか議論した結果、NWG/RFC #42の提案は次のように並べ替えられました：

  • type 0 = bit string of arbitrary length follows
  • type 1 = 8-bit ASCII follows
  • type 2 = EBCDIC follows
  • type 3 = MOD 33 TTY 7-bit ASCII
  • type 4 = YOUR Local followed by another type byte
  • type 5 = MY Local followed by another type byte
  • タイプ0 = 任意の長さのビット列が続く
  • タイプ1 = 8ビットASCIIが続く
  • タイプ2 = EBCDICが続く
  • タイプ3 = MOD 33 TTY 7ビットASCII
  • タイプ4 = YOUR Local（あなたのローカル）、続けてもう1つのタイプバイト
  • タイプ5 = MY Local（私のローカル）、続けてもう1つのタイプバイト
