RFC 576

Proposal for modifying linking

RFC 576

リンク機能の変更の提案

Abstract

概要

We plan to modify the link jsys in TENEX to work in a little bit better way in terms of the user interface. Conversations with BBN indicate that they have no complaints with the current implementation. However, if after we have gained experience with our new implementation, we will let them know about it and they will review the new implementation and possibly accept it as part of standard TENEX.

TENEXのlink jsys（システムコール）を、ユーザーインターフェイスの面で少しよい動作をするように変更することを計画しています。BBNとの話し合いでは、BBNは現在の実装に不満はないとのことでした。しかし、私たちが新しい実装の経験を積んだあとでBBNに知らせれば、BBNは新しい実装をレビューし、標準のTENEXの一部として受け入れる可能性もあります。

I would appreciate feedback in the next couple of days so that I can go ahead and implement this proposal (or a modified proposal or nothing...). (I estimate that it will only take a couple of hours to implement!)

この提案（または修正した提案、あるいは何もしないこと…）の実装に取りかかれるよう、この数日のうちにフィードバックをいただけるとありがたいです。（実装には数時間しかかからないと見積もっています！）

(Note that by modifying the jsys, the proposed changes as specified will be in effect at the user level in the exec.)

（jsysを変更することで、ここに記述した変更案はexecのユーザーレベルでも有効になることに注意してください。）

The default state for all users will remain as it currently is, i.e. RECEIVE LINKS.

すべてのユーザーのデフォルトの状態は、現在と同じRECEIVE LINKSのままとします。

Now, consider users A, B, and C.

ここで、ユーザーA、B、Cを考えます。

If A and B link to each other they are now holding a conversation.

AとBが互いにリンクすると、2人は会話をしている状態になります。

After establishing a conversation, all members of the conversation will be placed in the REFUSE LINKS state.

会話が確立すると、会話の参加者全員がREFUSE LINKS状態になります。

If user C (or any other user) now tries to link to user A (or B), the bell will ring on users A (or B) and C terminals indicating that A (or B) is in a REFUSE LINKS state.

ここでユーザーC（または他のユーザー）がユーザーA（またはB）にリンクしようとすると、ユーザーA（またはB）とCの端末でベルが鳴り、A（またはB）がREFUSE LINKS状態であることを示します。

  • If A ignores the bell then C is not admitted to the conversation and A and B can continue their conversation as if C had never tried to enter the conversation.
  • However, if A does a RECEIVE LINKS while the bell is ringing (the bell rings for approximately 15 seconds), then C will be linked into the conversation and not to just user A. Thus A and B will be linked, A and C will be linked, and B and C will be linked, i.e., a three way conversation. Also, users A, B, and C will be in the REFUSE LINKS state.
  • Aがベルを無視した場合、Cは会話に参加できず、AとBは、Cが会話に加わろうとしなかったかのように会話を続けられます。
  • 一方、ベルが鳴っている間（ベルは約15秒間鳴ります）にAがRECEIVE LINKSを実行すると、CはユーザーAだけでなく会話にリンクされます。つまり、AとB、AとC、BとCがそれぞれリンクされ、3者間の会話になります。また、ユーザーA、B、CはREFUSE LINKS状態になります。

Whenever a user leaves a conversation, his state will be set automatically to RECEIVE LINKS.

ユーザーが会話から抜けると、そのユーザーの状態は自動的にRECEIVE LINKSに設定されます。

  • Thus, when user C does a break links the resulting states will be:
  • したがって、ユーザーCがリンクを切断（break links）すると、結果の状態は次のようになります。
  • A and B will be linked and both will be in REFUSE LINKS
  • C will be out of the conversation and will be in RECEIVE LINKS
  • AとBはリンクされたままで、どちらもREFUSE LINKS状態です
  • Cは会話から抜け、RECEIVE LINKS状態になります
  • Now, when A or B does a BREAK LINKS there will no longer be a conversation and both A and B will be in the RECEIVE LINKS state.
  • 次に、AまたはBがBREAK LINKSを実行すると、会話はなくなり、AとBはどちらもRECEIVE LINKS状態になります。

To summarize:

まとめると次のとおりです。

  • After any conversation is established, all members of the conversation are placed in the REFUSED LINKS state.
  • When a user links to a terminal or a user, he is in fact linking into a conversation if one exists or to an individual if no conversation is taking place.
  • When a user leaves a conversation, she is placed in the RECEIVE LINKS state.
  • 会話が確立したあとは、会話の参加者全員がREFUSED LINKS状態になります。
  • ユーザーが端末やユーザーにリンクするとき、実際には、会話があればその会話にリンクし、会話が行われていなければその個人にリンクします。
  • ユーザーが会話から抜けると、そのユーザーはRECEIVE LINKS状態になります。

Changes to the TLINK jsys will be necessary to implement the above. No changes are required in the EXEC. In addition to the above changes, we will add a new jsys that will return the link and advise status for a passed terminal, i.e., you will be able to tell which lines are linked to the passed terminal, which lines the passed terminal is linked to, which line the passed terminal is advising, and/or which line is advising the passed terminal. This information will probably be incorporated into the systat printout, the where is printout, and will probably be used within NLS for shared screen work.

上記を実装するには、TLINK jsysの変更が必要です。EXECの変更は必要ありません。上記の変更に加えて、指定した端末のリンクとアドバイス（advise）の状態を返す新しいjsysを追加します。つまり、指定した端末にどの回線がリンクされているか、指定した端末がどの回線にリンクしているか、指定した端末がどの回線をアドバイスしているか、どの回線が指定した端末をアドバイスしているかがわかるようになります。この情報は、おそらくsystatの出力やwhere isの出力に組み込まれ、NLS内で画面共有の作業にも使われることになるでしょう。
