RFC 3085

URN Namespace for NewsML Resources

RFC 3085

NewsMLリソースのためのURN名前空間

Abstract

概要

This document describes a URN (Uniform Resource Name) namespace for identifying NewsML NewsItems. A NewsItem is an information resource that is expressible as a NewsML element within a NewsML document conforming to the NewsML Document Type Declaration (DTD) as defined by the International Press Telecommunications Council (IPTC).

この文書は、NewsMLのNewsItemを識別するためのURN（Uniform Resource Name）名前空間について説明します。NewsItemとは、国際新聞電気通信評議会（International Press Telecommunications Council、IPTC）が定めるNewsML文書型宣言（Document Type Declaration、DTD）に準拠したNewsML文書の中で、NewsML要素として表現できる情報リソースです。

1. Introduction

1. はじめに

NewsML is an XML format for packaging multimedia news resources. It has been created under the auspices of the International Press Telecommunications Council (IPTC), and version 1.0 was approved by the IPTC on 6 October 2000.

NewsMLは、マルチメディアのニュースリソースをパッケージ化するためのXML形式です。NewsMLは国際新聞電気通信評議会（IPTC）の主催のもとで作成され、バージョン1.0は2000年10月6日にIPTCによって承認されました。

The same logical NewsItem may exist in multiple physical locations. The NewsML specification allows NewsItems to have multiple URLs, but only a single URN. It is the latter which then uniquely names the resource.

論理的に同一のNewsItemが、物理的には複数の場所に存在することがあります。NewsMLの仕様では、NewsItemが複数のURLを持つことを認めていますが、URNは1つしか持てません。そのリソースに一意な名前を付けるのは後者のURNです。

This namespace specification is for a formal namespace.

この名前空間の仕様は、正式な名前空間のためのものです。

Declaration of structure:

The identifier has the following ABNF[6] specification:

NSS = ProviderId ":" DateId ":" NewsItemId ":" RevisionId Update
ProviderId = string
DateId = date
NewsItemId = string
RevisionId = posint
Update = 0*1( "A" / "U" )
date = century year month day
century = ( "0" posdig ) / ( posdig DIGIT )
year = 1*2DIGIT
month = ( 0 posdig ) / ( "1" ( "0" "1" "2" ) )
day = ( 0 posdig ) / ( ( "1" / "2" ) DIGIT ) / "30" / "31"
string = 1*char
char = ALPHA / DIGIT / symbol / escape
symbol = "(" / ")" / "+" / "," / "-" / "." / "=" / "@" / ";" /
  "$" / "_" / "!" / "*" / "'"
escape = "%" HEXDIG HEXDIG
posint = posdig *DIGIT
posdig = "1" / "2" / "3" / "4" / "5" / "6" / "7" / "8" / "9"

The ProviderId must be an Internet domain name, and must be owned by the organisation creating the NewsML resource and allocating the URN to it, at the date identified by the DateId.

DateId is a date in ISO 8601 Basic Format (CCYYMMDD), and must correspond to a date at which the organisation allocating the URN owned the domain name specified in the ProviderId.

The NewsItemId must be unique among all NewsItems emanating from the same provider and having the same DateId.

RevisionId is a positive integer indicating which revision of a given NewsItem this is. Any positive integer may be used, but it must always be the case that of two instances of a NewsItem that have the same ProviderId, DateId and NewsItemId, the one whose RevisionId has the larger value must be the more recent revision. A RevisionId of 0 is not permitted.

If the NewsItem contains an "Update" element or elements, then Update must be set to "U". If the NewsItem consists only of a replacement set of NewsManagement data, then Update must be set to "A". If neither of these is the case, then Update must be suppressed.

Relevant ancillary documentation:
None
Identifier uniqueness considerations:
The combination of ProviderId and DateId serves to uniquely identify the organisation that is allocating the URN. That organisation is responsible for ensuring the uniqueness of the DateId/NewsItemId/RevisionId combination.
Identifier persistence considerations:
A NewsML URN may only be allocated by an organisation that owns an Internet domain name. The URN identifies a date on which the organisation owned that domain name. The combination of date and domain name will serve to uniquely identify that organisation for all time.
Process of identifier assignment:
The organisation identified by the ProviderId/DateId combination is responsible for allocating a NewsItemId that is unique among all those that it allocates with that DateId.
Process of identifier resolution:
NewsML providers are responsible for the provision of a URN resolution service, if any, for NewsML URNs they have assigned with a valid ProviderId/DateId combination.
Rules for Lexical Equivalence:
URNs are lexically equivalent if the ProviderId, DateId, NewsItemId, and RevisionId are all identical (case-insensitive comparison).
Conformance with URN Syntax:
No special considerations beyond the syntax herein described.
Validation mechanism:
Organisations that allocate NewsML URNs are responsible for the provision of a URN validation service, if any, for URNs they have assigned with a valid ProviderId/DateId combination.
Scope:
Global

構造の宣言（Declaration of structure）：

識別子は、次のABNF[6]で規定されます。

NSS = ProviderId ":" DateId ":" NewsItemId ":" RevisionId Update
ProviderId = string
DateId = date
NewsItemId = string
RevisionId = posint
Update = 0*1( "A" / "U" )
date = century year month day
century = ( "0" posdig ) / ( posdig DIGIT )
year = 1*2DIGIT
month = ( 0 posdig ) / ( "1" ( "0" "1" "2" ) )
day = ( 0 posdig ) / ( ( "1" / "2" ) DIGIT ) / "30" / "31"
string = 1*char
char = ALPHA / DIGIT / symbol / escape
symbol = "(" / ")" / "+" / "," / "-" / "." / "=" / "@" / ";" /
  "$" / "_" / "!" / "*" / "'"
escape = "%" HEXDIG HEXDIG
posint = posdig *DIGIT
posdig = "1" / "2" / "3" / "4" / "5" / "6" / "7" / "8" / "9"

ProviderIdはインターネットのドメイン名でなければならず、DateIdで識別される日付の時点で、NewsMLリソースを作成してそれにURNを割り当てる組織が所有しているものでなければなりません。

DateIdはISO 8601基本形式（CCYYMMDD）の日付であり、URNを割り当てる組織がProviderIdで指定されたドメイン名を所有していた日付でなければなりません。

NewsItemIdは、同じプロバイダーから発信され、同じDateIdを持つすべてのNewsItemの中で一意でなければなりません。

RevisionIdは、そのNewsItemが何番目の改訂版であるかを示す正の整数です。任意の正の整数を使用できますが、同じProviderId、DateId、NewsItemIdを持つNewsItemの2つのインスタンスについて、RevisionIdの値が大きいほうが常により新しい改訂版でなければなりません。RevisionIdの0は許可されません。

NewsItemに"Update"要素が1つ以上含まれる場合は、Updateを"U"に設定しなければなりません。NewsItemがNewsManagementデータの置き換え用のセットだけで構成される場合は、Updateを"A"に設定しなければなりません。どちらにも当てはまらない場合は、Updateを省略しなければなりません。

関連する補足文書（Relevant ancillary documentation）：
なし
識別子の一意性に関する考慮事項（Identifier uniqueness considerations）：
ProviderIdとDateIdの組み合わせによって、URNを割り当てている組織が一意に識別されます。その組織は、DateId/NewsItemId/RevisionIdの組み合わせの一意性を保証する責任を負います。
識別子の永続性に関する考慮事項（Identifier persistence considerations）：
NewsMLのURNは、インターネットのドメイン名を所有する組織だけが割り当てられます。URNは、その組織がそのドメイン名を所有していた日付を示します。日付とドメイン名の組み合わせによって、その組織は永久に一意に識別されます。
識別子の割り当て手順（Process of identifier assignment）：
ProviderId/DateIdの組み合わせで識別される組織は、そのDateIdで割り当てるすべてのNewsItemIdの中で一意となるNewsItemIdを割り当てる責任を負います。
識別子の解決手順（Process of identifier resolution）：
NewsMLプロバイダーは、有効なProviderId/DateIdの組み合わせで自身が割り当てたNewsMLのURNについて、URN解決サービスを提供する場合、その提供に責任を負います。
字句的な同等性の規則（Rules for Lexical Equivalence）：
ProviderId、DateId、NewsItemId、RevisionIdがすべて同一（大文字と小文字を区別しない比較）であれば、URNは字句的に同等です。
URN構文への準拠（Conformance with URN Syntax）：
ここで説明した構文以外に、特別な考慮事項はありません。
検証メカニズム（Validation mechanism）：
NewsMLのURNを割り当てる組織は、有効なProviderId/DateIdの組み合わせで自身が割り当てたURNについて、URN検証サービスを提供する場合、その提供に責任を負います。
スコープ（Scope）：
グローバル

4. セキュリティーに関する考慮事項

There are no additional security considerations other than those normally associated with the use and resolution of URNs in general.

URN全般の使用と解決に通常伴うもの以外に、追加のセキュリティーに関する考慮事項はありません。
