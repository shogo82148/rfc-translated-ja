RFC 3504

Internet Open Trading Protocol (IOTP) Version 1, Errata

RFC 3504

インターネットオープン取引プロトコル（IOTP）バージョン1の正誤表

Abstract

概要

Since the publication of the RFCs specifying Version 1.0 of the Internet Open Trading Protocol (IOTP), some errors have been noted. This informational document lists these errors and provides corrections for them.

インターネットオープン取引プロトコル（Internet Open Trading Protocol、IOTP）のバージョン1.0を規定するRFCが公開されて以来、いくつかの誤りが指摘されています。この情報提供文書は、これらの誤りを列挙し、その訂正を示します。

1. Introduction

1. はじめに

The Internet Open Trading Protocol (IOTP), Version 1.0, is specified in [RFC 2801], [RFC 2802], [RFC 2803]. It provides a payment system independent framework for Internet commerce oriented to consumer to business transactions. It provides mechanism for different portions of the business function, such as fulfillment or payment handling, to be distributed or outsourced. It does not require a prior relationship between the consumer and business.

インターネットオープン取引プロトコル（IOTP）のバージョン1.0は、[RFC 2801]、[RFC 2802]、[RFC 2803]で規定されています。IOTPは、消費者と企業の間の取引を対象とした、支払いシステムに依存しないインターネット商取引のフレームワークを提供します。IOTPは、商品の履行（fulfillment）や支払いの処理など、業務機能のさまざまな部分を分散させたり外部委託したりするための仕組みを提供します。IOTPは、消費者と企業の間に事前の関係があることを必要としません。

Several errors have been noted in the IOTP v1.0 specification, particularly RFC 2801, which was the largest RFC ever issued. These are listed, with their fix, in this document.

IOTP v1.0の仕様、特にこれまでに発行された中で最大のRFCであるRFC 2801には、いくつかの誤りが指摘されています。この文書では、それらの誤りを修正とともに列挙します。

2. DTD Errata

2. DTDの正誤表

2.1. PackagedContent Element

2.1. PackagedContent要素

Attribute types are swapped.

属性の型が入れ替わっています。

OLD/INCORRECT:

誤（OLD/INCORRECT）:

   !ELEMENT PackagedContent (#PCDATA) >
   <!ATTLIST PackagedContent
            Name             CDATA     #IMPLIED
            Content          NMTOKEN   "PCDATA"
            Transform   (NONE|BASE64)  "NONE" >

   !ELEMENT PackagedContent (#PCDATA) >
   <!ATTLIST PackagedContent
            Name             CDATA     #IMPLIED
            Content          NMTOKEN   "PCDATA"
            Transform   (NONE|BASE64)  "NONE" >

NEW/CORRECT:

正（NEW/CORRECT）:

   <!ELEMENT PackagedContent (#PCDATA) >
   <!ATTLIST PackagedContent
             Name           NMTOKEN     #IMPLIED
             Content        CDATA       "PCDATA"
             Transform   (NONE|BASE64)  "NONE" >

   <!ELEMENT PackagedContent (#PCDATA) >
   <!ATTLIST PackagedContent
             Name           NMTOKEN     #IMPLIED
             Content        CDATA       "PCDATA"
             Transform   (NONE|BASE64)  "NONE" >

2.2. The Element called Attribute

2.2. Attributeという名前の要素

Incorrect element content specification syntax.

要素の内容の指定の構文が誤っています。

OLD/INCORRECT:

誤（OLD/INCORRECT）:

   <!ELEMENT Attribute ( ANY ) >
   <!ATTLIST Attribute
             type                NMTOKEN            #REQUIRED
             critical        ( true | false )       #REQUIRED
   >

   <!ELEMENT Attribute ( ANY ) >
   <!ATTLIST Attribute
             type                NMTOKEN            #REQUIRED
             critical        ( true | false )       #REQUIRED
   >

NEW/CORRECT

正（NEW/CORRECT）

   <!ELEMENT Attribute ANY >
   <!ATTLIST Attribute
             type                NMTOKEN            #REQUIRED
             critical        ( true | false )       #REQUIRED
   >

   <!ELEMENT Attribute ANY >
   <!ATTLIST Attribute
             type                NMTOKEN            #REQUIRED
             critical        ( true | false )       #REQUIRED
   >

3. Other Errata

3. その他の正誤表

3.1. Re: Combining Authentication Transactions with other Transactions

3.1. 認証トランザクションと他のトランザクションとの組み合わせについて

Section 9.1.13. page 234, restarted->continued:

セクション9.1.13、234ページ、restarted->continued:

OLD/INCORRECT:

誤（OLD/INCORRECT）:

   if the Authentication transaction is successful, then the original
   IOTP Transaction is restarted

   if the Authentication transaction is successful, then the original
   IOTP Transaction is restarted

NEW/CORRECT:

正（NEW/CORRECT）:

   if the Authentication transaction is successful, then the original
   IOTP Transaction is continued

   if the Authentication transaction is successful, then the original
   IOTP Transaction is continued

3.2. Type attribute of Element called Attribute

3.2. Attributeという名前の要素のType属性

Section 7.19.1, Page 150, insufficient list of signature types:

セクション7.19.1、150ページ、署名の種類の一覧が不十分:

OLD/INCORRECT:

誤（OLD/INCORRECT）:

   There must be one and only one Attribute Element that contains a
   Type attribute with a value of IOTP Signature Type and with
   content set to either: OfferResponse, PaymentResponse,
   DeliveryResponse, AuthenticationRequest, AuthenticationResponse,
   PingReq or PingResponse; depending on the type of the signature.

   There must be one and only one Attribute Element that contains a
   Type attribute with a value of IOTP Signature Type and with
   content set to either: OfferResponse, PaymentResponse,
   DeliveryResponse, AuthenticationRequest, AuthenticationResponse,
   PingReq or PingResponse; depending on the type of the signature.

NEW/CORRECT:

正（NEW/CORRECT）:

   There must be one and only one Attribute Element that contains a
   Type attribute with a value of IOTP Signature Type and with
   content set to either: OfferResponse, PaymentResponse,
   DeliveryResponse, AuthenticationRequest, AuthenticationResponse,
   PingReq, PingResponse, AuthenticationStatus, InquiryRequest, or
   InquiryResponse; depending on the type of the signature.

   There must be one and only one Attribute Element that contains a
   Type attribute with a value of IOTP Signature Type and with
   content set to either: OfferResponse, PaymentResponse,
   DeliveryResponse, AuthenticationRequest, AuthenticationResponse,
   PingReq, PingResponse, AuthenticationStatus, InquiryRequest, or
   InquiryResponse; depending on the type of the signature.

AND a similar change extending the list of values in Section 12.1, Page 262.

さらに、セクション12.1（262ページ）の値の一覧にも、同様の拡張を行います。

And at Section 6.1.2, Page 82, add the following:

また、セクション6.1.2（82ページ）に次のものを追加します。

   AuthenticationStatus       any role

   InquiryRequest             any role

   InquiryResponse            any role

   AuthenticationStatus       any role

   InquiryRequest             any role

   InquiryResponse            any role

4. Security Considerations

4. セキュリティーに関する考慮事項

The errata listed herein are not particularly security related. Never the less, incorrect implementations due to uncorrected errors in the specification may compromise security.

ここに挙げた正誤表は、特にセキュリティーに関係するものではありません。とはいえ、仕様の誤りが訂正されないことによる誤った実装は、セキュリティーを損なう可能性があります。
