RFC 393

Comments on TELNET Protocol Changes

RFC 393

TELNETプロトコルの変更に関するコメント

Abstract

概要

Through this RFC, I am registering my objection to two of the three suggestions for changing the TELNET protocol as described in RFC 328 and am adding my suggestion for the interpretation of the TELNET Reverse Break Control Code.

このRFCにより、私は、RFC 328で述べられているTELNETプロトコルの変更に関する3つの提案のうち2つに対して異議を表明し、あわせてTELNETのReverse Break制御コードの解釈について私の提案を追加します。

This material has not been reviewed for public release and is intended only for use with the ARPA network. It should not be quoted or cited in any publication not related to the ARPA network.

この資料は一般公開のための審査を受けておらず、ARPAネットワークでの利用だけを目的としています。ARPAネットワークに関係のない出版物で引用または参照しないでください。

1. Hide-your-input

1. Hide-your-input

This code was originally put in the TELNET protocol to give the virtual terminal the ability to simulate a real terminal which has the print suppress capability. If the terminals being used at some installations do not have the ability to disable the printing mechanism, the TELNET being used can either ignore this code or attempt to simulate the function using other means (e. g., blacking out a number of character positions and returning to the first character position). Every attempt should be made to allow a network user of a time-sharing system to have the same facilities as a local user of the time-sharing system. The specification of TELNET protocol should not limit the function of users if a function cannot be supported by all users.

このコードは、もともと、印字抑止の機能を持つ実際の端末を仮想端末が模倣できるようにするために、TELNETプロトコルに入れられました。 一部の設置場所で使われている端末が印字機構を無効にする機能を持たない場合、そこで使われているTELNETは、このコードを無視するか、ほかの手段（たとえば、いくつかの文字位置を黒く塗りつぶしてから最初の文字位置に戻るなど）を用いてその機能の模倣を試みることができます。 タイムシェアリングシステムのネットワークユーザーが、そのタイムシェアリングシステムのローカルユーザーと同じ機能を利用できるよう、あらゆる努力をすべきです。 ある機能をすべてのユーザーがサポートできないからといって、TELNETプロトコルの仕様がユーザーの機能を制限すべきではありません。

The "Hide-your-input" and "Echo" TELNET control codes provide for the support of two functions available in some time-sharing systems. The "Hide-your-input" function is really a special case of the "Echo" mode of operation where the server tells the user that the server will echo but the server does not. A separate code is used for this func- tion since some servers may support this function but may not support the full "Echo" mode of operation.

"Hide-your-input"と"Echo"のTELNET制御コードは、一部のタイムシェアリングシステムで利用できる2つの機能をサポートするためのものです。 "Hide-your-input"機能は、実際には"Echo"動作モードの特殊な場合であり、サーバーはエコーするとユーザーに伝えますが、実際にはエコーしません。 サーバーによってはこの機能をサポートしていても完全な"Echo"動作モードはサポートしていない場合があるため、この機能には別のコードが使われています。

The "Hide-your-input" and "Echo" modes of operation are disabled with the "No-echo" control. ASCII control codes could have been chosen for these functions but it was decided that the NVT ASCII control codes should only be specified for commonly used functions.

"Hide-your-input"と"Echo"の動作モードは、"No-echo"制御によって無効になります。 これらの機能にはASCII制御コードを選ぶこともできましたが、NVTのASCII制御コードはよく使われる機能に対してだけ規定すべきであると決定されました。

To indicate the number of characters for which the printing should be suppressed, the "Hide-your-input" TELNET control could be rede- fined to include a byte following the "Hide-your-input" control to indicate the number of characters for which the printing should be concealed. The "No-echo" control would still be sent so that systems with the print suppress feature would not have to count characters.

印字を抑止すべき文字数を示すために、"Hide-your-input" TELNET制御を再定義して、"Hide-your-input"制御の後ろに、印字を隠すべき文字数を示すバイトを含めるようにすることもできるでしょう。 その場合でも"No-echo"制御は送られるので、印字抑止の機能を持つシステムは文字数を数える必要はありません。

2. Data Types

2. データ型

The protocol should allow a server to support users with character codes other than ASCII, e. g., EBCDIC. The definition of an alternate character code should include the definition of the TELNET control codes. An EBCDIC code has been proposed in RFC # 109 and has been implemented on the Lincoln Laboratory 360/67. If it is desired to allow one to return to the network standard ASCII code, the non-ASCII code should contain a code to indicate return to ASCII.

プロトコルは、サーバーがASCII以外の文字コード（たとえばEBCDIC）を使うユーザーをサポートできるようにすべきです。 代替の文字コードの定義には、TELNET制御コードの定義を含めるべきです。 EBCDICのコードはRFC # 109で提案されており、Lincoln Laboratoryの360/67に実装されています。 ネットワーク標準のASCIIコードに戻れるようにしたい場合は、ASCII以外のコードにASCIIへの復帰を示すコードを含めるべきです。

3. Reverse Break

3. リバースブレーク

The code for Break is defined as a 129th ASCII data code. It is usually transmitted from a user's network virtual terminal to a server when a corresponding key (break key or attention key) is typed on the TELNET terminal and is interpreted by serving systems as that special key. Since a common function of this key is to interrupt a running process the server must be alerted to the fact that this code has been transmitted no matter when it is sent. Thus, the TELNET SYNC (TELNET data mark together with a network interrupt on the TELNET send socket) must also be trans- mitted to cause the serving process to examine the received charac- ters. The ASCII control code EOT (Octal 4) could have been chosen for the break function but his code is not interpreted by all systems. Thus, it was decided that an NVT TELNET control code should be used for this purpose.

Breakのコードは、129番目のASCIIデータコードとして定義されています。 これは通常、TELNET端末で対応するキー（ブレークキーまたはアテンションキー）が打鍵されたときに、ユーザーのネットワーク仮想端末からサーバーへ送信され、サービスを提供するシステムによってその特殊キーとして解釈されます。 このキーの一般的な機能は実行中のプロセスに割り込むことなので、このコードがいつ送られたとしても、送信されたという事実をサーバーに知らせなければなりません。 したがって、サービスを提供するプロセスに受信した文字を調べさせるために、TELNET SYNC（TELNETのデータマークと、TELNET送信ソケット上のネットワーク割り込みを組み合わせたもの）も送信しなければなりません。 ブレーク機能にはASCII制御コードのEOT（8進数の4）を選ぶこともできましたが、このコードはすべてのシステムで解釈されるわけではありません。 そのため、この目的にはNVTのTELNET制御コードを使うことに決定されました。

The use of the Break Code from server to user TELNET has not previously been defined and, thus, could be used to solve the following problems which occur with line at a time and half duplex systems. Line at a time systems do not output characters to the terminal a character at a time but, instead, wait until a line is ready for output. If a CR-LF sequence (TELNET protocol for end of line) is received it is interpreted as an end of line and the characters received are output. If characters are received which do not end with CR-LF the user TELNET does not know whether or not other characters will follow which are part of the current line. Thus, the characters received thus far must be output, without a CR-LF (new line). If an end of message code were transmitted, the user TELNET would know whether or not other characters would be received for output. The user TELNET would then print characters either when the TELNET Break control is received or when the CR-LF newline sequence is received.

サーバーからユーザーTELNETへのBreakコードの使用は、これまで定義されていませんでした。 したがって、これを、行単位のシステムや半二重のシステムで起こる次のような問題の解決に使えるでしょう。 行単位のシステムは、端末に文字を1文字ずつ出力するのではなく、1行の出力の準備ができるまで待ちます。 CR-LFシーケンス（行末を表すTELNETプロトコル）を受信すると、それは行末として解釈され、受信した文字が出力されます。 CR-LFで終わらない文字を受信した場合、ユーザーTELNETは、現在の行の一部であるほかの文字が続くかどうかがわかりません。 そのため、それまでに受信した文字を、CR-LF（改行）なしで出力しなければなりません。 もしメッセージ終端コードが送信されれば、ユーザーTELNETは、出力すべきほかの文字を受信することになるかどうかがわかります。 そうすれば、ユーザーTELNETは、TELNETのBreak制御を受信したとき、またはCR-LFの改行シーケンスを受信したときに文字を印字すればよくなります。

If the user TELNET is being run from a half duplex terminal, the terminal cannot receive input and type output at the same time. Thus, if output is received while the terminal is being used for input the TELNET program must either buffer the received characters or abort the input mode of operation to write out the received charac- ters. If characters received are written out as they are received, the terminal operation would be very similar to a full duplex terminal. This mode of operation requires that the terminal have a reverse break capability to allow the input mode to be aborted by program control.

ユーザーTELNETが半二重の端末から実行されている場合、その端末は入力の受け付けと出力の印字を同時に行えません。 したがって、端末が入力に使われている間に出力を受信した場合、TELNETプログラムは、受信した文字をバッファーに溜めるか、受信した文字を書き出すために入力動作モードを中止しなければなりません。 受信した文字を受信したそばから書き出すのであれば、端末の動作は全二重の端末とよく似たものになるでしょう。 この動作モードには、プログラム制御によって入力モードを中止できるようにする、リバースブレーク（reverse break）の機能を端末が備えている必要があります。

In some systems it is only desirable to abort the input mode of operation when a complete line is ready for output. If a string of characters received does not end with an end of line code, the characters received will not be output until after the input line is entered, i. e., the mode of operation changed from input to output. If an end of message code were transmitted, the user TELNET could abort the input mode of operation even though the end of line code was not received.

システムによっては、完全な1行の出力の準備ができたときにだけ入力動作モードを中止することが望ましい場合があります。 受信した文字列が行末コードで終わっていない場合、受信した文字は、入力行が入力された後、すなわち動作モードが入力から出力に変わった後になるまで出力されません。 もしメッセージ終端コードが送信されれば、ユーザーTELNETは、行末コードを受信していなくても入力動作モードを中止できます。

In systems which do not support the reverse break feature or if the terminal does not have this feature it is not possible to abort an input mode of operation in order to output received characters. In this case, the systems can operate in either of two modes, a) unlocked keyboard, or b) locked keyboard mode.

リバースブレーク機能をサポートしていないシステムや、端末がこの機能を持たない場合は、受信した文字を出力するために入力動作モードを中止することはできません。 この場合、システムは、a) キーボード非ロックモード、b) キーボードロックモードの2つのモードのどちらかで動作できます。

In an unlocked keyboard system, received characters are not output until the user completes an input line. An input line is completed when the end of line code is entered. This might be a CR, a LF, or a NL code. After received characters, if any, are output, the input modes is re-entered. To receive output the user must enter an input line (possibly a null line). If the user is waiting for output, he must repeatedly enter a line until the output has been received and typed. Since an input line must be entered just to receive output, it is desirable to define an input line which does not result in anything being sent to the serving system. If a null line (a line consisting of just the end of line code) is chosen for this purpose, some other input line must be defined to cause a null line to be transmitted.

キーボード非ロックのシステムでは、受信した文字は、ユーザーが入力行を完了するまで出力されません。 入力行は、行末コードが入力されたときに完了します。 これはCR、LF、NLのいずれかのコードかもしれません。 受信した文字があればそれが出力された後、再び入力モードに入ります。 出力を受け取るには、ユーザーは入力行（空行でもかまいません）を入力しなければなりません。 出力を待っている場合、ユーザーは、出力が受信されて印字されるまで、繰り返し行を入力しなければなりません。 出力を受け取るためだけに入力行を入力しなければならないので、サービスを提供するシステムに何も送られない入力行を定義しておくことが望ましいです。 この目的に空行（行末コードだけからなる行）を選んだ場合は、空行を送信させるための別の入力行を定義しなければなりません。

In a locked keyboard system, the input mode is not immediately re-entered after an input line is entered. It is re-entered only after a defined prompt is received. The prompt can be defined to be the reception of any character or can be defined to be a specific character code. If a specific code is chosen the serving site must send this code whenever the terminal should be put into input mode. If an end of message code were transmitted this code could be inter- preted to be the input prompt code.

キーボードロックのシステムでは、入力行が入力された後、すぐには入力モードに戻りません。 入力モードに戻るのは、定められたプロンプトを受信した後だけです。 プロンプトは、任意の文字の受信と定義することも、特定の文字コードと定義することもできます。 特定のコードを選んだ場合、サービスを提供するサイトは、端末を入力モードにすべきときには常にこのコードを送らなければなりません。 もしメッセージ終端コードが送信されれば、このコードを入力プロンプトのコードとして解釈できるでしょう。

In summary, three situations have been described where an end of message code would be desirable.

まとめると、メッセージ終端コードが望ましい状況として、次の3つを説明しました。

  1. To indicate when a line which does not end with CR-LF should be output for line at a time systems
  2. To indicate that the input mode in half duplex operation should be aborted so that received characters can be output
  3. As a prompt character to cause the input mode to be entered for locked keyboard half duplex systems
  1. 行単位のシステムで、CR-LFで終わらない行をいつ出力すべきかを示すため
  2. 受信した文字を出力できるように、半二重動作において入力モードを中止すべきことを示すため
  3. キーボードロック方式の半二重システムで、入力モードに入らせるためのプロンプト文字として

The ASCII TELNET control code for Break (Reverse Break) could be interpreted as an end of message code when sent from server to user.

BreakのASCII TELNET制御コード（Reverse Break）は、サーバーからユーザーに送られた場合には、メッセージ終端コードとして解釈できるでしょう。
