RFC 377

Using TSO via ARPA Network Virtual Terminal

RFC 377

ARPAネットワーク仮想端末を介したTSOの利用

A. Connecting to TSO

A. TSOへの接続

IBM's Time Sharing Option (TSO) is available at UCLA-CCN on Socket 1 using the standard Telnet protocol.

IBMのTime Sharing Option（TSO）は、UCLA-CCNのソケット1で、標準のTelnetプロトコルを使って利用できます。

  1. To access TSO, the remote user performs ICP to Socket 1 at CCN and executes the command:

            TSO CR LF
            -- --

  2. Possible responses to the TSO command are:

    1. "WELCOME TO UCLA/CCN TSO"

      followed by a herald ("!"). TSO is available. A TSO LOGON command should be entered following the herald.

    2. "TSO NOT AVAILABLE AT THIS TIME"

      The user should check the TSO schedule and verify that it should be available. If so, he can call the CCN on-line help phone, 213-825-1652 for availability information, or send a message to the operator through NETRJS.

    3. "ALL TSO PORTS BUSY"

      The user should try again after a short time. If this condition recurs frequently, notify the Technical Liaison at CCN so that more Network ports can be added.

  3. When first connected to CCN server Telnet, the user has a choice of several commands besides "TSO". The TSO-related commands are:

    HELP
    A listing of commands at this level, and other general information.
    BBOARD
    List operational notices.
  4. Local echoing (i.e., by the user site) is required.

  5. Server-Telnet will time-out and disconnect the user if:

    1. Output to the Network does not complete within 5 minutes, or
    2. An INS, DATA MARK pair does not match within 2 minutes, or
    3. TSO waits for the user to enter input for 20 minutes.

  1. TSOにアクセスするには、遠隔のユーザーはCCNのソケット1に対してICPを実行し、次のコマンドを実行します。

            TSO CR LF
            -- --

  2. TSOコマンドに対して考えられる応答は次のとおりです。

    1. 「WELCOME TO UCLA/CCN TSO」

      これに続いてヘラルド（herald、「!」）が表示されます。TSOは利用可能です。ヘラルドに続けてTSOのLOGONコマンドを入力してください。

    2. 「TSO NOT AVAILABLE AT THIS TIME」

      ユーザーはTSOのスケジュールを確認し、利用可能なはずの時間帯であるかを確かめてください。そうであれば、CCNのオンラインヘルプ電話213-825-1652に電話して利用可能かどうかの情報を得るか、NETRJSを通じてオペレーターにメッセージを送ることができます。

    3. 「ALL TSO PORTS BUSY」

      ユーザーは、しばらくしてから再試行してください。この状態が頻繁に繰り返される場合は、ネットワークのポートを増やせるように、CCNの技術連絡担当者に知らせてください。

  3. CCNのサーバーTelnetに最初に接続したとき、ユーザーは「TSO」以外にもいくつかのコマンドを選択できます。TSOに関連するコマンドは次のとおりです。

    HELP
    このレベルのコマンドの一覧と、その他の一般的な情報。
    BBOARD
    運用上のお知らせを一覧表示する。
  4. ローカルエコー（つまり、ユーザーのサイトによるエコー）が必要です。

  5. サーバーTelnetは、次の場合にタイムアウトし、ユーザーを切断します。

    1. ネットワークへの出力が5分以内に完了しない場合
    2. INSとDATA MARKの組が2分以内に対応しない場合
    3. TSOがユーザーの入力を20分間待ち続けた場合

B. Conversing with TSO

B. TSOとの対話

  1. TSO is strictly a line-at-a-time system. Input is not scanned until either an end-of-line or an INS (interrupt) is received at CCN. TSO sends the user an exclamation mark ("!") as a herald when waiting for input.
  2. The end-of-line indication for input and output lines is the standard CR LF sequence.

  3. The remote user my interrupt TSO output by sending an INS and DATA MARK (Telnet X'80'). Note to TIP users: this may be accomplished with the TIP command "SEND SYNC". Each such interrupt is passed to TSO, which interprets it as an output break, i.e., as if the user pressed the ATTention key on his 2741 while the keyboard was locked.

    On the Network, "attentions" are not used to delete lines being entered. The CCN Server-Telnet provides line editing functions for TSO users: the ASCII control CAN deletes the line being entered, while BS deletes the preceding character.

  4. There is a third interrupt case to be considered: suppose a program has placed the user's terminal into input state, but the user wants to suspend its execution and take control up a level without satisfying the pending input request. This is supposed to be accomplished by sending an INS/DATA MARK pair. Unfortunately, due to a bug in our Network interface to TSO, the interrupt will be ignored in this case. To circumvent this problem, we recommend that you define a software break string, such as "!!!!". This may be accomplished with the command:

            TERM INPUT (!!!!)

    Note that there are no quotes around the string. You can enter this command when you first log on, and it will remain in effect for the session (or until you issue a new TERM command). Then any input line containing four successive exclamation points will be interpreted as if an interrupt (attention) had been sent. If that line contains other characters preceding the exclamation marks, the latter will be interpreted as line delete; otherwise, the result will be to take control up a level.

  1. TSOは厳密に1行ずつ処理するシステムです。CCNで行末かINS（割り込み）のどちらかを受信するまで、入力は走査されません。TSOは入力を待っているとき、ヘラルドとして感嘆符（「!」）をユーザーに送ります。
  2. 入力行と出力行の行末を示すのは、標準のCR LFシーケンスです。

  3. 遠隔のユーザーは、INSとDATA MARK（TelnetのX'80'）を送ることで、TSOの出力に割り込めます。TIPのユーザーへの注意: これはTIPコマンド「SEND SYNC」で実現できます。このような割り込みはそれぞれTSOに渡され、TSOはそれを出力の中断として解釈します。つまり、キーボードがロックされているときに、ユーザーが2741のATTentionキーを押したかのように解釈します。

    ネットワーク上では、入力中の行を削除するために「アテンション」は使いません。CCNのサーバーTelnetは、TSOのユーザー向けに行編集機能を提供しています。ASCIIの制御文字CANは入力中の行を削除し、BSは直前の文字を削除します。

  4. 考慮すべき3つ目の割り込みの場合があります。プログラムがユーザーの端末を入力状態にしているが、ユーザーは保留中の入力要求に応えずに、そのプログラムの実行を中断して1つ上のレベルに制御を移したい場合を考えてください。本来は、INSとDATA MARKの組を送ることでこれを実現するはずです。残念ながら、TSOへのネットワークインターフェイスにバグがあるため、この場合には割り込みが無視されてしまいます。この問題を回避するために、「!!!!」のようなソフトウェアによる中断文字列を定義することを推奨します。これは次のコマンドで設定できます。

            TERM INPUT (!!!!)

    文字列を引用符で囲まないことに注意してください。このコマンドは最初にログオンしたときに入力でき、そのセッションの間（または新しいTERMコマンドを発行するまで）有効です。その後は、感嘆符が4つ連続して含まれる入力行は、割り込み（アテンション）が送られたかのように解釈されます。その行の感嘆符の前に他の文字が含まれていれば、感嘆符は行の削除として解釈されます。そうでなければ、1つ上のレベルに制御が移ります。

C. Character Sets

C. 文字セット

  1. Both upper and lower case input are allowed, but the server Telnet will translate all lower case to upper. Output is normally upper case.

  2. Line-editing is provided by the Server-Telnet program before passing the input line to TSO.

    Table 1
    INPUT ACTION
    CAN (control X) delete current line.
    BS (control H) delete previous character on same line
    (NOTE: Telnet control characters are not deleted; they are bypassed in the backspace operation.)
    HT (control I) insert one space in input.

    All other ASCII controls are deleted from the input before line-editing is performed.

  3. Input lines are translated to EBCDIC by the rules used for a NETRJS remote operator console (see Appendix B in RFC189). Specifically:

    1. ASCII controls are ignored except for BS, CAN, HT, and CR LF.

    2. The following correspondence is used for the EBCDIC graphics not in ASCII:

      [In the original, the ASCII and EBCDIC graphics were handwritten; in this version the ASCII graphics are typed and the EBCDIC graphics are omitted.]

      Table 2
      ASCII TSO
      ! (Vertical bar)
      ~ (EBCDIC "not")
      \ (Cent)
    3. The six ASCII graphics not in EBCDIC are translated into EBCDIC question marks.
  4. All Telnet controls except DATA MARK are ignored.
  1. 入力には大文字と小文字の両方を使えますが、サーバーTelnetは小文字をすべて大文字に変換します。出力は通常は大文字です。

  2. 行編集は、入力行をTSOに渡す前に、サーバーTelnetプログラムによって行われます。

    表1
    入力 動作
    CAN (control X) 現在の行を削除する。
    BS (control H) 同じ行の直前の文字を削除する
    （注: Telnetの制御文字は削除されません。バックスペース操作では読み飛ばされます。）
    HT (control I) 入力に空白を1つ挿入する。

    その他のASCII制御文字は、行編集を行う前にすべて入力から削除されます。

  3. 入力行は、NETRJSのリモートオペレーターコンソールで使われる規則（RFC189の付録Bを参照）によってEBCDICに変換されます。具体的には次のとおりです。

    1. ASCIIの制御文字は、BS、CAN、HT、CR LFを除いて無視されます。

    2. ASCIIにないEBCDICの図形文字には、次の対応を使います。

      [原本ではASCIIとEBCDICの図形文字は手書きでした。この版ではASCIIの図形文字は活字にし、EBCDICの図形文字は省略しています。]

      表2
      ASCII TSO
      ! （縦棒）
      ~ （EBCDICの「not」記号）
      \ （セント記号）
    3. EBCDICにない6つのASCII図形文字は、EBCDICの疑問符に変換されます。
  4. DATA MARK以外のTelnetの制御はすべて無視されます。
