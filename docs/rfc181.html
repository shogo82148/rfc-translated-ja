RFC 181

Modifications to RFC #177

RFC 181

RFC 177の修正

Abstract

概要

This RFC is intended to modifiy the proposal for a device independent graphical display description discussed in RFC #177. Thanks are due to Stan Mantiply of Ames for his ideas. The main changes are in the defini- tion of coordinate areas to avoid one problem encountered with the old definition and to provide more flexibility. Terms used are those defined in RFC #177.

このRFCは、RFC #177で論じた、デバイスに依存しないグラフィック表示記述の提案を修正することを目的としています。アイデアを提供してくれたAmesのStan Mantiplyに感謝します。主な変更点は座標領域の定義で、古い定義で生じていた問題の1つを回避し、より柔軟にするためのものです。使用する用語はRFC #177で定義されたものです。

The problem encountered in the previous proposal was that the areas of the NGS (network standard graphics screen), which were supposed to be absolute boundaries, could be crossed when a list was executed within that space. Scaling of lists was also awkwardly done with specific commands in the network standard graphic display list (NGDL).

以前の提案で生じていた問題は、絶対的な境界となるはずだったNGS（network standard graphics screen、ネットワーク標準グラフィックス画面）の領域が、その空間内でリストを実行したときに越えられてしまう可能性があることでした。また、リストの拡大縮小は、ネットワーク標準グラフィック表示リスト（network standard graphic display list: NGDL）の特定のコマンドによって、ぎこちなく行われていました。

Coordinates will still be defined with 16 bit unsigned normalized fractions. This will leave the resolution of the picture up to the device which eventually receives the NGDL. The values will not now be tied to the NGS or an area of the screen, but will be fractional displace- ments from the lower left corner of the screen, an area, or an image space.

座標は、引き続き16ビットの符号なし正規化小数で定義します。これにより、画像の解像度は、最終的にNGDLを受け取るデバイスに委ねられます。値は、もはやNGSや画面の領域に結び付けられるのではなく、画面、領域、またはイメージ空間の左下隅からの小数による変位になります。

Areas will still be rectangular and will be allowed to overlap, but not contain another area completely. The attributes of an area are: its 16 bit integer name, by which it may be manipulated, two (x,y) pairs which will define its lower left and upper right corners with respect to the NGS. No list executed in an area may cross its boundaries. Within an area may be any number of image spaces which are dynamically defined with the execution of a list and define its relationship to the containing area.

領域は引き続き長方形とし、重なり合うことは許しますが、別の領域を完全に含むことは許しません。領域の属性は、その領域を操作するために使う16ビット整数の名前と、NGSに対する左下隅と右上隅を定義する2つの(x,y)の組です。領域内で実行されるリストは、その境界を越えることはできません。領域内には任意の数のイメージ空間を置くことができます。イメージ空間はリストの実行に伴って動的に定義され、それを含む領域との関係を定義します。

The list item types 7 and 8 shall be changed from EXECUTE LIST (Name,x,y) and COPY LIST (Name,x,y) to EXECUTE LIST (Name,(Xl,Yl),(Xr,Yr)) and COPY LIST (Name,(Xl,Yl),(Xr,Yr)) respectively. The coordinate pairs (Xl,Yl) and (Xr,Yr) define the image area of that list as displacements from the lower left corner of the containing area. If the list executes other lists within it, their image areas are defined as displacements from the image area of the list containing the execute command. Thus each list can be scaled differently each time it is executed and may even be distorted if the image area defined has different ratios of X and Y lengths. Lists executed within other lists will have the same relationship to their containing lists regardless of that lists's rela- tionship to the NGS area. Since the initial image area is defined rela- tive to the NGSD area, no overlaps can occur.

リスト項目の種類7と8は、それぞれEXECUTE LIST (Name,x,y)とCOPY LIST (Name,x,y)から、EXECUTE LIST (Name,(Xl,Yl),(Xr,Yr))とCOPY LIST (Name,(Xl,Yl),(Xr,Yr))に変更するものとします。座標の組(Xl,Yl)と(Xr,Yr)は、そのリストのイメージ領域を、それを含む領域の左下隅からの変位として定義します。そのリストが内部でほかのリストを実行する場合、それらのイメージ領域は、実行コマンドを含むリストのイメージ領域からの変位として定義されます。したがって、各リストは実行されるたびに異なる倍率で拡大縮小でき、定義されたイメージ領域のXとYの長さの比率が異なれば、ゆがめることさえできます。ほかのリストの中で実行されるリストは、そのリストとNGS領域との関係にかかわらず、それを含むリストに対して同じ関係を持ちます。最初のイメージ領域はNGSD領域を基準として定義されるので、重なりが生じることはありません。

If a table (item type = 9) is executed, the coordinate pairs it contains are relative to whatever area is valid at the time of its execution.

テーブル（項目の種類 = 9）が実行された場合、そのテーブルに含まれる座標の組は、実行時に有効な領域を基準とします。

A change to the NGLI is implied. Whenever an EXECUTE LIST command is encountered, the current state is saved, a new current origin is computed, NGLP is reset to zero, and new X and Y scale factors must be calculated to transform the coordinates in the new list to actual screen coor- dinates.

これは、NGLIの変更を意味します。EXECUTE LISTコマンドに出会うたびに、現在の状態を保存し、新しい現在の原点を計算し、NGLPを0にリセットし、新しいリスト内の座標を実際の画面座標に変換するための新しいXとYの倍率を計算しなければなりません。

Another construct for graphics processing will be added. This is the mode stack for each graphics mode. It will be used for saving and restoring character and vector mode values as lists are recursively executed. Four new list items will be added to handle these operations.

グラフィックス処理のための別の構成要素を追加します。それは、グラフィックスモードごとのモードスタックです。これは、リストが再帰的に実行される際に、文字モードとベクターモードの値を保存および復元するために使われます。これらの操作を扱うために、4つの新しいリスト項目を追加します。

   PUSH CHARACTER MODE    (item type = 14)
   PUSH VECTOR MODE       (item type = 15)
   POP CHARACTER MODE     (item type = 16)
   POP VECTOR MODE        (item type = 17)

   PUSH CHARACTER MODE    (item type = 14)
   PUSH VECTOR MODE       (item type = 15)
   POP CHARACTER MODE     (item type = 16)
   POP VECTOR MODE        (item type = 17)

The DEFINE LIST command (type = 1) shall have its parameters changed. It shall have two parameters, a 16 bit integer name, by which it may be manipulated and referenced, and a 16 bit integer defining the length of the list in bytes rather than items. This change is intended to make processing the NGDS easier and will eliminate the TABLE item (type = 11).

DEFINE LISTコマンド（種類 = 1）のパラメーターを変更するものとします。このコマンドは2つのパラメーターを持つものとします。1つは、そのリストを操作したり参照したりするために使う16ビット整数の名前で、もう1つは、リストの長さを項目数ではなくバイト数で定義する16ビット整数です。この変更は、NGDSの処理を容易にすることを目的としており、TABLE項目（種類 = 11）は不要になります。

The first three list items should have the WORD IMAGE eliminated from them, since they are defining NGS areas now.

最初の3つのリスト項目は、今やNGS領域を定義するものになったので、IMAGEという語を取り除くべきです。

The list command DEFINE IMAGE ARE (type = 2) shall be changed to DEFINE AREA for the same reasons.

同じ理由で、リストコマンドDEFINE IMAGE ARE（種類 = 2）はDEFINE AREAに変更するものとします。
