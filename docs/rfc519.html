RFC 519

Resource Evaluation

RFC 519

資源の評価

Abstract

概要

In the spirit of RFC # 369, Evaluation of ARPANET resources, a new test group was organized at UCSB to take a detailed look at specific network resources and develop initial site dependent and function dependent MINIMAN's (Concise User Manuals). As the group was again composed of novices, initial effort revolved about basic procedural indoctrination. In the period between January and March 1973 a number of resources were investigated with varying degrees of success, as to availability, proper usage, sample problem solutions, and access to help and documentation. Included in this paper are a summary of the projects undertaken, initial suggestions at MINIMAN composition, and suggestions for future test groups. As these groups are attempting to perform a useful function for the ARPANET community, comments and suggestions are requested. Copies of the reports described herein are available on request from the Computer Systems Laboratory at UCSB.

RFC 369「Evaluation of ARPANET resources」の精神にのっとり、特定のネットワーク資源を詳しく調べ、サイトに依存したものと機能に依存したものの初期のMINIMAN（簡潔なユーザーマニュアル）を作成するために、UCSBで新しいテストグループが組織されました。このグループもまた初心者で構成されていたため、初期の取り組みは基本的な手順を身につけることが中心でした。1973年1月から3月までの期間に、いくつかの資源について、可用性、適切な使い方、例題の解法、ヘルプや文書へのアクセスといった点を調査し、その成果の程度はさまざまでした。この文書には、取り組んだプロジェクトの概要、MINIMANの構成に関する初期の提案、将来のテストグループへの提案が含まれています。これらのグループはARPANETコミュニティーのために有用な役割を果たそうとしているので、コメントと提案をお待ちしています。ここで説明しているレポートの写しは、UCSBのComputer Systems Laboratoryに依頼すれば入手できます。

Resources Investigated by the Group

グループが調査した資源

I. APL
APL was investigated primarily at MULTICS. UCSD was also scheduled for evaluation but not carried out. APL at MULTICS was used to solve a few trivial problems. Most effort revolved about the difficult task of obtaining any available documentation. The octal codes for APL characters were obtained and mapped into the OLS keyboard. A side goal of the project, the comparison of APL with OLS, was begun but progressed very little.
II. Basic
Basic was investigated at a number of TENEX sites. Differences between sites were pointed out and necessary file manipulation commands were documented. An integration problem was written at one site, sent via FTP to another site, and then run again to show comparative execution times and compatability. Non-PDP/10 sites were investigated but no report was submitted.
III. TSO
IBM's Time Sharing option was exercised at UCLA-CCN. Interesting results were obtained regarding cost and execution time. Available commands were documented and a PL/1 program was written and executed.
IV. MIT-MATHLAB
This, the most successful of the projects, involved documentation of help, file manipulation, and MACSYMA access and an original research project in resource sharing. A recursive problem in pattern recognition and a triple integration were solved to demonstrate MACSYMA generated expressions into user programs on the OLS. More information on this project is forthcoming.
V. Local User Guide
A first pass network users manual was completed for UCSB users. In it are described console access and settings, character mappings, current servers, users and TIPs, and error conditions. Following minor revisions this guide will be distributed to local users.
VI. Local IMLAC Access to Network
Access to network graphics programs was attempted with a local IMLAC. Due to the non-uniformity of network IMLACs very little success was obtained. However, a program to access SRI-ARC's NLS was compiled and loaded from NIC and attempts were made to iron out the bugs. In addition a project was begun to maintain an IMLAC library and compiler locally for network usage. As in the other projects, basic operating procedures were documented.
VII. Harvard Graphics
Several attempts were made to learn of availability of graphics access to organic molecule synthesis programs but no response could be generated. This project was eventually abandoned.
I. APL
APLは主にMULTICSで調査しました。UCSDも評価する予定でしたが、実施されませんでした。MULTICSのAPLを使って、いくつかの簡単な問題を解きました。取り組みの大部分は、利用可能な文書を入手するという困難な作業に費やされました。APLの文字の8進コードを入手し、OLSのキーボードにマッピングしました。このプロジェクトの副次的な目標であったAPLとOLSの比較は、着手したもののほとんど進みませんでした。
II. Basic
Basicは、いくつかのTENEXサイトで調査しました。サイト間の違いを指摘し、必要なファイル操作コマンドを文書化しました。あるサイトで積分の問題を書き、FTPで別のサイトに送ってから再び実行し、実行時間と互換性を比較しました。PDP/10以外のサイトも調査しましたが、レポートは提出されませんでした。
III. TSO
UCLA-CCNで、IBMのTime Sharing Option（TSO）を試しました。コストと実行時間について興味深い結果が得られました。利用可能なコマンドを文書化し、PL/1のプログラムを書いて実行しました。
IV. MIT-MATHLAB
プロジェクトの中で最も成功したこのプロジェクトでは、ヘルプ、ファイル操作、MACSYMAへのアクセスについての文書化と、資源共有に関する独自の研究プロジェクトを行いました。MACSYMAが生成した式をOLS上のユーザープログラムに取り込めることを示すため、パターン認識における再帰的な問題と三重積分を解きました。このプロジェクトに関する詳しい情報は近日中にお知らせします。
V. ローカルユーザーガイド
UCSBのユーザー向けに、ネットワークユーザーマニュアルの初版を完成させました。このマニュアルでは、コンソールのアクセスと設定、文字のマッピング、現在のサーバー、ユーザーとTIP、エラー状態について説明しています。軽微な修正を加えた後、このガイドはローカルのユーザーに配布される予定です。
VI. ローカルのIMLACからのネットワークへのアクセス
ローカルのIMLACを使って、ネットワーク上のグラフィックスプログラムへのアクセスを試みました。ネットワーク上のIMLACが統一されていないため、ほとんど成功しませんでした。しかし、SRI-ARCのNLSにアクセスするためのプログラムをNICからコンパイルしてロードし、バグを取り除く試みを行いました。さらに、ネットワークで利用するためのIMLACのライブラリーとコンパイラーをローカルで保守するプロジェクトを開始しました。ほかのプロジェクトと同様に、基本的な操作手順を文書化しました。
VII. Harvard Graphics
有機分子合成プログラムへのグラフィックスによるアクセスが利用可能かどうかを知るために何度か試みましたが、何の反応も得られませんでした。このプロジェクトは最終的に断念しました。

MINIMAN Composition

MINIMANの構成

As mentioned in a previous report, concise manuals are needed for network resources so that uniniated users may gain basic familiarity with foreign systems. In addition, manuals which describe specific network wide functions, such as Fortran compilors, are needed if resource sharing is to become a real trait of the ARPANET. For the resources evaluated, each group member submitted two reports analagous to the two types of MINIMANS needed in the network. The headings and format of the reports will be included here to stimulate future discussion on MINIMAN composition.

以前のレポートで述べたように、初心者のユーザーがほかのシステムに基本的に慣れることができるよう、ネットワーク資源のための簡潔なマニュアルが必要です。さらに、資源共有をARPANETの真の特性とするためには、Fortranコンパイラーのような、ネットワーク全体にわたる特定の機能を説明するマニュアルが必要です。評価した資源について、グループの各メンバーは、ネットワークで必要とされる2種類のMINIMANに相当する2つのレポートを提出しました。MINIMANの構成に関する今後の議論を促すために、レポートの見出しと形式をここに示します。

REPORT # 1: Online Help for [a specific host computer]

レポート1：[特定のホストコンピューター]のオンラインヘルプ

  1. Connection, Login, and Optimal TELNET Settings
  2. Help Files
  3. Job Status
  4. Time of Day
  5. Time/Money Used/Left

  6. Interpersonal Communications

    1. Console Linking
    2. Location of Users
    3. Mail Facilities
    4. Access to Operator and/or Consultants
  7. Warnings or Unfriendly User Behavior
  8. Useful References and Documentation
  1. 接続、ログイン、最適なTELNETの設定
  2. ヘルプファイル
  3. ジョブの状態
  4. 時刻
  5. 使用した時間と費用／残りの時間と費用

  6. 人と人とのコミュニケーション

    1. コンソールのリンク
    2. ユーザーの所在
    3. メール機能
    4. オペレーターやコンサルタントへの連絡手段
  7. 注意事項、またはユーザーに不親切な挙動
  8. 有用な参考資料と文書

REPORT #2: How to Use [a specific resource]

レポート2：[特定の資源]の使い方

  1. Table of Contents
  2. Access and Usage (or How to Start and Stop)
  3. Editing Commands and File Structures
  4. Documentation, Location, and Cost
  5. Sample Solutions and Significant Problems

  6. Appendices

    1. Special Characters and Terminal Settings
    2. Similarities and Differences from Site to Site
  1. 目次
  2. アクセスと使い方（または開始と終了の方法）
  3. 編集コマンドとファイル構造
  4. 文書、その所在、費用
  5. 解法の例と重要な問題

  6. 付録

    1. 特殊文字と端末の設定
    2. サイトごとの類似点と相違点

Future Test Groups

将来のテストグループ

A number of projects are envisioned for future resource evaluators and include:

将来の資源評価者のために、次のようなプロジェクトがいくつか想定されています。

  1. Complete evaluation of APL at MULTICS and UCSD with comparison to the On-Line System (OLS).
  2. Investigate BASIC in depth, network wide.
  3. Evaluate other symbolic manipulation programs such as REDUCE.
  4. Summarize all games available in the network.
  5. Find and evaluate specific application programs such as ZOG or the weather data base at CCA.
  1. MULTICSとUCSDのAPLを完全に評価し、On-Line System（OLS）と比較する。
  2. ネットワーク全体にわたって、BASICを詳しく調査する。
  3. REDUCEなど、ほかの数式処理プログラムを評価する。
  4. ネットワークで利用できるすべてのゲームをまとめる。
  5. ZOGやCCAの気象データベースのような、特定のアプリケーションプログラムを見つけて評価する。

The projects undertaken will be determined in part by local interests. But a serious effort is being made for reports to accompany each evaluation.

取り組むプロジェクトは、ローカルの関心によって部分的に決まります。ただし、各評価にレポートを添えるよう真剣に取り組んでいます。

Conclusion

結論

Good results have been obtained from the two test groups thus far. Although composed of novices, as far as network familiarity is concerned, the groups have been able to produce data and reports which benefit the network community. The reports run the gambit from poor to excellent, but even the poorer ones have generated results by motivating more knowledgeable system personnel to find time to write the report in the "right" way. All data and reports compiled by these groups are available to interested network users. In addition, any information or documentation or manuals which might fit into the framework of the MINIMAN is requested from the network community. As this information begins to be collected, the network may truly start to become a resource sharing network.

これまでの2つのテストグループからは良い結果が得られています。ネットワークへの習熟という点では初心者で構成されていたにもかかわらず、グループはネットワークコミュニティーに役立つデータとレポートを作成できました。レポートの出来は不十分なものから優れたものまでさまざまですが、不十分なものであっても、より知識のあるシステム担当者に時間を割いて「正しい」方法でレポートを書いてもらうきっかけとなり、成果を生んでいます。これらのグループがまとめたすべてのデータとレポートは、関心のあるネットワークユーザーが利用できます。さらに、MINIMANの枠組みに合いそうな情報、文書、マニュアルがあれば、ネットワークコミュニティーから提供していただくようお願いします。こうした情報が集まり始めれば、ネットワークは真に資源共有のネットワークになり始めるでしょう。
