RFC 8268

More Modular Exponentiation (MODP) Diffie-Hellman (DH) Key Exchange (KEX) Groups for Secure Shell (SSH)

RFC 8268

SSH（Secure Shell）のためのさらなるべき乗剰余（MODP）Diffie-Hellman（DH）鍵交換（KEX）グループ

Abstract

概要

This document defines added Modular Exponentiation (MODP) groups for the Secure Shell (SSH) protocol using SHA-2 hashes. This document updates RFC 4250. This document updates RFC 4253 by correcting an error regarding checking the Peer's DH Public Key.

この文書は、SHA-2ハッシュを使用するSSH（Secure Shell）プロトコルのために、べき乗剰余（MODP）グループを追加定義します。この文書はRFC 4250を更新します。また、この文書は、ピアのDH公開鍵の検査に関する誤りを訂正することにより、RFC 4253を更新します。

1. Overview and Rationale

1. 概要と論拠

Secure Shell (SSH) is a common protocol for secure communication on the Internet. Security protocols and primitives are an active area for research and help to suggest updates to SSH.

SSH（Secure Shell）は、インターネット上の安全な通信のための一般的なプロトコルです。セキュリティープロトコルとプリミティブは活発な研究分野であり、SSHの更新を提案する助けになっています。

Section 8 of [RFC4253] contains a small error in point 3 regarding checking the Peer's DH Public Key. Section 4 of this document provides the correction.

[RFC4253]のセクション8には、ピアのDH公開鍵の検査に関して、項目3に小さな誤りがあります。この文書のセクション4で、その訂正を示します。

Due to security concerns with SHA-1 [RFC6194] and with MODP groups with less than 2048 bits [NIST-SP-800-131Ar1], implementers and users should request support for larger Diffie-Hellman (DH) MODP group sizes with data-integrity verification by using the SHA-2 family of secure hash algorithms and by having MODP groups provide more security. The use of larger MODP groups and the move to the SHA-2 family of hashes are important features to strengthen the key exchange algorithms available to the SSH client and server.

SHA-1 [RFC6194]と、2048ビット未満のMODPグループ[NIST-SP-800-131Ar1]には、セキュリティー上の懸念があるため、実装者とユーザーは、SHA-2ファミリーのセキュアハッシュアルゴリズムを使用してデータ完全性検証を行い、より高いセキュリティーを提供するMODPグループを用いることで、より大きなDiffie-Hellman（DH）MODPグループサイズのサポートを要求すべきです。より大きなMODPグループの使用と、SHA-2ファミリーのハッシュへの移行は、SSHクライアントとサーバーが利用できる鍵交換アルゴリズムを強化するための重要な特徴です。

DH primes being adopted by this document are all "safe primes" such that p = 2q + 1 where q is also a prime. New MODP groups are being introduced starting with the MODP 3072-bit group15. All use SHA512 as the hash algorithm.

この文書で採用するDHの素数はすべて「安全素数（safe prime）」であり、qも素数であるようなp = 2q + 1です。新しいMODPグループは、MODP 3072ビットのgroup15から始めて導入されます。これらはすべて、ハッシュアルゴリズムとしてSHA512を使用します。

The DH 2048-bit MODP group14 is already present in most SSH implementations and most implementations already have a SHA256 implementation, so "diffie-hellman-group14-sha256" is provided as easy to implement.

DH 2048ビットMODP group14は、ほとんどのSSH実装にすでに存在し、ほとんどの実装はすでにSHA256の実装を持っているため、"diffie-hellman-group14-sha256"は実装が容易なものとして提供されます。

It is intended that these new MODP groups with SHA-2-based hashes update Section 6.4 of [RFC4253] and Section 4.10 of [RFC4250].

SHA-2ベースのハッシュを使用するこれらの新しいMODPグループは、[RFC4253]のセクション6.4と[RFC4250]のセクション4.10を更新することを意図しています。

The United States Information Assurance Directorate (IAD) at the National Security Agency (NSA) has published "Commercial National Security Algorithm Suite and Quantum Computing Frequently Asked Questions". [MFQ-U-OO-815099-15] is addressed to organizations that run classified or unclassified national security systems (NSS) and vendors that build products used in NSS.

米国国家安全保障局（NSA）の情報保証局（IAD）は、「Commercial National Security Algorithm Suite and Quantum Computing Frequently Asked Questions」を公開しています。[MFQ-U-OO-815099-15]は、機密または非機密の国家安全保障システム（NSS）を運用する組織と、NSSで使用される製品を構築するベンダーを対象としています。

This FAQ document indicates that NSS should no longer use:

このFAQ文書は、NSSでは次のものをもはや使用すべきでないとしています。

  • Elliptic Curve Diffie-Hellman (ECDH) and Elliptic Curve Digital Signature Algorithm (ECDSA) with NIST P-256. (For SSH, this would suggest avoiding [RFC5656] Key Exchange Algorithm "ecdh-sha2-nistp256" and Public Key Algorithm "ecdsa-sha2-nistp256".)
  • SHA-256 (For SSH, this would suggest avoiding any Key Exchange Method using SHA1, SHA224, or SHA256 in favor of using SHA384 or SHA512.)
  • AES-128 (For SSH, this would suggest avoiding Encryption Algorithms [RFC4253] "aes128-cbc" and [RFC4344] "aes128-ctr".)
  • RSA with 2048-bit keys (For SSH, this would suggest avoiding [RFC4253] "ssh-rsa" using RSA with SHA1 as well as [RFC6187] "x509v3-rsa2048-sha256" as well as any other RSA key that has a length less than 3072-bits or uses a hash less than SHA384.)
  • Diffie-Hellman with 2048-bit keys (For SSH, this would suggest avoiding use of [RFC4253] both of "diffie-hellman-group1-sha1" and "diffie-hellman-group14-sha1" as well as avoiding "diffie-hellman-group14-sha256" added by this document.)
  • NIST P-256を用いる楕円曲線Diffie-Hellman（ECDH）および楕円曲線デジタル署名アルゴリズム（ECDSA）。（SSHについては、[RFC5656]の鍵交換アルゴリズム"ecdh-sha2-nistp256"と公開鍵アルゴリズム"ecdsa-sha2-nistp256"を避けることを示唆します。）
  • SHA-256（SSHについては、SHA1、SHA224、SHA256を使用するすべての鍵交換方式を避け、SHA384またはSHA512を使用することを示唆します。）
  • AES-128（SSHについては、[RFC4253]の暗号化アルゴリズム"aes128-cbc"と[RFC4344]の"aes128-ctr"を避けることを示唆します。）
  • 2048ビット鍵のRSA（SSHについては、SHA1とともにRSAを使用する[RFC4253]の"ssh-rsa"、[RFC6187]の"x509v3-rsa2048-sha256"、さらに長さが3072ビット未満であるか、SHA384より弱いハッシュを使用するその他のRSA鍵を避けることを示唆します。）
  • 2048ビット鍵のDiffie-Hellman（SSHについては、[RFC4253]の"diffie-hellman-group1-sha1"と"diffie-hellman-group14-sha1"の両方の使用を避け、さらにこの文書で追加する"diffie-hellman-group14-sha256"も避けることを示唆します。）

The FAQ also states that NSS users should select DH groups based upon well-established and validated parameter sets that comply with the minimum required sizes. Some specific examples include:

このFAQはまた、NSSのユーザーは、必要な最小サイズを満たす、確立され検証されたパラメーターセットに基づいてDHグループを選択すべきであるとしています。具体例には次のものがあります。

  • Elliptic Curves are currently restricted to the NIST P-384 group only for both ECDH and ECDSA, in accordance with existing NIST and National Information Assurance Partnership (NIAP) standards. (For SSH, this means using [RFC5656] "ecdh-sha2-nistp384" for key exchange and "ecdsa-sha2-nistp384" for Public Key Algorithm Names.)
  • RSA moduli should have a minimum size of 3072 bits (other than the noted PKI exception), and keys should be generated in accordance with all relevant NIST standards.
  • For Diffie-Hellman, use a Diffie-Hellman prime modulus of at least 3072 bits. (For bit sizes as specified in [RFC3526], this would allow for any of group15, group16, group17, group18 to be used.)
  • 楕円曲線は現在、既存のNISTおよびNational Information Assurance Partnership（NIAP）の標準に従い、ECDHとECDSAの両方についてNIST P-384グループのみに制限されています。（SSHについては、鍵交換に[RFC5656]の"ecdh-sha2-nistp384"を、公開鍵アルゴリズム名に"ecdsa-sha2-nistp384"を使用することを意味します。）
  • RSAのモジュラスは最小で3072ビットのサイズであるべきであり（前述のPKIの例外を除く）、鍵は関連するすべてのNIST標準に従って生成すべきです。
  • Diffie-Hellmanについては、3072ビット以上のDiffie-Hellman素数モジュラスを使用します。（[RFC3526]で規定されたビットサイズについては、group15、group16、group17、group18のいずれも使用できることになります。）

Although SSH may not always be used to protect Top Secret communications, this document adopts the use of the DH groups provided as an example in the FAQ as well as the use of SHA512 rather than SHA256 for the new DH groups.

SSHは常にトップシークレット（Top Secret）の通信の保護に使用されるとは限りませんが、この文書では、FAQで例として示されたDHグループの使用と、新しいDHグループについてSHA256ではなくSHA512を使用することを採用します。

3. Key Exchange Algorithms

3. 鍵交換アルゴリズム

This document adds some new Key Exchange Algorithm Method Names to what originally appeared in [RFC4253] and [RFC4250].

この文書は、もともと[RFC4253]と[RFC4250]に記載されていたものに、いくつかの新しい鍵交換アルゴリズム方式名を追加します。

This document adopts the style and conventions of [RFC4253] in specifying how the use of new data key exchange is indicated in SSH.

この文書は、新しいデータ鍵交換の使用をSSHでどのように示すかを規定するにあたり、[RFC4253]のスタイルと規則を採用します。

The following new key exchange method algorithms are defined:

次の新しい鍵交換方式のアルゴリズムを定義します。

  • diffie-hellman-group14-sha256
  • diffie-hellman-group15-sha512
  • diffie-hellman-group16-sha512
  • diffie-hellman-group17-sha512
  • diffie-hellman-group18-sha512
  • diffie-hellman-group14-sha256
  • diffie-hellman-group15-sha512
  • diffie-hellman-group16-sha512
  • diffie-hellman-group17-sha512
  • diffie-hellman-group18-sha512

The SHA-2 family of secure hash algorithms is defined in [RFC6234].

SHA-2ファミリーのセキュアハッシュアルゴリズムは、[RFC6234]で定義されています。

The method of key exchange used for the name "diffie-hellman-group14-sha256" is the same as that for "diffie-hellman-group14-sha1" except that the SHA256 hash algorithm is used. It is recommended that "diffie-hellman-group14-sha256" SHOULD be supported to smooth the transition to newer group sizes.

"diffie-hellman-group14-sha256"という名前に使用される鍵交換の方式は、SHA256ハッシュアルゴリズムを使用する点を除いて、"diffie-hellman-group14-sha1"のものと同じです。より新しいグループサイズへの移行を円滑にするため、"diffie-hellman-group14-sha256"はサポートされるべきです（SHOULD）。

The group15 through group18 names are the same as those specified in [RFC3526]: 3072-bit MODP group15, 4096-bit MODP group16, 6144-bit MODP group17, and 8192-bit MODP group18.

group15からgroup18までの名前は、[RFC3526]で規定されているもの、すなわち3072ビットMODP group15、4096ビットMODP group16、6144ビットMODP group17、8192ビットMODP group18と同じです。

The SHA512 algorithm is to be used when "sha512" is specified as a part of the key exchange method name.

鍵交換方式名の一部として"sha512"が指定されている場合は、SHA512アルゴリズムを使用します。

4. Checking the Peer's DH Public Key

4. ピアのDH公開鍵の検査

Section 8 of [RFC4253] contains a small error in point 3. When checking e (client Public Key) and f (server Public Key) values, an incorrect range is provided. The erroneous text is:

[RFC4253]のセクション8には、項目3に小さな誤りがあります。e（クライアントの公開鍵）とf（サーバーの公開鍵）の値を検査する際の範囲が誤っています。誤りのあるテキストは次のとおりです。

Values of 'e' or 'f' that are not in the range [1, p-1] MUST NOT be sent or accepted by either side. If this condition is violated, the key exchange fails.

範囲[1, p-1]にない'e'または'f'の値は、どちらの側も送信または受け入れてはなりません（MUST NOT）。この条件に違反した場合、鍵交換は失敗します。

The problem is that the range should have been an open interval excluding the endpoint values. (i.e., "(1, p-1)"). This document amends that document text as follows:

問題は、この範囲が端点の値を除いた開区間（すなわち「(1, p-1)」）であるべきだったことです。この文書は、その文書のテキストを次のように修正します。

DH Public Key values MUST be checked and both conditions:

   1 < e < p-1

   1 < f < p-1

MUST be true. Values not within these bounds MUST NOT be sent or accepted by either side. If either one of these conditions is violated, then the key exchange fails.

DH公開鍵の値を検査しなければなりません（MUST）。そして、次の両方の条件

   1 < e < p-1

   1 < f < p-1

が真でなければなりません（MUST）。この範囲内にない値は、どちらの側も送信または受け入れてはなりません（MUST NOT）。これらの条件のいずれか一方でも違反した場合、鍵交換は失敗します。

This simple check ensures that:

この単純な検査により、次のことが保証されます。

  • The remote peer behaves properly.
  • The local system is not forced into the two-element subgroup.
  • リモートピアが適切に振る舞うこと。
  • ローカルシステムが、2つの要素からなる部分群に強制されないこと。

6. Security Considerations

6. セキュリティーに関する考慮事項

The security considerations of [RFC4253] apply to this document.

[RFC4253]のセキュリティーに関する考慮事項がこの文書に適用されます。

The security considerations of [RFC3526] suggest that MODP group14 through group18 have security strengths that range between 110 bits of security through 310 bits of security. They are based on "Determining Strengths For Public Keys Used For Exchanging Symmetric Keys" [RFC3766]. Care should be taken to use sufficient entropy and/or deterministic random-bit generator (DRBG) algorithms to maximize the true security strength of the key exchange and ciphers selected.

[RFC3526]のセキュリティーに関する考慮事項は、MODP group14からgroup18までのセキュリティー強度が、110ビットから310ビットのセキュリティーの範囲にあることを示唆しています。これらは「Determining Strengths For Public Keys Used For Exchanging Symmetric Keys」[RFC3766]に基づいています。選択された鍵交換と暗号の真のセキュリティー強度を最大化するために、十分なエントロピーおよび／または決定論的乱数ビット生成器（DRBG）アルゴリズムを使用するよう注意すべきです。

Using a fixed set of Diffie-Hellman parameters makes them a high value target for pre-computation. Generating additional sets of primes to be used, or moving to larger values mitigates this issue.

Diffie-Hellmanパラメーターの固定されたセットを使用すると、それらは事前計算の価値の高い標的になります。使用する素数の追加のセットを生成するか、より大きな値に移行することで、この問題は緩和されます。
