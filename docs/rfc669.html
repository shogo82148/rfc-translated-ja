RFC 669

November, 1974, Survey of New-Protocol TELNET Servers

RFC 669

1974年11月の新プロトコルTelnetサーバーの調査

Abstract

概要

Two months have elapsed since our last survey, and the appearance of additional New-Protocol servers has progressed at the usual snail's pace. The changes in this list are (with host numbers in octal):

前回の調査から2か月が経ちましたが、新プロトコル（New-Protocol）サーバーの追加は相変わらずのろのろとしか進んでいません。一覧の変更点は次のとおりです（ホスト番号は8進数）。

  • SRI-AI (102) now has a New-Protocol server;
  • SDC-LAB (10) is back on the net and the list;
  • SDC-CC (110) is coming on the net but status is as yet unknown;
  • USC-ISI (126) and USC-ISIB (226) (formerly ISI-DEVTENEX) now have New-Protocol servers;
  • SDAC-44 (32) has been removed -- no longer classed as a server host;
  • HAWAII-500 (344) is coming on the net, status presently unknown;
  • LONDON (52) has been added;
  • BBN-TENEXD is now host 162 (formerly 205).
  • SRI-AI（102）に新プロトコルサーバーができました。
  • SDC-LAB（10）がネットワークに復帰し、一覧にも戻りました。
  • SDC-CC（110）がネットワークに接続しつつありますが、状態はまだ不明です。
  • USC-ISI（126）とUSC-ISIB（226）（旧ISI-DEVTENEX）に新プロトコルサーバーができました。
  • SDAC-44（32）を削除しました。もはやサーバーホストとして分類されません。
  • HAWAII-500（344）がネットワークに接続しつつありますが、現時点で状態は不明です。
  • LONDON（52）を追加しました。
  • BBN-TENEXDは現在ホスト162（以前は205）です。

What follows is an update of the summary and tabulation that appeared in RFC #702.* Is there light at the end of the tunnel?

注記：

*
All data in this report were gathered via a surveying program run at various times, plus a few manual checks to fill out the data. What is reported here is the way the various servers work as seen by the new-Protocol User Telnet at BBNA, as of 4 Dec. 1974.
(2)
These are the sites whose operation is 100% correct according to all protocols and conventions, as I understand them.
(3)
We realize that some of the servers that appear here as New-Protocol servers on socket 1 are actually servers which attempt to communicate with both Old- and New-Protocol User TELNETs according to what control sequences are received.
*
このレポートのデータはすべて、さまざまな時刻に実行した調査プログラムで収集し、データを補うためにいくつか手作業で確認したものです。ここに報告しているのは、1974年12月4日時点で、BBNAの新プロトコルのUser Telnetから見た各サーバーの動作です。
(2)
これらは、私の理解する限り、すべてのプロトコルと慣例に照らして100%正しく動作しているサイトです。
(3)
ここでソケット1の新プロトコルサーバーとして挙げているサーバーの一部は、実際には受信した制御シーケンスに応じて、旧プロトコルと新プロトコルの両方のUser TELNETと通信しようとするサーバーであることは承知しています。

Key:

凡例：

X
No server at this socket
?
Status not ascertained -- unable to connect to host
I#
Option # implemented incoming to user (Server says "Will #")
O#
Option # implemented outgoing from user (Server says "Do #")
X
このソケットにサーバーなし
?
状態を確認できず（ホストに接続できない）
I#
ユーザーへの受信方向のオプション#を実装（サーバーが「Will #」と送る）
O#
ユーザーからの送信方向のオプション#を実装（サーバーが「Do #」と送る）

(# is option number in new Protocol. All options implemented by anyone are:

（#は新プロトコルでのオプション番号です。いずれかのサーバーで実装されているオプションは、次のとおりです。

1

3

6
Timing-Mark )
