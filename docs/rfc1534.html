RFC 1534

Interoperation Between DHCP and BOOTP

RFC 1534

DHCPとBOOTPの相互運用

Abstract

概要

DHCP provides a superset of the functions provided by BOOTP. This document describes the interactions between DHCP and BOOTP network participants.

DHCPは、BOOTPが提供する機能の上位集合（superset）を提供します。この文書は、DHCPとBOOTPのネットワーク参加者の間の相互作用を説明します。

Status of This Memo

このメモのステータス

This RFC specifies an Internet standards track protocol for the Internet community, and requests discussion and suggestions for improvements. Please refer to the current edition of the "Internet Official Protocol Standards" for the standardization state and status of this protocol. Distribution of this memo is unlimited.

このRFCは、インターネットコミュニティーのためのインターネット標準化過程のプロトコルを規定し、改善のための議論と提案を求めるものです。このプロトコルの標準化の状態とステータスについては、「Internet Official Protocol Standards」の最新版を参照してください。このメモの配布は無制限です。

1. Introduction

1. はじめに

The Dynamic Host Configuration Protocol (DHCP) provides a mechanism for transmitting configuration parameters to hosts using the TCP/IP protocol suite. The format of DHCP messages is based on the format of BOOTP messages, so that, in certain circumstances, DHCP and BOOTP participants may exchange messages. This document specifies the ways in which DHCP and BOOTP participants may interoperate.

動的ホスト構成プロトコル（Dynamic Host Configuration Protocol; DHCP）は、TCP/IPプロトコルスイートを使用するホストに構成パラメーターを送信するための仕組みを提供します。DHCPメッセージのフォーマットはBOOTPメッセージのフォーマットに基づいているので、状況によってはDHCPとBOOTPの参加者がメッセージを交換できます。この文書は、DHCPとBOOTPの参加者が相互運用できる方法を規定します。

DHCP introduces a small change in terminology intended to clarify the meaning of one of the fields. What was the "vendor extensions" field in BOOTP has been re-named the "options" field in DHCP. Similarly, the tagged data items that were used inside the BOOTP "vendor extensions" field, which were formerly referred to as "vendor extensions", are now termed simply "options". This document will refer to BOOTP vendor extensions and DHCP options uniformly as "options".

DHCPでは、あるフィールドの意味を明確にするために、用語を少し変更しています。BOOTPで「ベンダー拡張（vendor extensions）」フィールドと呼ばれていたものは、DHCPでは「オプション（options）」フィールドに名前が変わりました。同様に、BOOTPの「ベンダー拡張」フィールド内で使われていたタグ付きのデータ項目は、以前は「ベンダー拡張」と呼ばれていましたが、現在は単に「オプション」と呼ばれます。この文書では、BOOTPのベンダー拡張とDHCPのオプションを一律に「オプション」と呼びます。

Throughout this document, DHCP messages that include a 'DHCP message type' option will be referred to by the type of the message; e.g., a DHCP message with 'DHCP message type' option type 1 will be referred to as a "DHCPDISCOVER" message.

この文書全体を通して、「DHCP message type」オプションを含むDHCPメッセージは、そのメッセージの種別で呼びます。たとえば、「DHCP message type」オプションの種別が1であるDHCPメッセージは、「DHCPDISCOVER」メッセージと呼びます。

2. BOOTP clients and DHCP servers

2. BOOTPクライアントとDHCPサーバー

The format of DHCP messages is defined to be compatible with the format of BOOTP messages, so that existing BOOTP clients can interoperate with DHCP servers. Any message received by a DHCP server that includes a 'DHCP message type' (51) option is assumed to have been sent by a DHCP client. Messages without the DHCP Message Type option are assumed to have been sent by a BOOTP client. Support of BOOTP clients by a DHCP server is optional at the discretion of the local system administrator. If a DHCP server that is not configured to support BOOTP clients receives a BOOTREQUEST message from a BOOTP client, that server silently discards the BOOTREQUEST message.

DHCPメッセージのフォーマットは、既存のBOOTPクライアントがDHCPサーバーと相互運用できるように、BOOTPメッセージのフォーマットと互換性を持つように定義されています。DHCPサーバーが受信したメッセージのうち、「DHCP message type」（51）オプションを含むものは、DHCPクライアントから送信されたものとみなします。DHCP Message Typeオプションを含まないメッセージは、BOOTPクライアントから送信されたものとみなします。DHCPサーバーがBOOTPクライアントをサポートするかどうかは任意であり、ローカルのシステム管理者の裁量に任されます。BOOTPクライアントをサポートするように構成されていないDHCPサーバーが、BOOTPクライアントからBOOTREQUESTメッセージを受信した場合、そのサーバーはBOOTREQUESTメッセージを黙って破棄します。

If a DHCP server is configured to support BOOTP clients, it may be configured to supply static addresses, automatic addresses or both. Static addresses are those that have been previously assigned by a system administrator and are stored in a database available to the DHCP server. Automatic addresses are those selected by the DHCP server from its pool of unassigned addresses.

DHCPサーバーがBOOTPクライアントをサポートするように構成されている場合、そのサーバーは静的アドレス、自動アドレス、またはその両方を提供するように構成できます。静的アドレスとは、システム管理者があらかじめ割り当て、DHCPサーバーが利用できるデータベースに格納されているアドレスです。自動アドレスとは、DHCPサーバーが未割り当てのアドレスのプールから選択するアドレスです。

Since BOOTP clients may not be prepared to receive automatic addresses, the decision to allow a DHCP server to return automatic addresses must be under the control of the system administrator. If a DHCP server supports supplying automatic addresses to BOOTP clients, this feature must be configurable, and the feature must default off. Enabling of the feature must be the result of an active decision by the system administrator.

BOOTPクライアントは自動アドレスを受け取る準備ができていないかもしれないので、DHCPサーバーが自動アドレスを返すことを許可するかどうかの決定は、システム管理者の管理下に置かなければなりません。DHCPサーバーがBOOTPクライアントへの自動アドレスの提供をサポートする場合、この機能は構成可能でなければならず、デフォルトでは無効でなければなりません。この機能の有効化は、システム管理者による能動的な決定の結果でなければなりません。

If a DHCP server returns a automatic address, the BOOTP client will not be aware of the DHCP lease mechanism for network address assignment. Thus the DHCP server must assign an infinite lease duration to for automatic addresses assigned to BOOTP clients. Such network addresses cannot be automatically reassigned by the server. The local system administrator may choose to manually release network addresses assigned to BOOTP clients.

DHCPサーバーが自動アドレスを返した場合、BOOTPクライアントはネットワークアドレス割り当てのためのDHCPのリースの仕組みを認識しません。したがって、DHCPサーバーは、BOOTPクライアントに割り当てた自動アドレスに対して、無期限のリース期間を割り当てなければなりません。そのようなネットワークアドレスは、サーバーが自動的に再割り当てすることはできません。ローカルのシステム管理者は、BOOTPクライアントに割り当てたネットワークアドレスを手動で解放することを選択できます。

A DHCP server that supports BOOTP clients MUST interact with BOOTP clients according to the BOOTP protocol. The server MUST formulate a BOOTP BOOTREPLY message rather than a DHCP DHCPOFFER message (i.e., the server MUST NOT include the 'DHCP message type' option and MUST NOT exceed the size limit for BOOTREPLY messages). The server marks a binding for a BOOTP client as BOUND after sending the BOOTP BOOTREPLY, as a non-DHCP client will not send a DHCPREQUEST message nor will that client expect a DHCPACK message.

BOOTPクライアントをサポートするDHCPサーバーは、BOOTPプロトコルに従ってBOOTPクライアントとやり取りしなければなりません（MUST）。サーバーは、DHCPのDHCPOFFERメッセージではなく、BOOTPのBOOTREPLYメッセージを作成しなければなりません（MUST）（つまり、サーバーは「DHCP message type」オプションを含めてはなりません（MUST NOT）。また、BOOTREPLYメッセージのサイズ制限を超えてはなりません（MUST NOT））。DHCPではないクライアントはDHCPREQUESTメッセージを送信せず、DHCPACKメッセージも期待しないので、サーバーはBOOTPのBOOTREPLYを送信した後に、BOOTPクライアントのバインディングをBOUNDとしてマークします。

DHCP servers MAY send any DHCP Options to a BOOTP client as allowed by the "DHCP Options and BOOTP Vendor Extensions" RFC [2].

DHCPサーバーは、「DHCP Options and BOOTP Vendor Extensions」RFC[2]で許可されているとおり、任意のDHCPオプションをBOOTPクライアントに送信してもよいです（MAY）。

In summary, a DHCP server:

まとめると、DHCPサーバーは次のとおりです。

  • MAY support BOOTP clients,
  • May return automatic addresses to BOOTP clients,
  • MUST provide a configuration switch if returning automatic addresses to BOOTP clients,
  • MUST default this optional configuration to OFF,
  • MUST abide by the BOOTP specification when interacting with BOOTP clients, and
  • MAY send DHCP options (those options defined in the DHCP options document but not in the BOOTP vendor extensions documents) to a BOOTP client.
  • BOOTPクライアントをサポートしてもよいです（MAY）。
  • BOOTPクライアントに自動アドレスを返してもかまいません。
  • BOOTPクライアントに自動アドレスを返す場合は、構成スイッチを提供しなければなりません（MUST）。
  • このオプションの構成のデフォルトをOFFにしなければなりません（MUST）。
  • BOOTPクライアントとやり取りするときは、BOOTPの仕様に従わなければなりません（MUST）。
  • DHCPオプション（DHCPオプションの文書で定義されているが、BOOTPベンダー拡張の文書では定義されていないオプション）をBOOTPクライアントに送信してもよいです（MAY）。

3. DHCP clients and BOOTP servers

3. DHCPクライアントとBOOTPサーバー

A DHCP client MAY use a reply from a BOOTP server if the configuration returned from the BOOTP server is acceptable to the DHCP client. A DHCP client MUST assume that an IP address returned in a message from a BOOTP server has an infinite lease. A DHCP client SHOULD choose to use a reply from a DHCP server in preference to a reply from a BOOTP server.

DHCPクライアントは、BOOTPサーバーから返された構成をDHCPクライアントが受け入れられる場合、BOOTPサーバーからの応答を使用してもよいです（MAY）。DHCPクライアントは、BOOTPサーバーからのメッセージで返されたIPアドレスのリースが無期限であるとみなさなければなりません（MUST）。DHCPクライアントは、BOOTPサーバーからの応答よりも、DHCPサーバーからの応答を優先して使用するべきです（SHOULD）。
