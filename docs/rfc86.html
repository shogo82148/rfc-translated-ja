RFC 86

Proposal for a Network Standard Format for a Data Stream to Control Graphics Display

RFC 86

グラフィックディスプレイを制御するデータストリームのためのネットワーク標準形式の提案

Abstract

概要

A typical arrangement of facilities is to have a console attached to a computer at the user's site, and to be using the computational facilities of a remote site. Information entered by the user is transmitted to the remote Host, and output from the remote Host is transmitted back to the local user. In this proposal I am concerned with specifying the form of the output stream for the case that the output portion of the console is a typical refresh display with point, vector and character drawing capability. Devices in this class include the DEC 338, DEC 340, IBM 2250, and IMLAC PDS-1.

典型的な設備の構成は、ユーザーのサイトにあるコンピューターにコンソールを接続し、リモートサイトの計算設備を利用するというものです。ユーザーが入力した情報はリモートHostに送信され、リモートHostからの出力はローカルのユーザーに送り返されます。この提案では、コンソールの出力部分が、点、ベクトル、文字を描画する機能を持つ典型的なリフレッシュディスプレイである場合について、出力ストリームの形式を規定することを扱います。この種類の装置には、DEC 338、DEC 340、IBM 2250、IMLAC PDS-1があります。

It must be understood that this proposal is illustrative only, and knowingly avoids important issues. Its main purpose is to provide a basis for discussion and development.

この提案は説明のためのものにすぎず、重要な問題を承知のうえで避けていることを理解してください。主な目的は、議論と開発の土台を提供することです。

In order to specify the semantices of the network standard graphics data stream (NGDS), I will postulate

ネットワーク標準グラフィックデータストリーム（NGDS）のセマンティクスを規定するために、次のものを仮定します。

  1. a network standard display list (NGDL)
  2. a network standard stream interpreter (NGSI)
  3. a network standard list interpreter (NGLI), also called the display controller, and
  4. a network standard screen (NGS)
  1. ネットワーク標準ディスプレイリスト（NGDL）
  2. ネットワーク標準ストリームインタープリター（NGSI）
  3. ディスプレイコントローラーとも呼ばれる、ネットワーク標準リストインタープリター（NGLI）
  4. ネットワーク標準スクリーン（NGS）

The NGDS is accepted into the local Host and interpreted by the NGSI. The NGSI is a process which modifies the NGDL according to inputs in the NGDS. The NGDL is the display list for the NGLI; the NGLI executes the NGDL and controls the beam which writes on the NGS.

NGDSはローカルHostに受け入れられ、NGSIによって解釈されます。NGSIは、NGDSの入力に従ってNGDLを変更するプロセスです。NGDLはNGLIのためのディスプレイリストです。NGLIはNGDLを実行し、NGSに描画するビームを制御します。

The NGS is square, has horizontal and vertical sides, and positions on it are specified by an ordered pair of unsigned 16 bit fractions. The first fraction specifies the horizontal distance from the left hand edge, and the second specifies the vertical distance from the bottom edge. The resolution of the screen is unspecified.

NGSは正方形で、水平な辺と垂直な辺を持ち、その上の位置は符号なし16ビットの小数の順序対で指定されます。1つ目の小数は左端からの水平距離を指定し、2つ目は下端からの垂直距離を指定します。スクリーンの解像度は規定しません。

The lack of specification of the resolution of the NGS is intentional; programs designers should not interpret this to mean that they may impose a particular requirement on the using system. Thus the quality of the displayed picture should degrade gradually with decreasing resolution.

NGSの解像度を規定しないのは意図的なものです。プログラムの設計者は、これを利用する側のシステムに特定の要件を課してよいという意味に解釈すべきではありません。したがって、表示される画像の品質は、解像度が下がるにつれて緩やかに劣化するようにすべきです。

The NGLI has primitives for moving the beam to a particular point, intensifying a point, drawing a vector, or drawing a character. Characters are assumed to be not more than .015 screen width wide, and not more than .025 screen height high. When the beam is moved to a screen position before drawing characters, that position should be at the lower left hand corner of the first character drawn. The beam position after drawing a character is immediately to the right of the character, properly positioned for another character. However, after drawing one or more characters, the exact horizontal position of the beam is unspecified.

NGLIは、ビームを特定の点に移動する、点を輝かせる、ベクトルを描画する、文字を描画する、というプリミティブを持ちます。文字の幅はスクリーン幅の.015以下、高さはスクリーン高の.025以下であると想定します。文字を描画する前にビームをスクリーン上の位置に移動するとき、その位置は最初に描画する文字の左下隅であるべきです。文字を描画した後のビームの位置は、その文字のすぐ右であり、次の文字を描画するのに適した位置になります。ただし、1つ以上の文字を描画した後のビームの正確な水平位置は規定しません。

The imprecise specification of character size is intended to take cognizance of the existance of character drawing hardware which is capable of producing only one or a few character sizes. The particular proportions of .015 wide by .025 high provides for 67 characters to a line and 40 lines, and seems well within the capability of most displays in the class considered. As in the case of screen resolution, variations in character drawing hardware should cause only minor degradation in the usefulness of the picture.

文字の大きさの規定をあいまいにしているのは、1つまたは少数の文字サイズしか生成できない文字描画ハードウェアが存在することを考慮したためです。幅.015、高さ.025という特定の比率では、1行に67文字、40行を表示でき、これは対象とする種類のほとんどのディスプレイの能力の範囲内に十分収まると思われます。スクリーンの解像度の場合と同様に、文字描画ハードウェアの違いが画像の有用性にもたらす劣化はわずかであるべきです。

The character set intrepreted by the NGLI is ASCII, excepting all form control characters, but including the space character. The tab, return and line feed functions should be simulated by explicit positioning of the beam.

NGLIが解釈する文字セットは、すべての書式制御文字を除き、空白文字を含めたASCIIです。タブ、復帰、改行の機能は、ビームの位置を明示的に指定することで模倣すべきです。

The NGDL consists of a set of named and possibly null lists. The names are 16 bit integers, and the name zero is the name of the chief list. Each list is composed of zero of more display items. An item is any of the following:

NGDLは、名前の付いた、空かもしれないリストの集合で構成されます。名前は16ビットの整数で、名前0は主リストの名前です。各リストは0個以上の表示項目で構成されます。項目は次のいずれかです。

  1. "Move beam to xxxx,yyyy, relative to current origin"
  2. "Display vector from current position to xxxx,yyyy, relative to current origin"
  3. "Display current point"

  4. "Display the following n characters:

           c  c  ...c "
        1  2     n
  5. "Execute list gggg with origin xxxx,yyyy relative to current origin"
  1. 「現在の原点からの相対位置xxxx,yyyyにビームを移動する」
  2. 「現在の位置から、現在の原点からの相対位置xxxx,yyyyまでベクトルを表示する」
  3. 「現在の点を表示する」

  4. 「次のn個の文字を表示する：

           c  c  ...c "
        1  2     n
  5. 「現在の原点からの相対位置xxxx,yyyyを原点としてリストggggを実行する」

The NGLI is constantly in a loop executing the chief list, the origin of the chief list is always <0,0>. When the NGLI comes to the end of the chief list, it returns to the top of it. When the NGLI encounters a type e item, it suspends execution of the current list, set the new origin to <xxxx,yyyy> + <the old origin>, and executes the list named gggg. When finished with the list, the old origin is restored and execution of the old list resumed. The NGLI is, therefore, a recursive interpreter, and type e items are subroutine calls.

NGLIは常にループで主リストを実行しており、主リストの原点は常に<0,0>です。NGLIは主リストの終わりに来ると、その先頭に戻ります。NGLIは種類eの項目に出会うと、現在のリストの実行を中断し、新しい原点を<xxxx,yyyy> + <古い原点>に設定して、ggggという名前のリストを実行します。そのリストを終えると、古い原点が復元され、古いリストの実行が再開されます。したがって、NGLIは再帰的なインタープリターであり、種類eの項目はサブルーチン呼び出しです。

There remains only the matter of the NGDS and the NGSI. The NGDS is parsed into commands by the NGSI and each command is executed as soon as it is recognized. The commands in the NGDS are in prefix form, consisting of an eight bit operation code followed by any arguments. Only two commands are defined: Erase and Replace.

残るのはNGDSとNGSIの問題だけです。NGDSはNGSIによってコマンドに解析され、各コマンドは認識されるとすぐに実行されます。NGDS内のコマンドは前置形式で、8ビットの操作コードとそれに続く引数で構成されます。定義するコマンドは、EraseとReplaceの2つだけです。

The Erase command consists of a single zero-valued opcode and no arguments. The NGSI executes the Erase command by making all lists into null lists. This erases the screen.

Eraseコマンドは、値が0のオペコード1つだけで構成され、引数はありません。NGSIは、すべてのリストを空のリストにすることでEraseコマンドを実行します。これによりスクリーンが消去されます。

The Replace command has an opcode of 1, followed by a 16-bit list name, followed by an 8 bit subargument count, followed by the indicated number of subarguments. The NGSI executes the Replcae command by deleteing all items from the indicated list, and rebuilding the list from the subarguments. There are five kinds of subarguments, corresponding to the five item types.

Replaceコマンドは、オペコード1と、それに続く16ビットのリスト名、それに続く8ビットのサブ引数の数、それに続く指示された数のサブ引数で構成されます。NGSIは、指示されたリストからすべての項目を削除し、サブ引数からリストを作り直すことでReplaceコマンドを実行します。5種類の項目に対応して、5種類のサブ引数があります。

<subargument>::=<atype> | <btype> |  <ctype> |

                                      <dtype> | <etype>


            <atype>::= <a> <x> <y>

            <btype>::= <b> <x> <y>

            <ctype>::= <c>

            <dtype>::= <d> <n> <c> ... <c>
                                    n

            <etype>::= <e> <g> <x> <y>

<subargument>::=<atype> | <btype> |  <ctype> |

                                      <dtype> | <etype>


            <atype>::= <a> <x> <y>

            <btype>::= <b> <x> <y>

            <ctype>::= <c>

            <dtype>::= <d> <n> <c> ... <c>
                                    n

            <etype>::= <e> <g> <x> <y>

<a>, <b>, <c>, <d>, and <e> are 8 bit bytes valued at 0, 1 ... 4, respectively and corresponging to the item types listed on page 4.

<a>、<b>、<c>、<d>、<e>は、それぞれ0、1、…、4の値を持つ8ビットのバイトで、4ページに挙げた項目の種類に対応します。

  • <x> and <y> are 16 bit numbers
  • <g> is a 16 bit list name
  • <n> is an 8 bit count
  • <c> is an ASCII character code
  • <x>と<y>は16ビットの数です
  • <g>は16ビットのリスト名です
  • <n>は8ビットの数です
  • <c>はASCII文字コードです
