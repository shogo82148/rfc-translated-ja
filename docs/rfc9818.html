RFC 9818

DHCPv6 Prefix Delegation on IPv6 Customer Edge (CE) Routers in LANs

RFC 9818

LANにおけるIPv6カスタマーエッジ（CE）ルーターでのDHCPv6プレフィックス委任

Abstract

概要

This document defines requirements for IPv6 Customer Edge (CE) routers to support DHCPv6 Prefix Delegation for distributing available prefixes to LAN devices that were delegated to an IPv6 CE router. This document updates RFC 7084.

この文書は、IPv6カスタマーエッジ（CE）ルーターに委任された利用可能なプレフィックスをLAN上のデバイスに配布するために、 IPv6 CEルーターがDHCPv6プレフィックス委任をサポートするための要件を定義します。 この文書はRFC 7084を更新します。

1. Introduction

1. はじめに

This document describes guidelines for DHCPv6 Prefix Delegation in IPv6 Customer Edge (CE) routers [RFC7084] in order to properly utilize the IPv6 prefixes delegated by service providers. Many service providers assign larger address blocks than /64 to CE routers, as recommended in [RFC6177]. If an IPv6 CE router does not support the Identity Association for Prefix Delegation (IA_PD) Prefix Option (Section 21.21 of [RFC8415]) on the LAN, it will not be able to assign any prefixes beyond its local interfaces, limiting the usefulness of assigning prefixes larger than /64 by the operator. Supporting IA_PD on the LAN interfaces of a CE router will allow those unused prefixes to be distributed into a network. Note that efforts such as those of the Stub Networking Auto Configuration (SNAC) Working Group depend on IPv6 prefixes being properly distributed in the LAN.

この文書は、サービスプロバイダーから委任されたIPv6プレフィックスを適切に活用するために、 IPv6カスタマーエッジ（CE）ルーター[RFC7084]におけるDHCPv6プレフィックス委任のガイドラインを記述します。 多くのサービスプロバイダーは、[RFC6177]で推奨されているとおり、/64より大きなアドレスブロックをCEルーターに割り当てています。 IPv6 CEルーターがLAN上でプレフィックス委任のためのアイデンティティー関連付け（IA_PD）プレフィックスオプション （[RFC8415]のSection 21.21）をサポートしていない場合、自身のローカルインターフェイス以外にはプレフィックスを割り当てることができず、 運用者が/64より大きなプレフィックスを割り当てることの有用性が限られてしまいます。 CEルーターのLANインターフェイスでIA_PDをサポートすれば、それらの未使用のプレフィックスをネットワーク内に配布できるようになります。 なお、Stub Networking Auto Configuration（SNAC）ワーキンググループの取り組みなどは、 IPv6プレフィックスがLAN内で適切に配布されることを前提としています。

Two models, hierarchical prefix and flat, were proposed in the past for prefix sub-delegation beyond an IPv6 CE router. Hierarchical prefix delegation requires an IPv6 CE router to sub-delegate IPv6 prefixes based on a set of rules. If more than one router uses hierarchical prefix delegation, an IPv6 prefix tree is created. When no routing protocol is enabled to discover the network topology, it is possible to have an unbalanced prefix delegation tree, which leads to running out of prefixes. More information on hierarchical prefix delegation can be found, e.g., in Section 8.5 of CableLabs IPv6 eRouter specification [eRouter]. A flat prefix delegation requires the router to be provisioned with the initial prefix and to assign /64 prefixes to all other prefix requests from routers in the LAN-facing interface. The default configuration of CE routers is designed to be a flat model to support zero-configuration networking.

IPv6 CEルーターの先へのプレフィックスの再委任については、過去に階層型プレフィックスとフラットという2つのモデルが提案されました。 階層型プレフィックス委任では、IPv6 CEルーターが一連のルールに基づいてIPv6プレフィックスを再委任する必要があります。 複数のルーターが階層型プレフィックス委任を使用すると、IPv6プレフィックスのツリーが作成されます。 ネットワークトポロジーを発見するためのルーティングプロトコルが有効になっていない場合、 プレフィックス委任のツリーが不均衡になる可能性があり、それによってプレフィックスが枯渇してしまいます。 階層型プレフィックス委任についての詳しい情報は、たとえばCableLabsのIPv6 eRouter仕様[eRouter]のセクション8.5に記載されています。 フラットなプレフィックス委任では、ルーターに初期プレフィックスが設定され、 LAN側インターフェイスにいるルーターからの他のすべてのプレフィックス要求に対して/64プレフィックスを割り当てる必要があります。 CEルーターのデフォルト設定は、ゼロコンフィギュレーションネットワーキングをサポートするために、フラットモデルとなるように設計されています。

This document does not cover dealing with multi-prefix networks with more than one provider. Due to the complexity of a solution that would require routing, provisioning, and policy, this is out of scope of this document.

この文書は、複数のプロバイダーを持つマルチプレフィックスネットワークの扱いについては扱いません。 ルーティング、プロビジョニング、ポリシーを必要とする解決策は複雑であるため、これはこの文書の範囲外です。

5. Requirements

5. 要件

IPv6 CE routers distribute configuration information obtained during WAN interface provisioning to LAN-facing IPv6 hosts and routers. A CE router that is compliant with [RFC7084] would only provide IPv6 hosts with configuration information. This document allows for addressing and routing of IPv6 prefixes to both hosts and routers. These requirements are in addition to the ones in Section 4.3 of [RFC7084].

IPv6 CEルーターは、WANインターフェイスのプロビジョニング中に取得した設定情報を、LAN側のIPv6ホストとルーターに配布します。 [RFC7084]に準拠したCEルーターは、IPv6ホストにのみ設定情報を提供します。 この文書では、ホストとルーターの両方に対するIPv6プレフィックスのアドレス割り当てとルーティングを可能にします。 これらの要件は、[RFC7084]のSection 4.3の要件に追加されるものです。

5.1. LAN Prefix Delegation Requirements (LPD)

5.1. LANプレフィックス委任の要件（LPD）

  1. Each IPv6 CE router MUST support IPv6 prefix assignment according to Section 13.3 of [RFC8415] (Identity Association for Prefix Delegation (IA_PD) option) on its LAN interface(s).

  2. Each IPv6 CE routers MUST assign a prefix from the delegated prefix as specified by L-2 in Section 4.3 of [RFC7084]. If insufficient prefixes are available, the IPv6 CE router MUST log a system management error.

  3. The prefix assigned to a link MUST NOT change in the absence of a local policy or a topology change.

  4. After LAN link prefix assignments, the IPv6 CE router MUST keep the remaining IPv6 prefixes available to other routers via Prefix Delegation.

  5. IPv6 CE routers MUST maintain a local routing table that is dynamically updated with leases and the associated next hops as they are delegated to clients. Absent explicit filtering, packets with destination addresses in a delegated prefix MUST be forwarded to that prefix regardless of which interface they are received on. When a delegated prefix is released or expires, the associated route MUST be removed from the IPv6 CE router's routing table. A delegated prefix expires when the valid lifetime assigned in the IA_PD expires without being renewed. When a prefix is released or expires, it MUST be returned the pool of available prefixes.

  6. By default, the IPv6 CE router filtering rules MUST allow forwarding of packets with an outer IPv6 header containing a source address belonging to delegated prefixes, along with reciprocal packets from the same flow, following the recommendations of [RFC6092]. This updates WPD-5 of [RFC7084] to not drop packets from prefixes that have been delegated. IPv6 CE routers MUST continue to drop packets, including destination address, that are not assigned to the LAN or delegated.

  7. The IPv6 CE routers MUST provision IA_PD prefixes with a prefix-length of 64 on the LAN-facing interface unless configured to use a different prefix-length by the CE router administrator. The prefix-length of 64 is used as that is the current prefix-length supported by SLAAC [RFC4862]. For hierarchical prefix delegation, a prefix-length shorter than 64 may be configured.

  8. IPv6 CE routers configured to generate a ULA prefix as defined in ULA-1 of Section 4.3 of [RFC7084] MUST continue to provision available GUA IPv6 prefixes.

  9. If an IPv6 CE router is provisioning both a ULA and GUA via prefix delegation, the GUA SHOULD appear first in the DHCPv6 packets.

  10. IPv6 CE routers MUST NOT delegate prefixes via DHCPv6 on the LAN using lifetimes that exceed the remaining lifetimes of the corresponding prefixes learned on the WAN.

  1. 各IPv6 CEルーターは、そのLANインターフェイス上で、[RFC8415]のSection 13.3（プレフィックス委任のためのアイデンティティー関連付け（IA_PD）オプション）に従ったIPv6プレフィックスの割り当てをサポートしなければなりません（MUST）。

  2. 各IPv6 CEルーターは、[RFC7084]のSection 4.3のL-2で規定されているとおりに、委任されたプレフィックスからプレフィックスを割り当てなければなりません（MUST）。 十分なプレフィックスが利用できない場合、IPv6 CEルーターはシステム管理エラーをログに記録しなければなりません（MUST）。

  3. リンクに割り当てられたプレフィックスは、ローカルポリシーまたはトポロジーの変更がない限り、変更されてはなりません（MUST NOT）。

  4. LANリンクへのプレフィックスの割り当て後、IPv6 CEルーターは、残りのIPv6プレフィックスをプレフィックス委任によって他のルーターが利用できる状態に保たなければなりません（MUST）。

  5. IPv6 CEルーターは、クライアントに委任されたリースとそれに関連付けられたネクストホップで動的に更新されるローカルルーティングテーブルを維持しなければなりません（MUST）。 明示的なフィルタリングがない限り、委任されたプレフィックス内の宛先アドレスを持つパケットは、どのインターフェイスで受信されたかにかかわらず、そのプレフィックスに転送されなければなりません（MUST）。 委任されたプレフィックスが解放されるか期限切れになった場合、関連付けられたルートはIPv6 CEルーターのルーティングテーブルから削除されなければなりません（MUST）。 委任されたプレフィックスは、IA_PDで割り当てられた有効期間（valid lifetime）が更新されずに切れたときに期限切れとなります。 プレフィックスが解放されるか期限切れになった場合、そのプレフィックスは利用可能なプレフィックスのプールに戻されなければなりません（MUST）。

  6. デフォルトでは、IPv6 CEルーターのフィルタリングルールは、[RFC6092]の推奨事項に従って、 委任されたプレフィックスに属する送信元アドレスを含む外側のIPv6ヘッダーを持つパケットと、同じフローの逆方向のパケットの転送を許可しなければなりません（MUST）。 これは、委任されたプレフィックスからのパケットをドロップしないように、[RFC7084]のWPD-5を更新するものです。 IPv6 CEルーターは、宛先アドレスを含め、LANに割り当てられていない、または委任されていないパケットについては引き続きドロップしなければなりません（MUST）。

  7. IPv6 CEルーターは、CEルーターの管理者によって異なるプレフィックス長を使用するように設定されていない限り、 LAN側インターフェイス上でプレフィックス長64のIA_PDプレフィックスをプロビジョニングしなければなりません（MUST）。 プレフィックス長64が使用されるのは、それが現在SLAAC [RFC4862]でサポートされているプレフィックス長だからです。 階層型プレフィックス委任の場合は、64より短いプレフィックス長が設定されることもあります。

  8. [RFC7084]のSection 4.3のULA-1で定義されているようにULAプレフィックスを生成するよう設定されたIPv6 CEルーターは、 利用可能なGUAのIPv6プレフィックスを引き続きプロビジョニングしなければなりません（MUST）。

  9. IPv6 CEルーターがプレフィックス委任によってULAとGUAの両方をプロビジョニングしている場合、DHCPv6パケット内ではGUAを先に記載すべきです（SHOULD）。

  10. IPv6 CEルーターは、WAN上で学習した対応するプレフィックスの残りの有効期間を超える有効期間を用いて、LAN上でDHCPv6によりプレフィックスを委任してはなりません（MUST NOT）。
