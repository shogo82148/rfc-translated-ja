RFC 2606

Reserved Top Level DNS Names

RFC 2606

予約済みのトップレベルDNS名

Abstract

概要

To reduce the likelihood of conflict and confusion, a few top level domain names are reserved for use in private testing, as examples in documentation, and the like. In addition, a few second level domain names reserved for use as examples are documented.

衝突と混乱の可能性を減らすために、いくつかのトップレベルドメイン名を、プライベートなテストや文書中の例などで使用するために予約します。さらに、例として使用するために予約されているいくつかのセカンドレベルドメイン名についても記載します。

Status of This Memo

このメモのステータス

This document specifies an Internet Best Current Practices for the Internet Community, and requests discussion and suggestions for improvements. Distribution of this memo is unlimited.

この文書は、インターネットコミュニティーのためのインターネットのベストカレントプラクティス（Best Current Practices）を規定し、改善のための議論と提案を求めるものです。このメモの配布は無制限です。

1. Introduction

1. はじめに

The global Internet Domain Name System is documented in [RFC1034], [RFC1035], [RFC1591] and numerous additional Requests for Comment. It defines a tree of names starting with root, ".", immediately below which are top level domain names such as ".com" and ".us". Below top level domain names there are normally additional levels of names.

グローバルなインターネットのドメインネームシステム（Domain Name System）は、[RFC1034]、[RFC1035]、[RFC1591]および多数の追加のRFC（Requests for Comment）で文書化されています。ドメインネームシステムは、ルート「.」から始まる名前のツリーを定義しており、そのすぐ下に「.com」や「.us」などのトップレベルドメイン名があります。トップレベルドメイン名の下には、通常、さらに名前の階層があります。

2. TLDs for Testing, & Documentation Examples

2. テスト用、および文書の例示用のTLD

There is a need for top level domain (TLD) names that can be used for creating names which, without fear of conflicts with current or future actual TLD names in the global DNS, can be used for private testing of existing DNS related code, examples in documentation, DNS related experimentation, invalid DNS names, or other similar uses.

既存のDNS関連のコードのプライベートなテスト、文書中の例、DNS関連の実験、無効なDNS名、その他の同様の用途で、グローバルなDNSにおける現在または将来の実際のTLD名と衝突するおそれなしに名前を作成するために使用できるトップレベルドメイン（TLD）名が必要とされています。

For example, without guidance, a site might set up some local additional unused top level domains for testing of its local DNS code and configuration. Later, these TLDs might come into actual use on the global Internet. As a result, local attempts to reference the real data in these zones could be thwarted by the local test versions. Or test or example code might be written that accesses a TLD that is in use with the thought that the test code would only be run in a restricted testbed net or the example never actually run. Later, the test code could escape from the testbed or the example be actually coded and run on the Internet. Depending on the nature of the test or example, it might be best for it to be referencing a TLD permanently reserved for such purposes.

たとえば、ガイダンスがなければ、あるサイトは、ローカルのDNSのコードと設定をテストするために、使われていないトップレベルドメインをローカルに追加で設定するかもしれません。その後、これらのTLDがグローバルなインターネットで実際に使われるようになるかもしれません。その結果、これらのゾーンの実際のデータをローカルから参照しようとしても、ローカルのテスト版に妨げられてしまう可能性があります。あるいは、テストコードは制限されたテストベッドのネットワークでしか実行されないだろう、または例は実際には実行されないだろうと考えて、使用中のTLDにアクセスするテストコードやサンプルコードが書かれるかもしれません。その後、テストコードがテストベッドから漏れ出したり、例が実際にコード化されてインターネット上で実行されたりする可能性があります。テストや例の性質によっては、そのような目的のために恒久的に予約されたTLDを参照するのが最善である場合があります。

To safely satisfy these needs, four domain names are reserved as listed and described below.

これらの必要性を安全に満たすために、以下に列挙して説明する4つのドメイン名を予約します。

                .test
             .example
             .invalid
           .localhost

                .test
             .example
             .invalid
           .localhost

".test" is recommended for use in testing of current or new DNS related code.

「.test」は、現在のDNS関連のコードや新しいDNS関連のコードのテストで使用することが推奨されます。

".example" is recommended for use in documentation or as examples.

「.example」は、文書中で、または例として使用することが推奨されます。

".invalid" is intended for use in online construction of domain names that are sure to be invalid and which it is obvious at a glance are invalid.

「.invalid」は、確実に無効であり、無効であることが一目でわかるドメイン名をオンラインで構築するために使用することを意図しています。

The ".localhost" TLD has traditionally been statically defined in host DNS implementations as having an A record pointing to the loop back IP address and is reserved for such use. Any other use would conflict with widely deployed code which assumes this use.

「.localhost」TLDは、従来、ホストのDNS実装において、ループバックIPアドレスを指すAレコードを持つものとして静的に定義されており、そのような用途のために予約されます。それ以外の用途は、この用途を前提とした広く展開されているコードと衝突することになります。

3. Reserved Example Second Level Domain Names

3. 例示用の予約済みセカンドレベルドメイン名

The Internet Assigned Numbers Authority (IANA) also currently has the following second level domain names reserved which can be used as examples.

インターネット番号割当機関（Internet Assigned Numbers Authority: IANA）も現在、例として使用できる次のセカンドレベルドメイン名を予約しています。

     example.com
     example.net
     example.org

     example.com
     example.net
     example.org

4. IANA Considerations

4. IANAに関する考慮事項

IANA has agreed to the four top level domain name reservations specified in this document and will reserve them for the uses indicated.

IANAは、この文書で規定した4つのトップレベルドメイン名の予約に同意しており、示された用途のためにそれらを予約します。

5. Security Considerations

5. セキュリティーに関する考慮事項

Confusion and conflict can be caused by the use of a current or future top level domain name in experimentation or testing, as an example in documentation, to indicate invalid names, or as a synonym for the loop back address. Test and experimental software can escape and end up being run against the global operational DNS. Even examples used "only" in documentation can end up being coded and released or cause conflicts due to later real use and the possible acquisition of intellectual property rights in such "example" names.

現在または将来のトップレベルドメイン名を、実験やテストで使用したり、文書中の例として使用したり、無効な名前を示すために使用したり、ループバックアドレスの別名として使用したりすると、混乱と衝突が生じる可能性があります。テスト用や実験用のソフトウェアは、漏れ出してグローバルに運用されているDNSに対して実行されてしまうことがあります。文書中で「だけ」使われる例であっても、コード化されてリリースされてしまったり、後に実際に使われたり、そのような「例」の名前に対する知的財産権が取得されたりすることによって、衝突を引き起こす可能性があります。

The reservation of several top level domain names for these purposes will minimize such confusion and conflict.

このような目的のためにいくつかのトップレベルドメイン名を予約することで、そのような混乱と衝突を最小限に抑えられます。
