RFC 8807

Login Security Extension for the Extensible Provisioning Protocol (EPP)

RFC 8807

拡張可能プロビジョニングプロトコル（EPP）のログインセキュリティー拡張

Abstract

概要

The Extensible Provisioning Protocol (EPP) includes a client authentication scheme that is based on a user identifier and password. The structure of the password field is defined by an XML Schema data type that specifies minimum and maximum password length values, but there are no other provisions for password management other than changing the password. This document describes an EPP extension that allows longer passwords to be created and adds additional security features to the EPP login command and response.

拡張可能プロビジョニングプロトコル（Extensible Provisioning Protocol: EPP）には、ユーザー識別子とパスワードに基づくクライアント認証方式が含まれています。パスワードフィールドの構造は、パスワード長の最小値と最大値を指定するXMLスキーマのデータ型によって定義されていますが、パスワードの変更以外にパスワード管理に関する規定はありません。この文書は、より長いパスワードを作成できるようにし、EPPのログインコマンドとレスポンスにセキュリティー機能を追加するEPP拡張について説明します。

1. Introduction

1. はじめに

This document describes an Extensible Provisioning Protocol (EPP) extension for enhancing the security of the EPP login command in EPP [RFC5730]. EPP [RFC5730] includes a maximum password length of 16 characters, which inhibits implementing stronger password security policies with higher entropy. The enhancements include supporting longer passwords (or passphrases) than the 16-character maximum and providing a list of security events in the login response. The password (current and new) in EPP [RFC5730] can be overridden by the password included in the extension to extend past the 16-character maximum. The security events supported include password expiry, client certificate expiry, insecure cipher, insecure TLS protocol, new password complexity, login security statistical warning, and a custom event. The attributes supported by the security events include an identified event type or a subtype, an indicated security level of warning or error, a future or past-due expiration date, the value that resulted in the event, the duration of the statistical event, and a free-form description with an optional language.

この文書は、拡張可能プロビジョニングプロトコル（Extensible Provisioning Protocol: EPP）[RFC5730]のログインコマンドのセキュリティーを強化するためのEPP拡張について説明します。EPP[RFC5730]にはパスワード長の最大値として16文字が含まれており、これがより高いエントロピーを持つより強力なパスワードセキュリティーポリシーの実装を妨げています。この強化には、最大16文字を超える長いパスワード（またはパスフレーズ）のサポートと、ログインレスポンスでのセキュリティーイベントの一覧の提供が含まれます。EPP[RFC5730]のパスワード（現在のパスワードと新しいパスワード）は、拡張に含まれるパスワードによって上書きでき、これにより最大16文字を超えられるようになります。サポートされるセキュリティーイベントには、パスワードの有効期限切れ、クライアント証明書の有効期限切れ、安全でない暗号、安全でないTLSプロトコル、新しいパスワードの複雑さ、ログインセキュリティーの統計的な警告、カスタムイベントがあります。セキュリティーイベントがサポートする属性には、特定されたイベントの種類またはサブタイプ、警告またはエラーのいずれかで示されるセキュリティーレベル、将来の日付または期限を過ぎた有効期限、イベントの原因となった値、統計的なイベントの期間、任意で言語を指定できる自由形式の説明があります。

2. Migrating to Newer Versions of This Extension

2. この拡張の新しいバージョンへの移行

Servers that implement this extension SHOULD provide a way for clients to progressively update their implementations when a new version of the extension is deployed. A newer version of the extension is expected to use an XML namespace with a higher version number than the prior versions.

この拡張を実装するサーバーは、拡張の新しいバージョンが展開されたときに、クライアントが自身の実装を段階的に更新できる方法を提供すべきです（SHOULD）。拡張の新しいバージョンは、以前のバージョンよりも大きいバージョン番号を持つXML名前空間を使用することが想定されています。

Servers SHOULD (for a temporary migration period up to server policy) provide support for older versions of the extension in parallel to the newest version and allow clients to select their preferred version via the <svcExtension> element of the <login> command.

サーバーは、（サーバーポリシーで定める一時的な移行期間の間）最新バージョンと並行して拡張の古いバージョンのサポートを提供し、クライアントが<login>コマンドの<svcExtension>要素を介して希望するバージョンを選択できるようにするべきです（SHOULD）。

If a client requests multiple versions of the extension at login, then, when preparing responses to commands that do not include extension elements, the server SHOULD only include extension elements in the namespace of the newest version of the extension requested by the client.

クライアントがログイン時に拡張の複数のバージョンを要求した場合、拡張要素を含まないコマンドに対するレスポンスを準備する際には、サーバーは、クライアントが要求した拡張の最新バージョンの名前空間にある拡張要素のみを含めるべきです（SHOULD）。

When preparing responses to commands that do include extension elements, the server SHOULD only include extension elements for the extension versions present in the command.

拡張要素を含むコマンドに対するレスポンスを準備する際には、サーバーは、コマンドに存在する拡張バージョンの拡張要素のみを含めるべきです（SHOULD）。

3. Object Attributes

3. オブジェクトの属性

This extension adds additional elements to [RFC5730] login command and response. Only those new elements are described here.

この拡張は、[RFC5730]のログインコマンドとレスポンスに要素を追加します。ここでは、それらの新しい要素のみを説明します。

3.1. Event

3.1. イベント

A security event using the <loginSec:event> element represents either a warning or error identified by the server after the client has connected and submitted the login command. The <loginSec:event> element is contained in a list of one or more elements in the <loginSec:loginSecData> element, so there MAY be multiple events returned that provide information for the client to address. The <loginSec:event> MAY include a free-form description. All of the security events use a consistent set of attributes, where the exact set of applicable attributes is based on the event type. The supported set of <loginSec:event> element attributes include:

<loginSec:event>要素を使用するセキュリティーイベントは、クライアントが接続してログインコマンドを送信した後にサーバーが特定した警告またはエラーのいずれかを表します。<loginSec:event>要素は<loginSec:loginSecData>要素内の1つ以上の要素からなるリストに含まれるため、クライアントが対処するための情報を提供する複数のイベントが返される場合があります（MAY）。<loginSec:event>には、自由形式の説明を含めてもよいです（MAY）。すべてのセキュリティーイベントは一貫した属性の集合を使用し、適用される属性の正確な集合はイベントの種類に基づいて決まります。サポートされる<loginSec:event>要素の属性の集合は次のとおりです。

"type":
A REQUIRED attribute that defines the type of security event. The enumerated list of "type" values includes:
"password":
Identifies a password expiry event where the password expires in the future or has expired based on the "exDate" date and time. The "exDate" attribute MUST be set with the password expiry date and time.
"certificate":
Identifies a client certificate expiry event where the client certificate will expire at the "exDate" date and time. The "exDate" attribute MUST be set with the certificate expiry date and time.
"cipher":
Identifies the use of an insecure or deprecated TLS cipher suite. The "name" attribute MUST be set with the name of the cipher suite, which is free-form and is not expected to be parsed and automatically addressed by the client. An example of cipher suite names can be found in the TLS Cipher Suites of the "Transport Layer Security (TLS) Parameters" registry.
"tlsProtocol":
Identifies the use of an insecure or deprecated TLS protocol. The "name" attribute MUST be set with the name of the TLS protocol, which is free-form and is not expected to be parsed and automatically addressed by the client.
"newPW":
The new password does not meet the server password complexity requirements.
"stat":
Provides a login security statistical warning that MUST set the "name" attribute to the name of the statistic subtype.
"custom":
Custom event type that MUST set the "name" attribute with the custom event type name.
"name":
Used to define a subtype when the "type" attribute is not "custom" or the full type name when the "type" attribute is "custom". The "name" attribute MUST be set when the "type" attribute is "stat" or "custom". The possible set of "name" values, by event type, can be discovered/negotiated out of band to EPP or using a separate EPP extension designed to provide server policy information to the client.
"level":
Defines the level of the event as either "warning" for a warning event that needs action or "error" for an error event that requires immediate action.
"exDate":
Contains the date and time that a "warning" level has or will become an "error" level. At expiry, there MAY be a connection failure or MAY be a login failure. An example is an expired certification that will result in a connection failure or an expired password that may result in a login failure.
"value":
Identifies the value that resulted in the login security event. An example is the negotiated insecure cipher suite or the negotiated insecure TLS protocol.
"duration":
Defines the duration that a statistical event is associated with, ending when the login command was received. The format of the duration is defined by the duration primitive data type in Section 3.2.6 of [W3C.REC-xmlschema-2-20041028].
"lang":
Identifies the negotiated language of the free-form description. The format of the language is defined by the language primitive data type in Section 3.3.3 of [W3C.REC-xmlschema-2-20041028]. The default is "en" (English).
"type":
セキュリティーイベントの種類を定義する属性で、指定することが要求されています（REQUIRED）。列挙された"type"の値の一覧は次のとおりです。
"password":
パスワードの有効期限切れのイベントを識別します。これは、"exDate"の日時に基づいて、パスワードが将来期限切れになるか、すでに期限切れになっていることを示します。"exDate"属性には、パスワードの有効期限の日時を設定しなければなりません（MUST）。
"certificate":
クライアント証明書の有効期限切れのイベントを識別します。これは、クライアント証明書が"exDate"の日時に期限切れになることを示します。"exDate"属性には、証明書の有効期限の日時を設定しなければなりません（MUST）。
"cipher":
安全でない、または非推奨のTLS暗号スイートの使用を識別します。"name"属性には暗号スイートの名前を設定しなければなりません（MUST）。この名前は自由形式であり、クライアントが解析して自動的に対処することは想定されていません。暗号スイート名の例は、「Transport Layer Security (TLS) Parameters」レジストリーのTLS Cipher Suitesにあります。
"tlsProtocol":
安全でない、または非推奨のTLSプロトコルの使用を識別します。"name"属性にはTLSプロトコルの名前を設定しなければなりません（MUST）。この名前は自由形式であり、クライアントが解析して自動的に対処することは想定されていません。
"newPW":
新しいパスワードがサーバーのパスワードの複雑さの要件を満たしていないことを示します。
"stat":
ログインセキュリティーの統計的な警告を提供します。"name"属性には統計のサブタイプの名前を設定しなければなりません（MUST）。
"custom":
カスタムのイベントの種類です。"name"属性にはカスタムのイベントの種類の名前を設定しなければなりません（MUST）。
"name":
"type"属性が"custom"でない場合はサブタイプを定義するために使用し、"type"属性が"custom"の場合は種類の完全な名前を定義するために使用します。"type"属性が"stat"または"custom"の場合は、"name"属性を設定しなければなりません（MUST）。イベントの種類ごとに取りうる"name"の値の集合は、EPPとは帯域外で発見またはネゴシエートするか、サーバーのポリシー情報をクライアントに提供するために設計された別のEPP拡張を使用して発見またはネゴシエートできます。
"level":
イベントのレベルを定義します。対処が必要な警告イベントの場合は"warning"、即時の対処が必要なエラーイベントの場合は"error"のいずれかです。
"exDate":
"warning"レベルが"error"レベルになった、またはなる予定の日時を含みます。期限切れになると、接続の失敗が起こる場合があります（MAY）。または、ログインの失敗が起こる場合があります（MAY）。例としては、接続の失敗を引き起こす期限切れの証明書や、ログインの失敗を引き起こす可能性のある期限切れのパスワードがあります。
"value":
ログインセキュリティーイベントの原因となった値を識別します。例としては、ネゴシエートされた安全でない暗号スイートや、ネゴシエートされた安全でないTLSプロトコルがあります。
"duration":
統計的なイベントが関連付けられている期間を定義します。この期間は、ログインコマンドを受信した時点で終わります。期間の形式は、[W3C.REC-xmlschema-2-20041028]のセクション3.2.6のdurationプリミティブデータ型によって定義されます。
"lang":
自由形式の説明についてネゴシエートされた言語を識別します。言語の形式は、[W3C.REC-xmlschema-2-20041028]のセクション3.3.3のlanguageプリミティブデータ型によって定義されます。デフォルトは"en"（英語）です。

Example login security event for password expiration, where the current date is 2020-03-25:

現在の日付が2020-03-25である場合の、パスワードの有効期限切れに関するログインセキュリティーイベントの例です。

<loginSec:event
  type="password"
  level="warning"
  exDate="2020-04-01T22:00:00.0Z"
  lang="en">
  Password expiration soon
</loginSec:event>

<loginSec:event
  type="password"
  level="warning"
  exDate="2020-04-01T22:00:00.0Z"
  lang="en">
  Password expiration soon
</loginSec:event>

Example login security event for identifying 100 failed logins over the last day, using the "stat" subtype of "failedLogins":

「failedLogins」という「stat」サブタイプを使用して、過去1日間に100回のログイン失敗があったことを識別するログインセキュリティーイベントの例です。

<loginSec:event
  type="stat"
  name="failedLogins"
  level="warning"
  value="100"
  duration="P1D">
  Excessive invalid daily logins
</loginSec:event>

<loginSec:event
  type="stat"
  name="failedLogins"
  level="warning"
  value="100"
  duration="P1D">
  Excessive invalid daily logins
</loginSec:event>

3.2. "[LOGIN-SECURITY]" Password

3.2. 「[LOGIN-SECURITY]」パスワード

When the [RFC5730] <pw> element contains the predefined value of "[LOGIN-SECURITY]", the <loginSec:pw> element overrides the <pw> element, which is a constant value for the server to use the <loginSec:pw> element for the password. Similarly, when the [RFC5730] <newPw> element contains the predefined value of "[LOGIN-SECURITY]", the <loginSec:newPw> element overrides the <newPw> element, which is a constant value for the server to use the <loginSec:newPW> element for the new password. The "[LOGIN-SECURITY]" predefined string MUST be supported by the server for the client to explicitly indicate to the server whether to use <loginSec:pw> element in place of the [RFC5730] <pw> element or to use the <loginSec:newPW> in place of the [RFC5730] <newPW> element. The server MUST NOT allow the client to set the password to the value "[LOGIN-SECURITY]".

[RFC5730]の<pw>要素に事前定義された値「[LOGIN-SECURITY]」が含まれている場合、<loginSec:pw>要素が<pw>要素を上書きします。この値は、パスワードとして<loginSec:pw>要素を使用するようサーバーに伝えるための定数値です。同様に、[RFC5730]の<newPw>要素に事前定義された値「[LOGIN-SECURITY]」が含まれている場合、<loginSec:newPw>要素が<newPw>要素を上書きします。この値は、新しいパスワードとして<loginSec:newPW>要素を使用するようサーバーに伝えるための定数値です。サーバーは、事前定義された文字列「[LOGIN-SECURITY]」をサポートしなければなりません（MUST）。これにより、クライアントは、[RFC5730]の<pw>要素の代わりに<loginSec:pw>要素を使用するのか、または[RFC5730]の<newPW>要素の代わりに<loginSec:newPW>を使用するのかを、サーバーに明示的に示せます。サーバーは、クライアントがパスワードを値「[LOGIN-SECURITY]」に設定することを許可してはなりません（MUST NOT）。

3.3. Dates and Times

3.3. 日付と時刻

Date and time attribute values MUST be represented in Universal Coordinated Time (UTC) using the Gregorian calendar. The extended date-time form using upper case "T" and "Z" characters defined in [W3C.REC-xmlschema-2-20041028] MUST be used to represent date-time values, as XML Schema does not support truncated date-time forms or lower case "T" and "Z" characters.

日付と時刻の属性値は、グレゴリオ暦を使用して協定世界時（UTC）で表現しなければなりません（MUST）。XMLスキーマは切り詰められた日時の形式や小文字の「T」と「Z」をサポートしていないため、日時の値を表現するには、[W3C.REC-xmlschema-2-20041028]で定義されている、大文字の「T」と「Z」を使用する拡張された日時の形式を使用しなければなりません（MUST）。

4.1. EPP <login> Command

4.1. EPPの<login>コマンド

This extension defines additional elements to extend the EPP <login> command and response to be used in conjunction with [RFC5730].

この拡張は、[RFC5730]と組み合わせて使用するために、EPPの<login>コマンドとレスポンスを拡張する要素を定義します。

The EPP <login> command is used to establish a session with an EPP server. This extension overrides the password that is passed with the [RFC5730] <pw> or the <newPW> element, as defined in Section 3.2. A <loginSec:loginSec> element is sent along with the [RFC5730] <login> command and MUST contain at least one of the following child elements:

EPPの<login>コマンドは、EPPサーバーとのセッションを確立するために使用されます。この拡張は、Section 3.2で定義されているように、[RFC5730]の<pw>要素または<newPW>要素で渡されるパスワードを上書きします。<loginSec:loginSec>要素は、[RFC5730]の<login>コマンドとともに送信され、次の子要素のうち少なくとも1つを含まなければなりません（MUST）。

<loginSec:userAgent>:
OPTIONAL client user-agent information that identifies the client application software, technology, and operating system used by the server to identify functional or security constraints, current security issues, and potential future functional or security issues for the client. The server may use the information for real-time identification and client notification of security issues, such as keying off of the client application software for executing security rule checks. The server may capture the information to identify future security policy issues, such as deprecating or removing TLS cipher suites or TLS protocols. The <loginSec:userAgent> element MUST contain at least one of the following child elements:
<loginSec:app>:

OPTIONAL name of the client application software with version if available, such as the name of the client SDK "EPP SDK 1.0.0". The <loginSec:app> element value can be created by appending the version number to the name of the application software, such as the Augmented Backus-Naur Form (ABNF) grammar [RFC5234] format:

app = name SP version
name = 1*VCHAR
version = 1*VCHAR
<loginSec:tech>:

OPTIONAL technology used for the client software with version if available, such as "Vendor Java 11.0.6". The <loginSec:tech> element value can be created by including the technology vendor, technology name, and technology version, such as the Augmented Backus-Naur Form (ABNF) grammar [RFC5234] format:

tech = vendor SP name SP version
vendor = 1*VCHAR
name = 1*VCHAR
version = 1*VCHAR
<loginSec:os>:

OPTIONAL client operating system used with version if available, such as "x86_64 Mac OS X 10.15.2". The <loginSec:os> element value can be created by including the operating system architecture, operating system name, and operating system version, such as the Augmented Backus-Naur Form (ABNF) grammar [RFC5234] format:

os = arch SP name SP version
arch = 1*VCHAR
name = 1*VCHAR
version = 1*VCHAR
<loginSec:pw>:
OPTIONAL plain text password that is case sensitive, has a minimum length of 6 characters, and has a maximum length that is up to server policy. All leading and trailing whitespace is removed, and all internal contiguous whitespace that includes #x9 (tab), #xA (linefeed), #xD (carriage return), and #x20 (space) is replaced with a single #x20 (space). This element MUST only be set if the [RFC5730] <pw> element is set to the "[LOGIN-SECURITY]" value.
<loginSec:newPW>:
OPTIONAL plain text new password that is case sensitive, has a minimum length of 6 characters, and has a maximum length that is up to server policy. All leading and trailing whitespace is removed, and all internal contiguous whitespace that includes #x9 (tab), #xA (linefeed), #xD (carriage return), and #x20 (space) is replaced with a single #x20 (space). This element MUST only be set if the [RFC5730] <newPW> element is set to the "[LOGIN-SECURITY]" value.
<loginSec:userAgent>:
この要素は選択できます（OPTIONAL）。クライアントのユーザーエージェント情報で、クライアントのアプリケーションソフトウェア、テクノロジー、オペレーティングシステムを識別します。サーバーはこの情報を使用して、クライアントの機能上またはセキュリティー上の制約、現在のセキュリティーの問題、将来起こりうる機能上またはセキュリティー上の問題を特定します。サーバーは、クライアントのアプリケーションソフトウェアに基づいてセキュリティールールのチェックを実行するなど、セキュリティーの問題をリアルタイムに特定してクライアントに通知するためにこの情報を使用することがあります。また、サーバーは、TLS暗号スイートやTLSプロトコルの非推奨化や削除など、将来のセキュリティーポリシーの問題を特定するためにこの情報を収集することがあります。<loginSec:userAgent>要素は、次の子要素のうち少なくとも1つを含まなければなりません（MUST）。
<loginSec:app>:

この要素は選択できます（OPTIONAL）。クライアントのアプリケーションソフトウェアの名前で、可能であればバージョンを含みます。たとえば、クライアントSDKの名前「EPP SDK 1.0.0」などです。<loginSec:app>要素の値は、アプリケーションソフトウェアの名前にバージョン番号を付加することで作成できます。拡張バッカス・ナウア記法（ABNF）[RFC5234]の文法で表すと、次の形式になります。

app = name SP version
name = 1*VCHAR
version = 1*VCHAR
<loginSec:tech>:

この要素は選択できます（OPTIONAL）。クライアントソフトウェアに使用されているテクノロジーで、可能であればバージョンを含みます。たとえば、「Vendor Java 11.0.6」などです。<loginSec:tech>要素の値は、テクノロジーのベンダー、テクノロジーの名前、テクノロジーのバージョンを含めることで作成できます。拡張バッカス・ナウア記法（ABNF）[RFC5234]の文法で表すと、次の形式になります。

tech = vendor SP name SP version
vendor = 1*VCHAR
name = 1*VCHAR
version = 1*VCHAR
<loginSec:os>:

この要素は選択できます（OPTIONAL）。クライアントが使用しているオペレーティングシステムで、可能であればバージョンを含みます。たとえば、「x86_64 Mac OS X 10.15.2」などです。<loginSec:os>要素の値は、オペレーティングシステムのアーキテクチャー、オペレーティングシステムの名前、オペレーティングシステムのバージョンを含めることで作成できます。拡張バッカス・ナウア記法（ABNF）[RFC5234]の文法で表すと、次の形式になります。

os = arch SP name SP version
arch = 1*VCHAR
name = 1*VCHAR
version = 1*VCHAR
<loginSec:pw>:
この要素は選択できます（OPTIONAL）。平文のパスワードで、大文字と小文字を区別し、最小長は6文字、最大長はサーバーポリシーで定めます。先頭と末尾の空白はすべて削除され、#x9（タブ）、#xA（ラインフィード）、#xD（キャリッジリターン）、#x20（スペース）を含む内部の連続した空白はすべて1つの#x20（スペース）に置き換えられます。この要素は、[RFC5730]の<pw>要素が値「[LOGIN-SECURITY]」に設定されている場合にのみ設定しなければなりません（MUST）。
<loginSec:newPW>:
この要素は選択できます（OPTIONAL）。平文の新しいパスワードで、大文字と小文字を区別し、最小長は6文字、最大長はサーバーポリシーで定めます。先頭と末尾の空白はすべて削除され、#x9（タブ）、#xA（ラインフィード）、#xD（キャリッジリターン）、#x20（スペース）を含む内部の連続した空白はすべて1つの#x20（スペース）に置き換えられます。この要素は、[RFC5730]の<newPW>要素が値「[LOGIN-SECURITY]」に設定されている場合にのみ設定しなければなりません（MUST）。

It is RECOMMENDED that the plain text password in the <loginSec:pw> and <loginSec:newPw> elements use printable ASCII characters #x20 (space) - #x7E (~) with high entropy, such as 128 bits. If non-ASCII characters are supported with the plain text password, then use a standard for passwords with international characters; the OpaqueString PRECIS profile in [RFC8265] is recommended in the absence of other considerations.

<loginSec:pw>要素と<loginSec:newPw>要素の平文のパスワードには、128ビットのような高いエントロピーを持つ、印字可能なASCII文字#x20（スペース）～#x7E（~）を使用することが推奨されます（RECOMMENDED）。平文のパスワードで非ASCII文字をサポートする場合は、国際化文字を含むパスワードのための標準を使用してください。ほかに考慮すべき事項がなければ、[RFC8265]のOpaqueString PRECISプロファイルが推奨されます。

7. Security Considerations

7. セキュリティーに関する考慮事項

The security considerations of [RFC5730] apply in this document, and this document enhances these considerations.

[RFC5730]のセキュリティーに関する考慮事項はこの文書にも適用され、この文書はそれらの考慮事項を強化します。

The extension leaves the password (<pw> element) and new password (<newPW> element) minimum length greater than 6 characters and the maximum length up to server policy. The server SHOULD enforce minimum and maximum length requirements that are appropriate for their operating environment. One example of a guideline for password length policies can be found in Section 5 of NIST Special Publication 800-63B.

この拡張では、パスワード（<pw>要素）と新しいパスワード（<newPW>要素）の最小長を6文字を超える長さとし、最大長はサーバーポリシーに委ねています。サーバーは、自身の運用環境に適した最小長と最大長の要件を強制すべきです（SHOULD）。パスワード長のポリシーに関するガイドラインの一例は、NIST Special Publication 800-63Bのセクション5にあります。

The client SHOULD NOT decrease the security of a new password by decreasing the length of the current password. For example, a client with a 20-character password set using the extension should not use the login command in [RFC5730] without using the extension to set a new password that is less than or equal to 16 characters.

クライアントは、現在のパスワードの長さを短くすることによって、新しいパスワードのセキュリティーを低下させるべきではありません（SHOULD NOT）。たとえば、この拡張を使用して20文字のパスワードを設定したクライアントは、この拡張を使用せずに[RFC5730]のログインコマンドを使用して、16文字以下の新しいパスワードを設定すべきではありません。

The extension provides an extensible list of login security events to inform clients of connection and login warnings and errors. The server returning of security events to unauthenticated users needs to take into account the security/privacy issues of returning information to potential attackers.

この拡張は、接続とログインの警告やエラーをクライアントに通知するための、拡張可能なログインセキュリティーイベントの一覧を提供します。認証されていないユーザーにセキュリティーイベントを返すサーバーは、潜在的な攻撃者に情報を返すことによるセキュリティーやプライバシーの問題を考慮する必要があります。

The user-agent information represents the client system of a system-to-system interface, so the user-agent information MUST NOT provide any ability to track individual users or classes of users.

ユーザーエージェント情報はシステム間インターフェイスにおけるクライアントシステムを表すものであるため、ユーザーエージェント情報は、個々のユーザーやユーザーの種類を追跡する手段を提供してはなりません（MUST NOT）。
