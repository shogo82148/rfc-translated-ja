RFC 1088

A Standard for the Transmission of IP Datagrams over NetBIOS Networks

RFC 1088

NetBIOSネットワーク上でのIPデータグラムの伝送に関する標準

Status of This Memo

このメモのステータス

This document specifies a standard method of encapsulating the Internet Protocol [1] (IP) datagrams on NetBIOS [2] networks. Distribution of this memo is unlimited.

この文書は、インターネットプロトコル[1]（IP）のデータグラムをNetBIOS[2]ネットワーク上でカプセル化する標準的な方法を規定します。このメモの配布は無制限です。

Introduction

はじめに

The goal of this specification is to allow compatible and interoperable implementations for transmitting IP datagrams over NetBIOS networks.

この仕様の目的は、NetBIOSネットワーク上でIPデータグラムを伝送する、互換性があり相互運用可能な実装を実現できるようにすることです。

NetBIOS is a standard which specifies a means of creating virtual circuits and of transmitting and receiving point-to-point, multicast, and broadcast datagrams. This specification uses only the datagram services.

NetBIOSは、仮想回線を作成する方法と、ポイントツーポイント、マルチキャスト、ブロードキャストの各データグラムを送受信する方法を規定する標準です。この仕様では、データグラムサービスだけを使用します。

Previous versions of this memo specified the use of the NetBIOS broadcast datagram services instead of the NetBIOS group name services to implement IP broadcasting. These versions are now obsolete.

このメモの以前の版では、IPのブロードキャストを実装するために、NetBIOSのグループ名サービスではなくNetBIOSのブロードキャストデータグラムサービスを使用するよう規定していました。これらの版は現在では廃止されています。

Description

説明

NetBIOS networks may be used to support IP networks and subnets [3] of any class. By means of encapsulating IP datagrams within NetBIOS datagrams and assigning IP numbers to the hosts on a NetBIOS network, IP-based applications are supported on these hosts. The addition of a router capable of encapsulating IP packets within ordinary data-link protocols (such as 802.3 [4]) as well as within NetBIOS datagrams allows these NetBIOS hosts to communicate with the Internet at large.

NetBIOSネットワークは、任意のクラスのIPネットワークおよびサブネット[3]をサポートするために使用できます。IPデータグラムをNetBIOSデータグラム内にカプセル化し、NetBIOSネットワーク上のホストにIP番号を割り当てることで、これらのホスト上でIPベースのアプリケーションがサポートされます。IPパケットをNetBIOSデータグラム内にカプセル化できるだけでなく、通常のデータリンクプロトコル（802.3[4]など）内にもカプセル化できるルーターを追加すれば、これらのNetBIOSホストはインターネット全般と通信できるようになります。

Address Mappings

アドレスのマッピング

In general, NetBIOS names may be any series of 16 bytes, however, a few values are reserved or used by common networking packages. NetBIOS names for the IP applications on each host are chosen on the basis of the internet number of that host. Since NetBIOS names are a mapping of IP addresses, no physical address query mechanism (e.g., ARP [5]) is required.

一般に、NetBIOS名は16バイトの任意の並びでかまいませんが、いくつかの値は予約されているか、一般的なネットワークパッケージで使用されています。各ホスト上のIPアプリケーション用のNetBIOS名は、そのホストのインターネット番号に基づいて選ばれます。NetBIOS名はIPアドレスのマッピングであるため、物理アドレスを問い合わせるメカニズム（たとえばARP[5]）は必要ありません。

For these internet protocol applications, IP.XX.XX.XX.XX is the NetBIOS name for any IP over NetBIOS host where XX represents the ascii hexadecimal representation of that byte of the internet address.

これらのインターネットプロトコルのアプリケーションでは、IP over NetBIOSの任意のホストのNetBIOS名はIP.XX.XX.XX.XXです。ここで、XXはインターネットアドレスの各バイトをASCIIの16進数で表したものです。

This addressing scheme allows for the multiplexing of standard datagram protocols over NetBIOS as well as easy visual confirmation of the correctness of a given packet's address.

このアドレス指定方式により、NetBIOS上で標準のデータグラムプロトコルを多重化できるだけでなく、特定のパケットのアドレスが正しいかどうかを目で見て簡単に確認できます。

Broadcast and Multicast Addresses

ブロードキャストアドレスとマルチキャストアドレス

Broadcast Internet addresses are represented by the NetBIOS group name IP.FF.FF.FF.FF. Currently, no attempt is made to provide support of IP multicast addresses using NetBIOS group names.

ブロードキャストのインターネットアドレスは、NetBIOSのグループ名IP.FF.FF.FF.FFで表します。現時点では、NetBIOSのグループ名を使用してIPマルチキャストアドレスをサポートする試みは行っていません。

Maximum Transmission Unit

最大伝送単位

The maximum data size of a NetBIOS datagram, and therefore the Maximum Transmission Unit (MTU) for IP over NetBIOS networks, is 512 bytes. Therefore, any hosts communicating with a host on a NetBIOS network may be required to reassemble fragmented datagrams.

NetBIOSデータグラムの最大データサイズ、したがってIP over NetBIOSネットワークの最大伝送単位（Maximum Transmission Unit、MTU）は512バイトです。そのため、NetBIOSネットワーク上のホストと通信するホストは、フラグメント化されたデータグラムを再組み立てする必要がある場合があります。

Implementation

実装

To support IP on a NetBIOS host for any given IP address the initialization code must:

NetBIOSホスト上で任意のIPアドレスに対してIPをサポートするには、初期化コードは次のことを行わなければなりません。

  1. Add IP.XX.XX.XX.XX to the host's NetBIOS name table.

  2. Add IP.FF.FF.FF.FF to the host's NetBIOS group name table.

  3. Submit a receive datagram request for the reception of NetBIOS datagrams destined for IP.XX.XX.XX.XX.

  4. Submit a receive datagram request for the reception of NetBIOS datagrams destined for IP.FF.FF.FF.FF.

  1. ホストのNetBIOS名テーブルにIP.XX.XX.XX.XXを追加します。

  2. ホストのNetBIOSグループ名テーブルにIP.FF.FF.FF.FFを追加します。

  3. IP.XX.XX.XX.XX宛てのNetBIOSデータグラムを受信するために、データグラム受信要求（receive datagram request）を発行します。

  4. IP.FF.FF.FF.FF宛てのNetBIOSデータグラムを受信するために、データグラム受信要求を発行します。

When a NetBIOS datagram to either address is received, it is processed by the protocol stack and another receive datagram request is submitted.

どちらかのアドレス宛てのNetBIOSデータグラムを受信すると、それはプロトコルスタックによって処理され、新たなデータグラム受信要求が発行されます。

When an IP datagram is sent, it is considered to be NetBIOS datagram data and sent by a send datagram request to either IP.XX.XX.XX.XX or IP.FF.FF.FF.FF.

IPデータグラムを送信するときは、それをNetBIOSデータグラムのデータとみなし、データグラム送信要求（send datagram request）によってIP.XX.XX.XX.XXまたはIP.FF.FF.FF.FFのどちらかに送信します。

Optionally, the IP software may desire to make adapter status queries of the NetBIOS network. As support for SNMP becomes a requirement for IP hosts, these adapter status queries may become mandatory.

オプションとして、IPソフトウェアがNetBIOSネットワークに対してアダプター状態の問い合わせ（adapter status query）を行いたい場合もあるでしょう。IPホストにとってSNMPのサポートが要件になるにつれ、これらのアダプター状態の問い合わせは必須になるかもしれません。

Finally, when the IP support for a given NetBIOS host is discontinued, a cancel command request should be submitted for every pending receive datagram, and a delete name request should be submitted for both the IP.XX.XX.XX.XX and IP.FF.FF.FF.FF address added during initialization.

最後に、特定のNetBIOSホストに対するIPのサポートを終了するときは、保留中のすべてのデータグラム受信に対してコマンド取り消し要求（cancel command request）を発行し、初期化時に追加したIP.XX.XX.XX.XXとIP.FF.FF.FF.FFの両方のアドレスに対して名前削除要求（delete name request）を発行すべきです。
