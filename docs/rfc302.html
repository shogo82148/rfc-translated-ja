RFC 302

Exercising The ARPANET

RFC 302

ARPANETを使ってみる

Questions

問い

  1. Can a technically competent person, initially uninformed as to network operation and naive as to the capabilities of various time-shared terminal systems attached to the Network, be able to develop problem solving competence at server sites on the ARPANET?
  2. What inherent user problems exist that complicate such adaptation?
  3. Once proficient in the use, what aspects of the various sites limit the usability and what modifications should be considered at both server and user sites to meet various needs?
  4. Should a user select a given site for composing and editing all of his files for subsequent transfer to other sites for processing or should he learn to compose and edit at each of the sites doing his processing?
  5. What are the problems in starting cooperating processes at several sites? How does a user control such processes?
  1. 技術的な能力はあるものの、最初はネットワークの運用について知らず、ネットワークに接続されたさまざまなタイムシェアリング端末システムの機能についても詳しくない人が、ARPANET上のサーバーサイトで問題を解決する能力を身につけることはできるでしょうか？
  2. そのような適応を難しくする、ユーザーに固有の問題にはどのようなものがあるでしょうか？
  3. 使い方に習熟したあと、さまざまなサイトのどのような点が使いやすさを制限しているでしょうか？また、さまざまなニーズを満たすために、サーバーサイトとユーザーサイトの両方でどのような修正を検討すべきでしょうか？
  4. ユーザーは、ある特定のサイトを選んで自分のファイルをすべてそこで作成・編集し、処理のためにあとでほかのサイトへ転送すべきでしょうか？それとも、処理を行うそれぞれのサイトで作成・編集する方法を学ぶべきでしょうか？
  5. 複数のサイトで協調するプロセスを開始する際には、どのような問題があるでしょうか？ユーザーはそのようなプロセスをどのように制御するのでしょうか？

Obtaining the Answers

答えを得る

Under the direction of UCSB Professor James Howard, a test group of 14 graduate students was formed to pursue the questions above, and any other aspect of ARPANET operation that they might uncover.

UCSBのJames Howard教授の指導のもと、上記の問いと、そのほかに見つかるかもしれないARPANETの運用に関するあらゆる側面を追究するため、14名の大学院生からなるテストグループを結成しました。

The test group has been given access to the 16 console On-Line System classroom in the E.E. Department at UCSB. The 16 consoles produce graphic and alphanumeric displays and are tied into the UCSB Host 360-75 which gains them access to the network. Old style Culler-Fried keyboards are being used which provide a limited key set Jim White has managed to program around most of the protocol problems brought about by these keyboards, but some still remain.

テストグループは、UCSBの電気工学科にある、16台のコンソールを備えたOn-Line Systemの教室を利用できるようになっています。16台のコンソールはグラフィックと英数字の表示ができ、UCSBのホスト360-75につながっていて、そこからネットワークにアクセスできます。使っているのは旧式のCuller-Friedキーボードで、使えるキーの種類が限られています。Jim Whiteは、これらのキーボードが引き起こすプロトコル上の問題の大部分をプログラムで回避することに成功しましたが、まだいくつか残っています。

Seminars were given to the test group to familiarize them with software and hardware aspects of the ARPANET, the local NIC file has been made available to the group, and the group has been allowed to sign onto the Network to pursue any available system.

テストグループにARPANETのソフトウェアとハードウェアの側面に慣れてもらうためにセミナーを開き、ローカルのNICファイルをグループが利用できるようにし、利用可能などのシステムでも追究できるようにグループがネットワークにサインオンすることを許可しました。

Some Initial Results

初期の結果

The first real encounters with the ARPANET at large produced a series of questions and comments. Test group comments are itemized below with additional comments by the author {In braces}. We plan subsequent reports on a periodic basis.

ARPANET全体と初めて本格的に接したことで、一連の質問や意見が出ました。テストグループの意見を以下に項目別に挙げ、著者による補足を{波かっこ内}に記します。今後も定期的に報告する予定です。

  1. We find that we need further information about access to the NCPs at various sites. User manuals from the sites might provide this. {Site response is solicited}
  2. We sometimes cannot sign into UCLA-NMC directly from UCSB, but can do so readily by way of BBN. {Protocol?}
  3. After running a Fortran or PL-1 program at some net location we can only display the results on our consoles but cannot store them as files. {UCSB programming need?}
  4. When communications break down how can a user be assured that he is logged out of some remote site? {Need for automatic Log-out?}
  5. How do we make contact with programmers at other sites to develop cooperative programs for file transfer, etc? {Jim White?}
  6. Is there a best time of day for operation at each site? Should contact be made with the site operator prior to user sessions? {Server sites please comment}
  7. UCLA-NMC has assigned a separate user identification for test group use. Would other sites prefer to do likewise? {Comments?}
  8. Is there information regarding uses made of the various time shared systems by internal users at each site? Does a bibliography exist to allow contact with such users? {Check the Resource Notebook}
  9. MIT-DMCG and BBN provide very good user service, especially the site survey. Also these sites have good responses to define events. Can UCSB provide local users with similar information? {Jim White?}
  1. さまざまなサイトのNCPへのアクセスについて、さらに情報が必要だとわかりました。各サイトのユーザーマニュアルがあれば、この情報が得られるかもしれません。{サイトからの回答を求めます}
  2. UCSBからUCLA-NMCへ直接サインインできないことがありますが、BBNを経由すれば簡単にサインインできます。{プロトコルの問題？}
  3. ネット上のどこかでFortranやPL-1のプログラムを実行したあと、結果をコンソールに表示することしかできず、ファイルとして保存できません。{UCSB側でプログラミングが必要？}
  4. 通信が途絶えたとき、ユーザーはリモートサイトから自分がログアウトしたことをどうやって確かめればよいのでしょうか？{自動ログアウトが必要？}
  5. ファイル転送などのための協調プログラムを開発するには、ほかのサイトのプログラマーとどうやって連絡を取ればよいのでしょうか？{Jim White？}
  6. 各サイトには、運用に最適な時間帯があるのでしょうか？ユーザーのセッションの前に、サイトのオペレーターに連絡を取るべきでしょうか？{サーバーサイトの意見をお願いします}
  7. UCLA-NMCは、テストグループ用に別のユーザー識別子を割り当ててくれました。ほかのサイトも同じようにするほうがよいでしょうか？{ご意見は？}
  8. 各サイトの内部ユーザーがさまざまなタイムシェアリングシステムをどのように使っているかについての情報はあるでしょうか？そのようなユーザーと連絡を取れるような文献一覧はあるでしょうか？{Resource Notebookを確認}
  9. MIT-DMCGとBBNは、とても優れたユーザーサービスを提供しており、特にサイト調査が優れています。また、これらのサイトはイベントの定義にもよく応えてくれます。UCSBもローカルのユーザーに同様の情報を提供できるでしょうか？{Jim White？}
