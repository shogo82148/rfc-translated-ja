RFC 946

Telnet terminal location number option

RFC 946

Telnetの端末位置番号オプション

Status of This Memo

このメモのステータス

This RFC proposes a new option for Telnet for the ARPA-Internet community, and requests discussion and suggestions for improvements. Distribution of this memo is unlimited.

このRFCは、ARPAインターネットコミュニティーのためにTelnetの新しいオプションを提案し、改善のための議論と提案を求めるものです。このメモの配布は無制限です。

Overview

概要

In a community of users that share a large degree of common facilities, it is often advantageous to use some common feature to improve software performance and reduce initial implementation costs.

共通の設備を大部分で共有しているユーザーのコミュニティーでは、何らかの共通の機能を使ってソフトウェアの性能を高め、初期の実装コストを削減すると有利なことがよくあります。

In March of 1982, CMU designed and implemented based on the growing CMU PUP-based network a terminal location database and modified existing network software to handle a 64-bit number which some call the Terminal Location Number or TTYLOC for short. The number can be efficiently stored in operating systems tables and can be passed between various levels of operating system and network layering with minimum modifications to existing software. An initial evaluation of changing software to communicate an unfixed or reasonable length terminal location string indicated it would be expensive.

1982年3月、CMUは、成長を続けていたCMUのPUPベースのネットワークを基盤として、端末位置のデータベースを設計、実装し、既存のネットワークソフトウェアを変更して、端末位置番号（Terminal Location Number）、略してTTYLOCと呼ばれる64ビットの番号を扱えるようにしました。この番号は、オペレーティングシステムのテーブルに効率よく格納でき、既存のソフトウェアへの変更を最小限に抑えつつ、オペレーティングシステムやネットワークの階層のさまざまなレベルの間で受け渡すことができます。長さが固定されていない、または相応の長さの端末位置の文字列を伝えるようにソフトウェアを変更することについて初期評価を行ったところ、コストが高くつくことがわかりました。

CMU now wishes to extend this mechanism into the TCP-based networking support that is replacing the existing PUP-based software. The mechanism is not viewed as a replacement for the Telnet Terminal Location (SEND-LOCATION) Option but as a shorthand mechansim for communicating hosts in the same community.

CMUは現在、この仕組みを、既存のPUPベースのソフトウェアを置き換えつつあるTCPベースのネットワークのサポートにも拡張したいと考えています。この仕組みは、TelnetのTerminal Location（SEND-LOCATION）オプションを置き換えるものではなく、同じコミュニティー内のホスト間で通信するための簡略な仕組みと位置付けられています。

TTYLOC Number

TTYLOC番号

The TTYLOC number is a 64-bit number composed of two (2) 32-bit numbers: The 32-bit official ARPA Internet host address (may be any one of the addresses for multi-homed hosts) and a 32-bit number representing the terminal on the specified host. The host address of [0.0.0.0] is defined to be "unknown", the terminal number of FFFFFFFF (hex, r or-1 in decimal) is defined to be "unknown" and the terminal number of FFFFFFFE (hex, or -2 in decimal) is defined to be "detached" for processes that are not attached to a terminal.

TTYLOC番号は、2つの32ビットの数値で構成される64ビットの数値です。1つは32ビットの公式なARPAインターネットのホストアドレス（マルチホームのホストでは、そのアドレスのどれでもかまいません）で、もう1つは指定されたホスト上の端末を表す32ビットの数値です。ホストアドレス[0.0.0.0]は「不明（unknown）」と定義されます。端末番号FFFFFFFF（16進数。10進数では-1）は「不明（unknown）」と定義され、端末番号FFFFFFFE（16進数。10進数では-2）は、端末に接続されていないプロセスを表す「切り離し（detached）」と定義されます。

1. Command Name and Option Code

1. コマンド名とオプションコード

TTYLOC 28

2. Command Meanings

2. コマンドの意味

IAC WILL TTYLOC
The sender offers to send the TTYLOC information or confirms that it can send the TTYLOC information.
IAC WON'T TTYLOC
The sender refuses to send the TTYLOC information.
IAC DO TTYLOC
The sender requests to receive the TTYLOC information or confirms that it will receive the TTYLOC information.
IAC DON'T TTYLOC
The sender refuses to receive the TTYLOC information.
IAC SB TTYLOC <format> <TTYLOC number with IAC doubling> IAC SE
The sender is transmitting the TTYLOC information. The 64-bit TTYLOC number has format 0. The first 32-bits is the Internet host number and the second 32-bits is the line on the specified Internet host. The bytes are in most significant 8-bit byte to least significant byte order.
IAC WILL TTYLOC
送信者は、TTYLOCの情報を送信することを申し出るか、TTYLOCの情報を送信できることを確認します。
IAC WON'T TTYLOC
送信者は、TTYLOCの情報を送信することを拒否します。
IAC DO TTYLOC
送信者は、TTYLOCの情報を受信することを要求するか、TTYLOCの情報を受信することを確認します。
IAC DON'T TTYLOC
送信者は、TTYLOCの情報を受信することを拒否します。
IAC SB TTYLOC <format> <IACを二重化したTTYLOC番号> IAC SE
送信者は、TTYLOCの情報を送信しています。64ビットのTTYLOC番号の形式は0です。最初の32ビットはインターネットのホスト番号で、次の32ビットは指定されたインターネットのホスト上の回線です。バイトは、最上位の8ビットのバイトから最下位のバイトの順に並びます。

4. Motivation

4. 動機

Many systems provide a mechanism for finding out where a user is logged in from usually including information about telephone extension and office occupants names. The information is useful for physically locating people and/or calling them on the phone.

多くのシステムには、ユーザーがどこからログインしているかを調べる仕組みがあり、通常は電話の内線番号やオフィスの使用者名に関する情報も含まれます。この情報は、人の物理的な居場所を突き止めたり、電話をかけたりするのに便利です。

For incoming network connections to a host, only the remote host's name is available. This option and the Telnet Terminal Location option (RFC-779) provide the information to the system so it in turn can provide the information to the various mechanisms (FINGER, WHOIS, etc.).

ホストへの着信のネットワークコネクションでは、リモートホストの名前しか得られません。このオプションと、TelnetのTerminal Locationオプション（RFC-779）は、システムに情報を提供し、システムがさらにその情報をさまざまな仕組み（FINGER、WHOISなど）に提供できるようにします。

5. Description of the Option

5. このオプションの説明

When the user Telnet connects to a remote host, it can attempt to send the terminal location number information by doing a IAC WILL TTYLOC command. If the Telnet server can use the information, it replies with a IAC DO TTYLOC command. The user Telnet then sends the TTYLOC number in the subnegotiation.

ユーザーTelnetは、リモートホストに接続するときに、IAC WILL TTYLOCコマンドを送ることで、端末位置番号の情報を送信しようと試みることができます。Telnetサーバーがその情報を利用できる場合は、IAC DO TTYLOCコマンドで応答します。その後、ユーザーTelnetはサブネゴシエーションでTTYLOC番号を送信します。

It is recommended that if sending the TTYLOC number is refused then the Telnet Terminal Location (SEND-LOCATION in RFC-779) should be attempted.

TTYLOC番号の送信が拒否された場合は、TelnetのTerminal Location（RFC-779のSEND-LOCATION）を試みることを推奨します。

The following are two example usage scenarios:

次に、2つの使用シナリオの例を示します。

User Side First:

ユーザー側が先の場合：

(User) Host1: IAC WILL TTYLOC
Host1 is asking if it can send the 64-bit terminal location number (I will send...).
(Server) Host2: IAC DO TTYLOC
Host2 indicates to Host1 that it will accept the 64-bit terminal location number in a subnegotiation (You please do ...).
(User) Host1: IAC SB TTYLOC 0 <64-bit number> IAC SE
Host1 is sending the location number to Host2 which can communicate the number to the operating system or other system components.
（ユーザー）Host1: IAC WILL TTYLOC
Host1は、64ビットの端末位置番号を送信してよいかを尋ねています（I will send...）。
（サーバー）Host2: IAC DO TTYLOC
Host2はHost1に対して、サブネゴシエーションで64ビットの端末位置番号を受け入れることを示します（You please do ...）。
（ユーザー）Host1: IAC SB TTYLOC 0 <64ビットの番号> IAC SE
Host1はHost2に位置番号を送信しています。Host2は、その番号をオペレーティングシステムや他のシステムコンポーネントに伝えることができます。

Server Side First:

サーバー側が先の場合：

(Server) HostA: IAC DO TTYLOC
HostA indicates to HostB that it would like to know the 64-bit terminal location number (You please do ...).
(User) HostB: IAC WILL TTYLOC
HostB agrees to send the 64-bit terminal location number to HostA in a subnegotiation (I will send...).
(User) HostB: IAC SB TTYLOC 0 <64-bit number> IAC SE
HostB is sending the location number to HostA which can communicate the number to the operating system or other system components.
（サーバー）HostA: IAC DO TTYLOC
HostAはHostBに対して、64ビットの端末位置番号を知りたいことを示します（You please do ...）。
（ユーザー）HostB: IAC WILL TTYLOC
HostBは、サブネゴシエーションで64ビットの端末位置番号をHostAに送信することに同意します（I will send...）。
（ユーザー）HostB: IAC SB TTYLOC 0 <64ビットの番号> IAC SE
HostBはHostAに位置番号を送信しています。HostAは、その番号をオペレーティングシステムや他のシステムコンポーネントに伝えることができます。
