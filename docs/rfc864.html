RFC 864

Character Generator Protocol

RFC 864

キャラクタージェネレータープロトコル

Abstract

概要

This RFC specifies a standard for the ARPA Internet community. Hosts on the ARPA Internet that choose to implement a Character Generator Protocol are expected to adopt and implement this standard.

このRFCは、ARPAインターネットコミュニティーのための標準を規定します。ARPAインターネット上のホストのうち、Character Generatorプロトコルを実装することにしたホストは、この標準を採用して実装することが求められます。

A useful debugging and measurement tool is a character generator service. A character generator service simply sends data without regard to the input.

キャラクタージェネレーター（character generator）サービスは、デバッグや計測に役立つツールです。キャラクタージェネレーターサービスは、入力に関係なく、単にデータを送信します。

TCP Based Character Generator Service

TCPベースのキャラクタージェネレーターサービス

One character generator service is defined as a connection based application on TCP. A server listens for TCP connections on TCP port 19. Once a connection is established a stream of data is sent out the connection (and any data received is thrown away). This continues until the calling user terminates the connection.

1つ目のキャラクタージェネレーターサービスは、TCP上のコネクションベースのアプリケーションとして定義します。サーバーはTCPポート19でTCPコネクションを待ち受けます。コネクションが確立されると、データのストリームがそのコネクションに送り出されます（受信したデータはすべて捨てられます）。これは、呼び出し側のユーザーがコネクションを終了するまで続きます。

It is fairly likely that users of this service will abruptly decide that they have had enough and abort the TCP connection, instead of carefully closing it. The service should be prepared for either the carfull close or the rude abort.

このサービスのユーザーは、丁寧にTCPコネクションを閉じるのではなく、もう十分だと判断して突然コネクションを中断（abort）することがかなり多いと考えられます。サービスは、丁寧なクローズと乱暴な中断のどちらにも備えておくべきです。

The data flow over the connection is limited by the normal TCP flow control mechanisms, so there is no concern about the service sending data faster than the user can process it.

コネクション上のデータの流れは通常のTCPのフロー制御の仕組みによって制限されるので、ユーザーが処理できるよりも速くサービスがデータを送信することを心配する必要はありません。

UDP Based Character Generator Service

UDPベースのキャラクタージェネレーターサービス

Another character generator service is defined as a datagram based application on UDP. A server listens for UDP datagrams on UDP port 19. When a datagram is received, an answering datagram is sent containing a random number (between 0 and 512) of characters (the data in the received datagram is ignored).

もう1つのキャラクタージェネレーターサービスは、UDP上のデータグラムベースのアプリケーションとして定義します。サーバーはUDPポート19でUDPデータグラムを待ち受けます。データグラムを受信すると、ランダムな数（0から512の間）の文字を含む応答のデータグラムを送信します（受信したデータグラム内のデータは無視します）。

There is no history or state information associated with the UDP version of this service, so there is no continuity of data from one answering datagram to another.

このサービスのUDP版には、履歴や状態の情報が結び付いていません。そのため、ある応答データグラムと次の応答データグラムとの間で、データの連続性はありません。

The service only send one datagram in response to each received datagram, so there is no concern about the service sending data faster than the user can process it.

サービスは、受信したデータグラム1つにつき1つのデータグラムしか応答として送信しないので、ユーザーが処理できるよりも速くサービスがデータを送信することを心配する必要はありません。

Data Syntax

データの構文

The data may be anything. It is recommended that a recognizable pattern be used in tha data.

データは何でもかまいません。データには、見てそれとわかるパターンを使うことを推奨します。

One popular pattern is 72 chraracter lines of the ASCII printing characters. There are 95 printing characters in the ASCII character set. Sort the characters into an ordered sequence and number the characters from 0 through 94. Think of the sequence as a ring so that character number 0 follows character number 94. On the first line (line 0) put the characters numbered 0 through 71. On the next line (line 1) put the characters numbered 1 through 72. And so on. On line N, put characters (0+N mod 95) through (71+N mod 95). End each line with carriage return and line feed.

よく使われるパターンの1つは、ASCIIの印字可能文字を1行72文字で並べたものです。ASCII文字セットには95個の印字可能文字があります。これらの文字を順序のある列に並べ、0から94までの番号を付けます。この列を環とみなし、文字番号94の次に文字番号0が来るようにします。最初の行（行0）には、番号0から71までの文字を置きます。次の行（行1）には、番号1から72までの文字を置きます。以下同様です。行Nには、文字（0+N mod 95）から文字（71+N mod 95）までを置きます。各行の終わりには復帰（carriage return）と改行（line feed）を付けます。
