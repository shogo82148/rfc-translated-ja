RFC 769

Rapicom 450 Facsimile File Format

RFC 769

Rapicom 450ファクシミリファイルフォーマット

Introduction

はじめに

Several organizations in the ARPA Internet community have RAPICOM 450 facsimile machines interfaced to computers. This allows these organizations to enter a facsimile representation of a page into a computer file, and to produce a page from stored facsimile data. These organizations can exchange stored facsimile data via file transfer and other protocols. The purpose of this note is to document the format used for these files so that other organizations with compatible facsimile devices can join in this information exchange procedure.

ARPAインターネットコミュニティーのいくつかの組織は、コンピューターに接続したRAPICOM 450ファクシミリ装置を持っています。これにより、これらの組織は、ページのファクシミリ表現をコンピューターのファイルに取り込んだり、格納されたファクシミリデータからページを出力したりできます。これらの組織は、格納したファクシミリデータを、ファイル転送やその他のプロトコルを使って交換できます。このノートの目的は、互換性のあるファクシミリ装置を持つほかの組織もこの情報交換の手順に参加できるように、これらのファイルに使われているフォーマットを文書化することです。

The Rapicom 450

Rapicom 450

The Rapicom 450 has a built in encoding/decoding scheme. It produces data blocks of 585 bits. There are "set up" blocks and "data" blocks. The machine sends/receives several copies of the set up block, but since they are identical only one set up block is stored in the file.

Rapicom 450には、符号化/復号の方式が組み込まれています。Rapicom 450は585ビットのデータブロックを生成します。ブロックには「セットアップ」ブロックと「データ」ブロックがあります。装置はセットアップブロックの複製を何個か送受信しますが、それらは同一なので、ファイルにはセットアップブロックを1つだけ格納します。

Records

レコード

Each 585 bit block is placed in a record of 8-bit bytes. The record format is a length byte, a command byte and the data bytes. Each record is an integral number of bytes. The length value includes the length byte and the command byte. The command describes the data in the data field.

585ビットの各ブロックは、8ビットバイトのレコードに格納されます。レコードのフォーマットは、長さバイト、コマンドバイト、データバイトの順です。各レコードは整数個のバイトから成ります。長さの値には、長さバイトとコマンドバイトも含まれます。コマンドは、データフィールドのデータの内容を表します。

Commands

コマンド

56 - SET-UP
The command code 56 (70 octal) indicates the following data field is a set up block.
57 - DATA
The command code 57 (71 octal) indicates the following data field is a data block.
58 - END
The command code 58 (72 octal) indicates that this is the last record in the file. In this case the length may be 2, indicating that there is no data in this record.
56 - SET-UP
コマンドコード56（8進数で70）は、後続のデータフィールドがセットアップブロックであることを示します。
57 - DATA
コマンドコード57（8進数で71）は、後続のデータフィールドがデータブロックであることを示します。
58 - END
コマンドコード58（8進数で72）は、これがファイルの最後のレコードであることを示します。この場合、長さは2でもかまいません。これは、このレコードにデータがないことを示します。

Conventions

慣例

In the files exchanged to date, each record contains one block. This means the data field is 74 bytes long (585/8=73.125), and the length field has the value 76 (114 octal), except the last record which may carry no data and have a length of 2.

これまでに交換されたファイルでは、各レコードに1つのブロックが含まれています。つまり、データフィールドの長さは74バイト（585/8=73.125）であり、長さフィールドの値は76（8進数で114）です。ただし、最後のレコードはデータを持たず、長さが2であることもあります。

The first record of a file is always a SET UP record, the following records are DATA records, until the last record which is an END record.

ファイルの最初のレコードは常にSET UPレコードで、それに続くレコードはDATAレコードであり、最後のレコードはENDレコードです。

Details

詳細

The 585 bit data block is encoded by the Rapicom 450 and so can not be used a bit map unless the encoding/decoding procedure is known and used.

585ビットのデータブロックはRapicom 450によって符号化されているので、符号化/復号の手順を知っていてそれを使うのでない限り、ビットマップとしては使えません。

The first 24 bits of the block is always a synchronization mark with the value 271 141 344 in octal or 101110010110000111100100 in binary.

ブロックの最初の24ビットは常に同期マークで、その値は8進数で271 141 344、2進数で101110010110000111100100です。

The low order two bits of the next byte contain a sequence number (modulo 4). The sequence number bits cycle in the order 11, 01, 10, 00, starting with the first DATA record (not the SET UP record).

次のバイトの下位2ビットには、シーケンス番号（4を法とする）が入ります。シーケンス番号のビットは、最初のDATAレコード（SET UPレコードではありません）から始まって、11、01、10、00の順に循環します。

以下の行はDATAレコードを表します。ここで、Lは長さのビット、Cはコマンドのビット、Mは同期マーク、Sはシーケンスのビット、Fは埋め草（fill）のビットを表し、ダッシュはその他の68個のデータオクテット、Dはデータのビットを表します。
