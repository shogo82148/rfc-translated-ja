RFC 1864

The Content-MD5 Header Field

RFC 1864

Content-MD5ヘッダーフィールド

Abstract

概要

This memo specifies an optional header field, Content-MD5, for use with MIME-conformant messages.

このメモは、MIMEに準拠したメッセージで使用する任意のヘッダーフィールドContent-MD5を規定します。

Status of This Memo

このメモのステータス

This document specifies an Internet standards track protocol for the Internet community, and requests discussion and suggestions for improvements. Please refer to the current edition of the "Internet Official Protocol Standards" (STD 1) for the standardization state and status of this protocol. Distribution of this memo is unlimited.

1. Introduction

1. はじめに

Despite all of the mechanisms provided by MIME [1] which attempt to protect data from being damaged in the course of email transport, it is still desirable to have a mechanism for verifying that the data, once decoded, are intact. For this reason, this memo defines the use of an optional header field, Content-MD5, which may be used as a message integrity check (MIC), to verify that the decoded data are the same data that were initially sent. The Content-MD5 header may also be placed in the encapsulated headers of an object of type message/external-body, to be used to verify that the retreived and decoded data are the same data that were initially referenced.

MIME[1]は電子メールの転送中にデータが損傷するのを防ごうとするさまざまな仕組みを提供していますが、それでもなお、デコードしたデータが無傷であることを検証する仕組みが望まれます。そのため、このメモでは、任意のヘッダーフィールドContent-MD5の使い方を定義します。このフィールドはメッセージ完全性チェック（MIC: message integrity check）として、デコードしたデータが最初に送信されたデータと同じであることの検証に使用できます。Content-MD5ヘッダーは、message/external-body型のオブジェクトのカプセル化されたヘッダーに置くこともでき、その場合は、取得してデコードしたデータが最初に参照されたデータと同じであることの検証に使用されます。

MD5 is an algorithm for computing a 128 bit "digest" of arbitrary-length data, with a high degree of confidence that any alterations in the data will be reflected in alterations in the digest. The MD5 algorithm itself is defined in [2]. This memo specifies how the algorithm may be used as an integrity check for MIME mail.

MD5は、任意の長さのデータから128ビットの「ダイジェスト」を計算するアルゴリズムで、データに何らかの変更があればダイジェストにも変化が現れることが高い確度で期待できます。MD5アルゴリズムそのものは[2]で定義されています。このメモでは、このアルゴリズムをMIMEメールの完全性チェックとして使う方法を規定します。

2. Generation of the Content-MD5 Field

2. Content-MD5フィールドの生成

The Content-MD5 field is generated by only an originating user agent. Message relays and gateways are expressly forbidden from generating a Content-MD5 field.

Content-MD5フィールドを生成するのは、発信元のユーザーエージェントだけです。メッセージの中継者やゲートウェイがContent-MD5フィールドを生成することは明示的に禁止されています。

Use of the Content-MD5 field is completely optional, but its use is recommended whenever data integrity is desired, but Privacy-Enhanced Mail services [3] are not available. (Consult Section 4 for further details.) The Content-MD5 field may only be added to MIME entities of a `leaf' nature, i.e., the Content-MD5 field may be used with any content type other than multipart or message/rfc822.

Content-MD5フィールドの使用はまったくの任意ですが、データの完全性が求められ、かつPrivacy-Enhanced Mailのサービス[3]が利用できない場合には、使用が推奨されます。（詳細はセクション4を参照してください。）Content-MD5フィールドは「葉」の性質を持つMIMEエンティティーにだけ追加できます。つまり、Content-MD5フィールドは、multipartとmessage/rfc822以外の任意のコンテンツタイプで使用できます。

To generate the value of the Content-MD5 field, the MD5 algorithm is computed on the canonical form of the MIME entity's object. In particular, this means that the sender applies the MD5 algorithm on the data immediately after conversion to canonical form, before applying any content-transfer-encoding, and that the receiver also applies the MD5 algorithm on the canonical form, after undoing any content-transfer-encoding. For textual data, this means the MD5 algorithm must be computed on data in which the canonical form for newlines applies, that is, in which each newline is represented by a CR-LF pair. The canonical encoding model of MIME is described in Appendix G of [1].

Content-MD5フィールドの値を生成するには、MIMEエンティティーのオブジェクトの正規形に対してMD5アルゴリズムを計算します。具体的には、送信者は正規形に変換した直後、コンテンツ転送エンコーディング（content-transfer-encoding）を適用する前のデータに対してMD5アルゴリズムを適用し、受信者もコンテンツ転送エンコーディングを元に戻した後の正規形に対してMD5アルゴリズムを適用するということです。テキストデータの場合は、改行の正規形を適用したデータ、つまり各改行をCR-LFの組で表したデータに対してMD5アルゴリズムを計算しなければならないということです。MIMEの正規エンコーディングモデルは[1]の付録Gで説明されています。

The output of the MD5 algorithm is a 128 bit digest. When viewed in network byte order (big-endian order), this yields a sequence of 16 octets of binary data. These 16 octets are then encoded according to the base64 algorithm in order to obtain the value that is placed in the Content-MD5 field. Thus, if the application of the MD5 algorithm over the raw data of a MIME entity results in a digest having the (unlikely) value of "Check Integrity!", then that MIME entity's header could contain the field

MD5アルゴリズムの出力は128ビットのダイジェストです。これをネットワークバイトオーダー（ビッグエンディアン順）で見ると、16オクテットのバイナリーデータの列になります。この16オクテットをbase64アルゴリズムに従ってエンコードして、Content-MD5フィールドに置く値を得ます。したがって、あるMIMEエンティティーの生データにMD5アルゴリズムを適用した結果、ダイジェストが（ありそうにありませんが）"Check Integrity!"という値になった場合、そのMIMEエンティティーのヘッダーには次のフィールドが含まれることになります。

     Content-MD5:  Q2hlY2sgSW50ZWdyaXR5IQ==

     Content-MD5:  Q2hlY2sgSW50ZWdyaXR5IQ==

Finally, as discussed in Appendix B of [1], textual data is regularly altered in the normal delivery of mail. Because the addition or deletion of trailing white space will result in a different digest, either the quoted-printable or base64 algorithm should be employed as a content-transfer-encoding when the Content-MD5 field is used.

最後に、[1]の付録Bで論じられているように、テキストデータはメールの通常の配送の過程でしばしば変更されます。末尾の空白の追加や削除によってダイジェストが変わってしまうので、Content-MD5フィールドを使用する場合は、コンテンツ転送エンコーディングとしてquoted-printableかbase64のどちらかのアルゴリズムを用いるべきです。

3. Processing the Content-MD5 field

3. Content-MD5フィールドの処理

If the Content-MD5 field is present, a recipient user agent may choose to use it to verify that the contents of a MIME entity have not been modified during transport. Message relays and gateways are expressly forbidden to alter their processing based on the presence of the Content-MD5 field. However, a message gateway is allowed to remove the Content-MD5 field if the corresponding MIME entity is translated into a different content-type.

Content-MD5フィールドが存在する場合、受信者のユーザーエージェントは、それを使ってMIMEエンティティーの内容が転送中に変更されていないことを検証することを選べます。メッセージの中継者やゲートウェイが、Content-MD5フィールドの有無によって処理を変えることは明示的に禁止されています。ただし、メッセージゲートウェイは、対応するMIMEエンティティーを別のコンテンツタイプに変換する場合には、Content-MD5フィールドを削除することが許されています。

4. Security Considerations

4. セキュリティーに関する考慮事項

This document specifies a data integrity service that protects data from accidental modification while in transit from the sender to the recipient. A secure data integrity service, such as that provided by Privacy Enhanced Mail [3], is conjectured to protect data from all modifications.

この文書は、送信者から受信者へ転送される間の偶発的な変更からデータを保護するデータ完全性サービスを規定します。Privacy Enhanced Mail[3]が提供するような安全なデータ完全性サービスであれば、あらゆる変更からデータを保護できると考えられます。
