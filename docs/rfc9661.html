RFC 9661

The JSON Meta Application Protocol (JMAP) for Sieve Scripts

RFC 9661

Sieveスクリプトのための JSON Meta Application Protocol（JMAP）

Abstract

概要

This document specifies a data model for managing Sieve scripts on a server using the JSON Meta Application Protocol (JMAP). Clients can use this protocol to efficiently search, access, organize, and validate Sieve scripts.

この文書は、JSON Meta Application Protocol（JMAP）を使用してサーバー上のSieveスクリプトを管理するためのデータモデルを規定します。 クライアントはこのプロトコルを使用して、Sieveスクリプトの検索、アクセス、整理、検証を効率的に行えます。

1. Introduction

1. はじめに

[RFC8620] is a generic protocol for synchronizing data, such as mail, calendars, or contacts, between a client and a server. It is optimized for mobile and web environments, and it aims to provide a consistent interface to different data types.

[RFC8620]は、メール、カレンダー、連絡先などのデータをクライアントとサーバーの間で同期するための汎用プロトコルです。 JMAPはモバイル環境とWeb環境に最適化されており、さまざまなデータ型に対して一貫したインターフェイスを提供することを目指しています。

This specification defines a data model for managing [RFC5228] on a server using JMAP. The data model is designed to allow a server to provide consistent access to the same scripts via [RFC5804] as well as JMAP.

この仕様は、JMAPを使用してサーバー上の[RFC5228]を管理するためのデータモデルを定義します。 このデータモデルは、サーバーがJMAPだけでなく[RFC5804]を介しても、同じスクリプトへの一貫したアクセスを提供できるように設計されています。

Type signatures, examples, and property descriptions in this document follow the conventions established in Section 1.1 of [RFC8620]. This document also uses data types and terminology established in Sections 1.2 through 1.6 of [RFC8620].

「SieveScript」という用語（この大文字小文字の表記どおりのもの）は、Section 2で定義するデータ型と、この文書全体で使用されるこのデータ型のインスタンスを指すために使用します。 サーバーは、この文書で定義するデータ型に規定されたすべてのプロパティーをサポートしなければなりません（MUST）。

1.2. Addition to the Capabilities Object

1.2. capabilitiesオブジェクトへの追加

The "capabilities" object is returned as part of the JMAP Session object; see [RFC8620], Section 2. This document defines one additional capability URI.

「capabilities」オブジェクトは、JMAPセッションオブジェクトの一部として返されます。 [RFC8620], Section 2を参照してください。 この文書は、ケイパビリティーURIを1つ追加で定義します。

1.2.1. urn:ietf:params:jmap:sieve

1.2.1. urn:ietf:params:jmap:sieve

The urn:ietf:params:jmap:sieve URI represents support for the SieveScript data type and associated API methods. The value of this property in the JMAP Session "capabilities" property is an object that MUST contain the following information on server capabilities:

urn:ietf:params:jmap:sieve URIは、SieveScriptデータ型と関連するAPIメソッドのサポートを表します。 JMAPセッションの「capabilities」プロパティーにおけるこのプロパティーの値はオブジェクトであり、サーバーのケイパビリティーに関する次の情報を含めなければなりません（MUST）。

implementation:

String

The name and version of the Sieve implementation.

implementation:

String

Sieve実装の名前とバージョンです。

The value of this property in an account's "accountCapabilities" property is an object that MUST contain the following information on per-account server capabilities:

アカウントの「accountCapabilities」プロパティーにおけるこのプロパティーの値はオブジェクトであり、アカウントごとのサーバーのケイパビリティーに関する次の情報を含めなければなりません（MUST）。

maxSizeScriptName:

UnsignedInt

The maximum length, in octets, allowed for the name of a SieveScript. For compatibility with ManageSieve, this MUST be at least 512 (up to 128 Unicode characters).

maxSizeScript:

UnsignedInt|null

The maximum size (in octets) of a Sieve script the server is willing to store for the user, or null for no limit.

maxNumberScripts:

UnsignedInt|null

The maximum number of Sieve scripts the server is willing to store for the user, or null for no limit.

maxNumberRedirects:

UnsignedInt|null

The maximum number of Sieve "redirect" actions a script can perform during a single evaluation, or null for no limit. Note that this is different from the total number of "redirect" actions a script can contain.

sieveExtensions:

String[]

A list of case-sensitive Sieve capability strings (as listed in the Sieve "require" action; see [RFC5228], Section 3.2) indicating the extensions supported by the Sieve engine.

notificationMethods:

String[]|null

A list of [RFC3986] for notification methods supported by the Sieve [RFC5435], or null if the extension is not supported by the Sieve engine.

externalLists:

String[]|null

A list of [RFC3986] for externally stored list types supported by the Sieve [RFC6134], or null if the extension is not supported by the Sieve engine.

maxSizeScriptName:

UnsignedInt

SieveScriptの名前に許される最大長（オクテット単位）です。 ManageSieveとの互換性のため、この値は少なくとも512（最大128 Unicode文字）でなければなりません（MUST）。

maxSizeScript:

UnsignedInt|null

サーバーがそのユーザーのために保存するSieveスクリプトの最大サイズ（オクテット単位）です。 制限がない場合はnullです。

maxNumberScripts:

UnsignedInt|null

サーバーがそのユーザーのために保存するSieveスクリプトの最大数です。 制限がない場合はnullです。

maxNumberRedirects:

UnsignedInt|null

1回の評価の間にスクリプトが実行できるSieveの「redirect」アクションの最大数です。 制限がない場合はnullです。 これは、スクリプトに含めることのできる「redirect」アクションの総数とは異なることに注意してください。

sieveExtensions:

String[]

Sieveエンジンがサポートする拡張を示す、大文字と小文字を区別するSieveケイパビリティー文字列（Sieveの「require」アクションに列挙するもの。[RFC5228], Section 3.2を参照）のリストです。

notificationMethods:

String[]|null

Sieveの[RFC5435]がサポートする通知方式の[RFC3986]のリストです。 Sieveエンジンがこの拡張をサポートしていない場合はnullです。

externalLists:

String[]|null

Sieveの[RFC6134]がサポートする、外部に保存されたリストの種類の[RFC3986]のリストです。 Sieveエンジンがこの拡張をサポートしていない場合はnullです。

2. Sieve Scripts

2. Sieveスクリプト

A "SieveScript" object represents a single [RFC5228] for filtering email messages at the time of final delivery.

「SieveScript」オブジェクトは、最終配送時に電子メールメッセージをフィルタリングするための1つの[RFC5228]を表します。

2.1. Sieve Script Properties

2.1. Sieveスクリプトのプロパティー

A "SieveScript" object has the following properties:

「SieveScript」オブジェクトは、次のプロパティーを持ちます。

id:

Id (immutable; server-set)

The id of the script.

name:

String|null (optional; default is server dependent)

User-visible name for the SieveScript. If non-null, this MUST be a [RFC5198] of at least 1 character in length, subject to the maximum size given in the "capability" object.

For compatibility with ManageSieve, servers MUST reject names that contain any of the following Unicode characters: U+0000-U+001F, U+007F-U+009F, U+2028, or U+2029.

Servers MAY reject names that violate server policy (e.g., names containing a slash (/)).

The name MUST be unique among all SieveScripts within an account.

blobId:

Id

The id of the blob containing the raw octets of the script.

isActive:

Boolean (server-set; default: false)

Indicator that the SieveScript is actively filtering incoming messages.

A user may have at most one active script. The Section 2.4 is used for changing the active script or disabling Sieve processing.

id:

Id （不変、サーバーが設定）

スクリプトのIDです。

name:

String|null （省略可能、デフォルトはサーバー依存）

ユーザーに表示されるSieveScriptの名前です。 nullでない場合、これは「capability」オブジェクトで示される最大サイズに従う、長さが1文字以上の[RFC5198]でなければなりません（MUST）。

ManageSieveとの互換性のため、サーバーは次のUnicode文字のいずれかを含む名前を拒否しなければなりません（MUST）。 U+0000～U+001F、U+007F～U+009F、U+2028、U+2029。

サーバーは、サーバーのポリシーに違反する名前（たとえば、スラッシュ（/）を含む名前）を拒否してもよいです（MAY）。

名前は、アカウント内のすべてのSieveScriptの中で一意でなければなりません（MUST）。

blobId:

Id

スクリプトの生のオクテットを含むBLOBのIDです。

isActive:

Boolean （サーバーが設定、デフォルト：false）

SieveScriptが受信メッセージのフィルタリングを実際に行っているかどうかを示すものです。

ユーザーが持てるアクティブなスクリプトは最大1つです。 アクティブなスクリプトを変更したり、Sieve処理を無効にしたりするには、Section 2.4を使用します。

2.2. Sieve Script Content

2.2. Sieveスクリプトのコンテンツ

A script MUST be [RFC3629] of at least 1 character in length, subject to the syntax of [RFC5228]. A script MUST NOT contain any "require" statement(s) mentioning Sieve capability strings not present in the Section 1.2.1. Note that if the Sieve [RFC5463] is present in the "capability" object, the script MAY mention unrecognized/unsupported extensions in the "ihave" test.

スクリプトは、[RFC5228]の構文に従う、長さが1文字以上の[RFC3629]でなければなりません（MUST）。 スクリプトは、Section 1.2.1に存在しないSieveケイパビリティー文字列に言及する「require」文を含んではなりません（MUST NOT）。 なお、Sieveの[RFC5463]が「capability」オブジェクトに存在する場合、スクリプトは「ihave」テストの中で認識されない拡張やサポートされていない拡張に言及してもよいです（MAY）。

Script content is treated as a binary blob and uploaded/downloaded via the mechanisms provided in Sections 6.1 and 6.2 of [RFC8620], respectively, and/or via the JMAP Blob management methods provided in Sections 4.1 and 4.2 of [RFC9404], respectively.

スクリプトのコンテンツはバイナリーBLOBとして扱われ、[RFC8620]のセクション6.1と6.2でそれぞれ提供されている仕組み、または[RFC9404]のセクション4.1と4.2でそれぞれ提供されているJMAP BLOB管理メソッド（あるいはその両方）を介して、アップロードおよびダウンロードされます。

Downloading script content via the JMAP downloadUrl or the Blob/get method provides functionality equivalent to that of the GETSCRIPT command defined in [RFC5804].

JMAPのdownloadUrlまたはBlob/getメソッドを介したスクリプトのコンテンツのダウンロードは、[RFC5804]で定義されているGETSCRIPTコマンドと同等の機能を提供します。

2.3. SieveScript/get

2.3. SieveScript/get

This is a standard "/get" method as described in [RFC8620], Section 5.1. The "ids" argument may be null to fetch all scripts at once.

これは、[RFC8620], Section 5.1で説明されている標準の「/get」メソッドです。 すべてのスクリプトを一度に取得する場合は、「ids」引数をnullにできます。

This method provides functionality equivalent to that of the LISTSCRIPTS command defined in [RFC5804].

このメソッドは、[RFC5804]で定義されているLISTSCRIPTSコマンドと同等の機能を提供します。

2.4. SieveScript/set

2.4. SieveScript/set

This is a standard "/set" method as described in [RFC8620], Section 5.3, but with the following additional optional request arguments:

これは、[RFC8620], Section 5.3で説明されている標準の「/set」メソッドですが、次の省略可能なリクエスト引数が追加されています。

onSuccessActivateScript:

Id

The id of the SieveScript to activate if and only if all of the creations, modifications, and destructions (if any) succeed. (For references to SieveScript creations, this is equivalent to a creation-reference, so the id will be the creation id prefixed with a "#".) The currently active SieveScript (if any) will be deactivated before activating the specified SieveScript.

If omitted, or if the id is either invalid or nonexistent, it MUST be ignored, and the currently active SieveScript (if any) will remain as such.

The id of any activated SieveScript MUST be reported in either the "created" or "updated" argument in the response as appropriate, including a value of "true" for the "isActive" property. The id of any deactivated SieveScript MUST be reported in the "updated" argument in the response, including a value of "false" for the "isActive" property.

onSuccessDeactivateScript:

Boolean

If "true", the currently active SieveScript (if any) will be deactivated if and only if all of the creations, modifications, and destructions (if any) succeed. If "false" or omitted, the currently active SieveScript (if any) will remain as such.

The id of any deactivated SieveScript MUST be reported in the "updated" argument in the response, including a value of "false" for the "isActive" property.

onSuccessActivateScript:

Id

作成、変更、破棄（もしあれば）がすべて成功した場合に限り、アクティブにするSieveScriptのIDです。 （作成するSieveScriptを参照する場合、これは作成参照（creation-reference）と同等なので、IDは作成IDの前に「#」を付けたものになります。） 現在アクティブなSieveScript（もしあれば）は、指定されたSieveScriptをアクティブにする前に非アクティブにされます。

省略された場合、またはIDが無効か存在しない場合は、この引数を無視しなければなりません（MUST）。現在アクティブなSieveScript（もしあれば）はそのままアクティブな状態に保たれます。

アクティブにされたSieveScriptのIDは、必要に応じてレスポンスの「created」引数または「updated」引数のいずれかで報告しなければなりません（MUST）。その際、「isActive」プロパティーの値として「true」を含めます。 非アクティブにされたSieveScriptのIDは、レスポンスの「updated」引数で報告しなければなりません（MUST）。その際、「isActive」プロパティーの値として「false」を含めます。

onSuccessDeactivateScript:

Boolean

「true」の場合、作成、変更、破棄（もしあれば）がすべて成功した場合に限り、現在アクティブなSieveScript（もしあれば）が非アクティブにされます。 「false」の場合または省略された場合、現在アクティブなSieveScript（もしあれば）はそのままアクティブな状態に保たれます。

非アクティブにされたSieveScriptのIDは、レスポンスの「updated」引数で報告しなければなりません（MUST）。その際、「isActive」プロパティーの値として「false」を含めます。

If both the "onSuccessActivateScript" and "onSuccessDeactivateScript" arguments are present in the request, then "onSuccessDeactivateScript" MUST be processed first. If neither argument is present in the request, the currently active SieveScript (if any) will remain as such.

リクエストに「onSuccessActivateScript」引数と「onSuccessDeactivateScript」引数の両方が存在する場合は、「onSuccessDeactivateScript」を先に処理しなければなりません（MUST）。 どちらの引数もリクエストに存在しない場合、現在アクティブなSieveScript（もしあれば）はそのままアクティブな状態に保たれます。

This method provides functionality equivalent to that of the PUTSCRIPT, DELETESCRIPT, RENAMESCRIPT, and SETACTIVE commands defined in [RFC5804].

このメソッドは、[RFC5804]で定義されているPUTSCRIPT、DELETESCRIPT、RENAMESCRIPT、SETACTIVEの各コマンドと同等の機能を提供します。

Script content must first be uploaded as per Section 2.2 prior to referencing it in a SieveScript/set call.

スクリプトのコンテンツは、SieveScript/set呼び出しで参照する前に、まずSection 2.2に従ってアップロードしておく必要があります。

If the SieveScript cannot be created or updated because it would result in two SieveScripts with the same name, the server MUST reject the request with an "alreadyExists" SetError. An "existingId" property of type "Id" MUST be included on the SetError object with the id of the existing SieveScript.

同じ名前のSieveScriptが2つ存在することになるためにSieveScriptを作成または更新できない場合、サーバーは「alreadyExists」SetErrorでそのリクエストを拒否しなければなりません（MUST）。 SetErrorオブジェクトには、既存のSieveScriptのIDを値とする「Id」型の「existingId」プロパティーを含めなければなりません（MUST）。

If the SieveScript cannot be created or updated because its size exceeds the "maxSizeScript" limit, the server MUST reject the request with a "tooLarge" SetError.

サイズが「maxSizeScript」の制限を超えるためにSieveScriptを作成または更新できない場合、サーバーは「tooLarge」SetErrorでそのリクエストを拒否しなければなりません（MUST）。

If the SieveScript cannot be created because it would exceed the "maxNumberScripts" limit or would exceed a server-imposed storage limit, the server MUST reject the request with an "overQuota" SetError.

「maxNumberScripts」の制限、またはサーバーが課すストレージの制限を超えることになるためにSieveScriptを作成できない場合、サーバーは「overQuota」SetErrorでそのリクエストを拒否しなければなりません（MUST）。

The active SieveScript MUST NOT be destroyed unless it is first deactivated in a separate SieveScript/set method call.

アクティブなSieveScriptは、まず別のSieveScript/setメソッド呼び出しで非アクティブにしない限り、破棄してはなりません（MUST NOT）。

sieveIsActive:

3. Quotas

3. クォータ

Servers SHOULD impose quotas on Sieve scripts to prevent malicious users from exceeding available storage. Administration of such quotas is outside of the scope of this specification; however, [RFC9425] defines a data model for users to obtain quota details over JMAP.

悪意のあるユーザーが利用可能なストレージを超過することを防ぐため、サーバーはSieveスクリプトにクォータを課すべきです（SHOULD）。 このようなクォータの管理はこの仕様の範囲外ですが、[RFC9425]は、ユーザーがJMAPを介してクォータの詳細を取得するためのデータモデルを定義しています。

The mechanism for handling SieveScript requests that would place a user over a quota setting is discussed in Section 2.4.

ユーザーがクォータの設定を超えることになるSieveScriptのリクエストを処理する仕組みについては、Section 2.4で説明しています。

4. Compatibility with JMAP Vacation Response

4. JMAP VacationResponseとの互換性

Section 8 of [RFC8621] defines a "VacationResponse" object to represent an autoresponder to incoming email messages. Servers that implement the VacationResponse as a Sieve script that resides among other user scripts are subject to the following requirements:

[RFC8621]のSection 8は、受信した電子メールメッセージへの自動応答を表す「VacationResponse」オブジェクトを定義しています。 VacationResponseを、ユーザーの他のスクリプトと並んで存在するSieveスクリプトとして実装するサーバーには、次の要件が適用されます。

  • MUST allow the VacationResponse Sieve script to be fetched by the Section 2.3.
  • MUST allow the VacationResponse Sieve script to be activated or deactivated via the "onSuccessActivateScript" argument to the Section 2.4.
  • MUST NOT allow the VacationResponse Sieve script to be destroyed or have its content updated by the Section 2.4. Any such request MUST be rejected with a "forbidden" SetError. A "description" property MAY be present with an explanation that the script can only be modified by a VacationResponse/set method.
  • VacationResponseのSieveスクリプトをSection 2.3で取得できるようにしなければなりません（MUST）。
  • VacationResponseのSieveスクリプトを、Section 2.4の「onSuccessActivateScript」引数によってアクティブまたは非アクティブにできるようにしなければなりません（MUST）。
  • VacationResponseのSieveスクリプトを、Section 2.4によって破棄したり、コンテンツを更新したりできるようにしてはなりません（MUST NOT）。 そのようなリクエストはすべて「forbidden」SetErrorで拒否しなければなりません（MUST）。 このスクリプトはVacationResponse/setメソッドによってのみ変更できるという説明を含む「description」プロパティーが存在してもよいです（MAY）。

5. Security Considerations

5. セキュリティーに関する考慮事項

All security considerations discussed in [RFC8620] and [RFC5228] apply to this specification.

[RFC8620]と[RFC5228]で議論されているすべてのセキュリティーに関する考慮事項が、この仕様にも適用されます。

Additionally, implementations MUST treat Sieve script content as untrusted data. As such, script parsers MUST fail gracefully in the face of syntactically invalid or malicious content and MUST be prepared to deal with resource exhaustion (e.g., allocation of enormous strings, lists, or command blocks).

さらに、実装はSieveスクリプトのコンテンツを信頼できないデータとして扱わなければなりません（MUST）。 したがって、スクリプトのパーサーは、構文的に無効なコンテンツや悪意のあるコンテンツに直面しても、適切に失敗しなければなりません（MUST）。 また、リソースの枯渇（たとえば、巨大な文字列、リスト、コマンドブロックの割り当て）に対処できるように備えている必要があります（MUST）。
