RFC 1517

Applicability Statement for the Implementation of Classless Inter-Domain Routing (CIDR)

RFC 1517

クラスレスドメイン間ルーティング（CIDR）の実装に関する適用性声明

Status of This Memo

このメモのステータス

This RFC specifies an Internet standards track protocol for the Internet community, and requests discussion and suggestions for improvements. Please refer to the current edition of the "Internet Official Protocol Standards" for the standardization state and status of this protocol. Distribution of this memo is unlimited.

このRFCは、インターネットコミュニティーのためのインターネット標準化過程（Internet Standards Track）のプロトコルを規定し、改善のための議論と提案を求めるものです。このプロトコルの標準化の状態とステータスについては、「Internet Official Protocol Standards」の最新版を参照してください。このメモの配布は無制限です。

1. Introduction

1. はじめに

As the Internet has evolved and grown in recent years, it has become clear that it will soon face several serious scaling problems. These include:

ここ数年でインターネットが進化し成長するにつれて、インターネットが近いうちにいくつかの深刻なスケーリングの問題に直面することが明らかになってきました。その問題には次のものがあります。

  • Exhaustion of the class-B network address space. One fundamental cause of this problem is the lack of a network class of a size that is appropriate for a mid-sized organization. Class-C, with a maximum of 254 host addresses, is too small, while class-B, which allows up to 65534 addresses, is too large to be densely populated. The result is inefficient utilization of class-B network numbers.
  • Routing information overload. The size and rate of growth of the routing tables in Internet routers is beyond the ability of current software (and people) to effectively manage.
  • Eventual exhaustion of IP network numbers.
  • クラスBのネットワークアドレス空間の枯渇。この問題の根本的な原因の1つは、中規模の組織に適したサイズのネットワーククラスがないことです。ホストアドレスが最大254個のクラスCは小さすぎ、最大65534個のアドレスを使用できるクラスBは大きすぎて密に埋めることができません。その結果、クラスBのネットワーク番号の利用効率が悪くなっています。
  • ルーティング情報の過負荷。インターネットのルーターにおけるルーティングテーブルのサイズとその増加速度は、現在のソフトウェア（および人間）が効果的に管理できる能力を超えています。
  • 最終的なIPネットワーク番号の枯渇。

It has become clear that the first two of these problems are likely to become critical in the near term. Classless Inter-Domain Routing (CIDR) ttempts to deal with these problems by defining a mechanism to slow the growth of routing tables and reduce the need to allocate new IP network numbers. It does not attempt to solve the third problem, which is of a more long-term nature, but instead endeavors to ease enough of the short to mid-term difficulties to allow the Internet to continue to function efficiently while progress is made on a longer-term solution.

これらの問題のうち最初の2つは、近い将来に深刻になる可能性が高いことが明らかになっています。クラスレスドメイン間ルーティング（CIDR: Classless Inter-Domain Routing）は、ルーティングテーブルの増加を遅らせ、新しいIPネットワーク番号を割り当てる必要性を減らすメカニズムを定義することで、これらの問題に対処しようとするものです。CIDRは、より長期的な性質を持つ3つ目の問題を解決しようとはしません。その代わりに、より長期的な解決策の検討が進む間もインターネットが効率的に機能し続けられるよう、短期から中期の困難を十分に緩和することを目指しています。

The IESG, after a thorough discussion in the IETF, in June 1992 selected CIDR as the solution for the short term routing table explosion problem [1].

IESGは、IETFでの徹底的な議論の後、1992年6月に、短期的なルーティングテーブル爆発問題の解決策としてCIDRを選択しました[1]。

2. Components of the Architecture

2. アーキテクチャーの構成要素

The CIDR architecture is described in the following documents:

CIDRのアーキテクチャーは、次の文書で説明されています。

  • "An Architecture for IP Address Allocation with CIDR" [2]
  • "Classless Inter-Domain Routing (CIDR): An Address Assignment and Aggregation Strategy" [3]
  • 「An Architecture for IP Address Allocation with CIDR」[2]
  • 「Classless Inter-Domain Routing (CIDR): An Address Assignment and Aggregation Strategy」[3]

The first of these documents presents the overall architecture of CIDR; the second describes the specific address allocation scheme to be used.

これらの文書のうち、1つ目はCIDRの全体的なアーキテクチャーを示し、2つ目は使用する具体的なアドレス割り当て方式を説明しています。

In addition to these two documents, "Guidelines for Management of IP Address Space" [4] provides specific recommendations for assigning IP addresses that are consistent with [2] and [3], and "Status of CIDR Deployment in the Internet" [5] describes the timetable for deploying [4] in the Internet. Both [4] and [5] should be viewed as supporting, rather than defining, documents.

これら2つの文書に加えて、「Guidelines for Management of IP Address Space」[4]は[2]および[3]と整合するIPアドレスの割り当てについて具体的な推奨事項を示しており、「Status of CIDR Deployment in the Internet」[5]はインターネットに[4]を展開するスケジュールを説明しています。[4]と[5]はどちらも、定義する文書ではなく、補助的な文書とみなすべきです。

In addition to the documents mentioned above, CIDR requires that inter-domain routing protocols be capable of handling reachability information that is expressed solely in terms of IP address prefixes. While several inter-domain routing protocols are capable of supporting such functionality, this Applicability Statement does not mandate the use of a particular one.

上記の文書に加えて、CIDRは、ドメイン間ルーティングプロトコルが、IPアドレスプレフィックスだけで表現された到達可能性情報を扱えることを要求します。そのような機能をサポートできるドメイン間ルーティングプロトコルはいくつかありますが、この適用性声明は特定のプロトコルの使用を義務付けるものではありません。

Although Internet routing domains are not required to use routing protocols capable of propagating CIDR routes, the topology such routing domains can support will be somewhat limited. In particular, the non-CIDR-capable parts of the Internet will need to default towards the CIDR-capable parts of the Internet for routes which have been aggregated to non-network boundaries.

インターネットのルーティングドメインは、CIDRの経路を伝播できるルーティングプロトコルを使用することを要求されていませんが、そのようなルーティングドメインがサポートできるトポロジーはいくらか制限されます。特に、インターネットのうちCIDRに対応していない部分は、ネットワーク境界ではない単位に集約された経路について、インターネットのうちCIDRに対応している部分に向けたデフォルト経路を使う必要があります。

3. Applicability of CIDR

3. CIDRの適用性

The CIDR architecture is applicable to any group of connected domains that supports IP version 4 [6] [7]. CIDR does not require all of the domains in the Internet to be converted to use CIDR. It assumes that some of the existing domains in the Internet will never be able to convert. Despite this, CIDR will still provide connectivity to such places, although the optimality of routes to these places may be impacted.

CIDRのアーキテクチャーは、IPバージョン4 [6] [7]をサポートする、相互に接続されたドメインのあらゆるグループに適用できます。CIDRは、インターネットのすべてのドメインがCIDRを使用するように移行することを要求しません。CIDRは、インターネットの既存のドメインの中には決して移行できないものがあることを想定しています。それでも、CIDRはそのような場所への接続性を提供します。ただし、そのような場所への経路の最適性には影響が出る可能性があります。

This Applicability Statement requires Internet domains providing backbone and/or transit service to fully implement CIDR in order to ensure that the growth of the resources required by routers to provide Internet-wide connectivity will be significantly slower than the growth of the number of assigned networks.

この適用性声明は、インターネット全体の接続性を提供するためにルーターが必要とするリソースの増加が、割り当てられたネットワークの数の増加よりも大幅に遅くなることを保証するために、バックボーンサービスやトランジットサービスを提供するインターネットのドメインに対して、CIDRを完全に実装することを要求します。

This Applicability Statement strongly recommends that all non-backbone/transit Internet domains also implement CIDR because it will reduce the amount of routing information inside of these domains.

この適用性声明は、バックボーンでもトランジットでもないすべてのインターネットのドメインにも、CIDRを実装することを強く推奨します。CIDRによって、これらのドメイン内部のルーティング情報の量が減るからです。

Individual domains are free to choose whatever inter-domain and intra-domain routing architectures best meet their requirements. Specifically, this Applicability Statement does not prevent a domain or a group of domains from using addressing schemes which do not conform to CIDR. Subject to the available resources in routers, CIDR should be able to co-exist with other addressing schemes without adversely impacting overall connectivity.

個々のドメインは、自身の要件に最もよく合うドメイン間ルーティングとドメイン内ルーティングのアーキテクチャーを自由に選択できます。具体的には、この適用性声明は、ドメインやドメインのグループがCIDRに準拠しないアドレッシング方式を使用することを妨げるものではありません。ルーターで利用可能なリソースの範囲内で、CIDRは、全体的な接続性に悪影響を与えることなく、他のアドレッシング方式と共存できるはずです。
