RFC 1367

Schedule for IP Address Space Management Guidelines

RFC 1367

IPアドレス空間管理ガイドラインのスケジュール

Status of This Memo

このメモのステータス

This memo provides information for the Internet community. It does not specify an Internet standard. Distribution of this memo is unlimited.

このメモは、インターネットコミュニティーに情報を提供するものです。このメモはインターネット標準を規定するものではありません。このメモの配布は無制限です。

Introduction

はじめに

This memo suggests a schedule for the implementation of the IP network number allocation plan described in RFC 1366. This schedule is meant to support the implementation and deployment of an address aggregation mechanism for the Internet by proposing an achievable target for which we can all aim. The timely deployment of that aggregation mechanism and the IP addressing plan will help the the size of the Internet router forwarding tables and management of the IP address space. By doing so, it will help the current Internet addressing and routing technology operate during the interim period until the next generation technology is deployed. This interim solution in no way constrains the selection of the next generation addressing and routing technology.

このメモは、RFC 1366で説明されているIPネットワーク番号の割り当て計画を実施するためのスケジュールを提案します。このスケジュールは、私たち全員が目指せる達成可能な目標を提案することで、インターネットのためのアドレス集約（address aggregation）の仕組みの実装と展開を支援することを目的としています。その集約の仕組みとIPアドレッシング計画を適時に展開することは、インターネットのルーターの転送テーブルの大きさと、IPアドレス空間の管理に役立ちます。そうすることで、次世代の技術が展開されるまでの暫定期間中、現在のインターネットのアドレッシングとルーティングの技術が機能するのを助けます。この暫定的な解決策は、次世代のアドレッシングとルーティングの技術の選択を何ら制約するものではありません。

This draft schedule was put together by the FNC Engineering and Planning Group (FEPG) based on the IP addressing plan BOF of the July 1992 IETF meeting, as well as discussions with a number (though, of course, not all) of knowledgeable and interested parties, including the IANA and IR. This draft schedule assumes that the address aggregation mechanism will be available in the Internet by mid-1993. The activities described in this schedule are the precursors to that deployment, and will promote the efficient operation of that mechanism. We feel that our assumptions are realistic and that this schedule can be met. We encourage its open discussion as we move toward community consensus.

このスケジュール案は、FNC Engineering and Planning Group（FEPG）が、1992年7月のIETF会合でのIPアドレッシング計画のBOFと、IANAやIRを含む、知識と関心を持つ多くの（もちろん全員ではありませんが）関係者との議論に基づいてまとめたものです。このスケジュール案は、アドレス集約の仕組みが1993年半ばまでにインターネットで利用できるようになることを前提としています。このスケジュールで説明する活動は、その展開に先立つものであり、その仕組みの効率的な運用を促進します。私たちは、この前提は現実的であり、このスケジュールは達成可能であると考えています。コミュニティーのコンセンサスに向けて進むにあたり、このスケジュールについてオープンに議論することを推奨します。

Please send comments to topolcic@nri.reston.va.us, or to the mailing list ipalloc@nri.reston.va.us. To be added to this mailing list, send a request to ipalloc-request@nri.reston.va.us.

コメントは、topolcic@nri.reston.va.us、またはメーリングリストipalloc@nri.reston.va.usに送ってください。このメーリングリストに追加してもらうには、ipalloc-request@nri.reston.va.usに依頼を送ってください。

以下でアドレッシング計画や地域アドレスレジストリーの基準に言及しているのは、RFC 1366を指していることに注意してください。

Draft Implementation Schedule for IP Network Number Allocation Plan:

IPネットワーク番号割り当て計画の実施スケジュール案：

1) 31 October 92:

The following address allocation procedures are continued:

  1. Initial set of criteria for selecting regional address registries will be put into place, and requests from prospective regional registries will be accepted by the IANA.
  2. Class A network numbers are practically impossible to obtain.
  3. Class B network numbers will continue to be issued only when reasonably justified. If possible, a block of C's will be issued rather than a B. The requirements for allocating a Class B will become progressively more constrained until the date in step (3).
  4. Class C network numbers will be allocated according to the addressing plan. Allocation will be performed by the Internet Registry (IR) if an appropriate regional registry has not yet been designated by the IANA.
2) 14 February 93:
Re-evaluate and readjust the schedule if necessary.
3) 15 April 93:
  1. The IR begins to allocate all networks according to the addressing plan in appropriately sized blocks of Class C numbers.
  2. Class B network numbers will be difficult to obtain, following the recommendation of the addressing plan and only issued when justified.
4) 6 June 93:
Expected date that an address aggregation mechanism is available in the Internet.
1) 1992年10月31日：

次のアドレス割り当ての手続きを継続します。

  1. 地域アドレスレジストリーを選定するための最初の基準一式を導入し、IANAは地域レジストリーの候補からの申請を受け付けます。
  2. クラスAのネットワーク番号は、事実上取得できません。
  3. クラスBのネットワーク番号は、引き続き、十分な正当性がある場合にのみ発行します。可能であれば、Bの代わりにCのブロックを発行します。クラスBを割り当てるための要件は、ステップ(3)の日付まで段階的に厳しくなります。
  4. クラスCのネットワーク番号は、アドレッシング計画に従って割り当てます。IANAが適切な地域レジストリーをまだ指定していない場合は、Internet Registry（IR）が割り当てを行います。
2) 1993年2月14日：
必要に応じて、スケジュールを再評価し、再調整します。
3) 1993年4月15日：
  1. IRは、すべてのネットワークの割り当てを、アドレッシング計画に従って、適切な大きさのクラスC番号のブロックで行い始めます。
  2. クラスBのネットワーク番号は、アドレッシング計画の推奨に従って取得が難しくなり、正当性がある場合にのみ発行されます。
4) 1993年6月6日：
アドレス集約の仕組みがインターネットで利用可能になると見込まれる日付です。
