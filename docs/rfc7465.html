RFC 7465

Prohibiting RC4 Cipher Suites

RFC 7465

RC4暗号スイートの禁止

Abstract

概要

This document requires that Transport Layer Security (TLS) clients and servers never negotiate the use of RC4 cipher suites when they establish connections. This applies to all TLS versions. This document updates RFCs 5246, 4346, and 2246.

この文書は、トランスポート層セキュリティー（TLS）のクライアントとサーバーが、接続を確立する際にRC4暗号スイートの使用を決してネゴシエートしないことを要求します。これはすべてのTLSバージョンに適用されます。この文書は、RFC 5246、4346、2246を更新します。

1. Introduction

1. はじめに

RC4 is a stream cipher that is described in [SCH]; it is widely supported, and often preferred by TLS servers. However, RC4 has long been known to have a variety of cryptographic weaknesses, e.g., see [PAU], [MAN], and [FLU]. Recent cryptanalysis results [ALF] exploit biases in the RC4 keystream to recover repeatedly encrypted plaintexts.

RC4は[SCH]で説明されているストリーム暗号です。RC4は広くサポートされており、TLSサーバーに好まれることも多くあります。しかし、RC4にはさまざまな暗号上の弱点があることが以前から知られています（たとえば、[PAU]、[MAN]、[FLU]を参照してください）。最近の暗号解析の成果[ALF]は、RC4のキーストリームの偏りを悪用して、繰り返し暗号化された平文を復元します。

These recent results are on the verge of becoming practically exploitable; currently, they require 2^26 sessions or 13x2^30 encryptions. As a result, RC4 can no longer be seen as providing a sufficient level of security for TLS sessions.

これらの最近の成果は、現実的に悪用可能になる寸前にあります。現時点では、2^26個のセッション、または13x2^30回の暗号化を必要とします。その結果、RC4はもはやTLSセッションに十分なレベルのセキュリティーを提供するとはみなせません。

This document requires that TLS ([RFC5246] [RFC4346] [RFC2246]) clients and servers never negotiate the use of RC4 cipher suites.

この文書は、TLS（[RFC5246] [RFC4346] [RFC2246]）のクライアントとサーバーが、RC4暗号スイートの使用を決してネゴシエートしないことを要求します。

2. Changes to TLS

2. TLSに対する変更

Because of the RC4 deficiencies noted in Section 1, the following apply:

セクション1で述べたRC4の欠陥のため、以下が適用されます。

  • TLS clients MUST NOT include RC4 cipher suites in the ClientHello message.
  • TLS servers MUST NOT select an RC4 cipher suite when a TLS client sends such a cipher suite in the ClientHello message.
  • If the TLS client only offers RC4 cipher suites, the TLS server MUST terminate the handshake. The TLS server MAY send the insufficient_security fatal alert in this case.
  • TLSクライアントは、ClientHelloメッセージにRC4暗号スイートを含めてはなりません（MUST NOT）。
  • TLSクライアントがClientHelloメッセージでRC4暗号スイートを送信した場合、TLSサーバーはRC4暗号スイートを選択してはなりません（MUST NOT）。
  • TLSクライアントがRC4暗号スイートだけを提示した場合、TLSサーバーはハンドシェイクを終了しなければなりません（MUST）。この場合、TLSサーバーはinsufficient_securityの致命的アラートを送信してもよいです（MAY）。

Appendix A lists the RC4 cipher suites defined for TLS.

付録Aに、TLS用に定義されたRC4暗号スイートを列挙します。

3. Security Considerations

3. セキュリティーに関する考慮事項

This document helps maintain the security guarantees of the TLS protocol by prohibiting the use of the RC4-based cipher suites (listed in Appendix A), which do not provide a sufficiently high level of security.

この文書は、十分に高いレベルのセキュリティーを提供しない、RC4ベースの暗号スイート（付録Aに列挙）の使用を禁止することにより、TLSプロトコルのセキュリティー保証の維持に役立ちます。
