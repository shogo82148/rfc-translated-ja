RFC 162

NETBUGGER3

RFC 162

NETBUGGER3

Abstract

概要

NETBUGGER3 is a third level program for the debugging of second and third level programs, experimentation with and simulation of third level protocols.

NETBUGGER3は、第2レベルと第3レベルのプログラムのデバッグや、第3レベルのプロトコルの実験やシミュレーションを行うための、第3レベルのプログラムです。

We were writing an RJE FILENET to interact with UCLA-CCN, and discovered that they (UCLA-CCN) wouldn't be up for a few months. We needed a program that would simulate CCN, so that we could interact with it and debug our FILENET. It occurred to me that all over the network, people had similar problems, i.e., they couldn't debug programs because the intended server wasn't up. And so I started to write a third level debugger-simulater.

当方では、UCLA-CCNとやり取りするためのRJE FILENETを書いていたところ、UCLA-CCNが数か月は稼働しないことがわかりました。CCNをシミュレートするプログラムがあれば、それとやり取りしてFILENETをデバッグできます。そこで気づいたのですが、ネットワークのあちこちで、同じような問題、つまり、相手となるはずのサーバーが稼働していないためにプログラムをデバッグできないという問題を抱えている人たちがいました。そこで、私は第3レベルのデバッガー兼シミュレーターを書き始めました。

With NETBUGGER3 the user can easily issue RTSs, STRs, and LISTENs, interrogate the status of connections, receive and display NCP-USER events and transmit and receive data over as many as twelve connections (per copy of program running). Received data can be displayed in ASCII, EBCDIC on HEX. The user can, of course, originate data for transmission in the same forms. NETBUGGER3 can be initiator, receiver and/or intermediate in connections.

NETBUGGER3を使うと、ユーザーは、RTS、STR、LISTENを簡単に発行し、コネクションの状態を問い合わせ、NCP-USERイベントを受信して表示し、最大12個のコネクション（実行中のプログラムのコピーごと）でデータを送受信できます。受信したデータは、ASCII、EBCDIC、16進数で表示できます。もちろん、ユーザーは同じ形式で送信用のデータを作成することもできます。NETBUGGER3は、コネクションの開始側、受信側、中継役のいずれにも（または複数を兼ねて）なれます。

An example of how NETBUGGER3 could be of use to other hosts on the Net follows.

NETBUGGER3がネット上の他のホストにどのように役立つかの例を次に示します。

Host X has a special third level Filenet to debug. The host they plan to interact with won't be up for several months. Host X can arrange with us to interact with NETBUGGER3, which will simulate the proposed third level protocol and transactions.

ホストXには、デバッグしなければならない特別な第3レベルのFilenetがあります。やり取りする予定の相手のホストは、数か月は稼働しません。ホストXは、当方と調整してNETBUGGER3とやり取りできます。NETBUGGER3は、提案されている第3レベルのプロトコルとトランザクションをシミュレートします。

An alternate possibility is for Host X to use his Telnet to enter our system and start NETBUGGER3 himself. He can then be running NETBUGGER3 on one console and his filenet on another.

別の方法として、ホストXが自分のTelnetを使って当方のシステムに入り、自分でNETBUGGER3を起動することもできます。そうすれば、一方のコンソールでNETBUGGER3を、もう一方のコンソールで自分のFilenetを実行できます。

An alternate possibility is for Host X to use his Telnet to enter our system and start NETBUGGER3 himself. He can then be running NETBUGGER3 on one console and his filenet on another.

別の方法として、ホストXが自分のTelnetを使って当方のシステムに入り、自分でNETBUGGER3を起動することもできます。そうすれば、一方のコンソールでNETBUGGER3を、もう一方のコンソールで自分のFilenetを実行できます。

Then, later on when the other server Host is up, NETBUGGER3 can be used an intermediate between Host X and his serving host. Every message from Host X to server and vice versa can be displayed, examined and, if necessary, edited as it passes through the NETBUGGER3 console, thus making possible the debugging and measurements.

その後、相手のサーバーホストが稼働したら、NETBUGGER3をホストXとそのサーバーホストとの間の中継役として使えます。ホストXからサーバーへのメッセージも、その逆方向のメッセージも、NETBUGGER3のコンソールを通過する際にすべて表示し、調べ、必要なら編集できるので、デバッグや計測が可能になります。

This is only one example. If you are interested in using, receiving, documentation, making suggestions or anything else regarding NETBUGGER3, please contact the Network liaison at UCLA - NMC.

これは一例にすぎません。NETBUGGER3の利用、ドキュメントの入手、提案など、NETBUGGER3に関することに興味がある場合は、UCLA-NMCのネットワーク連絡担当者に連絡してください。
