RFC 307

Using network Remote Job Entry

RFC 307

ネットワークリモートジョブエントリーの使用

OVERVIEW

概要

As has been mentioned in previous RFCs and at previous Network meetings various groups at Rand have been doing RJE to remote Network sites (UCBS and UCLA) for over a year. Until recently all this work has been done from our IBM 360/65 which is only a Network using host (not a server). Recently our PDP-10 has come onto the Network as both a user and server host. We now have, as well, a program on the PDP-10 allowing access to the Remote Job Service (RJS) at UCLA. Our normal mode of operation is diagramed below.

以前のRFCや以前のネットワーク会合で述べられてきたように、Randのさまざまなグループが、1年以上にわたって遠隔のネットワークサイト（UCBSとUCLA）に対してRJE（リモートジョブエントリー）を行ってきました。最近まで、この作業はすべて、ネットワークを利用するだけのホスト（サーバーではない）であるIBM 360/65から行われていました。最近、PDP-10が利用者ホストとしてもサーバーホストとしてもネットワークに加わりました。さらに現在では、UCLAのリモートジョブサービス（Remote Job Service、RJS）にアクセスできるプログラムがPDP-10上にあります。通常の運用形態を以下に図示します。

To use RJS the user creates a job source "deck" in the Rand File system. He then instructs the RJS Access Program (RJSAP) to send that file (job) to RJS. (Sample session below.) He can then monitor the status of his job via RJSAP (and hence RJS) and ask that RJSAP retrieve his print output to a local file, (or directly to his console, the line printer or whatever).

RJSを使うには、ユーザーはまずRandのファイルシステムにジョブのソース「デッキ」を作成します。次に、RJSアクセスプログラム（RJS Access Program、RJSAP）に、そのファイル（ジョブ）をRJSへ送るよう指示します（後述のセッション例を参照）。その後、ユーザーはRJSAPを介して（したがってRJSを介して）ジョブの状況を監視でき、RJSAPに印刷出力をローカルファイルに（あるいはコンソールやラインプリンターなどに直接）取り出すよう依頼できます。

Recently, several people at other Network sites have expressed an interest in using RJS. However, they are located at a minimal Host or at a host not providing RJS access. Since the Rand PDP-10 is a Network server, these people can solve their access problem by logging onto the Rand PDP-10, using Telnet, and running the RJSAP themselves. The remainder of this RFC describe the steps necessary to run that program.

最近、ほかのネットワークサイトの何人かが、RJSを使うことに関心を示しています。しかし、彼らは最小限のホスト、またはRJSへのアクセスを提供していないホストのところにいます。RandのPDP-10はネットワークサーバーなので、これらの人々は、Telnetを使ってRandのPDP-10にログインし、自分でRJSAPを実行することで、アクセスの問題を解決できます。このRFCの残りの部分では、そのプログラムを実行するために必要な手順を説明します。

The RJS Access Program (RJSAP)

RJSアクセスプログラム（RJSAP）

A sample session using RJSAP is attached below. The RJSAP is started by typing "RJS<return>" to the Tenex executive. The program will then initialize and check (via your login information) to see if you are a user recorded in its tables. This is done to assure you have a valid RJS terminal ID. If your ID is not found, the program will terminate with appropriate message.

RJSAPを使ったセッションの例を以下に添付します。RJSAPは、Tenex executiveに対して「RJS<return>」と入力することで起動します。するとプログラムは初期化を行い、（ログイン情報を使って）あなたがそのテーブルに記録されているユーザーかどうかを確認します。これは、あなたが有効なRJS端末IDを持っていることを確かめるために行われます。IDが見つからない場合、プログラムは適切なメッセージを出して終了します。

If your ID is found, RJSAP will attempt to connect to RJS. If UCLA is down, a message to that effect will appear and the program will terminate. If UCLA is up, RJSAP will connect you to RJS and sign-on your terminal ID (see RFC 189). RJSAP will respond "YOU ARE CONNECTED TO RJS."

IDが見つかった場合、RJSAPはRJSへの接続を試みます。UCLAが停止している場合は、その旨のメッセージが表示され、プログラムは終了します。UCLAが稼働している場合、RJSAPはあなたをRJSに接続し、あなたの端末IDでサインオンします（RFC 189を参照）。RJSAPは「YOU ARE CONNECTED TO RJS.」と応答します。

At this point RJS will acknowledge your signon and print out messages regarding system status.

この時点で、RJSはあなたのサインオンに確認応答し、システムの状況に関するメッセージを出力します。

The programs (RJSAP and RJS) are now ready to perform RJE functions. All commands are initially interpreted by RJSAP. They are listed and explained below.

これで、プログラム（RJSAPとRJS）がRJEの機能を実行する準備が整いました。すべてのコマンドは、まずRJSAPによって解釈されます。コマンドの一覧と説明を以下に示します。

1. Help
If the user types "?" RJSAP will echo the "?" and list the valid set of commands (see below).
2. Message to RJS

If the first character of a command is a "/" all subsequent characters up to a "return" are transmitted to RJS on the operator input connection. See RFC 189 for the syntax and semantics of these commands.

An operator input message can be cancelled with the RUB OUT key or backspaced using BACKSPACE.

3. Send a Job
When the user types "S" RJSAP echoes "SEND SOURCE DECK FROM FILE". The user then enters the file name containing his job followed by a "return." Obviously the file must already exist. If the file is ok and is transmitted successfully, both RJSAP and RJS will print an acknowledgement on the user's terminal (see example below).
4. Retrieve Job Output-Printer
The user can retrieve printed output by entering "PR". RJSAP will echo "PRINT OUTPUT TO FILE". The user then enters the files name where he wants the output. This can be a new file or even a device such as the printer or teletype. When the print output is completely received, the RJSAP will print an acknowledgment (see example).
5. Retrieve Job Output-Punch
This function is currently not implemented, pending a decision on the use of this channel between a PDP-10 and a 360.
6. Transmission Status
For long transmissions of job input or output it may be desirable to check on the progress of the transmission. Typing "R" will cause RJSAP to echo "REPORT ON TRANSMISSIONS--", followed by a record count for the job input and printer output channels.
7. Termination
If the user types a "Q" at the start of a command, RJSAP will echo "QUIT IN PROGRESS" and terminate. This is the preferred way of terminating the program. (Rather than just ^C).
1. ヘルプ
ユーザーが「?」と入力すると、RJSAPは「?」をエコーし、有効なコマンドの一覧を表示します（後述）。
2. RJSへのメッセージ

コマンドの最初の文字が「/」の場合、それに続く「return」までのすべての文字が、オペレーター入力コネクション上でRJSに送信されます。これらのコマンドの構文と意味については、RFC 189を参照してください。

オペレーター入力メッセージは、RUB OUTキーで取り消すことも、BACKSPACEで後退することもできます。

3. ジョブの送信
ユーザーが「S」と入力すると、RJSAPは「SEND SOURCE DECK FROM FILE」とエコーします。次に、ユーザーはジョブを含むファイル名を入力し、続けて「return」を入力します。当然ながら、そのファイルはすでに存在していなければなりません。ファイルに問題がなく、正常に送信されると、RJSAPとRJSの両方がユーザーの端末に確認応答を表示します（後述の例を参照）。
4. ジョブ出力の取り出し（プリンター）
ユーザーは「PR」と入力することで、印刷出力を取り出せます。RJSAPは「PRINT OUTPUT TO FILE」とエコーします。次に、ユーザーは出力先とするファイル名を入力します。これは新しいファイルでも、プリンターやテレタイプなどのデバイスでもかまいません。印刷出力をすべて受信すると、RJSAPは確認応答を表示します（例を参照）。
5. ジョブ出力の取り出し（パンチ）
この機能は、PDP-10と360の間でのこのチャネルの使用に関する決定が出るまで、現在は実装されていません。
6. 送信状況
ジョブの入力または出力の送信が長くかかる場合は、送信の進行状況を確認したいことがあります。「R」と入力すると、RJSAPは「REPORT ON TRANSMISSIONS--」とエコーし、続けてジョブ入力チャネルとプリンター出力チャネルのレコード数を表示します。
7. 終了
ユーザーがコマンドの先頭で「Q」を入力すると、RJSAPは「QUIT IN PROGRESS」とエコーして終了します。これがプログラムを終了する望ましい方法です（単に^Cを使うよりも望ましいです）。

NOTE: Since RJSAP has not been extensively used, we expect it to be improved and modified in the future. Thus, the last section of this RFC -- the explanation of the use of RJSAP -- will be kept in file <HARSLEM>RJSACCESSPROGRAM.EXPLANATION on the Rand PDP-10 and be updated appropriately.

注記：RJSAPはまだあまり使われていないので、今後改良や変更が加えられると考えています。そのため、このRFCの最後の部分、つまりRJSAPの使い方の説明は、RandのPDP-10上のファイル<HARSLEM>RJSACCESSPROGRAM.EXPLANATIONに保管し、適宜更新します。
