RFC 695

Official Change in Host-Host Protocol

RFC 695

ホスト間プロトコルの公式な変更

Abstract

概要

This is an official change to the Host to Host protocol, this document should be filed with the protocol specification (nic -- 8246,) in the Current Network Protocols Notebook (nic -- 7104,).

これはホスト間（Host to Host）プロトコルに対する公式な変更です。この文書は、Current Network Protocols Notebook（nic -- 7104）にあるプロトコル仕様（nic -- 8246）と一緒に綴じておいてください。

-- Jon Postel

-- Jon Postel

This document corrects an ambiguity in the current host-host protocol, concerning the ERR command. Paragraph "f", page 35, of NIC 8246 defines the meaning of an ERR command with error code of 5 to be "socket (link) not connected". The error code is stated to apply to two cases, one in which a control command other than STR or RTS refers to a socket that is neither fully open nor fully closed, and the other in which a (non-control) message arrives over a link not being used for a connection.

この文書は、現在のホスト間プロトコルのERRコマンドに関する曖昧さを修正します。NIC 8246の35ページの段落「f」では、エラーコード5のERRコマンドの意味を「ソケット（リンク）が接続されていない」と定義しています。このエラーコードは2つの場合に適用されると記述されています。1つは、STRまたはRTS以外の制御コマンドが、完全に開いても完全に閉じてもいないソケットを参照した場合で、もう1つは、コネクションに使われていないリンク上に（制御用ではない）メッセージが到着した場合です。

The difficulty arises from the fact that the contents of the "data" field of the ERR command has distinctly different formats in the two cases. In the first, it is a host-host command, and in the second it is a message header. There is no reliable way for the code in the NCP receiving the ERR command (or a human reviewing an error log) to distinguish between the two cases, and therefore fullest use cannot be made of the ERR command.

問題は、ERRコマンドの「data」フィールドの内容が、2つの場合でまったく異なる形式になることから生じます。1つ目の場合はホスト間コマンドで、2つ目の場合はメッセージヘッダーです。ERRコマンドを受信したNCPのコード（あるいはエラーログを確認する人間）が、2つの場合を区別する確実な方法はないため、ERRコマンドを最大限に活用できません。

The two cases are now defined to have different error codes. In addition, a new error code is defined, meaning "invalid host leader received". Therefore, paragraph "f" under "ERR - Error detected" is now replaced by the following:

今後、2つの場合には異なるエラーコードを定義します。さらに、「無効なホストリーダーを受信した」という意味の新しいエラーコードを定義します。したがって、「ERR - Error detected」の下の段落「f」を次のものに置き換えます。

  1. Request on a non-open socket (Error code = 5)

    A request other than an STR or RTS was made for a socket (perhaps referenced by link number) that is not party to an fully established connection. The socket's inappropriate state could either be that only one RFC has been sent (not yet open) or that only one CLS has been sent (not yet closed). The "data" field contains the command in error; the value of any fill necessary is zeros.

  2. Message on an unknown link (Error code = 6)

    A message was received over a user link which is not currently being used for any connection. The contents of the "data" field are the message header followed by the first eight bits of text, if any, or zeros.

  3. Invalid host header (Error code = 7)

    A message was received either over the control link or a valid user link that had a host header with invalid format. Examples of when this subtype would be appropriate are the following: the M1 or M2 fields were non-zero, the byte size was invalid (not 8 for a control link, zero for any link), or the declared length (byte size times byte count) exceeded the actual length. The contents of the "data" field is the message header padded with eight bits of zeros.

  1. 開いていないソケットに対するリクエスト（エラーコード = 5）

    完全に確立されたコネクションに属していないソケット（リンク番号によって参照されることもあります）に対して、STRまたはRTS以外のリクエストが行われました。ソケットの不適切な状態は、RFCが1つだけ送信された（まだ開いていない）か、CLSが1つだけ送信された（まだ閉じていない）かのどちらかです。「data」フィールドには誤りのあるコマンドが入ります。必要な埋め草の値はゼロです。

  2. 未知のリンク上のメッセージ（エラーコード = 6）

    現在どのコネクションにも使われていないユーザーリンク上で、メッセージを受信しました。「data」フィールドの内容は、メッセージヘッダーと、それに続くテキストの最初の8ビット（テキストがなければゼロ）です。

  3. 無効なホストヘッダー（エラーコード = 7）

    制御リンクまたは有効なユーザーリンクのどちらかで、無効な形式のホストヘッダーを持つメッセージを受信しました。このサブタイプが適切となる例は次のとおりです。M1またはM2フィールドがゼロ以外だった場合、バイトサイズが無効だった場合（制御リンクで8以外、または任意のリンクでゼロ）、宣言された長さ（バイトサイズ×バイト数）が実際の長さを超えていた場合。「data」フィールドの内容は、8ビットのゼロで埋めたメッセージヘッダーです。
