A YANG Module for Network Address Translation (NAT) and Network Prefix Translation (NPT)

RFC 8512

ネットワークアドレス変換（NAT）とネットワークプレフィックス変換（NPT）のためのYANGモジュール

Abstract

概要

This document defines a YANG module for the Network Address Translation (NAT) function.

この文書は、ネットワークアドレス変換（Network Address Translation、NAT）機能のためのYANGモジュールを定義します。

Network Address Translation from IPv4 to IPv4 (NAT44), Network Address and Protocol Translation from IPv6 Clients to IPv4 Servers (NAT64), customer-side translator (CLAT), Stateless IP/ICMP Translation (SIIT), Explicit Address Mappings (EAM) for SIIT, IPv6-to-IPv6 Network Prefix Translation (NPTv6), and Destination NAT are covered in this document.

この文書では、IPv4からIPv4へのネットワークアドレス変換（NAT44）、IPv6クライアントからIPv4サーバーへのネットワークアドレスおよびプロトコル変換（NAT64）、カスタマー側トランスレーター（CLAT）、ステートレスIP/ICMP変換（SIIT）、SIITのための明示的アドレスマッピング（EAM）、IPv6からIPv6へのネットワークプレフィックス変換（NPTv6）、および宛先NATを扱います。

1. Introduction

1. はじめに

This document defines a data model for Network Address Translation (NAT) and Network Prefix Translation (NPT) capabilities using the YANG data modeling language [RFC7950].

この文書は、YANGデータモデリング言語[RFC7950]を使用して、ネットワークアドレス変換（NAT）機能とネットワークプレフィックス変換（Network Prefix Translation、NPT）機能のためのデータモデルを定義します。

Traditional NAT is defined in [RFC2663], while Carrier Grade NAT (CGN) is defined in [RFC6888]. Unlike traditional NAT, the CGN is used to optimize the usage of global IP address space at the scale of a domain: a CGN is not managed by end users but by service providers instead. This document covers both traditional NATs and CGNs.

従来型NATは[RFC2663]で定義されており、キャリアグレードNAT（Carrier Grade NAT、CGN）は[RFC6888]で定義されています。 従来型NATとは異なり、CGNはドメインの規模でグローバルIPアドレス空間の使用を最適化するために使用されます。つまり、CGNはエンドユーザーではなくサービスプロバイダーによって管理されます。 この文書は、従来型NATとCGNの両方を扱います。

This document also covers NAT64 [RFC6146], customer-side translator (CLAT) [RFC6877], Stateless IP/ICMP Translation (SIIT) [RFC7915], Explicit Address Mappings (EAM) for SIIT [RFC7757], IPv6 Network Prefix Translation (NPTv6) [RFC6296], and Destination NAT. The full set of translation schemes that are in scope is included in Section 2.2.

この文書は、NAT64[RFC6146]、カスタマー側トランスレーター（CLAT）[RFC6877]、ステートレスIP/ICMP変換（SIIT）[RFC7915]、SIITのための明示的アドレスマッピング（EAM）[RFC7757]、IPv6ネットワークプレフィックス変換（NPTv6）[RFC6296]、および宛先NATも扱います。 範囲内の変換方式の全体は、Section 2.2に示します。

Some examples are provided in Appendix A. These examples are not intended to be exhaustive.

いくつかの例をAppendix Aに示します。 これらの例は網羅的なものではありません。

1.1. Terminology

1.1. 用語

This document makes use of the following terms:

この文書では、次の用語を使用します。

  • Basic Network Address Translation from IPv4 to IPv4 (NAT44): translation is limited to IP addresses alone (Section 2.1 of [RFC3022]).
  • Network Address Port Translator (NAPT): translation in NAPT is extended to include IP addresses and transport identifiers (such as a TCP/UDP port or ICMP query ID); refer to Section 2.2 of [RFC3022]. A NAPT may use an extra identifier, in addition to the five transport tuples, to disambiguate bindings [RFC6619].
  • Destination NAT: is a translation that acts on the destination IP address and/or destination port number. This flavor is usually deployed in load balancers or at devices in front of public servers.
  • Port-restricted IPv4 address: an IPv4 address with a restricted port set. Multiple hosts may share the same IPv4 address; however, their port sets must not overlap [RFC7596].
  • Restricted port set: a non-overlapping range of allowed external ports to use for NAT operation. Source ports of IPv4 packets translated by a NAT must belong to the assigned port set. The port set is used for all port-aware IP protocols [RFC7596].
  • Internal host: a host that may need to use a translation capability to send to and receive traffic from the Internet.
  • Internal address/prefix: the IP address/prefix of an internal host.
  • External address: the IP address/prefix assigned by a translator to an internal host; this is the address that will be seen by a remote host on the Internet.
  • Mapping: denotes a state at the translator that is necessary for network address and/or port translation.
  • Dynamic implicit mapping: is created implicitly as a side effect of processing a packet (e.g., an initial TCP SYN packet) that requires a new mapping. A validity lifetime is associated with this mapping.
  • Dynamic explicit mapping: is created as a result of an explicit request, e.g., a Port Control Protocol (PCP) message [RFC6887]. A validity lifetime is associated with this mapping.
  • Static explicit mapping: is created using, e.g., a command-line interface (CLI). This mapping is likely to be maintained by the NAT function till an explicit action is executed to remove it.
  • IPv4からIPv4への基本ネットワークアドレス変換（Basic Network Address Translation from IPv4 to IPv4、NAT44）：変換はIPアドレスのみに限定されます（[RFC3022]のSection 2.1）。
  • ネットワークアドレスポートトランスレーター（Network Address Port Translator、NAPT）：NAPTでの変換は、IPアドレスとトランスポート識別子（TCP/UDPポートやICMPクエリーIDなど）を含むように拡張されています。[RFC3022]のSection 2.2を参照してください。 NAPTは、バインディングを区別するために、5つのトランスポートタプルに加えて追加の識別子を使用する場合があります[RFC6619]。
  • 宛先NAT（Destination NAT）：宛先IPアドレスと宛先ポート番号の一方または両方に作用する変換です。 この種類は通常、ロードバランサーや公開サーバーの前段にある機器に展開されます。
  • ポート制限付きIPv4アドレス（Port-restricted IPv4 address）：制限されたポートセットを持つIPv4アドレスです。 複数のホストが同じIPv4アドレスを共有できますが、それらのポートセットは重複してはなりません[RFC7596]。
  • 制限付きポートセット（Restricted port set）：NAT操作に使用できる外部ポートの、重複しない範囲です。 NATによって変換されたIPv4パケットの送信元ポートは、割り当てられたポートセットに属していなければなりません。 このポートセットは、ポートを意識するすべてのIPプロトコルに使用されます[RFC7596]。
  • 内部ホスト（Internal host）：インターネットとの間でトラフィックを送受信するために、変換機能を使用する必要がある可能性のあるホストです。
  • 内部アドレス/プレフィックス（Internal address/prefix）：内部ホストのIPアドレス/プレフィックスです。
  • 外部アドレス（External address）：トランスレーターが内部ホストに割り当てるIPアドレス/プレフィックスです。これは、インターネット上のリモートホストから見えるアドレスです。
  • マッピング（Mapping）：ネットワークアドレス変換やポート変換に必要な、トランスレーターにおける状態を指します。
  • 動的暗黙マッピング（Dynamic implicit mapping）：新しいマッピングを必要とするパケット（たとえば、最初のTCP SYNパケット）を処理した副作用として、暗黙的に作成されます。 このマッピングには有効期間が関連付けられます。
  • 動的明示マッピング（Dynamic explicit mapping）：明示的な要求（たとえば、ポート制御プロトコル（PCP）メッセージ[RFC6887]）の結果として作成されます。 このマッピングには有効期間が関連付けられます。
  • 静的明示マッピング（Static explicit mapping）：たとえば、コマンドラインインターフェイス（CLI）を使用して作成されます。 このマッピングは、削除する明示的な操作が実行されるまで、NAT機能によって維持されることが多いです。

The usage of the term NAT in this document refers to any translation flavor (NAT44, NAT64, etc.) indifferently.

この文書におけるNATという用語は、どの種類の変換（NAT44、NAT64など）も区別なく指します。

This document uses the term "session" as defined in [RFC2663] and [RFC6146] for NAT64.

この文書では、「セッション」という用語を、[RFC2663]およびNAT64については[RFC6146]で定義されているとおりの意味で使用します。

This document follows the guidelines of [RFC8407], uses the common YANG types defined in [RFC6991], and adopts the Network Management Datastore Architecture (NMDA). The meaning of the symbols in tree diagrams is defined in [RFC8340].

この文書は、[RFC8407]のガイドラインに従い、[RFC6991]で定義されている共通YANG型を使用し、ネットワーク管理データストアアーキテクチャー（NMDA）を採用しています。 ツリー図で使われる記号の意味は、[RFC8340]で定義されています。

2. Overview of the NAT YANG Data Model

2. NATのYANGデータモデルの概要

2.1. Overview

2.1. 概要

The NAT YANG module is designed to cover dynamic implicit mappings and static explicit mappings. The required functionality to instruct dynamic explicit mappings is defined in separate documents such as [YANG-PCP]. Considerations about instructing by explicit dynamic means (e.g., [RFC6887], [RFC6736], or [RFC8045]) are out of scope. As a reminder, REQ-9 of [RFC6888] requires that a CGN must implement a protocol giving subscribers explicit control over NAT mappings; that protocol should be the Port Control Protocol [RFC6887].

NATのYANGモジュールは、動的暗黙マッピングと静的明示マッピングを扱うように設計されています。 動的明示マッピングを指示するために必要な機能は、[YANG-PCP]などの別の文書で定義されています。 明示的な動的手段（たとえば、[RFC6887]、[RFC6736]、[RFC8045]）による指示に関する考慮事項は範囲外です。 念のため述べておくと、[RFC6888]のREQ-9は、NATマッピングに対する明示的な制御を加入者に与えるプロトコルをCGNが実装しなければならないことを要求しており、そのプロトコルはポート制御プロトコル[RFC6887]であるべきだとしています。

A single NAT device can have multiple NAT instances; each of these instances can be provided with its own policies (e.g., be responsible for serving a group of hosts). This document does not make any assumption about how internal hosts or flows are associated with a given NAT instance.

1つのNAT機器は複数のNATインスタンスを持つことができ、これらのインスタンスはそれぞれ独自のポリシーを与えられます（たとえば、あるホストのグループへのサービスを担当するなど）。 この文書は、内部ホストやフローが特定のNATインスタンスにどのように関連付けられるかについて、何の前提も置きません。

The NAT YANG module assumes that each NAT instance can be enabled/ disabled, be provisioned with a specific set of configuration data, and maintain its own mapping tables.

NATのYANGモジュールは、各NATインスタンスが有効化・無効化でき、特定の設定データの集合を設定でき、独自のマッピングテーブルを維持できることを前提としています。

The NAT YANG module allows for a NAT instance to be provided with multiple NAT policies (/nat/instances/instance/policy). The document does not make any assumption about how flows are associated with a given NAT policy of a given NAT instance. Classification filters are out of scope.

NATのYANGモジュールでは、1つのNATインスタンスに複数のNATポリシー（/nat/instances/instance/policy）を与えることができます。 この文書は、フローが特定のNATインスタンスの特定のNATポリシーにどのように関連付けられるかについて、何の前提も置きません。 分類フィルターは範囲外です。

Defining multiple NAT instances or configuring multiple NAT policies within one single NAT instance is implementation and deployment specific.

複数のNATインスタンスを定義するか、1つのNATインスタンス内に複数のNATポリシーを設定するかは、実装と展開に固有です。

This YANG module does not provide any method to instruct a NAT function to enable the logging feature or to specify the information to be logged for administrative or regulatory reasons (Section 2.3 of [RFC6908] and REQ-12 of [RFC6888]). Those considerations are out of the scope of this document.

このYANGモジュールは、管理上または規制上の理由（[RFC6908]のSection 2.3および[RFC6888]のREQ-12）で、ログ機能を有効にしたり、ログに記録する情報を指定したりするようNAT機能に指示する方法を提供しません。 それらの考慮事項は、この文書の範囲外です。

2.2. Various Translation Flavors

2.2. さまざまな種類の変換

The following translation modes are supported:

次の変換モードがサポートされています。

  • Basic NAT44
  • NAPT
  • Destination NAT
  • Port-restricted NAT
  • Stateful NAT64 (including with destination-based Pref64::/n [RFC7050])
  • SIIT
  • CLAT
  • EAM
  • NPTv6
  • Combination of Basic NAT/NAPT and Destination NAT
  • Combination of port-restricted and Destination NAT
  • Combination of NAT64 and EAM
  • Stateful and Stateless NAT64
  • 基本NAT44
  • NAPT
  • 宛先NAT
  • ポート制限付きNAT
  • ステートフルNAT64（宛先ベースのPref64::/n[RFC7050]を含む）
  • SIIT
  • CLAT
  • EAM
  • NPTv6
  • 基本NAT/NAPTと宛先NATの組み合わせ
  • ポート制限付きNATと宛先NATの組み合わせ
  • NAT64とEAMの組み合わせ
  • ステートフルNAT64とステートレスNAT64

[RFC8513] specifies an extension to the NAT YANG module to support Dual-Stack Lite (DS-Lite).

[RFC8513]は、デュアルスタックライト（DS-Lite）をサポートするためのNATのYANGモジュールの拡張を規定しています。

YANGの"feature"ステートメントは、異なる変換モードのうちどれが特定のデータノードに関係するかを示すために使用されます。 Table 1は、定義されている機能の一覧です。

The following translation modes do not require that dedicated features be defined:

次の変換モードでは、専用の機能を定義する必要はありません。

  • Port-restricted NAT: This mode corresponds to supplying port-restriction policies to a NAPT or NAT64 (port-set-restrict).
  • Combination of Basic NAT/NAPT and Destination NAT: This mode corresponds to setting 'dst-nat-enable' for Basic NAT44 or NAPT.
  • Combination of port-restricted and Destination NAT: This mode can be achieved by configuring a NAPT with port restriction policies (port-set-restrict) together with a destination IP address pool (dst-ip-address-pool).
  • Combination of NAT64 and EAM: This mode corresponds to configuring static mappings for NAT64.
  • Stateful and stateless NAT64: A NAT64 implementation can be instructed to behave in the stateless mode for a given prefix by setting the parameter (nat64-prefixes/stateless-enable). A NAT64 implementation may behave in both stateful and stateless modes if, in addition to appropriately setting the parameter (nat64-prefixes/stateless-enable), an external IPv4 address pool is configured.
  • ポート制限付きNAT：このモードは、NAPTまたはNAT64にポート制限ポリシー（port-set-restrict）を与えることに相当します。
  • 基本NAT/NAPTと宛先NATの組み合わせ：このモードは、基本NAT44またはNAPTに対して'dst-nat-enable'を設定することに相当します。
  • ポート制限付きNATと宛先NATの組み合わせ：このモードは、ポート制限ポリシー（port-set-restrict）と宛先IPアドレスプール（dst-ip-address-pool）をあわせてNAPTに設定することで実現できます。
  • NAT64とEAMの組み合わせ：このモードは、NAT64に静的マッピングを設定することに相当します。
  • ステートフルNAT64とステートレスNAT64：パラメーター（nat64-prefixes/stateless-enable）を設定することで、特定のプレフィックスについてステートレスモードで動作するようNAT64実装に指示できます。 パラメーター（nat64-prefixes/stateless-enable）を適切に設定することに加えて、外部IPv4アドレスプールが設定されている場合、NAT64実装はステートフルモードとステートレスモードの両方で動作できます。

The NAT YANG module provides a method to retrieve the capabilities of a NAT instance (including a list of supported translation modes, a list of supported protocols, the supported NAT mapping types, the supported NAT filtering types, the behavior for handling fragments (all, out-of-order, in-order), and the support statuses for the following: port restriction, port range allocation, port parity preservation, and port preservation).

NATのYANGモジュールは、NATインスタンスの能力（サポートされる変換モードの一覧、サポートされるプロトコルの一覧、サポートされるNATマッピングの種類、サポートされるNATフィルタリングの種類、フラグメントの処理の動作（all、out-of-order、in-order）、および次のもののサポート状況：ポート制限、ポート範囲割り当て、ポートパリティー保持、ポート保持）を取得する方法を提供します。

2.3. TCP/UDP/ICMP NAT Behavioral Requirements

2.3. TCP/UDP/ICMPのNATの動作要件

This document assumes NAT behavioral recommendations for UDP [RFC4787], TCP [RFC5382], and ICMP [RFC5508] are enabled by default.

この文書は、UDP[RFC4787]、TCP[RFC5382]、ICMP[RFC5508]に関するNATの動作の推奨事項がデフォルトで有効になっていることを前提としています。

Furthermore, the NAT YANG module relies upon the recommendations detailed in [RFC6888] and [RFC7857].

さらに、NATのYANGモジュールは、[RFC6888]と[RFC7857]で詳述されている推奨事項に依拠しています。

2.4. Other Transport Protocols

2.4. ほかのトランスポートプロトコル

The module is structured to support protocols other than UDP, TCP, and ICMP. Concretely, the module allows the operator to enable translation for other transport protocols when required (/nat/instances/instance/policy/transport-protocols). Moreover, the mapping table is designed so that it can indicate any transport protocol. For example, this module may be used to manage a NAT capable of the Datagram Congestion Control Protocol (DCCP) that adheres to [RFC5597].

このモジュールは、UDP、TCP、ICMP以外のプロトコルをサポートするように構成されています。 具体的には、このモジュールでは、必要に応じて運用者がほかのトランスポートプロトコルの変換を有効にできます（/nat/instances/instance/policy/transport-protocols）。 さらに、マッピングテーブルは、任意のトランスポートプロトコルを示せるように設計されています。 たとえば、このモジュールは、[RFC5597]に準拠したデータグラム輻輳制御プロトコル（DCCP）に対応するNATの管理に使用できます。

Future extensions may be needed to cover NAT-related considerations that are specific to other transport protocols such as the Stream Control Transmission Protocol (SCTP) [NAT-SUPP]. Typically, the mapping entry can be extended to record two optional SCTP-specific parameters: the Internal Verification Tag (Int-VTag) and External Verification Tag (Ext-VTag).

ストリーム制御伝送プロトコル（SCTP）[NAT-SUPP]のような、ほかのトランスポートプロトコルに固有のNAT関連の考慮事項を扱うために、将来の拡張が必要になる可能性があります。 典型的には、マッピングエントリーを拡張して、SCTP固有の2つの任意のパラメーター、すなわち内部検証タグ（Internal Verification Tag、Int-VTag）と外部検証タグ（External Verification Tag、Ext-VTag）を記録できます。

This document only specifies transport-protocol-specific timers for UDP, TCP, and ICMP. While some timers could potentially be generalized for other connection-oriented protocols, this document does not follow such an approach because there is no standard document specifying such generic behavior. Future documents may be edited to clarify how to reuse TCP-specific timers when needed.

この文書では、UDP、TCP、ICMPについてのみトランスポートプロトコル固有のタイマーを規定します。 一部のタイマーはほかのコネクション指向プロトコル向けに一般化できる可能性がありますが、そのような汎用的な動作を規定する標準文書が存在しないため、この文書ではそのようなアプローチをとりません。 必要に応じて、TCP固有のタイマーを再利用する方法を明確にするために、将来の文書が作成される可能性があります。

2.5. IP Addresses Used for Translation

2.5. 変換に使用するIPアドレス

The NAT YANG module assumes that blocks of IP external addresses (external-ip-address-pool) can be provisioned to the NAT function. These blocks may be contiguous or not.

NATのYANGモジュールは、外部IPアドレスのブロック（external-ip-address-pool）をNAT機能に設定できることを前提としています。 これらのブロックは連続していても、していなくてもかまいません。

This behavior is aligned with [RFC6888], which specifies that a NAT function should not have any limitations on the size or the contiguity of the external address pool. In particular, the NAT function must be configurable with contiguous or non-contiguous external IPv4 address ranges. To accommodate traditional NAT, the module allows for a single IP address to be configured for external- ip-address-pool.

この動作は[RFC6888]と整合しています。[RFC6888]は、NAT機能は外部アドレスプールのサイズや連続性に何の制限も持つべきではないと規定しています。 特に、NAT機能は、連続した、または不連続な外部IPv4アドレス範囲で設定できなければなりません。 従来型NATに対応するために、このモジュールでは、external-ip-address-poolに単一のIPアドレスを設定できます。

Likewise, one or multiple IP address pools may be configured for Destination NAT (dst-ip-address-pool).

同様に、宛先NATには1つまたは複数のIPアドレスプール（dst-ip-address-pool）を設定できます。

2.6. Port-Set Assignment

2.6. ポートセットの割り当て

Port numbers can be assigned by a NAT individually (that is, a single port is assigned on a per-session basis), but this port allocation scheme may not be optimal for logging purposes (Section 12 of [RFC6269]). A NAT function should be able to assign port sets (e.g., [RFC7753]) to optimize the volume of the logging data (REQ-14 of [RFC6888]). Both allocation schemes are supported in the NAT YANG module.

ポート番号はNATによって個別に割り当てることができます（つまり、セッションごとに1つのポートが割り当てられます）が、このポート割り当て方式はログ記録の目的には最適ではない可能性があります（[RFC6269]のSection 12）。 NAT機能は、ログデータの量を最適化するために、ポートセット（たとえば、[RFC7753]）を割り当てられるべきです（[RFC6888]のREQ-14）。 NATのYANGモジュールでは、両方の割り当て方式がサポートされています。

When port-set assignment is activated (i.e., port-allocation- type==port-range-allocation), the NAT can be provided with the size of the port set to be assigned (port-set-size).

ポートセットの割り当てが有効になっている場合（つまり、port-allocation-type==port-range-allocation）、割り当てるポートセットのサイズ（port-set-size）をNATに与えることができます。

2.7. Port-Restricted IP Addresses

2.7. ポート制限付きIPアドレス

Some NATs restrict the source port numbers (e.g., Lightweight 4over6 [RFC7596] and Mapping of Address and Port with Encapsulation (MAP-E) [RFC7597]). Two schemes of port-set assignments (port-set-restrict) are supported in this document:

一部のNATは、送信元ポート番号を制限します（たとえば、Lightweight 4over6[RFC7596]や、カプセル化を用いたアドレスとポートのマッピング（Mapping of Address and Port with Encapsulation、MAP-E）[RFC7597]）。 この文書では、2つのポートセット割り当て方式（port-set-restrict）をサポートしています。

  • Simple port range: is defined by two port values, the start and the end of the port range [RFC8045].
  • Algorithmic: an algorithm is defined in [RFC7597] to characterize the set of ports that can be used.
  • 単純なポート範囲（Simple port range）：ポート範囲の始点と終点の2つのポート値によって定義されます[RFC8045]。
  • アルゴリズム方式（Algorithmic）：使用できるポートの集合を特徴づけるアルゴリズムが[RFC7597]で定義されています。

2.9. Resource Limits

2.9. リソースの制限

In order to comply with CGN deployments in particular, the NAT YANG module allows limiting the number of external ports per subscriber (port-quota) and the amount of state memory allocated per mapping and per subscriber (mapping-limits and connection-limits). According to [RFC6888], the module is designed to allow for the following:

特にCGNの展開に対応するために、NATのYANGモジュールでは、加入者ごとの外部ポートの数（port-quota）と、マッピングごとおよび加入者ごとに割り当てられる状態メモリーの量（mapping-limitsとconnection-limits）を制限できます。 [RFC6888]に従って、このモジュールは次のことができるように設計されています。

  • Per-subscriber limits are configurable by the NAT administrator.
  • Per-subscriber limits are configurable independently per the transport protocol.
  • Administrator-adjustable thresholds to prevent a single subscriber from consuming excessive CPU resources from the NAT (e.g., rate-limit the subscriber's creation of new mappings) can be configured.
  • 加入者ごとの制限は、NATの管理者が設定できます。
  • 加入者ごとの制限は、トランスポートプロトコルごとに独立して設定できます。
  • 単一の加入者がNATのCPUリソースを過度に消費すること（たとえば、加入者による新しいマッピングの作成をレート制限すること）を防ぐために、管理者が調整可能なしきい値を設定できます。

2.10. Binding the NAT Function to an External Interface

2.10. NAT機能の外部インターフェイスへのバインド

The module is designed to specify an external realm on which the NAT function must be applied (external-realm). The module supports indicating an interface as an external realm [RFC8343], but the module is extensible so that other choices can be indicated in the future (e.g., Virtual Routing and Forwarding (VRF) instance).

このモジュールは、NAT機能を適用しなければならない外部レルム（external-realm）を指定するように設計されています。 このモジュールは、外部レルムとしてインターフェイス[RFC8343]を示すことをサポートしていますが、将来ほかの選択肢（たとえば、仮想ルーティング転送（Virtual Routing and Forwarding、VRF）インスタンス）を示せるように拡張可能になっています。

Distinct external realms can be provided as a function of the NAT policy (see, for example, Section 4 of [RFC7289]).

NATポリシーに応じて、異なる外部レルムを与えることができます（たとえば、[RFC7289]のSection 4を参照してください）。

If no external realm is provided, this assumes that the system is able to determine the external interface (VRF instance, etc.) on which the NAT will be applied. Typically, the WAN and LAN interfaces of Customer Premises Equipment (CPE) are determined by the CPE.

外部レルムが与えられない場合は、NATを適用する外部インターフェイス（VRFインスタンスなど）をシステムが判断できることを前提とします。 典型的には、顧客宅内機器（Customer Premises Equipment、CPE）のWANインターフェイスとLANインターフェイスは、CPEによって判断されます。

2.11. Relationship to NATV2-MIB

2.11. NATV2-MIBとの関係

Section of 5.1 of [RFC7659] indicates that the NATV2-MIB assumes that the following information is configured on the NAT by some means, which is not specified in [RFC7659]:

[RFC7659]のセクション5.1は、NATV2-MIBが、[RFC7659]では規定されていない何らかの手段によって次の情報がNATに設定されることを前提としていると述べています。

  • The set of address realms to which the device connects.
  • For the CGN case, per-subscriber information including the subscriber index, address realm, assigned prefix or address, and (possibly) policies regarding address pool selection in the various possible address realms to which the subscriber may connect.
  • The set of NAT instances running on the device, identified by NAT instance index and name.
  • The port mapping, filtering, pooling, and fragment behaviors for each NAT instance.
  • The set of protocols supported by each NAT instance.
  • Address pools for each NAT instance, including for each pool the pool index, address realm, and minimum and maximum port numbers.
  • Static address and port mapping entries.
  • 機器が接続するアドレスレルムの集合。
  • CGNの場合、加入者ごとの情報。これには、加入者インデックス、アドレスレルム、割り当てられたプレフィックスまたはアドレス、および（場合によっては）加入者が接続する可能性のあるさまざまなアドレスレルムにおけるアドレスプールの選択に関するポリシーが含まれます。
  • 機器上で動作しているNATインスタンスの集合。NATインスタンスのインデックスと名前によって識別されます。
  • 各NATインスタンスのポートマッピング、フィルタリング、プーリング、フラグメントの動作。
  • 各NATインスタンスがサポートするプロトコルの集合。
  • 各NATインスタンスのアドレスプール。各プールについて、プールのインデックス、アドレスレルム、最小ポート番号と最大ポート番号を含みます。
  • 静的なアドレスとポートのマッピングエントリー。

All the above parameters can be configured by means of the NAT YANG module.

上記のパラメーターはすべて、NATのYANGモジュールによって設定できます。

Unlike the NATV2-MIB, the NAT YANG module allows the configuration of multiple policies per NAT instance.

NATV2-MIBとは異なり、NATのYANGモジュールでは、NATインスタンスごとに複数のポリシーを設定できます。

4. Security Considerations

4. セキュリティーに関する考慮事項

Security considerations related to address and prefix translation are discussed in [RFC6888], [RFC6146], [RFC6877], [RFC6296], and [RFC7757].

アドレス変換とプレフィックス変換に関連するセキュリティーに関する考慮事項は、[RFC6888]、[RFC6146]、[RFC6877]、[RFC6296]、[RFC7757]で議論されています。

The YANG module specified in this document defines a schema for data that is designed to be accessed via network management protocols such as NETCONF [RFC6241] or RESTCONF [RFC8040]. The lowest NETCONF layer is the secure transport layer, and the mandatory-to-implement secure transport is Secure Shell (SSH) [RFC6242]. The lowest RESTCONF layer is HTTPS, and the mandatory-to-implement secure transport is TLS [RFC8446].

この文書で規定するYANGモジュールは、NETCONF[RFC6241]やRESTCONF[RFC8040]などのネットワーク管理プロトコルを介してアクセスされるように設計されたデータのスキーマを定義します。 NETCONFの最下位層は安全なトランスポート層であり、実装必須の安全なトランスポートはSecure Shell（SSH）[RFC6242]です。 RESTCONFの最下位層はHTTPSであり、実装必須の安全なトランスポートはTLS[RFC8446]です。

The Network Configuration Access Control Model (NACM) [RFC8341] provides the means to restrict access for particular NETCONF or RESTCONF users to a preconfigured subset of all available NETCONF or RESTCONF protocol operations and content.

ネットワーク設定アクセス制御モデル（NACM）[RFC8341]は、特定のNETCONFユーザーやRESTCONFユーザーのアクセスを、利用可能なすべてのNETCONFプロトコルやRESTCONFプロトコルの操作とコンテンツのうち、事前に設定されたサブセットに制限する手段を提供します。

All data nodes defined in the YANG module that can be created, modified, and deleted (i.e., config true, which is the default) are considered sensitive. Write operations (e.g., edit-config) applied to these data nodes without proper protection can negatively affect network operations. The NAT YANG module provides a method to set parameters to prevent a user from aggressively using NAT resources (port-quota), rate-limit connections as a guard against DoS, or to enable notifications so that appropriate measures are enforced to anticipate traffic drops. Nevertheless, an attacker who is able to access the NAT can undertake various attacks, such as:

このYANGモジュールで定義されている、作成・変更・削除が可能なすべてのデータノード（つまり、デフォルトであるconfig true）は、機密性が高いものとみなされます。 適切な保護なしにこれらのデータノードに対して書き込み操作（たとえば、edit-config）が適用されると、ネットワークの運用に悪影響を及ぼす可能性があります。 NATのYANGモジュールは、ユーザーがNATリソースを過度に使用することを防ぐためのパラメーター（port-quota）を設定したり、DoSへの防御として接続をレート制限したり、トラフィックの破棄を予期して適切な対策が講じられるように通知を有効にしたりする方法を提供します。 それでも、NATにアクセスできる攻撃者は、たとえば次のようなさまざまな攻撃を行うことができます。

  • Set a high or low resource limit to cause a DoS attack:

    • /nat/instances/instance/policy/port-quota
    • /nat/instances/instance/policy/fragments-limit
    • /nat/instances/instance/mapping-limits
    • /nat/instances/instance/connection-limits

  • Set a low notification threshold to cause useless notifications to be generated:

    • /nat/instances/instance/policy/notify-pool-usage/high-threshold
    • /nat/instances/instance/notification-limits/notify-addresses-usage
    • /nat/instances/instance/notification-limits/notify-ports-usage
    • /nat/instances/instance/notification-limits/notify-subscribers-limit

  • Set an arbitrarily high threshold, which may lead to the deactivation of notifications:

    • /nat/instances/instance/policy/notify-pool-usage/high-threshold
    • /nat/instances/instance/notification-limits/notify-addresses-usage
    • /nat/instances/instance/notification-limits/notify-ports-usage
    • /nat/instances/instance/notification-limits/notify-subscribers-limit

  • Set a low notification interval and a low notification threshold to induce useless notifications to be generated:

    • /nat/instances/instance/policy/notify-pool-usage/notify-interval
    • /nat/instances/instance/notification-limits/notify-interval

  • Access to privacy data maintained in the mapping table. Such data can be misused to track the activity of a host:

    • /nat/instances/instance/mapping-table

  • DoS攻撃を引き起こすために、リソースの制限を高く、または低く設定する。

    • /nat/instances/instance/policy/port-quota
    • /nat/instances/instance/policy/fragments-limit
    • /nat/instances/instance/mapping-limits
    • /nat/instances/instance/connection-limits

  • 不要な通知を生成させるために、通知のしきい値を低く設定する。

    • /nat/instances/instance/policy/notify-pool-usage/high-threshold
    • /nat/instances/instance/notification-limits/notify-addresses-usage
    • /nat/instances/instance/notification-limits/notify-ports-usage
    • /nat/instances/instance/notification-limits/notify-subscribers-limit

  • 通知の無効化につながる可能性のある、任意に高いしきい値を設定する。

    • /nat/instances/instance/policy/notify-pool-usage/high-threshold
    • /nat/instances/instance/notification-limits/notify-addresses-usage
    • /nat/instances/instance/notification-limits/notify-ports-usage
    • /nat/instances/instance/notification-limits/notify-subscribers-limit

  • 不要な通知を生成させるために、通知間隔を短く、通知のしきい値を低く設定する。

    • /nat/instances/instance/policy/notify-pool-usage/notify-interval
    • /nat/instances/instance/notification-limits/notify-interval

  • マッピングテーブルに保持されているプライバシーデータにアクセスする。 このようなデータは、ホストの活動を追跡するために悪用される可能性があります。

    • /nat/instances/instance/mapping-table

A.1. 従来型NAT44

When the translator receives an IPv6 packet, for example, with a source address (2001:db8:1c0:2:21::) and destination address (2001:db8:1c6:3364:2::), it extracts embedded IPv4 addresses following rules per RFC 6052 with 2001:db8:100::/40 as the NSP:

トランスレーターは、たとえば送信元アドレス（2001:db8:1c0:2:21::）と宛先アドレス（2001:db8:1c6:3364:2::）を持つIPv6パケットを受信すると、2001:db8:100::/40をNSPとしてRFC 6052の規則に従い、埋め込まれたIPv4アドレスを抽出します。

  • 192.0.2.33 is extracted from 2001:db8:1c0:2:21::
  • 198.51.100.2 is extracted from 2001:db8:1c6:3364:2::
  • 2001:db8:1c0:2:21::から192.0.2.33が抽出されます。
  • 2001:db8:1c6:3364:2::から198.51.100.2が抽出されます。

The translator transforms the IPv6 header into an IPv4 header using the IP/ICMP Translation Algorithm [RFC7915]. The IPv4 packets will include 192.0.2.33 as the source address and 198.51.100.2 as the destination address.

トランスレーターは、IP/ICMP変換アルゴリズム[RFC7915]を使用して、IPv6ヘッダーをIPv4ヘッダーに変換します。 IPv4パケットには、送信元アドレスとして192.0.2.33、宛先アドレスとして198.51.100.2が含まれます。
