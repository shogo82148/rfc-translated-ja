S/MIME Signature Verification Extension to the JSON Meta Application Protocol (JMAP)

RFC 9219

JSON Meta Application Protocol（JMAP）のS/MIME署名検証拡張

Abstract

概要

This document specifies an extension to "The JSON Meta Application Protocol (JMAP) for Mail" (RFC 8621) for returning the S/MIME signature verification status.

この文書は、S/MIME署名の検証ステータスを返すための、「The JSON Meta Application Protocol (JMAP) for Mail」（RFC 8621）に対する拡張を規定します。

1. Introduction

1. はじめに

JMAP for Mail [RFC8621] is a JSON-based application protocol for synchronizing email data between a client and a server.

JMAP for Mail[RFC8621]は、クライアントとサーバーの間で電子メールのデータを同期するための、JSONベースのアプリケーションプロトコルです。

This document describes an extension to JMAP for returning the S/MIME signature verification status [RFC8551], without requiring a JMAP client to download the signature body part and all signed body parts (when the multipart/signed media type [RFC1847] is used) or to download and decode the Cryptographic Message Syntax (CMS) (when the application/pkcs7-mime media type (Section 3.2 of [RFC8551]) is used). The use of the extension implies the client trusts the JMAP server's S/MIME signature verification code and configuration. This extension is suitable for cases where reduction in network bandwidth and client-side code complexity outweigh security concerns about trusting the JMAP server to perform S/MIME signature verifications. One possible use case is when the same organization controls both the JMAP server and the JMAP client.

この文書は、S/MIME署名の検証ステータス[RFC8551]を返すためのJMAPの拡張を記述します。 この拡張により、JMAPクライアントは、署名のボディーパートと署名されたすべてのボディーパートをダウンロードしたり（multipart/signedメディアタイプ[RFC1847]が使われている場合）、暗号メッセージ構文（Cryptographic Message Syntax：CMS）をダウンロードしてデコードしたり（application/pkcs7-mimeメディアタイプ（[RFC8551]のSection 3.2）が使われている場合）する必要がなくなります。 この拡張を使うことは、クライアントがJMAPサーバーのS/MIME署名検証コードとその設定を信頼していることを意味します。 この拡張は、S/MIME署名の検証をJMAPサーバーに任せることのセキュリティー上の懸念よりも、ネットワーク帯域幅とクライアント側のコードの複雑さを減らすことのほうが重要な場合に適しています。 考えられるユースケースの1つは、同じ組織がJMAPサーバーとJMAPクライアントの両方を管理している場合です。

3. Addition to the Capabilities Object

3. capabilitiesオブジェクトへの追加

The capabilities object is returned as part of the standard JMAP Session object; see Section 2 of [RFC8620]. Servers supporting this specification MUST add a property called "urn:ietf:params:jmap:smimeverify" to the capabilities object.

capabilitiesオブジェクトは、標準のJMAPのSessionオブジェクトの一部として返されます。[RFC8620]のSection 2を参照してください。 この仕様をサポートするサーバーは、capabilitiesオブジェクトに「urn:ietf:params:jmap:smimeverify」という名前のプロパティーを追加しなければなりません（MUST）。

The value of this property is an empty object in both the JMAP Session capabilities property and an account's accountCapabilities property.

このプロパティーの値は、JMAPのSessionのcapabilitiesプロパティーとアカウントのaccountCapabilitiesプロパティーのどちらにおいても、空のオブジェクトです。

4. Extension for S/MIME Signature Verification

4. S/MIME署名検証のための拡張

4.1. Extension to Email/get

4.1. Email/getへの拡張

[RFC8621] defines the Email/get method for retrieving message-specific information. This document defines the following pseudo values in the properties argument:

[RFC8621]は、メッセージ固有の情報を取得するためのEmail/getメソッドを定義しています。 この文書は、properties引数に指定できる次の疑似値を定義します。

smimeStatus:
If "smimeStatus" is included in the list of requested properties, it MUST be interpreted by the server as a request to return the "smimeStatus" response property.
smimeStatusAtDelivery:
If "smimeStatusAtDelivery" is included in the list of requested properties, it MUST be interpreted by the server as a request to return the "smimeStatusAtDelivery" response property. (It is effectively the same as the "smimeStatus" value calculated at the date/time of delivery, as specified by "receivedAt".)
smimeErrors:
If "smimeErrors" is included in the list of requested properties, it MUST be interpreted by the server as a request to return the "smimeErrors" response property.
smimeVerifiedAt:
If "smimeVerifiedAt" is included in the list of requested properties, it MUST be interpreted by the server as a request to return the "smimeVerifiedAt" response property.
smimeStatus:
要求されたプロパティーのリストに「smimeStatus」が含まれている場合、サーバーはそれを「smimeStatus」レスポンスプロパティーを返すことの要求として解釈しなければなりません（MUST）。
smimeStatusAtDelivery:
要求されたプロパティーのリストに「smimeStatusAtDelivery」が含まれている場合、サーバーはそれを「smimeStatusAtDelivery」レスポンスプロパティーを返すことの要求として解釈しなければなりません（MUST）。 （これは実質的に、「receivedAt」で示される配送日時の時点で計算した「smimeStatus」の値と同じです。）
smimeErrors:
要求されたプロパティーのリストに「smimeErrors」が含まれている場合、サーバーはそれを「smimeErrors」レスポンスプロパティーを返すことの要求として解釈しなければなりません（MUST）。
smimeVerifiedAt:
要求されたプロパティーのリストに「smimeVerifiedAt」が含まれている場合、サーバーはそれを「smimeVerifiedAt」レスポンスプロパティーを返すことの要求として解釈しなければなりません（MUST）。

The "smimeStatus" response property is defined as follows:

「smimeStatus」レスポンスプロパティーは次のように定義されます。

smimeStatus:

"String|null" (server-set). null signifies that the message doesn't contain any signature. Otherwise, this property contains the S/MIME signature and certificate verification status calculated according to [RFC8551], [RFC8550], and [RFC5280]. Possible string values of the property are listed below. Servers MAY return other values not defined below, as defined in extensions to this document. Clients MUST treat unrecognized values as "unknown" or "signed/failed". Note that the value of this property might change over time.

unknown:
An S/MIME message, but it was neither signed nor encrypted. This can also be returned for a multipart/signed message that contains an unrecognized signing protocol (for example, OpenPGP).
signed:
An S/MIME signed message, but the signature was not yet verified. Some servers might not attempt to verify a signature until a particular message is requested by the client. (This is a useful optimization for a JMAP server to avoid doing work until exact information is needed. A JMAP client that only needs to display an icon that signifies presence of an S/MIME signature can still use this value.) JMAP servers compliant with this document SHOULD attempt signature verification and return "signed/verified" or "signed/failed" instead of this signature status.
signed/verified:
An S/MIME signed message, and the sender's signature was successfully verified according to [RFC8551] and [RFC8550]. Additionally, the signer email address extracted from the S/MIME certificate matches the From header field value, and the signer certificate SHOULD be checked for revocation.
signed/failed:
S/MIME signed message, but the signature failed to verify according to [RFC8551] and [RFC8550]. This might be because of a policy-related decision (e.g., the message signer email address doesn't match the From header field value), the message was modified, the signer's certificate has expired or was revoked, etc.
encrypted+signed/verified:
This value is reserved for future use. It is typically handled in the same way as "signed/verified".
encrypted+signed/failed:
This value is reserved for future use. It is typically handled in the same way as "signed/failed".
smimeStatus:

"String|null"（サーバーが設定）。 nullは、そのメッセージに署名がまったく含まれていないことを表します。 それ以外の場合、このプロパティーには、[RFC8551]、[RFC8550]、[RFC5280]に従って計算した、S/MIME署名と証明書の検証ステータスが入ります。 このプロパティーが取りうる文字列値を以下に示します。 サーバーは、この文書の拡張で定義された、以下にない値を返してもよいです（MAY）。 クライアントは、認識できない値を「unknown」または「signed/failed」として扱わなければなりません（MUST）。 このプロパティーの値は時間とともに変わる可能性があることに注意してください。

unknown:
S/MIMEメッセージですが、署名も暗号化もされていません。 この値は、認識できない署名プロトコル（たとえばOpenPGP）を含むmultipart/signedメッセージに対しても返されることがあります。
signed:
S/MIMEで署名されたメッセージですが、署名はまだ検証されていません。 サーバーによっては、クライアントが特定のメッセージを要求するまで署名の検証を試みないことがあります。 （これは、正確な情報が必要になるまで処理を行わないようにするための、JMAPサーバーにとって有用な最適化です。 S/MIME署名の存在を表すアイコンを表示するだけでよいJMAPクライアントは、この値をそのまま使えます。） この文書に準拠したJMAPサーバーは、署名の検証を試み、この署名ステータスの代わりに「signed/verified」または「signed/failed」を返すべきです（SHOULD）。
signed/verified:
S/MIMEで署名されたメッセージであり、送信者の署名が[RFC8551]と[RFC8550]に従って正常に検証されました。 さらに、S/MIME証明書から抽出した署名者のメールアドレスがFromヘッダーフィールドの値と一致しています。 また、署名者の証明書の失効を確認すべきです（SHOULD）。
signed/failed:
S/MIMEで署名されたメッセージですが、[RFC8551]と[RFC8550]に従った署名の検証に失敗しました。 その原因としては、ポリシーに関する判断（たとえば、メッセージの署名者のメールアドレスがFromヘッダーフィールドの値と一致しない）、メッセージが改変された、署名者の証明書が期限切れになったか失効した、などが考えられます。
encrypted+signed/verified:
この値は将来の使用のために予約されています。通常は「signed/verified」と同じように扱います。
encrypted+signed/failed:
この値は将来の使用のために予約されています。通常は「signed/failed」と同じように扱います。

The "smimeStatusAtDelivery" response property has the same syntax as "smimeStatus" but is calculated in relationship to the "receivedAt" date/time. Unlike "smimeStatus", the "smimeStatusAtDelivery" response property value doesn't change unless trust anchors are added. (For example, addition of a trust anchor can change the value of a message "smimeStatusAtDelivery" property from "signed/failed" to "signed/verified". Note that trust anchor removal doesn't affect this response property.) The "smimeStatusAtDelivery" response property value allows clients to compare the S/MIME signature verification status at delivery with the current status as returned by "smimeStatus", for example, to help to answer questions like "was the signature valid at the time of delivery?".

「smimeStatusAtDelivery」レスポンスプロパティーは「smimeStatus」と同じ構文を持ちますが、「receivedAt」の日時を基準に計算されます。 「smimeStatus」とは異なり、「smimeStatusAtDelivery」レスポンスプロパティーの値は、トラストアンカーが追加されない限り変わりません。 （たとえば、トラストアンカーを追加すると、メッセージの「smimeStatusAtDelivery」プロパティーの値が「signed/failed」から「signed/verified」に変わることがあります。 トラストアンカーを削除しても、このレスポンスプロパティーには影響しないことに注意してください。） 「smimeStatusAtDelivery」レスポンスプロパティーの値を使うと、クライアントは、配送時のS/MIME署名の検証ステータスと「smimeStatus」が返す現在のステータスとを比較できます。 これはたとえば、「配送時点で署名は有効だったか？」のような問いに答えるのに役立ちます。

Note that the "smimeStatusAtDelivery" response property value doesn't have to be calculated at delivery time. A JMAP server can defer its calculation until it is explicitly requested; however, once it is calculated, its value is remembered for later use.

「smimeStatusAtDelivery」レスポンスプロパティーの値は、配送時に計算する必要はないことに注意してください。 JMAPサーバーは、明示的に要求されるまでその計算を遅らせることができます。 ただし、いったん計算したら、その値は後で使うために記憶されます。

The "smimeErrors" response property is defined as follows:

「smimeErrors」レスポンスプロパティーは次のように定義されます。

smimeErrors:
"String[]|null" (server-set). null signifies that the message doesn't contain any signature or that there were no errors when verifying the S/MIME signature. (That is, this property is non-null only when the corresponding "smimeStatus" response property value is "signed/failed" or "encrypted+signed/failed". Note that future extensions to this document can specify other "smimeStatus" values that can be used with "smimeErrors".) Each string in the array is a human-readable description (in the language specified in the Content-Language header field, if any) of a problem with the signature, the signing certificate, or the signing certificate chain. (See Section 3.8 of [RFC8620] in regards to how this is affected by the language selection.) In one example, the signing certificate might be expired and the message From email address might not correspond to any of the email addresses in the signing certificate. In another example, the certificate might be expired and the JMAP server might be unable to retrieve a Certificate Revocation List (CRL) for the certificate. In both of these cases, there would be 2 elements in the array.
smimeErrors:
"String[]|null"（サーバーが設定）。 nullは、そのメッセージに署名がまったく含まれていないこと、またはS/MIME署名の検証時にエラーがなかったことを表します。 （つまり、このプロパティーがnullでないのは、対応する「smimeStatus」レスポンスプロパティーの値が「signed/failed」または「encrypted+signed/failed」の場合だけです。 この文書に対する将来の拡張で、「smimeErrors」とともに使える他の「smimeStatus」の値を規定できることに注意してください。） 配列内の各文字列は、署名、署名証明書、または署名証明書チェーンの問題を人が読める形で説明したものです（Content-Languageヘッダーフィールドがあれば、そこで指定された言語で記述します）。 （言語の選択がこれにどう影響するかについては、[RFC8620]のSection 3.8を参照してください。） 1つ目の例として、署名証明書が期限切れになっており、かつメッセージのFromのメールアドレスが署名証明書内のどのメールアドレスとも一致しない場合が考えられます。 別の例として、証明書が期限切れになっており、かつJMAPサーバーがその証明書の証明書失効リスト（CRL）を取得できない場合が考えられます。 どちらの場合も、配列には2つの要素が入ります。

The "smimeVerifiedAt" response property is defined as follows:

「smimeVerifiedAt」レスポンスプロパティーは次のように定義されます。

smimeVerifiedAt:
"UTCDate|null" (server-set). null signifies that the message doesn't contain any S/MIME signature or that there is a signature, but there was no attempt to verify it. (Retrieval of the "smimeStatus" value can be used to distinguish these 2 cases). In all other cases, it is set to the date and time of when the S/MIME signature was most recently verified. Note that a request to fetch "smimeStatus", "smimeStatusAtDelivery", and/or "smimeErrors" would force this response property to be set to a non-null value if an S/MIME signature exists.
smimeVerifiedAt:
"UTCDate|null"（サーバーが設定）。 nullは、そのメッセージにS/MIME署名がまったく含まれていないこと、または署名はあるものの検証が試みられていないことを表します。 （この2つの場合は、「smimeStatus」の値を取得すれば区別できます。） それ以外のすべての場合、このプロパティーには、S/MIME署名が最後に検証された日時が設定されます。 「smimeStatus」、「smimeStatusAtDelivery」、「smimeErrors」のいずれかを取得するリクエストを行うと、S/MIME署名が存在する場合には、このレスポンスプロパティーに強制的にnull以外の値が設定されることに注意してください。

The "smimeStatus" and "smimeErrors" values are calculated at the time the corresponding JMAP request is processed (but see below about the effect of result caching), not at the time when the message is generated (according to its Date header field value). In all cases, "smimeVerifiedAt" is set to the time when "smimeStatus" and "smimeErrors" were last updated. As recalculating these values is expensive for the server, they MAY be cached for up to 24 hours from the moment when they were calculated.

「smimeStatus」と「smimeErrors」の値は、メッセージが生成された時点（Dateヘッダーフィールドの値による）ではなく、対応するJMAPリクエストが処理される時点で計算されます（ただし、結果のキャッシュの影響については後述します）。 どの場合でも、「smimeVerifiedAt」には「smimeStatus」と「smimeErrors」が最後に更新された時刻が設定されます。 これらの値の再計算はサーバーにとってコストが高いため、計算した時点から最大24時間まで、これらの値をキャッシュしてもよいです（MAY）。

Example 1: Retrieval of minimal information about a message, including its From, Subject, and Date header fields, as well as the S/MIME signature verification status at delivery and date/time when the message was received.

例1：メッセージに関する最小限の情報の取得。From、Subject、Dateの各ヘッダーフィールドに加えて、配送時のS/MIME署名の検証ステータスと、メッセージを受信した日時を取得します。 

["Email/get", {
"ids": [ "fe123u457" ],
"properties": [ "mailboxIds", "from", "subject", "date",
 "smimeStatusAtDelivery", "receivedAt" ]
}, "#1"]

 "smimeStatusAtDelivery", "receivedAt" ]
}, "#1"]

これにより、たとえば次のレスポンスが返されます。

4.1.1. "smimeStatus" Response Property Extensibility

4.1.1. 「smimeStatus」レスポンスプロパティーの拡張性

Future extensions to this document can specify extra allowed values for the "smimeStatus" response property. All values (defined in this document or in extensions to this document) MUST be in ASCII. (Note that this response property contains tokens; thus, it is not subject to internationalization or localization).

この文書に対する将来の拡張で、「smimeStatus」レスポンスプロパティーに使える値を追加で規定できます。 （この文書で定義されたものであれ、この文書の拡張で定義されたものであれ）すべての値はASCIIでなければなりません（MUST）。 （このレスポンスプロパティーにはトークンが入るため、国際化やローカライゼーションの対象にはならないことに注意してください。）

New "smimeStatus" response property values defined in extensions may affect the behavior of properties, such as the "smimeErrors" response property of Email/get (see Section 4.1) or the "hasVerifiedSmime" property of Email/query (see Section 4.2). In particular, the new values can be treated similarly to values defined in this document.

拡張で定義された新しい「smimeStatus」レスポンスプロパティーの値は、Email/getの「smimeErrors」レスポンスプロパティー（Section 4.1を参照）やEmail/queryの「hasVerifiedSmime」プロパティー（Section 4.2を参照）などのプロパティーの振る舞いに影響する場合があります。 特に、新しい値は、この文書で定義された値と同様に扱うことができます。

For example, a putative JMAP extension for automatically decrypting S/MIME messages can specify two additional values, one specifying that a message is both encrypted and signed with a valid S/MIME signature (e.g. "encrypted+signed/verified") and another one specifying that a message is both encrypted and signed with an invalid S/MIME signature (e.g. "encrypted+signed/failed"). The former value can be treated as "signed/verified" (and would thus affect "hasVerifiedSmime") and the latter can be treated as "signed/failed" (and thus can be used with "smimeErrors").

たとえば、S/MIMEメッセージを自動的に復号するための仮想的なJMAP拡張では、値を2つ追加で規定することが考えられます。 1つはメッセージが暗号化され、かつ有効なS/MIME署名で署名されていることを示す値（例：「encrypted+signed/verified」）、もう1つはメッセージが暗号化され、かつ無効なS/MIME署名で署名されていることを示す値（例：「encrypted+signed/failed」）です。 前者の値は「signed/verified」として扱えます（したがって「hasVerifiedSmime」に影響します）。 後者の値は「signed/failed」として扱えます（したがって「smimeErrors」とともに使えます）。

4.2. Extension to Email/query

4.2. Email/queryへの拡張

[RFC8621] defines the Email/query method for searching for messages with specific properties. This document defines the following properties of the FilterCondition object:

[RFC8621]は、特定のプロパティーを持つメッセージを検索するためのEmail/queryメソッドを定義しています。 この文書は、FilterConditionオブジェクトの次のプロパティーを定義します。

hasSmime:
"Boolean". If "hasSmime" has the value true, only messages with "smimeStatus" other than null match the condition. If "hasSmime" has the value false, only messages with "smimeStatus" equal to null match the condition.
hasVerifiedSmime:

"Boolean". If "hasVerifiedSmime" has the value true, only messages with "smimeStatus" equal to "signed/verified" or "encrypted+signed/verified" (*) match the condition. If "hasVerifiedSmime" has the value false, only messages with "smimeStatus" not equal to "signed/verified" and not equal to "encrypted+signed/verified" (*) (including the value null) match the condition. Note that use of this attribute is potentially expensive for a JMAP server, as it forces calculation of the "smimeStatus" property value for each message. However, caching of the "smimeStatus" values should ameliorate this cost somewhat.

(*) as well as the "smimeStatus" values added by future extensions to this document that are explicitly specified as having similar effect to "signed/verified" as far as "hasVerifiedSmime" calculation is concerned.

hasVerifiedSmimeAtDelivery:
"Boolean". The "hasVerifiedSmimeAtDelivery" property is handled similarly to the "hasVerifiedSmime" property, but the value of "smimeStatusAtDelivery" is used instead of "smimeStatus" to assess whether a particular message matches the condition.
hasSmime:
"Boolean"。 「hasSmime」の値がtrueの場合、「smimeStatus」がnull以外のメッセージだけが条件に一致します。 「hasSmime」の値がfalseの場合、「smimeStatus」がnullのメッセージだけが条件に一致します。
hasVerifiedSmime:

"Boolean"。 「hasVerifiedSmime」の値がtrueの場合、「smimeStatus」が「signed/verified」または「encrypted+signed/verified」（*）であるメッセージだけが条件に一致します。 「hasVerifiedSmime」の値がfalseの場合、「smimeStatus」が「signed/verified」でも「encrypted+signed/verified」（*）でもないメッセージ（値がnullのものを含む）だけが条件に一致します。 この属性を使うと、メッセージごとに「smimeStatus」プロパティーの値を計算しなければならなくなるため、JMAPサーバーにとってコストが高くなる可能性があることに注意してください。 ただし、「smimeStatus」の値をキャッシュすれば、このコストはある程度緩和されるはずです。

（*）この文書に対する将来の拡張で追加された「smimeStatus」の値のうち、「hasVerifiedSmime」の計算に関して「signed/verified」と同様の効果を持つことが明示的に規定されたものも含みます。

hasVerifiedSmimeAtDelivery:
"Boolean"。 「hasVerifiedSmimeAtDelivery」プロパティーは「hasVerifiedSmime」プロパティーと同様に扱われますが、特定のメッセージが条件に一致するかどうかの判定には、「smimeStatus」の代わりに「smimeStatusAtDelivery」の値が使われます。

4.3. Interaction with Email/changes

4.3. Email/changesとの相互作用

Changes to the "smimeVerifiedAt" response property value MUST NOT cause the message to be included in the "updated" argument of the Email/changes response. However, changes to the "smimeStatus", "smimeStatusAtDelivery", and/or "smimeErrors" response properties MUST result in message inclusion in the "updated" argument of the Email/changes response.

「smimeVerifiedAt」レスポンスプロパティーの値の変更によって、そのメッセージがEmail/changesレスポンスの「updated」引数に含まれるようになってはなりません（MUST NOT）。 一方、「smimeStatus」、「smimeStatusAtDelivery」、「smimeErrors」のいずれかのレスポンスプロパティーが変更された場合は、そのメッセージをEmail/changesレスポンスの「updated」引数に含めなければなりません（MUST）。

6. Security Considerations

6. セキュリティーに関する考慮事項

Use of the server-side S/MIME signature verification JMAP extension requires the client to trust the server signature verification code, the server configuration, and the server's operational practices to perform S/MIME signature verification, as well as to trust that the channel between the client and the server is integrity protected. (For example, if the server is not configured with some trust anchors, some messages will have the "signed/failed" status instead of "signed/verified".) A malicious or compromised server could return a false verification status to a client. A successful verification could be conveyed to a client for a forged or altered message. A properly signed message could be signaled as having a failed signature verification or no signature at all. In the case of the latter attack, no new attack surface is presented with this extension above what a malicious or compromised server could already do by stripping or tampering with the S/MIME information in the message. In the case of the former attack, client software capable of performing S/MIME signature verification could detect this attack. Local configuration of the client should determine if this client-side verification should occur. For clients without local verification capabilities, such an attack would be difficult to detect.

サーバー側でS/MIME署名を検証するこのJMAP拡張を使うには、クライアントは、S/MIME署名の検証を行うサーバーの署名検証コード、サーバーの設定、サーバーの運用方法を信頼する必要があります。 また、クライアントとサーバーの間のチャネルが完全性保護されていることも信頼する必要があります。 （たとえば、サーバーに一部のトラストアンカーが設定されていない場合、一部のメッセージのステータスは「signed/verified」ではなく「signed/failed」になります。） 悪意のあるサーバーや侵害されたサーバーは、偽の検証ステータスをクライアントに返す可能性があります。 偽造または改変されたメッセージについて、検証に成功したことがクライアントに伝えられる可能性があります。 正しく署名されたメッセージについて、署名の検証に失敗した、あるいは署名がまったくないと伝えられる可能性もあります。 後者の攻撃の場合、悪意のあるサーバーや侵害されたサーバーは、もともとメッセージ内のS/MIME情報を取り除いたり改ざんしたりすることで同じことができるので、この拡張によって新たな攻撃対象領域が生じることはありません。 前者の攻撃の場合、S/MIME署名の検証を行えるクライアントソフトウェアであれば、この攻撃を検出できます。 このようなクライアント側の検証を行うかどうかは、クライアントのローカル設定で決めるべきです。 ローカルで検証する能力を持たないクライアントにとって、このような攻撃を検出するのは困難です。

Integrity protection of the channel between the client and the server is provided by use of TLS, as required by the JMAP specification (see Section 8.1 of [RFC8620]).

クライアントとサーバーの間のチャネルの完全性保護は、JMAPの仕様で要求されているとおり（[RFC8620]のSection 8.1を参照）、TLSを使うことで提供されます。

Constant recalculation of the S/MIME signature status can result in a denial-of-service condition. For that reason, it is RECOMMENDED that servers cache results of signature verification for up to 24 hours.

S/MIME署名のステータスを絶えず再計算すると、サービス拒否の状態に陥る可能性があります。 そのため、サーバーは署名検証の結果を最大24時間までキャッシュすることが推奨されます（RECOMMENDED）。
