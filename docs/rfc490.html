RFC 490

Surrogate RJS for UCLA-CCN

RFC 490

UCLA-CCNのための代理RJS

Abstract

概要

By using UCSB's Network Standard RJS* users can now gain access to UCLA-CCN's RJS without converting to the UCLA protocol. In addition, the need to use and create files in an intermediate host is avoided. For example, TIP users may operate with hot card readers and printers through UCSB's Remote Job Server and have their jobs execute at UCLA-CCN. The disadvantages of this scheme as compared to direct connections to UCLA are as follows:

UCSBのネットワーク標準RJS*を使うことで、ユーザーはUCLAのプロトコルに変換することなく、UCLA-CCNのRJSにアクセスできるようになりました。さらに、中間ホストでファイルを使用したり作成したりする必要もなくなります。たとえば、TIPのユーザーは、UCSBのリモートジョブサーバー（Remote Job Server）を通じて、ホットカードリーダーやプリンターを操作し、ジョブをUCLA-CCNで実行させることができます。UCLAに直接接続する場合と比べたこの方式の欠点は、次のとおりです。

  1. A small amount of additional JCL is required to route jobs from UCSB to UCLA.
  2. A UCSB batch account must be opened.
  3. Turnaround time includes waits in UCSB batch queues.
  4. The current implementation requires separate submission and retrieval steps.
  5. The RJS terminal used for submission/retrieval at UCLA-CCN should not be accessed online until all transfers to/from UCSB are complete.
  1. ジョブをUCSBからUCLAへ回送するために、少量の追加のJCLが必要です。
  2. UCSBのバッチアカウントを開設しなければなりません。
  3. ターンアラウンド時間には、UCSBのバッチキューでの待ち時間が含まれます。
  4. 現在の実装では、投入と取得を別々の手順で行う必要があります。
  5. UCLA-CCNで投入や取得に使用するRJS端末には、UCSBとの間のすべての転送が完了するまで、オンラインでアクセスすべきではありません。

Hopefully, these disadvantages are outweighed by the convenient interface to standard RJS.

これらの欠点を、標準RJSへの便利なインターフェイスという利点が上回ることを期待しています。

Attached is the document which describes this procedure to access UCLA-CCN.

UCLA-CCNにアクセスするためのこの手順を説明する文書を添付します。

*RFC #436 announces RJS at UCSB and RFC #477 describes its use.

*RFC #436はUCSBでのRJSを発表しており、RFC #477はその使い方を説明しています。

UCLA REMOTE JOB SUBMISSION FROM UCSB

UCSBからのUCLAへのリモートジョブ投入

Introduction

はじめに

Users of the IBM 360/75 at UCSB may now route jobs to and from UCLA-CCN (IBM 360/91). Only the reading, printing, and punching are handled at UCSB while the scheduling, allocation of resources, and execution are handled at UCLA. The program described below operates by establishing operator and data connections with UCLA's Remote Job Service through the ARPA Network and issuing operator commands to control the submission and retrieval of jobs. Thus it is possible for a user to run jobs on UCLA's 360/91 almost as if he were at UCLA.

UCSBのIBM 360/75のユーザーは、UCLA-CCN（IBM 360/91）との間でジョブを回送できるようになりました。UCSBで扱うのは読み取り、印刷、穿孔だけであり、スケジューリング、資源の割り当て、実行はUCLAで扱います。以下で説明するプログラムは、ARPAネットワークを通じてUCLAのリモートジョブサービス（Remote Job Service）とのオペレーター接続とデータ接続を確立し、オペレーターコマンドを発行してジョブの投入と取得を制御することで動作します。このため、ユーザーはUCLAにいるのとほとんど同じようにUCLAの360/91でジョブを実行できます。

Procedure

手順

Submission and retrieval are two separate phases which the user must initiate for each of his UCLA destined jobs. Usually, two UCSB jobs will be required for the two phases of one UCLA job. Exceptions do occur using the BATCH options described below and jobs with a guaranteed fast UCLA turnaround (e.g. QUICKRUN jobs.)

投入と取得は2つの別々のフェーズであり、ユーザーはUCLA宛ての各ジョブについてそれぞれを開始しなければなりません。通常、1つのUCLAのジョブの2つのフェーズのために、2つのUCSBのジョブが必要になります。例外は、以下で説明するBATCHオプションを使う場合と、UCLAでの高速なターンアラウンドが保証されているジョブ（たとえばQUICKRUNジョブ）の場合です。

Commands are issued through JCL to the local process and resultant actions and messages are recorded in the RJS system log on the user's listing. The user must be aware of the timing of his commands, e.g. a request to retrieve print output for a specific job will result in an error condition if the job has not finished executing at UCLA. Available commands are READ, PRINT, PUNCH, STATUS, and TERMID.

コマンドはJCLを通じてローカルプロセスに発行され、その結果の動作とメッセージは、ユーザーのリストに出力されるRJSシステムログに記録されます。ユーザーはコマンドのタイミングに注意しなければなりません。たとえば、特定のジョブの印刷出力を取得する要求は、そのジョブがUCLAで実行を終えていなければエラー状態になります。使用できるコマンドは、READ、PRINT、PUNCH、STATUS、TERMIDです。

Effort has been made to provide the user with fairly intelligible error diagnostics although this is not always possible. Error conditions are described in the section "ERRORS".

ユーザーにかなりわかりやすいエラー診断を提供するよう努めましたが、常に可能とは限りません。エラー状態については「ERRORS」の節で説明します。

Job Submission

ジョブの投入

The READ command is used to send jobs to UCLA. It is the default command if none other is specified. UCLA jobs may be batched together under a single read operation. Great care should be taken to terminate the batch with the correct delimiter (see DD Cards below) so that any following non-UCLA jobs won't be sent to UCLA by mistake. A suggested procedure, if submitting jobs from the campus computer center, would be to indicate on the job submission card the intended destination. If the job is accepted by UCLA a message from UCLA will be recorded indicating the job name and number of cards received.

READコマンドは、ジョブをUCLAへ送るために使います。ほかのコマンドが指定されていない場合は、これがデフォルトのコマンドです。UCLAのジョブは、1回の読み取り操作でまとめてバッチにできます。後続のUCLA以外のジョブが誤ってUCLAに送られないように、正しい区切り文字（以下のDDカードを参照）でバッチを終了するよう十分に注意すべきです。キャンパスのコンピューターセンターからジョブを投入する場合に推奨する手順は、ジョブ投入カードに意図した宛先を示しておくことです。ジョブがUCLAに受け付けられると、ジョブ名と受け取ったカードの枚数を示すUCLAからのメッセージが記録されます。

Single Job Retrieval

単一ジョブの取得

PRINT (JOBNAME) and PUNCH (JOBNAME) are used to explicitly fetch print and punch output, respectively. The UCLA RESET command is used to set all job priorities the same, and then to set the named job's priority to the highest value. An unknown command, HEREIAM, is used for synchronization purposes only. If the named job is not ready for output the local process will terminate with a timeout error (the current timer is set at one minute).

PRINT (JOBNAME)とPUNCH (JOBNAME)は、それぞれ印刷出力と穿孔出力を明示的に取り出すために使います。UCLAのRESETコマンドは、すべてのジョブの優先度を同じにしたうえで、指定したジョブの優先度を最高値に設定するために使います。未知のコマンドであるHEREIAMは、同期の目的にだけ使います。指定したジョブの出力の準備ができていない場合、ローカルプロセスはタイムアウトエラーで終了します（現在のタイマーは1分に設定されています）。

Multiple Job Retrieval

複数ジョブの取得

PRINT (*) and PUNCH (*) are used to fetch all waiting output. These commands should always be preceded by the TERMID command. Users who have their own RJS terminal assigned to them will use this mode.

PRINT (*)とPUNCH (*)は、待機中のすべての出力を取り出すために使います。これらのコマンドの前には、常にTERMIDコマンドを置くべきです。自分専用のRJS端末を割り当てられているユーザーは、このモードを使うことになるでしょう。

UCSB Job Control Cards

UCSBのジョブ制御カード

EXEC Card

EXECカード

The catalogued procedure to executed is named UCLARJS. Parameters are used to specify which functions are to be performed. The general form of the execute card is:

実行するカタログ式プロシージャーの名前はUCLARJSです。どの機能を実行するかは、パラメーターで指定します。実行カードの一般的な形式は次のとおりです。

    //anyname EXEC UCLARJS, PARM.RJS-'...functions...'

    //anyname EXEC UCLARJS, PARM.RJS-'...functions...'

PARM Field

PARMフィールド

The following list defines the allowable parameters and their indicated functions. All parameters are executed in sequence and separated by commas.

次の一覧は、使用できるパラメーターとその機能を定義します。すべてのパラメーターは順番に実行され、コンマで区切ります。

READ
Open the reader channel and send 80 column records from the SYSIN data set.
PRINT(JOBNAME)
Set indicated job's priority to highest value and retrieve the print output to the SYSPRINT data set. Records over 132 characters are folded to the next line.
PRINT (*)
Retrieve all print jobs.
PUNCH(JOBNAME)
Set indicated job's priority to highest value and retrieve 80 column punch output to the SYSPUNCH data set.
PUNCH (*)
Retrieve all punch jobs.
STATUS
Query UCLA about the status of all jobs assigned to this RJS terminal.
TERMID(NAME-PASSWORD)
Sign on as named RJS terminal. PASSWORD is optional and should be declared only if the terminal has a password. The local process always signs on initially as NETUCSB.
READ
リーダーチャネルを開き、SYSINデータセットから80桁のレコードを送ります。
PRINT(JOBNAME)
指定したジョブの優先度を最高値に設定し、印刷出力をSYSPRINTデータセットに取得します。132文字を超えるレコードは次の行に折り返されます。
PRINT (*)
すべての印刷ジョブを取得します。
PUNCH(JOBNAME)
指定したジョブの優先度を最高値に設定し、80桁の穿孔出力をSYSPUNCHデータセットに取得します。
PUNCH (*)
すべての穿孔ジョブを取得します。
STATUS
このRJS端末に割り当てられたすべてのジョブの状態をUCLAに問い合わせます。
TERMID(NAME-PASSWORD)
指定した名前のRJS端末としてサインオンします。PASSWORDは省略可能であり、端末にパスワードがある場合にだけ宣言すべきです。ローカルプロセスは、最初は常にNETUCSBとしてサインオンします。

DD Cards

DDカード

  1. Reader - The SYSIN data set should have the following format to be able to send JCL and /* cards:

       // RJS.SYSIN DD DATA,DLM=$$,DCB=(RECFM=F,LRECL=80,BLKSIZE=80)
                   .
                   .
                   .
                job(s)
                   .
                   .
                   .
   $$ (note, this special delimiter is required)
  2. Printer - The default RJS.SYSPRINT data set is specified as SYSOUT=A
  3. Punch - The default RJS.SYSPUNCH data set is specified as SYSOUT=B
  4. RJS log - The default RJS.MESSAGES data set is specified as SYSYOUT=A

  1. リーダー - JCLと/*カードを送れるようにするために、SYSINデータセットは次の形式にすべきです。

       // RJS.SYSIN DD DATA,DLM=$$,DCB=(RECFM=F,LRECL=80,BLKSIZE=80)
                   .
                   .
                   .
                job(s)
                   .
                   .
                   .
   $$ (note, this special delimiter is required)
  2. プリンター - デフォルトのRJS.SYSPRINTデータセットはSYSOUT=Aと指定されています。
  3. 穿孔 - デフォルトのRJS.SYSPUNCHデータセットはSYSOUT=Bと指定されています。
  4. RJSログ - デフォルトのRJS.MESSAGESデータセットはSYSYOUT=Aと指定されています。

Problems and Errors

問題とエラー

Most problems encountered fall into one of the following categories:

遭遇する問題のほとんどは、次のいずれかの分類に当てはまります。

  1. UCLA-CCN or ARPANET down.

    This condition is usually noted when the local process attempts connection with UCLA. The error message is usually "INITIAL CONNECTION OPEN ERROR."

  2. RJS terminal in use by a non-UCSB-jobshop process.

    This can occur if a user submits a job but signs on to his UCLA RJS terminal online prior to the local batch process coming into execution. This condition is usually noted by the appearance of "FAILURE OR TIMEOUT IN OPERATOR, PRINT OR PUNCH CHANNEL" with completion code 252.

  3. Job not ready to be retrieved.

    The local process attempts to set the priority of the indicated job but receives no successful response. This condition is also noted by the appearance of "FAILURE OR TIMEOUT IN OPERATOR, PRINT OR PUNCH CHANNEL" with completion code 252.

  4. UCLA is unable to retrieve output because of an age-old bug.

    Unfortunately this condition can occur for very small amounts of output. It is usually noted by the message "BEGINNING RETRIEVAL OF" followed by "(PROBABLE UCLA BUG).. PREVIOUSLY GOOD CONNECTION NOW HAS STATUS = 8". The output in this case is usually lost.

  1. UCLA-CCNまたはARPANETが停止している。

    この状態は、通常、ローカルプロセスがUCLAとの接続を試みたときに判明します。エラーメッセージは通常「INITIAL CONNECTION OPEN ERROR.」です。

  2. RJS端末がUCSBのジョブショップ以外のプロセスによって使用されている。

    これは、ユーザーがジョブを投入したものの、ローカルのバッチプロセスが実行に入る前に自分のUCLAのRJS端末にオンラインでサインオンした場合に起こりえます。この状態は、通常、完了コード252とともに「FAILURE OR TIMEOUT IN OPERATOR, PRINT OR PUNCH CHANNEL」が現れることで判明します。

  3. ジョブを取得する準備ができていない。

    ローカルプロセスは指定されたジョブの優先度を設定しようとしますが、成功の応答を受け取れません。この状態も、完了コード252とともに「FAILURE OR TIMEOUT IN OPERATOR, PRINT OR PUNCH CHANNEL」が現れることで判明します。

  4. 古くからあるバグのために、UCLAが出力を取得できない。

    残念ながら、この状態はごく少量の出力でも起こりえます。通常、「BEGINNING RETRIEVAL OF」に続いて「(PROBABLE UCLA BUG).. PREVIOUSLY GOOD CONNECTION NOW HAS STATUS = 8」というメッセージが出ることで判明します。この場合、出力は通常失われます。

Cases 1 through 3 are corrected by waiting and then trying again. Other error messages may require reference to the NETWORK USER GUIDE or consultation with Computer Center or Computer Systems Lab personnel.

ケース1から3は、待ってから再試行することで解決します。その他のエラーメッセージについては、NETWORK USER GUIDEを参照するか、コンピューターセンターまたはコンピューターシステム研究室の職員に相談する必要がある場合があります。

Examples

例

  1. Submit a job to UCLA-CCN through RJS terminal NETUCSB.

    //SUBMIT JOB (0000,ROBERTS),'PSYCH BOX'
//STEP1 EXEC UCLARJS
//RJS.SYSIN DD DATA,DLM=$$,DCB=(RECFM=F,LRECL=80,BLKSIZE=80
//AAA000IC JOB......
            .
            .
            .
            .
            .

$$
//

  2. Retrieve print job AAA000IC from terminal NETUCSB.

    //RETR JOB (0000,ROBERTS),'PSYCH BOX'
//STEP1 EXEC UCLARJS,PARM.RJS='PRINT(AAA000IC)'
//

  3. Retrieve all prints jobs from terminal NETRAND0

    //RETR JOB (0000, ROBERTS),'PSYCH BOX'
//STEP1 EXEC UCLARJS,'TERMID(NETRAND0),PRINT(*),STATUS'
//

  1. RJS端末NETUCSBを通じてUCLA-CCNにジョブを投入します。

    //SUBMIT JOB (0000,ROBERTS),'PSYCH BOX'
//STEP1 EXEC UCLARJS
//RJS.SYSIN DD DATA,DLM=$$,DCB=(RECFM=F,LRECL=80,BLKSIZE=80
//AAA000IC JOB......
            .
            .
            .
            .
            .

$$
//

  2. 端末NETUCSBから印刷ジョブAAA000ICを取得します。

    //RETR JOB (0000,ROBERTS),'PSYCH BOX'
//STEP1 EXEC UCLARJS,PARM.RJS='PRINT(AAA000IC)'
//

  3. 端末NETRAND0からすべての印刷ジョブを取得します。

//STEP1 EXEC UCLARJS,'TERMID(NETRAND0),PRINT(*),STATUS'
//
