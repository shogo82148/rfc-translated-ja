RFC 737

FTP Extension: XSEN

RFC 737

FTPの拡張：XSEN

Abstract

概要

This note describes an extension to the File Transfer Protocol which provides for "sending" a message to a logged-in user, as well as variants for mailing it normally whether the user is logged in or not.

このメモでは、ログイン中のユーザーにメッセージを「送信（send）」する機能と、ユーザーがログインしているかどうかにかかわらず通常どおりメールする変種を提供する、File Transfer Protocolの拡張について説明します。

Several systems have a SEND command or program which sends a message directly to a user's terminal. On the SAIL (SU-AI) and ITS (MIT-(AI/ML/MC/DMS)) systems the concept has been broadened to allow SEND'ing to users on other network sites; to support this, three new FTP commands were added which have a syntax identical to the existing MAIL command. For reference, the latter is:

いくつかのシステムには、ユーザーの端末にメッセージを直接送るSENDコマンドやプログラムがあります。SAIL（SU-AI）とITS（MIT-(AI/ML/MC/DMS)）のシステムでは、この概念を広げて、ネットワーク上のほかのサイトのユーザーにもSENDできるようにしました。これをサポートするため、既存のMAILコマンドとまったく同じ構文を持つ3つの新しいFTPコマンドを追加しました。参考までに、MAILコマンドは次のとおりです。

MAIL <SP> <recipient name> <CRLF>
If accepted, returns 350 reply and considers all succeeding lines to be the message text, terminated by a line containing only a period, upon which a 256 completion reply is returned. Various errors are possible.
MAIL <SP> <recipient name> <CRLF>
受け付けた場合は350応答を返し、後続のすべての行を、ピリオドだけを含む行で終わるメッセージテキストとみなします。その行を受け取ると256完了応答を返します。さまざまなエラーが起こりえます。

The new commands, with their special replies, are:

新しいコマンドと、それぞれに特有の応答は次のとおりです。

XSEN -- Send to terminal.
Returns 453 failure reply if the addressee is refusing or not logged in.
XSEM -- Send, Mail if can't.
Returns 009 notification reply if message cannot be SENT.
XMAS -- Mail And Send. (couldn't resist this one)
No special replies.
XSEN -- 端末に送信します。
宛先のユーザーが受信を拒否している場合や、ログインしていない場合は、453失敗応答を返します。
XSEM -- 送信し、できなければメールします。
メッセージをSENDできない場合は、009通知応答を返します。
XMAS -- メールして送信します。（これはやらずにはいられませんでした）
特有の応答はありません。

Note that for XSEM and XMAS, it is the mailing which determines success, not the SENDing, although XSEM as implemented uses a 009 reply (in addition to the normal success/failure code) to indicate that because the SEND failed, an attempt is being made to mail the message instead. There are no corresponding variants for MLFL, since messages transmitted in this way are generally short, and neither I nor Brian Harvey (implementing respectively the ITS and SAIL servers) wanted to bother.

XSEMとXMASでは、成功かどうかを決めるのはSENDではなくメールであることに注意してください。ただし、実装されているXSEMでは、SENDに失敗したので代わりにメッセージをメールしようとしていることを示すために、（通常の成功・失敗コードに加えて）009応答を使います。MLFLに対応する変種はありません。この方法で送られるメッセージは一般に短いうえ、私も（それぞれITSとSAILのサーバーを実装した）Brian Harveyも、わざわざ手間をかける気にならなかったからです。
