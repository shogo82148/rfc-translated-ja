RFC 4109

Algorithms for Internet Key Exchange version 1 (IKEv1)

RFC 4109

インターネット鍵交換バージョン1（IKEv1）のためのアルゴリズム

Abstract

概要

The required and suggested algorithms in the original Internet Key Exchange version 1 (IKEv1) specification do not reflect the current reality of the IPsec market requirements. The original specification allows weak security and suggests algorithms that are thinly implemented. This document updates RFC 2409, the original specification, and is intended for all IKEv1 implementations deployed today.

元のインターネット鍵交換バージョン1（IKEv1）の仕様で必須とされているアルゴリズムや推奨されているアルゴリズムは、IPsec市場の要件の現状を反映していません。元の仕様は弱いセキュリティーを許容しており、ほとんど実装されていないアルゴリズムを推奨しています。この文書は、元の仕様であるRFC 2409を更新するもので、現在配備されているすべてのIKEv1実装を対象としています。

Status of This Memo

このメモのステータス

This document specifies an Internet standards track protocol for the Internet community, and requests discussion and suggestions for improvements. Please refer to the current edition of the "Internet Official Protocol Standards" (STD 1) for the standardization state and status of this protocol. Distribution of this memo is unlimited.

この文書は、インターネットコミュニティーのためのインターネット標準化過程（Internet Standards Track）のプロトコルを規定し、改善のための議論と提案を求めるものです。このプロトコルの標準化の状態とステータスについては、「Internet Official Protocol Standards」（STD 1）の最新版を参照してください。このメモの配布は無制限です。

1. Introduction

1. はじめに

The original IKEv1 definition, [RFC2409], has a set of MUST-level and SHOULD-level requirements that do not match the needs of IPsec users. This document updates RFC 2409 by changing the algorithm requirements defined there.

元のIKEv1の定義[RFC2409]には、IPsecのユーザーのニーズに合わないしなければなりません（MUST）レベルとすべきです（SHOULD）レベルの一連の要件があります。この文書は、RFC 2409で定義されたアルゴリズムの要件を変更することによって、RFC 2409を更新します。

The keywords MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, MAY, and OPTIONAL, when they appear in this document, are to be interpreted as described in [RFC2119].

この文書に現れるキーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、「要求されています（REQUIRED）」、「することになります（SHALL）」、「することはありません（SHALL NOT）」、「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、「推奨されます（RECOMMENDED）」、「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、[RFC2119]に記載されているとおりに解釈されるものとします。

2. Old Algorithm Requirements

2. 従来のアルゴリズムの要件

RFC 2409 has the following MUST-level and SHOULD-level requirements:

RFC 2409には、しなければなりません（MUST）レベルとすべきです（SHOULD）レベルの要件として次のものがあります。

  • DES for encryption MUST be supported.
  • MD5 and SHA-1 for hashing and HMAC functions MUST be supported.
  • Pre-shared secrets for authentication MUST be supported.
  • Diffie-Hellman MODP group 1 (discrete log 768 bits) MUST be supported.
  • TripleDES for encryption SHOULD be supported.
  • Tiger for hashing SHOULD be supported.
  • DSA and RSA for authentication with signatures SHOULD be supported.
  • RSA for authentication with encryption SHOULD be supported.
  • Diffie-Hellman MODP group 2 (discrete log 1024 bits) SHOULD be supported.
  • 暗号化用のDESをサポートしなければなりません（MUST）。
  • ハッシュとHMAC関数用のMD5とSHA-1をサポートしなければなりません（MUST）。
  • 認証用の事前共有秘密をサポートしなければなりません（MUST）。
  • Diffie-HellmanのMODPグループ1（離散対数768ビット）をサポートしなければなりません（MUST）。
  • 暗号化用のTripleDESをサポートすべきです（SHOULD）。
  • ハッシュ用のTigerをサポートすべきです（SHOULD）。
  • 署名による認証用のDSAとRSAをサポートすべきです（SHOULD）。
  • 暗号化による認証用のRSAをサポートすべきです（SHOULD）。
  • Diffie-HellmanのMODPグループ2（離散対数1024ビット）をサポートすべきです（SHOULD）。

RFC 2409 gives two conflicting requirement levels for Diffie-Hellman MODP groups with elliptic curves. Section 4 of that specification says that "IKE implementations ... MAY support ECP and EC2N groups", but Sections 6.3 and 6.4 say that MODP groups 3 and 4 for EC2N groups SHOULD be supported.

RFC 2409は、楕円曲線を使うDiffie-HellmanのMODPグループについて、矛盾する2つの要件レベルを示しています。この仕様のセクション4には「IKEの実装は、ECPグループとEC2Nグループをサポート……してもよいです（MAY）」とありますが、セクション6.3と6.4には、EC2NグループのためのMODPグループ3と4をサポートすべきです（SHOULD）とあります。

3. New Algorithm Requirements

3. 新しいアルゴリズムの要件

The new requirements for IKEv1 are listed here. Note that some of the requirements are the same as those in RFC 2409, whereas others are changed.

IKEv1の新しい要件をここに挙げます。要件の一部はRFC 2409と同じですが、ほかは変更されていることに注意してください。

  • TripleDES for encryption MUST be supported.
  • AES-128 in CBC mode [RFC3602] for encryption SHOULD be supported.
  • SHA-1 for hashing and HMAC functions MUST be supported.
  • Pre-shared secrets for authentication MUST be supported.
  • AES-128 in XCBC mode for PRF functions ([RFC3566] and [RFC3664]) SHOULD be supported.
  • Diffie-Hellman MODP group 2 (discrete log 1024 bits) MUST be supported.
  • Diffie-Hellman MODP group 14 (discrete log 2048 bits) [RFC3526] SHOULD be supported.
  • RSA for authentication with signatures SHOULD be supported.
  • 暗号化用のTripleDESをサポートしなければなりません（MUST）。
  • 暗号化用のCBCモードのAES-128[RFC3602]をサポートすべきです（SHOULD）。
  • ハッシュとHMAC関数用のSHA-1をサポートしなければなりません（MUST）。
  • 認証用の事前共有秘密をサポートしなければなりません（MUST）。
  • PRF関数用のXCBCモードのAES-128（[RFC3566]と[RFC3664]）をサポートすべきです（SHOULD）。
  • Diffie-HellmanのMODPグループ2（離散対数1024ビット）をサポートしなければなりません（MUST）。
  • Diffie-HellmanのMODPグループ14（離散対数2048ビット）[RFC3526]をサポートすべきです（SHOULD）。
  • 署名による認証用のRSAをサポートすべきです（SHOULD）。

If additional updates are made to IKEv1 in the future, then it is very likely that implementation of AES-128 in CBC mode for encryption will become mandatory.

将来、IKEv1にさらに更新が加えられる場合、暗号化用のCBCモードのAES-128の実装が必須になる可能性が非常に高いです。

The other algorithms that were listed at MUST-level and SHOULD-level in RFC 2409 are now MAY-level. This includes DES for encryption, MD5 and Tiger for hashing, Diffie-Hellman MODP group 1, Diffie-Hellman MODP groups with elliptic curves, DSA for authentication with signatures, and RSA for authentication with encryption.

RFC 2409でしなければなりません（MUST）レベルとすべきです（SHOULD）レベルとして挙げられていたその他のアルゴリズムは、現在ではしてもよいです（MAY）レベルです。これには、暗号化用のDES、ハッシュ用のMD5とTiger、Diffie-HellmanのMODPグループ1、楕円曲線を使うDiffie-HellmanのMODPグループ、署名による認証用のDSA、暗号化による認証用のRSAが含まれます。

DES for encryption, MD5 for hashing, and Diffie-Hellman MODP group 1 are dropped to MAY due to cryptographic weakness.

暗号化用のDES、ハッシュ用のMD5、Diffie-HellmanのMODPグループ1は、暗号学的な弱さのためしてもよいです（MAY）に格下げされています。

Tiger for hashing, Diffie-Hellman MODP groups with elliptic curves, DSA for authentication with signatures, and RSA for authentication with encryption are dropped due to lack of any significant deployment and interoperability.

ハッシュ用のTiger、楕円曲線を使うDiffie-HellmanのMODPグループ、署名による認証用のDSA、暗号化による認証用のRSAは、目立った配備も相互運用性もないため格下げされています。

5. Security Considerations

5. セキュリティーに関する考慮事項

This document is all about security. All the algorithms that are either MUST-level or SHOULD-level in the "new algorithm requirements" section of this document are believed to be robust and secure at the time of this writing.

この文書は、全体がセキュリティーに関するものです。この文書の「新しいアルゴリズムの要件」のセクションでしなければなりません（MUST）レベルまたはすべきです（SHOULD）レベルとしたアルゴリズムはすべて、この文書の執筆時点で堅牢かつ安全であると考えられています。
