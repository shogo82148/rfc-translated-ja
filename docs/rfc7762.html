RFC 7762

Initial Assignment for the Content Security Policy Directives Registry

RFC 7762

Content Security Policyディレクティブレジストリーの初期割り当て

Abstract

概要

This document establishes an Internet Assigned Number Authority (IANA) registry for Content Security Policy directives and populates that registry with the directives defined in the Content Security Policy Level 2 specification.

この文書は、Content Security Policyのディレクティブのためのインターネット番号割当機関（IANA）レジストリーを設立し、Content Security Policy Level 2仕様で定義されたディレクティブをそのレジストリーに登録します。

1. Introduction

1. はじめに

The Content Security Policy (CSP) specification [CSP] defines a mechanism that web developers can use to control the resources that a particular page can fetch or execute, as well as a number of additional security-relevant policy decisions.

Content Security Policy（CSP）仕様[CSP]は、特定のページが取得または実行できるリソースを制御するためにウェブ開発者が使える仕組みと、セキュリティーに関連するその他の多くのポリシー判断を定義しています。

The policy language specified in that document consists of an extensible set of "directives", each of which controls a specific resource type or policy decision. This specification establishes a registry to ensure that extensions to CSP are listed and standardized.

その文書で規定されたポリシー言語は、拡張可能な「ディレクティブ」の集合で構成され、各ディレクティブは特定のリソースの種類またはポリシー判断を制御します。この仕様は、CSPの拡張が確実に一覧化され標準化されるように、レジストリーを設立します。

2. Terminology

2. 用語

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in [RFC2119].

キーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、「要求されています（REQUIRED）」、「することになります（SHALL）」、「することはありません（SHALL NOT）」、「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、「推奨されます（RECOMMENDED）」、「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、[RFC2119]に記載されているとおりに解釈されるものとします。

3. Use of the Registry

3. レジストリーの使用

Content Security Policy directives must be documented in a readily available public specification in order to be registered by IANA. This documentation MUST fully explain the syntax, intended usage, and semantics of the directive. The intent of this requirement is to assure interoperable independent implementations, and to prevent accidental namespace collisions between implementations of dissimilar features.

Content Security Policyのディレクティブは、IANAに登録されるために、容易に入手可能な公開仕様に文書化されている必要があります。この文書は、ディレクティブの構文、意図された使用法、およびセマンティクスを完全に説明しなければなりません（MUST）。この要件の意図は、相互運用可能な独立した実装を保証し、異なる機能の実装間で偶発的に名前空間が衝突するのを防ぐことです。

Documents defining new Content Security Policy directives MUST register them with IANA, as described in Section 3. The IANA registration policy for such parameters is "Specification Required" [RFC5226] and is further discussed in Section 3.2.

新しいContent Security Policyディレクティブを定義する文書は、セクション3で説明しているとおり、それらをIANAに登録しなければなりません（MUST）。そのようなパラメーターに対するIANAの登録ポリシーは「Specification Required」[RFC5226]であり、セクション3.2でさらに説明します。

4. IANA Considerations

4. IANAに関する考慮事項

This specification creates a new top-level IANA registry named "Content Security Policy Directives".

この仕様は、「Content Security Policy Directives」という名前の新しいトップレベルのIANAレジストリーを作成します。

4.1. Content Security Policy Directives Registry

4.1. Content Security Policy Directivesレジストリー

New Content Security Policy directives, and updates to existing directives, MUST be registered with IANA.

新しいContent Security Policyディレクティブ、および既存のディレクティブの更新は、IANAに登録しなければなりません（MUST）。

When registering a new Content Security Policy directive, the following information MUST be provided:

新しいContent Security Policyディレクティブを登録する際には、次の情報を提供しなければなりません（MUST）。

  • The directive's name, an ASCII string conforming to the "directive-name" rule specified in Section 4.1 of [CSP]. The ABNF [RFC5234] is as follows:

        directive-name  = 1*( ALPHA / DIGIT / "-" )
  • A reference to the readily available public specification defining the new directive's syntax, usage, and semantics.

  • ディレクティブの名前。これは、[CSP]のセクション4.1で規定された「directive-name」規則に適合するASCII文字列です。ABNF[RFC5234]は次のとおりです。

        directive-name  = 1*( ALPHA / DIGIT / "-" )
  • 新しいディレクティブの構文、使用法、およびセマンティクスを定義する、容易に入手可能な公開仕様への参照。

4.2. Registration Policy for Content Security Policy Directives

4.2. Content Security Policyディレクティブの登録ポリシー

The registration policy for Content Security Policy directives is "Specification Required" [RFC5226], which uses a designated expert to review the specification.

Content Security Policyディレクティブの登録ポリシーは「Specification Required」[RFC5226]であり、指定専門家が仕様をレビューします。

When appointing an Expert (or Experts), the IESG SHOULD draw from the W3C's security community, coordinating through the liaison.

専門家を任命する際、IESGはリエゾンを通じて調整し、W3Cのセキュリティーコミュニティーから選出すべきです（SHOULD）。

The designated expert, when deliberating on whether to include a new directive in the registry, SHOULD consider the following criteria. This is not an exhaustive list, but representative of the issues to consider when rendering a decision:

指定専門家は、新しいディレクティブをレジストリーに含めるかどうかを審議する際に、次の基準を考慮すべきです（SHOULD）。これは網羅的な一覧ではなく、判断を下す際に考慮すべき問題の代表例です。

  • Content Security Policy is a restrictive feature, which allows web developers to deny themselves access to resources and APIs that would otherwise be available. Deploying Content Security Policy is, therefore, a strict reduction in risk. The expert SHOULD carefully consider whether proposed directives would violate this property.
  • Granular directives are valuable, but the expert SHOULD strive to strike a reasonable balance between providing developers with all the knobs and switches possible and providing only those with known security implications.
  • Content Security Policyは制限的な機能であり、ウェブ開発者は、本来なら利用できるリソースやAPIへのアクセスを自ら拒否できます。したがって、Content Security Policyを導入することは、リスクを厳密に低減することになります。専門家は、提案されたディレクティブがこの性質に反しないかどうかを慎重に検討すべきです（SHOULD）。
  • きめ細かいディレクティブには価値がありますが、専門家は、可能なすべてのつまみやスイッチを開発者に提供することと、セキュリティー上の影響がわかっているものだけを提供することとの間で、合理的なバランスをとるよう努めるべきです（SHOULD）。

5. Security Considerations

5. セキュリティーに関する考慮事項

The registry in this document does not in itself have security implications. The directives specified, however, certainly do. The documents referenced when registering new directives MUST contain detailed security and privacy considerations sections, and SHOULD contain usage information that informs web developers as to the directive's expected implementation.

この文書のレジストリー自体には、セキュリティー上の影響はありません。しかし、規定されるディレクティブには確実に影響があります。新しいディレクティブを登録する際に参照される文書には、詳細なセキュリティーおよびプライバシーに関する考慮事項のセクションを含めなければなりません（MUST）。また、ディレクティブに期待される実装についてウェブ開発者に知らせる使用法の情報を含めるべきです（SHOULD）。
