RFC 1074

NSFNET Backbone SPF based Interior Gateway Protocol

RFC 1074

NSFNETバックボーンのSPFに基づく内部ゲートウェイプロトコル

Status of This Memo

このメモのステータス

This memo is an implementation description of the standard ANSI IS-IS and ISO ES-IS routing protocols within the NSFNET backbone network. Distribution of this memo is unlimited.

このメモは、NSFNETバックボーンネットワークにおける標準のANSI IS-ISおよびISO ES-ISルーティングプロトコルの実装について説明するものです。 このメモの配布は無制限です。

謝辞

この文書への貢献に対して、Hans-Werner Braun（MERIT）に感謝の意を表します。

1. Overview

1. 概要

This document provides an overview of the NSFNET Backbone routing with specific emphasis on the intra-backbone routing.

この文書は、NSFNETバックボーンのルーティングについて、特にバックボーン内部のルーティングに重点を置いて概要を示します。

By the end of 1987, the American National Standardization Institute (ANSI) forwarded a specification for an Intermediate System to Intermediate System routing protocol to the International Standardization Organizations (ISO) for the adaptation as an international standard. This ANSI IS-IS protocol is used as the interior gateway protocol (IGP) of the NSFNET backbone. Documented here is an implementation description which also includes further definitions that were necessary for the integration into an Internet Protocol (IP) environment. Therefore, it should be viewed as a continuation of the specifications of the ANSI IS-IS protocol [1] and the ISO standard End System to Intermediate System (ES-IS) protocol [2]. While the ANSI IS-IS protocol suffices as an IGP, additional methods are used to orchestrate routing between the backbone and the attached mid-level networks; most notably the Exterior Gateway Protocol (EGP). Further information about the overall NSFNET routing as well as some future aspects can be found in [3], [4], [5] and [6].

1987年末までに、米国規格協会（ANSI）は、中間システム間（Intermediate System to Intermediate System）ルーティングプロトコルの仕様を、国際標準として採用してもらうために国際標準化機構（ISO）に送付しました。 このANSI IS-ISプロトコルは、NSFNETバックボーンの内部ゲートウェイプロトコル（IGP）として使われています。 ここに記述するのは実装の説明であり、インターネットプロトコル（IP）環境に統合するために必要だった追加の定義も含んでいます。 したがって、この文書は、ANSI IS-ISプロトコル[1]とISO標準のエンドシステム・中間システム間（ES-IS）プロトコル[2]の仕様の続きとして見るべきです。 ANSI IS-ISプロトコルはIGPとしては十分ですが、バックボーンと接続された中間レベルのネットワークとの間のルーティングを調整するために、追加の方法が使われています。その最たるものが外部ゲートウェイプロトコル（EGP）です。 NSFNETのルーティング全体と、今後の側面のいくつかに関する詳しい情報は、[3]、[4]、[5]、[6]にあります。

2. A brief overview of the NSFNET backbone

2. NSFNETバックボーンの簡単な概要

The NSFNET backbone is a wide area network which currently connects thirteen sites within the continental United States. All connections are permanent point-to-point links at T1 speed (1.544Mbps). These T1 links may contain multiple logical links at sub-T1 and up to the full T1 speed. The result is a hybrid circuit/packet switching network able to contain a connectivity-richer logical topology than the underlying physical topology would allow by itself. Each site has a Nodal Switching Subsystem (NSS) which is responsible for packet switching. Each NSS is a RISC technology based multiprocessor system using IBM RT/PC processors which operate a modified version of a 4.3BSD kernel. For the purpose of routing, each NSS is considered as a single entity which has connections to both other NSS (via the logical network infrastructure) and to regional networks (via local area network attachments; typically an Ethernet).

NSFNETバックボーンは、現在、米国本土内の13のサイトを接続している広域ネットワークです。 すべての接続は、T1速度（1.544Mbps）の常設のポイントツーポイントリンクです。 これらのT1リンクには、T1未満から最大でT1の全速度までの複数の論理リンクが含まれる場合があります。 その結果、下位の物理トポロジーだけで可能になるよりも接続性の豊かな論理トポロジーを収容できる、回線交換とパケット交換のハイブリッドネットワークになっています。 各サイトには、パケット交換を担うノード交換サブシステム（NSS）があります。 各NSSは、4.3BSDカーネルの改変版を動作させるIBM RT/PCプロセッサーを使った、RISC技術に基づくマルチプロセッサーシステムです。 ルーティングの目的上、各NSSは、ほかのNSSへの接続（論理ネットワーク基盤経由）と地域ネットワークへの接続（ローカルエリアネットワークへの接続経由。通常はイーサネット）の両方を持つ単一の実体とみなされます。

The routing protocol which is used for the inter-NSS routing within the NSFNET backbone is an adaptation of the ANSI IS-IS routing protocol [1]. The routing protocol which is used between the backbone and the attached mid-level networks is the Exterior Gateway Protocol (EGP) [3]. The information exchange between the backbone and its connected EGP peers is subject to policy based routing restrictions which are maintained in the Policy Based Routing Database [4], [5].

NSFNETバックボーン内のNSS間のルーティングに使われるルーティングプロトコルは、ANSI IS-ISルーティングプロトコル[1]を適合させたものです。 バックボーンと接続された中間レベルのネットワークとの間で使われるルーティングプロトコルは、外部ゲートウェイプロトコル（EGP）[3]です。 バックボーンと、それに接続されたEGPピアとの間の情報交換は、ポリシーに基づくルーティングの制約の対象となります。この制約は、ポリシーに基づくルーティングデータベース[4]、[5]で管理されています。

3. An overview of the ANSI IS-IS routing document

3. ANSI IS-ISルーティング文書の概要

The ANSI IS-IS routing protocol specifies a two level hierarchical routing where Level 1 routing deals with routing within an area, while Level 2 routing deals with routing between different areas.

ANSI IS-ISルーティングプロトコルは、2レベルの階層型ルーティングを規定しています。レベル1ルーティングはエリア内のルーティングを扱い、レベル2ルーティングは異なるエリア間のルーティングを扱います。

This routing protocol belongs to a class of so called "Link State" protocols where each node maintains a complete topology of the whole network. The route computation is based on a modified version of Dijkstra's Shortest Path First (SPF) algorithm.

このルーティングプロトコルは、各ノードがネットワーク全体の完全なトポロジーを保持する、いわゆる「リンクステート」プロトコルの部類に属します。 経路計算は、ダイクストラの最短経路優先（SPF）アルゴリズムの改変版に基づいています。

Both Level 1 and Level 2 routing use two types of Protocol Data Units (PDU):

レベル1ルーティングとレベル2ルーティングはどちらも、2種類のプロトコルデータユニット（PDU）を使います。

  • The Level 1 Router Link PDU lists IS neighbors. The Level 1 End System PDU lists ES neighbors.
  • The Level 2 Router Link PDU lists neighbor Level 2 routes. The Level 2 End System PDU lists address prefixes for systems in other Routing Domains.
  • レベル1ルーターリンクPDUは、ISの隣接ノードを列挙します。 レベル1エンドシステムPDUは、ESの隣接ノードを列挙します。
  • レベル2ルーターリンクPDUは、隣接するレベル2の経路を列挙します。 レベル2エンドシステムPDUは、ほかのルーティングドメインにあるシステムのアドレスプレフィックスを列挙します。

The ANSI IS-IS document separates subnetwork independent functions from the subnetwork dependent functions. Subnetwork independent functions include dissemination of Router Link and End System Link PDU's and the Routing Algorithm. The subnetwork dependent functions cover different types of subnets such as X.25, permanent point-to- point links and LANs.

ANSI IS-ISの文書は、サブネットワークに依存しない機能とサブネットワークに依存する機能とを分けています。 サブネットワークに依存しない機能には、ルーターリンクPDUとエンドシステムリンクPDUの配布や、ルーティングアルゴリズムが含まれます。 サブネットワークに依存する機能は、X.25、常設のポイントツーポイントリンク、LANなど、さまざまな種類のサブネットを対象とします。

The IS-IS Protocol is designed to interoperate with the End System to Intermediate System (ES-IS) routing exchange protocol [2]. The ES-IS protocol is used to determine connectivity and network layer addresses. This information is used to construct the Router Link PDUs.

IS-ISプロトコルは、エンドシステム・中間システム間（ES-IS）ルーティング交換プロトコル[2]と相互運用するように設計されています。 ES-ISプロトコルは、接続性とネットワーク層アドレスを判断するために使われます。 この情報は、ルーターリンクPDUを構築するために使われます。

4. How the ANSI IS-IS protocol is adapted for the NSFNET backbone routing

4. ANSI IS-ISプロトコルをNSFNETバックボーンのルーティングに適合させる方法

The NSFNET backbone implements a subset of the ANSI IS-IS protocol. With respect to subnetwork independent functions, it only supports Level 2 routing. With respect to subnetwork dependent functions, it only supports general topology subnetworks with permanent point-to- point links. Since the ANSI IS-IS protocol is designed for ISO Network Service Access Point (NSAP) addresses, there is a need to encapsulate IP addresses into NSAP addresses.

NSFNETバックボーンは、ANSI IS-ISプロトコルのサブセットを実装しています。 サブネットワークに依存しない機能については、レベル2ルーティングだけをサポートしています。 サブネットワークに依存する機能については、常設のポイントツーポイントリンクを持つ一般トポロジーのサブネットワークだけをサポートしています。 ANSI IS-ISプロトコルはISOのネットワークサービスアクセスポイント（NSAP）アドレス用に設計されているため、IPアドレスをNSAPアドレスにカプセル化する必要があります。

For this, the Initial Domain Part (IDP) is unused. The Domain Specific Part (DSP) includes nine bytes which are partitioned as follows:

そのために、初期ドメイン部（IDP）は使用しません。 ドメイン固有部（DSP）は9バイトからなり、次のように分割されます。

  • 2 bytes - administrative domain
  • 2 bytes - empty
  • 4 bytes - IP address
  • 1 byte - empty
  • 2バイト - 管理ドメイン
  • 2バイト - 空
  • 4バイト - IPアドレス
  • 1バイト - 空

In the ANSI IS-IS protocol, each router has its own identifier (ID) which is 6 bytes long. For the NSFNET implementation, the first 2 bytes of the ID are empty and the last four bytes include the IP address of a particular router.

ANSI IS-ISプロトコルでは、各ルーターは6バイト長の独自の識別子（ID）を持ちます。 NSFNETの実装では、IDの最初の2バイトは空で、最後の4バイトにはその特定のルーターのIPアドレスが入ります。

The NSFNET backbone PDUs (both IS-IS and IS-ES) are transmitted as a protocol on top of IP, with "85" being the assigned protocol number for this purpose. The IS-IS PDUs are distinguished from the IS-ES PDUs by the Protocol Discriminator Field within the PDUs. The IP fragmentation/reassembly mechanism provides support for transmission of up to 64 kilobytes in a single IP packet. Within the backbone, it is highly unlikely that the size of IS-IS PDUs will exceed this limit. Therefore, no IS-IS fragmentation/reassembly is implemented for this environment. This is different from the ISO framework where the ISIS is located directly on top of the Data Link Layer.

NSFNETバックボーンのPDU（IS-ISとIS-ESの両方）は、IP上のプロトコルとして送信され、そのために割り当てられたプロトコル番号は「85」です。 IS-IS PDUとIS-ES PDUは、PDU内のプロトコル識別子フィールドによって区別されます。 IPのフラグメンテーション／再組み立ての仕組みにより、単一のIPパケットで最大64キロバイトまで送信できます。 バックボーン内では、IS-IS PDUのサイズがこの上限を超えることはまずありません。 そのため、この環境ではIS-ISのフラグメンテーション／再組み立ては実装していません。 これは、ISISがデータリンク層の直上に位置するISOの枠組みとは異なります。

For the purpose of the NSFNET Backbone routing, each Autonomous System (AS) is treated as a separate Administrative Domain (AD). The list of administrative domains (as obtained via EGP and filtered through the Policy Based Routing Database) which are connected directly to a particular NSS is distributed in the set of the partitionAreaAddresses part of the Level 2 Router Links PDU. Each area address is 5 bytes long and consists of 3 empty bytes (IDP) followed by 2 bytes of the Administrative Domain.

NSFNETバックボーンのルーティングの目的上、各自律システム（AS）は、別々の管理ドメイン（AD）として扱われます。 特定のNSSに直接接続されている管理ドメインのリスト（EGPで取得し、ポリシーに基づくルーティングデータベースでフィルタリングしたもの）は、レベル2ルーターリンクPDUのpartitionAreaAddresses部の集合に入れて配布されます。 各エリアアドレスは5バイト長で、3バイトの空のバイト（IDP）とそれに続く2バイトの管理ドメインからなります。

The reachability information obtained from regional networks via EGP is distributed within the backbone by End System PDUs. In order to support multi-domain topologies, the ANSI IS-IS protocol allows for a set of Address Prefixes to be entered by the System Management at the boundary IS. In the NSFNET Backbone, these Address Prefixes are obtained via the Exterior Gateway Protocol. For each network listed in EGP NR packets which is received from an EGP peer, the network and administrative domain number of the EGP peer are encapsulated into NSAP addresses (as described above). A complete NSAP address is used as an address prefix in the reachable address prefix neighbor part of the End System PDU. The cost field in the reachable address prefix neighbor part of the End System PDU is derived from the Policy Based Routing Database maintained in each NSS.

EGPを介して地域ネットワークから得た到達可能性情報は、エンドシステムPDUによってバックボーン内に配布されます。 複数ドメインのトポロジーをサポートするために、ANSI IS-ISプロトコルでは、境界ISでシステム管理がアドレスプレフィックスの集合を入力できるようになっています。 NSFNETバックボーンでは、これらのアドレスプレフィックスは外部ゲートウェイプロトコルを介して取得されます。 EGPピアから受信したEGP NRパケットに列挙されている各ネットワークについて、そのネットワークとEGPピアの管理ドメイン番号を（上で説明したように）NSAPアドレスにカプセル化します。 完全なNSAPアドレスは、エンドシステムPDUの到達可能なアドレスプレフィックス隣接部でアドレスプレフィックスとして使われます。 エンドシステムPDUの到達可能なアドレスプレフィックス隣接部にあるコストフィールドは、各NSSで管理されているポリシーに基づくルーティングデータベースから導出されます。

At each NSS, the reachability information obtained from other nodes (via their End System PDU's) is passed on to the mid-level network EGP peers, following the appropriate processing and filtering according to the Policy Based Routing Database.

各NSSでは、ほかのノードから（そのエンドシステムPDUを介して）得た到達可能性情報を、ポリシーに基づくルーティングデータベースに従って適切な処理とフィルタリングを行ったうえで、中間レベルのネットワークのEGPピアに渡します。

The Network Entity Title (NET) (which is used in the IS-ES protocol) is eleven bytes long and is constructed by first encapsulating an IP address into a NSAP address, then taking the first 11 bytes of this address as a NET.

（IS-ESプロトコルで使われる）ネットワークエンティティタイトル（NET）は11バイト長で、まずIPアドレスをNSAPアドレスにカプセル化し、次にこのアドレスの最初の11バイトをNETとして取り出すことで構築されます。

5. Current timer parameters

5. 現在のタイマーパラメーター

The following timer parameters are currently implemented:

現在、次のタイマーパラメーターが実装されています。

  • Hello Interval (IS-ES Hello): 10 seconds
  • Hold Time (ES-IS protocol): 40 seconds
  • Other timer parameters for the IS-IS protocol are taken from the section 6.3.7 of [1].
  • Hello間隔（IS-ES Hello）：10秒
  • 保持時間（ES-ISプロトコル）：40秒
  • IS-ISプロトコルのその他のタイマーパラメーターは、[1]のセクション6.3.7から引用しています。
