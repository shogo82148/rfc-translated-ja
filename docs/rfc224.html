RFC 224

Comments on Mailbox Protocol

RFC 224

メールボックスプロトコルについてのコメント

Abstract

概要

It should be noted that the Terminal IMP will be unable to directly implement the currently-proposed mailbox protocol for the following reasons:

次の理由により、Terminal IMPは現在提案されているメールボックスプロトコルを直接実装できないことに留意してください。

  1. The Terminal IMP is completely incapable of storing incoming messages for later printing or display.
  2. The Terminal IMP is not expected to be able to perform as the "server" portion of any connection.
  3. The Terminal IMP cannot provide programs for the processing of a variety of types of input streams. It currently supports the TELNET protocol, and is expected to support at least one mode of Data Transfer Protocol in the future. It is _not_ likely to support the File Transfer Protocol. Furthermore, when using the Data Transfer Protocol it will not perform any transformations on the data stream (e.g., interpretation of line printer form-control "characters," translation from one character set to another, etc.). It will be up to the "other end" of the connection to set up and decode messages based on the terminal type.
  1. Terminal IMPには、受信したメッセージを後で印刷したり表示したりするために保存する能力がまったくありません。
  2. Terminal IMPが、いずれかのコネクションの「サーバー」側として動作できることは期待されていません。
  3. Terminal IMPは、さまざまな種類の入力ストリームを処理するプログラムを提供できません。現在はTELNETプロトコルをサポートしており、将来はData Transfer Protocolの少なくとも1つのモードをサポートする見込みです。File Transfer Protocolをサポートする可能性は_ありません_。さらに、Data Transfer Protocolを使う場合も、データストリームに対して何の変換（たとえば、ラインプリンターの書式制御「文字」の解釈や、ある文字セットから別の文字セットへの変換など）も行いません。端末の種類に基づいてメッセージを組み立てたり解読したりするのは、コネクションの「相手側」の役目になります。

Although these limitations preclude Terminal IMPs from participating in the currently-proposed mailbox protocol, this should not be considered an objection to implementation of the protocol, provided that Terminal IMP installations will be guaranteed the right to "rent" mailboxes at some larger Host site [the NIC is probably a good candidate]. With this capability, a message destined for a Terminal IMP user would be shipped to the site of the "rented" mailbox according to protocol and stored there. A terminal IMP user could then periodically log in to that site (under TELNET protocol) and examine the contents of the mailbox; since the "examination" would be carried out over a TELNET connection the Host containing the mailbox would _automatically_ perform the necessary transformation of the data before transmitting it to the Terminal IMP.

これらの制限により、Terminal IMPは現在提案されているメールボックスプロトコルに参加できませんが、Terminal IMPの設置サイトが、どこかの大規模なホストのサイト[おそらくNICが良い候補です]でメールボックスを「借りる」権利を保証されるのであれば、このことをプロトコルの実装に対する異議と考えるべきではありません。この機能があれば、Terminal IMPのユーザー宛てのメッセージは、プロトコルに従って「借りた」メールボックスのあるサイトへ送られ、そこに保存されます。Terminal IMPのユーザーは、定期的にそのサイトに（TELNETプロトコルで）ログインし、メールボックスの内容を調べることができます。この「調べる」作業はTELNETコネクション上で行われるので、メールボックスを持つホストは、Terminal IMPへ送信する前に必要なデータの変換を_自動的に_行います。

A technically unattractive alternative to this scheme would be to _require_ each Terminal IMP site to have a printer dedicated to the mailbox function. If the mail were then transferred in TELNET format, we could probably provide a socket connected to the dedicated printer for receipt of mail. Obviously, if this scheme were chosen, a Terminal IMP could accept mail from only one sender at a time, and the transmission rate would be limited to the speed of the printer. Furthermore, a single central mailbox printer is likely to provide poor service to Terminal IMPs with widely scattered terminals (e.g., dial-in terminals distributed over an area with a 10-mile radius).

この方式に代わる、技術的に魅力のない方法としては、各Terminal IMPサイトにメールボックス機能専用のプリンターを置くことを_必須にする_ことが考えられます。そのうえでメールをTELNET形式で転送すれば、メールを受信するために、その専用プリンターにつながったソケットを用意できるでしょう。当然ながら、この方式を選んだ場合、Terminal IMPは一度に1つの送信者からしかメールを受け付けられず、伝送速度はプリンターの速度に制限されます。さらに、中央に1台だけ置いたメールボックス用プリンターでは、端末が広く散らばっているTerminal IMP（たとえば、半径10マイルの範囲に分散したダイヤルイン端末）に対して、十分なサービスを提供できない可能性が高くなります。

We feel that, in addition to other arguments, it would be more cost-effective to provide storage for rented mailboxes at one site than to provide a _special_ mailbox printer at each Terminal IMP site.

ほかの論点に加えて、各Terminal IMPサイトに_特別な_メールボックス用プリンターを用意するよりも、1つのサイトで貸し出し用メールボックスのための記憶領域を用意するほうが費用対効果が高いと考えます。
