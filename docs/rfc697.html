RFC 697

CWD Command of FTP

RFC 697

FTPのCWDコマンド

Introduction

はじめに

The Tenex file system support a "files only" directory. This type of directory cannot be "logged in" but it can be "connected to". A login gives directory "owner" access to the job generated by the system and an address space in which the user can execute programs. A connect allows an existing job and its associated user "owner" access to a directory but creates no address space. The words "owner", "group", and "universal" or "public" determine which field of the protection specification is to be used to check the legality of a file access request.

Tenexのファイルシステムは「ファイル専用（files only）」ディレクトリーをサポートしています。この種類のディレクトリーには「ログイン（logged in）」できませんが、「接続（connected to）」はできます。ログインすると、システムが生成したジョブにディレクトリーへの「所有者（owner）」アクセスが与えられ、ユーザーがプログラムを実行できるアドレス空間も与えられます。接続では、既存のジョブとそれに関連付けられたユーザーにディレクトリーへの「所有者」アクセスが与えられますが、アドレス空間は作成されません。「所有者（owner）」「グループ（group）」「全体（universal）」または「公開（public）」という語によって、ファイルアクセス要求が正当かどうかを検査するために保護指定のどのフィールドを使うかが決まります。

Problem

問題

The Tenex FTP server does not allow an FTP Login to a "files only" directory. The current protocol contains the CWD (Change Working Directory) command which gets part of the "connect" functions but it does not grant "owner" access to the user. Therefore, there is no way a user can access a "files only" directory as the "owner" (i.e. he can supply the password). This is undesirable for private directories of this type since it is uneconomical to define a user - directory "group" for so few directories and unrestricted "public" access may be undesirable.

TenexのFTPサーバーは、「ファイル専用」ディレクトリーへのFTPログインを許可していません。現在のプロトコルにはCWD（Change Working Directory）コマンドがあり、これで「接続」機能の一部は得られますが、ユーザーに「所有者」アクセスは与えられません。そのため、ユーザーが「ファイル専用」ディレクトリーに「所有者」として（つまり、パスワードを提示できる者として）アクセスする方法はありません。この種類の私的なディレクトリーにとって、これは望ましくありません。こうした少数のディレクトリーのためにユーザーとディレクトリーの「グループ」を定義するのは割に合いませんし、制限のない「公開」アクセスは望ましくないかもしれないからです。

Solution

解決策

There are two approach we can take. Either we remove the distinction "files only" from the FTP login, or we create a command that does the "connect" function. The restriction placed on "files only" directories is based on how we define a user of FTP to the server. If we say that any net user who knows the password to a directory has ownership of that directory as far as FTP is concerned, then we have a solution. If we want an FTP login to be as restrictive as a user login, then we need the second alternative.

取りうる方法は2つあります。FTPログインから「ファイル専用」の区別をなくすか、「接続」機能を行うコマンドを作るかのどちらかです。「ファイル専用」ディレクトリーに課される制限は、サーバーに対してFTPのユーザーをどう定義するかに基づいています。ディレクトリーのパスワードを知っているネットワーク上のユーザーは誰でも、FTPに関する限りそのディレクトリーの所有権を持つと考えるのであれば、これで解決します。FTPログインをユーザーログインと同じくらい制限の厳しいものにしたいのであれば、2つ目の方法が必要です。

Proposal

提案

Change the protocol in one of the following ways:

プロトコルを次のいずれかの方法で変更します。

  1. Remove the restriction on "files only" directories for FTP logins or
  2. Add an optional argument to the CWD (Change Working Directory) command to specify the password string for the directory. If the password check is successful the user is granted ownership rights to that directory. If the password is not present or the check fails, the command functions as it presently does and access is controlled by the current protection mechanism. Anonymous users should not be allowed to use this mechanism to change their access to the file system.
  1. FTPログインについて、「ファイル専用」ディレクトリーに対する制限をなくす。または
  2. CWD（Change Working Directory）コマンドに、ディレクトリーのパスワード文字列を指定する省略可能な引数を追加する。パスワードの検査に成功すると、ユーザーにはそのディレクトリーの所有者権限が与えられます。パスワードがない場合や検査に失敗した場合、コマンドは現在と同じように機能し、アクセスは現在の保護機構によって制御されます。匿名ユーザーには、この機構を使ってファイルシステムへのアクセス権を変更させるべきではありません。
