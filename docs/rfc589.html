RFC 589

CCN NETRJS server messages to remote user

RFC 589

CCNのNETRJSサーバーがリモートユーザーに送るメッセージ

A. INITIAL CONNECTION, SIGNON, AND SIGNOFF

A. 初期接続、サインオン、サインオフ

  1. If CCN refuses an ICP to a NETRJS socket, it means either that there is no free core within the NCP region, or that CCN's software is crashing.

  2. Once ICP is completed, CCN might send the user one of the following messages and close the Telnet connections:

              NRJ110I NETRJS PORTS BUSY.  TRY LATER

    This may be expected occasionally; frequent occurrance should be reported to CCN User Relations (825-7548), or to BELL@CCN.

              NRJ111I RJS NOT UP, TRY LATER

  3. Normally, however, the user will receive a READY message:

                   NRJ876R CCN NETRJS READY.  ENTER SIGNON

    If the user sends no operator input for 3 minutes, CCN will send:

                   NRJ308R SIGNON TIMEOUT EXCEEDED

               NRJ205R NETRJS SESSION TERMINATED

    and close the Telnet connection. If he sends an invalid SIGNON command, he will receive the message:

                   NRJ307R INVALID SIGNON, RE-ENTER

    Finally, a valid signon will be acknowledged by RJS with the message:

                   RJS750I TERMINAL -termid- HAS SIGNED ONTO RJS

  4. If the user terminates the session by entering a SIGNOFF command, NETRJS will wait until all data transfer has completed before sending the message:

                   NRJ205R NETRJS SESSION TERMINATED

    and closing the Telnet connection.

  1. CCNがNETRJSソケットへのICPを拒否した場合、それはNCP領域内に空きコア（メモリー）がないか、CCNのソフトウェアがクラッシュしていることを意味します。

  2. ICPが完了すると、CCNはユーザーに次のいずれかのメッセージを送り、Telnetコネクションを閉じることがあります。

              NRJ110I NETRJS PORTS BUSY.  TRY LATER

    これはときどき起こることが予想されます。頻繁に起こる場合は、CCNのユーザー窓口（User Relations、825-7548）またはBELL@CCNに報告してください。

              NRJ111I RJS NOT UP, TRY LATER

  3. しかし、通常はユーザーはREADYメッセージを受け取ります。

                   NRJ876R CCN NETRJS READY.  ENTER SIGNON

    ユーザーが3分間オペレーター入力を送らなかった場合、CCNは次のメッセージを送り、

                   NRJ308R SIGNON TIMEOUT EXCEEDED

               NRJ205R NETRJS SESSION TERMINATED

    Telnetコネクションを閉じます。ユーザーが無効なSIGNONコマンドを送った場合は、次のメッセージを受け取ります。

                   NRJ307R INVALID SIGNON, RE-ENTER

    最後に、有効なサインオンに対しては、RJSが次のメッセージで確認応答します。

                   RJS750I TERMINAL -termid- HAS SIGNED ONTO RJS

  4. ユーザーがSIGNOFFコマンドを入力してセッションを終了した場合、NETRJSはすべてのデータ転送が完了するまで待ってから次のメッセージを送り、

                   NRJ205R NETRJS SESSION TERMINATED

    Telnetコネクションを閉じます。

B. REMOTE SITE OR NETWORK FAILURES

B. リモートサイトまたはネットワークの障害

  1. During data transfer, the user must be reasonably responsive. If not, CCN will close the data transfer connection and send the remote operator message:

                   NRJ504I DATA TRANSFER TIMEOUT FOR THE -device-, -termid-

    1. if -device- is PRINTER or PUNCH, user site stopped accepting bits (sending "allocates") for over 5 minutes.

    2. if -device- is READER, user site left reader connection open without sending any bits for 5 minutes.

  2. During data transfer on the CR connection, CCN may detect an incorrect header or record, presumably due to user site software or Network transmission error. The following messages beginning with the word "BAD" will follow an NRJ512I message containing the faulty header in hex:

                   NRJ505I BAD HEADER SEQUENCE FOR NETRJS READER

    Sequence number in transaction header does not match internal counter of records passed.

                   NRJ506I BAD HEADER LENGTH FOR NETRJS READER

    Length given in header exceeds 880 bytes.

                   NRJ507I BAD HEADER TYPE FOR NETRJS READER

    Type code in header is not X'FF' (data) or X'FE' (end-of-data)

                   NRJ511I BAD FILL BIT COUNT FOR NETRJS READER

    The filler bit count in header is not a multiple of 8.

  3. If the header is correct but a data record is faulty, the following message will be sent to a remote user:

                   NRJ602I line STREAM ERROR - READER, -code-

    A protocol error was detected in the READER stream. CCN will close the stream and ready it to be reopened so the remote user may retry the data transfer operation. The valid -code- values are:

    Table 1
    CODE ERROR
    1 Device id byte has high bit off.
    2 End of transaction in the middle of a data line.
    3 Truncated input line longer than 255 bytes.
    4 In compressed text, string control byte has high bit off.
    5 In compressed text, duplicate blank string extends line longer than 255 bytes.
    6 In compressed text, duplicate character string extends line longer than 255 bytes.
    7 In compressed text, character string extends line longer than 255 bytes.

  4. Finally, if the user aborts his data transfer, he receives the message:

                   NRJ502I NETRJS -device- DATA TRANSFER ABORTED BY USER
               -termid-.

  1. データ転送中、ユーザーは適度に迅速に応答しなければなりません。そうでない場合、CCNはデータ転送コネクションを閉じ、リモートのオペレーターに次のメッセージを送ります。

                   NRJ504I DATA TRANSFER TIMEOUT FOR THE -device-, -termid-

    1. -device-がPRINTERまたはPUNCHの場合、ユーザーサイトが5分を超えてビットの受け入れ（「allocate」の送信）を停止した。

    2. -device-がREADERの場合、ユーザーサイトがリーダーコネクションを開いたまま、5分間ビットをまったく送らなかった。

  2. CRコネクションでのデータ転送中に、おそらくユーザーサイトのソフトウェアまたはネットワークの伝送エラーが原因で、CCNが誤ったヘッダーやレコードを検出することがあります。「BAD」という語で始まる次のメッセージは、問題のあるヘッダーを16進数で含むNRJ512Iメッセージの後に続きます。

                   NRJ505I BAD HEADER SEQUENCE FOR NETRJS READER

    トランザクションヘッダーのシーケンス番号が、受け渡したレコードの内部カウンターと一致しません。

                   NRJ506I BAD HEADER LENGTH FOR NETRJS READER

    ヘッダーで指定された長さが880バイトを超えています。

                   NRJ507I BAD HEADER TYPE FOR NETRJS READER

    ヘッダーのタイプコードがX'FF'（データ）でもX'FE'（データの終わり）でもありません

                   NRJ511I BAD FILL BIT COUNT FOR NETRJS READER

    ヘッダーのフィラービット数が8の倍数ではありません。

  3. ヘッダーは正しいもののデータレコードに問題がある場合、リモートユーザーに次のメッセージが送られます。

                   NRJ602I line STREAM ERROR - READER, -code-

    READERストリームでプロトコルエラーが検出されました。CCNはストリームを閉じ、再び開けるように準備するので、リモートユーザーはデータ転送操作を再試行できます。有効な-code-の値は次のとおりです。

    表1
    コード エラー
    1 デバイスIDバイトの最上位ビットがオフになっている。
    2 データ行の途中でトランザクションが終わっている。
    3 255バイトを超える入力行が切り詰められた。
    4 圧縮テキストで、文字列制御バイトの最上位ビットがオフになっている。
    5 圧縮テキストで、重複する空白文字列によって行が255バイトを超えて延びている。
    6 圧縮テキストで、重複する文字の文字列によって行が255バイトを超えて延びている。
    7 圧縮テキストで、文字列によって行が255バイトを超えて延びている。

  4. 最後に、ユーザーがデータ転送を中止した場合、ユーザーは次のメッセージを受け取ります。

                   NRJ502I NETRJS -device- DATA TRANSFER ABORTED BY USER
               -termid-.

C. CCN FAILURES

C. CCNの障害

  1. The CCN operator can cancel a NETRJS session, aborting any open data transfer streams and sending the message:

                   NRJ204I NETRJS SESSION ABORTED BY CENTRAL OPERATOR, TERM=
               -termid-

  2. Any of the following messages indicate a serious CCN Network software problem, and will cause the session to be aborted:

                   NRJ106A NETRJS DEAD - EXCHANGE INOPERATIVE

               NRJ201A NETRJS DT SOCKET ERROR - BAD LISTEN

               NRJ208A NETRJS PROGRAM CHECK IN -device-, code=ccc

               NRJ209A NETRJS LOAD FAILED FOR -device-, code=xx

               NRJ304I RJS LINE HANDLER DEAD

               NRJ401I RJS LINE HANDLER DEAD

               NRJ402I RJS LINE HANDLER DEAD

    Any of these should be reported to CCN.

  3. Besides global catastrophes like these above, the user might encounter a failure of a particular data transfer process. These do not terminate the session, only cause the data connection to be refused or terminated; the user can try again to open the data connection. Repeated failure should be reported to CCN.

                   NRJ501I NO CORE FOR DATA TRANSFER BUFFER -device-

               NRJ503I NO CORE FOR DATA TRANSFER WORKAREA -device-

               NRJ207I NO CORE FOR-device-DATA TRANSFER MODULE

    Due to core memory limitations in CCN's NCP, -device- cannot be started now. The data transfer connection indicated by -device- will be refused. This may happen occasionally during active periods, but repeated occurrences should be reported to CCN.

                   NRJ509I -device- DATA TRANSFER DEAD

               NRJ510I -device- DATA TRANSFER DEAD

               NRJ602I line STREAM ERROR - PRINTER, -code-

               NRJ602I line STREAM ERROR - PUNCH, -code-

    CCN data transfer failed, but recovery may be possible. User may try again.

  1. CCNのオペレーターはNETRJSセッションを取り消すことができます。その場合、開いているデータ転送ストリームを中止し、次のメッセージを送ります。

                   NRJ204I NETRJS SESSION ABORTED BY CENTRAL OPERATOR, TERM=
               -termid-

  2. 次のメッセージはいずれも、CCNのネットワークソフトウェアに深刻な問題があることを示しており、セッションは中止されます。

                   NRJ106A NETRJS DEAD - EXCHANGE INOPERATIVE

               NRJ201A NETRJS DT SOCKET ERROR - BAD LISTEN

               NRJ208A NETRJS PROGRAM CHECK IN -device-, code=ccc

               NRJ209A NETRJS LOAD FAILED FOR -device-, code=xx

               NRJ304I RJS LINE HANDLER DEAD

               NRJ401I RJS LINE HANDLER DEAD

               NRJ402I RJS LINE HANDLER DEAD

    これらはいずれもCCNに報告してください。

  3. 上記のような全体的な障害のほかに、ユーザーは特定のデータ転送プロセスの障害に遭遇することがあります。これらはセッションを終了させず、データコネクションを拒否または終了させるだけです。ユーザーは再びデータコネクションを開くことを試みられます。障害が繰り返し起こる場合は、CCNに報告してください。

                   NRJ501I NO CORE FOR DATA TRANSFER BUFFER -device-

               NRJ503I NO CORE FOR DATA TRANSFER WORKAREA -device-

               NRJ207I NO CORE FOR-device-DATA TRANSFER MODULE

    CCNのNCPのコアメモリーの制限により、-device-を現在開始できません。-device-が示すデータ転送コネクションは拒否されます。これは利用の多い時間帯にはときどき起こることがありますが、繰り返し起こる場合はCCNに報告してください。

                   NRJ509I -device- DATA TRANSFER DEAD

               NRJ510I -device- DATA TRANSFER DEAD

               NRJ602I line STREAM ERROR - PRINTER, -code-

               NRJ602I line STREAM ERROR - PUNCH, -code-

    CCNのデータ転送が失敗しましたが、回復できる可能性があります。ユーザーは再試行できます。
