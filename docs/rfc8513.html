1. Introduction

1. はじめに

This document defines a data model for DS-Lite [RFC6333], using the YANG data modeling language [RFC7950]. Both the Address Family Transition Router (AFTR) and Basic Bridging BroadBand (B4) elements are covered by this specification.

この文書は、YANGデータモデリング言語[RFC7950]を使用して、DS-Lite[RFC6333]のためのデータモデルを定義します。 この仕様は、アドレスファミリー移行ルーター（Address Family Transition Router: AFTR）要素とBasic Bridging BroadBand（B4）要素の両方を対象とします。

Figure 1 is a slight adaptation of Figure 1 from RFC 6333 and is provided here for the convenience of the reader.

図1は、RFC 6333の図1にわずかな変更を加えたもので、読者の便宜のためにここに示します。

DS-Lite deployment considerations are discussed in [RFC6908].

DS-Liteの展開に関する考慮事項は[RFC6908]で議論されています。

This document follows the guidelines of [RFC8407], uses the common YANG types defined in [RFC6991], and adopts the Network Management Datastore Architecture (NMDA) [RFC8342].

この文書は、[RFC8407]のガイドラインに従い、[RFC6991]で定義されている共通YANG型を使用し、ネットワーク管理データストアアーキテクチャー（NMDA）[RFC8342]を採用しています。

2. DS-Lite YANG Module: An Overview

2. DS-Lite YANGモジュール：概要

As shown in Figure 1:

図1に示すとおり、次のようになります。

  • The AFTR element is a combination of an IPv4-in-IPv6 tunnel and a NAPT function (Section 2.2 of [RFC3022]).
  • The B4 element is an IPv4-in-IPv6 tunnel.
  • AFTR要素は、IPv4-in-IPv6トンネルとNAPT機能（[RFC3022]のSection 2.2）を組み合わせたものです。
  • B4要素は、IPv4-in-IPv6トンネルです。

Therefore, the DS-Lite YANG module is designed to augment both the Interfaces YANG module [RFC8343] and the NAT YANG module [RFC8512] with DS-Lite-specific features.

そのため、DS-LiteのYANGモジュールは、インターフェイスのYANGモジュール[RFC8343]とNATのYANGモジュール[RFC8512]の両方を、DS-Lite固有の機能で拡張（augment）するように設計されています。

The YANG "feature" statement is used to distinguish which of the DS-Lite elements ('aftr' or 'b4') is relevant for a specific data node.

YANGの"feature"ステートメントは、特定のデータノードにどちらのDS-Lite要素（'aftr'または'b4'）が関係するかを区別するために使用されます。

Concretely, the DS-Lite YANG module (Figure 2) augments the Interfaces YANG module with the following:

具体的には、DS-LiteのYANGモジュール（図2）は、インターフェイスのYANGモジュールを次のもので拡張（augment）します。

  • An IPv6 address used by the tunnel endpoint (AFTR or B4) for sending and receiving IPv4-in-IPv6 packets (ipv6-address).
  • An IPv4 address that is used by the tunnel endpoint (AFTR or B4) for troubleshooting purposes (ipv4-address).
  • An IPv6 address used by a B4 element to reach its AFTR (aftr-ipv6-addr).
  • The tunnel MTU used to avoid fragmentation (tunnel-mtu).
  • A policy to instruct the tunnel endpoint (AFTR or B4) whether it must preserve Differentiated Services Code Point (DSCP) marking when encapsulating/decapsulating packets (v6-v4-dscp-preservation).
  • トンネルエンドポイント（AFTRまたはB4）がIPv4-in-IPv6パケットを送受信するために使用するIPv6アドレス（ipv6-address）。
  • トンネルエンドポイント（AFTRまたはB4）がトラブルシューティングの目的で使用するIPv4アドレス（ipv4-address）。
  • B4要素が自身のAFTRに到達するために使用するIPv6アドレス（aftr-ipv6-addr）。
  • フラグメンテーションを避けるために使用するトンネルMTU（tunnel-mtu）。
  • パケットのカプセル化やカプセル化解除の際に、差別化サービスコードポイント（DSCP）のマーキングを保持しなければならないかどうかをトンネルエンドポイント（AFTRまたはB4）に指示するポリシー（v6-v4-dscp-preservation）。

In addition, the DS-Lite YANG module augments the NAT YANG module (policy, in particular) with the following:

加えて、DS-LiteのYANGモジュールは、NATのYANGモジュール（特にポリシー）を次のもので拡張（augment）します。

  • A policy to limit the number of DS-Lite softwires per subscriber (max-softwire-per-subscriber).
  • A policy to instruct the AFTR whether a state can be automatically migrated (state-migrate).
  • Further, in order to prevent a Denial of Service (DoS) by frequently changing the source IPv6 address, 'b4-address-change-limit' is used to rate-limit such changes.
  • An instruction to rewrite the TCP Maximum Segment Size (MSS) option (mss-clamping) to avoid TCP fragmentation.
  • 加入者ごとのDS-Liteソフトワイヤーの数を制限するポリシー（max-softwire-per-subscriber）。
  • 状態を自動的に移行できるかどうかをAFTRに指示するポリシー（state-migrate）。
  • さらに、送信元IPv6アドレスを頻繁に変更することによるサービス拒否（DoS）を防ぐために、'b4-address-change-limit'を使用してそのような変更のレートを制限します。
  • TCPのフラグメンテーションを避けるために、TCPの最大セグメントサイズ（MSS）オプションを書き換える指示（mss-clamping）。

Given that the NAPT table of the AFTR element is extended to include the source IPv6 address of incoming packets, the DS-Lite YANG module augments the NAPT44 mapping entry with the following:

AFTR要素のNAPTテーブルは受信パケットの送信元IPv6アドレスを含むように拡張されるので、DS-LiteのYANGモジュールは、NAPT44のマッピングエントリーを次のもので拡張（augment）します。

  • b4-ipv6-address, which is used to record the source IPv6 address of a packet received from a B4 element. This IPv6 address is required to disambiguate between the overlapping IPv4 address space of subscribers.
  • The value of the Traffic Class field in the IPv6 header as received from a B4 element (v6-dscp): This information is used to preserve DSCP marking when encapsulating/decapsulating at the AFTR.
  • The IPv4 DSCP marking of the IPv4 packet received from a B4 element (internal-v4-dscp): This information can be used by the AFTR for setting the DSCP of packets relayed to a B4 element.
  • The IPv4 DSCP marking as set by the AFTR in its external interface (external-v4-dscp): An AFTR can be instructed to preserve the same marking or to set it to another value when forwarding an IPv4 packet destined to a remote IPv4 host.
  • b4-ipv6-address。B4要素から受信したパケットの送信元IPv6アドレスを記録するために使用します。 このIPv6アドレスは、加入者間で重複するIPv4アドレス空間を区別するために必要です。
  • B4要素から受信したIPv6ヘッダーのトラフィッククラスフィールドの値（v6-dscp）：この情報は、AFTRでのカプセル化やカプセル化解除の際にDSCPのマーキングを保持するために使用されます。
  • B4要素から受信したIPv4パケットのIPv4 DSCPマーキング（internal-v4-dscp）：この情報は、AFTRがB4要素へ中継するパケットのDSCPを設定するために使用できます。
  • AFTRが外部インターフェイスで設定するIPv4 DSCPマーキング（external-v4-dscp）：AFTRには、リモートのIPv4ホスト宛てのIPv4パケットを転送するときに、同じマーキングを保持するか、別の値に設定するかを指示できます。

Access Control List (ACL) and Quality-of-Service (QoS) policies discussed in Section 2.5 of [RFC6908] are out of scope. A YANG module for ACLs is documented in [ACL-YANG].

[RFC6908]のSection 2.5で議論されているアクセス制御リスト（ACL）とサービス品質（QoS）のポリシーは範囲外です。 ACLのためのYANGモジュールは[ACL-YANG]に記載されています。

Likewise, considerations that are related to the Port Control Protocol (PCP) and discussed in Section 8.5 of [RFC6333] are out of scope. A YANG module for PCP is documented in [YANG-PCP].

同様に、ポート制御プロトコル（PCP）に関連し、[RFC6333]のSection 8.5で議論されている考慮事項も範囲外です。 PCPのためのYANGモジュールは[YANG-PCP]に記載されています。

YANGモジュール"ietf-dslite"は次の構造を持ちます。

 augment "/if:interfaces/if:interface" {
   when 'derived-from(if:type, "dslite")';
   description
     "Augments Interface module with DS-Lite parameters.

      IANA interface types are maintained at this registry:
      <https://www.iana.org/assignments/ianaiftype-mib/>.

      tunnel (131),       -- Encapsulation interface";
   leaf ipv6-address {
     type inet:ipv6-address;
     description
       "IPv6 address of the local DS-Lite endpoint (AFTR or B4).";
     reference
       "RFC 6333: Dual-Stack Lite Broadband Deployments Following
                  IPv4 Exhaustion";
   }
   leaf ipv4-address {
     type inet:ipv4-address;
     description
       "IPv4 address of the local DS-Lite AFTR or B4.

        192.0.0.1 is reserved for the AFTR element, while
        192.0.0.0/29 is reserved for the B4 element.

        This address can be used to report ICMP problems and will
        appear in traceroute outputs.";
     reference
       "RFC 6333: Dual-Stack Lite Broadband Deployments Following
                  IPv4 Exhaustion";
   }
   leaf aftr-ipv6-addr {
     if-feature "b4";
     type inet:ipv6-address;
     description
       "Indicates the AFTR's IPv6 address to be used by a B4
        element.";
     reference
       "RFC 6333: Dual-Stack Lite Broadband Deployments Following
                  IPv4 Exhaustion";
   }
   leaf tunnel-mtu {
     type uint16;
     description
       "Configures a tunnel MTU.

        RFC 6908 specifies that since fragmentation and reassembly
        are not optimal, the operator should do everything possible
        to eliminate the need for them.  If the operator uses simple
        IPv4-in-IPv6 softwire, it is recommended that the MTU size
        of the IPv6 network between the B4 and the AFTR account
        for the additional overhead (40 bytes).";
     reference
       "RFC 6908: Deployment Considerations for Dual-Stack Lite";
   }
   leaf v6-v4-dscp-preservation {
     type boolean;
     description
       "Copies the DSCP value from the IPv6 header, and vice versa.

        According to Section 2.10 of RFC 6908, operators should
        use the uniform model by provisioning the network such
        that the AFTR/B4 copies the DSCP value in the IPv4 header
        to the Traffic Class field in the IPv6 header, after the
        IPv4-in-IPv6 encapsulation.";
     reference
       "Section 2.10 of RFC 6908";
   }
 }

 augment "/nat:nat/nat:instances/nat:instance/nat:policy" {
   when "derived-from-or-self(/nat:nat/nat:instances/nat:instance"
      + "/nat:type, 'nat:napt44')"
      + " and /nat:nat/nat:instances/nat:instance/"
      + "nat:per-interface-binding='dslite'";
   if-feature "aftr";
   description
     "Augments the NAPT44 module with AFTR parameters.";
   leaf max-softwires-per-subscriber {
     type uint8;
     default "1";
     description
       "Configures the maximum softwires per subscriber feature.

        A subscriber is uniquely identified by means
        of a subscriber-mask (subscriber-mask-v6).

        This policy aims to prevent a misbehaving subscriber from
        mounting several DS-Lite softwires that would consume
        additional AFTR resources (e.g., get more external ports
        if the quota was enforced on a per-softwire basis and
        consume extra processing due to a large number of active
        softwires).";
     reference
       "Section 4 of RFC 7785";
   }
   leaf state-migrate {
     type boolean;
     default "true";
     description
       "State migration is enabled by default.

        In the event a new IPv6 address is assigned to the B4 element,
        the AFTR should migrate existing state to be bound to the new
        IPv6 address.  This operation ensures that traffic destined to
        the previous B4's IPv6 address will be redirected to the newer
        B4's IPv6 address.  The destination IPv6 address for tunneling
        return traffic from the AFTR should be the last seen as the
        B4's IPv6 source address from the user device (e.g., CPE).

        The AFTR uses the subscriber-mask-v6 to determine whether two
        IPv6 addresses belong to the same CPE (e.g., if the
        subscriber-mask-v6 is set to 56, the AFTR concludes that
        2001:db8:100:100::1 and 2001:db8:100:100::2 belong to the same
        CPE assigned with 2001:db8:100:100::/56).";
     reference
       "RFC 7785: Recommendations for Prefix Binding in the Context
                  of Softwire Dual-Stack Lite";
   }
   leaf b4-address-change-limit {
     type uint32;
     units "seconds";
     default "1800";
     description
       "Minimum number of seconds between a successive B4's IPv6
        address change from the same prefix.

        Changing the source B4's IPv6 address may be used as an attack
        vector.  Packets with a new B4's IPv6 address from the same
        prefix should be rate-limited.

        It is recommended that this rate limit be set to 30 minutes;
        other values can be set on a per-deployment basis.";
     reference
       "RFC 7785: Recommendations for Prefix Binding in the Context
                  of Softwire Dual-Stack Lite";
   }
   container mss-clamping {
     description
       "MSS rewriting configuration to avoid IPv6 fragmentation.";
     leaf enable {
       type boolean;
       description
         "Enable/disable MSS rewriting feature.";
     }
     leaf mss-value {
       type uint16;
       units "octets";
       description
         "Sets the MSS value to be used for MSS rewriting.";
     }
   }
 }

       + "/nat:mapping-table/nat:mapping-entry" {

4. Security Considerations

4. セキュリティーに関する考慮事項

The YANG module specified in this document defines a schema for data that is designed to be accessed via network management protocols such as NETCONF [RFC6241] or RESTCONF [RFC8040]. The lowest NETCONF layer is the secure transport layer, and the mandatory-to-implement secure transport is Secure Shell (SSH) [RFC6242]. The lowest RESTCONF layer is HTTPS, and the mandatory-to-implement secure transport is TLS [RFC8446].

この文書で規定するYANGモジュールは、NETCONF[RFC6241]やRESTCONF[RFC8040]などのネットワーク管理プロトコルを介してアクセスされるように設計されたデータのスキーマを定義します。 NETCONFの最下位層は安全なトランスポート層であり、実装必須の安全なトランスポートはSecure Shell（SSH）[RFC6242]です。 RESTCONFの最下位層はHTTPSであり、実装必須の安全なトランスポートはTLS[RFC8446]です。

The Network Configuration Access Control Model (NACM) [RFC8341] provides the means to restrict access for particular NETCONF or RESTCONF users to a preconfigured subset of all available NETCONF or RESTCONF protocol operations and content.

ネットワーク設定アクセス制御モデル（NACM）[RFC8341]は、特定のNETCONFユーザーやRESTCONFユーザーのアクセスを、利用可能なすべてのNETCONFプロトコルやRESTCONFプロトコルの操作とコンテンツのうち、事前に設定されたサブセットに制限する手段を提供します。

All data nodes defined in the YANG module that can be created, modified, and deleted (i.e., config true, which is the default) are considered sensitive. Write operations (e.g., edit-config) applied to these data nodes without proper protection can negatively affect network operations. An attacker who is able to access the B4/AFTR can undertake various attacks, such as:

このYANGモジュールで定義されている、作成・変更・削除が可能なすべてのデータノード（つまり、デフォルトであるconfig true）は、機密性が高いものとみなされます。 適切な保護なしにこれらのデータノードに対して書き込み操作（たとえば、edit-config）が適用されると、ネットワークの運用に悪影響を及ぼす可能性があります。 B4やAFTRにアクセスできる攻撃者は、たとえば次のようなさまざまな攻撃を行うことができます。

  • Setting the value of 'aftr-ipv6-addr' on the B4 to point to an illegitimate AFTR so that it can intercept all the traffic sent by a B4. Illegitimately intercepting users' traffic is an attack with severe implications on privacy.
  • Setting the MTU to a low value, which may increase the number of fragments ('tunnel-mtu' for both B4 and AFTR).
  • Setting 'max-softwire-per-subscriber' to an arbitrary high value, which will be exploited by a misbehaving user to grab more resources (by mounting as many softwires as required to get more external IP addresses/ports) or to perform a DoS on the AFTR by mounting a massive number of softwires.
  • Setting 'state-migrate' to 'false' on the AFTR. This action may lead to a service degradation for the users.
  • Setting 'b4-address-change-limit' to an arbitrary low value can ease DoS attacks based on frequent change of the B4 IPv6 address.
  • Setting 'v6-v4-dscp-preservation' to 'false" may lead to a service degradation if some policies are applied on the network based on the DSCP value.
  • B4上の'aftr-ipv6-addr'の値を、正規でないAFTRを指すように設定し、B4が送信するすべてのトラフィックを傍受できるようにすること。 ユーザーのトラフィックを不正に傍受することは、プライバシーに深刻な影響を及ぼす攻撃です。
  • MTUを小さい値に設定すること（B4とAFTRの両方における'tunnel-mtu'）。 これにより、フラグメントの数が増える可能性があります。
  • 'max-softwire-per-subscriber'を任意の大きな値に設定すること。 これは、不正な振る舞いをするユーザーによって、（より多くの外部IPアドレスやポートを得るために必要なだけソフトワイヤーを張ることで）より多くのリソースを獲得したり、大量のソフトワイヤーを張ることでAFTRに対するDoSを行ったりするために悪用されます。
  • AFTR上で'state-migrate'を'false'に設定すること。 この操作は、ユーザーに対するサービスの劣化につながる可能性があります。
  • 'b4-address-change-limit'を任意の小さな値に設定すると、B4のIPv6アドレスを頻繁に変更することに基づくDoS攻撃が容易になる可能性があります。
  • 'v6-v4-dscp-preservation'を'false'に設定すると、DSCPの値に基づくポリシーがネットワークで適用されている場合に、サービスの劣化につながる可能性があります。

Additional security considerations are discussed in [RFC8512].

追加のセキュリティーに関する考慮事項は[RFC8512]で議論されています。

Security considerations related to DS-Lite are discussed in [RFC6333].

DS-Liteに関連するセキュリティーに関する考慮事項は[RFC6333]で議論されています。

      true
    </dslite:v6-v4-dscp-preservation>
  </interface>
</interfaces>

Appendix B. AFTR Examples

Appendix B. AFTRの例

The following example shows an AFTR that is reachable at 2001:db8:0:2::1. Also, this XML snippet indicates that the AFTR is provided with an IPv4 address (192.0.0.1) to be used for troubleshooting purposes such as reporting problems to B4s.

次の例は、2001:db8:0:2::1で到達可能なAFTRを示しています。 また、このXMLスニペットは、B4への問題の報告などのトラブルシューティングの目的で使用するIPv4アドレス（192.0.0.1）がAFTRに与えられていることを示しています。

Note that a subscriber is identified by a subscriber-mask [RFC7785] that can be configured by means of [RFC8512].

加入者は、[RFC8512]によって設定できるsubscriber-mask[RFC7785]によって識別されることに注意してください。

<interfaces>
  <interface>
    <name>myAFTR</name>
    <type>dslite:dslite</type>
    <enabled>true</enabled>
    <dslite:ipv6-address>2001:db8:0:2::1</dslite:ipv6-address>
    <dslite:ipv4-address>192.0.0.1</dslite:ipv4-address>
  </interface>
</interfaces>

<interfaces>
  <interface>
    <name>myAFTR</name>
    <type>dslite:dslite</type>
    <enabled>true</enabled>
    <dslite:ipv6-address>2001:db8:0:2::1</dslite:ipv6-address>
    <dslite:ipv4-address>192.0.0.1</dslite:ipv4-address>
  </interface>
</interfaces>

The following shows an XML excerpt depicting a dynamic UDP mapping entry maintained by a DS-Lite AFTR for a packet received from the B4 element introduced in Appendix A. The remaining lifetime of this mapping is 300 seconds.

次に示すのは、付録Aで紹介したB4要素から受信したパケットに対して、DS-LiteのAFTRが維持する動的なUDPマッピングエントリーを表すXMLの抜粋です。 具体的には、送信元IPv6アドレス（2001:db8:0:1::1）、送信元IPv4アドレス（192.0.2.1）、送信元ポート番号（1568）で受信したこのUDPパケットは、送信元IPv4アドレス（198.51.100.1）と送信元ポート番号（15000）を持つUDPパケットに変換されます。 このマッピングの残りの有効期間は300秒です。

  <index>15</index>

    dynamic-explicit
  </type>

    17
  </transport-protocol>

  </dslite:b4-ipv6-address>
  <internal-src-address>
    192.0.2.1
  </internal-src-address>
  <internal-src-port>

      1568
    </start-port-number>
  </internal-src-port>

    198.51.100.1
  </external-src-address>
  <external-src-port>
    <start-port-number>
      15000
    </start-port-number>
  </external-src-port>
