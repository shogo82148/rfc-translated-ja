RFC 9702

YANG Data Model for Maximum Segment Identifier (SID) Depth (MSD) Types and MPLS MSD

RFC 9702

最大セグメント識別子（SID）深度（MSD）タイプおよびMPLS MSDのためのYANGデータモデル

Abstract

概要

This document defines two YANG modules. The first module is the initial version of the IANA-maintained YANG module for Maximum Segment Identifier (SID) Depth (MSD) Types, which includes identities for both the MPLS data plane and Segment Routing over IPv6 (SRv6) data plane. The second module augments the IETF MPLS YANG data model to provide support for MPLS MSDs as defined in RFCs 8476 and 8491.

この文書は2つのYANGモジュールを定義します。1つ目のモジュールは、最大セグメント識別子（SID）深度（Maximum Segment Identifier (SID) Depth、MSD）タイプのためのIANAが維持管理するYANGモジュールの初版であり、MPLSデータプレーンとIPv6上のセグメントルーティング（Segment Routing over IPv6、SRv6）データプレーンの両方のアイデンティティーを含みます。2つ目のモジュールは、IETF MPLS YANGデータモデルを拡張（augment）し、RFC 8476およびRFC 8491で定義されたMPLS MSDをサポートします。

1. Overview

1. 概要

There are two YANG modules [RFC7950] defined in this document. Module iana-msd-types defines the identities for Maximum SID Depth (MSD) Types as per the "IGP MSD-Types" IANA registry [IANA-IGP-MSD-Types], which includes MSD types for both the MPLS and SRv6 data planes. This document also defines module ietf-mpls-msd augmenting the IETF MPLS YANG data model [RFC8960], which augments the routing RIB data model [RFC8349] to provide operational state for various MSDs [RFC8662] for the MPLS data plane. The module augments the base MPLS model with a list of various types of Node MSDs as well as various types of Link MSDs.

この文書では2つのYANGモジュール[RFC7950]を定義します。iana-msd-typesモジュールは、IANAの「IGP MSD-Types」レジストリー[IANA-IGP-MSD-Types]にしたがって、最大SID深度（Maximum SID Depth、MSD）タイプのアイデンティティーを定義します。このレジストリーには、MPLSとSRv6の両方のデータプレーンのMSDタイプが含まれます。この文書では、IETF MPLS YANGデータモデル[RFC8960]を拡張するietf-mpls-msdモジュールも定義します。IETF MPLS YANGデータモデルはルーティングRIBデータモデル[RFC8349]を拡張するもので、ietf-mpls-msdモジュールはこれを拡張して、MPLSデータプレーンにおけるさまざまなMSD[RFC8662]の運用状態を提供します。このモジュールは、ベースMPLSモデルに、さまざまな種類のノードMSD（Node MSD）のリストと、さまざまな種類のリンクMSD（Link MSD）のリストを追加します。

The YANG modules in this document conform to the Network Management Datastore Architecture (NMDA) [RFC8342].

この文書のYANGモジュールは、ネットワーク管理データストアアーキテクチャー（Network Management Datastore Architecture、NMDA）[RFC8342]に準拠しています。

2. Design of the Model

2. モデルの設計

2.1. IANA MSD Types Module

2.1. IANA MSDタイプモジュール

IANA has created a registry titled "IGP MSD-Types" under the "Interior Gateway Protocol (IGP) Parameters" registry group to identify MSD-Types. Module iana-msd-types is an IANA-maintained module, which defines the identities for the MSD-Types as in the IANA "IGP MSD-Types" registry. This module references [RFC8476], [RFC8491], [RFC8662], [RFC8664], [RFC8814], [RFC9088], and [RFC9352].

IANAは、MSDタイプを識別するために、「Interior Gateway Protocol (IGP) Parameters」レジストリーグループの下に「IGP MSD-Types」という名前のレジストリーを作成しました。iana-msd-typesモジュールはIANAが維持管理するモジュールであり、IANAの「IGP MSD-Types」レジストリーにあるとおりにMSDタイプのアイデンティティーを定義します。このモジュールは、[RFC8476]、[RFC8491]、[RFC8662]、[RFC8664]、[RFC8814]、[RFC9088]、[RFC9352]を参照しています。

On top of the base identity "msd-base", identity "msd-base-mpls" is defined to serve as the base for MSD types for the MPLS data plane, and identity "msd-base-srh" is defined to serve as the base for MSD types for the Segment Routing Header (SRH) in the IPv6 data plane.

ベースアイデンティティー「msd-base」の上に、MPLSデータプレーン向けのMSDタイプのベースとなるアイデンティティー「msd-base-mpls」と、IPv6データプレーンにおけるセグメントルーティングヘッダー（Segment Routing Header、SRH）向けのMSDタイプのベースとなるアイデンティティー「msd-base-srh」を定義します。

This module is maintained by IANA and will be updated if and when there is any change to the registry.

このモジュールはIANAによって維持管理され、レジストリーに変更があった場合には更新されます。

2.2. IETF MPLS MSD Module

2.2. IETF MPLS MSDモジュール

Module ietf-mpls-msd augments the base MPLS model [RFC8960], and it provides support of different types of MSDs in the MPLS data plane.

ietf-mpls-msdモジュールは、ベースMPLSモデル[RFC8960]を拡張し、MPLSデータプレーンにおけるさまざまな種類のMSDをサポートします。

As defined in [RFC8491], a Link MSD is the number of SIDs supported by a node's link, while a Node MSD is the smallest MSD supported by the node across all its links. The module defines lists of MSDs and their MSD Types for a node and its links. Please note that these are read-only data nodes exposing a node's hardware capability.

[RFC8491]で定義されているように、リンクMSDはノードのリンクがサポートするSIDの数であり、ノードMSDはそのノードのすべてのリンクでサポートされるMSDのうち最小のものです。このモジュールは、ノードとそのリンクについて、MSDとそのMSDタイプのリストを定義します。これらはノードのハードウェア能力を公開する読み取り専用のデータノードであることに注意してください。

4.2. MPLS MSD YANG

4.2. MPLS MSDのYANGモジュール

This document also defines a YANG module for MSD extensions [RFC8476] [RFC8491] to the MPLS base model as defined in [RFC8960].

5. Security Considerations

5. セキュリティーに関する考慮事項

The YANG modules specified in this document define a schema for data that is designed to be accessed via network management protocols such as NETCONF [RFC6241] or RESTCONF [RFC8040]. The lowest NETCONF layer is the secure transport layer, and the mandatory-to-implement secure transport is Secure Shell (SSH) [RFC6242]. The lowest RESTCONF layer is HTTPS, and the mandatory-to-implement secure transport is TLS [RFC8446].

この文書で規定するYANGモジュールは、NETCONF [RFC6241]やRESTCONF [RFC8040]などのネットワーク管理プロトコルを介してアクセスされるように設計されたデータのスキーマを定義します。NETCONFの最下層はセキュアなトランスポート層であり、実装必須のセキュアなトランスポートはSecure Shell（SSH）[RFC6242]です。RESTCONFの最下層はHTTPSであり、実装必須のセキュアなトランスポートはTLS [RFC8446]です。

The Network Configuration Access Control Model (NACM) [RFC8341] provides the means to restrict access for particular NETCONF or RESTCONF users to a pre-configured subset of all available NETCONF or RESTCONF protocol operations and content.

ネットワーク構成アクセス制御モデル（Network Configuration Access Control Model、NACM）[RFC8341]は、特定のNETCONFまたはRESTCONFユーザーのアクセスを、利用可能なすべてのNETCONFまたはRESTCONFプロトコル操作とコンテンツのうち、あらかじめ設定されたサブセットに制限する手段を提供します。

Some of the readable data nodes in the ietf-mpls-msd YANG module may be considered sensitive or vulnerable in some network environments. It is thus important to control read access (e.g., via get, get-config, or notification) to these data nodes. These are the subtrees and data nodes and their sensitivity/vulnerability:

ietf-mpls-msd YANGモジュールの読み取り可能なデータノードの一部は、ネットワーク環境によっては機密性が高い、または脆弱であるとみなされる場合があります。したがって、これらのデータノードへの読み取りアクセス（たとえば、get、get-config、notificationを介したもの）を制御することが重要です。サブツリーとデータノード、およびその機密性・脆弱性は次のとおりです。

/rt:routing/mpls:mpls/msd/node-msds

/rt:routing/mpls:mpls/msd/node-msds

/rt:routing/mpls:mpls/msd/link-msds

/rt:routing/mpls:mpls/msd/link-msds

Exposure of the node's maximum SID depth may be useful in mounting a Denial-of-Service (DoS) attack by sending packets to the node that the router can't process.

ノードの最大SID深度が公開されると、ルーターが処理できないパケットをそのノードに送りつけるサービス拒否（Denial-of-Service、DoS）攻撃を仕掛けるのに利用される可能性があります。

The iana-msd-types YANG module defines a set of identities that mirror the IANA "IGP MSD-Types" registry. These identities are intended to be reused by other YANG modules. The module by itself does not expose any data nodes that are writable or readable. As such, there are no additional security issues related to this YANG module that need to be considered.

iana-msd-types YANGモジュールは、IANAの「IGP MSD-Types」レジストリーを反映したアイデンティティーの集合を定義します。これらのアイデンティティーは、他のYANGモジュールで再利用されることを意図しています。このモジュール自体は、書き込み可能または読み取り可能なデータノードを一切公開しません。そのため、このYANGモジュールに関連して考慮すべき追加のセキュリティー上の問題はありません。
