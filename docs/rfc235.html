RFC 235

Site status

RFC 235

サイトの状況

Abstract

概要

Beginning with this RFC, BBN will report on the status of most Network Hosts approximately once every two weeks. The information for these reports will be gained from talking to people at each site, and from experimental "data". These data will be the results of daily attempts to log into each of the Hosts which might be accessible to a Network user; the attempts will have been made from the BBN prototype Terminal IMP at a random time each weekday.

このRFCから、BBNはほとんどのネットワークホストの状況を、およそ2週間に1回報告します。これらの報告のための情報は、各サイトの人々と話をすることと、実験による「データ」から得ます。このデータは、ネットワークユーザーがアクセスできる可能性のある各ホストに毎日ログインを試みた結果です。ログインの試行は、BBNの試作版Terminal IMPから、平日の毎日ランダムな時刻に行います。

Several Hosts are currently excluded from the daily testing. These Hosts fall into two categories:

現在、いくつかのホストは毎日の試験から除外されています。これらのホストは2つの分類に分けられます。

1) Hosts which are not expected to be functioning on the Network as servers (available for use from other sites) for at least a month. Included here are:

1) 少なくとも1か月間は、ネットワーク上でサーバーとして（他のサイトから利用できる状態で）機能する見込みのないホスト。次のホストが含まれます。

where

ここで、各記号の意味は次のとおりです。

D
Dead. (Destination Host either dead or inaccessible (due to network partitioning or local IMP failure from the BBN Terminal IMP)
R
Refused. (Destination Host returned a CLS to the initial RFC.)
T
Timed out. (Destination Host did not responding any way to the initial RFC, although not dead.)
1/2 0
1/2 Open. (Destination Host opened a connection but then either immediately closed it, or did not respond any further.)
0
Open. (Destination Host opened a connection and was accessible to users.
D
Dead（停止）。（宛先ホストが停止しているか、BBN Terminal IMPから（ネットワークの分断またはローカルIMPの障害により）アクセスできない状態です）
R
Refused（拒否）。（宛先ホストが、最初のRFC（接続要求）に対してCLSを返しました。）
T
Timed out（タイムアウト）。（宛先ホストは停止していないものの、最初のRFCに対してまったく応答しませんでした。）
1/2 0
1/2 Open（半開）。（宛先ホストはコネクションを開いたものの、その後すぐに閉じたか、それ以上応答しませんでした。）
0
Open（オープン）。（宛先ホストがコネクションを開き、ユーザーからアクセスできました。

* The UCLA IBM-360 is at the moment only able to handle Remote Job Service. BBN is not equipped to test this, but is assuming that receipt of their canned message indicates that RJS is also functioning.

* UCLAのIBM-360は、現時点ではリモートジョブサービスしか扱えません。BBNにはこれを試験する設備がありませんが、UCLAの定型メッセージを受信したことは、RJSも機能していることを示すものとみなしています。
