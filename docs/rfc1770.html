RFC 1770

IPv4 Option for Sender Directed Multi-Destination Delivery

RFC 1770

送信者指定の複数宛先配送のためのIPv4オプション

Abstract

概要

This memo defines an IPv4 option to provide a sender directed multi-destination delivery mechanism called Selective Directed Broadcast Mode (SDBM). The SDBM provides unreliable UDP delivery to a set of IP addresses included in the option field of an IPv4 datagram. Data reliability if required will be provided by the application layer. This approach was developed to support sender directed multi-destination delivery to sparsely populated groups with no additional control traffic. This approach will find application in the extremely bandwidth constrained tactical military environment, as well as in some commercial applications requiring sender control of data delivery.

このメモは、選択的ダイレクテッドブロードキャストモード（Selective Directed Broadcast Mode、SDBM）と呼ばれる、送信者が宛先を指定する複数宛先配送のメカニズムを提供するためのIPv4オプションを定義します。SDBMは、IPv4データグラムのオプションフィールドに含まれる一連のIPアドレスに対して、信頼性のないUDP配送を提供します。データの信頼性が必要な場合は、アプリケーション層によって提供されます。このアプローチは、追加の制御トラフィックなしに、まばらに分布するグループへの送信者指定の複数宛先配送をサポートするために開発されました。このアプローチは、帯域幅が極端に制約された戦術的な軍事環境に加えて、送信者がデータ配送を制御する必要がある一部の商用アプリケーションでも応用されるでしょう。

このメモのステータス

This memo provides information for the Internet community. This memo does not specify an Internet standard of any kind. Distribution of this memo is unlimited.

このメモは、インターネットコミュニティーに情報を提供するものです。いかなる種類のインターネット標準も規定するものではありません。このメモの配布は無制限です。

Background

背景

The Selective Directed Broadcast Mode (SDBM) is an integral part of the U.S. Army standard for tactical data communication networks as defined in MIL-STD-188-220() (Reference [1]). The MIL-STD-188-220() defines a protocol architecture for the lower four layers of the ISO-OSI Reference model. The MIL-STD-188-220() is currently undergoing a reformatting to be consistent with other DoD standards that deal with IP networking. These efforts will provide tactical IP internetting of tactical Army broadcast radio networks, and will support fully IP compliant internetworking to other types of IP networks via commercial IP routers. It is the goal of the U.S. Army to move toward a fully IP compliant internetwork architecture for all tactical battlefield data communications. The Army does, however, have a critical need for a reliable, sender directed multi-destination data transfer capability that is not currently supported by the existing or emerging internet standards. The SDBM IP option was developed to meet this need. The required data reliability will be provided by incorporating an acknowledgement strategy at the application layer. It is hoped that this IP option, providing multi-destination capability not currently provided by the current and emerging internet standards, will be embraced by the internet community and become an integal part of the IP family of protocols and be incorporated in commercial IP software products.

選択的ダイレクテッドブロードキャストモード（SDBM）は、MIL-STD-188-220()（参考文献[1]）で定義されている、戦術データ通信ネットワークのための米国陸軍標準に不可欠な部分です。MIL-STD-188-220()は、ISO-OSI参照モデルの下位4層のプロトコルアーキテクチャーを定義しています。MIL-STD-188-220()は現在、IPネットワーキングを扱う他の国防総省（DoD）標準と整合するよう、書式の見直しが進められています。この取り組みにより、陸軍の戦術ブロードキャスト無線ネットワークの戦術IPインターネット接続が実現し、商用IPルーターを介した他の種類のIPネットワークとの完全にIP準拠のインターネットワーキングがサポートされます。米国陸軍の目標は、すべての戦場における戦術データ通信について、完全にIP準拠のインターネットワークアーキテクチャーへ移行することです。しかし陸軍には、信頼性のある、送信者が宛先を指定する複数宛先データ転送の能力がどうしても必要であり、これは既存または策定中のインターネット標準では現在サポートされていません。SDBM IPオプションは、この必要性を満たすために開発されました。必要なデータの信頼性は、アプリケーション層に確認応答の戦略を組み込むことで提供されます。現在および策定中のインターネット標準では現在提供されていない複数宛先の能力を提供するこのIPオプションが、インターネットコミュニティーに受け入れられ、IPプロトコルファミリーの不可欠な部分となり、商用IPソフトウェア製品に組み込まれることが期待されています。

SDBM Format

SDBMの形式

The SDBM provides the ability for an application to explicitly list a set of intended IP destinations. This capability will be implemented as an option in the IP layer, as shown in Figure 1. This option field is variable in length, up to a maximum of 40 octets due to the limitation of the HLEN field as specified in STD 5, RFC 791 (Reference [2]). Under this option 38 of the 40 octets would be used to contain the 2 octet control field and a maximum of 9 IP addresses.

SDBMは、アプリケーションが意図するIP宛先の集合を明示的に列挙する機能を提供します。この機能は、図1に示すように、IP層のオプションとして実装されます。このオプションフィールドは可変長で、STD 5、RFC 791（参考文献[2]）で規定されているHLENフィールドの制限により、最大40オクテットです。このオプションでは、40オクテットのうち38オクテットを使って、2オクテットの制御フィールドと最大9個のIPアドレスを格納することになります。

The TYPE field specifies the copy flag, class, and option number. The copy field indicates whether or not this option field is to be copied into each fragment if the IP datagram is fragmented. The class field and option number field are set to 0 and 21 respectively. The format of the TYPE field is shown at Figure 2.

TYPEフィールドは、コピーフラグ、クラス、オプション番号を指定します。コピーフィールドは、IPデータグラムがフラグメント化される場合に、このオプションフィールドを各フラグメントにコピーするかどうかを示します。クラスフィールドとオプション番号フィールドは、それぞれ0と21に設定されます。TYPEフィールドの形式を図2に示します。

Since the IP multi-address list shall always be copied to all IP headers during fragmentation, the COPY bit should be set to 1.

IPの複数アドレスのリストは、断片化の際に常にすべてのIPヘッダーにコピーされるので、COPYビットは1に設定すべきです。

Returning to Figure 1, the LENGTH octet indicates how many octets are in the option field. It is calculated as:

図1に戻ると、LENGTHオクテットはオプションフィールドに何オクテットあるかを示します。これは次のように計算されます。

LENGTH = 2 + 4*(number of IP addresses)

LENGTH = 2 + 4*(number of IP addresses)

The remaining octets contain the IP addresses of the specified destination hosts. Each IP address occupies 4 octets.

残りのオクテットには、指定された宛先ホストのIPアドレスが含まれます。各IPアドレスは4オクテットを占めます。

Transmission of SDBM datagrams

SDBMデータグラムの送信

The procedures for a source host, transit router, and destination router are provided below. When a source host has a message to send to multiple destination hosts, it shall,

送信元ホスト、中継ルーター、宛先ルーターの手順を以下に示します。送信元ホストは、複数の宛先ホストに送るメッセージがある場合、次のようにします。

  1. Group the destination host internet addresses by their network identifiers (Net IDs). If there are N distinct Net IDs, there will be at least N distinct directed broadcast packets. If there are more that 9 destination hosts on a single net, multiple directed broadcast datagrams must be sent to that net.
  2. For each Net ID, form the directed broadcast address as defined in STD 3, RFC 1122 (Reference [3]) for that network. The directed broadcast address is used as the destination address in the IP datagram and the source address is the address of the host sending the message.
  3. Place the entire IP address for up to 9 destination hosts in the in the same net in the option field defined above. The total length of all IP options in a given datagram is limited to 40 octets as determined by the HLEN (Header Length) field which defines the number of 32 bit words in the header. If other options are to be included in addition to the SDBM option, the number of addresses in the option field must be reduced accordingly.
  4. The thusly formed datagram shall be transmitted and processed according to normal datagram handling procedures.
  1. 宛先ホストのインターネットアドレスを、ネットワーク識別子（Net ID）ごとにグループ化します。異なるNet IDがN個ある場合、異なるダイレクテッドブロードキャストパケットが少なくともN個あることになります。1つのネットワーク上に9を超える宛先ホストがある場合は、そのネットワークに複数のダイレクテッドブロードキャストデータグラムを送らなければなりません。
  2. 各Net IDについて、STD 3、RFC 1122（参考文献[3]）で定義されているとおりに、そのネットワークのダイレクテッドブロードキャストアドレスを作ります。ダイレクテッドブロードキャストアドレスはIPデータグラムの宛先アドレスとして使われ、送信元アドレスはメッセージを送信するホストのアドレスです。
  3. 同じネットワーク内の最大9個の宛先ホストについて、IPアドレス全体を上で定義したオプションフィールドに格納します。ヘッダー内の32ビットワードの数を定義するHLEN（ヘッダー長）フィールドによって決まるとおり、1つのデータグラム内のすべてのIPオプションの合計長は40オクテットに制限されます。SDBMオプションに加えて他のオプションも含める場合は、それに応じてオプションフィールド内のアドレスの数を減らさなければなりません。
  4. このようにして作られたデータグラムは、通常のデータグラム処理手順に従って送信され、処理されます。

When a IP SDBM datagram encounters a transit router (router not connected to the destination network), the datagram shall be processed in accordance with normal IP datagram handling procedures. When encountering the destination router (the destination network is directly attached to the router), the destination router shall perform a, b or c below:

IP SDBMデータグラムが中継ルーター（宛先ネットワークに接続されていないルーター）に到達した場合、そのデータグラムは通常のIPデータグラム処理手順に従って処理されます。宛先ルーター（宛先ネットワークがそのルーターに直接接続されている）に到達した場合、宛先ルーターは次のa、b、cのいずれかを実行します。

  1. If the local subnet has a broadcast capability, broadcast to all hosts in the network and let the hosts perform address filtering.
  2. If the local subnet does not support broadcast, form a local subnet packet for each destination host in the SDBM datagram and transmit into the network.
  3. If the local subnet supports reliable layer 2 multi-address capability as provided by MIL-STD-188-220() networks, use a layer 2 multi-address frame to deliver the datagram to addresses found in the IP option field.
  1. ローカルサブネットにブロードキャスト機能がある場合は、ネットワーク内のすべてのホストにブロードキャストし、ホストにアドレスのフィルタリングを行わせます。
  2. ローカルサブネットがブロードキャストをサポートしていない場合は、SDBMデータグラム内の各宛先ホストについてローカルサブネットのパケットを作り、ネットワークに送信します。
  3. ローカルサブネットが、MIL-STD-188-220()のネットワークが提供するような信頼性のあるレイヤー2の複数アドレス機能をサポートしている場合は、レイヤー2の複数アドレスフレームを使って、IPオプションフィールドにあるアドレスにデータグラムを配送します。

Reception of SDBM datagrams

SDBMデータグラムの受信

In processing received SDBM datagrams, receiving hosts shall look inside the IP option field for their address. Processing shall continue only if the host's IP address is found inside this option field. Thus the source host has explicit control over which hosts will process its datagrams. Since SDBM uses a broadcast address in its destination field, the SDBM can only be used with UDP (Reference [4]) and not TCP (Reference [5]) as the TCP supports only point-to-point connections and not point-to-multi-point.

受信したSDBMデータグラムを処理する際、受信ホストはIPオプションフィールドの中に自身のアドレスがあるかどうかを調べます。ホストのIPアドレスがこのオプションフィールドの中に見つかった場合にのみ、処理を続行します。これにより、送信元ホストは、どのホストが自身のデータグラムを処理するかを明示的に制御できます。SDBMは宛先フィールドにブロードキャストアドレスを使うので、SDBMはUDP（参考文献[4]）でのみ使用でき、TCP（参考文献[5]）では使用できません。TCPはポイントツーポイントのコネクションのみをサポートし、ポイントツーマルチポイントはサポートしないためです。
