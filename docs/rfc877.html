RFC 877

Standard for the Transmission of IP Datagrams Over Public Data Networks

RFC 877

公衆データネットワーク上でのIPデータグラムの伝送に関する標準

Abstract

概要

This RFC specifies a standard adopted by CSNET, the VAN gateway, and other organizations for the transmission of IP datagrams over the X.25-based public data networks.

このRFCは、X.25ベースの公衆データネットワーク上でIPデータグラムを伝送するために、CSNET、VANゲートウェイ、その他の組織が採用している標準を規定します。

An X.25 virtual circuit is opened on demand when a datagram arrives at the network interface for transmission. A virtual circuit is closed after some period of inactivity (the length of the period depends on the cost associated with an open virtual circuit). A virtual circuit may also be closed if the interface runs out of virtual circuits. An algorithm for managing virtual circuits during peak demand is given in [1].

X.25の仮想回線（virtual circuit）は、送信するデータグラムがネットワークインターフェイスに到着したときに、必要に応じて開設します。仮想回線は、一定期間何も動きがなければ閉じます（その期間の長さは、開いている仮想回線にかかるコストによって決まります）。インターフェイスの仮想回線が足りなくなった場合にも、仮想回線を閉じることがあります。需要のピーク時に仮想回線を管理するアルゴリズムは[1]で示しています。

STANDARDS

標準

1.1
The first octet in the Call User Data Field (the first data octet in the Call Request packet) is used for protocol demultiplexing. The value hex CC (binary 11001100, decimal 204) is used to mean INTERNET PROTOCOL.
1.2
IP datagrams are sent as X.25 "complete packet sequences". That is, datagrams begin on packet boundaries and the M bit ("more data") is used for datagrams that are larger than one packet. There are no additional headers or other data in the packets.
1.3
Unless a larger packet size is negotiated, the maximum size of an IP datagram transmitted over X.25 is 576 octets. If two sites negotiate a large X.25 packet size (for example, 1024 octets), an IP datagram of that size is allowed.
1.4
Either site may close a virtual circuit. If the virtual circuit is closed or reset while a datagram is being transmitted, the datagram is lost.
1.1
Call User Dataフィールドの最初のオクテット（Call Requestパケットの最初のデータオクテット）は、プロトコルの多重分離に使用します。値16進数CC（2進数11001100、10進数204）は、INTERNET PROTOCOLを意味します。
1.2
IPデータグラムは、X.25の「完全パケットシーケンス（complete packet sequence）」として送信します。つまり、データグラムはパケットの境界から始まり、1パケットより大きいデータグラムにはMビット（「more data」）を使用します。パケット内には追加のヘッダーやその他のデータはありません。
1.3
より大きなパケットサイズをネゴシエートしない限り、X.25上で伝送するIPデータグラムの最大サイズは576オクテットです。2つのサイトが大きなX.25パケットサイズ（たとえば1024オクテット）をネゴシエートした場合は、そのサイズのIPデータグラムが許されます。
1.4
どちらのサイトも仮想回線を閉じることができます。データグラムの送信中に仮想回線が閉じられたりリセットされたりした場合、そのデータグラムは失われます。

GENERAL REMARKS

一般的な注意事項

2.1
Protocols above IP, such as TCP, do not affect this standard. In particular, no attempt is made to open X.25 virtual circuits corresponding to TCP connections.
2.2
Features of X.25 not discussed in this document are not used. For example, interrupt packets and the D bit (indicating end-to-end significance) are not used.
2.3
Negotiable features (facilities) of X.25 are allowed. For example, sites are free to negotiate larger packet and window sizes.
2.4
Some sites, such as CSNET sites, may attempt to open multiple virtual circuits to a single site. Sites should attempt to handle such incoming calls gracefully: transmit on the additional circuits if possible and accept incoming datagrams from them, but do not accept the CALL REQUEST, only to immediately close the connection or ignore datagrams transmitted on such circuits.
2.1
TCPなど、IPより上位のプロトコルはこの標準に影響しません。特に、TCPコネクションに対応するX.25仮想回線を開こうとはしません。
2.2
この文書で説明していないX.25の機能は使用しません。たとえば、割り込みパケットやDビット（エンドツーエンドの意味を持つことを示す）は使用しません。
2.3
X.25のネゴシエート可能な機能（ファシリティー）は使用してかまいません。たとえば、サイトはより大きなパケットサイズやウィンドウサイズを自由にネゴシエートできます。
2.4
CSNETのサイトなど、一部のサイトは、1つのサイトに対して複数の仮想回線を開こうとすることがあります。サイトは、そのような着信呼をうまく処理するよう努めるべきです。可能であれば追加の回線でも送信し、そこから着信したデータグラムを受け入れてください。CALL REQUESTを受け入れておきながら、すぐにコネクションを閉じたり、そのような回線で送信されたデータグラムを無視したりしてはいけません。
