Multilinear Galois Mode (MGM)

RFC 9058

多重線形ガロアモード（MGM）

Abstract

概要

Multilinear Galois Mode (MGM) is an Authenticated Encryption with Associated Data (AEAD) block cipher mode based on the Encrypt-then-MAC (EtM) principle. MGM is defined for use with 64-bit and 128-bit block ciphers.

多重線形ガロアモード（Multilinear Galois Mode、MGM）は、Encrypt-then-MAC（EtM）原則に基づく、関連データ付き認証付き暗号（Authenticated Encryption with Associated Data、AEAD）のブロック暗号モードです。MGMは、64ビットおよび128ビットのブロック暗号で使用するために定義されています。

MGM has been standardized in Russia. It is used as an AEAD mode for the GOST block cipher algorithms in many protocols, e.g., TLS 1.3 and IPsec. This document provides a reference for MGM to enable review of the mechanisms in use and to make MGM available for use with any block cipher.

MGMはロシアで標準化されています。MGMは、TLS 1.3やIPsecなどの多くのプロトコルで、GOSTブロック暗号アルゴリズムのAEADモードとして使用されています。この文書は、使用されているメカニズムをレビューできるようにし、MGMを任意のブロック暗号で使用できるようにするために、MGMのリファレンスを提供します。

1. Introduction

1. はじめに

Multilinear Galois Mode (MGM) is an Authenticated Encryption with Associated Data (AEAD) block cipher mode based on EtM principle. MGM is defined for use with 64-bit and 128-bit block ciphers. The MGM design principles can easily be applied to other block sizes.

多重線形ガロアモード（MGM）は、EtM原則に基づく、関連データ付き認証付き暗号（AEAD）のブロック暗号モードです。MGMは、64ビットおよび128ビットのブロック暗号で使用するために定義されています。MGMの設計原則は、他のブロックサイズにも容易に適用できます。

MGM has been standardized in Russia [AUTH-ENC-BLOCK-CIPHER]. It is used as an AEAD mode for the GOST block cipher algorithms in many protocols, e.g., TLS 1.3 and IPsec. This document provides a reference for MGM to enable review of the mechanisms in use and to make MGM available for use with any block cipher.

MGMはロシアで標準化されています[AUTH-ENC-BLOCK-CIPHER]。MGMは、TLS 1.3やIPsecなどの多くのプロトコルで、GOSTブロック暗号アルゴリズムのAEADモードとして使用されています。この文書は、使用されているメカニズムをレビューできるようにし、MGMを任意のブロック暗号で使用できるようにするために、MGMのリファレンスを提供します。

This document does not have IETF consensus and does not imply IETF support for MGM.

この文書はIETFのコンセンサスを得たものではなく、IETFがMGMを支持することを意味するものでもありません。

3. Basic Terms and Definitions

3. 基本的な用語と定義

This document uses the following terms and definitions for the sets and operations on the elements of these sets:

この文書では、集合と、その集合の要素に対する演算について、次の用語と定義を使用します。

V*
The set of all bit strings of a finite length (hereinafter referred to as strings), including the empty string; substrings and string components are enumerated from right to left starting from zero.
V_s
The set of all bit strings of length s, where s is a non-negative integer. For s = 0, the V_0 consists of a single empty string.
|X|
The bit length of the bit string X (if X is an empty string, then |X| = 0).
X || Y
Concatenation of strings X and Y both belonging to V*, i.e., a string from V_{|X|+|Y|}, where the left substring from V_{|X|} is equal to X, and the right substring from V_{|Y|} is equal to Y.
a^s
The string in V_s that consists of s 'a' bits.
(xor)
Exclusive-or of two bit strings of the same length.
Z_{2^s}
Ring of residues modulo 2^s.
MSB_i

V_s -> V_i

The transformation that maps the string X = (x_{s-1}, ... , x_0) in V_s into the string MSB_i(X) = (x_{s-1}, ... , x_{s-i}) in V_i, i <= s (most significant bits).

Int_s

V_s -> Z_{2^s}

The transformation that maps the string X = (x_{s-1}, ... , x_0) in V_s, s > 0, into the integer Int_s(X) = 2^{s-1} * x_{s-1} + ... + 2 * x_1 + x_0 (the interpretation of the bit string as an integer).

Vec_s

Z_{2^s} -> V_s

The transformation inverse to the mapping Int_s (the interpretation of an integer as a bit string).

E_K

V_n -> V_n

The block cipher permutation under the key K in V_k.

k
The bit length of the block cipher key.
n
The block size of the block cipher (in bits).
len

V_s -> V_{n/2}

The transformation that maps a string X in V_s, 0 <= s <= 2^{n/2} - 1, into the string len(X) = Vec_{n/2}(|X|) in V_{n/2}, where n is the block size of the used block cipher.

[+]
The addition operation in Z_{2^{n/2}}, where n is the block size of the used block cipher.
(x)
The transformation that maps two strings, X = (x_{n-1}, ... , x_0) in V_n and Y = (y_{n-1}, ... , y_0), in V_n into the string Z = X (x) Y = (z_{n-1}, ... , z_0) in V_n; the string Z corresponds to the polynomial Z(w) = z_{n-1} * w^{n-1} + ... + z_1 * w + z_0, which is the result of multiplying the polynomials X(w) = x_{n-1} * w^{n-1} + ... + x_1 * w + x_0 and Y(w) = y_{n-1} * w^{n-1} + ... + y_1 * w + y_0 in the field GF(2^n), where n is the block size of the used block cipher; if n = 64, then the field polynomial is equal to f(w) = w^64 + w^4 + w^3 + w + 1; if n = 128, then the field polynomial is equal to f(w) = w^128 + w^7 + w^2 + w + 1.
incr_l

V_n -> V_n

The transformation that maps an n-byte string A = L || R into the n-byte string incr_l(A) = Vec_{n/2}(Int_{n/2}(L) [+] 1) || R, where L and R are n/2-byte strings.

incr_r

V_n -> V_n

The transformation that maps an n-byte string A = L || R into the n-byte string incr_r(A) = L || Vec_{n/2}(Int_{n/2}(R) [+] 1), where L and R are n/2-byte strings.

V*
空文字列を含む、有限長のすべてのビット列の集合（以下、単に文字列と呼びます）。部分文字列と文字列の成分には、右から左に0から始まる番号を付けます。
V_s
長さsのすべてのビット列の集合。ここで、sは非負整数です。s = 0の場合、V_0は単一の空文字列からなります。
|X|
ビット列Xのビット長（Xが空文字列の場合、|X| = 0）。
X || Y
どちらもV*に属する文字列XとYの連結。すなわち、V_{|X|+|Y|}に属する文字列で、V_{|X|}に属する左側の部分文字列がXに等しく、V_{|Y|}に属する右側の部分文字列がYに等しいものです。
a^s
s個の'a'ビットからなる、V_sに属する文字列。
(xor)
同じ長さの2つのビット列の排他的論理和。
Z_{2^s}
2^sを法とする剰余環。
MSB_i

V_s -> V_i

V_sに属する文字列X = (x_{s-1}, ... , x_0)を、V_iに属する文字列MSB_i(X) = (x_{s-1}, ... , x_{s-i})に写す変換（i <= s）（最上位ビット）。

Int_s

V_s -> Z_{2^s}

V_sに属する文字列X = (x_{s-1}, ... , x_0)（s > 0）を、整数Int_s(X) = 2^{s-1} * x_{s-1} + ... + 2 * x_1 + x_0に写す変換（ビット列を整数として解釈するもの）。

Vec_s

Z_{2^s} -> V_s

写像Int_sの逆変換（整数をビット列として解釈するもの）。

E_K

V_n -> V_n

V_kに属する鍵Kのもとでのブロック暗号の置換。

k
ブロック暗号の鍵のビット長。
n
ブロック暗号のブロックサイズ（ビット単位）。
len

V_s -> V_{n/2}

V_sに属する文字列X（0 <= s <= 2^{n/2} - 1）を、V_{n/2}に属する文字列len(X) = Vec_{n/2}(|X|)に写す変換。ここで、nは使用するブロック暗号のブロックサイズです。

[+]
Z_{2^{n/2}}における加算演算。ここで、nは使用するブロック暗号のブロックサイズです。
(x)
V_nに属する2つの文字列X = (x_{n-1}, ... , x_0)とY = (y_{n-1}, ... , y_0)を、V_nに属する文字列Z = X (x) Y = (z_{n-1}, ... , z_0)に写す変換。文字列Zは多項式Z(w) = z_{n-1} * w^{n-1} + ... + z_1 * w + z_0に対応し、これは体GF(2^n)において多項式X(w) = x_{n-1} * w^{n-1} + ... + x_1 * w + x_0とY(w) = y_{n-1} * w^{n-1} + ... + y_1 * w + y_0を乗算した結果です。ここで、nは使用するブロック暗号のブロックサイズです。n = 64の場合、体の多項式はf(w) = w^64 + w^4 + w^3 + w + 1です。n = 128の場合、体の多項式はf(w) = w^128 + w^7 + w^2 + w + 1です。
incr_l

V_n -> V_n

nバイトの文字列A = L || Rを、nバイトの文字列incr_l(A) = Vec_{n/2}(Int_{n/2}(L) [+] 1) || Rに写す変換。ここで、LとRはn/2バイトの文字列です。

incr_r

V_n -> V_n

nバイトの文字列A = L || Rを、nバイトの文字列incr_r(A) = L || Vec_{n/2}(Int_{n/2}(R) [+] 1)に写す変換。ここで、LとRはn/2バイトの文字列です。

4. Specification

4. 仕様

An additional parameter that defines the functioning of MGM is the bit length S of the authentication tag, 32 <= S <= n. The value of S MUST be fixed for a particular protocol. The choice of the value S involves a trade-off between message expansion and the forgery probability.

MGMの動作を定める追加のパラメーターとして、認証タグのビット長S（32 <= S <= n）があります。Sの値は、個々のプロトコルごとに固定されなければなりません（MUST）。Sの値の選択には、メッセージの拡大と偽造確率の間のトレードオフが伴います。

4.1. MGM Encryption and Tag Generation Procedure

4.1. MGMの暗号化とタグ生成の手順

The MGM encryption and tag generation procedure takes the following parameters as inputs:

MGMの暗号化とタグ生成の手順は、次のパラメーターを入力として受け取ります。

  1. Encryption key K in V_k.
  2. Initial counter nonce ICN in V_{n-1}.
  3. Associated authenticated data A, 0 <= |A| < 2^{n/2}. If |A| > 0, then A = A_1 || ... || A*_h, A_j in V_n, for j = 1, ... , h - 1, A*_h in V_t, 1 <= t <= n. If |A| = 0, then by definition A*_h is empty, and the h and t parameters are set as follows: h = 0, t = n. The associated data is authenticated but is not encrypted.
  4. Plaintext P, 0 <= |P| < 2^{n/2}. If |P| > 0, then P = P_1 || ... || P*_q, P_i in V_n, for i = 1, ... , q - 1, P*_q in V_u, 1 <= u <= n. If |P| = 0, then by definition P*_q is empty, and the q and u parameters are set as follows: q = 0, u = n.
  1. V_kに属する暗号化鍵K。
  2. V_{n-1}に属する初期カウンターノンスICN。
  3. 関連認証データA（0 <= |A| < 2^{n/2}）。|A| > 0の場合、A = A_1 || ... || A*_hであり、j = 1, ... , h - 1についてA_jはV_nに属し、A*_hはV_tに属します（1 <= t <= n）。|A| = 0の場合、定義によりA*_hは空であり、パラメーターhとtは次のように設定されます：h = 0、t = n。関連データは認証されますが、暗号化はされません。
  4. 平文P（0 <= |P| < 2^{n/2}）。|P| > 0の場合、P = P_1 || ... || P*_qであり、i = 1, ... , q - 1についてP_iはV_nに属し、P*_qはV_uに属します（1 <= u <= n）。|P| = 0の場合、定義によりP*_qは空であり、パラメーターqとuは次のように設定されます：q = 0、u = n。

The MGM encryption and tag generation procedure outputs the following parameters:

MGMの暗号化とタグ生成の手順は、次のパラメーターを出力します。

  1. Initial counter nonce ICN.
  2. Associated authenticated data A.
  3. Ciphertext C in V_{|P|}.
  4. Authentication tag T in V_S.
  1. 初期カウンターノンスICN。
  2. 関連認証データA。
  3. V_{|P|}に属する暗号文C。
  4. V_Sに属する認証タグT。

The MGM encryption and tag generation procedure consists of the following steps:

MGMの暗号化とタグ生成の手順は、次のステップからなります。 

   +----------------------------------------------------------------+
   |  MGM-Encrypt(K, ICN, A, P)                                     |
   |----------------------------------------------------------------|
   |  1. Encryption step:                                           |
   |      - if |P| = 0 then                                         |
   |            - C*_q = P*_q                                       |
   |            - C = P                                             |
   |      - else                                                    |
   |            - Y_1 = E_K(0^1 || ICN),                            |
   |            - For i = 2, 3, ... , q do                          |
   |                    Y_i = incr_r(Y_{i-1}),                      |
   |            - For i = 1, 2, ... , q - 1 do                      |
   |                    C_i = P_i (xor) E_K(Y_i),                   |
   |            - C*_q = P*_q (xor) MSB_u(E_K(Y_q)),                |
   |            - C = C_1 || ... || C*_q.                           |
   |                                                                |
   |  2. Padding step:                                              |
   |      - A_h = A*_h || 0^{n-t},                                  |
   |      - C_q = C*_q || 0^{n-u}.                                  |
   |                                                                |
   |  3. Authentication tag T generation step:                      |
   |      - Z_1 = E_K(1^1 || ICN),                                  |
   |      - sum = 0^n,                                              |
   |      - For i = 1, 2, ..., h do                                 |
   |              H_i = E_K(Z_i),                                   |
   |              sum = sum (xor) ( H_i (x) A_i ),                  |
   |              Z_{i+1} = incr_l(Z_i),                            |
   |      - For j = 1, 2, ..., q do                                 |
   |              H_{h+j} = E_K(Z_{h+j}),                           |
   |              sum = sum (xor) ( H_{h+j} (x) C_j ),              |
   |              Z_{h+j+1} = incr_l(Z_{h+j}),                      |
   |      - H_{h+q+1} = E_K(Z_{h+q+1}),                             |
   |      - T = MSB_S(E_K(sum (xor) ( H_{h+q+1} (x)                 |
   |                       ( len(A) || len(C) ) ))).                |
   |                                                                |
   |  4. Return (ICN, A, C, T).                                     |
   +----------------------------------------------------------------+

   +----------------------------------------------------------------+
   |  MGM-Encrypt(K, ICN, A, P)                                     |
   |----------------------------------------------------------------|
   |  1. Encryption step:                                           |
   |      - if |P| = 0 then                                         |
   |            - C*_q = P*_q                                       |
   |            - C = P                                             |
   |      - else                                                    |
   |            - Y_1 = E_K(0^1 || ICN),                            |
   |            - For i = 2, 3, ... , q do                          |
   |                    Y_i = incr_r(Y_{i-1}),                      |
   |            - For i = 1, 2, ... , q - 1 do                      |
   |                    C_i = P_i (xor) E_K(Y_i),                   |
   |            - C*_q = P*_q (xor) MSB_u(E_K(Y_q)),                |
   |            - C = C_1 || ... || C*_q.                           |
   |                                                                |
   |  2. Padding step:                                              |
   |      - A_h = A*_h || 0^{n-t},                                  |
   |      - C_q = C*_q || 0^{n-u}.                                  |
   |                                                                |
   |  3. Authentication tag T generation step:                      |
   |      - Z_1 = E_K(1^1 || ICN),                                  |
   |      - sum = 0^n,                                              |
   |      - For i = 1, 2, ..., h do                                 |
   |              H_i = E_K(Z_i),                                   |
   |              sum = sum (xor) ( H_i (x) A_i ),                  |
   |              Z_{i+1} = incr_l(Z_i),                            |
   |      - For j = 1, 2, ..., q do                                 |
   |              H_{h+j} = E_K(Z_{h+j}),                           |
   |              sum = sum (xor) ( H_{h+j} (x) C_j ),              |
   |              Z_{h+j+1} = incr_l(Z_{h+j}),                      |
   |      - H_{h+q+1} = E_K(Z_{h+q+1}),                             |
   |      - T = MSB_S(E_K(sum (xor) ( H_{h+q+1} (x)                 |
   |                       ( len(A) || len(C) ) ))).                |
   |                                                                |
   |  4. Return (ICN, A, C, T).                                     |
   +----------------------------------------------------------------+

The ICN value for each message that is encrypted under the given key K must be chosen in a unique manner.

与えられた鍵Kのもとで暗号化される各メッセージのICN値は、一意になるように選択しなければなりません。

Users who do not wish to encrypt plaintext can provide a string P of zero length. Users who do not wish to authenticate associated data can provide a string A of zero length. The length of the associated data A and of the plaintext P MUST be such that 0 < |A| + |P| < 2^{n/2}.

平文を暗号化したくないユーザーは、長さ0の文字列Pを与えることができます。関連データを認証したくないユーザーは、長さ0の文字列Aを与えることができます。関連データAと平文Pの長さは、0 < |A| + |P| < 2^{n/2}を満たさなければなりません（MUST）。

4.2. MGM Decryption and Tag Verification Check Procedure

4.2. MGMの復号とタグ検証チェックの手順

The MGM decryption and tag verification procedure takes the following parameters as inputs:

MGMの復号とタグ検証の手順は、次のパラメーターを入力として受け取ります。

  1. Encryption key K in V_k.
  2. Initial counter nonce ICN in V_{n-1}.
  3. Associated authenticated data A, 0 <= |A| < 2^{n/2}. If |A| > 0, then A = A_1 || ... || A*_h, A_j in V_n, for j = 1, ... , h - 1, A*_h in V_t, 1 <= t <= n. If |A| = 0, then by definition A*_h is empty, and the h and t parameters are set as follows: h = 0, t = n. The associated data is authenticated but is not encrypted.
  4. Ciphertext C, 0 <= |C| < 2^{n/2}. If |C| > 0, then C = C_1 || ... || C*_q, C_i in V_n, for i = 1, ... , q - 1, C*_q in V_u, 1 <= u <= n. If |C| = 0, then by definition C*_q is empty, and the q and u parameters are set as follows: q = 0, u = n.
  5. Authentication tag T in V_S.
  1. V_kに属する暗号化鍵K。
  2. V_{n-1}に属する初期カウンターノンスICN。
  3. 関連認証データA（0 <= |A| < 2^{n/2}）。|A| > 0の場合、A = A_1 || ... || A*_hであり、j = 1, ... , h - 1についてA_jはV_nに属し、A*_hはV_tに属します（1 <= t <= n）。|A| = 0の場合、定義によりA*_hは空であり、パラメーターhとtは次のように設定されます：h = 0、t = n。関連データは認証されますが、暗号化はされません。
  4. 暗号文C（0 <= |C| < 2^{n/2}）。|C| > 0の場合、C = C_1 || ... || C*_qであり、i = 1, ... , q - 1についてC_iはV_nに属し、C*_qはV_uに属します（1 <= u <= n）。|C| = 0の場合、定義によりC*_qは空であり、パラメーターqとuは次のように設定されます：q = 0、u = n。
  5. V_Sに属する認証タグT。

The MGM decryption and tag verification procedure outputs FAIL or the following parameters:

MGMの復号とタグ検証の手順は、FAILまたは次のパラメーターを出力します。

  1. Associated authenticated data A.
  2. Plaintext P in V_{|C|}.
  1. 関連認証データA。
  2. V_{|C|}に属する平文P。

The MGM decryption and tag verification procedure consists of the following steps:

MGMの復号とタグ検証の手順は、次のステップからなります。 

   +----------------------------------------------------------------+
   |  MGM-Decrypt(K, ICN, A, C, T)                                  |
   |----------------------------------------------------------------|
   |  1. Padding step:                                              |
   |      - A_h = A*_h || 0^{n-t},                                  |
   |      - C_q = C*_q || 0^{n-u}.                                  |
   |                                                                |
   |  2. Authentication tag T verification step:                    |
   |      - Z_1 = E_K(1^1 || ICN),                                  |
   |      - sum = 0^n,                                              |
   |      - For i = 1, 2, ..., h do                                 |
   |              H_i = E_K(Z_i),                                   |
   |              sum = sum (xor) ( H_i (x) A_i ),                  |
   |              Z_{i+1} = incr_l(Z_i),                            |
   |      - For j = 1,  2, ..., q do                                |
   |              H_{h+j} = E_K(Z_{h+j}),                           |
   |              sum = sum (xor) ( H_{h+j} (x) C_j ),              |
   |              Z_{h+j+1} = incr_l(Z_{h+j}),                      |
   |      - H_{h+q+1} = E_K(Z_{h+q+1}),                             |
   |      - T' = MSB_S(E_K(sum (xor) ( H_{h+q+1} (x)                |
   |                       ( len(A) || len(C) ) ))),                |
   |      - If T' != T then return FAIL.                            |
   |                                                                |
   |  3. Decryption step:                                           |
   |      - if |C| = 0 then                                         |
   |            - P = C                                             |
   |      - else                                                    |
   |            - Y_1 = E_K(0^1 || ICN),                            |
   |            - For i = 2, 3, ... , q do                          |
   |                    Y_i = incr_r(Y_{i-1}),                      |
   |            - For i = 1, 2, ... , q - 1 do                      |
   |                    P_i = C_i (xor) E_K(Y_i),                   |
   |            - P*_q = C*_q (xor) MSB_u(E_K(Y_q)),                |
   |            - P = P_1 || ... || P*_q.                           |
   |                                                                |
   |  4. Return (A, P).                                             |
   +----------------------------------------------------------------+

   +----------------------------------------------------------------+
   |  MGM-Decrypt(K, ICN, A, C, T)                                  |
   |----------------------------------------------------------------|
   |  1. Padding step:                                              |

   |                                                                |
   |  2. Authentication tag T verification step:                    |

   |              Z_{i+1} = incr_l(Z_i),                            |
   |      - For j = 1,  2, ..., q do                                |
   |              H_{h+j} = E_K(Z_{h+j}),                           |
   |              sum = sum (xor) ( H_{h+j} (x) C_j ),              |
   |              Z_{h+j+1} = incr_l(Z_{h+j}),                      |
   |      - H_{h+q+1} = E_K(Z_{h+q+1}),                             |
   |      - T' = MSB_S(E_K(sum (xor) ( H_{h+q+1} (x)                |
   |                       ( len(A) || len(C) ) ))),                |
   |      - If T' != T then return FAIL.                            |
   |                                                                |
   |  3. Decryption step:                                           |
   |      - if |C| = 0 then                                         |
   |            - P = C                                             |
   |      - else                                                    |
   |            - Y_1 = E_K(0^1 || ICN),                            |
   |            - For i = 2, 3, ... , q do                          |
   |                    Y_i = incr_r(Y_{i-1}),                      |
   |            - For i = 1, 2, ... , q - 1 do                      |
   |                    P_i = C_i (xor) E_K(Y_i),                   |
   |            - P*_q = C*_q (xor) MSB_u(E_K(Y_q)),                |
   |            - P = P_1 || ... || P*_q.                           |

関連データAと暗号文Cの長さは、0 < |A| + |C| < 2^{n/2}を満たさなければなりません（MUST）。

5. Rationale

5. 根拠

MGM was originally proposed in [PDMODE].

MGMは、もともと[PDMODE]で提案されました。

From the operational point of view, MGM is designed to be parallelizable, inverse free, and online and is also designed to provide availability of precomputations.

運用の観点からは、MGMは、並列化可能で、逆関数が不要（inverse free）で、オンライン処理が可能であるように設計されており、さらに事前計算を利用できるようにも設計されています。

Parallelizability of MGM is achieved due to its counter-type structure and the usage of the multilinear function for authentication. Indeed, both encryption blocks E_K(Y_i) and authentication blocks H_i are produced in the counter mode manner, and the multilinear function determined by H_i is parallelizable in itself. Additionally, the counter-type structure of the mode provides the inverse-free property.

MGMの並列化可能性は、カウンター型の構造と、認証に多重線形関数を使用することによって実現されています。実際、暗号化ブロックE_K(Y_i)と認証ブロックH_iはどちらもカウンターモードと同じ方法で生成され、H_iによって決まる多重線形関数はそれ自体が並列化可能です。さらに、このモードのカウンター型の構造により、逆関数が不要という性質も得られます。

The online property means the possibility of processing messages even if it is not completely received (so its length is unknown). To provide this property, MGM uses blocks E_K(Y_i) and H_i, which are produced based on two independent source blocks Y_i and Z_i.

オンライン処理が可能という性質は、メッセージが完全に受信されていない（したがってその長さが未知である）場合でも、メッセージを処理できることを意味します。この性質を実現するために、MGMは、2つの独立した元ブロックY_iとZ_iに基づいて生成されるブロックE_K(Y_i)とH_iを使用します。

Availability of precomputations for MGM means the possibility of calculating H_i and E_K(Y_i) even before data is retrieved. It holds again due to the usage of counters for calculating them.

MGMで事前計算を利用できるとは、データを取得する前であってもH_iとE_K(Y_i)を計算できることを意味します。これも、それらの計算にカウンターを使用していることによって成り立ちます。

6. Security Considerations

6. セキュリティーに関する考慮事項

The security properties of MGM are based on the following:

MGMのセキュリティー特性は、次のものに基づいています。

Different functions generating the counter values:
The functions incr_r and incr_l are chosen to minimize intersection (if it happens) of counter values Y_i and Z_i.
Encryption of the multilinear function output:
It allows attacks based on padding and linear properties to be resisted (see [FERG05] for details).
Multilinear function for authentication:
It allows the small subgroup attacks to be resisted [SAAR12].
Encryption of the nonces (0^1 || ICN) and (1^1 || ICN):
The use of this encryption minimizes the number of plaintext/ciphertext pairs of blocks known to an adversary. It prevents attacks that need a substantial amount of such material (e.g., linear and differential cryptanalysis and side-channel attacks).
カウンター値を生成する異なる関数：
関数incr_rとincr_lは、カウンター値Y_iとZ_iの重なり（発生する場合）を最小にするように選ばれています。
多重線形関数の出力の暗号化：
これにより、パディングと線形性に基づく攻撃に耐えられます（詳細は[FERG05]を参照してください）。
認証のための多重線形関数：
これにより、小部分群攻撃に耐えられます[SAAR12]。
ノンス(0^1 || ICN)と(1^1 || ICN)の暗号化：
この暗号化を使用することで、敵対者に知られる平文と暗号文のブロックのペアの数が最小になります。これにより、そのような素材を大量に必要とする攻撃（たとえば、線形解読法、差分解読法、サイドチャネル攻撃）を防ぎます。

It is crucial to the security of MGM to use unique ICN values. Using the same ICN values for two different messages encrypted with the same key eliminates the security properties of this mode.

MGMのセキュリティーにとって、一意なICN値を使用することは極めて重要です。同じ鍵で暗号化される2つの異なるメッセージに同じICN値を使用すると、このモードのセキュリティー特性が失われます。

It is crucial for the security of MGM not to process empty plaintext and empty associated data at the same time. Otherwise, a tag becomes independent from a nonce value, leading to vulnerability to forgery attacks.

MGMのセキュリティーにとって、空の平文と空の関連データを同時に処理しないことは極めて重要です。そうしないと、タグがノンスの値に依存しなくなり、偽造攻撃に対して脆弱になります。

Security analysis for MGM with E_K being a random permutation was performed in [SEC-MGM]. More precisely, the bounds for confidentiality advantage (CA) and integrity advantage (IA) (for details, see [AEAD-LIMITS]) were obtained. According to these results, for an adversary making at most q encryption queries with the total length of plaintexts and associated data of at most s blocks, and allowed to output a forgery with the summary length of ciphertext and associated data of at most l blocks:

E_Kがランダム置換であるとした場合のMGMのセキュリティー解析が、[SEC-MGM]で行われました。より正確には、機密性の優位性（confidentiality advantage、CA）と完全性の優位性（integrity advantage、IA）の上界（詳細は[AEAD-LIMITS]を参照してください）が得られています。これらの結果によると、平文と関連データの合計長が最大sブロックの暗号化クエリーを最大q回行い、暗号文と関連データの合計長が最大lブロックの偽造を出力することが許されている敵対者に対して、次が成り立ちます。

CA <= ( 3( s + 4q )^2 )/ 2^n,

CA <= ( 3( s + 4q )^2 )/ 2^n,

IA <= ( 3( s + 4q + l + 3 )^2 )/ 2^n + 2/2^S,

IA <= ( 3( s + 4q + l + 3 )^2 )/ 2^n + 2/2^S,

where n is the block size and S is the authentication tag size.

ここで、nはブロックサイズ、Sは認証タグのサイズです。

These bounds can be used as guidelines on how to calculate confidentiality and integrity limits (for details, also see [AEAD-LIMITS]).

これらの上界は、機密性と完全性の制限を計算する方法のガイドラインとして使用できます（詳細は[AEAD-LIMITS]も参照してください）。
