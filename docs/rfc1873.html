RFC 1873

Message/External-Body Content-ID Access Type

RFC 1873

Message/External-BodyのContent-IDアクセスタイプ

Abstract

概要

When using MIME [MIME] to encapsulate a structured object that consist of many elements, for example an SGML [SGML] document, a single element may occur several times. An encapsulation normally maps each of the structured objects elements to a MIME entity. It is useful to include elements that occur multiple time exactly once. To accomplish that and to preserve the object structure it is desirable to unambiguously refer to another body part of the same message.

多数の要素からなる構造化オブジェクト、たとえばSGML [SGML]文書をMIME [MIME]でカプセル化する場合、1つの要素が何度も出現することがあります。カプセル化では通常、構造化オブジェクトの各要素をMIMEエンティティーに対応付けます。複数回出現する要素をちょうど1回だけ含められると便利です。それを実現しつつオブジェクトの構造を保つには、同じメッセージ内の別のボディーパートをあいまいさなく参照できることが望ましいです。

The existing MIME Content-Type Message/External-Body access-types allow a MIME entity (body-part) to refer to an object that is not in the message by specifying how to access that object. The Content-ID access method described in this document provides the capability to refer to an object within the message.

既存のMIMEのContent-Type Message/External-Bodyのアクセスタイプ（access-type）では、オブジェクトへのアクセス方法を指定することで、MIMEエンティティー（ボディーパート）がメッセージ内にないオブジェクトを参照できます。この文書で説明するContent-IDアクセス方法は、メッセージ内のオブジェクトを参照する機能を提供します。

Status of This Memo

このメモのステータス

This memo defines an Experimental Protocol for the Internet community. This memo does not specify an Internet standard of any kind. Discussion and suggestions for improvement are requested. Distribution of this memo is unlimited.

このメモは、インターネットコミュニティーのための実験的プロトコル（Experimental Protocol）を定義します。このメモは、いかなる種類のインターネット標準も規定しません。改善のための議論と提案を求めています。このメモの配布は無制限です。

1. Introduction

1. はじめに

Consider a MIME multipart entity several of whose body parts contain the same data (body) but different parameters or Content-* headers. Representing those body parts without duplicating the data in each one promotes efficient use of resources (bandwidth and storage space). To achieve these benefits an access-type is defined that permits one message part to refer to another one in the same message.

複数のボディーパートが同じデータ（本体）を含み、パラメーターやContent-*ヘッダーだけが異なる、MIMEのマルチパートエンティティーを考えてみてください。各ボディーパートでデータを重複させずにそれらのボディーパートを表現できれば、資源（帯域幅と記憶領域）を効率的に使えます。こうした利点を得るために、あるメッセージパートが同じメッセージ内の別のメッセージパートを参照できるようにするアクセスタイプを定義します。

2. The Content-ID Access Type

2. Content-IDアクセスタイプ

2.1. Registration Information

2.1. 登録情報

MIME access-type name:
content-id
Required parameters:
none
Optional parameters:
none
Published specification:
this document
Person & email address to contact for further information:
Ed Levinson <ELevinson@accurate.com>
Additional requirements:

The content-id header of the access-type=content-id MIME entity must match (be identical to) exactly one content-id in the same message, excluding other access-type=content-id entities. Thus, the content-id access type can only occur within a multipart message and can refer to another body part anywhere in the same message.

A MIME User Agent (MUA) constructs the resultant MIME body part as described below. We call the access-type=content-id MIME entity the referring body part and the MIME body part to which it refers, the one with the matching content-id, the referenced body part. The MIME entity that results from content-id access type consists of:

MIMEアクセスタイプ名：
content-id
必須パラメーター：
なし
省略可能なパラメーター：
なし
公開された仕様：
この文書
詳細情報の問い合わせ先の人物と電子メールアドレス：
Ed Levinson <ELevinson@accurate.com>
追加の要件：

access-type=content-idであるMIMEエンティティーのcontent-idヘッダーは、他のaccess-type=content-idエンティティーを除いて、同じメッセージ内のちょうど1つのcontent-idと一致（同一である）しなければなりません。したがって、content-idアクセスタイプはマルチパートメッセージ内でのみ出現でき、同じメッセージ内の任意の場所にある別のボディーパートを参照できます。

MIMEユーザーエージェント（MUA）は、結果となるMIMEボディーパートを以下のように構築します。access-type=content-idであるMIMEエンティティーを参照元ボディーパート（referring body part）、それが参照するMIMEボディーパート（content-idが一致するもの）を参照先ボディーパート（referenced body part）と呼びます。content-idアクセスタイプの結果となるMIMEエンティティーは、次のもので構成されます。

  1. the referenced body part's content-type header,
  2. the referring body part's headers except its content-type header,
  3. any headers in the referenced body part not in the referring one,
  4. the line separating the headers from the body, and
  5. the referenced body part's body.
  1. 参照先ボディーパートのcontent-typeヘッダー
  2. 参照元ボディーパートの、content-typeヘッダーを除くヘッダー
  3. 参照先ボディーパートにあって参照元ボディーパートにないヘッダー
  4. ヘッダーと本体とを区切る行
  5. 参照先ボディーパートの本体

2.2. Example Usage

2.2. 使用例

The following example shows a message that consists of two identical images.

次の例は、2つの同一の画像からなるメッセージを示しています。

            MIME-Version: 1.0
            Content-Type: Multipart/Mixed;
               boundary=tiger-lily

            --tiger-lily
            Content-Type: image/jpeg
            Content-ID: <950323.1552@XIson.com>

            AAAcdb...
            --tiger-lily
            Content-type: Message/External-Body;
               access-type=content-id
            Content-ID: <950323.1552@XIson.com>
            Content-Description:
               This body part is duplicated by reference

            --tiger-lily--

            MIME-Version: 1.0
            Content-Type: Multipart/Mixed;
               boundary=tiger-lily

            --tiger-lily
            Content-Type: image/jpeg
            Content-ID: <950323.1552@XIson.com>

            AAAcdb...
            --tiger-lily
            Content-type: Message/External-Body;
               access-type=content-id
            Content-ID: <950323.1552@XIson.com>
            Content-Description:
               This body part is duplicated by reference

            --tiger-lily--

The equivalent MIME entity for the second body part is:

2つ目のボディーパートと同等のMIMEエンティティーは次のとおりです。

            --tiger-lily
            Content-Type: image/jpeg
            Content-ID: <950323.1552@XIson.com>
            Content-Description:
               This body part is duplicated by reference

            AAAcdb...
            --tiger-lily

            --tiger-lily
            Content-Type: image/jpeg
            Content-ID: <950323.1552@XIson.com>
            Content-Description:
               This body part is duplicated by reference

            AAAcdb...
            --tiger-lily

3. Security Considerations

3. セキュリティーに関する考慮事項

The content-id access-type does not impact the security of messages or systems. The referenced MIME entity may have security implications.

content-idアクセスタイプは、メッセージやシステムのセキュリティーに影響を与えません。参照先のMIMEエンティティーには、セキュリティー上の影響がある場合があります。
