Simple Fixes to the IP Flow Information Export (IPFIX) Entities IANA Registry

RFC 9710

IP Flow Information Export（IPFIX）エンティティーのIANAレジストリーに対する簡単な修正

Abstract

概要

This document provides simple fixes to the IANA "IP Flow Information Export (IPFIX) Entities" registry. Specifically, this document provides updates to fix shortcomings in the description of some Information Elements (IEs), to ensure a consistent structure when citing an existing IANA registry, and to fix broken pointers, orphaned section references, etc. The updates are also meant to bring some consistency among the entries of the registry.

この文書は、IANAの「IP Flow Information Export (IPFIX) Entities」レジストリーに対する簡単な修正を提供します。具体的には、この文書は、一部の情報要素（Information Element、IE）の説明の不備を修正し、既存のIANAレジストリーを引用する際の構造の一貫性を確保し、壊れたポインターや参照先のないセクション参照などを修正するための更新を提供します。これらの更新は、レジストリーのエントリー間にある程度の一貫性をもたらすことも目的としています。

1. Introduction

1. はじめに

When the Operations and Management Area Working Group (OPSAWG) was considering [RFC9565], which obsoletes [RFC7125], the WG realized that some parts of the IANA "IP Flow Information Export (IPFIX) Entities" registry [IANA-IPFIX] were not up to date. This document updates the IANA registry and brings some consistency among the entries of the registry.

運用・管理エリアワーキンググループ（OPSAWG）が、[RFC7125]を廃止する[RFC9565]を検討していたとき、WGは、IANAの「IP Flow Information Export (IPFIX) Entities」レジストリー[IANA-IPFIX]の一部が最新の状態になっていないことに気づきました。この文書は、このIANAレジストリーを更新し、レジストリーのエントリー間にある程度の一貫性をもたらします。

As discussed with IANA during the development of [RFC9487], the "Additional Information" entry in [IANA-IPFIX] should contain a link to an existing registry, when applicable, as opposed to having:

[RFC9487]の策定中にIANAと議論したとおり、[IANA-IPFIX]の「Additional Information」エントリーには、該当する場合、次のようにするのではなく、既存のレジストリーへのリンクを含めるべきです。

  • A link to an existing registry in the "Description" entry.

  • The registry detailed values repeated in the "Description" entry. This practice has the drawback that the description must be updated each time the registry is updated.

  • 「Description」エントリーに既存のレジストリーへのリンクを含める。

  • 「Description」エントリーにレジストリーの詳細な値を繰り返し記載する。このやり方には、レジストリーが更新されるたびに説明も更新しなければならないという欠点があります。

Therefore, this document lists a set of simple fixes to the IPFIX registry [IANA-IPFIX]. These fixes are classified as follows:

したがって、この文書は、IPFIXレジストリー[IANA-IPFIX]に対する一連の簡単な修正を列挙します。これらの修正は次のように分類されます。

  • Updates to fix a shortcoming in the description of an IE (Section 4).

  • Updates to include a pointer to an existing IANA registry (Section 5).

  • Updates to ensure a consistent structure when calling an existing IANA registry (Section 6).

  • Miscellaneous updates to fix broken pointers, orphaned section references, etc. (Section 7).

  • IEの説明の不備を修正するための更新（Section 4）。

  • 既存のIANAレジストリーへのポインターを含めるための更新（Section 5）。

  • 既存のIANAレジストリーを参照する際の構造の一貫性を確保するための更新（Section 6）。

  • 壊れたポインターや参照先のないセクション参照などを修正するためのその他の更新（Section 7）。

These updates are also meant to facilitate the automatic extraction of the values maintained in IANA registries (e.g., with a cron job), required by Collectors to be able to support new IPFIX IEs and, more importantly, adequately interpret new values in registries specified by those IPFIX IEs.

これらの更新は、IANAレジストリーで管理されている値を（たとえばcronジョブで）自動的に抽出しやすくすることも目的としています。この自動抽出は、コレクター（Collector）が新しいIPFIX IEをサポートできるようにするため、そしてさらに重要なこととして、それらのIPFIX IEが指定するレジストリーの新しい値を適切に解釈できるようにするために必要です。

Note that, as per Section 5 of [RFC7012], [IANA-IPFIX] is the normative reference for the IPFIX IEs that were defined in [RFC5102]. Therefore, the updates in this document do not update any part of [RFC7011].

[RFC7012]のSection 5にあるとおり、[RFC5102]で定義されたIPFIX IEについては、[IANA-IPFIX]が規範的な参照であることに注意してください。したがって、この文書の更新は[RFC7011]のいかなる部分も更新しません。

Likewise, this document is not marked as formally updating [RFC5477], [RFC5610], [RFC5655], [RFC6235], [RFC6759], [RFC7014], [RFC7015], [RFC7133], [RFC7270], [RFC8038], and [RFC8158].

同様に、この文書は、[RFC5477], [RFC5610], [RFC5655], [RFC6235], [RFC6759], [RFC7014], [RFC7015], [RFC7133], [RFC7270], [RFC8038]、[RFC8158]を正式に更新するものとしては示されていません。

2. Conventions and Definitions

2. 規約と定義

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

キーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、 「要求されています（REQUIRED）」、 「することになります（SHALL）」、「することはありません（SHALL NOT）」、 「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、 「推奨されます（RECOMMENDED）」、「推奨されません（NOT RECOMMENDED）」、 「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、 BCP 14 [RFC2119] [RFC8174]に記載されているとおりに解釈されるものとします。 ただし、ここに示すようにすべて大文字で表示される場合に限ります。

This document uses the IPFIX-specific terminology (Information Element, Template, Collector, Data Record, Flow Record, Exporting Process, Collecting Process, etc.) defined in Section 2 of [RFC7011]. As in [RFC7011], these IPFIX-specific terms have the first letter of a word capitalized.

この文書は、[RFC7011]のSection 2で定義されているIPFIX固有の用語（Information Element、Template、Collector、Data Record、Flow Record、Exporting Process、Collecting Processなど）を使用します。[RFC7011]と同様に、これらのIPFIX固有の用語は英語では各単語の先頭を大文字で表記します。

3. Why an RFC Is Needed for These Updates

3. これらの更新にRFCが必要な理由

Many of the edits in this document may be handled by the IPFIX Experts (informally called the IE-DOCTORS [RFC7013]). However, and given that many of the impacted IEs were created via the IETF stream, the following from Section 5.1 of [RFC7013] is followed:

この文書の編集の多くは、IPFIXエキスパート（非公式にはIE-DOCTORS [RFC7013]と呼ばれます）が処理できるかもしれません。しかし、影響を受けるIEの多くはIETFストリームを通じて作成されたものであるため、[RFC7013]のSection 5.1の次の記述に従います。

This process should not in any way be construed as allowing the IE-DOCTORS to overrule IETF consensus. Specifically, Information Elements in the IANA IE registry that were added with IETF consensus require IETF consensus for revision or deprecation.

このプロセスは、IE-DOCTORSがIETFのコンセンサスを覆すことを認めるものと決して解釈されるべきではありません。具体的には、IANAのIEレジストリーにある情報要素のうち、IETFのコンセンサスによって追加されたものは、改訂や非推奨化にIETFのコンセンサスが必要です。

4.3. forwardingStatus

The current forwardingStatus entry in [IANA-IPFIX] deviates from what is provided in [RFC7270]. In particular, the registered Abstract Data Type is unsigned8, while it must be unsigned32. The following update fixes that issue. The description is also updated to clarify the use of the reduced-size encoding as per Section 6.2 of [RFC7011].

[IANA-IPFIX]にある現在のforwardingStatusエントリーは、[RFC7270]で規定されている内容と食い違っています。特に、登録されている抽象データ型（Abstract Data Type）はunsigned8ですが、unsigned32でなければなりません。次の更新でこの問題を修正します。また、[RFC7011]のSection 6.2にしたがったサイズ縮小エンコーディング（reduced-size encoding）の使用を明確にするために、説明も更新します。

この情報要素は単なるチェックサムとしてのみ意図されています。したがって、衝突耐性やアルゴリズムの俊敏性は必要とされず、MD5は適切なメッセージダイジェストです。この情報要素は16オクテットの固定長です。
