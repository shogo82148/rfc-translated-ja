Precision Time Protocol Version 2 (PTPv2) Management Information Base

RFC 8173

高精度時間プロトコルバージョン2（PTPv2）の管理情報ベース

Abstract

概要

This memo defines a portion of the Management Information Base (MIB) for use with network management protocols in internets based on TCP or IP. In particular, it defines objects for managing networks using the Precision Time Protocol (PTP), specified in IEEE Std. 1588-2008.

このメモは、TCPまたはIPに基づくインターネット（internets）でネットワーク管理プロトコルとともに使用する管理情報ベース（Management Information Base、MIB）の一部を定義します。特に、IEEE Std. 1588-2008で規定されている高精度時間プロトコル（Precision Time Protocol、PTP）を使用するネットワークを管理するためのオブジェクトを定義します。

This memo specifies a MIB module in a manner that is both compliant to the Structure of Management Information version 2 (SMIv2) and semantically identical to the peer SMIv1 definitions.

このメモは、管理情報構造バージョン2（Structure of Management Information version 2、SMIv2）に準拠し、かつ対応するSMIv1の定義と意味的に同一となる方法で、MIBモジュールを規定します。

1. Introduction

1. はじめに

This memo defines a portion of the Management Information Base (MIB) module for use with network management protocols in the Internet community. In particular, it describes managed objects used for managing PTP devices including ordinary clocks, transparent clocks, and boundary clocks.

このメモは、インターネットコミュニティーにおいてネットワーク管理プロトコルとともに使用する管理情報ベース（MIB）モジュールの一部を定義します。特に、オーディナリークロック、トランスペアレントクロック、バウンダリークロックを含むPTPデバイスの管理に使用される管理オブジェクトについて記述します。

This MIB module is restricted to reading standard PTP data elements, as described in [IEEE-1588-2008]. This enables it to monitor the operation of PTP clocks within the network. It is envisioned that this MIB module will complement other managed objects to be defined that will provide more detailed information on the performance of PTP clocks supporting the Telecom Profile defined in [G.8265.1] and any future profiles that may be defined. Those objects are considered out of scope for the current document.

このMIBモジュールは、[IEEE-1588-2008]で記述されている標準のPTPデータ要素の読み取りに限定されています。これにより、このMIBモジュールはネットワーク内のPTPクロックの動作を監視できます。このMIBモジュールは、今後定義される他の管理オブジェクトを補完することが想定されています。それらの管理オブジェクトは、[G.8265.1]で定義されているテレコムプロファイル（Telecom Profile）や今後定義される可能性のあるプロファイルをサポートするPTPクロックの性能について、より詳細な情報を提供するものです。それらのオブジェクトは、この文書の範囲外とみなされます。

Similarly, this MIB module is read-only and not intended to provide the ability to configure PTP clocks. Since PTP clocks are often embedded in other network elements such as routers, switches, and gateways, this ability is generally provided via the configuration interface for the network element.

同様に、このMIBモジュールは読み取り専用であり、PTPクロックを設定する機能を提供することは意図していません。PTPクロックはルーター、スイッチ、ゲートウェイなどの他のネットワーク要素に組み込まれていることが多いため、この機能は一般に、そのネットワーク要素の設定インターフェイスを介して提供されます。

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

キーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、 「要求されています（REQUIRED）」、 「することになります（SHALL）」、「することはありません（SHALL NOT）」、 「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、 「推奨されます（RECOMMENDED）」、「推奨されません（NOT RECOMMENDED）」、 「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、 BCP 14 [RFC2119] [RFC8174]に記載されているとおりに解釈されるものとします。 ただし、ここに示すようにすべて大文字で表示される場合に限ります。

1.1. Relationship to Other Profiles and MIBs

1.1. 他のプロファイルやMIBとの関係

This MIB module is intended to be used with the default PTP profile described in [IEEE-1588-2008] when running over the IP network layer. As stated above, it is envisioned that this MIB module will complement other managed objects to be defined to monitor and measure the performance of PTP clocks supporting specific PTP profiles, e.g., the Telecom Profile defined in [G.8265.1].

このMIBモジュールは、IPネットワーク層上で動作する場合に、[IEEE-1588-2008]で記述されているデフォルトのPTPプロファイルとともに使用することを意図しています。上で述べたように、このMIBモジュールは、特定のPTPプロファイル（たとえば[G.8265.1]で定義されているテレコムプロファイル）をサポートするPTPクロックの性能を監視・測定するために今後定義される他の管理オブジェクトを補完することが想定されています。

Some other PTP profiles have their own MIB modules defined as part of the profile, and this MIB module is not intended to replace those MIB modules.

他のいくつかのPTPプロファイルには、そのプロファイルの一部として定義された独自のMIBモジュールがあります。このMIBモジュールは、それらのMIBモジュールを置き換えることを意図していません。

2. The Internet-Standard Management Framework

2. インターネット標準管理フレームワーク

For a detailed overview of the documents that describe the current Internet-Standard Management Framework, please refer to section 7 of RFC 3410 [RFC3410].

現在のインターネット標準管理フレームワーク（Internet-Standard Management Framework）を記述している文書の詳細な概要については、RFC 3410 [RFC3410]のセクション7を参照してください。

Managed objects are accessed via a virtual information store, termed the Management Information Base or MIB. MIB objects are generally accessed through the Simple Network Management Protocol (SNMP). Objects in the MIB are defined using the mechanisms defined in the Structure of Management Information (SMI). This memo specifies a MIB module that is compliant to the SMIv2, which is described in STD 58, RFC 2578 [RFC2578], STD 58, RFC 2579 [RFC2579] and STD 58, RFC 2580 [RFC2580].

管理オブジェクトには、管理情報ベース（Management Information Base、MIB）と呼ばれる仮想的な情報ストアを介してアクセスします。MIBオブジェクトには、一般にSimple Network Management Protocol（SNMP）を通じてアクセスします。MIB内のオブジェクトは、管理情報構造（Structure of Management Information、SMI）で定義されたメカニズムを使って定義されます。このメモでは、STD 58、RFC 2578 [RFC2578]、STD 58、RFC 2579 [RFC2579]、およびSTD 58、RFC 2580 [RFC2580]で記述されているSMIv2に準拠したMIBモジュールを規定します。

3. Overview

3. 概要

The objects defined in this MIB module are to be used when describing the Precision Time Protocol (PTP), as defined in [IEEE-1588-2008].

このMIBモジュールで定義されるオブジェクトは、[IEEE-1588-2008]で定義されている高精度時間プロトコル（PTP）を記述する際に使用されます。

Section 6 of [IEEE-1588-2008] provides an overview of synchronization networks using PTP.

[IEEE-1588-2008]のセクション6は、PTPを使用する同期ネットワークの概要を示しています。

Terms used in this document have meanings as defined in Section 3.1 of [IEEE-1588-2008].

この文書で使用される用語は、[IEEE-1588-2008]のセクション3.1で定義されている意味を持ちます。

        Overview of PTP version 2 (IEEE Std. 1588-2008)

        [IEEE-1588-2008] defines a protocol enabling precise
        synchronization of clocks in measurement and control systems
        implemented with packet-based networks, the Precision Time
        Protocol version 2 (PTPv2).  This MIB module does not address
        PTPv1, the earlier version defined in IEEE Std. 1588-2002.
        The protocol is applicable to network elements communicating
        using IP.  The protocol enables heterogeneous systems that
        include clocks of various inherent precision, resolution, and
        stability to synchronize to a grandmaster clock.

        The protocol supports system-wide synchronization accuracy in
        the sub-microsecond range with minimal network and local clock
        computing resources.  [IEEE-1588-2008] uses UDP/IP or
        Ethernet and can be adapted to other mappings.  It includes
        formal mechanisms for message extensions, higher sampling rates,
        correction for asymmetry, a clock type to reduce error
        accumulation in large topologies, and specifications on how to
        incorporate the resulting additional data into the
        synchronization protocol.  [IEEE-1588-2008] also defines
        conformance and management capability.

        MIB description

        This MIB module supports the Precision Time Protocol version 2
        (PTPv2, hereafter designated as PTP) features of network element
        system devices, when using the default PTP profile described in
        [IEEE-1588-2008] when running over the IP network layer.

        managed objects to be defined to monitor and measure the
        performance of the PTP devices and telecom clocks supporting
        specific PTP profiles.

        replace those MIB modules.

        Overview of PTP version 2 (IEEE Std. 1588-2008)

        [IEEE-1588-2008] defines a protocol enabling precise
        synchronization of clocks in measurement and control systems
        implemented with packet-based networks, the Precision Time
        Protocol version 2 (PTPv2).  This MIB module does not address
        PTPv1, the earlier version defined in IEEE Std. 1588-2002.
        The protocol is applicable to network elements communicating
        using IP.  The protocol enables heterogeneous systems that
        include clocks of various inherent precision, resolution, and
        stability to synchronize to a grandmaster clock.

        The protocol supports system-wide synchronization accuracy in
        the sub-microsecond range with minimal network and local clock
        computing resources.  [IEEE-1588-2008] uses UDP/IP or
        Ethernet and can be adapted to other mappings.  It includes
        formal mechanisms for message extensions, higher sampling rates,
        correction for asymmetry, a clock type to reduce error
        accumulation in large topologies, and specifications on how to
        incorporate the resulting additional data into the
        synchronization protocol.  [IEEE-1588-2008] also defines
        conformance and management capability.

        (PTPv2, hereafter designated as PTP) features of network element
        system devices, when using the default PTP profile described in
        [IEEE-1588-2008] when running over the IP network layer.

        managed objects to be defined to monitor and measure the
        performance of the PTP devices and telecom clocks supporting
        specific PTP profiles.

5. Security Considerations

5. セキュリティーに関する考慮事項

There are no management objects defined in this MIB module that have a MAX-ACCESS clause of read-write and/or read-create. So, if this MIB module is implemented correctly, then there is no risk that an intruder can alter or create any management objects of this MIB module via direct SNMP SET operations.

このMIBモジュールには、MAX-ACCESS句がread-writeまたはread-create（あるいはその両方）である管理オブジェクトは定義されていません。したがって、このMIBモジュールが正しく実装されていれば、侵入者が直接のSNMP SET操作によってこのMIBモジュールの管理オブジェクトを変更したり作成したりする危険はありません。

Some of the readable objects in this MIB module (i.e., objects with a MAX-ACCESS other than not-accessible) may be considered sensitive or vulnerable in some network environments. It is thus important to control even GET and/or NOTIFY access to these objects and possibly to even encrypt the values of these objects when sending them over the network via SNMP.

このMIBモジュールの読み取り可能なオブジェクト（すなわち、MAX-ACCESSがnot-accessible以外のオブジェクト）の一部は、ネットワーク環境によっては機密である、または脆弱であるとみなされる場合があります。したがって、これらのオブジェクトへのGETアクセスやNOTIFYアクセスさえも制御し、場合によってはSNMPを介してネットワーク上で送信する際にこれらのオブジェクトの値を暗号化することさえ重要です。

以下に、これらのテーブルとオブジェクト、およびその機密性・脆弱性を示します。

ptpDomainClockPortsTotal, ptpbaseSystemDomainTotals, and ptpbaseSystemProfile expose general information about the clock system.

ptpDomainClockPortsTotal、ptpbaseSystemDomainTotals、ptpbaseSystemProfileは、クロックシステムに関する一般的な情報を公開します。

ptpbaseClockRunningState, ptpbaseClockRunningPacketsSent, and ptpbaseClockRunningPacketsReceived expose a clock's current running status.

SNMP versions prior to SNMPv3 did not include adequate security. Even if the network itself is secure (for example, by using IPsec), even then, there is no control as to who on the secure network is allowed to access and GET (read) the objects in this MIB module.

SNMPv3より前のバージョンのSNMPには、十分なセキュリティーが含まれていませんでした。ネットワーク自体が安全であっても（たとえば、IPsecを使用することによって）、その場合でも、安全なネットワーク上の誰がこのMIBモジュールのオブジェクトにアクセスしてGET（読み取り）できるかについては制御がありません。

Implementations SHOULD provide the security features described by the SNMPv3 framework (see [RFC3410]), and implementations claiming compliance to the SNMPv3 standard MUST include full support for authentication and privacy via the User-based Security Model (USM) [RFC3414] with the AES cipher algorithm [RFC3826]. Implementations MAY also provide support for the Transport Security Model (TSM) [RFC5591] in combination with a secure transport such as SSH [RFC5592] or TLS/DTLS [RFC6353].

実装は、SNMPv3フレームワークで説明されているセキュリティー機能を提供すべきです（SHOULD）（[RFC3410]を参照）。また、SNMPv3標準への準拠を主張する実装は、AES暗号アルゴリズム[RFC3826]を用いたユーザーベースセキュリティーモデル（USM）[RFC3414]による認証とプライバシーを完全にサポートしなければなりません（MUST）。実装は、SSH [RFC5592]やTLS/DTLS [RFC6353]などの安全なトランスポートと組み合わせて、トランスポートセキュリティーモデル（TSM）[RFC5591]のサポートも提供してもよいです（MAY）。

Further, deployment of SNMP versions prior to SNMPv3 is NOT recommended. Instead, it is recommended to deploy SNMPv3 and to enable cryptographic security. It is then a customer/operator responsibility to ensure that the SNMP entity giving access to an instance of this MIB module is properly configured to give access to those objects only to those principals (users) that have legitimate rights to access them.

さらに、SNMPv3より前のバージョンのSNMPを展開することは推奨されません。代わりに、SNMPv3を展開し、暗号によるセキュリティーを有効にすることが推奨されます。そのうえで、このMIBモジュールのインスタンスへのアクセスを提供するSNMPエンティティーが、それらのオブジェクトにアクセスする正当な権利を持つプリンシパル（ユーザー）にのみそれらのオブジェクトへのアクセスを与えるよう適切に設定されていることを保証するのは、顧客・運用者の責任です。
