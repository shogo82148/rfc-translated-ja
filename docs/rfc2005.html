RFC 2005

Applicability Statement for IP Mobility Support

RFC 2005

IPモビリティーサポートの適用性声明

Abstract

概要

As required by [RFC 1264], this report discusses the applicability of Mobile IP to provide host mobility in the Internet. In particular, this document describes the key features of Mobile IP and shows how the requirements for advancement to Proposed Standard RFC have been satisfied.

この報告書は、[RFC 1264]の要求に従って、インターネットでホストのモビリティーを提供するためのMobile IPの適用性について論じます。特に、この文書はMobile IPの主要な機能を説明し、Proposed Standard RFCに昇格するための要件が満たされていることを示します。

Status of This Memo

このメモのステータス

This document specifies an Internet standards track protocol for the Internet community, and requests discussion and suggestions for improvements. Please refer to the current edition of the "Internet Official Protocol Standards" (STD 1) for the standardization state and status of this protocol. Distribution of this memo is unlimited.

この文書は、インターネットコミュニティーのためのインターネット標準化過程（Internet Standards Track）のプロトコルを規定し、改善のための議論と提案を求めるものです。このプロトコルの標準化の状態とステータスについては、「Internet Official Protocol Standards」（STD 1）の最新版を参照してください。このメモの配布は無制限です。

1. Protocol Overview

1. プロトコルの概要

Mobile IP provides an efficient, scalable mechanism for node mobility within the Internet. Using Mobile IP, nodes may change their point-of-attachment to the Internet without changing their IP address. This allows them to maintain transport and higher-layer connections while moving. Node mobility is realized without the need to propagate host-specific routes throughout the Internet routing fabric. The protocol is documented in [MIP-PROTO].

Mobile IPは、インターネット内でのノードのモビリティーのための、効率的でスケーラブルな仕組みを提供します。Mobile IPを使うと、ノードはIPアドレスを変えずに、インターネットへの接続点（point-of-attachment）を変えられます。これにより、ノードは移動しながらトランスポート層や上位層のコネクションを維持できます。ノードのモビリティーは、ホスト固有の経路をインターネットのルーティング構造全体に伝搬させる必要なく実現されます。このプロトコルは[MIP-PROTO]で文書化されています。

In brief, Mobile IP routing works as follows. Packets destined to a mobile node are routed first to its home network -- a network identified by the network prefix of the mobile node's (permanent) home address. At the home network, the mobile node's home agent intercepts such packets and tunnels them to the mobile node's most recently reported care-of address. At the endpoint of the tunnel, the inner packets are decapsulated and delivered to the mobile node. In the reverse direction, packets sourced by mobile nodes are routed to their destination using standard IP routing mechanisms.

簡単に言うと、Mobile IPのルーティングは次のように動作します。モバイルノード宛てのパケットは、まずそのホームネットワークにルーティングされます。ホームネットワークとは、モバイルノードの（恒久的な）ホームアドレスのネットワークプレフィックスで識別されるネットワークです。ホームネットワークでは、モバイルノードのホームエージェントがそのようなパケットを横取りし、モバイルノードが最後に報告した気付アドレス（care-of address）へトンネリングします。トンネルの終端では、内側のパケットがカプセル化を解除され、モバイルノードに配送されます。逆方向では、モバイルノードが送信元のパケットは、標準的なIPルーティングの仕組みを使って宛先にルーティングされます。

Thus, Mobile IP relies on protocol tunneling to deliver packets to mobile nodes that are away from their home network. The mobile node's home address is hidden from routers along the path from the home agent to the mobile node due to the presence of the tunnel. The encapsulating packet is destined to the mobile node's care-of address -- a topologically significant address -- to which standard IP routing mechanisms can deliver packets.

このように、Mobile IPは、ホームネットワークから離れているモバイルノードにパケットを配送するために、プロトコルのトンネリングに頼っています。トンネルがあるため、ホームエージェントからモバイルノードまでの経路上のルーターからは、モバイルノードのホームアドレスは隠されます。カプセル化したパケットの宛先は、モバイルノードの気付アドレスです。これはトポロジー上意味のあるアドレスであり、標準的なIPルーティングの仕組みでパケットを配送できます。

The Mobile IP protocol defines the following:

Mobile IPプロトコルは次のものを定義します。

  • an authenticated registration procedure by which a mobile node informs its home agent(s) of its care-of address(es);
  • an extension to ICMP Router Discovery [RFC1256] which allows mobile nodes to discover prospective home agents and foreign agents; and
  • the rules for routing packets to and from mobile nodes, including the specification of one mandatory tunneling mechanism ([MIP-IPinIP]) and several optional tunneling mechanisms ([MIP-MINENC] and [RFC1701]).
  • モバイルノードが自分の気付アドレスをホームエージェントに通知するための、認証付きの登録手順
  • モバイルノードがホームエージェントや外部エージェントの候補を発見できるようにする、ICMPルーター発見[RFC1256]の拡張
  • モバイルノードとの間でパケットをルーティングするための規則。1つの必須のトンネリングの仕組み（[MIP-IPinIP]）と、いくつかの省略可能なトンネリングの仕組み（[MIP-MINENC]と[RFC1701]）の仕様を含みます。

2. Applicability

2. 適用性

Mobile IP is intended to solve node mobility across changes in IP subnet. It is just as suitable for mobility across homogeneous media as it is for mobility across heterogeneous media. That is, Mobile IP facilitates node movement from one Ethernet segment to another as well as it accommodates node movement from an Ethernet segment to a wireless LAN.

Mobile IPは、IPサブネットの変更をまたぐノードのモビリティーを解決することを目的としています。同種のメディア間のモビリティーにも、異種のメディア間のモビリティーにも同じように適しています。つまり、Mobile IPは、あるイーサネットセグメントから別のイーサネットセグメントへのノードの移動を容易にするのと同様に、イーサネットセグメントから無線LANへのノードの移動にも対応します。

One can think of Mobile IP as solving the "macro" mobility management problem. It is less well suited for more "micro" mobility management applications -- for example, handoff amongst wireless transceivers, each of which covers only a very small geographic area. In this later situation, link-layer mechanisms for link maintenance (i.e. link-layer handoff) might offer faster convergence and less overhead than Mobile IP.

Mobile IPは、「マクロ」なモビリティー管理の問題を解決するものと考えることができます。より「ミクロ」なモビリティー管理の用途、たとえば、それぞれがごく狭い地理的範囲だけをカバーする無線トランシーバー間のハンドオフには、あまり適していません。後者の状況では、リンクを維持するためのリンク層の仕組み（つまりリンク層のハンドオフ）の方が、Mobile IPよりも収束が速く、オーバーヘッドも少ない可能性があります。

Mobile IP scales to handle a large number of mobile nodes in the Internet. Without route optimization as described in [MIP-OPTIM], however, the home agent is a potential load point when serving many mobile nodes. When home agents become overburdened, additional home agents can be added -- and even dynamically discovered by mobile nodes -- using mechanisms defined in the Mobile IP documents.

Mobile IPは、インターネット内の多数のモバイルノードを扱えるようにスケールします。ただし、[MIP-OPTIM]で説明されている経路最適化がない場合、多くのモバイルノードにサービスを提供するホームエージェントは、負荷が集中する箇所になる可能性があります。ホームエージェントが過負荷になった場合は、Mobile IPの文書で定義されている仕組みを使って、ホームエージェントを追加できます。さらに、モバイルノードがそれを動的に発見することもできます。

Finally, it is noted that mobile nodes are assigned (home) IP addresses largely the same way in which stationary hosts are assigned long-term IP addresses; namely, by the authority who owns them. Properly applied, Mobile IP allows mobile nodes to communicate using only their home address regardless of their current location. Mobile IP, therefore, makes no attempt to solve the problems related to local or global, IP address, renumbering.

最後に、モバイルノードへの（ホーム）IPアドレスの割り当ては、固定ホストへの長期的なIPアドレスの割り当てとほぼ同じ方法、つまり、そのアドレスを所有する機関によって行われることに注意してください。Mobile IPを適切に適用すれば、モバイルノードは現在の位置にかかわらず、ホームアドレスだけを使って通信できます。したがって、Mobile IPは、ローカルまたはグローバルなIPアドレスのリナンバリングに関する問題を解決しようとはしていません。

3. Security

3. セキュリティー

Mobile IP mandates the use of cryptographically strong authentication for all registration messages exchanged between a mobile node and its home agent. Optionally, strong authentication can be used between foreign agents and mobile nodes or home agents. Replay protection is realized via one of two possible mechanisms -- timestamps or nonces.

Mobile IPは、モバイルノードとホームエージェントの間で交換されるすべての登録メッセージに、暗号学的に強力な認証を使うことを義務付けています。省略可能ですが、外部エージェントとモバイルノードやホームエージェントとの間でも強力な認証を使えます。リプレイ保護は、タイムスタンプかナンス（nonce）かの2つの仕組みのどちらかで実現されます。

Due to the unavailability of an Internet key management protocol, agent discovery messages are not required to be authenticated.

インターネットの鍵管理プロトコルがないため、エージェント発見メッセージの認証は要求されていません。

All Mobile IP implementations are required to support, at a minimum, keyed MD5 authentication with manual key distribution. Other authentication and key distribution algorithms may be supported.

すべてのMobile IP実装は、少なくとも、手動の鍵配布による鍵付きMD5認証をサポートすることが要求されています。ほかの認証と鍵配布のアルゴリズムをサポートしてもかまいません。

Mobile IP defines security mechanisms only for the registration protocol. Implementations requiring privacy and/or authentication of data packets sent to and from a mobile node should use the IP security protocols described in RFCs 1827 and 1826 for this purpose.

Mobile IPは、登録プロトコルについてだけセキュリティーの仕組みを定義しています。モバイルノードとの間で送受信されるデータパケットの秘匿性や認証を必要とする実装は、そのためにRFC 1827とRFC 1826で説明されているIPセキュリティープロトコルを使うべきです。

6. Implementation Experience

6. 実装経験

FTP Software hosted an interim meeting, October 23-27, 1995 in which interoperability of several implementations was demonstrated. The following major features of the Mobile IP protocol were tested:

FTP Softwareが1995年10月23日から27日にかけて中間会議を主催し、そこでいくつかの実装の相互運用性が実証されました。Mobile IPプロトコルの次の主要な機能がテストされました。

  1. Mobile Nodes receiving and processing Agent Advertisements.
  2. Agents receiving Agent Solicitations and responding with Agent Advertisements.
  3. Mobile Nodes registering with foreign agents on foreign networks.
  4. Packets being received by the mobile node after having been tunneled by the home agent and de-tunneled by the foreign agent.
  5. Packets from the mobile node being routed directly to their destinations.
  6. Mobile nodes discovering that their connectivity/subnet had changed and re-registering at their new location.
  7. Mobile nodes discovering that their current foreign agent had rebooted and therefore re-registering with that foreign agent.
  8. The required form of tunneling (IP-in-IP encapsulation [MIP-IPinIP]) as well as the one of the optional forms of tunneling; namely, Minimal Encapsulation [MIP-MINENC].
  9. Mobile nodes de-registering upon returning to their home network.
  10. Registrations being rejected for authentication failures, including invalid authenticators as well as mismatched identification values (replay protection).
  11. TCP connections remaining open (with data flowing) while a mobile node moved from its home network to a foreign network and then back again to the home network.
  1. モバイルノードがエージェント広告（Agent Advertisement）を受信して処理すること。
  2. エージェントがエージェント要請（Agent Solicitation）を受信し、エージェント広告で応答すること。
  3. モバイルノードが外部ネットワーク上の外部エージェントに登録すること。
  4. ホームエージェントによってトンネリングされ、外部エージェントによってトンネルから取り出されたパケットを、モバイルノードが受信すること。
  5. モバイルノードからのパケットが宛先に直接ルーティングされること。
  6. モバイルノードが接続先やサブネットが変わったことを発見し、新しい位置で再登録すること。
  7. モバイルノードが現在の外部エージェントが再起動したことを発見し、その外部エージェントに再登録すること。
  8. 必須のトンネリング形式（IP-in-IPカプセル化[MIP-IPinIP]）と、省略可能なトンネリング形式の1つ、つまり最小カプセル化（Minimal Encapsulation）[MIP-MINENC]。
  9. モバイルノードがホームネットワークに戻ったときに登録を解除すること。
  10. 認証の失敗により登録が拒否されること。不正な認証子や、識別値の不一致（リプレイ保護）を含みます。
  11. モバイルノードがホームネットワークから外部ネットワークへ移動し、再びホームネットワークに戻る間、TCPコネクションが（データが流れたまま）開いた状態を保つこと。

Interoperability of at least two independent implementations was demonstrated for all of the features listed above.

上に挙げたすべての機能について、少なくとも2つの独立した実装の相互運用性が実証されました。

7. Summary

7. まとめ

The co-chairs, on behalf of the working group participants, believe that the Mobile IP working group has satisfied the requirements set forth in [RFC1264] for the advancement of Mobile IP to Proposed Standard RFC. Specifically, the technical specification document is stable, a MIB has been written, the security architecture has been set forth in accordance with IAB principles, and several independent implementations have been demonstrated to be interoperable.

共同議長は、ワーキンググループの参加者を代表して、Mobile IPをProposed Standard RFCに昇格させるために[RFC1264]で定められた要件を、Mobile IPワーキンググループが満たしたと考えています。具体的には、技術仕様の文書は安定しており、MIBが作成され、IABの原則に従ってセキュリティーアーキテクチャーが定められ、いくつかの独立した実装が相互運用できることが実証されています。
