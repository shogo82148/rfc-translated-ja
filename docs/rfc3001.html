RFC 3001

A URN Namespace of Object Identifiers

RFC 3001

オブジェクト識別子のURN名前空間

Abstract

概要

This document describes a Uniform Resource Names (URN) namespace that contains Object Identifiers (OIDs).

この文書は、オブジェクト識別子（Object Identifier、OID）を含む統一リソース名（Uniform Resource Names、URN）の名前空間について説明します。

このメモのステータス

1. Introduction

1. はじめに

An Object Identifier is a series of digits delimited in some way. The rules roughly state that once an entity is assigned an Object Identifier (OID) it has sole discretion to further subdelegate off of that OID. Some examples of OIDs include:

オブジェクト識別子は、何らかの方法で区切られた一連の数字です。その規則は大まかに言うと、あるエンティティーにオブジェクト識別子（OID）が割り当てられると、そのエンティティーはそのOIDの下をさらに下位委任する唯一の裁量権を持つというものです。OIDの例には次のようなものがあります。

  • 1.3.6.1 - the Internet OID
  • 1.3.6.1.4.1 - IANA-assigned company OIDs, used for private MIBs and such things
  • 1.3.6.1.2.1.27 - The Applications MIB
  • 0.9.2342.19200300.100.4 - Object ID's used in the directory pilot project to identify X.500 Object Classes. Mostly defined in RFC-1274.
  • 1.3.6.1 - インターネットのOID
  • 1.3.6.1.4.1 - IANAが割り当てる企業のOIDで、プライベートMIBなどに使われるもの
  • 1.3.6.1.2.1.27 - Applications MIB
  • 0.9.2342.19200300.100.4 - ディレクトリーパイロットプロジェクトでX.500のオブジェクトクラスを識別するために使われたオブジェクトID。ほとんどはRFC-1274で定義されています。

This document specifies the "oid" URN namespace [1]. This namespace is for encoding an Object Identifier as specified in ASN.1 [2] as a URI.

この文書は、"oid" URN名前空間[1]を規定します。この名前空間は、ASN.1 [2]で規定されているオブジェクト識別子をURIとして符号化するためのものです。

The namespace specification is for a formal namespace.

この名前空間の仕様は、正式な名前空間のためのものです。

2. Specification Template

2. 仕様テンプレート

Namespace ID:
"oid" requested.
Registration Information:

Registration Version Number: 1

Registration Date: 2000-04-30

Declared registrant of the namespace:

I need help here. I'm not comfortable being the 'registrant'. So who do I actually put here?

The ISO/IEC Joint Technical Committee 1 - SubCommittee 6 The actual real authority is the ASN.1 specification itself but at present SC6 is the committee that has the authority to interpret what that means.

Declaration of structure:

The NSS portion of the identifier follows the string encoding rules found in RFC 1778 Section 2.15 [3] which specifies a series of digits separated by a period with the most significant digit being at the left and the least significant being at the right.

No changes are anticipated since Object Identifiers are fairly simple and have been standardized with no changes for many years.

Relevant ancillary documentation:
Relevant documentation can be found in X.660/Amd 2 | ISO/IEC 9834-1/Amd 2 [2].
Identifier uniqueness considerations:
The rules for assignment of OIDs requires that each OID be unique to the OID space and that it cannot be reassigned or reused. By reference this URN namespace inherents those rules.
Identifier persistence considerations:
The rules concerning the use of OIDs requires that they not be reused once assigned. By reference this URN namespace inherents those rules.
Process of identifier assignment:

Once an OID is assigned to some entity, that entity can then create and assign new OIDs below that particular OID. There are multiple entities that assign new OIDs to the general public. The top three levels are pre-assigned as follows:

   0 - ITU-T assigned
   1 - ISO assigned
   2 - Joint ISO/ITU-T assignment

several assigned OIDs that are of importance to the Internet are:

   1.3.6.1 - the Internet OID
   1.3.6.1.4.1 - IANA-assigned company OIDs, used for private
                 MIBs and such things
Process of identifier resolution:
At this time no resolution mechanism is defined.
Rules for Lexical Equivalence:
OIDs are composed of multiple occurrences of digits and the "." character. Lexical equivalence is achieved by exact string match.
Conformance with URN Syntax:
There are no additional characters reserved.
Validation mechanism:
None.
Scope:
Global

名前空間の登録者として宣言される者（Declared registrant of the namespace）：

ここは助けが必要です。私が「登録者」になるのは気が進みません。では、実際にここには誰を書けばよいのでしょうか。

ISO/IEC第1合同技術委員会第6分科委員会（ISO/IEC Joint Technical Committee 1 - SubCommittee 6）。実際の本当の権威はASN.1の仕様そのものですが、現時点ではSC6がその意味を解釈する権限を持つ委員会です。

構造の宣言（Declaration of structure）：

識別子のNSS部分は、RFC 1778のセクション2.15 [3]にある文字列の符号化規則に従います。この規則は、ピリオドで区切られた一連の数字を規定しており、最上位の数字が左端に、最下位の数字が右端に置かれます。

オブジェクト識別子はかなり単純であり、長年にわたって変更なく標準化されているため、変更は予定されていません。

関連する補足文書（Relevant ancillary documentation）：
関連する文書は、X.660/Amd 2 | ISO/IEC 9834-1/Amd 2 [2]にあります。
識別子の一意性に関する考慮事項（Identifier uniqueness considerations）：
OIDの割り当て規則では、各OIDがOID空間において一意であること、そして再割り当てや再利用ができないことが要求されています。このURN名前空間は、参照によってこれらの規則を継承します。
識別子の永続性に関する考慮事項（Identifier persistence considerations）：
OIDの使用に関する規則では、一度割り当てられたOIDを再利用しないことが要求されています。このURN名前空間は、参照によってこれらの規則を継承します。
識別子の割り当て手順（Process of identifier assignment）：

あるエンティティーにOIDが割り当てられると、そのエンティティーはその特定のOIDの下に新しいOIDを作成して割り当てることができます。一般向けに新しいOIDを割り当てるエンティティーは複数あります。上位3レベルは、次のようにあらかじめ割り当てられています。

   0 - ITU-T assigned
   1 - ISO assigned
   2 - Joint ISO/ITU-T assignment

インターネットにとって重要な、割り当て済みのOIDには次のようなものがあります。

   1.3.6.1 - the Internet OID
   1.3.6.1.4.1 - IANA-assigned company OIDs, used for private
                 MIBs and such things
識別子の解決手順（Process of identifier resolution）：
現時点では、解決メカニズムは定義されていません。
字句的等価性の規則（Rules for Lexical Equivalence）：
OIDは、数字と"."文字が複数回現れることで構成されます。字句的等価性は、文字列の完全一致によって判定されます。
URN構文への準拠（Conformance with URN Syntax）：
追加で予約される文字はありません。
検証メカニズム（Validation mechanism）：
なし。
範囲（Scope）：
グローバル
