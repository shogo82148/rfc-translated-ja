RFC 2088

IMAP4 non-synchronizing literals

RFC 2088

IMAP4の非同期リテラル

Status of This Memo

このメモのステータス

This document specifies an Internet standards track protocol for the Internet community, and requests discussion and suggestions for improvements. Please refer to the current edition of the "Internet Official Protocol Standards" (STD 1) for the standardization state and status of this protocol. Distribution of this memo is unlimited.

この文書は、インターネットコミュニティーのためのインターネット標準化過程（Internet Standards Track）のプロトコルを規定し、改善のための議論と提案を求めるものです。このプロトコルの標準化の状態とステータスについては、「Internet Official Protocol Standards」（STD 1）の最新版を参照してください。このメモの配布は無制限です。

1. Abstract

1. 概要

The Internet Message Access Protocol [IMAP4] contains the "literal" syntactic construct for communicating strings. When sending a literal from client to server, IMAP4 requires the client to wait for the server to send a command continuation request between sending the octet count and the string data. This document specifies an alternate form of literal which does not require this network round trip.

インターネットメッセージアクセスプロトコル（Internet Message Access Protocol）[IMAP4]には、文字列を伝達するための「リテラル」という構文要素があります。クライアントからサーバーへリテラルを送信するとき、IMAP4では、クライアントはオクテット数を送信してから文字列データを送信するまでの間に、サーバーがコマンド継続リクエストを送信してくるのを待つ必要があります。この文書では、このネットワーク往復を必要としない、リテラルの代替形式を規定します。

2. Conventions Used in this Document

2. この文書で使用する表記規則

In examples, "C:" and "S:" indicate lines sent by the client and server respectively.

例の中の「C:」と「S:」は、それぞれクライアントとサーバーが送信する行を表します。

3. Specification

3. 仕様

The non-synchronizing literal is added an alternate form of literal, and may appear in communication from client to server instead of the IMAP4 form of literal. The IMAP4 form of literal, used in communication from client to server, is referred to as a synchronizing literal.

非同期リテラル（non-synchronizing literal）は、リテラルの代替形式として追加されるものであり、クライアントからサーバーへの通信において、IMAP4の形式のリテラルの代わりに使うことができます。クライアントからサーバーへの通信で使われるIMAP4の形式のリテラルは、同期リテラル（synchronizing literal）と呼びます。

Non-synchronizing literals may be used with any IMAP4 server implementation which returns "LITERAL+" as one of the supported capabilities to the CAPABILITY command. If the server does not advertise the LITERAL+ capability, the client must use synchronizing literals instead.

非同期リテラルは、CAPABILITYコマンドに対して、サポートしている機能の1つとして「LITERAL+」を返すIMAP4サーバー実装であれば、どれに対しても使うことができます。サーバーがLITERAL+機能を広告していない場合、クライアントは代わりに同期リテラルを使わなければなりません。

The non-synchronizing literal is distinguished from the original synchronizing literal by having a plus ('+') between the octet count and the closing brace ('}'). The server does not generate a command continuation request in response to a non-synchronizing literal, and clients are not required to wait before sending the octets of a non- synchronizing literal.

非同期リテラルは、オクテット数と閉じ波括弧（'}'）の間にプラス（'+'）があることで、元の同期リテラルと区別されます。サーバーは、非同期リテラルに対してはコマンド継続リクエストを生成しません。また、クライアントは、非同期リテラルのオクテットを送信する前に待つ必要はありません。

The protocol receiver of an IMAP4 server must check the end of every received line for an open brace ('{') followed by an octet count, a plus ('+'), and a close brace ('}') immediately preceeding the CRLF. If it finds this sequence, it is the octet count of a non- synchronizing literal and the server MUST treat the specified number of following octets and the following line as part of the same command. A server MAY still process commands and reject errors on a line-by-line basis, as long as it checks for non-synchronizing literals at the end of each line.

IMAP4サーバーのプロトコル受信部は、受信したすべての行の末尾について、開き波括弧（'{'）に続いてオクテット数、プラス（'+'）、閉じ波括弧（'}'）があり、その直後にCRLFがあるかどうかを調べなければなりません。この並びが見つかった場合、それは非同期リテラルのオクテット数であり、サーバーは、それに続く指定された数のオクテットと、その次の行を、同じコマンドの一部として扱わなければなりません（MUST）。各行の末尾で非同期リテラルを確認している限り、サーバーは引き続き行単位でコマンドを処理し、エラーを拒否してもよいです（MAY）。

Example:

例:

C: A001 LOGIN {11+}
C: FRED FOOBAR {7+}
C: fat man
S: A001 OK LOGIN completed

C: A001 LOGIN {11+}
C: FRED FOOBAR {7+}
C: fat man
S: A001 OK LOGIN completed

4. Formal Syntax

4. 形式的構文

The following syntax specification uses the augmented Backus-Naur Form (BNF) notation as specified in [RFC-822] as modified by [IMAP4]. Non-terminals referenced but not defined below are as defined by [IMAP4].

以下の構文仕様では、[IMAP4]で修正された、[RFC-822]で規定されている拡張バッカス・ナウア記法（BNF）を使います。参照されているが以下で定義されていない非終端記号は、[IMAP4]で定義されているとおりです。

literal         ::= "{" number ["+"] "}" CRLF *CHAR8
                    ;; Number represents the number of CHAR8 octets

literal         ::= "{" number ["+"] "}" CRLF *CHAR8
                    ;; numberはCHAR8オクテットの数を表す
