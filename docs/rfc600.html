RFC 600

Interfacing an Illinois plasma terminal to the ARPANET

RFC 600

イリノイ大学のプラズマ端末とARPANETとのインターフェイス

INTRODUCTION

はじめに

The PLATO IV System based at the University of Illinois at Urbana is a highly sophisticated and very powerful approach to Computer Aided Instruction. The PLATO IV system makes use of a plasma display terminal that is a unique device with capabilities not presently found on computer terminals. A number of ARPA supported projects intend to use the plasma terminal on local connection to computer resources or by long-distance connection to the PLATO IV System.

イリノイ大学アーバナ校を拠点とするPLATO IVシステムは、コンピューター支援教育（Computer Aided Instruction）に対する、非常に洗練された非常に強力なアプローチです。PLATO IVシステムは、プラズマディスプレイ端末を使います。これは、現在のコンピューター端末には見られない機能を持つ独特な装置です。ARPAが支援するいくつかのプロジェクトは、このプラズマ端末を、コンピューター資源へのローカル接続で使ったり、PLATO IVシステムへの長距離接続で使ったりすることを予定しています。

One problem in using the PLATO System from any appreciable distance, is the communication costs involved (i.e. long-distance telephone rates for many consecutive hours). Also, use of the plasma terminal in other applications is hampered since the communications scheme employed in the PLATO System in non-standard.

ある程度離れた場所からPLATOシステムを使う際の問題の1つは、それにかかる通信コスト（つまり、何時間も連続して使う場合の長距離電話料金）です。また、PLATOシステムで採用されている通信方式は標準的なものではないため、プラズマ端末を他の用途に使うことも困難です。

One approach to reducing the communications cost is to use the ARPANET for the long-distance connection, since the Network is potentially one of the most reliable and cost effective means of transmitting computer data. This approach is reasonable the is a Network node near the PLATO System, (the PDP-11/ANTS system at the Center for Advanced Computation at the University of Illinois at Urbana) and with the increasing number of TIPS and IMPS on the ARPANET access is becomming easier ad more widespread.

通信コストを削減する1つのアプローチは、長距離接続にARPANETを使うことです。ネットワーク（Network）は、コンピューターデータを伝送する手段として、潜在的に最も信頼性が高く費用対効果の高いものの1つだからです。PLATOシステムの近くにはネットワークノード（イリノイ大学アーバナ校の先端計算センター（Center for Advanced Computation）にあるPDP-11/ANTSシステム）があり、またARPANET上のTIPやIMPの数が増えるにつれて、アクセスはより容易になり、より広く普及しつつあるので、このアプローチは妥当です。

The plasma terminals are designed to be connected directly to telephone lines using Frequency Shift Keying (FSK) modulation. Using dedicated telephone lines, the plasma terminal may be run at a data rate of 1200 bits/sec in full-duplex operation. Using dial-up lines, the terminal may be run with display information being received at 1200 bits/sec and data to the computer being transmitted at 120 bits/sec using a reverse chanel scheme.

プラズマ端末は、周波数偏移変調（Frequency Shift Keying; FSK）を使って電話回線に直接接続するように設計されています。専用電話回線を使う場合、プラズマ端末は、全二重動作で1200ビット/秒のデータレートで動作できます。ダイヤルアップ回線を使う場合、逆方向チャネル方式を使って、表示情報を1200ビット/秒で受信し、コンピューターへのデータを120ビット/秒で送信するように動作させることができます。

The data and command words used by the plasma terminal differ for input and output. Input received from the computer arrives in 20-bit words plus one start bit. Data transmitted to the computer is sent in 11-bit words plus one start bit.

プラズマ端末が使うデータワードとコマンドワードは、入力と出力で異なります。コンピューターから受信する入力は、20ビットのワードに1つのスタートビットを加えた形で届きます。コンピューターへ送信するデータは、11ビットのワードに1つのスタートビットを加えた形で送られます。

In order to make the plasma terminal more generally applicable for standard communication, and specifically adapted to the ARPANET connection by way of a TIP, the terminal must be interfaced in such a way as to communicate using Teletype-like codes. In addition, if the PLATO System is to be linked by way of the Network with no changes to the system, then a special interface must be provided to allow the Network to communicate with the PLATO System using the FSK communication scheme.

プラズマ端末を標準的な通信に広く適用できるようにし、特にTIP経由のARPANET接続に適応させるためには、テレタイプ（Teletype）のようなコードを使って通信するように端末をインターフェイスしなければなりません。さらに、PLATOシステムに変更を加えずにネットワーク経由で接続するのであれば、ネットワークがFSK通信方式を使ってPLATOシステムと通信できるようにする特別なインターフェイスを用意しなければなりません。

APPROACH

アプローチ

So that the plasma terminal would communicate like a Teletype when tied to a TIP, and still be able to work with the PLATO System through the Network, it was decided to build an interface that could be operated in two modes. There would be an "ASCII" mode to send and receive Network oriented data (such as TIP log-on or running at some arbitrary Network site); and a "PLATO System" mode to allow data, imbedded in 8-bit codes, to pass transparently through the Network.

プラズマ端末がTIPにつながっているときはテレタイプのように通信し、なおかつネットワーク経由でPLATOシステムとも動作できるように、2つのモードで動作できるインターフェイスを作ることにしました。1つは、ネットワーク向けのデータ（TIPへのログオンや、ネットワーク上の任意のサイトでの実行など）を送受信するための「ASCII」モードです。もう1つは、8ビットコードに埋め込まれたデータがネットワークを透過的に通過できるようにする「PLATO System」モードです。

Since there is a possibility that when in the PLATO mode, re-formatted codes can appear to be standard ACSII characters that will be seized upon by intervening TIPs or HOSTs, the interface must insure that no recognizable codes be sent. For example, the @ is recognized by a TIP as the beginning of a TIP command string. Therefore the interface must either "double-up" this code (@@) or not send it at all.

PLATOモードのときに、再フォーマットされたコードが標準的なASCII文字のように見えてしまい、間にあるTIPやHOSTに横取りされる可能性があるため、インターフェイスは、認識されうるコードが送信されないようにしなければなりません。たとえば、@はTIPによってTIPコマンド文字列の始まりとして認識されます。そのため、インターフェイスは、このコードを「二重にする」（@@）か、まったく送らないかのどちらかにしなければなりません。

With the above requirement, and with other limitations, the proto-type interface, now in use at UCSB, operates as follows:

上記の要件とその他の制約のもとで、現在UCSBで使われているプロトタイプのインターフェイスは、次のように動作します。

  1. In ASCII mode, the plasma terminal has been made to send and receive 8-bit ASCII code. In this mode, there is no graphics capability. The keyboard that is provided can only send 124 codes, therefore 4 seldom used ASCII codes have been excluded, and certain ASCII characters cannot be displayed.
  2. In PLATO mode, PLATO data is embedded in 8-bit codes. The capability of running the keyboard in ASCII mode while the display remains in PLATO mode has also been provided.
  1. ASCIIモードでは、プラズマ端末は8ビットのASCIIコードを送受信するようになっています。このモードには、グラフィックス機能はありません。用意されているキーボードは124種類のコードしか送れないため、あまり使われない4つのASCIIコードは除外されており、また一部のASCII文字は表示できません。
  2. PLATOモードでは、PLATOのデータは8ビットコードに埋め込まれます。表示はPLATOモードのままで、キーボードをASCIIモードで動作させる機能も用意されています。

SUBSEQUENT WORK

その後の作業

After discusion, it became clear that the flexability of the interface to do such things as emulate standard graphics terminals, implement a cursor, and to respond to Network Graphics Protocols, will be highly desirable. So it has been decided that the original hardware will be re-packaged using a micro-computer with a ROM for the control program. With the addition of more RAM and/or ROM, the micro-computer will have the capability of being programmed to allow the plasma terminal to do a wide variety of tasks. Work on developing this interface has begun at UCSB.

議論の結果、標準的なグラフィックス端末のエミュレート、カーソルの実装、ネットワークグラフィックスプロトコル（Network Graphics Protocols）への応答といったことができるインターフェイスの柔軟性が非常に望ましいことが明らかになりました。そこで、元のハードウェアを、制御プログラム用のROMを備えたマイクロコンピューターを使って作り直すことにしました。RAMやROMを追加すれば、マイクロコンピューターをプログラムして、プラズマ端末にさまざまなタスクを行わせることができるようになります。このインターフェイスの開発作業は、UCSBで始まっています。
