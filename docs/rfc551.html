RFC 551

NYU, ANL, and LBL Joining the Net

RFC 551

NYU、ANL、LBLのネットワークへの参加

Abstract

概要

New York University
Courant Institute of Mathematical Sciences
AEC Computing and Applied Mathematics Center
251 Mercer Street
New York, N.Y. 10012

New York University
Courant Institute of Mathematical Sciences
AEC Computing and Applied Mathematics Center
251 Mercer Street
New York, N.Y. 10012

ARPA Network Information Center

Several Atomic Energy Commission installations are planning to enter the network in the (hopefully) near future. These sites include Argonne National Laboratory (IBM 360/195), Lawrence Berkeley Labs, (CDC 7600), and New York University (CDC 6600). Our applications make early implementation of an RJE facility imperative, and although we are resigned to the necessity of implementing FTP, we would like to avoid RJE protocol at least in the first go-around. We would like to be able to use FTP to transfer a file, have it queued for execution, and return output and status information.

原子力委員会（Atomic Energy Commission）のいくつかの施設が、（願わくは）近い将来にネットワークに参加することを計画しています。これらのサイトには、Argonne National Laboratory（IBM 360/195）、Lawrence Berkeley Labs（CDC 7600）、New York University（CDC 6600）が含まれます。私たちのアプリケーションでは、RJE機能を早期に実装することが不可欠です。FTPを実装しなければならないことは受け入れていますが、少なくとも最初の段階では、RJEプロトコルは避けたいと考えています。私たちは、FTPを使ってファイルを転送し、それを実行キューに入れ、出力とステータス情報を返せるようにしたいと考えています。

To this end we propose to implement local conventions within the site dependent PATHNAME parameter of the FTP. Specifically, the following commands are specified:

そのために、FTPのサイト依存のPATHNAMEパラメーターの中で、ローカルな規約を実装することを提案します。具体的には、次のコマンドを規定します：

STOR           RJE.JOB<rest of pathname>  queue this file for execution
(STOR/RETR)    RJE.PR <    >              transfer remote job print file
(STOR/RETR)    RJE.PU <    >                 "        "    "  punch   "
(STOR/RETR)    RJE.MT <    >                 "        "    "  magtape "

RETR           RJE.STAT  <    >           retrieve  status of remote job

STOR           RJE.JOB<rest of pathname>  queue this file for execution
(STOR/RETR)    RJE.PR <    >              transfer remote job print file
(STOR/RETR)    RJE.PU <    >                 "        "    "  punch   "
(STOR/RETR)    RJE.MT <    >                 "        "    "  magtape "

RETR           RJE.STAT  <    >           retrieve  status of remote job

The job execution parameters are not part of the protocol, but must be specified in the standard site dependent control cards which are transmitted with the file. These parameters also determine the output disposition, and the output can be retrieved by the user via RETR, or (optionally) automatically by server initiation via STOR.* The RETR RJE.STAT causes the server to create a file with the status information and transfer it to the user. The FTP user/acct/pass logon is used only to validate the data transfer, not the job's right to execute, and to identify and distribute the output.

ジョブの実行パラメーターはプロトコルの一部ではなく、ファイルとともに送信される、標準のサイト依存の制御カードで指定しなければなりません。これらのパラメーターによって出力の処理方法も決まります。出力は、ユーザーがRETRで取得することも、（オプションで）サーバーが開始するSTORによって自動的に取得することもできます。* RETR RJE.STATを受けると、サーバーはステータス情報を含むファイルを作成し、ユーザーに転送します。FTPのuser/acct/passによるログオンは、データ転送の検証と、出力の識別および配布のためだけに使われ、ジョブを実行する権利の検証には使われません。

We are concerned that we may have overlooked some problems which are obvious to more knowledgeable people and invite (and request) comments.

もっと詳しい人にとっては明らかな問題を、私たちが見落としているのではないかと懸念しています。ご意見をお寄せください（ぜひお願いします）。

* note that in this case the RJE server is an FTP user.

* この場合、RJEサーバーはFTPユーザーであることに注意してください。
