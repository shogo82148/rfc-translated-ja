RFC 1420

SNMP over IPX

RFC 1420

IPX上のSNMP

Abstract

概要

This document defines a convention for encapsulating Simple Network Management Protocol (SNMP) [1] packets over the transport mechanism provided via the Internetwork Packet Exchange (IPX) protocol [2].

この文書は、簡易ネットワーク管理プロトコル（SNMP: Simple Network Management Protocol）[1]のパケットを、IPX（Internetwork Packet Exchange）プロトコル[2]が提供するトランスポートの仕組み上でカプセル化するための規約を定義します。

Status of This Memo

このメモのステータス

This RFC specifies an IAB standards track protocol for the Internet community, and requests discussion and suggestions for improvements. Please refer to the current edition of the "IAB Official Protocol Standards" for the standardization state and status of this protocol. Distribution of this memo is unlimited.

このRFCは、インターネットコミュニティーのためのIAB標準化過程のプロトコルを規定し、改善のための議論と提案を求めるものです。このプロトコルの標準化の状態とステータスについては、「IAB Official Protocol Standards」の最新版を参照してください。このメモの配布は無制限です。

1. Introduction

1. はじめに

The Simple Network Management Protocol (SNMP) as defined in [1] is now used as an integral part of the network management framework for TCP/IP-based internets. Together with its companion standards, which define the Structure of Management Information (SMI) [3], [4], and the Management Information Base (MIB) [5], the SNMP has received widespread deployment in many operational networks running the Internet suite of protocols.

[1]で定義されている簡易ネットワーク管理プロトコル（SNMP）は、現在、TCP/IPベースのインターネットにおけるネットワーク管理フレームワークの不可欠な部分として使用されています。管理情報の構造（SMI: Structure of Management Information）[3], [4]と管理情報ベース（MIB: Management Information Base）[5]を定義する関連標準とともに、SNMPは、インターネットプロトコルスイートを運用している多くのネットワークで広く展開されています。

The success of SNMP in the TCP/IP environment has led to its deployment in non TCP/IP-based internets. This specification describes the mapping of SNMP onto the Internetwork Packet Exchange (IPX) protocol [2] used in Novell NetWare environments.

TCP/IP環境でのSNMPの成功により、SNMPはTCP/IPベースではないインターネットにも展開されるようになりました。この仕様は、Novell NetWare環境で使用されているIPX（Internetwork Packet Exchange）プロトコル[2]へのSNMPのマッピングを説明します。

As noted in [6], the preferred mapping for SNMP is onto UDP [7]. As such, this specification is intended for use in environments where UDP transport is not available. No aspect of this specification should be construed as a suggestion that, in a heterogeneous transport environment, a managed agent should support more than one mapping. Conversely, management stations are strongly encouraged to support mappings of SNMP onto all popular transports.

[6]で述べられているように、SNMPの望ましいマッピングはUDP [7]へのマッピングです。そのため、この仕様は、UDPトランスポートが利用できない環境で使用することを意図しています。この仕様のいかなる部分も、異種のトランスポートが混在する環境において、管理対象のエージェントが複数のマッピングをサポートすべきだという示唆として解釈すべきではありません。逆に、管理ステーションは、普及しているすべてのトランスポートへのSNMPのマッピングをサポートすることが強く推奨されます。

2. Mapping SNMP onto IPX

2. SNMPのIPXへのマッピング

Mapping SNMP onto IPX is straight-forward since IPX provides a datagram service very similar to that provided by IP/UDP.

IPXはIP/UDPが提供するものとよく似たデータグラムサービスを提供するため、SNMPのIPXへのマッピングは簡単です。

Although modifications have been made elsewhere in the NetWare protocol suite, IPX is identical to the Xerox Internet Datagram Protocol (IDP) [8]. The socket address space authority is administered by Novell.

NetWareプロトコルスイートのほかの部分には変更が加えられていますが、IPXはXerox Internet Datagram Protocol（IDP）[8]と同一です。ソケットアドレス空間の管理権限はNovellが持っています。

SNMP packets will always set the Packet Type field in the IPX header to 4 (i.e., Packet Exchange Packet).

SNMPのパケットでは、IPXヘッダーのPacket Typeフィールドを常に4（つまり、Packet Exchange Packet）に設定します。

2.1. Socket Assignments

2.1. ソケットの割り当て

SNMP protocol entities will receive GetRequest-PDU, GetNextRequest-PDU, and SetRequest-PDU messages on socket 36879 (Destination Socket field set to hexadecimal 900F), and Trap-PDU messages on socket 36880 (Destination Socket field set to hexadecimal 9010).

SNMPプロトコルエンティティーは、GetRequest-PDU、GetNextRequest-PDU、SetRequest-PDUのメッセージをソケット36879（Destination Socketフィールドを16進数の900Fに設定）で受信し、Trap-PDUのメッセージをソケット36880（Destination Socketフィールドを16進数の9010に設定）で受信します。

GetResponse-PDU messages will be addressed to the IPX address and socket from which the corresponding GetRequest-PDU, GetNextRequest-PDU, or SetRequest-PDU originated.

GetResponse-PDUのメッセージは、対応するGetRequest-PDU、GetNextRequest-PDU、またはSetRequest-PDUの送信元のIPXアドレスとソケットに宛てて送られます。

2.2. Traps

2.2. トラップ

When SNMP traps are sent over IPX, the agent-addr field in the Trap-PDU contains the IP-address "0.0.0.0". An SNMP manager may ascertain the source of the trap based on information provided by the transport service

SNMPのトラップをIPX上で送信する場合、Trap-PDUのagent-addrフィールドにはIPアドレス「0.0.0.0」を入れます。SNMPマネージャーは、トランスポートサービスが提供する情報に基づいてトラップの送信元を確認できます。

2.3. Maximum Message Size

2.3. 最大メッセージサイズ

Although SNMP does not require conformant implementations to accept messages whose length exceeds 484 bytes, it is recommended that implementations support a maximum SNMP message size of 546 bytes (the maximum size allowed under IPX). Furthermore, this limit is the maximum packet length guaranteed to traverse IPX routers which do not provide fragmentation. Implementors may choose to use longer packet lengths if the maximum is known, which depends on the intermediate routers and/or intermediate datalink layer protocols.

SNMPは、準拠する実装に対して長さが484バイトを超えるメッセージを受け入れることを要求していませんが、実装はSNMPの最大メッセージサイズとして546バイト（IPXで許される最大サイズ）をサポートすることが推奨されます。さらに、この上限は、フラグメンテーションを提供しないIPXルーターを通過できることが保証されている最大パケット長です。最大値がわかっている場合、実装者はより長いパケット長を使用することを選択できます。最大値は、途中のルーターや途中のデータリンク層プロトコルに依存します。
