YANG Data Model for OSPFv3 Extended Link State Advertisements (LSAs)

RFC 9587

OSPFv3拡張リンクステート広告（LSA）のためのYANGデータモデル

Abstract

概要

This document defines a YANG data model augmenting the IETF OSPF YANG data model (RFC 9129) to provide support for OSPFv3 Link State Advertisement (LSA) Extensibility as defined in RFC 8362. OSPFv3 Extended LSAs provide extensible TLV-based LSAs for the base LSA types defined in RFC 5340.

この文書は、RFC 8362で定義されているOSPFv3リンクステート広告（LSA）の拡張性をサポートするために、IETFのOSPF YANGデータモデル（RFC 9129）を拡張（augment）するYANGデータモデルを定義します。 OSPFv3拡張LSAは、RFC 5340で定義されている基本LSAタイプに対して、TLVベースの拡張可能なLSAを提供します。

1. Overview

1. 概要

YANG [RFC7950] is a data definition language used to define the contents of a conceptual datastore that allows networked devices to be managed using NETCONF [RFC6241]. YANG is proving relevant beyond its initial confines as bindings to other interfaces (e.g., RESTCONF [RFC8040]) and encodings other than XML (e.g., JSON) are being defined. Furthermore, YANG data models can be used as the basis for implementation of other interfaces, such as Command-Line Interfaces (CLIs) and programmatic APIs.

YANG [RFC7950]は、ネットワーク機器をNETCONF [RFC6241]を使って管理できるようにする、概念的なデータストアの内容を定義するために使われるデータ定義言語です。 他のインターフェイス（たとえば、RESTCONF [RFC8040]）へのバインディングや、XML以外のエンコーディング（たとえば、JSON）が定義されつつあり、YANGは当初の範囲を超えて有用であることが明らかになってきています。 さらに、YANGデータモデルは、コマンドラインインターフェイス（CLI）やプログラム用のAPIなど、他のインターフェイスを実装する際の基礎としても利用できます。

This document defines a YANG data model augmenting the IETF OSPF YANG data model [RFC9129], which itself augments [RFC8349], to provide support for configuration and operational state for OSPFv3 Extended Link State Advertisements (LSAs) as defined in [RFC8362].

この文書は、[RFC8362]で定義されているOSPFv3拡張リンクステート広告（LSA）の設定と運用状態をサポートするために、IETFのOSPF YANGデータモデル[RFC9129]（それ自体が[RFC8349]を拡張しています）を拡張（augment）するYANGデータモデルを定義します。

The YANG module specified in this document conforms to the Network Management Datastore Architecture (NMDA) [RFC8342].

この文書で規定するYANGモジュールは、ネットワーク管理データストアアーキテクチャー（NMDA）[RFC8342]に準拠しています。

3. OSPFv3 Extended LSAs

3. OSPFv3拡張LSA

This document defines a YANG data model for the OSPFv3 Extended LSA feature. It is an augmentation of the OSPF base model [RFC9129] to provide support for OSPFv3 LSA Extensibility [RFC8362]. OSPFv3 Extended LSAs provide extensible TLV-based LSAs for the base LSA types defined in [RFC5340].

この文書は、OSPFv3拡張LSA機能のためのYANGデータモデルを定義します。 これは、OSPFv3 LSAの拡張性[RFC8362]をサポートするための、OSPFベースモデル[RFC9129]の拡張（augmentation）です。 OSPFv3拡張LSAは、[RFC5340]で定義されている基本LSAタイプに対して、TLVベースの拡張可能なLSAを提供します。

The OSPFv3 Extended LSA YANG module requires support for the OSPF base model, which defines basic OSPF configuration and state. The OSPF YANG data model augments the "ietf-routing" YANG data model defined in [RFC8349]. The augmentations defined in the "ietf-ospfv3-extended-lsa" YANG module provide global configuration, area configuration, and the addition of OSPFv3 Extended LSAs to the Link State Database (LSDB) operational state.

OSPFv3拡張LSA YANGモジュールには、OSPFの基本的な設定と状態を定義するOSPFベースモデルのサポートが必要です。 OSPF YANGデータモデルは、[RFC8349]で定義されている"ietf-routing" YANGデータモデルを拡張しています。 "ietf-ospfv3-extended-lsa" YANGモジュールで定義される拡張は、グローバルな設定、エリアの設定、およびリンクステートデータベース（LSDB）の運用状態へのOSPFv3拡張LSAの追加を提供します。

5. Security Considerations

5. セキュリティーに関する考慮事項

The YANG module specified in this document defines a schema for data that is designed to be accessed via network management protocols such as NETCONF [RFC6241] or RESTCONF [RFC8040]. The lowest NETCONF layer is the secure transport layer, and the mandatory-to-implement secure transport is Secure Shell (SSH) [RFC6242]. The lowest RESTCONF layer is HTTPS, and the mandatory-to-implement secure transport is TLS [RFC8446].

この文書で規定するYANGモジュールは、NETCONF [RFC6241]やRESTCONF [RFC8040]などのネットワーク管理プロトコルを介してアクセスされるように設計されたデータのスキーマを定義します。 NETCONFの最下位層はセキュアなトランスポート層であり、実装必須のセキュアなトランスポートはSecure Shell（SSH）[RFC6242]です。 RESTCONFの最下位層はHTTPSであり、実装必須のセキュアなトランスポートはTLS [RFC8446]です。

The Network Configuration Access Control Model (NACM) [RFC8341] provides the means to restrict access for particular NETCONF or RESTCONF users to a preconfigured subset of all available NETCONF or RESTCONF protocol operations and content.

ネットワーク設定アクセス制御モデル（Network Configuration Access Control Model、NACM）[RFC8341]は、特定のNETCONFまたはRESTCONFユーザーのアクセスを、利用可能なすべてのNETCONFまたはRESTCONFプロトコル操作とコンテンツのうち、あらかじめ設定されたサブセットに制限する手段を提供します。

There are a number of data nodes defined in the "ietf-ospfv3-extended-lsa.yang" module that are writable/creatable/deletable (i.e., config true, which is the default). These data nodes may be considered sensitive or vulnerable in some network environments. Write operations (e.g., edit-config) to these data nodes without proper protection can have a negative effect on network operations. These are the subtrees and data nodes and their sensitivity/vulnerability:

"ietf-ospfv3-extended-lsa.yang"モジュールには、書き込み・作成・削除が可能な（つまり、デフォルトであるconfig trueの）データノードがいくつか定義されています。 これらのデータノードは、一部のネットワーク環境では機密性が高い、または脆弱であるとみなされる場合があります。 適切な保護なしにこれらのデータノードへの書き込み操作（たとえば、edit-config）を行うと、ネットワーク運用に悪影響を及ぼす可能性があります。 該当するサブツリーとデータノード、およびそれらの機密性・脆弱性は次のとおりです：

/ospf:ospf/extended-lsa-support

/ospf:ospf/extended-lsa-support

/ospf:ospf/ospf:areas/ospf:area/extended-lsa-support

/ospf:ospf/ospf:areas/ospf:area/extended-lsa-support

The ability to disable or enable OSPFv3 Extended LSA support can result in a Denial-of-Service (DoS) attack, since OSPFv3 routers will use solely OSPFv3 Extended LSAs or OSPFv3 Legacy LSAs for the OSPFv3 SPF computation. OSPFv3 routers using different types of LSAs will result in incomplete reachability and possible partitioning of the OSPFv3 routing domain. Refer to Section 6 of [RFC8362] for more information on OSPFv3 Extended LSA compatibility.

OSPFv3ルーターはOSPFv3のSPF計算に、OSPFv3拡張LSAとOSPFv3レガシーLSAのどちらか一方のみを使用するため、OSPFv3拡張LSAのサポートを無効化または有効化できる能力は、サービス拒否（DoS）攻撃につながる可能性があります。 異なるタイプのLSAを使用するOSPFv3ルーターが混在すると、到達可能性が不完全になり、OSPFv3ルーティングドメインが分断されるおそれがあります。 OSPFv3拡張LSAの互換性に関する詳細については、[RFC8362]のSection 6を参照してください。

Some of the readable data nodes in the "ietf-ospfv3-extended-lsa.yang" module may be considered sensitive or vulnerable in some network environments. It is thus important to control read access (e.g., via get, get-config, or notification) to these data nodes.

"ietf-ospfv3-extended-lsa.yang"モジュール内の読み取り可能なデータノードの一部は、一部のネットワーク環境では機密性が高い、または脆弱であるとみなされる場合があります。 したがって、これらのデータノードへの読み取りアクセス（たとえば、get、get-config、または通知を介したもの）を制御することが重要です。

Exposing the Link State Database (LSDB) will in turn expose the detailed topology of the network. This includes topological information from other routers. This may be undesirable due to the fact that exposure may facilitate other attacks. Additionally, network operators may consider their topologies to be sensitive confidential data.

リンクステートデータベース（LSDB）を公開すると、結果としてネットワークの詳細なトポロジーが公開されることになります。 これには、他のルーターからのトポロジー情報も含まれます。 公開によって他の攻撃が容易になる可能性があるため、これは望ましくない場合があります。 さらに、ネットワーク運用者は、自身のトポロジーを機密性の高い秘密のデータとみなす場合があります。
