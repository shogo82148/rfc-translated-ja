RFC 123

A Proferred Official ICP

RFC 123

公式ICPの提案

Abstract

概要

By Initial Connection Protocol (ICP), I mean a third level protocol which is initiated by a user process at one site in order to contact a server process at another site. Typically, the user process will be a Telnet and the server process will be a logger, but there may be other cases.

初期接続プロトコル（Initial Connection Protocol: ICP）とは、あるサイトのユーザープロセスが、別のサイトのサーバープロセスと連絡を取るために開始する第3レベルのプロトコルのことです。通常、ユーザープロセスはTelnetで、サーバープロセスはロガーですが、それ以外の場合もありえます。

In this RFC, I wish to describe a family of ICPs suitable for establishing one pair of connections (one in each direction) between any user process and any server process, and to propose further a particular subset of this family as the standard ICP for connecting user processes to loggers on systems which accept teletype-like devices.

このRFCでは、任意のユーザープロセスと任意のサーバープロセスの間に1組の接続（各方向に1つずつ）を確立するのに適したICPの系統を説明し、さらにこの系統の特定のサブセットを、テレタイプ類似のデバイスを受け付けるシステム上のロガーにユーザープロセスを接続するための標準ICPとして提案したいと思います。

Notation

表記法

We have no standard notation for describing system calls which initiate and close connections or cause data to be sent, so I will use the following ad hoc notation.

接続を開始・切断したり、データを送信させたりするシステムコールを記述するための標準的な表記法はないので、次の場当たり的な表記法を使います。

Init (local = l, foreign = f, size = s)

causes the local Host to attempt to establish a connection between socket l at the local Host and socket f, with a byte size of s for the connection.

l is a 32 bit local socket number,
f is a 40 bit foreign socket number, the high-order eight bits of which specify the foreign Host, and
s is an eight bit non-zero byte size.
The sum of l and f must be odd.

Listen (local = l, size = s)

causes the local Host to wait for a request for connection to local socket l with byte size s. The process will be woken when a connection is established. The parameters l and s are the same as for Init.

Send (socket = l, data = d)

The data named by d is sent over the connection attached to local socket l. l must be a send socket attached to a connection. d is the name of a data area.

Receive (socket = l, data = d)

The receive side counterpart to send.

Close (socket = l)

Any connection currently attached to a local socket l is closed.

Init (local = l, foreign = f, size = s)

ローカルホストに、ローカルホストのソケットlとソケットfの間に、バイトサイズsの接続を確立するよう試みさせます。

lは32ビットのローカルソケット番号です。
fは40ビットの外部ソケット番号で、その上位8ビットが外部ホストを示します。
sは0でない8ビットのバイトサイズです。
lとfの和は奇数でなければなりません。

Listen (local = l, size = s)

ローカルホストに、ローカルソケットlへのバイトサイズsの接続要求を待たせます。接続が確立されると、プロセスは起こされます。パラメーターlとsはInitと同じです。

Send (socket = l, data = d)

dで指定されたデータを、ローカルソケットlに結び付けられた接続を通じて送信します。lは、接続に結び付けられた送信ソケットでなければなりません。dはデータ領域の名前です。

Receive (socket = l, data = d)

sendに対応する受信側の操作です。

Close (socket = l)

ローカルソケットlに現在結び付けられている接続を切断します。

A Family of ICPs

ICPの系統

Briefly, a server process at a site attaches a well-advertised send socket L and listens. A user process initiates connection to L from its receive socket U. The byte size for this connection is 32. The server process then transmits a 32-bit even number S and closes the connection. The 32-bit number S and its successor, S+1, are the socket number the server will use. The final steps are for sockets S and S+1 at the server site to be connected to sockets U+1 and U respectively at the user site.

簡単に言うと、あるサイトのサーバープロセスは、広く知られた送信ソケットLを結び付けて待ち受けます。ユーザープロセスは、自身の受信ソケットUからLへの接続を開始します。この接続のバイトサイズは32です。次にサーバープロセスは32ビットの偶数Sを送信し、接続を切断します。32ビットの数値Sとその次の数S+1が、サーバーが使用するソケット番号です。最後の手順として、サーバーサイトのソケットSとS+1を、ユーザーサイトのソケットU+1とUにそれぞれ接続します。

Using the notation, the server executes the following sequence:

この表記法を使うと、サーバーは次の手順を実行します。

   Listen (socket = L, size = 32)
   [Wait until a user connects]
   Send (socket = L, data = S)
   Close (socket = L)
   Init (local = S, foreign = U+1, size = Bu)
   Init (local = S+1, foreign = U, size = Bs)

   Listen (socket = L, size = 32)
   [Wait until a user connects]
   Send (socket = L, data = S)
   Close (socket = L)
   Init (local = S, foreign = U+1, size = Bu)
   Init (local = S+1, foreign = U, size = Bs)

The user executes the following:

ユーザーは次の手順を実行します。

   Init (local = U, foreign = L, size = 32)
   Receive (socket = U, data = S)
   Close (socket = U)
   Init (local = U+1, foreign = S, size = Bu)
   Init (local = U, foreign = S+1, size = Bs)

   Init (local = U, foreign = L, size = 32)
   Receive (socket = U, data = S)
   Close (socket = U)
   Init (local = U+1, foreign = S, size = Bu)
   Init (local = U, foreign = S+1, size = Bs)

Note that L is a send socket (odd), while S and U are receive sockets (even). Where L, S or U are used as values of local, they are 32-bit numbers; where they are values of foreign, they are 40-bit numbers. The parameters Bs and Bu are the byte sizes to be sent by the server and user, respectively.

Lは送信ソケット（奇数）であり、SとUは受信ソケット（偶数）であることに注意してください。L、S、Uがlocalの値として使われる場合は32ビットの数値であり、foreignの値として使われる場合は40ビットの数値です。パラメーターBsとBuは、それぞれサーバーとユーザーが送信するバイトサイズです。

Examination of the above sequences reveals that an ICP is characterized by the three numbers L, Bs and Bu, and must meet the restrictions that

上記の手順を調べると、ICPは3つの数値L、Bs、Buによって特徴付けられ、次の制約を満たさなければならないことがわかります。

  1. L is a send socket,
  2. Bs and Bu are legal byte sizes, and
  3. for each L there is only on pair of associated byte sizes.
  1. Lは送信ソケットである。
  2. BsとBuは正当なバイトサイズである。
  3. 各Lに対して、関連付けられるバイトサイズの組は1つだけである。

This last restriction prevents two distinct services from being available through the same socket and distinguished only by the byte sizes.

最後の制約は、2つの異なるサービスが同じソケットを通じて提供され、バイトサイズだけで区別されるという事態を防ぐためのものです。

Telnet ICP

Telnet ICP

For connecting teletype-like users, i.e. interactive and ASCII, to Hosts serving such users, I propose an ICP of the form described above and characterized by L = 1, Bs = Bu = 8. [There has been some confusion about socket numbers. Here I specifically mean L = X00000001]

テレタイプ類似のユーザー、つまり対話型でASCIIを使うユーザーを、そのようなユーザーにサービスを提供するホストに接続するために、上で説明した形式で、L = 1、Bs = Bu = 8で特徴付けられるICPを提案します。[ソケット番号について混乱がありました。ここでは具体的にL = X00000001を意味しています]

Formalities

正式な手続き

I propose that the Telnet ICP be made official. Comments should be published before the May NWG meeting, the subject will be discussed there, and we will decide there to accept or reject this protocol.

Telnet ICPを公式なものとすることを提案します。コメントは5月のNWG会合の前に公表してください。この件はその会合で議論し、このプロトコルを採用するか却下するかをその場で決定します。
