RFC 679

February, 1975, Survey of New-Protocol TELNET Servers

RFC 679

1975年2月の新プロトコルTELNETサーバーの調査

Abstract

概要

It has been two and a half months since our last survey, and it has been depressing to note that "progress" toward an all-new-protocol network has been even slower than previously. Changes since the last list (with host numbers in octal):

前回の調査から2か月半が経ちましたが、すべてが新プロトコルのネットワークに向けた「進捗」が以前よりもさらに遅くなっていることに気づき、気が滅入っています。前回の一覧からの変更点は次のとおりです（ホスト番号は8進数）。

  • SRI-ARC (2) and OFFICE-1 (53) have added logger sockets 27, but with Old-Protocol servers (are these forerunners of New-Protocol servers?);
  • SDC-CC (110) has been removed from the list until it starts operating on the network
  • LL-67 (12) now has a New-Protocol server on socket 1;
  • CASE-10 (15) has departed from the network;
  • BBN-TENEX is now host 361 (formerly 105);
  • ANL (ARGONNE, 67) has come on the net with Old- and New-Protocol servers on sockets 1 and 27, respectively.
  • SRI-ARC（2）とOFFICE-1（53）はロガーのソケット27を追加しましたが、サーバーは旧プロトコルのものです（これらは新プロトコルのサーバーの先駆けなのでしょうか？）。
  • SDC-CC（110）は、ネットワーク上で運用を開始するまで一覧から外しました。
  • LL-67（12）は、ソケット1で新プロトコルのサーバーを提供するようになりました。
  • CASE-10（15）はネットワークから離脱しました。
  • BBN-TENEXは、ホスト361になりました（以前は105）。
  • ANL（ARGONNE、67）が、ソケット1に旧プロトコルのサーバー、ソケット27に新プロトコルのサーバーを備えてネットワークに参加しました。

注：

*
All data in this report were gathered via a surveying program run at various times, plus a few manual checks to fill out the data. What is reported here is the way the various servers work as seen by the new-Protocol User Telnet at BBNA, as of 20 Feb. 1975.
(2)
These are the sites whose operation is 100% correct according to all protocols and conventions, as I understand them.
(3)
We realize that some of the servers that appear here as New- Protocol servers on socket 1 are actually servers which attempt to communicate with both Old- and New-Protocol User TELNETs according to what control sequences are received.
*
このレポートのデータはすべて、さまざまな時刻に実行した調査プログラムによって収集し、データを補うためにいくつか手作業で確認したものです。ここで報告しているのは、1975年2月20日時点で、BBNAの新プロトコルのユーザーTelnetから見た各サーバーの動作です。
(2)
私の理解する限り、すべてのプロトコルと慣例に従って100%正しく動作しているサイトです。
(3)

Key:

凡例：

X
No server at this socket
?
Status not ascertained -- unable to connect to host
I#
Option # implemented incoming to user (Server says "Will #")
O#
Option # implemented outgoing from user (Server says "Do #")
X
このソケットにはサーバーがありません
?
状態を確認できませんでした（ホストに接続できませんでした）
I#
ユーザーへの受信方向のオプション#が実装されています（サーバーは「Will #」と応答します）
O#
ユーザーからの送信方向のオプション#が実装されています（サーバーは「Do #」と応答します）

(# is option number in new Protocol. All options implemented by anyone are:

（#は新プロトコルでのオプション番号です。いずれかのサイトで実装されているオプションは次のとおりです。

0
Transmit-Binary
1
Echo
3
Suppress-Go-Ahead
6
Timing-Mark )
0
Transmit-Binary
1
Echo
3
Suppress-Go-Ahead
6
Timing-Mark）

Note: * These servers return improper responses to some TELNET option requests.

注：*これらのサーバーは、一部のTELNETオプションの要求に対して不適切な応答を返します。
