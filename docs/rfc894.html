RFC 894

A Standard for the Transmission of IP Datagrams over Ethernet Networks

RFC 894

イーサネットネットワーク上でIPデータグラムを伝送するための標準

Status of This Memo

このメモのステータス

This RFC specifies a standard method of encapsulating Internet Protocol (IP) [1] datagrams on an Ethernet [2]. This RFC specifies a standard protocol for the ARPA-Internet community.

このRFCは、インターネットプロトコル（IP）[1]のデータグラムをイーサネット[2]上でカプセル化する標準的な方法を規定します。このRFCは、ARPAインターネットコミュニティーのための標準プロトコルを規定します。

Introduction

はじめに

This memo applies to the Ethernet (10-megabit/second, 48-bit addresses). The procedure for transmission of IP datagrams on the Experimental Ethernet (3-megabit/second, 8-bit addresses) is described in [3].

このメモは、イーサネット（10メガビット/秒、48ビットアドレス）に適用されます。実験的イーサネット（Experimental Ethernet、3メガビット/秒、8ビットアドレス）上でIPデータグラムを伝送する手順は、[3]で説明しています。

Frame Format

フレーム形式

IP datagrams are transmitted in standard Ethernet frames. The type field of the Ethernet frame must contain the value hexadecimal 0800. The data field contains the IP header followed immediately by the IP data.

IPデータグラムは、標準のイーサネットフレームで伝送します。イーサネットフレームのタイプフィールドには、16進数の値0800が入っていなければなりません。データフィールドにはIPヘッダーが入り、その直後にIPデータが続きます。

The minimum length of the data field of a packet sent over an Ethernet is 46 octets. If necessary, the data field should be padded (with octets of zero) to meet the Ethernet minimum frame size. This padding is not part of the IP packet and is not included in the total length field of the IP header.

イーサネット上で送るパケットのデータフィールドの最小長は46オクテットです。必要であれば、イーサネットの最小フレームサイズを満たすように、データフィールドを（値が0のオクテットで）パディングすべきです。このパディングはIPパケットの一部ではなく、IPヘッダーの全長フィールドにも含めません。

The minimum length of the data field of a packet sent over an Ethernet is 1500 octets, thus the maximum length of an IP datagram sent over an Ethernet is 1500 octets. Implementations are encouraged to support full-length packets. Gateway implementations MUST be prepared to accept full-length packets and fragment them if necessary. If a system cannot receive full-length packets, it should take steps to discourage others from sending them, such as using the TCP Maximum Segment Size option [4].

イーサネット上で送るパケットのデータフィールドの最小長は1500オクテットです。したがって、イーサネット上で送るIPデータグラムの最大長は1500オクテットです。実装は最大長のパケットをサポートすることが推奨されます。ゲートウェイの実装は、最大長のパケットを受け入れ、必要であればそれをフラグメント化できるように準備しておかなければなりません（MUST）。最大長のパケットを受信できないシステムは、TCPの最大セグメントサイズ（Maximum Segment Size）オプション[4]を使うなどして、他のシステムがそのようなパケットを送らないようにする措置をとるべきです。

Note: Datagrams on the Ethernet may be longer than the general Internet default maximum packet size of 576 octets. Hosts connected to an Ethernet should keep this in mind when sending datagrams to hosts not on the same Ethernet. It may be appropriate to send smaller datagrams to avoid unnecessary fragmentation at intermediate gateways. Please see [4] for further information on this point.

注：イーサネット上のデータグラムは、インターネット全般のデフォルトの最大パケットサイズである576オクテットよりも長くなることがあります。イーサネットに接続しているホストは、同じイーサネット上にないホストにデータグラムを送るときに、このことを念頭に置くべきです。途中のゲートウェイでの不要なフラグメント化を避けるために、より小さいデータグラムを送るのが適切な場合もあります。この点に関する詳しい情報は[4]を参照してください。

Address Mappings

アドレスの対応付け

The mapping of 32-bit Internet addresses to 48-bit Ethernet addresses can be done several ways. A static table could be used, or a dynamic discovery procedure could be used.

32ビットのインターネットアドレスを48ビットのイーサネットアドレスに対応付けるには、いくつかの方法があります。静的な表を使うこともできますし、動的な発見手順を使うこともできます。

Static Table

Each host could be provided with a table of all other hosts on the local network with both their Ethernet and Internet addresses.

Dynamic Discovery

Mappings between 32-bit Internet addresses and 48-bit Ethernet addresses could be accomplished through the Address Resolution Protocol (ARP) [5]. Internet addresses are assigned arbitrarily on some Internet network. Each host's implementation must know its own Internet address and respond to Ethernet Address Resolution packets appropriately. It should also use ARP to translate Internet addresses to Ethernet addresses when needed.

Broadcast Address

The broadcast Internet address (the address on that network with a host part of all binary ones) should be mapped to the broadcast Ethernet address (of all binary ones, FF-FF-FF-FF-FF-FF hex).

静的な表

各ホストに、ローカルネットワーク上の他のすべてのホストについて、そのイーサネットアドレスとインターネットアドレスの両方を載せた表を持たせることができます。

動的な発見

32ビットのインターネットアドレスと48ビットのイーサネットアドレスの対応付けは、アドレス解決プロトコル（Address Resolution Protocol、ARP）[5]によって行えます。インターネットネットワークによっては、インターネットアドレスが任意に割り当てられます。各ホストの実装は、自分のインターネットアドレスを知っていなければならず、イーサネットのアドレス解決パケットに適切に応答しなければなりません。また、必要なときには、ARPを使ってインターネットアドレスをイーサネットアドレスに変換すべきです。

ブロードキャストアドレス

ブロードキャストのインターネットアドレス（そのネットワーク上で、ホスト部が2進数ですべて1のアドレス）は、ブロードキャストのイーサネットアドレス（2進数ですべて1、16進数でFF-FF-FF-FF-FF-FF）に対応付けるべきです。

The use of the ARP dynamic discovery procedure is strongly recommended.

ARPによる動的な発見手順を使うことを強く推奨します。

Trailer Formats

トレーラー形式

Some versions of Unix 4.2bsd use a different encapsulation method in order to get better network performance with the VAX virtual memory architecture. Consenting systems on the same Ethernet may use this format between themselves.

Unix 4.2bsdのいくつかのバージョンは、VAXの仮想メモリーアーキテクチャーでより良いネットワーク性能を得るために、別のカプセル化方法を使います。同じイーサネット上の、合意したシステム同士は、この形式を使ってもかまいません。

No host is required to implement it, and no datagrams in this format should be sent to any host unless the sender has positive knowledge that the recipient will be able to interpret them. Details of the trailer encapsulation may be found in [6].

どのホストもこれを実装する必要はありません。また、受信者がこの形式のデータグラムを解釈できることを送信者が確実に知っている場合を除き、この形式のデータグラムをどのホストにも送るべきではありません。トレーラーカプセル化の詳細は[6]にあります。

(Note: At the present time Unix 4.2bsd will either always use trailers or never use them (per interface), depending on a boot-time option. This is expected to be changed in the future. Unix 4.2bsd also uses a non-standard Internet broadcast address with a host part of all zeroes, this may also be changed in the future.)

（注：現時点では、Unix 4.2bsdは、起動時のオプションに応じて、（インターフェイスごとに）トレーラーを常に使うか、まったく使わないかのどちらかです。これは将来変更される見込みです。また、Unix 4.2bsdはホスト部がすべて0という非標準のインターネットブロードキャストアドレスを使っていますが、これも将来変更されるかもしれません。）

Byte Order

バイト順序

As described in Appendix B of the Internet Protocol specification [1], the IP datagram is transmitted over the Ethernet as a series of 8-bit bytes.

インターネットプロトコルの仕様[1]の付録Bで説明しているように、IPデータグラムは8ビットのバイトの列としてイーサネット上で伝送します。
