RFC 1626

Default IP MTU for use over ATM AAL5

RFC 1626

ATM AAL5上で使用するデフォルトのIP MTU

Status of This Memo

このメモのステータス

This document specifies an Internet standards track protocol for the Internet community, and requests discussion and suggestions for improvements. Please refer to the current edition of the "Internet Official Protocol Standards" (STD 1) for the standardization state and status of this protocol. Distribution of this memo is unlimited.

この文書は、インターネットコミュニティーのためのインターネット標準化過程（Internet Standards Track）のプロトコルを規定し、改善のための議論と提案を求めるものです。このプロトコルの標準化の状態とステータスについては、「Internet Official Protocol Standards」（STD 1）の最新版を参照してください。このメモの配布は無制限です。

Default Value for IP MTU over ATM AAL5

ATM AAL5上のIP MTUのデフォルト値

Protocols in wide use throughout the Internet, such as the Network File System (NFS), currently use large frame sizes (e.g. 8 KB). Empirical evidence with various applications over the Transmission Control Protocol (TCP) indicates that larger Maximum Transmission Unit (MTU) sizes for the Internet Protocol (IP) tend to give better performance. Fragmentation of IP datagrams is known to be highly undesirable. [KM87] It is desirable to reduce fragmentation in the network and thereby enhance performance by having the IP Maximum Transmission Unit (MTU) for AAL5 be reasonably large. NFS defaults to an 8192 byte frame size. Allowing for RPC/XDR, UDP, IP, and LLC headers, NFS would prefer a default MTU of at least 8300 octets. Routers can sometimes perform better with larger packet sizes because most of the performance costs in routers relate to "packets handled" rather than "bytes transferred". So there are a number of good reasons to have a reasonably large default MTU value for IP over ATM AAL5.

ネットワークファイルシステム（Network File System; NFS）など、インターネット全体で広く使われているプロトコルは、現在、大きなフレームサイズ（たとえば8KB）を使っています。伝送制御プロトコル（Transmission Control Protocol; TCP）上のさまざまなアプリケーションによる経験的な証拠から、インターネットプロトコル（Internet Protocol; IP）の最大転送単位（Maximum Transmission Unit; MTU）のサイズが大きいほど性能が向上する傾向があることがわかっています。IPデータグラムのフラグメント化は非常に望ましくないことが知られています。[KM87] AAL5のIP最大転送単位（MTU）を適度に大きくすることで、ネットワーク内のフラグメント化を減らし、それによって性能を向上させることが望まれます。NFSのデフォルトのフレームサイズは8192バイトです。RPC/XDR、UDP、IP、LLCの各ヘッダーを考慮すると、NFSにとってはデフォルトMTUが8300オクテット以上であることが望ましいでしょう。ルーターのコストの大部分は「転送したバイト数」ではなく「処理したパケット数」に関係するため、ルーターはパケットサイズが大きいほうが性能が向上することがあります。このように、ATM AAL5上のIPのデフォルトMTU値を適度に大きくすべき十分な理由がいくつもあります。

RFC 1209 specifies the IP MTU over SMDS to be 9180 octets, which is larger than 8300 octets but still in the same range. [RFC-1209] There is no good reason for the default MTU of IP over ATM AAL5 to be different from IP over SMDS, given that they will be the same magnitude. Having the two be the same size will be helpful in interoperability and will also help reduce incidence of IP fragmentation.

RFC 1209は、SMDS上のIP MTUを9180オクテットと規定しています。これは8300オクテットより大きいですが、同じ範囲内にあります。[RFC-1209]両者が同じ規模であることを考えると、ATM AAL5上のIPのデフォルトMTUをSMDS上のIPと異なるものにする十分な理由はありません。両者を同じサイズにすることは、相互運用性に役立ち、IPのフラグメント化の発生を減らすことにも役立つでしょう。

Therefore, the default IP MTU for use with ATM AAL5 shall be 9180 octets. All implementations compliant and conformant with this specification shall support at least the default IP MTU value for use over ATM AAL5.

したがって、ATM AAL5で使用するデフォルトのIP MTUは9180オクテットとします。この仕様に準拠するすべての実装は、ATM AAL5上で使用するために、少なくともデフォルトのIP MTU値をサポートするものとします。

Permanent Virtual Circuits

永続仮想回線

Implementations which only support Permanent Virtual Circuits (PVCs) will (by definition) not implement any ATM signalling protocol. Such implementations shall use the default IP MTU value of 9180 octets unless both parties have agreed in advance to use some other IP MTU value via some mechanism not specified here.

永続仮想回線（Permanent Virtual Circuit; PVC）だけをサポートする実装は、（定義上）ATMシグナリングプロトコルを実装しません。そのような実装は、ここでは規定しない何らかの仕組みによって両者が別のIP MTU値を使うことにあらかじめ合意していない限り、9180オクテットというデフォルトのIP MTU値を使うものとします。

Switched Virtual Circuits

交換仮想回線

Implementations that support Switched Virtual Circuits (SVCs) MUST attempt to negotiate the AAL CPCS-SDU size using the ATM signalling protocol. The industry standard ATM signalling protocol uses two different parts of the Information Element named "AAL Parameters" to exchange information on the MTU over the ATM circuit being setup [ATMF93a]. The Forward Maximum CPCS-SDU Size field contains the value over the path from the calling party to the called party. The Backwards Maximum CPCS-SDU Size Identifier field contains the value over the path from the called party to the calling party. The ATM Forum specifies the valid values of this identifier as 1 to 65535 inclusive. Note that the ATM Forum's User-to-Network-Interface (UNI) signalling permits the MTU in one direction to be different from the MTU in the opposite direction, so the Forward Maximum CPCS-SDU Size Identifier might have a different value from the Backwards Maximum CPCS-SDU Size Identifier on the same connection.

交換仮想回線（Switched Virtual Circuit; SVC）をサポートする実装は、ATMシグナリングプロトコルを使ってAAL CPCS-SDUサイズのネゴシエーションを試みなければなりません。業界標準のATMシグナリングプロトコルは、「AAL Parameters」という名前の情報要素（Information Element）の2つの異なる部分を使って、設定中のATM回線上のMTUに関する情報を交換します[ATMF93a]。Forward Maximum CPCS-SDU Sizeフィールドには、発呼側から着呼側への経路の値が含まれます。Backwards Maximum CPCS-SDU Size Identifierフィールドには、着呼側から発呼側への経路の値が含まれます。ATMフォーラムは、この識別子の有効な値を1以上65535以下と規定しています。ATMフォーラムのユーザー・ネットワーク・インターフェイス（User-to-Network-Interface; UNI）のシグナリングでは、一方向のMTUを逆方向のMTUと異なるものにできるので、同じ接続上でForward Maximum CPCS-SDU Size IdentifierとBackwards Maximum CPCS-SDU Size Identifierの値が異なる場合があることに注意してください。

If the calling party wishes to use the default MTU it shall still include the "AAL Parameters" information element with the default values for the Maximum CPCS-SDU Size as part of the SETUP message of the ATM signalling protocol [ATMF93b]. If the calling party desires to use a different value than the default, it shall include the "AAL Parameters" information element with the desired value for the Maximum CPCS-SDU Size as part of the SETUP message of the ATM Signalling Protocol. The called party will respond using the same information elements and identifiers in its CONNECT message response [ATMF93c].

発呼側がデフォルトのMTUを使いたい場合でも、ATMシグナリングプロトコルのSETUPメッセージの一部として、Maximum CPCS-SDU Sizeのデフォルト値を含む「AAL Parameters」情報要素を含めるものとします[ATMF93b]。発呼側がデフォルトとは異なる値を使いたい場合は、ATMシグナリングプロトコルのSETUPメッセージの一部として、Maximum CPCS-SDU Sizeの希望する値を含む「AAL Parameters」情報要素を含めるものとします。着呼側は、CONNECTメッセージの応答で同じ情報要素と識別子を使って応答します[ATMF93c]。

If the called party receives a SETUP message containing the "Maximum CPCS-SDU Size" in the AAL Parameters information element, it shall handle the Forward and Backward Maximum CPCS-SDU Size Identifier as follows:

着呼側は、AAL Parameters情報要素に「Maximum CPCS-SDU Size」を含むSETUPメッセージを受信した場合、ForwardおよびBackwardのMaximum CPCS-SDU Size Identifierを次のように扱うものとします。

  1. If it is able to accept the ATM MTU values proposed by the SETUP message, it shall include an AAL Parameters information element in its response. The Forward and Backwards Maximum CPCS-SDU Size fields shall be present and their values shall be equal to the corresponding values in the SETUP message.
  2. If it wishes a smaller ATM MTU size than that proposed, then it shall set the values of the Maximum CPCS-SDU Size in the AAL Parameters information elements equal to the desired value in the CONNECT message responding to the original SETUP message.
  3. If the calling endpoint receives a CONNECT message that does not contain the AAL Parameters Information Element, but the corresponding SETUP message did contain the AAL Parameters Information Telement (including the forward and backward CPCS-SDU Size fields), it shall clear the call with cause "AAL Parameters cannot be supported".
  4. If either endpoint receives a STATUS message with cause "Information Element Non-existent or Not Implemented" or cause ""Access Information Discarded", and with a diagnostic field indicating the AAL Parameters Information Element identifier, it shall clear the call with cause "AAL Parameters cannot be supported."
  5. If either endpoint receives CPCS-SDUs in excess of the negotiated MTU size, it may use IP fragmentation or may clear the call with cause "AAL Parameters cannot be supported". In this case, an error has occurred either due to a fault in an end system or in the ATM network. The error should be noted by ATM network management for human examination and intervention.
  1. SETUPメッセージで提案されたATM MTU値を受け入れられる場合、着呼側は応答にAAL Parameters情報要素を含めるものとします。ForwardおよびBackwardsのMaximum CPCS-SDU Sizeフィールドが存在し、その値はSETUPメッセージの対応する値と等しいものとします。
  2. 提案されたものより小さいATM MTUサイズを希望する場合、着呼側は、元のSETUPメッセージに応答するCONNECTメッセージにおいて、AAL Parameters情報要素のMaximum CPCS-SDU Sizeの値を希望する値に設定するものとします。
  3. 発呼側のエンドポイントが、AAL Parameters情報要素を含まないCONNECTメッセージを受信したが、対応するSETUPメッセージにはAAL Parameters情報要素（forwardおよびbackwardのCPCS-SDU Sizeフィールドを含む）が含まれていた場合、そのエンドポイントは原因「AAL Parameters cannot be supported」で呼を解放するものとします。
  4. いずれかのエンドポイントが、原因「Information Element Non-existent or Not Implemented」または原因「"Access Information Discarded」で、AAL Parameters情報要素の識別子を示す診断フィールドを持つSTATUSメッセージを受信した場合、そのエンドポイントは原因「AAL Parameters cannot be supported.」で呼を解放するものとします。
  5. いずれかのエンドポイントが、ネゴシエーションしたMTUサイズを超えるCPCS-SDUを受信した場合、そのエンドポイントはIPのフラグメント化を使うか、原因「AAL Parameters cannot be supported」で呼を解放してもかまいません。この場合、エンドシステムかATMネットワークのいずれかの障害によってエラーが発生しています。このエラーは、人間が調査して介入できるように、ATMネットワーク管理によって記録されるべきです。

If the called endpoint incorrectly includes the Forward and Backward Maximum CPCS-SDU Size fields in the CONNECT messages (e.g. because the original SETUP message did not include these fields) or it sets these fields to an invalid value, then the calling party shall clear the call with cause "Invalid Information Element Contents".

着呼側のエンドポイントが、CONNECTメッセージに誤ってForwardおよびBackwardのMaximum CPCS-SDU Sizeフィールドを含めた場合（たとえば、元のSETUPメッセージにこれらのフィールドが含まれていなかったため）、またはこれらのフィールドを無効な値に設定した場合、発呼側は原因「Invalid Information Element Contents」で呼を解放するものとします。

Path MTU Discovery Required

経路MTU探索の必須化

The Path MTU Discovery mechanism is an Internet Standard [RFC-1191] and is an important mechanism for reducing IP fragmentation in the Internet. This mechanism is particularly important because new subnet ATM uses a default MTU sizes significantly different from older subnet technologies such as Ethernet and FDDI.

経路MTU探索（Path MTU Discovery）の仕組みはインターネット標準[RFC-1191]であり、インターネットにおけるIPのフラグメント化を減らすための重要な仕組みです。新しいサブネットであるATMは、イーサネットやFDDIなどの古いサブネット技術とは大きく異なるデフォルトMTUサイズを使うため、この仕組みは特に重要です。

In order to ensure good performance throughout the Internet and also to permit IP to take full advantage of the potentially larger IP datagram sizes supported by ATM, all routers implementations that comply or conform with this specification must also implement the IP Path MTU Discovery mechanism as defined in RFC-1191 and clarified by RFC-1435. Host implementations should implement the IP Path MTU Discovery mechanism as defined in RFC-1191.

インターネット全体で良好な性能を確保し、またATMがサポートする潜在的に大きなIPデータグラムサイズをIPが最大限に活用できるようにするために、この仕様に準拠するすべてのルーター実装は、RFC-1191で定義されRFC-1435で明確化されたIP経路MTU探索の仕組みも実装しなければなりません。ホスト実装は、RFC-1191で定義されたIP経路MTU探索の仕組みを実装すべきです。

Applicability Statement

適用性声明

The Multiprotocol Encapsulation over ATM AAL5 defined in RFC-1483 is not specific to any model of IP and ATM interaction. [RFC-1483] Similarly, this specification is general enough to apply to all models for use of IP over ATM AAL5. Use of this specification is recommended for all implementatons of IP over ATM AAL5 in order to increase interoperability and performance. This specification does not conflict with the Classical IP over ATM specification and may be used as a conforming extension to that specification. [RFC-1577] Applicability of this draft is not limited to the Classical IP over ATM model.

RFC-1483で定義されたATM AAL5上のマルチプロトコルカプセル化は、IPとATMの相互作用の特定のモデルに固有のものではありません。[RFC-1483]同様に、この仕様は、ATM AAL5上でIPを使うすべてのモデルに適用できるほど汎用的です。相互運用性と性能を高めるために、ATM AAL5上のIPのすべての実装でこの仕様を使うことを推奨します。この仕様はClassical IP over ATMの仕様と矛盾せず、その仕様に適合する拡張として使えます。[RFC-1577]このドラフトの適用範囲は、Classical IP over ATMのモデルに限定されません。
