Abstract

概要

This document describes an Extensible Provisioning Protocol (EPP) mapping for provisioning and management of organization objects stored in a shared central repository.

この文書は、共有の中央リポジトリーに格納される組織オブジェクトのプロビジョニングと管理のための、拡張可能なプロビジョニングプロトコル（EPP）のマッピングについて説明します。

1. Introduction

1. はじめに

There are many entities, such as registrars, resellers, DNS service operators, and privacy proxies, involved in the domain registration business. These kinds of entities have not been formally defined as having an object in Extensible Provisioning Protocol (EPP). This document provides a way to specify them as "organization" entities.

ドメイン登録ビジネスには、レジストラー、リセラー、DNSサービス運用者、プライバシープロキシーなど、多くのエンティティーが関与しています。これらの種類のエンティティーは、拡張可能なプロビジョニングプロトコル（EPP）において、オブジェクトを持つものとして正式に定義されていませんでした。この文書は、それらを「組織（organization）」エンティティーとして規定する方法を提供します。

This document describes an organization object mapping for version 1.0 of the EPP [RFC5730]. This mapping is specified using XML 1.0 as described in [W3C.REC-xml-20081126] and XML Schema notation as described in [W3C.REC-xmlschema-1-20041028] and [W3C.REC-xmlschema-2-20041028].

この文書は、EPP [RFC5730]のバージョン1.0のための組織オブジェクトマッピングについて説明します。このマッピングは、[W3C.REC-xml-20081126]で説明されているXML 1.0と、[W3C.REC-xmlschema-1-20041028]および[W3C.REC-xmlschema-2-20041028]で説明されているXMLスキーマ表記を使用して規定されます。

3. Object Attributes

3. オブジェクトの属性

An EPP organization object has attributes and associated values that can be viewed and modified by the sponsoring client or the server. This section describes each attribute type in detail. The formal syntax for the attribute values described here can be found in the "Formal Syntax" section of this document and in the appropriate normative references.

EPPの組織オブジェクトは、スポンサークライアントまたはサーバーが参照および変更できる属性と、それに関連付けられた値を持ちます。このセクションでは、各属性の種類について詳しく説明します。ここで説明する属性値の形式的な構文は、この文書の「形式的な構文」のセクションと、該当する引用規格に記載されています。

3.1. Organization Identifier

3.1. 組織識別子

All EPP organizations are identified by a server-unique identifier. Organization identifiers are character strings with a specified minimum length, a specified maximum length, and a specified format. Organization identifiers use the "clIDType" client identifier syntax described in [RFC5730]. The corresponding element is <org:id>.

すべてのEPPの組織は、サーバー内で一意な識別子によって識別されます。組織識別子は、規定された最小長、規定された最大長、および規定された形式を持つ文字列です。組織識別子は、[RFC5730]で説明されている「clIDType」クライアント識別子の構文を使用します。対応する要素は<org:id>です。

3.2. Organization Roles

3.2. 組織のロール

The organization roles are used to represent the relationship an organization could have. The corresponding element is <org:role>. An organization object MUST always have at least one associated role. Roles can be set only by the client that sponsors an organization object. A client can change the role of an organization object using the EPP <update> command (see Section 4.2.5).

組織のロールは、組織が持ちうる関係を表すために使用されます。対応する要素は<org:role>です。組織オブジェクトは、関連付けられたロールを常に少なくとも1つ持たなければなりません（MUST）。ロールは、組織オブジェクトのスポンサーとなっているクライアントだけが設定できます。クライアントは、EPP <update>コマンドを使用して組織オブジェクトのロールを変更できます（Section 4.2.5を参照）。

3.2.1. Role Type

3.2.1. ロールの種別

An organization role MUST have a type field, which may have any of the values listed in Section 7.3. The corresponding element is <org:type>. An organization could have multiple roles with different role types.

組織のロールは種別フィールドを持たなければなりません（MUST）。種別フィールドは、Section 7.3に列挙されている値のいずれかを取ることができます。対応する要素は<org:type>です。組織は、ロールの種別が異なる複数のロールを持つことができます。

3.2.2. Role Status

3.2.2. ロールのステータス

A role of an organization object MAY have its own statuses. The corresponding element is <org:status>. The possible values for the role status are defined in Section 3.5.

組織オブジェクトのロールは、独自のステータスを持ってもよいです（MAY）。対応する要素は<org:status>です。ロールのステータスが取りうる値は、Section 3.5で定義されています。

3.2.3. Role Identifier

3.2.3. ロール識別子

A role MAY have a third-party-assigned identifier such as the IANA ID for registrars. The corresponding element is <org:roleID>.

ロールは、レジストラーのIANA IDのような、第三者によって割り当てられた識別子を持ってもよいです（MAY）。対応する要素は<org:roleID>です。

Example of organization role identifier:

組織のロール識別子の例：

<org:role>
  <org:type>registrar</org:type>
  <org:status>ok</org:status>
  <org:status>linked</org:status>
  <org:roleID>1362</org:roleID>
</org:role>
<org:role>
  <org:type>registrar</org:type>
  <org:status>ok</org:status>
  <org:status>linked</org:status>
  <org:roleID>1362</org:roleID>
</org:role>

3.3. Contact and Client Identifiers

3.3. 連絡先識別子とクライアント識別子

All EPP contacts are identified by server-unique identifiers. Contact identifiers are character strings with a specified minimum length, a specified maximum length, and a specified format. Contact identifiers use the "clIDType" client identifier syntax described in [RFC5730].

すべてのEPPの連絡先は、サーバー内で一意な識別子によって識別されます。連絡先識別子は、規定された最小長、規定された最大長、および規定された形式を持つ文字列です。連絡先識別子は、[RFC5730]で説明されている「clIDType」クライアント識別子の構文を使用します。

3.4. Organization Status Values

3.4. 組織のステータス値

An organization object MUST always have at least one associated status value. Status values can be set only by the client that sponsors an organization object and by the server on which the object resides. A client can change the status of an organization object using the EPP <update> command. Each status value MAY be accompanied by a string of human-readable text that describes the rationale for the status applied to the object.

組織オブジェクトは、関連付けられたステータス値を常に少なくとも1つ持たなければなりません（MUST）。ステータス値は、組織オブジェクトのスポンサーとなっているクライアントと、そのオブジェクトが存在するサーバーだけが設定できます。クライアントは、EPP <update>コマンドを使用して組織オブジェクトのステータスを変更できます。各ステータス値には、そのオブジェクトにステータスが適用された理由を説明する、人間が読めるテキストの文字列を付けてもよいです（MAY）。

A client MUST NOT alter server status values set by the server. A server MAY alter or override status values set by a client, subject to local server policies. The status of an object MAY change as a result of either a client-initiated transform command or an action performed by a server operator.

クライアントは、サーバーが設定したサーバーステータス値を変更してはなりません（MUST NOT）。サーバーは、ローカルのサーバーポリシーに従って、クライアントが設定したステータス値を変更または上書きしてもよいです（MAY）。オブジェクトのステータスは、クライアントが開始した変換コマンド、またはサーバー運用者が実行したアクションの結果として変化してもよいです（MAY）。

Status values that can be added or removed by a client are prefixed with "client". Corresponding server status values that can be added or removed by a server are prefixed with "server". The "hold" and "terminated" status values are server managed when the organization has no parent identifier (Section 3.6) and otherwise MAY be client managed based on server policy. Other status values that do not begin with either "client" or "server" are server managed.

クライアントが追加または削除できるステータス値には、接頭辞「client」が付きます。サーバーが追加または削除できる、それに対応するサーバーステータス値には、接頭辞「server」が付きます。ステータス値「hold」と「terminated」は、組織が親識別子（Section 3.6）を持たない場合はサーバーが管理し、それ以外の場合はサーバーポリシーに基づいてクライアントが管理してもよいです（MAY）。「client」と「server」のどちらでも始まらないその他のステータス値は、サーバーが管理します。

Status Value Descriptions:

ステータス値の説明：

  • ok: This is the normal status value for an object that has no operations pending or active prohibitions. This value is set and removed by the server as other status values are added or removed.
  • hold: Organization transform commands and new links MUST be rejected.
  • terminated: The organization that has been terminated MUST NOT be linked. Organization transform commands and new links MUST be rejected.
  • linked: The organization object has at least one active association with another object. The "linked" status is not explicitly set by the client. Servers should provide services to determine existing object associations.
  • clientLinkProhibited, serverLinkProhibited: Requests to add new links to the organization MUST be rejected.
  • clientUpdateProhibited, serverUpdateProhibited: Requests to update the object (other than to remove this status) MUST be rejected.
  • clientDeleteProhibited, serverDeleteProhibited: Requests to delete the object MUST be rejected.
  • pendingCreate, pendingUpdate, pendingDelete: A transform command has been processed for the object, but the action has not been completed by the server. Server operators can delay action completion for a variety of reasons, such as to allow for human review or third-party action. A transform command that is processed, but whose requested action is pending, is noted with response code 1001.
  • ok：保留中の操作も有効な禁止もないオブジェクトの通常のステータス値です。この値は、他のステータス値が追加または削除されるのに応じて、サーバーによって設定および削除されます。
  • hold：組織の変換コマンドと新しいリンクを拒否しなければなりません（MUST）。
  • terminated：終了した組織をリンクしてはなりません（MUST NOT）。組織の変換コマンドと新しいリンクを拒否しなければなりません（MUST）。
  • linked：組織オブジェクトが、他のオブジェクトとの有効な関連付けを少なくとも1つ持っています。「linked」ステータスは、クライアントが明示的に設定するものではありません。サーバーは、既存のオブジェクトの関連付けを判断するためのサービスを提供すべきです。
  • clientLinkProhibited、serverLinkProhibited：組織に新しいリンクを追加するリクエストを拒否しなければなりません（MUST）。
  • clientUpdateProhibited、serverUpdateProhibited：オブジェクトを更新するリクエスト（このステータスを削除するものを除く）を拒否しなければなりません（MUST）。
  • clientDeleteProhibited、serverDeleteProhibited：オブジェクトを削除するリクエストを拒否しなければなりません（MUST）。
  • pendingCreate、pendingUpdate、pendingDelete：オブジェクトに対する変換コマンドは処理されましたが、そのアクションはサーバーによってまだ完了していません。サーバー運用者は、人間によるレビューや第三者によるアクションを可能にするためなど、さまざまな理由でアクションの完了を遅らせることができます。処理されたものの、要求されたアクションが保留中である変換コマンドは、レスポンスコード1001で示されます。

"pendingCreate", "ok", "hold", and "terminated" are mutually exclusive statuses. An organization MUST have exactly one of these statuses set.

「pendingCreate」、「ok」、「hold」、「terminated」は、互いに排他的なステータスです。組織には、これらのステータスのうちちょうど1つが設定されていなければなりません（MUST）。

"ok" status MAY only be combined with "linked" status.

「ok」ステータスは、「linked」ステータスとだけ組み合わせてもよいです（MAY）。

A client or server MAY combine "linked" with either "clientLinkProhibited" or "serverLinkProhibited" if new links must be prohibited.

新しいリンクを禁止する必要がある場合、クライアントまたはサーバーは、「linked」を「clientLinkProhibited」または「serverLinkProhibited」と組み合わせてもよいです（MAY）。

"pendingDelete" status MUST NOT be combined with either "clientDeleteProhibited" or "serverDeleteProhibited" status.

「pendingDelete」ステータスを、「clientDeleteProhibited」ステータスまたは「serverDeleteProhibited」ステータスと組み合わせてはなりません（MUST NOT）。

The "pendingCreate", "pendingDelete", and "pendingUpdate" status values MUST NOT be combined with each other.

ステータス値「pendingCreate」、「pendingDelete」、「pendingUpdate」を互いに組み合わせてはなりません（MUST NOT）。

If "clientUpdateProhibited" or "serverUpdateProhibited" is set, the client will not be able to update the object. For "clientUpdateProhibited", the client will first need to remove "clientUpdateProhibited" prior to attempting to update the object. The server can modify the object at any time.

「clientUpdateProhibited」または「serverUpdateProhibited」が設定されている場合、クライアントはオブジェクトを更新できません。「clientUpdateProhibited」の場合、クライアントは、オブジェクトの更新を試みる前に、まず「clientUpdateProhibited」を削除する必要があります。サーバーは、いつでもオブジェクトを変更できます。

3.5. Role Status Values

3.5. ロールのステータス値

A role SHOULD have at least one associated status value. Valid values include "ok", "linked", "clientLinkProhibited", and "serverLinkProhibited".

ロールは、関連付けられたステータス値を少なくとも1つ持つべきです（SHOULD）。有効な値には、「ok」、「linked」、「clientLinkProhibited」、「serverLinkProhibited」があります。

Status Value Descriptions:

ステータス値の説明：

  • ok: This is the normal status value for a role that has no operations pending or active prohibitions. This value is set and removed by the server as other status values are added or removed.
  • linked: The role of an organization object has at least one active association with another object. The "linked" status is not explicitly set by the client. Servers SHOULD provide services to determine existing object associations.
  • clientLinkProhibited, serverLinkProhibited: Requests to add new links to the role MUST be rejected.
  • ok：保留中の操作も有効な禁止もないロールの通常のステータス値です。この値は、他のステータス値が追加または削除されるのに応じて、サーバーによって設定および削除されます。
  • linked：組織オブジェクトのロールが、他のオブジェクトとの有効な関連付けを少なくとも1つ持っています。「linked」ステータスは、クライアントが明示的に設定するものではありません。サーバーは、既存のオブジェクトの関連付けを判断するためのサービスを提供すべきです（SHOULD）。
  • clientLinkProhibited、serverLinkProhibited：ロールに新しいリンクを追加するリクエストを拒否しなければなりません（MUST）。

3.6. Parent Identifier

3.6. 親識別子

Organizations can have more than one layer. The parent identifier, as defined with the <org:parentId> element, represents the parent organization identifier in a child organization.

組織は、複数の階層を持つことができます。<org:parentId>要素で定義される親識別子は、子組織における親組織の識別子を表します。

The case of reseller organizations provides an example. The parent identifier is not defined for the top-level reseller, namely the registrar of the registry. An N-tier reseller has a parent reseller and at least one child reseller. A reseller customer has a parent reseller and no child resellers.

リセラー組織の場合を例に挙げます。最上位のリセラー、すなわちレジストリーのレジストラーには、親識別子は定義されません。N階層目のリセラーは、親リセラーと少なくとも1つの子リセラーを持ちます。リセラーの顧客は、親リセラーを持ち、子リセラーを持ちません。

Loops MUST be prohibited. For example: if organization A has organization B as its parent identifier, organization B cannot have organization A as its parent identifier. The same is true for larger loops involving three or more organizations.

ループは禁止しなければなりません（MUST）。たとえば、組織Aが組織Bを親識別子として持つ場合、組織Bは組織Aを親識別子として持つことはできません。3つ以上の組織が関わる、より大きなループについても同様です。

3.7. URL

3.7. URL

The URL represents the organization web home page, as defined with the <org:url> element.

URLは、<org:url>要素で定義されるとおり、組織のWebホームページを表します。

3.8. Dates and Times

3.8. 日付と時刻

Date and time attribute values MUST be represented in Coordinated Universal Time (UTC) using the Gregorian calendar. The extended date-time form using uppercase "T" and "Z" characters defined in [W3C.REC-xmlschema-2-20041028] MUST be used to represent date-time values, as XML Schema does not support truncated date-time forms or lowercase "T" and "Z" characters.

日付と時刻の属性値は、グレゴリオ暦を使用した協定世界時（UTC）で表さなければなりません（MUST）。XMLスキーマは、切り詰められた日付時刻の形式や小文字の「T」と「Z」の文字をサポートしていないため、日付時刻の値を表すには、[W3C.REC-xmlschema-2-20041028]で定義されている、大文字の「T」と「Z」の文字を使用する拡張日付時刻形式を使用しなければなりません（MUST）。

4. EPP Command Mapping

4. EPPコマンドマッピング

A detailed description of the EPP syntax and semantics can be found in the EPP core protocol specification [RFC5730]. The command mappings described here are specifically for use in provisioning and managing organization information via EPP.

EPPの構文とセマンティクスの詳細な説明は、EPPのコアプロトコル仕様[RFC5730]にあります。ここで説明するコマンドマッピングは、特にEPPを介して組織の情報をプロビジョニングおよび管理するために使用するものです。

4.1. EPP Query Commands

4.1. EPPクエリーコマンド

EPP provides two commands to retrieve organization information: <check> to determine if an organization object can be provisioned within a repository and <info> to retrieve detailed information associated with an organization object. This document does not define a mapping for the EPP <transfer> command to retrieve organization-object transfer status information.

EPPは、組織の情報を取得するための2つのコマンドを提供しています。組織オブジェクトをリポジトリー内にプロビジョニングできるかどうかを判断する<check>と、組織オブジェクトに関連付けられた詳細な情報を取得する<info>です。この文書は、組織オブジェクトの移管ステータス情報を取得するためのEPP <transfer>コマンドのマッピングを定義しません。

4.1.1. EPP <check> Command

4.1.1. EPP <check>コマンド

The EPP <check> command is used to determine if an object can be provisioned within a repository. It provides a hint that allows a client to anticipate the success or failure of provisioning an object using the <create> command, as object-provisioning requirements are ultimately a matter of server policy.

EPP <check>コマンドは、オブジェクトをリポジトリー内にプロビジョニングできるかどうかを判断するために使用されます。オブジェクトのプロビジョニングの要件は最終的にはサーバーポリシーの問題であるため、このコマンドは、<create>コマンドを使用したオブジェクトのプロビジョニングが成功するか失敗するかをクライアントが予測できるようにするためのヒントを提供します。

In addition to the standard EPP command elements, the <check> command MUST contain an <org:check> element. This element or its ancestor element MUST identify the organization namespace "urn:ietf:params:xml:ns:epp:org-1.0". The <org:check> element contains the following child elements:

標準のEPPコマンド要素に加えて、<check>コマンドは<org:check>要素を含まなければなりません（MUST）。この要素またはその祖先要素は、組織名前空間「urn:ietf:params:xml:ns:epp:org-1.0」を識別しなければなりません（MUST）。<org:check>要素は、次の子要素を含みます。

  • One or more <org:id> elements that contain the server-unique identifier of the organization objects to be queried.
  • 照会する組織オブジェクトのサーバー内で一意な識別子を含む、1つ以上の<org:id>要素。

4.1.2. EPP <info> Command

4.1.2. EPP <info>コマンド

The EPP <info> command is used to retrieve information associated with an organization object. In addition to the standard EPP command elements, the <info> command MUST contain an <org:info> element. This element or its ancestor element MUST identify the organization namespace "urn:ietf:params:xml:ns:epp:org-1.0". The <org:info> element contains the following child element:

EPP <info>コマンドは、組織オブジェクトに関連付けられた情報を取得するために使用されます。標準のEPPコマンド要素に加えて、<info>コマンドは<org:info>要素を含まなければなりません（MUST）。この要素またはその祖先要素は、組織名前空間「urn:ietf:params:xml:ns:epp:org-1.0」を識別しなければなりません（MUST）。<org:info>要素は、次の子要素を含みます。

  • An <org:id> element that contains the server-unique identifier of the organization object to be queried.
  • 照会する組織オブジェクトのサーバー内で一意な識別子を含む<org:id>要素。

Example <info> command:

<info>コマンドの例：

When an <info> command has been processed successfully, the EPP <resData> element MUST contain a child <org:infData> element. This element or its ancestor element MUST identify the organization namespace "urn:ietf:params:xml:ns:epp:org-1.0". The <org:infData> element contains the following child elements:

<info>コマンドが正常に処理された場合、EPPの<resData>要素は子要素<org:infData>を含まなければなりません（MUST）。この要素またはその祖先要素は、組織名前空間「urn:ietf:params:xml:ns:epp:org-1.0」を識別しなければなりません（MUST）。<org:infData>要素は、次の子要素を含みます。

  • An <org:id> element that contains the server-unique identifier of the organization object, as defined in Section 3.1.
  • An <org:roid> element that contains the Repository Object Identifier assigned to the organization object when the object was created.

  • One or more <org:role> elements that contain the role type, role statuses, and optional role ID of the organization.

    • An <org:type> element that contains the type of the organization, as defined in Section 3.2.
    • One or more <org:status> elements that contain the role statuses. The values of the role status are defined in Section 3.5.
    • An OPTIONAL <org:roleID> element that contains a third-party-assigned identifier, such as IANA ID for registrars, as defined in Section 3.2.3.
  • One or more <org:status> elements that contain the operational status of the organization, as defined in Section 3.4.
  • An OPTIONAL <org:parentId> element that contains the identifier of the parent object, as defined in Section 3.6.

  • Zero to two <org:postalInfo> elements that contain postal-address information. Two elements are provided so that address information can be provided in both internationalized and localized forms; a "type" attribute is used to identify the two forms. If an internationalized form (type="int") is provided, element content MUST be represented in a subset of Unicode [UNICODE] in the range U+0020 - U+007E. If a localized form (type="loc") is provided, element content MAY be represented in unrestricted UTF-8. The <org:postalInfo> element contains the following child elements:

    • An <org:name> element that contains the name of the organization.

    • An OPTIONAL <org:addr> element that contains address information associated with the organization. An <org:addr> element contains the following child elements:

      • One, two, or three <org:street> elements that contain the organization's street address.
      • An <org:city> element that contains the organization's city.
      • An OPTIONAL <org:sp> element that contains the organization's state or province.
      • An OPTIONAL <org:pc> element that contains the organization's postal code.
      • An <org:cc> element that contains the alpha-2 organization's country code. The detailed format of this element is described in Section 2.4.3 of [RFC5733].
  • An OPTIONAL <org:voice> element that contains the organization's voice telephone number. The detailed format of this element is described in Section 2.5 of [RFC5733].
  • An OPTIONAL <org:fax> element that contains the organization's facsimile telephone number. The detailed format of this element is described in Section 2.5 of [RFC5733].
  • An OPTIONAL <org:email> element that contains the organization's email address. The detailed format of this element is described in [RFC5322].
  • An OPTIONAL <org:url> element that contains the URL to the website of the organization. The detailed format of this element is described in [RFC3986].
  • Zero or more <org:contact> elements that contain identifiers for the contact objects to be associated with the organization object. Contact object identifiers MUST be known to the server before the contact object can be associated with the organization object. The required "type" is used to represent contact types. The type values include "admin", "tech", "billing", "abuse", and "custom". The OPTIONAL "typeName" attribute is used to define the name of a "custom" type.
  • An OPTIONAL <org:clID> element that contains the organization identifier of the sponsoring client. There is no <org:clID> element if the organization is managed by the registry.
  • An <org:crID> element that contains the identifier of the client that created the organization object.
  • An <org:crDate> element that contains the date and time of organization object creation.
  • An <org:upID> element that contains the identifier of the client that last updated the organization object. This element MUST NOT be present if the organization has never been modified.
  • An <org:upDate> element that contains the date and time of the most recent organization object modification. This element MUST NOT be present if the organization object has never been modified.
  • Section 3.1で定義されている、組織オブジェクトのサーバー内で一意な識別子を含む<org:id>要素。
  • 組織オブジェクトの作成時にそのオブジェクトに割り当てられたリポジトリーオブジェクト識別子（Repository Object Identifier）を含む<org:roid>要素。

  • 組織のロールの種別、ロールのステータス、任意のロールIDを含む、1つ以上の<org:role>要素。

    • Section 3.2で定義されている、組織の種別を含む<org:type>要素。
    • ロールのステータスを含む、1つ以上の<org:status>要素。ロールのステータスの値は、Section 3.5で定義されています。
    • Section 3.2.3で定義されている、レジストラーのIANA IDのような、第三者によって割り当てられた識別子を含む選択可能な（OPTIONAL）<org:roleID>要素。
  • Section 3.4で定義されている、組織の運用上のステータスを含む、1つ以上の<org:status>要素。
  • Section 3.6で定義されている、親オブジェクトの識別子を含む選択可能な（OPTIONAL）<org:parentId>要素。

  • 郵便の住所情報を含む、0～2個の<org:postalInfo>要素。住所情報を国際化形式とローカライズ形式の両方で提供できるように、2つの要素が用意されています。2つの形式を識別するために「type」属性が使用されます。国際化形式（type="int"）が提供される場合、要素の内容は、Unicode [UNICODE]のうちU+0020～U+007Eの範囲のサブセットで表さなければなりません（MUST）。ローカライズ形式（type="loc"）が提供される場合、要素の内容は、制限のないUTF-8で表してもよいです（MAY）。<org:postalInfo>要素は、次の子要素を含みます。

    • 組織の名前を含む<org:name>要素。

    • 組織に関連付けられた住所情報を含む選択可能な（OPTIONAL）<org:addr>要素。<org:addr>要素は、次の子要素を含みます。

      • 組織の番地を含む、1つ、2つ、または3つの<org:street>要素。
      • 組織の市区町村を含む<org:city>要素。
      • 組織の州または県を含む選択可能な（OPTIONAL）<org:sp>要素。
      • 組織の郵便番号を含む選択可能な（OPTIONAL）<org:pc>要素。
      • 組織の2文字（alpha-2）の国コードを含む<org:cc>要素。この要素の詳細な形式は、[RFC5733]のSection 2.4.3で説明されています。
  • 組織の音声電話番号を含む選択可能な（OPTIONAL）<org:voice>要素。この要素の詳細な形式は、[RFC5733]のSection 2.5で説明されています。
  • 組織のファクシミリの電話番号を含む選択可能な（OPTIONAL）<org:fax>要素。この要素の詳細な形式は、[RFC5733]のSection 2.5で説明されています。
  • 組織の電子メールアドレスを含む選択可能な（OPTIONAL）<org:email>要素。この要素の詳細な形式は、[RFC5322]で説明されています。
  • 組織のWebサイトのURLを含む選択可能な（OPTIONAL）<org:url>要素。この要素の詳細な形式は、[RFC3986]で説明されています。
  • 組織オブジェクトに関連付ける連絡先オブジェクトの識別子を含む、0個以上の<org:contact>要素。連絡先オブジェクトを組織オブジェクトに関連付ける前に、連絡先オブジェクトの識別子がサーバーに既知でなければなりません（MUST）。必須の「type」は、連絡先の種別を表すために使用されます。種別の値には、「admin」、「tech」、「billing」、「abuse」、「custom」があります。選択可能な（OPTIONAL）「typeName」属性は、「custom」種別の名前を定義するために使用されます。
  • スポンサークライアントの組織識別子を含む選択可能な（OPTIONAL）<org:clID>要素。組織がレジストリーによって管理されている場合、<org:clID>要素はありません。
  • 組織オブジェクトを作成したクライアントの識別子を含む<org:crID>要素。

4.2. EPP Transform Commands

4.2. EPP変換コマンド

This document provides three commands to transform organization object information: <create> to create an instance of an organization object, <delete> to delete an instance of an organization object, and <update> to change information associated with an organization object. This document does not define a mapping for the EPP <transfer> and <renew> command.

この文書は、組織オブジェクトの情報を変換するための3つのコマンドを提供します。組織オブジェクトのインスタンスを作成する<create>、組織オブジェクトのインスタンスを削除する<delete>、組織オブジェクトに関連付けられた情報を変更する<update>です。この文書は、EPP <transfer>コマンドと<renew>コマンドのマッピングを定義しません。

Transform commands are typically processed and completed in real time. Server operators MAY receive and process transform commands but defer completing the requested action if human or third-party review is required before the requested action can be completed. In such situations, the server MUST return a 1001 response code to the client to note that the command has been received and processed but that the requested action is pending. The server MUST also manage the status of the object that is the subject of the command to reflect the initiation and completion of the requested action. Once the action has been completed, the client MUST be notified using a service message that the action has been completed and the status of the object has changed. Other notification methods MAY be used in addition to the required service message.

変換コマンドは、通常リアルタイムで処理され、完了します。要求されたアクションを完了する前に人間または第三者によるレビューが必要な場合、サーバー運用者は、変換コマンドを受信して処理したうえで、要求されたアクションの完了を延期してもよいです（MAY）。そのような場合、サーバーは、コマンドを受信して処理したものの、要求されたアクションが保留中であることを示すために、レスポンスコード1001をクライアントに返さなければなりません（MUST）。また、サーバーは、要求されたアクションの開始と完了を反映するように、コマンドの対象であるオブジェクトのステータスを管理しなければなりません（MUST）。アクションが完了したら、アクションが完了してオブジェクトのステータスが変化したことを、サービスメッセージを使用してクライアントに通知しなければなりません（MUST）。必須のサービスメッセージに加えて、他の通知方法を使用してもよいです（MAY）。

4.2.1. EPP <create> Command

4.2.1. EPP <create>コマンド

The EPP <create> command provides a transform operation that allows a client to create an organization object. In addition to the standard EPP command elements, the <create> command MUST contain an <org:create> element. This element or its ancestor element MUST identify the organization namespace "urn:ietf:params:xml:ns:epp:org-1.0". The <org:create> element contains the following child elements:

EPP <create>コマンドは、クライアントが組織オブジェクトを作成できるようにする変換操作を提供します。標準のEPPコマンド要素に加えて、<create>コマンドは<org:create>要素を含まなければなりません（MUST）。この要素またはその祖先要素は、組織名前空間「urn:ietf:params:xml:ns:epp:org-1.0」を識別しなければなりません（MUST）。<org:create>要素は、次の子要素を含みます。

  • An <org:id> element that contains the desired server-unique identifier for the organization to be created, as defined in Section 3.1.

  • One or more <org:role> elements that contain the role type, role statuses, and optional role ID of the organization.

    • An <org:type> element that contains the type of the organization, as defined in Section 3.2.
    • Zero or more <org:status> elements that contain the role statuses. The possible values of the role statuses are defined in Section 3.5.
    • An OPTIONAL <org:roleID> element that contains a third-party-assigned identifier, such as IANA ID for registrars, as defined in Section 3.2.3.
  • Zero or more <org:status> elements that contain the operational status of the organization, as defined in Section 3.4.
  • An OPTIONAL <org:parentId> element that contains the identifier of the parent object, as defined in Section 3.6.

  • Zero to two <org:postalInfo> elements that contain postal-address information. Two elements are provided so that address information can be provided in both internationalized and localized forms; a "type" attribute is used to identify the two forms. If an internationalized form (type="int") is provided, element content MUST be represented in a subset of Unicode [UNICODE] in the range U+0020 - U+007E. If a localized form (type="loc") is provided, element content MAY be represented in unrestricted UTF-8. The <org:postalInfo> element contains the following child elements:

    • An <org:name> element that contains the name of the organization.

    • An OPTIONAL <org:addr> element that contains address information associated with the organization. An <org:addr> element contains the following child elements:

      • One, two, or three <org:street> elements that contain the organization's street address.
      • An <org:city> element that contains the organization's city.
      • An OPTIONAL <org:sp> element that contains the organization's state or province.
      • An OPTIONAL <org:pc> element that contains the organization's postal code.
      • An <org:cc> element that contains the alpha-2 organization's country code. The detailed format of this element is described in Section 2.4.3 of [RFC5733].
  • An OPTIONAL <org:voice> element that contains the organization's voice telephone number. The detailed format of this element is described in Section 2.5 of [RFC5733].
  • An OPTIONAL <org:fax> element that contains the organization's facsimile telephone number. The detailed format of this element is described in Section 2.5 of [RFC5733].
  • An OPTIONAL <org:email> element that contains the organization's email address. The detailed format of this element is described of [RFC5322].
  • An OPTIONAL <org:url> element that contains the URL to the website of the organization. The detailed format of this element is described in [RFC3986].
  • Zero or more <org:contact> elements that contain identifiers for the contact objects associated with the organization object.
  • Section 3.1で定義されている、作成する組織に対して希望する、サーバー内で一意な識別子を含む<org:id>要素。

  • 組織のロールの種別、ロールのステータス、任意のロールIDを含む、1つ以上の<org:role>要素。

    • Section 3.2で定義されている、組織の種別を含む<org:type>要素。
    • ロールのステータスを含む、0個以上の<org:status>要素。ロールのステータスが取りうる値は、Section 3.5で定義されています。
    • Section 3.2.3で定義されている、レジストラーのIANA IDのような、第三者によって割り当てられた識別子を含む選択可能な（OPTIONAL）<org:roleID>要素。
  • Section 3.4で定義されている、組織の運用上のステータスを含む、0個以上の<org:status>要素。
  • Section 3.6で定義されている、親オブジェクトの識別子を含む選択可能な（OPTIONAL）<org:parentId>要素。

  • 郵便の住所情報を含む、0～2個の<org:postalInfo>要素。住所情報を国際化形式とローカライズ形式の両方で提供できるように、2つの要素が用意されています。2つの形式を識別するために「type」属性が使用されます。国際化形式（type="int"）が提供される場合、要素の内容は、Unicode [UNICODE]のうちU+0020～U+007Eの範囲のサブセットで表さなければなりません（MUST）。ローカライズ形式（type="loc"）が提供される場合、要素の内容は、制限のないUTF-8で表してもよいです（MAY）。<org:postalInfo>要素は、次の子要素を含みます。

    • 組織の名前を含む<org:name>要素。

    • 組織に関連付けられた住所情報を含む選択可能な（OPTIONAL）<org:addr>要素。<org:addr>要素は、次の子要素を含みます。

      • 組織の番地を含む、1つ、2つ、または3つの<org:street>要素。
      • 組織の市区町村を含む<org:city>要素。
      • 組織の州または県を含む選択可能な（OPTIONAL）<org:sp>要素。
      • 組織の郵便番号を含む選択可能な（OPTIONAL）<org:pc>要素。
      • 組織の2文字（alpha-2）の国コードを含む<org:cc>要素。この要素の詳細な形式は、[RFC5733]のSection 2.4.3で説明されています。
  • 組織の音声電話番号を含む選択可能な（OPTIONAL）<org:voice>要素。この要素の詳細な形式は、[RFC5733]のSection 2.5で説明されています。
  • 組織のファクシミリの電話番号を含む選択可能な（OPTIONAL）<org:fax>要素。この要素の詳細な形式は、[RFC5733]のSection 2.5で説明されています。
  • 組織の電子メールアドレスを含む選択可能な（OPTIONAL）<org:email>要素。この要素の詳細な形式は、[RFC5322]で説明されています。
  • 組織のWebサイトのURLを含む選択可能な（OPTIONAL）<org:url>要素。この要素の詳細な形式は、[RFC3986]で説明されています。
  • 組織オブジェクトに関連付けられる連絡先オブジェクトの識別子を含む、0個以上の<org:contact>要素。

4.2.5. EPP <update> Command

4.2.5. EPP <update>コマンド

The EPP <update> command provides a transform operation that allows a client to modify the attributes of an organization object. In addition to the standard EPP command elements, the <update> command MUST contain an <org:update> element. This element or its ancestor element MUST identify the organization namespace "urn:ietf:params:xml:ns:epp:org-1.0". The <org:update> element contains the following child elements:

EPP <update>コマンドは、クライアントが組織オブジェクトの属性を変更できるようにする変換操作を提供します。標準のEPPコマンド要素に加えて、<update>コマンドは<org:update>要素を含まなければなりません（MUST）。この要素またはその祖先要素は、組織名前空間「urn:ietf:params:xml:ns:epp:org-1.0」を識別しなければなりません（MUST）。<org:update>要素は、次の子要素を含みます。

  • An <org:id> element that contains the server-unique identifier of the organization object to be updated, as defined in Section 3.1.
  • An OPTIONAL <org:add> element that contains attribute values to be added to the object.
  • An OPTIONAL <org:rem> element that contains attribute values to be removed from the object.
  • An OPTIONAL <org:chg> element that contains attribute values to be changed.
  • Section 3.1で定義されている、更新する組織オブジェクトのサーバー内で一意な識別子を含む<org:id>要素。
  • オブジェクトに追加する属性値を含む選択可能な（OPTIONAL）<org:add>要素。
  • オブジェクトから削除する属性値を含む選択可能な（OPTIONAL）<org:rem>要素。
  • 変更する属性値を含む選択可能な（OPTIONAL）<org:chg>要素。

At least one <org:add>, <org:rem>, or <org:chg> element MUST be provided if the command is not being extended. All of these elements MAY be omitted if an <update> extension is present. The OPTIONAL <org:add> and <org:rem> elements contain the following child elements:

コマンドが拡張されていない場合は、<org:add>、<org:rem>、<org:chg>要素のうち少なくとも1つを提供しなければなりません（MUST）。<update>拡張が存在する場合は、これらの要素をすべて省略してもよいです（MAY）。選択可能な（OPTIONAL）<org:add>要素と<org:rem>要素は、次の子要素を含みます。

  • Zero or more <org:contact> elements that contain the identifiers for contact objects to be associated with or removed from the organization object. Contact object identifiers MUST be known to the server before the contact object can be associated with the organization object.

  • Zero or more <org:role> elements that contain the role type, role statuses, and optional role ID of the organization.

    • An <org:type> element that contains the role type of the organization, as defined in Section 3.2. The role type uniquely identifies the role to update.
    • Zero or more <org:status> elements that contain the role statuses. The values of the role status are defined in Section 3.5.
    • An OPTIONAL <org:roleID> element that contains a third-party-assigned identifier, such as IANA ID for registrars, as defined in Section 3.2.3.
  • Zero or more <org:status> elements that contain the operational status of the organization.
  • 組織オブジェクトに関連付ける、または組織オブジェクトから削除する連絡先オブジェクトの識別子を含む、0個以上の<org:contact>要素。連絡先オブジェクトを組織オブジェクトに関連付ける前に、連絡先オブジェクトの識別子がサーバーに既知でなければなりません（MUST）。

  • 組織のロールの種別、ロールのステータス、任意のロールIDを含む、0個以上の<org:role>要素。

    • Section 3.2で定義されている、組織のロールの種別を含む<org:type>要素。ロールの種別は、更新するロールを一意に識別します。
    • ロールのステータスを含む、0個以上の<org:status>要素。ロールのステータスの値は、Section 3.5で定義されています。
    • Section 3.2.3で定義されている、レジストラーのIANA IDのような、第三者によって割り当てられた識別子を含む選択可能な（OPTIONAL）<org:roleID>要素。
  • 組織の運用上のステータスを含む、0個以上の<org:status>要素。

An OPTIONAL <org:chg> element contains the following child elements, where at least one child element MUST be present:

選択可能な（OPTIONAL）<org:chg>要素は次の子要素を含みます。少なくとも1つの子要素が存在しなければなりません（MUST）。

  • An OPTIONAL <org:parentId> element that contains the identifier of the parent object.

  • Zero to two <org:postalInfo> elements that contain postal-address information. Two elements are provided so that address information can be provided in both internationalized and localized forms; a "type" attribute is used to identify the two forms. If an internationalized form (type="int") is provided, element content MUST be represented in a subset of Unicode [UNICODE] in the range U+0020 - U+007E. If a localized form (type="loc") is provided, element content MAY be represented in unrestricted UTF-8. The change of the postal info is defined as a replacement of that postal info element with the contents of the sub-elements included in the <update> command. An empty <org:postalInfo> element is supported to allow a type of postal info to be removed. The <org:postalInfo> element contains the following child elements:

    • An <org:name> element that contains the name of the organization.

    • An OPTIONAL <org:addr> element that contains address information associated with the organization. An <org:addr> element contains the following child elements:

      • One, two, or three <org:street> elements that contain the organization's street address.
      • An <org:city> element that contains the organization's city.
      • An OPTIONAL <org:sp> element that contains the organization's state or province.
      • An OPTIONAL <org:pc> element that contains the organization's postal code.
      • An <org:cc> element that contains the alpha-2 organization's country code. The detailed format of this element is described in Section 2.4.3 of [RFC5733].
  • An OPTIONAL <org:voice> element that contains the organization's voice telephone number. The detailed format of this element is described in Section 2.5 of [RFC5733].
  • An OPTIONAL <org:fax> element that contains the organization's facsimile telephone number. The detailed format of this element is described in Section 2.5 of [RFC5733].
  • An OPTIONAL <org:email> element that contains the organization's email address. The detailed format of this element is described in [RFC5322].
  • An OPTIONAL <org:url> element that contains the URL to the website of the organization. The detailed format of this element is described in [RFC3986].
  • 親オブジェクトの識別子を含む選択可能な（OPTIONAL）<org:parentId>要素。

  • 郵便の住所情報を含む、0～2個の<org:postalInfo>要素。住所情報を国際化形式とローカライズ形式の両方で提供できるように、2つの要素が用意されています。2つの形式を識別するために「type」属性が使用されます。国際化形式（type="int"）が提供される場合、要素の内容は、Unicode [UNICODE]のうちU+0020～U+007Eの範囲のサブセットで表さなければなりません（MUST）。ローカライズ形式（type="loc"）が提供される場合、要素の内容は、制限のないUTF-8で表してもよいです（MAY）。郵便の住所情報の変更は、その住所情報の要素を、<update>コマンドに含まれるサブ要素の内容で置き換えることとして定義されます。ある種類の住所情報を削除できるように、空の<org:postalInfo>要素がサポートされています。<org:postalInfo>要素は、次の子要素を含みます。

    • 組織の名前を含む<org:name>要素。

    • 組織に関連付けられた住所情報を含む選択可能な（OPTIONAL）<org:addr>要素。<org:addr>要素は、次の子要素を含みます。

      • 組織の番地を含む、1つ、2つ、または3つの<org:street>要素。
      • 組織の市区町村を含む<org:city>要素。
      • 組織の州または県を含む選択可能な（OPTIONAL）<org:sp>要素。
      • 組織の郵便番号を含む選択可能な（OPTIONAL）<org:pc>要素。
      • 組織の2文字（alpha-2）の国コードを含む<org:cc>要素。この要素の詳細な形式は、[RFC5733]のSection 2.4.3で説明されています。
  • 組織の音声電話番号を含む選択可能な（OPTIONAL）<org:voice>要素。この要素の詳細な形式は、[RFC5733]のSection 2.5で説明されています。
  • 組織のファクシミリの電話番号を含む選択可能な（OPTIONAL）<org:fax>要素。この要素の詳細な形式は、[RFC5733]のSection 2.5で説明されています。

4.3. Offline Review of Requested Actions

4.3. 要求されたアクションのオフラインレビュー

Commands are processed by a server in the order they are received from a client. Though an immediate response confirming receipt and processing of the command is produced by the server, a server operator MAY perform an offline review of requested transform commands before completing the requested action. In such situations, the response from the server MUST clearly note that the transform command has been received and processed, but the requested action is pending. The status in the response of the corresponding object MUST clearly reflect processing of the pending action. The server MUST notify the client when offline processing of the action has been completed.

コマンドは、クライアントから受信した順序でサーバーによって処理されます。コマンドの受信と処理を確認する即時のレスポンスはサーバーによって生成されますが、サーバー運用者は、要求されたアクションを完了する前に、要求された変換コマンドのオフラインレビューを実行してもよいです（MAY）。そのような場合、サーバーからのレスポンスは、変換コマンドを受信して処理したものの、要求されたアクションが保留中であることを明確に示さなければなりません（MUST）。レスポンス内の対応するオブジェクトのステータスは、保留中のアクションの処理を明確に反映しなければなりません（MUST）。サーバーは、アクションのオフライン処理が完了したときに、クライアントに通知しなければなりません（MUST）。

  • An <org:paTRID> element that contains the client transaction identifier and server transaction identifier returned with the original response to process the command. 6. Internationalization Considerations

6. 国際化に関する考慮事項

EPP is represented in XML, which provides native support for encoding information using the Unicode character set [UNICODE] and its more compact representations, including UTF-8. Conformant XML processors recognize both UTF-8 [RFC3629] and UTF-16 [RFC2781]. Though XML includes provisions to identify and use other character encodings through use of an "encoding" attribute in an <?xml?> declaration, use of UTF-8 is RECOMMENDED.

EPPはXMLで表現されます。XMLは、Unicode文字セット[UNICODE]と、UTF-8を含むそのよりコンパクトな表現を使用した情報の符号化をネイティブにサポートしています。準拠するXMLプロセッサーは、UTF-8 [RFC3629]とUTF-16 [RFC2781]の両方を認識します。XMLには、<?xml?>宣言の「encoding」属性を使用して他の文字エンコーディングを識別および使用するための規定が含まれていますが、UTF-8の使用が推奨されます（RECOMMENDED）。

As an extension of the EPP organization object mapping, the elements and element content described in this document MUST inherit the internationalization conventions used to represent higher-layer domain and core protocol structures present in an XML instance that includes this extension.

EPPの組織オブジェクトマッピングの拡張として、この文書で説明する要素と要素の内容は、この拡張を含むXMLインスタンスに存在する、上位層のドメインとコアプロトコルの構造を表すために使用される国際化の規則を継承しなければなりません（MUST）。

8. Security Considerations

8. セキュリティーに関する考慮事項

The organization object may have personally identifiable information, such as <org:contact>. This information is not a required element in this document that can be provided on a voluntary basis. If it is provided, both client and server MUST ensure that authorization information is stored and exchanged with high-grade encryption mechanisms to provide privacy services, which are specified in [RFC5733]. The security considerations described in [RFC5730] or those caused by the protocol layers used by EPP will apply to this specification as well.

組織オブジェクトは、<org:contact>のような個人を識別できる情報を持つ場合があります。この情報は、この文書では必須の要素ではなく、任意で提供できるものです。この情報が提供される場合、クライアントとサーバーの両方は、[RFC5733]で規定されているプライバシーサービスを提供するために、認可情報が高度な暗号化メカニズムを用いて格納および交換されることを保証しなければなりません（MUST）。[RFC5730]で説明されているセキュリティーに関する考慮事項や、EPPが使用するプロトコル層によって生じるセキュリティーに関する考慮事項は、この仕様にも適用されます。
