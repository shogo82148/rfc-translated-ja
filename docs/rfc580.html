RFC 580

note to protocol designers and implementers

RFC 580

プロトコルの設計者と実装者への注意

Abstract

概要

Hereafter proposed protocols shall be submitted in the form of on-line documents, preferably as nls files at the Network Information Center. This will greatly facilitate the review process and enable editorial and substantive changes to proceed quickly. This also will permit timely updating of protocol documents as may be neccessitated by future decisions. On-line documents are also easily distributed to the network community. If you find great difficulty in complying with this request please contact me.

今後、提案するプロトコルは、オンライン文書の形で、できればNetwork Information Centerのnlsファイルとして提出してください。そうすれば、レビューの過程がとても楽になり、編集上の変更や内容の変更を素早く進められます。また、今後の決定に応じて必要になるプロトコル文書の更新も、適時に行えるようになります。オンライン文書は、ネットワークコミュニティーに配布するのも簡単です。この依頼に従うのがとても難しい場合は、私に連絡してください。

It should be noted by all Telnet protocol readers and especially implementers that all the existing Telnet Options that involve subnegotiation are modified [see RFC 562] to terminate the subnegotiation strings with IAC SE. The value of SE is 240. Also note that within subnegotiations the occurance of a byte with the value 255 [IAC] requires doubling that byte on transmission.

Telnetプロトコルの読者、特に実装者は全員、サブネゴシエーションを伴う既存のTelnetオプションがすべて修正され[RFC 562を参照]、サブネゴシエーションの文字列をIAC SEで終えるようになったことに注意してください。SEの値は240です。また、サブネゴシエーションの中に値255[IAC]のバイトが現れる場合は、送信時にそのバイトを2回繰り返す必要があることにも注意してください。
