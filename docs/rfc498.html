RFC 498

On mail service to CCN

RFC 498

CCNのメールサービスについて

Abstract

概要

Most of the recent documents on mail protocols have discussed the facilities desired at "post-office" hosts, i.e. those which provide store-and-forward services. CCN has no plans to provide post-office services; we expect to receive mail only for the staff of CCN. Our greatest concern is to get messages reliably to and from our administrative and user support people who don't habitually use on-line terminals, so we are printing out all mail and distributing it by courier/secretary.

最近のメールプロトコルに関する文書の多くは、「郵便局（post-office）」ホスト、つまり蓄積転送サービスを提供するホストに求められる機能を論じています。CCNには郵便局サービスを提供する予定はなく、CCNのスタッフ宛てのメールだけを受け取るつもりです。私たちが最も気にかけているのは、オンライン端末をふだん使わない管理部門やユーザーサポートの人々との間で、メッセージを確実にやり取りすることです。そのため、届いたメールはすべて印刷し、連絡係や秘書を通じて配布しています。

Let me say a friendly word for SNDMSG. This Tenex command, which uses the FTP MAIL command to deliver messages, is very simple but extremely useful--probably because it is so simple. Furthermore, it is one of the well-kept secrets of the Network that SNDMSG can be used to send messages to any host which supports the MAIL command (without requiring logon to FTP). Thus, to send a message to anyone at CCN, the recommended procedure is to do SNDMSG to "name@CCN". This connects to CCN's FTP and sends a "MAIL name" command followed by the message. We now accept any "name" and print an immediate upper-case copy which is distributed to the recipient's office. So, if you SNDMSG to "BRADEN@CCN", your message will end up on my desk, usually within a few hours. Other useful SNDMSG destination at CCN are:

SNDMSGについてひとこと褒めさせてください。このTenexのコマンドは、FTPのMAILコマンドを使ってメッセージを配送するもので、とても単純ですが非常に便利です。おそらく単純だからこそ便利なのでしょう。さらに、SNDMSGを使えば、MAILコマンドをサポートしている任意のホストに（FTPへのログオンを必要とせずに）メッセージを送れることは、ネットワークのよく守られた秘密の1つです。したがって、CCNの誰かにメッセージを送るには、「name@CCN」に対してSNDMSGを実行するのが推奨の手順です。これはCCNのFTPに接続し、「MAIL name」コマンドに続けてメッセージを送信します。現在、私たちは任意の「name」を受け付け、すぐに大文字で写しを印刷して受取人の事務所に配布しています。ですから、「BRADEN@CCN」にSNDMSGで送れば、メッセージはたいてい数時間以内に私の机に届きます。CCNで役に立つその他のSNDMSGの宛先は次のとおりです。

WBK@CCN or KEHL@CCN
(the Director)
RIB@CCN or BELL@CCN
(Supervisor Of User Relations)
BBN@CCN or NOBLE@CCN
(Barbara Noble, User Consultant)
WBK@CCNまたはKEHL@CCN
（所長）
RIB@CCNまたはBELL@CCN
（ユーザー対応の責任者）
BBN@CCNまたはNOBLE@CCN
（ユーザーコンサルタントのBarbara Noble）

This fine service is brought to you by your friendly neighborhood Tenex.

このすばらしいサービスは、あなたの近所の親しみやすいTenexがお届けしています。

On the other hand, the Tenex READMAIL command is a little too simple. After giving you a message, it should ask you whether you want to delete, keep, forward, and/or repeat the message.

一方、TenexのREADMAILコマンドは少し単純すぎます。メッセージを表示したあとで、そのメッセージを削除するか、残しておくか、転送するか、もう一度表示するかを尋ねるべきです。

Dave Crocker of NMC has suggested an extension to the MAIL and MLFL (Mail File) commands in CCN's FTP to allow CCN to serve as a mail delivery station for NMC as well as CCN. This extension is intended to be a trivial subset of the full-blown mail protocol which is currently being developed by Jim White et al. It is a simple means to allow CCN's high-speed printers to be used conveniently for receiving and disseminating Network documentation as well as messages. It is based upon extensions of the pathname/user name fields in the MLFL/MAIL commands, respectively. The proposed syntax is as follows:

NMCのDave Crockerは、CCNがCCNだけでなくNMCのためのメール配送拠点としても機能できるよう、CCNのFTPのMAILコマンドとMLFL（Mail File）コマンドの拡張を提案しました。この拡張は、Jim Whiteらが現在開発している本格的なメールプロトコルの、ごく小さなサブセットとなることを意図しています。これは、CCNの高速プリンターを、メッセージだけでなくネットワークの文書の受信と配布にも手軽に使えるようにするための簡単な手段です。これは、MLFLコマンドのパス名フィールドとMAILコマンドのユーザー名フィールドをそれぞれ拡張したものに基づいています。提案する構文は次のとおりです。

                        __                   __
                       |                       |
                       | ;D[DOCUMENT]          |
                       | ;M[MESSAGE]           |
            <userid>   | ;C[COPIES]= <integer> |
                       | ;BIN= <integer>       |
                       |__                   __|

                        __                   __
                       |                       |
                       | ;D[DOCUMENT]          |
                       | ;M[MESSAGE]           |
            <userid>   | ;C[COPIES]= <integer> |
                       | ;BIN= <integer>       |
                       |__                   __|

The semantics would be:

意味は次のとおりです。

(1) <userid>
will normally be a valid TSO userid; this will be used to determine a charge number to account for the printing. If <userid> is not recognized, the rest of the parameters will be ignored, but the mail will still be accepted. The result will be to print one copy immediately in upper case and send it to Bin 9906, charging it to an overhead account.
(2) MESSAGE
means print a copy immediately using the normal upper-case-only train. This is the default.
(3) DOCUMENT
means enqueue the text for overnight printing with an upper/lower case print train. A message indicating receipt (and perhaps the first block) will also be printed immediately in upper case and distributed.
(4) COPIES
makes multiple copies. [This facility will not be available immediately].
(5) BIN
specifies CCN bin to receive output. Default will be 9906 (ARPA mail bin).
(1) <userid>
通常は有効なTSOのユーザーIDです。これは、印刷の費用を計上する課金番号を決めるために使われます。<userid>を認識できない場合、残りのパラメーターは無視されますが、メールは受け付けられます。その結果、すぐに大文字で1部印刷してビン9906に送り、費用は間接費の勘定に計上します。
(2) MESSAGE
通常の大文字専用の印字トレイン（print train）を使って、すぐに1部印刷することを意味します。これがデフォルトです。
(3) DOCUMENT
大文字と小文字の印字トレインを使って夜間に印刷するよう、テキストをキューに入れることを意味します。受信したことを示すメッセージ（と、場合によっては最初のブロック）も、すぐに大文字で印刷して配布します。
(4) COPIES
複数部を作成します。[この機能はすぐには利用できません]。
(5) BIN
出力を受け取るCCNのビンを指定します。デフォルトは9906（ARPAのメール用ビン）です。

Each incoming message will be time-and-date-stamped. The time/date will appear on the first page of the message (on a separate page in the case of upper/lowercase), in the 256 acknowledgment message from FTP, and on our system log file. This time/date stamp may be useful for users to keep tabs on their documents, and to allow us to track down missing messages. The semicolon and equal sign delimiters of this syntax are acceptable in the "user" parameter to SNDMSG.

届いたメッセージにはそれぞれ日時のスタンプが付きます。日時は、メッセージの最初のページ（大文字と小文字の場合は別のページ）、FTPからの256の確認応答メッセージ、および私たちのシステムのログファイルに記録されます。この日時のスタンプは、ユーザーが自分の文書の状況を把握したり、私たちが紛失したメッセージを追跡したりするのに役立つでしょう。この構文の区切り文字であるセミコロンと等号は、SNDMSGの「user」パラメーターで使えます。

This extended MAIL syntax will be implemented by June 1.

この拡張したMAILの構文は、6月1日までに実装する予定です。
