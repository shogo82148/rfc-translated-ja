RFC 406

Scheduled IMP Software Releases

RFC 406

IMPソフトウェアの定期リリース

Abstract

概要

This note is a reminder that the procedures suggested in RFC # 381 for scheduling IMP software maintenance have now been in effect for a period of about two months. Two points apparently require re-emphasis:

このノートは、IMPソフトウェアの保守をスケジュールするためにRFC # 381で提案した手順が、施行されてから約2か月たったことをお知らせするものです。次の2点は、改めて強調しておく必要があるようです。

  1. We reserve the hour from 7 to 8 a.m. eastern time every Tuesday as the time when IMPs can be reloaded. We will probably not use this period every Tuesday, but we do reserve this period every Tuesday. The software maintenance time period is in addition to the hardware preventive maintenance scheduled at each site.
  2. We now send an IMP - Going - Down message to all the Hosts at the site which contains information on the time that the IMP is going down, the expected duration, and the reason. We try to send out this message an hour before software releases, and five to ten minutes before scheduled preventive maintenance. Further, we will also notify the Hosts at a site, whenever possible, when it is necessary to stop the IMP on an unscheduled basis. Finally, 30 seconds before the IMP goes down, a second IMP - Going - Down message will be sent to the Hosts informing them that the IMP is going down immediately. The format of the IMP - Going - Down message is as follows:
  1. 私たちは、毎週火曜日の東部時間午前7時から8時までの1時間を、IMPを再ロードできる時間として確保しています。毎週火曜日にこの時間帯を使うことはおそらくありませんが、この時間帯は毎週火曜日に確保しておきます。このソフトウェア保守の時間帯は、各サイトで予定されているハードウェアの予防保守とは別のものです。
  2. 現在、私たちは、IMPが停止する時刻、停止の予想時間、および理由を含むIMP - Going - Downメッセージを、そのサイトのすべてのホストに送っています。このメッセージは、ソフトウェアリリースの場合は1時間前に、予定された予防保守の場合は5〜10分前に送るようにしています。さらに、予定外にIMPを止める必要があるときも、可能な限りそのサイトのホストに通知します。最後に、IMPが停止する30秒前に、IMPがただちに停止することをホストに知らせる2回目のIMP - Going - Downメッセージが送られます。IMP - Going - Downメッセージの形式は次のとおりです。
bits 1 - 4  -  all zero

bits 5 - 8  -  0010

bits 9 - 16 -  all zero

bits 17 - 32 -  coded as follows:


          All bits zero - going down in 30 seconds



          Bits 17, 18 = 01 - scheduled hardware PM

          Bits 17, 18 = 10 - scheduled software reload

          Bits 17, 18 = 11 - emergency reload on restart



          Bits 19 - 22 - how soon the IMP is going down,
                         in 5 minute units.



          Bits 23 - 32 - how long the IMP will be down, in
                         5 minute units.

bits 1 - 4  -  all zero

bits 5 - 8  -  0010

bits 9 - 16 -  all zero

bits 17 - 32 -  coded as follows:


          All bits zero - going down in 30 seconds



          Bits 17, 18 = 01 - scheduled hardware PM

          Bits 17, 18 = 10 - scheduled software reload

          Bits 17, 18 = 11 - emergency reload on restart



          Bits 19 - 22 - how soon the IMP is going down,
                         in 5 minute units.



          Bits 23 - 32 - how long the IMP will be down, in
                         5 minute units.
