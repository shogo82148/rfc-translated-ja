RFC 1997

BGP Communities Attribute

RFC 1997

BGPコミュニティー属性

Abstract

概要

Border Gateway Protocol [1] is an inter-autonomous system routing protocol designed for TCP/IP internets.

ボーダーゲートウェイプロトコル（BGP: Border Gateway Protocol）[1]は、TCP/IPインターネットのために設計された自律システム間ルーティングプロトコルです。

This document describes an extension to BGP which may be used to pass additional information to both neighboring and remote BGP peers.

この文書は、隣接するBGPピアと遠隔のBGPピアの両方に追加情報を渡すために使用できる、BGPの拡張について説明します。

The intention of the proposed technique is to aid in policy administration and reduce the management complexity of maintaining the Internet.

提案する手法の目的は、ポリシー管理を支援し、インターネットを維持するための管理の複雑さを軽減することです。

Status of This Memo

このメモのステータス

This document specifies an Internet standards track protocol for the Internet community, and requests discussion and suggestions for improvements. Please refer to the current edition of the "Internet Official Protocol Standards" (STD 1) for the standardization state and status of this protocol. Distribution of this memo is unlimited.

この文書は、インターネットコミュニティーのためのインターネット標準化過程（Internet Standards Track）のプロトコルを規定し、改善のための議論と提案を求めるものです。このプロトコルの標準化の状態とステータスについては、「Internet Official Protocol Standards」（STD 1）の最新版を参照してください。このメモの配布は無制限です。

Introduction

はじめに

BGP supports transit policies via controlled distribution of routing information. Mechanisms for this are described in [1] and have been successfully used by transit service providers. However, control over the distribution of routing information is presently based on either IP address prefixes or on the value of the AS_PATH attribute (or part of it).

BGPは、ルーティング情報の配布を制御することによって、トランジットポリシーをサポートしています。そのための仕組みは[1]で説明されており、トランジットサービスプロバイダーによってうまく使用されてきました。しかし、ルーティング情報の配布の制御は、現在のところ、IPアドレスプレフィックスか、AS_PATH属性の値（またはその一部）のどちらかに基づいています。

To facilitate and simplify the control of routing information this document suggests a grouping of destinations so that the routing decision can also be based on the identity of a group. Such a scheme is expected to significantly simplify a BGP speaker's configuration that controls distribution of routing information.

ルーティング情報の制御を容易かつ単純にするために、この文書は、ルーティングの決定をグループの識別情報にも基づいて行えるように、宛先をグループ化することを提案します。このような方式によって、ルーティング情報の配布を制御するBGPスピーカーの設定が大幅に単純になると期待されます。

Terms and Definitions

用語と定義

Community

A community is a group of destinations which share some common property.

Each autonomous system administrator may define which communities a destination belongs to. By default, all destinations belong to the general Internet community.

コミュニティー（Community）

コミュニティーとは、何らかの共通の性質を共有する宛先のグループです。

各自律システムの管理者は、宛先がどのコミュニティーに属するかを定義できます。デフォルトでは、すべての宛先は一般的なインターネットコミュニティーに属します。

Examples

例

A property such as "NSFNET sponsored/AUP" could be added to all AUP compliant destinations advertised into the NSFNET. NSFNET operators could define a policy that would advertise all routes, tagged or not, to directly connected AUP compliant customers and only tagged routes to commercial or external sites. This would insure that at least one side of a given connection is AUP compliant as a way of enforcing NSF transit policy guidelines.

NSFNETに広告される、AUPに準拠したすべての宛先に、「NSFNET sponsored/AUP」のような性質を付加できます。NSFNETの運用者は、直接接続されているAUP準拠の顧客にはタグの有無にかかわらずすべての経路を広告し、商用サイトや外部サイトにはタグ付きの経路だけを広告するポリシーを定義できます。これにより、NSFのトランジットポリシーのガイドラインを施行する手段として、ある接続の少なくとも一方の側がAUPに準拠していることを保証できます。

In this example, we have just eliminated the primary motivation for a complex policy routing database that is used to generate huge prefix and AS path based filter rules. We have also eliminated the delays caused by the out-of-band maintenance of this database (mailing in NACRs, weekly configuration runs, etc.)

この例では、巨大なプレフィックスベースおよびASパスベースのフィルター規則を生成するために使用される、複雑なポリシールーティングデータベースの主な動機を取り除いたことになります。また、このデータベースの帯域外での保守（NACRの郵送、毎週の設定の実行など）によって生じる遅延も取り除いたことになります。

A second example comes from experience with aggregation. It is often useful to advertise both an aggregate prefix and the component more-specific prefixes that were used to form the aggregate to optimize "next hop" routing. These component prefixes are only useful to the neighboring BGP peer or perhaps the autonomous system of the neighboring BGP peer, so it is desirable to filter this information. By specifying a community value that the neighboring peer or peers will match and filter on, these more specific routes may be advertised with the assurance that they will not propagate beyond their desired scope.

2つ目の例は、集約の経験から来ています。「ネクストホップ」ルーティングを最適化するために、集約プレフィックスと、その集約を形成するために使われた構成要素であるより具体的なプレフィックスの両方を広告すると便利なことがよくあります。これらの構成要素のプレフィックスは、隣接するBGPピア、あるいは隣接するBGPピアの自律システムにとってのみ有用なので、この情報はフィルタリングすることが望ましいです。隣接するピアが照合してフィルタリングするコミュニティー値を指定することで、これらのより具体的な経路を、意図した範囲を超えて伝播しないという保証のもとで広告できます。

COMMUNITIES attribute

COMMUNITIES属性

This document creates the COMMUNITIES path attribute is an optional transitive attribute of variable length. The attribute consists of a set of four octet values, each of which specify a community. All routes with this attribute belong to the communities listed in the attribute.

この文書は、可変長の任意推移的（optional transitive）属性であるCOMMUNITIESパス属性を作成します。この属性は4オクテットの値の集合からなり、それぞれの値が1つのコミュニティーを指定します。この属性を持つすべての経路は、属性内に列挙されたコミュニティーに属します。

The COMMUNITIES attribute has Type Code 8.

COMMUNITIES属性のタイプコードは8です。

Communities are treated as 32 bit values, however for administrative assignment, the following presumptions may be made:

コミュニティーは32ビットの値として扱われますが、管理上の割り当てのために、次のような前提を置くことができます。

The community attribute values ranging from 0x0000000 through 0x0000FFFF and 0xFFFF0000 through 0xFFFFFFFF are hereby reserved.

0x0000000から0x0000FFFFまで、および0xFFFF0000から0xFFFFFFFFまでの範囲のコミュニティー属性値は、ここに予約されます。

The rest of the community attribute values shall be encoded using an autonomous system number in the first two octets. The semantics of the final two octets may be defined by the autonomous system (e.g. AS 690 may define research, educational and commercial community values that may be used for policy routing as defined by the operators of that AS using community attribute values 0x02B20000 through 0x02B2FFFF).

残りのコミュニティー属性値は、最初の2オクテットに自律システム番号を使用してエンコードすることになります。最後の2オクテットの意味は、その自律システムが定義できます（たとえば、AS 690は、そのASの運用者が定義するポリシールーティングに使用できる研究用、教育用、商用のコミュニティー値を、コミュニティー属性値0x02B20000から0x02B2FFFFを使用して定義できます）。

Well-known Communities

ウェルノウンコミュニティー

The following communities have global significance and their operations shall be implemented in any community-attribute-aware BGP speaker.

次のコミュニティーはグローバルな意味を持ち、その動作は、コミュニティー属性を認識するすべてのBGPスピーカーで実装されることになります。

NO_EXPORT (0xFFFFFF01)
All routes received carrying a communities attribute containing this value MUST NOT be advertised outside a BGP confederation boundary (a stand-alone autonomous system that is not part of a confederation should be considered a confederation itself).
NO_ADVERTISE (0xFFFFFF02)
All routes received carrying a communities attribute containing this value MUST NOT be advertised to other BGP peers.
NO_EXPORT_SUBCONFED (0xFFFFFF03)
All routes received carrying a communities attribute containing this value MUST NOT be advertised to external BGP peers (this includes peers in other members autonomous systems inside a BGP confederation).
NO_EXPORT (0xFFFFFF01)
この値を含むコミュニティー属性を持って受信されたすべての経路は、BGPコンフェデレーションの境界の外に広告してはなりません（MUST NOT）（コンフェデレーションの一部ではない独立した自律システムは、それ自体を1つのコンフェデレーションとみなすべきです）。
NO_ADVERTISE (0xFFFFFF02)
この値を含むコミュニティー属性を持って受信されたすべての経路は、他のBGPピアに広告してはなりません（MUST NOT）。
NO_EXPORT_SUBCONFED (0xFFFFFF03)
この値を含むコミュニティー属性を持って受信されたすべての経路は、外部BGPピアに広告してはなりません（MUST NOT）（これには、BGPコンフェデレーション内の他のメンバー自律システムにあるピアも含まれます）。

Operation

動作

A BGP speaker may use this attribute to control which routing information it accepts, prefers or distributes to other neighbors.

BGPスピーカーは、どのルーティング情報を受け入れるか、優先するか、他の隣接ノードに配布するかを制御するために、この属性を使用できます。

A BGP speaker receiving a route that does not have the COMMUNITIES path attribute may append this attribute to the route when propagating it to its peers.

COMMUNITIESパス属性を持たない経路を受信したBGPスピーカーは、その経路をピアに伝播する際に、この属性を経路に付加できます。

A BGP speaker receiving a route with the COMMUNITIES path attribute may modify this attribute according to the local policy.

COMMUNITIESパス属性を持つ経路を受信したBGPスピーカーは、ローカルポリシーに従ってこの属性を変更できます。

Aggregation

集約

If a range of routes is to be aggregated and the resultant aggregates attribute section does not carry the ATOMIC_AGGREGATE attribute, then the resulting aggregate should have a COMMUNITIES path attribute which contains all communities from all of the aggregated routes.

ある範囲の経路を集約する際に、その結果得られる集約の属性部分にATOMIC_AGGREGATE属性が含まれない場合、結果の集約経路は、集約されたすべての経路のすべてのコミュニティーを含むCOMMUNITIESパス属性を持つべきです。

Applicability

適用範囲

The COMMUNITIES path attribute may be used with BGP version 2 and all subsequent versions of BGP unless specifically noted otherwise.

COMMUNITIESパス属性は、特に断りがない限り、BGPバージョン2およびそれ以降のすべてのバージョンのBGPで使用できます。

セキュリティーに関する考慮事項

このメモではセキュリティーの問題については議論しません。
