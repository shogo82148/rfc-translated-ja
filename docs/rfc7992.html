RFC 7992

HTML Format for RFCs

RFC 7992

RFCのためのHTMLフォーマット

Abstract

概要

In order to meet the evolving needs of the Internet community, the canonical format for RFCs is changing from a plain-text, ASCII-only format to an XML format that will, in turn, be rendered into several publication formats. This document defines the HTML format that will be rendered for an RFC or Internet-Draft.

インターネットコミュニティーの変化するニーズを満たすため、RFCの正規フォーマットは、プレーンテキストでASCIIのみのフォーマットから、XMLフォーマットへと変わりつつあります。このXMLフォーマットは、さらにいくつかの公開フォーマットへとレンダリングされます。この文書は、RFCまたはインターネットドラフトのためにレンダリングされるHTMLフォーマットを定義します。

1. Introduction

1. はじめに

As described in [RFC7990], the RFC Series is changing. One of those changes includes the RFC Editor publishing a non-canonical HTML version of RFCs.

[RFC7990]で説明されているように、RFCシリーズは変わりつつあります。その変化の1つに、RFCエディターがRFCの非正規のHTML版を公開することが含まれます。

This document describes the HTML format that will be used as one of the publication formats for the RFC Series. It defines a strict subset of HTML appropriate for RFC Series documents. The visual layout of the document will be defined through a cascading style sheet (CSS) [W3C.REC-CSS2-20110607]. The CSS will be included in the HTML file but will be described in [RFC7993].

この文書は、RFCシリーズの公開フォーマットの1つとして使われるHTMLフォーマットについて説明します。この文書は、RFCシリーズの文書に適したHTMLの厳密なサブセットを定義します。文書の視覚的なレイアウトは、カスケーディングスタイルシート（CSS）[W3C.REC-CSS2-20110607]によって定義されます。CSSはHTMLファイルに含まれますが、その内容は[RFC7993]で説明します。

The details (particularly any vocabularies) described in this document are expected to change based on experience gained in implementing the new publication toolsets. Revised documents will be published capturing those changes as the toolsets are completed. Other implementers must not expect those changes to remain backwards compatible with the details described in this document.

この文書で説明する詳細（特に語彙）は、新しい公開ツールセットを実装する中で得られる経験に基づいて変更されることが見込まれています。ツールセットが完成するにつれ、それらの変更を取り込んだ改訂版の文書が公開される予定です。他の実装者は、それらの変更がこの文書で説明する詳細との後方互換性を保つと期待してはいけません。

2. Requirements for the HTML Format

2. HTMLフォーマットの要件

This section lists the design requirements used to create the HTML format described in this document. These requirements build on those found in [RFC6949]. Many of these requirements are naturally fulfilled by using the output of the preparation tool [RFC7998].

このセクションでは、この文書で説明するHTMLフォーマットを作成するために用いた設計上の要件を列挙します。これらの要件は、[RFC6949]にある要件に基づいています。これらの要件の多くは、準備ツール（preparation tool）[RFC7998]の出力を使うことで自然に満たされます。

  • The HTML has to render correctly on a list of browser versions that the RFC Editor will keep up to date outside of this document.
  • The format will consist of a subset of HTML deemed to be widely implemented by common browsers at the time the specification is created, likely to continue to be widely implemented, and unlikely to cause security issues. This will maximize the chances that future HTML renderers (such as new web browsers) will continue to produce readable text from the HTML format without the format needing to be changed frequently.
  • These requirements are expected to change in the future to reflect the expectation that HTML rendering will be required for current versions of browsers and platforms, while ideally continuing to render correctly on recent versions of those browsers.
  • The HTML documents from the RFC Editor or Internet-Drafts directory may be re-rendered from the canonical XML format in the future to ensure the ongoing readability of the documents. The intent is that any re-rendering would be due to exceptional circumstances rather than for minor annoyances.
  • The HTML must display adequately in at least one text-based browser. Some consumers of the RFC Series can only access the documents on text-based terminals.
  • The HTML document will be self-contained, without requiring external files for images, CSS, JavaScript, or the like. This will allow the HTML file to be moved over various non-HTTP transports (such as email, FTP, and rsync) without breakage.
  • JavaScript will be supported on a limited basis. It will not be permitted to overwrite or change any text present in the rendered HTML. It may, on a limited basis, add additional text that provides post-publication metadata or pointers if warranted. All such text will be clearly marked as additional.
  • The HTML document will allow easy local override of the default CSS formatting. This will allow users who have a different visual style that they prefer to make RFCs display with that style without having to alter the contents of the HTML document. This might also be valuable for allowing people with specific accessibility needs to use a customized CSS.
  • HTML tags in documents will rarely have attributes whose only purpose is to affect the rendered styling, and those will only be used if it would not be possible to specify that styling in a CSS. No such attributes are known at this time.
  • Both user-defined and auto-generated anchors must be supported and linkable, with user-defined anchors appearing in an "id" attribute. Auto-generated anchors will be generated for every heading, paragraph, and so on, not just those that do not have user-defined anchors. User-defined anchors may, and auto-generated anchors will, appear next to paragraphs, figures, tables, blockquotes, and section titles.
  • All sections, subsections, figures, and paragraphs should have stable numbered link anchors. Additionally, anchors expressed in the source XML should be exposed as anchors in the HTML output as well.
  • The HTML must make it easy to separate sections along with all of their subsections into separate files. This will make creating EPUB documents easier in the future.
  • The HTML produced for Internet-Drafts will differ from that produced by the RFC Editor due to differences in the output from the prep tool.
  • The abstract must be marked up or tagged in a way that popular search engines will extract it as a summary.
  • HTMLは、RFCエディターがこの文書の外で最新に保つブラウザーのバージョンの一覧において、正しくレンダリングされなければなりません。
  • このフォーマットは、仕様の作成時点で一般的なブラウザーに広く実装されていると見なされ、今後も広く実装され続ける可能性が高く、セキュリティー上の問題を引き起こす可能性が低い、HTMLのサブセットで構成されます。これにより、将来のHTMLレンダラー（新しいウェブブラウザーなど）が、フォーマットを頻繁に変更しなくても、HTMLフォーマットから読みやすいテキストを生成し続けられる可能性が最大になります。
  • これらの要件は、HTMLのレンダリングが現行バージョンのブラウザーやプラットフォームで求められる一方、理想的にはそれらのブラウザーの最近のバージョンでも正しくレンダリングされ続けるという期待を反映して、将来変更されることが見込まれています。
  • RFCエディターまたはインターネットドラフトのディレクトリーにあるHTML文書は、文書が今後も読めることを保証するために、将来、正規のXMLフォーマットから再レンダリングされる場合があります。再レンダリングは、ささいな不便のためではなく、例外的な状況によって行われることを意図しています。
  • HTMLは、少なくとも1つのテキストベースのブラウザーで適切に表示されなければなりません。RFCシリーズの利用者の中には、テキストベースの端末でしか文書にアクセスできない人もいます。
  • HTML文書は自己完結しており、画像、CSS、JavaScriptなどのための外部ファイルを必要としません。これにより、HTMLファイルを壊すことなく、さまざまな非HTTPのトランスポート（電子メール、FTP、rsyncなど）で移動できます。
  • JavaScriptは限定的にサポートされます。JavaScriptが、レンダリングされたHTMLに存在するテキストを上書きしたり変更したりすることは許可されません。正当な理由がある場合、JavaScriptは限定的に、公開後のメタデータやポインターを提供する追加のテキストを加えることができます。そのようなテキストにはすべて、追加されたものであることが明確に示されます。
  • HTML文書では、デフォルトのCSSの書式をローカルで簡単に上書きできます。これにより、好みの視覚スタイルが異なるユーザーは、HTML文書の内容を変更しなくても、RFCをそのスタイルで表示できます。これは、特定のアクセシビリティーのニーズを持つ人々がカスタマイズしたCSSを使えるようにするためにも役立つでしょう。
  • 文書内のHTMLタグが、レンダリングされるスタイルに影響を与えることだけを目的とした属性を持つことはまれであり、そのような属性は、そのスタイルをCSSで指定できない場合にのみ使われます。現時点では、そのような属性は知られていません。
  • ユーザー定義のアンカーと自動生成されたアンカーの両方がサポートされ、リンク可能でなければなりません。ユーザー定義のアンカーは「id」属性に現れます。自動生成されたアンカーは、ユーザー定義のアンカーを持たないものだけでなく、すべての見出しや段落などに対して生成されます。ユーザー定義のアンカーは段落、図、表、ブロック引用、セクションのタイトルの隣に現れる場合があり、自動生成されたアンカーはそれらの隣に必ず現れます。
  • すべてのセクション、サブセクション、図、段落は、安定した番号付きのリンクアンカーを持つべきです。さらに、ソースのXMLで表現されたアンカーも、HTML出力でアンカーとして公開されるべきです。
  • HTMLでは、セクションを、そのすべてのサブセクションとともに別々のファイルに簡単に分割できなければなりません。これにより、将来EPUB文書を作成するのが容易になります。
  • インターネットドラフト用に生成されるHTMLは、準備ツールの出力の違いにより、RFCエディターが生成するHTMLとは異なります。
  • アブストラクトは、一般的な検索エンジンがそれを要約として抽出するような方法でマークアップまたはタグ付けされなければなりません。

2.1. Requirements for Accessibility

2.1. アクセシビリティーの要件

  • Normative information must be easily accessible to the following consumers:

    • People with impaired vision, including those that use large fonts and those that use screen readers
    • People with difficulty distinguishing between colors
    • People who use devices with small screens, such as cell phones
  • Specific instances where goals for accessibility are important in the design choices of the format have been called out in the text.
  • Note: designing for these consumers does not preclude the use of features they cannot use, but it does require that key semantic data not be lost when read using the tools and settings that are required by a given constituency.

  • 規範的な情報は、次の利用者が容易にアクセスできなければなりません。

    • 視覚に障害のある人々（大きなフォントを使う人々やスクリーンリーダーを使う人々を含む）
    • 色の区別が困難な人々
    • 携帯電話のような小さな画面のデバイスを使う人々
  • アクセシビリティーの目標がフォーマットの設計上の選択において重要となる具体的な箇所は、本文中で明示しています。
  • 注：これらの利用者を考慮して設計することは、彼らが使えない機能の使用を妨げるものではありません。しかし、特定の利用者層が必要とするツールや設定を使って読んだときに、重要な意味的データが失われないことは要求されます。

3. HTML Version

3. HTMLのバージョン

The RFC Editor will periodically determine which version of the HTML specification will be referenced for tools generating the format defined in this document. The starting version will be that defined in [W3C.REC-html5-20141028], commonly known as "HTML5". Although the HTML specification mandates several of the syntax and structure rules described in this document, they are called out here for emphasis.

RFCエディターは、この文書で定義するフォーマットを生成するツールが、HTML仕様のどのバージョンを参照するかを定期的に決定します。最初のバージョンは、[W3C.REC-html5-20141028]で定義されている、一般に「HTML5」として知られるものです。この文書で説明する構文や構造の規則のいくつかはHTML仕様によって義務付けられていますが、強調のためにここで明示しています。

4. HTML Syntax

4. HTMLの構文

The processor emitting HTML from the XML source will follow these rules:

XMLソースからHTMLを出力するプロセッサーは、次の規則に従います。

  • The HTML output is encoded as UTF-8, as specified in [RFC3629].
  • The document is valid HTML.
  • Double quotes (U+0022 QUOTATION MARK: ") are used to quote attribute values unless the HTML specification forbids quoting a particular attribute.
  • Each logical line is terminated solely with a \n (U+000A: LINE FEED), otherwise known as "Unix-style" line endings.
  • Code points below (U+0020: SPACE) or character entity references that generate them (e.g. &#9;), other than (U+000A: LINE FEED) may not be used. Note: this rule explicitly forbids \t (U+0009: CHARACTER TABULATION), \f (U+000C: FORM FEED), and \r (U+000D: CARRIAGE RETURN) from appearing in the HTML output.
  • Comments in the source XML, if any, will not be copied into the HTML.
  • The HTML output will be pretty-printed, using whatever consistent rules are deemed best by the developers of the HTML production tools.
  • HTML出力は、[RFC3629]で規定されているとおり、UTF-8でエンコードされます。
  • 文書は有効なHTMLです。
  • HTML仕様が特定の属性を引用符で囲むことを禁止していない限り、属性値を囲むために二重引用符（U+0022 QUOTATION MARK: "）を使います。
  • 各論理行は、\n（U+000A: LINE FEED）のみで終端されます。これは「Unixスタイル」の行末としても知られています。
  • （U+0020: SPACE）より小さいコードポイントや、それを生成する文字実体参照（たとえば&#9;）は、（U+000A: LINE FEED）を除いて使ってはいけません。注：この規則は、\t（U+0009: CHARACTER TABULATION）、\f（U+000C: FORM FEED）、\r（U+000D: CARRIAGE RETURN）がHTML出力に現れることを明示的に禁止します。
  • ソースのXML中のコメントは、もしあってもHTMLにはコピーされません。
  • HTML出力は、HTML生成ツールの開発者が最善と考える一貫した規則を使って、整形出力（pretty-print）されます。

Note: none of these rules affect the rendered output of the HTML, but they are intended to increase the chance that text comparison tools (e.g., "diff") that operate on the HTML output are easier to write.

注：これらの規則はいずれもHTMLのレンダリング結果には影響しませんが、HTML出力を処理するテキスト比較ツール（たとえば「diff」）を書きやすくすることを意図しています。

5. Common Items

5. 共通の項目

This section lists items that are common across multiple parts of the HTML document.

このセクションでは、HTML文書の複数の部分に共通する項目を列挙します。

5.1. IDs

5.1. ID

HTML elements that are generated from XML elements that include an "anchor" attribute will use the value of the "anchor" attribute as the value of the "id" attribute of the corresponding HTML element. The prep tool produces XML with "anchor" attributes in all elements that need them. Some HTML constructs (such as <section>) will use multiple instances of these identifiers.

「anchor」属性を含むXML要素から生成されるHTML要素は、対応するHTML要素の「id」属性の値として「anchor」属性の値を使います。準備ツールは、それを必要とするすべての要素に「anchor」属性を付けたXMLを生成します。一部のHTML構造（<section>など）は、これらの識別子の複数のインスタンスを使います。

5.2. Pilcrows

5.2. ピルクロウ

Each paragraph, artwork, or sourcecode segment outside of a <figure> or <table> element will be appended with a space and a "pilcrow" (U+00B6: PILCROW SIGN), otherwise known as a "paragraph sign". For the purposes of clarity in ASCII renderings of this document, in this document pilcrows are rendered as "&para;". The pilcrow will be linked to the "id" attribute on the XML entity to which it is associated using an <a> element of class "pilcrow". For example:

<figure>要素または<table>要素の外にある各段落、アートワーク、ソースコードの断片の末尾には、スペースと「ピルクロウ（pilcrow）」（U+00B6: PILCROW SIGN）が付け加えられます。ピルクロウは「段落記号」としても知られています。この文書のASCIIレンダリングでわかりやすくするため、この文書ではピルクロウを「&para;」と表記します。ピルクロウは、クラス「pilcrow」の<a>要素を使って、それが関連付けられているXMLエンティティーの「id」属性にリンクされます。たとえば次のようになります。

<p id="s-1.1-1">
  Some paragraph text. <a class="pilcrow" href="#s-1.1-1">&para;</a>
</p>

<p id="s-1.1-1">
  Some paragraph text. <a class="pilcrow" href="#s-1.1-1">&para;</a>
</p>

The pilcrow will normally be invisible unless the element it is attached to is moused over. The pilcrow will be surrounded by a link that points to the element it is attached to.

ピルクロウは通常、それが付けられている要素の上にマウスを置かない限り表示されません。ピルクロウは、それが付けられている要素を指すリンクで囲まれます。

Pilcrows are never included inside a <table> or <figure> element, since the figure number or table number serves as an adequate link target.

図番号や表番号が十分なリンク先として機能するため、ピルクロウが<table>要素や<figure>要素の中に含まれることはありません。

Elements that might otherwise contain a pilcrow do not get marked with a pilcrow if they contain one or more child elements that are marked with a pilcrow. For example:

本来ならピルクロウを含むはずの要素でも、ピルクロウが付けられた子要素を1つ以上含む場合は、ピルクロウが付けられません。たとえば次のようになります。

<blockquote id="s-1.2-1">
  <p id="s-1.2-2">Four score and seven years ago our fathers brought
    forth on this continent, a new nation, conceived in Liberty, and
    dedicated to the proposition that all men are created equal.
    <a href="#s-1.2-2" class="pilcrow">&para;</a></p>
  <!-- NO pilcrow here -->
</blockquote>

<blockquote id="s-1.2-1">
  <p id="s-1.2-2">Four score and seven years ago our fathers brought
    forth on this continent, a new nation, conceived in Liberty, and
    dedicated to the proposition that all men are created equal.
    <a href="#s-1.2-2" class="pilcrow">&para;</a></p>
  <!-- NO pilcrow here -->
</blockquote>

6. Front Matter

6. 前付け

The front matter of the HTML format contains processing information, metadata of various types, and styling information that applies to the document as a whole. This section describes HTML that is not necessarily a direct transform from the XML format. For more details on each of the tags that generate content in this section, see Section 9.

HTMLフォーマットの前付けには、処理情報、さまざまな種類のメタデータ、そして文書全体に適用されるスタイル情報が含まれます。このセクションでは、必ずしもXMLフォーマットから直接変換されるわけではないHTMLについて説明します。このセクションの内容を生成する各タグの詳細については、Section 9を参照してください。

6.1. DOCTYPE

6.1. DOCTYPE

The DOCTYPE of the document is "html", which declares that the document is compliant with HTML5. The document will start with exactly this string:

文書のDOCTYPEは「html」であり、これは文書がHTML5に準拠していることを宣言します。文書は、正確に次の文字列で始まります。

<!DOCTYPE html>

<!DOCTYPE html>

6.2. Root Element

6.2. ルート要素

The root element of the document is <html>. This element includes a "lang" attribute, whose value is a language tag, as discussed in [RFC5646], that describes the natural language of the document. The language tag to be included is "en". The class of the <html> element will be copied verbatim from the XML <rfc> element's <front> element's <seriesInfo> element's "name" attributes (separated by spaces; see Section 2.47.3 of [RFC7991]), allowing CSS to style RFCs and Internet-Drafts differently from one another (if needed):

文書のルート要素は<html>です。この要素には「lang」属性が含まれ、その値は[RFC5646]で議論されている言語タグであり、文書の自然言語を表します。含める言語タグは「en」です。<html>要素のクラスは、XMLの<rfc>要素の<front>要素の<seriesInfo>要素の「name」属性から、そのままコピーされます（スペースで区切られます。[RFC7991]のSection 2.47.3のセクション2.47.3を参照してください）。これにより、必要に応じて、CSSでRFCとインターネットドラフトに異なるスタイルを設定できます。

<html lang="en" class="RFC">

<html lang="en" class="RFC">

6.3. <head> Element

6.3. <head>要素

The root <html> will contain a <head> element that contains the following elements, as needed.

ルートの<html>は<head>要素を含み、その<head>要素には必要に応じて次の要素が含まれます。

6.3.1. Charset Declaration

6.3.1. 文字セットの宣言

In order to be correctly processed by browsers that load the HTML using a mechanism that does not provide a valid content-type or charset (such as from a local file system using a "file:" URL), the HTML <head> element contains a <meta> element, whose "charset" attribute value is "utf-8":

有効なcontent-typeやcharsetを提供しない仕組み（「file:」URLを使ったローカルファイルシステムからの読み込みなど）でHTMLを読み込むブラウザーで正しく処理されるように、HTMLの<head>要素には、「charset」属性の値が「utf-8」である<meta>要素が含まれます。

<meta charset="utf-8">

<meta charset="utf-8">

6.3.2. Document Title

6.3.2. 文書のタイトル

The contents of the <title> element from the XML source will be placed inside an HTML <title> element in the header.

XMLソースの<title>要素の内容は、ヘッダー内のHTMLの<title>要素の中に配置されます。

6.3.3. Document Metadata

6.3.3. 文書のメタデータ

The following <meta> elements will be included:

次の<meta>要素が含まれます。

  • author - one each for the each of the "fullname"s and "asciiFullname"s of all of the <author>s from the <front> of the XML source
  • description - the <abstract> from the XML source
  • generator - the name and version number of the software used to create the HTML
  • keywords - comma-separated <keyword>s from the XML source
  • author - XMLソースの<front>にあるすべての<author>の「fullname」と「asciiFullname」のそれぞれについて1つずつ
  • description - XMLソースの<abstract>
  • generator - HTMLの作成に使われたソフトウェアの名前とバージョン番号
  • keywords - XMLソースの<keyword>をカンマで区切ったもの

For example:

たとえば次のようになります。

<meta name="description" content="This document defines...">
<meta name="generator" content="xmljade v0.2.4">
<meta name="keywords" content="html,css,rfc">

<meta name="author" content="Joe Hildebrand">
<meta name="author" content="JOE HILDEBRAND">

<meta name="description" content="This document defines...">

<meta name="keywords" content="html,css,rfc">

Note: the HTML <meta> tag does not contain a closing slash.

注：HTMLの<meta>タグには、閉じスラッシュは含まれません。

6.3.4. XMLソースへのリンク

The <head> element contains a <link> tag, with "rel" attribute of "alternate", "type" attribute of "application/rfc+xml", and "href" attribute pointing to the prepared XML source that was used to generate this document.

<head>要素には、「rel」属性が「alternate」、「type」属性が「application/rfc+xml」で、「href」属性がこの文書の生成に使われた準備済みのXMLソースを指す<link>タグが含まれます。

<link rel="alternate" type="application/rfc+xml" href="source.xml">

<link rel="alternate" type="application/rfc+xml" href="source.xml">

6.3.5. ライセンスへのリンク

The <head> element contains a <link> tag, with "rel" attribute of "license" and "href" attribute pointing to the an appropriate copyright license for the document.

<head>要素には、「rel」属性が「license」で、「href」属性が文書の適切な著作権ライセンスを指す<link>タグが含まれます。

6.3.6. Style

6.3.6. スタイル

The <head> element contains an embedded CSS in a <style> element. The styles in the style sheet are to be set consistently between documents by the RFC Editor, according to the best practices of the day.

<head>要素には、<style>要素に埋め込まれたCSSが含まれます。スタイルシートのスタイルは、その時々のベストプラクティスに従って、RFCエディターが文書間で一貫して設定します。

仕様の読者によって、RFCのHTML版を読むときに望む書式は異なります。これを容易にするため、<head>要素には、HTMLファイルと同じディレクトリーにある「rfc-local.css」という名前のスタイルシートへの<link>も含まれます。リンクされたスタイルシートの書式は、含まれているスタイルシートの書式を上書きします。たとえば次のようになります。

9.5. <artwork>

9.5. <artwork>

Artwork can consist of either inline text or SVG. If the artwork is not inside a <figure> element, a pilcrow (Section 5.2) is included. Inside a <figure> element, the figure title serves the purpose of the pilcrow. If the "align" attribute has the value "right", the CSS class "alignRight" will be added. If the "align" attribute has the value "center", the CSS class "alignCenter" will be added.

アートワークは、インラインのテキストかSVGのいずれかで構成されます。アートワークが<figure>要素の中にない場合は、ピルクロウ（Section 5.2）が含まれます。<figure>要素の中では、図のタイトルがピルクロウの役割を果たします。「align」属性の値が「right」の場合は、CSSクラス「alignRight」が追加されます。「align」属性の値が「center」の場合は、CSSクラス「alignCenter」が追加されます。

9.63. <ul>

9.63. <ul>

This element is directly rendered as its HTML counterpart. If the "spacing" attribute has the value "compact", a CSS class of "ulCompact" will be added. If the "empty" attribute has the value "true", a CSS class of "ulEmpty" will be added.

この要素は、対応するHTML要素として直接レンダリングされます。「spacing」属性の値が「compact」の場合は、CSSクラス「ulCompact」が追加されます。「empty」属性の値が「true」の場合は、CSSクラス「ulEmpty」が追加されます。

9.64. <uri>

9.64. <uri>

This element is rendered as an HTML <div> containing the string "URI:" and an HTML <a> element with the "href" attribute set to the linked URI, CSS class of "url" (note that the value is "url", not "uri" as one might expect), and the contents set to the linked URI.

この要素は、文字列「URI:」と、「href」属性にリンク先のURIが設定され、CSSクラスが「url」（期待されるかもしれない「uri」ではなく、値が「url」であることに注意してください）で、内容がリンク先のURIであるHTMLの<a>要素を含む、HTMLの<div>としてレンダリングされます。

<div>URI:
  <a href="http://www.example.com"
     class="url">http://www.example.com</a>
</div>

<div>URI:
  <a href="http://www.example.com"
     class="url">http://www.example.com</a>
</div>

9.65. <workgroup>

9.65. <workgroup>

This element does not add any direct output to HTML.

この要素は、HTMLに直接の出力を追加しません。

9.66. <xref>

9.66. <xref>

This element is rendered as an HTML <a> element containing an appropriate local link as the "href" attribute. The value of the "href" attribute is taken from the "target" attribute, prepended by "#". The <a> element generated will have class "xref". The contents of the <a> element are the value of the "derivedContent" attribute. If the "format" attribute has the value "default", and the "target" attribute points to a <reference> or <referencegroup> element, then the generated <a> element is surrounded by square brackets in the output.

この要素は、「href」属性として適切なローカルリンクを含むHTMLの<a>要素としてレンダリングされます。「href」属性の値は、「target」属性の値の前に「#」を付けたものです。生成される<a>要素はクラス「xref」を持ちます。<a>要素の内容は、「derivedContent」属性の値です。「format」属性の値が「default」で、かつ「target」属性が<reference>要素または<referencegroup>要素を指している場合、生成された<a>要素は出力の中で角かっこで囲まれます。

<a class="xref" href="#target">Table 2</a>

<a class="xref" href="#target">Table 2</a>

or

または

[<a class="xref" href="#RFC1234">RFC1234</a>]

[<a class="xref" href="#RFC1234">RFC1234</a>]

9.67. <svg xmlns='http://www.w3.org/2000/svg'>

9.67. <svg xmlns='http://www.w3.org/2000/svg'>

This element is rendered as part of the <artwork> element. The "xmlns='http://www.w3.org/2000/svg'" namespace declaration should be included, and the SVG should be serialized as well-formed XML, even for tags that would otherwise not need closing in HTML5.

この要素は、<artwork>要素の一部としてレンダリングされます。「xmlns='http://www.w3.org/2000/svg'」名前空間宣言を含めるべきです。また、HTML5では本来閉じる必要のないタグであっても、SVGは整形式のXMLとしてシリアル化されるべきです。

10. Security Considerations

10. セキュリティーに関する考慮事項

Since RFCs are sometimes exchanged outside the normal Web sandboxing mechanism (such as using the "rsync" program to a mirror site) then loaded from a local file, more care must be taken with the HTML than is ordinary on the web.

RFCは、通常のウェブのサンドボックスの仕組みの外で交換され（たとえば「rsync」プログラムを使ってミラーサイトに転送され）、その後ローカルファイルから読み込まれることがあるため、HTMLについては、ウェブで通常行われるよりも多くの注意を払わなければなりません。
