1. Introduction

1. はじめに

This document defines a data model for Large-Scale Measurement Platforms (LMAPs) [RFC7594]. The data model is defined using the YANG [RFC7950] data modeling language. It is based on the LMAP Information Model [RFC8193].

この文書は、大規模測定プラットフォーム（LMAP）[RFC7594]のためのデータモデルを定義します。このデータモデルは、YANG [RFC7950]データモデリング言語を使用して定義されます。このデータモデルは、LMAP情報モデル[RFC8193]に基づいています。

1.1. Terminology

1.1. 用語

This document uses the LMAP terminology defined in [RFC7594].

この文書では、[RFC7594]で定義されているLMAPの用語を使用します。

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

キーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、 「要求されています（REQUIRED）」、 「することになります（SHALL）」、「することはありません（SHALL NOT）」、 「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、 「推奨されます（RECOMMENDED）」、「推奨されません（NOT RECOMMENDED）」、 「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、 BCP 14 [RFC2119] [RFC8174]に記載されているとおりに解釈されるものとします。 ただし、ここに示すようにすべて大文字で表示される場合に限ります。

2. Data Model Overview

2. データモデルの概要

The LMAP framework has three basic elements: Measurement Agents (MAs), Controllers, and Collectors. Measurement Agents initiate the actual measurements, which are called Measurement Tasks in the LMAP terminology. The Controller instructs one or more MAs and communicates the set of Measurement Tasks an MA should perform and when. The Collector accepts Reports from the MAs with the Results from their Measurement Tasks.

LMAPフレームワークには、測定エージェント（Measurement Agent、MA）、コントローラー（Controller）、コレクター（Collector）という3つの基本要素があります。測定エージェントは実際の測定を開始します。この測定はLMAPの用語で測定タスク（Measurement Task）と呼ばれます。コントローラーは1つ以上のMAに指示を出し、MAが実行すべき測定タスクの集合とその実行時期を伝えます。コレクターは、MAから、その測定タスクの結果（Result）を含むレポート（Report）を受け取ります。

The YANG data model for LMAP has been split into three modules:

LMAPのためのYANGデータモデルは、3つのモジュールに分割されています。

  1. The module ietf-lmap-common.yang provides common definitions such as LMAP-specific data types.
  2. The module ietf-lmap-control.yang defines the data structures exchanged between a Controller and Measurement Agents.
  3. The module ietf-lmap-report.yang defines the data structures exchanged between Measurement Agents and Collectors.
  1. モジュールietf-lmap-common.yangは、LMAP固有のデータ型などの共通の定義を提供します。
  2. モジュールietf-lmap-control.yangは、コントローラーと測定エージェントの間で交換されるデータ構造を定義します。
  3. モジュールietf-lmap-report.yangは、測定エージェントとコレクターの間で交換されるデータ構造を定義します。

As shown in Figure 1, a Controller, implementing ietf-lmap-common.yang and ietf-lmap-control.yang as a client, will instruct Measurement Agents, which implement ietf-lmap-common.yang and ietf-lmap-control.yang as servers. A Measurement Agent, implementing ietf-lmap-common.yang and ietf-lmap-report.yang, will send results to a Collector, which implements ietf-lmap-common.yang and ietf-lmap-report.yang as a server.

図1に示すように、ietf-lmap-common.yangとietf-lmap-control.yangをクライアントとして実装するコントローラーは、ietf-lmap-common.yangとietf-lmap-control.yangをサーバーとして実装する測定エージェントに指示を出します。ietf-lmap-common.yangとietf-lmap-report.yangを実装する測定エージェントは、ietf-lmap-common.yangとietf-lmap-report.yangをサーバーとして実装するコレクターに結果を送信します。

3. Relationship to the Information Model

3. 情報モデルとの関係

The LMAP Information Model [RFC8193] is divided into six aspects. They are mapped into the YANG data model as explained below:

LMAP情報モデル[RFC8193]は6つの側面に分かれています。これらは、以下で説明するようにYANGデータモデルに対応付けられます。

  • Preconfiguration Information: This is not modeled explicitly since bootstrapping information is outside the scope of this data model. Implementations may use some of the Configuration Information also for bootstrapping purposes.
  • Configuration Information: This is modeled in the /lmap/agent subtree, the /lmap/schedules subtree, and the /lmap/tasks subtree described below. Some items have been left out because they are expected to be dealt with by the underlying protocol.
  • Instruction Information: This is modeled in the /lmap/suppressions subtree, the /lmap/schedules subtree, and the /lmap/tasks subtree described below.
  • Logging Information: Some of the Logging Information, in particular 'success/failure/warning messages in response to information updates from the Controller', will be handled by the protocol used to manipulate the LMAP-specific configuration. The LMAP data model defined in this document assumes that runtime Logging Information will be communicated using protocols that do not require a formal data model, e.g., the syslog protocol defined in [RFC5424].
  • Capability and Status Information: Some of the Capability and Status Information is modeled in the /lmap/capability subtree. The list of supported Tasks is modeled in the /lmap/capabilities/task list. Status Information about Schedules and Actions is included in the /lmap/schedules subtree. Information about network interfaces can be obtained from the ietf-interfaces YANG data model [RFC7223]. Information about the hardware and the firmware can be obtained from the ietf-system YANG data model [RFC7317]. A device identifier can be obtained from the ietf-hardware YANG data model [YANG-HARDWARE].
  • Reporting Information: This is modeled by the report data model to be implemented by the Collector. Measurement Agents send results to the Collector by invoking an RPC on the Collector.
  • 事前設定情報（Preconfiguration Information）：ブートストラップ情報はこのデータモデルの範囲外であるため、これは明示的にはモデル化されていません。実装は、設定情報の一部をブートストラップの目的にも使用してかまいません。
  • 設定情報（Configuration Information）：これは、以下で説明する/lmap/agentサブツリー、/lmap/schedulesサブツリー、および/lmap/tasksサブツリーでモデル化されています。一部の項目は、下位のプロトコルで扱われることが想定されるため、省かれています。
  • 指示情報（Instruction Information）：これは、以下で説明する/lmap/suppressionsサブツリー、/lmap/schedulesサブツリー、および/lmap/tasksサブツリーでモデル化されています。
  • ログ情報（Logging Information）：ログ情報の一部、特に「コントローラーからの情報更新に応答する成功/失敗/警告メッセージ」は、LMAP固有の設定を操作するために使用されるプロトコルによって扱われます。この文書で定義するLMAPデータモデルは、実行時のログ情報が、形式的なデータモデルを必要としないプロトコル（たとえば、[RFC5424]で定義されているsyslogプロトコル）を使用して伝達されることを想定しています。
  • 能力およびステータス情報（Capability and Status Information）：能力およびステータス情報の一部は、/lmap/capabilityサブツリーでモデル化されています。サポートされるタスクのリストは、/lmap/capabilities/taskリストでモデル化されています。スケジュールとアクションに関するステータス情報は、/lmap/schedulesサブツリーに含まれています。ネットワークインターフェイスに関する情報は、ietf-interfaces YANGデータモデル[RFC7223]から取得できます。ハードウェアとファームウェアに関する情報は、ietf-system YANGデータモデル[RFC7317]から取得できます。デバイス識別子は、ietf-hardware YANGデータモデル[YANG-HARDWARE]から取得できます。
  • 報告情報（Reporting Information）：これは、コレクターが実装する報告データモデルによってモデル化されています。測定エージェントは、コレクター上のRPCを呼び出すことによって、結果をコレクターに送信します。

These six Information Model aspects use a collection of common information objects. These common information objects are represented in the YANG data model as follows:

これら6つの情報モデルの側面は、共通の情報オブジェクトの集まりを使用します。これらの共通の情報オブジェクトは、YANGデータモデルでは次のように表現されます。

  • Schedules: Schedules are modeled in the /lmap/schedules subtree.
  • Channels: Channels are not modeled since the NETCONF server configuration data model [NETCONF-CLIENT-SERVER] already provides a mechanism to configure NETCONF server Channels.
  • Task Configurations: Configured Tasks are modeled in the /lmap/tasks subtree.
  • Event Information: Event definitions are modeled in the /lmap/events subtree.
  • スケジュール（Schedules）：スケジュールは、/lmap/schedulesサブツリーでモデル化されています。
  • チャネル（Channels）：NETCONFサーバー設定データモデル[NETCONF-CLIENT-SERVER]がNETCONFサーバーのチャネルを設定する仕組みをすでに提供しているため、チャネルはモデル化されていません。
  • タスク設定（Task Configurations）：設定されたタスクは、/lmap/tasksサブツリーでモデル化されています。
  • イベント情報（Event Information）：イベントの定義は、/lmap/eventsサブツリーでモデル化されています。

5. Security Considerations

5. セキュリティーに関する考慮事項

The YANG module defined in this document is designed to be accessed via network management protocols such as NETCONF [RFC6241] or RESTCONF [RFC8040]. The lowest NETCONF layer is the secure transport layer, and the mandatory-to-implement secure transport is Secure Shell (SSH) [RFC6242]. The lowest RESTCONF layer is HTTPS, and the mandatory-to-implement secure transport is Transport Layer Security (TLS) [RFC5246].

この文書で定義するYANGモジュールは、NETCONF [RFC6241]やRESTCONF [RFC8040]などのネットワーク管理プロトコルを介してアクセスされるように設計されています。NETCONFの最下層はセキュアなトランスポート層であり、実装必須のセキュアなトランスポートはSecure Shell（SSH）[RFC6242]です。RESTCONFの最下層はHTTPSであり、実装必須のセキュアなトランスポートはTransport Layer Security（TLS）[RFC5246]です。

The NETCONF access control model [RFC6536] provides the means to restrict access for particular NETCONF or RESTCONF users to a preconfigured subset of all available NETCONF or RESTCONF protocol operations and content.

NETCONFアクセス制御モデル[RFC6536]は、特定のNETCONFユーザーまたはRESTCONFユーザーのアクセスを、利用可能なすべてのNETCONFまたはRESTCONFのプロトコル操作とコンテンツのうち、事前に設定されたサブセットに制限する手段を提供します。

There are a number of data nodes defined in this YANG module that are writable/creatable/deletable (i.e., config true, which is the default). These data nodes may be considered sensitive or vulnerable in some network environments. Write operations (e.g., edit-config) to these data nodes without proper protection can have a negative effect on network operations. These are the subtrees and data nodes and their sensitivity/vulnerability:

このYANGモジュールで定義されているデータノードには、書き込み可能/作成可能/削除可能なもの（つまり、デフォルトであるconfig true）が数多くあります。これらのデータノードは、一部のネットワーク環境では機密性が高い、または脆弱であるとみなされる場合があります。適切な保護なしにこれらのデータノードへ書き込み操作（たとえば、edit-config）を行うと、ネットワークの運用に悪影響を及ぼす可能性があります。該当するサブツリーとデータノード、およびそれらの機密性/脆弱性は次のとおりです。

/lmap/agent
This subtree configures general properties of the Measurement Agent such as its identity, measurement point, or Controller timeout. This subtree should only have write access for the system responsible for configuring the Measurement Agent.
/lmap/tasks
This subtree configures the Tasks that can be invoked by a Controller. This subtree should only have write access for the system responsible for configuring the Measurement Agent. Care must be taken to not expose Tasks to a Controller that can cause damage to the system or the network.
/lmap/schedules
This subtree is used by a Controller to define the Schedules and Actions that are executed when certain events occur. Unauthorized access can cause unwanted load on the device or network, or it might direct measurement traffic to targets that become victims of an attack.
/lmap/suppressions
This subtree is used by a Controller to define Suppressions that can temporarily disable the execution of Schedules or Actions. Unauthorized access can either disable measurements that should normally take place or cause measurements to take place during times when normally no measurements should take place.
/lmap/events
This subtree is used by a Controller to define events that trigger the execution of Schedules and Actions. Unauthorized access can either disable measurements that should normally take place or cause measurements to take place during times when normally no measurements should take place or at a frequency that is higher than normally expected.
/lmap/agent
このサブツリーは、測定エージェントの識別情報、測定点、コントローラーのタイムアウトなど、測定エージェントの一般的なプロパティーを設定します。このサブツリーへの書き込みアクセスは、測定エージェントの設定を担当するシステムだけが持つべきです。
/lmap/tasks
このサブツリーは、コントローラーが呼び出すことのできるタスクを設定します。このサブツリーへの書き込みアクセスは、測定エージェントの設定を担当するシステムだけが持つべきです。システムやネットワークに損害を与えうるタスクをコントローラーに公開しないよう注意しなければなりません。
/lmap/schedules
このサブツリーは、特定のイベントが発生したときに実行されるスケジュールとアクションを定義するためにコントローラーが使用します。不正なアクセスにより、デバイスやネットワークに望ましくない負荷がかかったり、攻撃の被害者となるターゲットに測定トラフィックが向けられたりする可能性があります。
/lmap/suppressions
このサブツリーは、スケジュールやアクションの実行を一時的に無効にできる抑制を定義するためにコントローラーが使用します。不正なアクセスにより、通常は行われるべき測定が無効にされたり、通常は測定が行われるべきでない時間帯に測定が行われたりする可能性があります。
/lmap/events
このサブツリーは、スケジュールとアクションの実行を引き起こすイベントを定義するためにコントローラーが使用します。不正なアクセスにより、通常は行われるべき測定が無効にされたり、通常は測定が行われるべきでない時間帯や通常想定されるよりも高い頻度で測定が行われたりする可能性があります。

Some of the readable data nodes in this YANG module may be considered sensitive or vulnerable in some network environments. It is thus important to control read access (e.g., via get, get-config, or notification) to these data nodes. These are the subtrees and data nodes and their sensitivity/vulnerability:

このYANGモジュールの読み取り可能なデータノードの一部は、一部のネットワーク環境では機密性が高い、または脆弱であるとみなされる場合があります。したがって、これらのデータノードへの読み取りアクセス（たとえば、get、get-config、notificationによるもの）を制御することが重要です。該当するサブツリーとデータノード、およびそれらの機密性/脆弱性は次のとおりです。

/lmap/agent
This subtree provides information about the Measurement Agent. This information may be used to select specific targets for attacks.
/lmap/capabilities
This subtree provides information about the capabilities of the Measurement Agent, including its software version number and the Tasks that it supports. This information may be used to execute targeted attacks against specific implementations.
/lmap/schedules
This subtree provides information about the Schedules and their associated Actions executed on the Measurement Agent. This information may be used to check whether attacks against the implementation are effective.
/lmap/suppressions
This subtree provides information about the Suppressions that can be active on the Measurement Agent. This information may be used to predict time periods where measurements take place (or do not take place).
/lmap/agent
このサブツリーは、測定エージェントに関する情報を提供します。この情報は、攻撃の特定のターゲットを選ぶために使用される可能性があります。
/lmap/capabilities
このサブツリーは、ソフトウェアのバージョン番号やサポートするタスクなど、測定エージェントの能力に関する情報を提供します。この情報は、特定の実装を狙った攻撃を実行するために使用される可能性があります。
/lmap/schedules
このサブツリーは、測定エージェント上で実行されるスケジュールとそれに関連するアクションに関する情報を提供します。この情報は、実装に対する攻撃が効果を上げているかどうかを確認するために使用される可能性があります。
/lmap/suppressions
このサブツリーは、測定エージェント上で有効になりうる抑制に関する情報を提供します。この情報は、測定が行われる（または行われない）時間帯を予測するために使用される可能性があります。

Some of the RPC operations in this YANG module may be considered sensitive or vulnerable in some network environments. It is thus important to control access to these operations. These are the operations and their sensitivity/vulnerability:

このYANGモジュールのRPC操作の一部は、一部のネットワーク環境では機密性が高い、または脆弱であるとみなされる場合があります。したがって、これらの操作へのアクセスを制御することが重要です。該当する操作とそれらの機密性/脆弱性は次のとおりです。

/report
The report operation is used to send locally collected measurement results to a remote Collector. Unauthorized access may leak measurement results, including those from passive measurements.
/report
report操作は、ローカルで収集した測定結果をリモートのコレクターに送信するために使用されます。不正なアクセスにより、受動的な測定によるものを含め、測定結果が漏洩する可能性があります。

Implementors may find these identifiers useful for the identification of resources, e.g., to identify objects in a file system providing temporary storage. このデータモデルは、コントローラーによって設定される多数の識別子を使用します。実装者は、これらの識別子をリソースの識別に役立てることができるかもしれません（たとえば、一時的な記憶領域を提供するファイルシステム内のオブジェクトを識別するなど）。YANGデータモデルで使用される識別子には、特定の文脈で特別な解釈を与えられうる文字が許される場合があるため、実装は、識別子が安全な識別子へ適切に対応付けられることを保証しなければなりません。

Appendix A. Example Parameter Extension Module

付録A. パラメーター拡張モジュールの例

Sometimes Tasks may require complicated parameters that cannot easily be fit into options, i.e., a list of name/value pairs. In such a situation, it is possible to augment the ietf-lmap-control.yang and ietf-lmap-report.yang data models with definitions for more complex parameters. The following example module demonstrates this idea using the parameters of UDP latency metrics as an example (although UDP latency metric parameters do not really need such an extension module).

タスクによっては、オプション（つまり、名前と値の組のリスト）に簡単には収まらない複雑なパラメーターを必要とすることがあります。そのような状況では、より複雑なパラメーターの定義でietf-lmap-control.yangデータモデルとietf-lmap-report.yangデータモデルを拡張（augment）できます。次のモジュールの例は、UDP遅延メトリクスのパラメーターを例として使用して、この考え方を示しています（ただし、UDP遅延メトリクスのパラメーターは、実際にはこのような拡張モジュールを必要としません）。

module example-ietf-ippm-udp-latency {

  namespace "urn:example:ietf-ippm-udp-latency";
  prefix "ippm-udp-latency";

  import ietf-inet-types {
    prefix inet;
  }
  import ietf-lmap-control {
    prefix "lmapc";
  }
  import ietf-lmap-report {
    prefix "lmapr";
  }

  grouping ippm-udp-latency-parameter-grouping {
    leaf src-ip {
      type inet:ip-address;
      description
        "The source IP address of the UDP measurement traffic.";
    }

    leaf src-port {
      type inet:port-number;
      description
        "The source port number of the UDP measurement traffic.";
    }

    leaf dst-ip {
      type inet:ip-address;
      description
        "The destination IP address of the UDP measurement traffic.";
    }

    leaf dst-port {
      type inet:port-number;
      description
        "The destination port number of the UDP measurement traffic.";
    }

    leaf poisson-lambda {
      type decimal64 {
        fraction-digits 4;
      }
      units "seconds";
      default 1.0000;
      description
        "The average interval for the poisson stream with a resolution
         of 0.0001 seconds (0.1 ms).";
    }

    leaf poisson-limit {
      type decimal64 {
        fraction-digits 4;
      }
      units "seconds";
      default 30.0000;
      description
        "The upper limit on the poisson distribution with a resolution
         of 0.0001 seconds (0.1 ms).";
    }
  }

  augment "/lmapc:lmap/lmapc:schedules/lmapc:schedule/lmapc:action"
        + "/lmapc:parameters/lmapc:extension" {
    description
      "This augmentation adds parameters specific to IP Performance
        Metrics (IPPM) and UDP latency metrics to Actions.";

    case "ietf-ippm-udp-latency" {
      uses ippm-udp-latency-parameter-grouping;
    }
  }

  augment "/lmapr:report/lmapr:input/lmapr:result"
        + "/lmapr:parameters/lmapr:extension" {
    description
      "This augmentation adds parameters specific to IPPM and
       UDP latency metrics to reports.";

    case "ietf-ippm-udp-latency" {
      uses ippm-udp-latency-parameter-grouping;
    }
  }

}
