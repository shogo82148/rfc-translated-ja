RFC 165

A Preferred Official Initial Connection Protocol

RFC 165

公式の初期接続プロトコルの提案

Abstract

概要

This document specifies the their level protocol used to connect a user process at one site with a server process at another site. In one instance, the user process will be a Telnet and the server process will be a Logger, but there will be other cases.

この文書は、あるサイトのユーザープロセスを別のサイトのサーバープロセスに接続するために使う第3レベルのプロトコルを規定します。ある場合には、ユーザープロセスはTelnetで、サーバープロセスはロガー（Logger）ですが、それ以外の場合もあるでしょう。

This document describes a family of Initial Connection Protocols (ICP's) suitable for establishing one pair of connections between any user process and any server process, and further to describe the parameter values for connecting Telnets and Loggers. The description will be at two levels, the third or user level, and the second or NCP level.

この文書では、任意のユーザープロセスと任意のサーバープロセスの間に1組の接続を確立するのに適した初期接続プロトコル（Initial Connection Protocol: ICP）の系統を説明し、さらにTelnetとロガーを接続するためのパラメーター値を説明します。説明は2つのレベル、つまり第3レベル（ユーザーレベル）と第2レベル（NCPレベル）で行います。

Third Level Description

第3レベルの説明

Notation

表記法

There is no standard notation for describing system calls, which initiate and close connections or cause data to be sent, so the following *ad hoc* notation will be used.

接続を開始・切断したり、データを送信させたりするシステムコールを記述するための標準的な表記法はないので、次の*場当たり的な*表記法を使います。

Init (local = l, foreign = f, size = s)

Causes the local Host to attempt to establish a connection between socket l at the local Host and socket f, with a byte size of s for the connection.

l is a 32 bit local socket number,
f is a 40 bit foreign socket number, the high-order eight bits of which specify the foreign Host, and
s is an eight bit non-zero byte size.

The sum of l and f must be odd.

Listen (local = l, size = s)

Causes the local Host to wait for a request for connection to local socket l with byte size s. The process will be woken when a connection is established. The parameters l and s are the same as for Init.

Send (socket = l, data = d)

The data named by d is sent over the connection attached to local socket l. l must be a send socket attached to a connection. d is the name of a data area.

Receive (socket = l, data = d)

The receive side counterpart to send.

Close (socket = l)

Any connection currently attached to local socket l is closed.

Init (local = l, foreign = f, size = s)

ローカルホストに、ローカルホストのソケットlとソケットfの間に、バイトサイズsの接続を確立するよう試みさせます。

lは32ビットのローカルソケット番号です。
fは40ビットの外部ソケット番号で、その上位8ビットが外部ホストを示します。
sは0でない8ビットのバイトサイズです。

lとfの和は奇数でなければなりません。

Listen (local = l, size = s)

ローカルホストに、ローカルソケットlへのバイトサイズsの接続要求を待たせます。接続が確立されると、プロセスは起こされます。パラメーターlとsはInitと同じです。

Send (socket = l, data = d)

dで指定されたデータを、ローカルソケットlに結び付けられた接続を通じて送信します。lは、接続に結び付けられた送信ソケットでなければなりません。dはデータ領域の名前です。

Receive (socket = l, data = d)

sendに対応する受信側の操作です。

Close (socket = l)

ローカルソケットlに現在結び付けられている接続を切断します。

A Family of ICP's

ICPの系統

Briefly, a server process at a site attaches a well-advertised send socket L and listens. A user process initiates connection to L from its receive socket U. The byte size for this connection is 32. The server process then transmits a 32-bit even number S and closes the connection. The 32-bit number S and its successor, S+1, are the socket numbers the server will use. The final steps are for sockets S and S+1 at the server site to be connected to sockets U+3 and U+2 respectively at the user site.

簡単に言うと、あるサイトのサーバープロセスは、広く知られた送信ソケットLを結び付けて待ち受けます。ユーザープロセスは、自身の受信ソケットUからLへの接続を開始します。この接続のバイトサイズは32です。次にサーバープロセスは32ビットの偶数Sを送信し、接続を切断します。32ビットの数値Sとその次の数S+1が、サーバーが使用するソケット番号です。最後の手順として、サーバーサイトのソケットSとS+1を、ユーザーサイトのソケットU+3とU+2にそれぞれ接続します。

Using the notation, the server executes the following sequence:

この表記法を使うと、サーバーは次の手順を実行します。

   Listen (socket = L, size = 32)
   [Wait until a user connects]
   Send (socket = L, data = S)
   Close (socket = L)
   Init (local = S, Foreign = U+3, size Bu)
   Init (local = S+1, foreign = U+2, size Bs)

   Listen (socket = L, size = 32)
   [Wait until a user connects]
   Send (socket = L, data = S)
   Close (socket = L)
   Init (local = S, Foreign = U+3, size Bu)
   Init (local = S+1, foreign = U+2, size Bs)

The user executes the following:

ユーザーは次の手順を実行します。

   Init (local = U, foreign = L, size = 32)
   Receive (socket = U, data = S)
   Optional Close (socket = U)
   Listen or Init (local U+3, foreign = S, size = Bu)
   Listen or Init (local = U+2, foreign = S+1, size = Bs)

   Init (local = U, foreign = L, size = 32)
   Receive (socket = U, data = S)
   Optional Close (socket = U)
   Listen or Init (local U+3, foreign = S, size = Bu)
   Listen or Init (local = U+2, foreign = S+1, size = Bs)

Note that L is a send socket (odd), while S and U are receive sockets (even). Where L, S, or U are used as values of local, they are 32-bit numbers; where they are values of foreign, they are 40-bit numbers. The parameters Bs and Bu are the byte sizes to be sent by the server and user, respectively. If the user side declines to close socket U, then it must be handled automatically by the second level (see page 4).

Lは送信ソケット（奇数）であり、SとUは受信ソケット（偶数）であることに注意してください。L、S、Uがlocalの値として使われる場合は32ビットの数値であり、foreignの値として使われる場合は40ビットの数値です。パラメーターBsとBuは、それぞれサーバーとユーザーが送信するバイトサイズです。ユーザー側がソケットUを切断しない場合、それは第2レベルで自動的に処理されなければなりません（4ページを参照）。

Examination of the above sequences reveals that an ICP is characterized by three numbers L, Bs, and Bu, and must meet the restrictions that

上記の手順を調べると、ICPは3つの数値L、Bs、Buによって特徴付けられ、次の制約を満たさなければならないことがわかります。

  1. L is a send socket,
  2. Bs and Bu are legal byte sizes, and
  3. For each L there is only one pair of associated byte sizes.
  1. Lは送信ソケットである。
  2. BsとBuは正当なバイトサイズである。
  3. 各Lに対して、関連付けられるバイトサイズの組は1つだけである。

This last restriction prevents two district services from being available through the same socket and distinguished only by the byte sizes.

最後の制約は、2つの異なるサービスが同じソケットを通じて提供され、バイトサイズだけで区別されるという事態を防ぐためのものです。

Second Level Description

第2レベルの説明

Notation

表記法

The following notation will be used for the NCP Control Command used in ICP.

ICPで使うNCP制御コマンドには、次の表記法を使います。

        STR (_ls_, _fs_, _s_)
                _ls_ = local send socket
                _fs_ = foreign receive socket
                _s_ = byte size

        RTS (_ls_, _fs_, _l_)
                _ls_ = local receive socket
                _fs_ = foreign send socket
                _l_ = link

        ALL (_l_, _m_, _b_)
                _l_ = link
                _m_ = message allocation
                _b_ = bit allocation

        CLS (_ls_, _fs_)
                _ls_  = local socket
                _fs_ = foreign socket

        STR (_ls_, _fs_, _s_)
                _ls_ = local send socket
                _fs_ = foreign receive socket
                _s_ = byte size

        RTS (_ls_, _fs_, _l_)
                _ls_ = local receive socket
                _fs_ = foreign send socket
                _l_ = link

        ALL (_l_, _m_, _b_)
                _l_ = link
                _m_ = message allocation
                _b_ = bit allocation

        CLS (_ls_, _fs_)
                _ls_  = local socket
                _fs_ = foreign socket

The same family of ICP's is now described again.

ここで、同じICPの系統をもう一度説明します。

Server                          User

S1: listening on socket L.      U1: RTS (U, L, _l1_)

S2: Wait for match.             U2: Wait for match.

S3: STR (L, U, _s1_)

S4: Wait for allocation.        U3: All (_l1_, _m1_, _b1_)

S5: Send data S in_s1_ bit      U4: Receive data S in s1 bit bytes.
    bytes as allowed by             _s1_ bit bytes.
    allocation m1_, _b1_).

S6: CLS (L, U)                  U5: CLS (U, L)

S7: RTS (S, U+3, _l2_)          U6: STR (U+3, S, _s2_)

S8: STR (S+1, U+2, _s3_)        U7: RTS (U+2, S+1, _l3_)

Server                          User

S1: listening on socket L.      U1: RTS (U, L, _l1_)

S2: Wait for match.             U2: Wait for match.

S3: STR (L, U, _s1_)

S4: Wait for allocation.        U3: All (_l1_, _m1_, _b1_)

S5: Send data S in_s1_ bit      U4: Receive data S in s1 bit bytes.
    bytes as allowed by             _s1_ bit bytes.
    allocation m1_, _b1_).

S6: CLS (L, U)                  U5: CLS (U, L)

S7: RTS (S, U+3, _l2_)          U6: STR (U+3, S, _s2_)

S8: STR (S+1, U+2, _s3_)        U7: RTS (U+2, S+1, _l3_)

The labels here imply no ordering except that ordering required by the Host-Host Protocol. Note that steps S7 and S8 can be reversed as can U6 and U7. Also, notice that at any time after S2 the server could initiate steps S7 and S8 in parallel with steps S3 through S6, and that at any time after U4 the user could initiate steps U6 and U7 in parallel with step U5.

ここでのラベルは、ホスト間プロトコル（Host-Host Protocol）が要求する順序以外の順序を意味しません。手順S7とS8は逆にしてもよく、U6とU7も同様であることに注意してください。また、サーバーはS2以降のいつでも、手順S3からS6と並行して手順S7とS8を開始でき、ユーザーはU4以降のいつでも、手順U5と並行して手順U6とU7を開始できることにも注意してください。

Following the above, exchanges ALL commands would be exchanged and data transfers could begin.

以上に続いてALLコマンドが交換され、データ転送を開始できます。

At this level the parameters of the above ICP family are L, _m1_, _b1_, _s1_, _s2_, _s3_, _l1_, _l2_, _l3_.

このレベルでは、上記のICPの系統のパラメーターは、L、_m1_、_b1_、_s1_、_s2_、_s3_、_l1_、_l2_、_l3_です。

L is a well known socket number and will be specified for each type of service.

Lは広く知られたソケット番号で、サービスの種類ごとに規定されます。

m1 and b1 are allocation quantities for the transfer of a socket number.

m1とb1は、ソケット番号を転送するための割り当て量です。

_m1_ is specified to be 1.
_b1_ is specified to be 32.
_s1_, _s2_, and _s3_ are byte sizes. Only _s1_ is to be specified as _s2_ and _s3_ are to be left to the process involved.
_s1_ is specified to be 32.

_m1_は1と規定します。
_b1_は32と規定します。
_s1_、_s2_、_s3_はバイトサイズです。_s2_と_s3_は関係するプロセスに任せるので、規定するのは_s1_だけです。
_s1_は32と規定します。

_l1_, _l2_, and _l3_ are links and are not specified.

_l1_、_l2_、_l3_はリンクであり、規定しません。

Note: Some hosts currently have difficulty sending 32 bit bytes. Thus, it is temporarily allowed to send the socket number S as four 8 bit bytes in one message.

注: 現在、32ビットのバイトを送信するのが難しいホストもあります。そのため、一時的に、ソケット番号Sを1つのメッセージ内の4つの8ビットバイトとして送信することを認めます。

It is legal for the NCP to receive RTS or STR before the corresponding local Init or Listen is issued. Therefore, it is suggested that requests for connection to idle sockets be queued as allowed by time and space limitations.

NCPが、対応するローカルのInitやListenが発行される前にRTSやSTRを受信することは正当です。したがって、アイドル状態のソケットへの接続要求は、時間と空間の制限が許す範囲でキューに入れることを提案します。

Telnet - Logger ICP

Telnet - ロガーICP

For connecting Telnet and Logger processes, the ICP parameters are L=1, Bu, _s2_, and Bs = _s3_ = 8. (To clarify the socket number required, L = X'00000001').

Telnetプロセスとロガープロセスを接続する場合、ICPのパラメーターはL=1、Bu、_s2_、Bs = _s3_ = 8です（必要なソケット番号を明確にしておくと、L = X'00000001'です）。

Formalities

正式な手続き

This proposed official protocol will become official if no serious objections are raised before 2 June 71. A telephone survey of Network Liaisons will be conducted by Jon Postel before that date. If no objections are raised, this protocol will be declared official by the Working Group chairman.

この公式プロトコルの提案は、71年6月2日までに重大な異議が出なければ公式なものとなります。その日までに、Jon Postelがネットワーク連絡担当者（Network Liaison）への電話調査を実施します。異議が出なければ、ワーキンググループの議長がこのプロトコルを公式なものと宣言します。
