RFC 241

Connecting Computers to MLC Ports

RFC 241

MLCポートへのコンピューターの接続

Abstract

概要

Several times we have been asked if computers can be con- nected through serial communication lines to ports on the Terminal IMP's Multi-Line Controller (MLC) [related questions about the level of software support provided by the Terminal IMP to such a connection, have also been raised]. In the past we have said, "Please don't!" We now say, "Sure, but will that really help you the way you think it will?"

Terminal IMPのマルチラインコントローラー（Multi-Line Controller、MLC）のポートに、シリアル通信回線を介してコンピューターを接続できるかと何度か尋ねられたことがあります[そのような接続に対してTerminal IMPが提供するソフトウェアサポートの水準に関する質問も寄せられています]。以前、私たちは「やめてください！」と答えていました。現在は「もちろんです。でも、それは本当に期待どおりに役立つでしょうか？」と答えています。

(1) Connections between computers and IMPs (i.e., the Host interfaces) have been assumed to be error-free. This assumption is justifiable on the basis that the IMP and Host computers were expected to be either in the same room (up to 30 feet of cable) or, via the Distant Host option, within 2000 feet on well- controlled, shielded cables. A connection through common carrier facilities is not comparably free of errors. Usage of common- carrier lines for connecting a terminal to an IMP, including the assumption of a human at the terminal, is a situation in which the typical errors which do occur can be accommodated. Usage of the same wire, with the same typical errors, for a computer-to- computer connection is likely to be a situation in which the errors are unacceptable. The present version of the Terminal IMP does not provide error control either within its hardware or within its software on any ports of the Multi-Line Controller. Further, we feel that computer-to-computer connections over common carrier circuits should employ strong error control, such as that used on the IMP/IMP circuits, and that attempts to use minimal error control (e.g., character parity) is an undesirable technical choice. Strong error control, with its retransmission scheme, not only would imply significant changes in the Terminal IMP, but a non-trivial hardware/software implementation at the remote computer end of the circuit.

(1) コンピューターとIMPとの間の接続（つまりホストインターフェイス）には、エラーがないものと想定されてきました。この想定は、IMPとホストコンピューターが同じ部屋（最大30フィートのケーブル）にあるか、Distant Hostオプションを使って、適切に管理されたシールドケーブルで2000フィート以内にあることが想定されていたことから正当化されます。通信事業者（common carrier）の設備を介した接続は、これに匹敵するほどエラーがないわけではありません。端末をIMPに接続するために通信事業者の回線を使用する場合は、端末の前に人間がいることを想定すれば、実際に発生する典型的なエラーに対処できる状況です。同じ典型的なエラーがある同じ回線をコンピューター間の接続に使用する場合は、エラーが許容できない状況になる可能性が高いでしょう。現在のバージョンのTerminal IMPは、マルチラインコントローラーのどのポートでも、ハードウェア内でもソフトウェア内でもエラー制御を提供しません。さらに、私たちは、通信事業者の回線を介したコンピューター間の接続では、IMP/IMP回線で使われているような強力なエラー制御を採用すべきであり、最小限のエラー制御（たとえば文字パリティー）を使おうとするのは望ましくない技術的選択だと考えています。再送方式を伴う強力なエラー制御は、Terminal IMPに大幅な変更を必要とするだけでなく、回線のリモートコンピューター側でも簡単ではないハードウェア/ソフトウェアの実装を必要とします。

(2) Because the Terminal IMP has many obligations, the share of its bandwidth which can be given to a Host coming in over the MLC will be small.

(2) Terminal IMPには多くの役割があるため、MLC経由で接続するホストに割り当てられる帯域幅の割合は小さくなります。

(3) The command language provided at a port of the Multi- Line Controller was designed with terminals and people in mind. It provides very few of the capabilities which a computer requires in order to effectively utilize the communication network. For example, only a single pair of connections can be made from a given Terminal TMP port; Host computers generally desire a larger number of simultaneous connections to other Hosts on the network. Assuming the present Host/Host protocols, such a Host could not conveniently act as a server.

(3) マルチラインコントローラーのポートで提供されるコマンド言語は、端末と人間を念頭に置いて設計されました。コンピューターが通信ネットワークを効果的に利用するために必要な機能は、ほとんど提供されていません。たとえば、ある1つのTerminal TMPポートからは1組の接続しか確立できませんが、ホストコンピューターは一般に、ネットワーク上のほかのホストとのより多くの同時接続を必要とします。現在のホスト/ホストプロトコルを前提とすると、そのようなホストは容易にはサーバーとして機能できません。

If, despite these potential difficulties, connection of a computer to the network through an MLC port appears to be useful, BBN has no objection. In fact, we would be extremely interested in hearing about actual experience with this type of network connection.

これらの潜在的な困難にもかかわらず、MLCポートを通じてコンピューターをネットワークに接続することが有用だと思われる場合、BBNに異論はありません。実際、私たちはこの種のネットワーク接続の実際の経験についてぜひ聞きたいと思っています。
