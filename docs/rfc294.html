RFC 294

The Use of 'Set Data Type' Transaction in File Transfer Protocol

RFC 294

ファイル転送プロトコルにおける「Set Data Type」トランザクションの使い方

Abstract

概要

As mentioned in RFC 265, the opcode of '00' is set aside for the clarify the use of 'set data type' in file transfer operations.

RFC 265で述べたように、オペコード'00'は〔訳注: 原文ではこの部分が欠落しています〕ファイル転送操作における'set data type'の使い方を明確にします。

In many systems such as Multics at MIT, there is no provision to identify the type of data (i.e., ASCII or numeric) stored in files. The manner in which the data is handled is context dependent. ASCII characters are stored as four 9-bit characters per 36-bit word, right justified with left most bit as zero. As efficient conversion programs exists in Multics for conversion of data from Multics' ASCII into Network ASCII, it would be useful for a user to be able to instruct the Multics server to convert data into Network ASCII in retrieve operations. It is suggested that the 'set data type' transaction be used for this purpose.

MITのMulticsなど多くのシステムには、ファイルに格納されたデータの種類（つまりASCIIか数値か）を識別するしくみがありません。データの扱い方は文脈に依存します。ASCII文字は、36ビットワードあたり9ビット文字を4つずつ、右詰めで最上位ビットを0にして格納します。Multicsには、データをMulticsのASCIIからネットワークASCIIに変換する効率的な変換プログラムがあるので、取得（retrieve）操作の際に、ユーザーがMulticsのサーバーにデータをネットワークASCIIに変換するよう指示できると便利です。この目的のために'set data type'トランザクションを使うことを提案します。

The 'set data type' transaction preceding a retrieve request should be interpreted by a server to mean that the user wants to receive his data in that form. If the server is unable to convert the data into the desired form, it should return a 'set data type' of

サーバーは、取得要求に先立つ'set data type'トランザクションを、ユーザーがその形式でデータを受け取りたいという意味に解釈すべきです。サーバーがデータを希望の形式に変換できない場合は、〔訳注: 原文ではこの部分が欠落しています〕の'set data type'を返すべきです。

The following examples should clarify the use of 'set data type' transactions.

次の例で、'set data type'トランザクションの使い方が明確になるはずです。

          ----                                             ------
                    Set data type '02' (Network ASCII)
                    ------------------------------------->
                    Store File X
                    ------------------------------------->
                    File X (in Network ASCII)
                    ------------------------------------->
                    End of File
                    ------------------------------------->
                    Acknowledge
                    <-------------------------------------

                    Retrieve File X
                    ------------------------------------->
                    File X in Network ASCII
                    <-------------------------------------
                    End of File
                    <-------------------------------------
