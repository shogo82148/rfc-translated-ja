RFC 611

Two changes to the IMP/Host Protocol to improve user/network communications

RFC 611

ユーザーとネットワークの間の通信を改善するためのIMP/Hostプロトコルの2つの変更

Abstract

概要

*Please file this RFC with your copy of BBN Report 1822 until that report is updated.

*BBN Report 1822が更新されるまで、このRFCをお手元のBBN Report 1822と一緒に保管してください。

1. A Reminder

1. 注意喚起

When a host receives an IMP-Going Down message from its IMP (see page 3-15 of BBN Report 1822, Specifications for the Interconnection of a Host and an IMP), the Host should forward the information included in the IMP-Going-Down message to its users from the network and its local users of the network. Further, we suggest that the Host keep this information around after the IMP has gone down, in order to tell local users who are attempting to use the network.

ホストが自身のIMPからIMP-Going Downメッセージを受信したとき（BBN Report 1822「Specifications for the Interconnection of a Host and an IMP」の3-15ページを参照）、ホストは、IMP-Going-Downメッセージに含まれる情報を、ネットワーク経由で接続しているユーザーと、ネットワークを利用するローカルユーザーに転送すべきです。さらに、ネットワークを使おうとしているローカルユーザーに伝えられるように、IMPがダウンした後もホストがこの情報を保持しておくことを提案します。

In the next two sections of the RFC, we describe modifications to the IMP/Host protocol which will allow the IMPs to distribute the same sort of information about Hosts which are down.

このRFCの次の2つのセクションでは、ダウンしているホストについて、IMPが同種の情報を配布できるようにするためのIMP/Hostプロトコルの変更について説明します。

2. Expansion of the Host-Going-Down Message

2. Host-Going-Downメッセージの拡張

The type 2, Host-Going-Down, message described on page 3-1l of BBN Report 1822 has not previously allowed for any provision by the Host for additional information such as why, when, and for how long the Host is going down. The following describes a modification to the Host-Going-Down message which permits the Host to supply this additiona1 information.

BBN Report 1822の3-1lページで説明されているタイプ2のHost-Going-Downメッセージには、これまで、ホストがダウンする理由、時期、期間などの追加情報をホストが提供する手段がありませんでした。以下では、ホストがこの追加情報を提供できるようにするHost-Going-Downメッセージの変更について説明します。

In a type 2, Host-Going-Down message, bits 17-28 give the time of the Host's coming back up, bit-coded as follows:

タイプ2のHost-Going-Downメッセージでは、ビット17〜28でホストが復帰する時刻を示します。ビットの符号化は次のとおりです。

bits 17-19:
the day of the week the Host is coming back up. Monday is day 0 and Sunday is day 6.
bits 20-24:
the hour of the day, from hour 0 to hour 23, that the Host is coming back up.
bits 25-28:
the five minute interval, from 0 to 11, in the hour that the Host is coning back up.
ビット17〜19：
ホストが復帰する曜日。月曜日を0、日曜日を6とします。
ビット20〜24：
ホストが復帰する時（0時から23時まで）。
ビット25〜28：
ホストが復帰する時刻の、その時間内での5分単位の区間（0から11まで）。

All three of the above or to be specified in Universal time (i.e., G.M.T.). The Host may indicate that it will be coming back up more than a week away by setting bits 17-28 all to ones. Setting all bits 17-27 to one and bit 28 to zero means it is unknown when the host is coming back up.

上記の3つはいずれも世界時（すなわちG.M.T.）で指定します。ホストは、ビット17〜28をすべて1に設定することで、復帰が1週間より先になることを示せます。ビット17〜27をすべて1に設定し、ビット28を0に設定すると、ホストがいつ復帰するかが不明であることを意味します。

ホストは、Host-Going-Downメッセージのビット29〜32を使って、ダウンする理由を示すべきです。これらのビットの符号化は次のとおりです。

It is assumed that as the time for the Host to go down approaches, the Host itself will send warning messages to its network users. Just before going down, the Host should send the Host-Going-Down message to its IMP. The IMP will store this message and return it to the source Host along with Destination (Host) Dead messages. The IMP will try to preserve this message over IMP reloads where appropriate. The NCC will be able to update manually the stored copy of this message in response to a phone call from the Host site in the event the Host is going to be down longer than it said or if it didn't have time to say before going down.

ホストがダウンする時刻が近づくにつれて、ホスト自身がネットワーク経由で接続しているユーザーに警告メッセージを送ることを想定しています。ダウンする直前に、ホストはHost-Going-DownメッセージをIMPに送るべきです。IMPはこのメッセージを保存し、Destination (Host) Deadメッセージと一緒に送信元のホストに返します。IMPは、適切な場合には、IMPの再ロードをまたいでこのメッセージを保持するよう努めます。ホストが告げていたよりも長くダウンする場合や、ダウンする前に告げる時間がなかった場合には、ホストのサイトからの電話連絡に応じて、NCCがこのメッセージの保存されたコピーを手動で更新できるようになります。

3. Addition of the Dead Host Status Message

3. Dead Host Statusメッセージの追加

The type 7, destination dead, message described on page 3-16 of BBN Report 1822, does not allow for providing the reason for the Destination Host's being "dead". An additional IMP to Host message is therefore being added which provides status information on the dead Host. This message is type 6, Dead Host Status, and will provide the additional information as follows:

BBN Report 1822の3-16ページで説明されているタイプ7のdestination deadメッセージでは、宛先ホストが「dead」である理由を提供できません。そこで、ダウンしているホストの状態情報を提供する、IMPからホストへのメッセージを新たに追加します。このメッセージはタイプ6のDead Host Statusで、次のように追加情報を提供します。

Bits 17-28 have the same meanings as bits 17-28 in the Host-Going-Down message described in Section 2 above.

ビット17〜28の意味は、前述のセクション2で説明したHost-Going-Downメッセージのビット17〜28と同じです。

Bits 29-32 have the following meanings:

ビット29〜32の意味は次のとおりです。

Table 2

1 The destination Host is not communicating with the network -- it took its ready-line down without saying why.
2 The destination Host is not communicating with the network -- the Host was tardy in taking traffic from the network and the network had to declare the Host down.

When the value of this 4-bit field is 0,1,2, or 3, bits 17-28 will have the "unknown" indication.

この4ビットのフィールドの値が0、1、2、3のいずれかの場合、ビット17〜28は「不明」を示します。

Bit 1 in this message will always be set to zero and Hosts receiving this message should discard without reporting an error type 6 messages with bit 1 set to 1. This will allow later addition of similar status information on dead destination IMPs.

このメッセージのビット1は常に0に設定されます。このメッセージを受信したホストは、ビット1が1に設定されたタイプ6のメッセージを、エラーを報告せずに破棄すべきです。これにより、将来、ダウンしている宛先IMPについての同様の状態情報を追加できるようになります。

The Dead Host Status message will be returned to the source Host shortly (immediately, if possible) after each Destination Host Dead message. The Destination Host Dead message applies to a specific message-id (link) although the information contained in the Destination Host Dead message should probably be reported to all users connected to the dead Host. The Dead Host Status message does not apply to a specific message-id (link) and all users connected to the dead Host should be notified of the information contained in the Dead Host Status message.

Dead Host Statusメッセージは、各Destination Host Deadメッセージの後すぐに（可能であれば直ちに）送信元のホストに返されます。Destination Host Deadメッセージは特定のmessage-id（リンク）に適用されますが、Destination Host Deadメッセージに含まれる情報は、おそらくダウンしているホストに接続しているすべてのユーザーに報告すべきでしょう。Dead Host Statusメッセージは特定のmessage-id（リンク）には適用されず、ダウンしているホストに接続しているすべてのユーザーに、Dead Host Statusメッセージに含まれる情報を通知すべきです。

The modifications mentioned in Section 2 and 3 above will be put into the network very soon, and we urge the Hosts to implement the code necessary to take advantage of these modifications as soon as possible. This modification is backward compatible with the exception (!) that Hosts which have not done the implementation can receive a type 6 message which they do not know how To handle and will presumably log as an error.

前述のセクション2と3で述べた変更は、まもなくネットワークに導入されます。ホストには、これらの変更を活用するために必要なコードをできるだけ早く実装するよう強くお願いします。この変更は後方互換ですが、例外（！）として、実装を済ませていないホストは、処理方法を知らないタイプ6のメッセージを受信する可能性があり、おそらくそれをエラーとして記録することになります。
