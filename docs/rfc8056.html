RFC 8056

Extensible Provisioning Protocol (EPP) and Registration Data Access Protocol (RDAP) Status Mapping

RFC 8056

拡張可能なプロビジョニングプロトコル（EPP）と登録データアクセスプロトコル（RDAP）のステータスマッピング

Abstract

概要

This document describes the mapping of the Extensible Provisioning Protocol (EPP) statuses with the statuses registered for use in the Registration Data Access Protocol (RDAP). This document identifies gaps in the mapping, and registers RDAP statuses to fill those gaps to ensure that all of the EPP statuses specified in RFCs are supported in RDAP.

この文書は、拡張可能なプロビジョニングプロトコル（Extensible Provisioning Protocol: EPP）のステータスと、登録データアクセスプロトコル（Registration Data Access Protocol: RDAP）で使用するために登録されているステータスとのマッピングを記述します。この文書は、マッピングにおける欠落を特定し、RFCで規定されているEPPのすべてのステータスがRDAPでサポートされるように、その欠落を埋めるRDAPのステータスを登録します。

1. Introduction

1. はじめに

This document maps the statuses defined in the Extensible Provisioning Protocol (EPP) RFCs to the list of statuses registered for use in the Registration Data Access Protocol (RDAP), in the "RDAP JSON Values" registry [rdap-json-values].

この文書は、拡張可能なプロビジョニングプロトコル（EPP）のRFCで定義されているステータスを、登録データアクセスプロトコル（RDAP）で使用するために「RDAP JSON Values」レジストリー[rdap-json-values]に登録されているステータスの一覧にマッピングします。

The "RDAP JSON Values" registry is described in Section 10.2 of [RFC7483] and is available in the "RDAP JSON Values" registry [rdap-json-values].

「RDAP JSON Values」レジストリーは[RFC7483]のセクション10.2で記述されており、「RDAP JSON Values」レジストリー[rdap-json-values]で参照できます。

The EPP statuses used as the source of the mapping include Section 2.3 of the Extensible Provisioning Protocol (EPP) Domain Name Mapping [RFC5731], Section 2.3 of "Extensible Provisioning Protocol (EPP) Host Mapping" [RFC5732], Section 2.2 of "Extensible Provisioning Protocol (EPP) Contact Mapping" [RFC5733], and Section 3.1 of "Domain Registry Grace Period Mapping for the Extensible Provisioning Protocol (EPP)" [RFC3915].

マッピングの元として使用するEPPのステータスには、拡張可能なプロビジョニングプロトコル（EPP）のドメイン名マッピング[RFC5731]のセクション2.3、「拡張可能なプロビジョニングプロトコル（EPP）のホストマッピング」[RFC5732]のセクション2.3、「拡張可能なプロビジョニングプロトコル（EPP）の連絡先マッピング」[RFC5733]のセクション2.2、「拡張可能なプロビジョニングプロトコル（EPP）のためのドメインレジストリー猶予期間マッピング」[RFC3915]のセクション3.1が含まれます。

Each EPP status MUST map to a single RDAP status to ensure that data in the Domain Name Registries (DNRs) that use EPP can be accurately presented in RDAP.

EPPを使用するドメイン名レジストリー（Domain Name Registry: DNR）のデータをRDAPで正確に提示できるように、EPPの各ステータスはRDAPの1つのステータスにマッピングされなければなりません（MUST）。

1.1. この文書で使用する規則

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in RFC 2119 [RFC2119].

この文書におけるキーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、「要求されています（REQUIRED）」、「することになります（SHALL）」、「することはありません（SHALL NOT）」、「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、「推奨されます（RECOMMENDED）」、「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、RFC 2119[RFC2119]に記載されているとおりに解釈されるものとします。

The "RDAP JSON Values" registry [rdap-json-values] does have a set of prohibited statuses including "renew prohibited", "update prohibited", "transfer prohibited", and "delete prohibited", but these statuses do not directly map to the EPP prohibited statuses. EPP provides status codes that allow distinguishing the case that an action is prohibited because of server policy from the case that an action is prohibited because of a client request. The ability to make this distinction needs to be preserved in RDAP.

「RDAP JSON Values」レジストリー[rdap-json-values]には、「renew prohibited」、「update prohibited」、「transfer prohibited」、「delete prohibited」などの禁止を表す一連のステータスがありますが、これらのステータスはEPPの禁止を表すステータスに直接はマッピングされません。EPPには、ある操作がサーバーポリシーのために禁止されている場合と、ある操作がクライアントのリクエストのために禁止されている場合とを区別できるステータスコードがあります。この区別ができることは、RDAPでも維持される必要があります。

Each of the EPP status values that don't map directly to an RDAP status value is described below. Each EPP status value includes a proposed new RDAP status value and a description of the value. The RDAP status value is derived from the EPP status value by converting the EPP "camelCase" representation to lowercase with a space character inserted between word boundaries.

RDAPのステータス値に直接マッピングされないEPPのステータス値のそれぞれについて、以下で説明します。EPPの各ステータス値には、提案する新しいRDAPのステータス値と、その値の説明が含まれます。RDAPのステータス値は、EPPの「camelCase」表現を小文字に変換し、単語の境界に空白文字を挿入することによって、EPPのステータス値から導出されます。

addPeriod = add period;
This grace period is provided after the initial registration of the object. If the object is deleted by the client during this period, the server provides a credit to the client for the cost of the registration.
autoRenewPeriod = auto renew period;
This grace period is provided after an object registration period expires and is extended (renewed) automatically by the server. If the object is deleted by the client during this period, the server provides a credit to the client for the cost of the auto renewal.
clientDeleteProhibited = client delete prohibited;
The client requested that requests to delete the object MUST be rejected.
clientHold = client hold;
The client requested that the DNS delegation information MUST NOT be published for the object.
clientRenewProhibited = client renew prohibited;
The client requested that requests to renew the object MUST be rejected.
clientTransferProhibited = client transfer prohibited;
The client requested that requests to transfer the object MUST be rejected.
clientUpdateProhibited = client update prohibited;
The client requested that requests to update the object (other than to remove this status) MUST be rejected.
pendingRestore = pending restore;
An object is in the process of being restored after being in the redemption period state.
redemptionPeriod = redemption period;
A delete has been received, but the object has not yet been purged because an opportunity exists to restore the object and abort the deletion process.
renewPeriod = renew period;
This grace period is provided after an object registration period is explicitly extended (renewed) by the client. If the object is deleted by the client during this period, the server provides a credit to the client for the cost of the renewal.
serverDeleteProhibited = server delete prohibited;
The server set the status so that requests to delete the object MUST be rejected.
serverRenewProhibited = server renew prohibited;
The server set the status so that requests to renew the object MUST be rejected.
serverTransferProhibited = server transfer prohibited;
The server set the status so that requests to transfer the object MUST be rejected.
serverUpdateProhibited = server update prohibited;
The server set the status so that requests to update the object (other than to remove this status) MUST be rejected.
serverHold = server hold;
The server set the status so that DNS delegation information MUST NOT be published for the object.
transferPeriod = transfer period;
This grace period is provided after the successful transfer of object registration sponsorship from one client to another client. If the object is deleted by the client during this period, the server provides a credit to the client for the cost of the transfer.
addPeriod = add period;
この猶予期間は、オブジェクトの最初の登録の後に設けられます。この期間中にクライアントがオブジェクトを削除した場合、サーバーはクライアントに登録の費用分のクレジットを提供します。
autoRenewPeriod = auto renew period;
この猶予期間は、オブジェクトの登録期間が満了し、サーバーによって自動的に延長（更新）された後に設けられます。この期間中にクライアントがオブジェクトを削除した場合、サーバーはクライアントに自動更新の費用分のクレジットを提供します。
clientDeleteProhibited = client delete prohibited;

clientHold = client hold;

clientUpdateProhibited = client update prohibited;
クライアントの要求により、（このステータスを取り除く場合を除いて）オブジェクトを変更（update）するリクエストは拒否されなければなりません（MUST）。
pendingRestore = pending restore;
オブジェクトが、償還期間（redemption period）の状態を経て、復元される処理の途中にあります。
redemptionPeriod = redemption period;
削除を受け取りましたが、オブジェクトを復元して削除処理を中止する機会があるため、オブジェクトはまだパージされていません。
renewPeriod = renew period;
この猶予期間は、オブジェクトの登録期間がクライアントによって明示的に延長（更新）された後に設けられます。この期間中にクライアントがオブジェクトを削除した場合、サーバーはクライアントに更新の費用分のクレジットを提供します。
serverDeleteProhibited = server delete prohibited;
サーバーがこのステータスを設定したため、オブジェクトを削除するリクエストは拒否されなければなりません（MUST）。
serverRenewProhibited = server renew prohibited;
サーバーがこのステータスを設定したため、オブジェクトを更新するリクエストは拒否されなければなりません（MUST）。
serverTransferProhibited = server transfer prohibited;
サーバーがこのステータスを設定したため、オブジェクトを移管するリクエストは拒否されなければなりません（MUST）。
serverUpdateProhibited = server update prohibited;
サーバーがこのステータスを設定したため、（このステータスを取り除く場合を除いて）オブジェクトを変更するリクエストは拒否されなければなりません（MUST）。
serverHold = server hold;
サーバーがこのステータスを設定したため、そのオブジェクトのDNS委任情報を公開してはなりません（MUST NOT）。
transferPeriod = transfer period;
この猶予期間は、オブジェクト登録のスポンサーをあるクライアントから別のクライアントへ移管することに成功した後に設けられます。この期間中にクライアントがオブジェクトを削除した場合、サーバーはクライアントに移管の費用分のクレジットを提供します。

4. Security Considerations

4. セキュリティーに関する考慮事項

The status values described in this document can be subject to server-side information disclosure policies that restrict display of the values to authorized clients. Implementers may wish to review [RFC7481] for a description of the RDAP security services that can be used to implement information disclosure policies.

この文書で説明するステータス値は、値の表示を認可されたクライアントに制限するサーバー側の情報開示ポリシーの対象となることがあります。実装者は、情報開示ポリシーの実装に使用できるRDAPのセキュリティーサービスの説明について、[RFC7481]を確認するとよいでしょう。
