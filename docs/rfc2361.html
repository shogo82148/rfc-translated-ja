RFC 2361

WAVE and AVI Codec Registries

RFC 2361

WAVEとAVIのコーデックのレジストリー

Abstract

概要

Internet applications may reference specific codecs within the WAVE and AVI registries as follows:

インターネットアプリケーションは、WAVEとAVIのレジストリー内の特定のコーデックを次のように参照できます。

  • video/vnd.avi; codec=XXX identifies a specific video codec (i.e., XXX) within the AVI Registry.
  • audio/vnd.wave; codec=YYY identifies a specific audio codec (i.e., YYY) within the WAVE Registry.
  • video/vnd.avi; codec=XXXは、AVIレジストリー内の特定のビデオコーデック（つまり、XXX）を識別します。
  • audio/vnd.wave; codec=YYYは、WAVEレジストリー内の特定のオーディオコーデック（つまり、YYY）を識別します。

Appendix A and Appendix B provides an authoritative reference for the interpretation of the required "codec" parameter. That is, the current set of audio codecs that are registered within the WAVE Registry are enumerated in Appendix A. Appendix B enumerates the current set of video codecs that have been registered to date within the AVI Registry.

付録Aと付録Bは、必須の「codec」パラメーターの解釈についての権威ある参照を提供します。つまり、WAVEレジストリー内に登録されているオーディオコーデックの現在の集合は付録Aに列挙されています。付録Bは、これまでにAVIレジストリー内に登録されたビデオコーデックの現在の集合を列挙しています。

1. Introduction

1. はじめに

Internet-oriented multimedia applications reference multimedia content via predefined mechanisms (e.g., [2]). In the general case, this content was created primarily for the use of these Internet- oriented applications. Unfortunately, this Internet-oriented multimedia content represents a small minority of the total amount of multimedia content that has been created to date.

インターネット指向のマルチメディアアプリケーションは、事前に定義されたメカニズム（たとえば、[2]）を介してマルチメディアのコンテンツを参照します。一般的な場合、このコンテンツは、主にこれらのインターネット指向のアプリケーションで使用するために作成されたものです。残念ながら、このインターネット指向のマルチメディアのコンテンツは、これまでに作成されたマルチメディアのコンテンツの総量のうちのごく一部にすぎません。

For this reason, a growing interest is forming in establishing mechanisms by which the repertoire of multimedia content available to Internet-oriented applications(e.g., for RTSP [3]) may be greatly extended to include multimedia content that has been created outside of distinctly Internet contexts. For this to occur, a mechanism must be created for Internet protocols (e.g., [1], [3], [4]) to be able to identify the codecs by which this so-called "traditional" multimedia content has been encoded.

このため、インターネット指向のアプリケーション（たとえば、RTSP [3]のためのもの）で利用できるマルチメディアのコンテンツの種類を、明確にインターネットの文脈の外で作成されたマルチメディアのコンテンツを含むように大幅に拡張できるメカニズムを確立することへの関心が高まっています。これを実現するには、インターネットのプロトコル（たとえば、[1]、[3]、[4]）が、このいわゆる「伝統的な」マルチメディアのコンテンツの符号化に使用されたコーデックを識別できるようにするメカニズムを作成しなければなりません。

Unfortunately, several distinct encoding systems exist for traditional multimedia content. Each system has its own registry to ensure unique and stable codec identifications within that system. Perhaps the best known of these registries are Microsoft (for WAVE and AVI content) and Apple (for QuickTime content).

残念ながら、伝統的なマルチメディアのコンテンツには、いくつかの異なる符号化のシステムが存在します。各システムは、そのシステム内でのコーデックの識別の一意性と安定性を確保するために、独自のレジストリーを持っています。おそらく、これらのレジストリーの中で最もよく知られているのは、Microsoft（WAVEとAVIのコンテンツのため）とApple（QuickTimeのコンテンツのため）のものです。

The purpose of this paper is to establish a mechanism by which codecs registered within Microsoft's WAVE and AVI Registries may be referenced within the IANA Namespace by Internet applications.

この文書の目的は、MicrosoftのWAVEとAVIのレジストリー内に登録されたコーデックを、インターネットアプリケーションがIANAの名前空間内で参照できるようにするメカニズムを確立することです。

2. References to Registries within the IANA Vendor Tree

2. IANAのベンダーツリー内でのレジストリーへの参照

Reference [7] specifies that the IANA Namespace encompasses several trees. Discussions within the IETF-Types mailing list concluded that the most appropriate tree in which to reference codecs, which had already been registered by non-IANA Registries, is the Vendor Tree.

参考文献[7]は、IANAの名前空間がいくつかのツリーを包含することを規定しています。IETF-Typesメーリングリストでの議論では、IANA以外のレジストリーによってすでに登録されているコーデックを参照するのに最も適切なツリーはベンダーツリーであると結論付けられました。

As a result, the non-IANA registry is identified within the IANA Vendor tree by vnd.RegistryName. A specific codec, which has been registered within that registry, is identified by a required codec parameter as specified by Section 2.2.3 of [7].

その結果、IANA以外のレジストリーは、IANAのベンダーツリー内でvnd.RegistryNameによって識別されます。そのレジストリー内に登録された特定のコーデックは、[7]の2.2.3節で規定されているように、必須のcodecパラメーターによって識別されます。

3. WAVE and AVI Registries

3. WAVEとAVIのレジストリー

Both the WAVE and AVI Registries are historic databases that have been maintained by Microsoft as a free service. The Registries sought to assist developers of WAVE and AVI content and to standardize WAVE and AVI content by 1) avoiding conflict and/or duplication with current definitions, and 2) providing the registered information in a standard document and format that is publicly available. The historic nature of these databases implies that unless the original registrants informed the registrar of a change of status (e.g., company acquired, new contact, new location, new phone), the contact information has generally not been updated from the originally registered values.

WAVEとAVIのレジストリーはどちらも、Microsoftが無料のサービスとして維持してきた歴史的なデータベースです。これらのレジストリーは、1) 現在の定義との衝突や重複を避けること、および2) 登録された情報を一般に公開されている標準的な文書と形式で提供することによって、WAVEとAVIのコンテンツの開発者を支援し、WAVEとAVIのコンテンツを標準化しようとしました。これらのデータベースが歴史的な性質を持つということは、元の登録者が状態の変化（たとえば、会社の買収、新しい連絡先、新しい所在地、新しい電話番号）を登録機関に知らせない限り、連絡先の情報は一般に最初に登録された値から更新されていないことを意味します。

Audio codecs within the WAVE Registry are identified by WAVE Format IDs. The (audio) WAVE Format ID is officially known as "WAVE form Registration Number". The WAVE Format ID is a hexadecimal integer value. These codecs may be referenced within the IANA namespace as "audio/vnd.wave; codec=XXX", where XXX represents a valid WAVE Format ID (e.g., the WAVE Format ID of "123" is referenced within the IANA namespace by "audio/vnd.wave; codec=123").

WAVEレジストリー内のオーディオコーデックは、WAVE Format IDによって識別されます。（オーディオの）WAVE Format IDは、正式には「WAVE form Registration Number」として知られています。WAVE Format IDは16進数の整数値です。これらのコーデックは、IANAの名前空間内で「audio/vnd.wave; codec=XXX」として参照できます。ここで、XXXは有効なWAVE Format IDを表します（たとえば、「123」のWAVE Format IDは、IANAの名前空間内で「audio/vnd.wave; codec=123」によって参照されます）。

Video codecs within the AVI Registry are identified by AVI Codec IDs. The AVI Codec ID value is a FourCC encoding. A FourCC is 32-bits long and represents a (case-sensitive) four-character (i.e., ASCII) code value. These codecs may be referenced within the IANA namespace as "video/vnd.avi; codec=XXX", where XXX represents a valid AVI Codec ID (e.g., the WAVE Format ID of "SCRN" is referenced within the IANA namespace by "video/vnd.avi; codec=SCRN").

AVIレジストリー内のビデオコーデックは、AVI Codec IDによって識別されます。AVI Codec IDの値はFourCCの符号化です。FourCCは32ビットの長さで、（大文字と小文字を区別する）4文字の（つまり、ASCIIの）コード値を表します。これらのコーデックは、IANAの名前空間内で「video/vnd.avi; codec=XXX」として参照できます。ここで、XXXは有効なAVI Codec IDを表します（たとえば、「SCRN」のWAVE Format IDは、IANAの名前空間内で「video/vnd.avi; codec=SCRN」によって参照されます）。

4. Mapping Codec IDs to GUID Values

4. コーデックIDからGUIDの値への対応付け

Direct mappings exist between WAVE Format IDs and GUIDs and between FourCC codec values and GUIDs [5]. [Note: GUIDs are Globally Unique Identifiers that are also known as Universally Unique Identifiers (UUIDs). UUIDs have been standardized within the Open Software Foundation's (OSF) Distributed Computing Environment (DCE).] These mappings enable GUID-oriented software to directly refer to these historic codec values. For example, the Advanced Streaming Format (ASF) [6] uses GUID values to refer to codecs, and the following mechanism is used to convert the historic WAVE and AVI codec values into the appropriate GUID value for use within ASF.

WAVE Format IDとGUIDの間、およびFourCCのコーデックの値とGUIDの間には、直接の対応付けが存在します[5]。［注記: GUIDはGlobally Unique Identifierであり、Universally Unique Identifier（UUID）としても知られています。UUIDは、Open Software Foundation（OSF）のDistributed Computing Environment（DCE）内で標準化されています。］これらの対応付けにより、GUID指向のソフトウェアは、これらの歴史的なコーデックの値を直接参照できます。たとえば、Advanced Streaming Format（ASF）[6]はコーデックを参照するためにGUIDの値を使用しており、歴史的なWAVEとAVIのコーデックの値を、ASF内で使用するための適切なGUIDの値に変換するために、次のメカニズムが使用されます。

WAVE Format IDs are converted to GUIDs by inserting the hexadecimal value of the WAVE Format ID into the XXXXXXXX part of the following template: {XXXXXXXX-0000-0010-8000-00AA00389B71}. For example, a WAVE Format ID of 123 has the GUID value of {00000123-0000-0010-8000- 00AA00389B71}.

WAVE Format IDは、WAVE Format IDの16進数の値を、次のテンプレートのXXXXXXXXの部分に挿入することでGUIDに変換されます: {XXXXXXXX-0000-0010-8000-00AA00389B71}。たとえば、123のWAVE Format IDは、{00000123-0000-0010-8000- 00AA00389B71}のGUIDの値を持ちます。

FourCC values are converted to GUIDs by inserting the FourCC value into the XXXXXXXX part of the same template: {XXXXXXXX-0000-0010- 8000-00AA00389B71}. For example, a conversion of the FourCC value of "H260" would result in the GUID value of {30363248-0000-0010-8000- 00AA00389B71}. [Note: the 32-bit FourCC value of "H260" is converted into hexadecimal 32-bit value (i.e., 30363248) because the initial XXXXXXXX of the GUID is defined as a DWORD and thus takes a 32-bit hexadecimal value. Endian considerations account for the apparent re-ordering of the original ASCII text.]

FourCCの値は、FourCCの値を同じテンプレートのXXXXXXXXの部分に挿入することでGUIDに変換されます: {XXXXXXXX-0000-0010- 8000-00AA00389B71}。たとえば、「H260」のFourCCの値を変換すると、{30363248-0000-0010-8000- 00AA00389B71}のGUIDの値になります。［注記: GUIDの先頭のXXXXXXXXはDWORDとして定義されており、32ビットの16進数の値をとるため、「H260」の32ビットのFourCCの値は、16進数の32ビットの値（つまり、30363248）に変換されます。元のASCIIのテキストの順序が入れ替わっているように見えるのは、エンディアンを考慮しているためです。］
