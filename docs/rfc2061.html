RFC 2061

IMAP4 Compatibility with IMAP2bis

RFC 2061

IMAP4とIMAP2bisとの互換性

Status of This Memo

このメモのステータス

This memo provides information for the Internet community. This memo does not specify an Internet standard of any kind. Distribution of this memo is unlimited.

このメモは、インターネットコミュニティーのための情報を提供します。このメモは、いかなる種類のインターネット標準も規定しません。このメモの配布は無制限です。

Introduction

はじめに

The Internet Message Access Protocol (IMAP) has been through several revisions and variants in its 10-year history. Many of these are either extinct or extremely rare; in particular, several undocumented variants and the variants described in RFC 1064, RFC 1176, and RFC 1203 fall into this category.

インターネットメッセージアクセスプロトコル（Internet Message Access Protocol; IMAP）は、その10年の歴史の中でいくつもの改訂と変種を経てきました。それらの多くは、すでに消滅したか、きわめてまれなものです。特に、文書化されていないいくつかの変種や、RFC 1064、RFC 1176、RFC 1203に記述された変種がこれに当たります。

One variant, IMAP2bis, is at the time of this writing very common and has been widely distributed with the Pine mailer. Unfortunately, there is no definite document describing IMAP2bis. This document is intended to be read along with RFC 1176 and the most recent IMAP4 specification (RFC 2060) to assist implementors in creating an IMAP4 implementation to interoperate with implementations that conform to earlier specifications. Nothing in this document is required by the IMAP4 specification; implementors must decide for themselves whether they want their implementation to fail if it encounters old software.

変種の1つであるIMAP2bisは、この文書の執筆時点で非常に普及しており、Pineメーラーとともに広く配布されています。残念ながら、IMAP2bisを記述した決定的な文書はありません。この文書は、RFC 1176および最新のIMAP4仕様（RFC 2060）とあわせて読み、以前の仕様に準拠した実装と相互運用できるIMAP4実装を実装者が作成するのを支援することを目的としています。この文書の内容は、IMAP4仕様で要求されているものではありません。古いソフトウェアに遭遇したときに自分の実装が失敗してもよいかどうかは、実装者自身が決めなければなりません。

At the time of this writing, IMAP4 has been updated from the version described in RFC 1730. An implementor who wishes to interoperate with both RFC 1730 and RFC 2060 should refer to both documents.

この文書の執筆時点で、IMAP4はRFC 1730に記述された版から更新されています。RFC 1730とRFC 2060の両方と相互運用したい実装者は、両方の文書を参照すべきです。

This information is not complete; it reflects current knowledge of server and client implementations as well as "folklore" acquired in the evolution of the protocol. It is NOT a description of how to interoperate with all variants of IMAP, but rather with the old variant that is most likely to be encountered. For detailed information on interoperating with other old variants, refer to RFC 1732.

この情報は完全なものではありません。サーバーとクライアントの実装に関する現在の知識と、プロトコルの進化の過程で得られた「言い伝え」を反映したものです。これは、IMAPのすべての変種と相互運用する方法を記述したものではなく、遭遇する可能性が最も高い古い変種と相互運用する方法を記述したものです。他の古い変種との相互運用に関する詳しい情報は、RFC 1732を参照してください。

IMAP4 client interoperability with IMAP2bis servers

IMAP4クライアントとIMAP2bisサーバーとの相互運用性

A quick way to check whether a server implementation supports the IMAP4 specification is to try the CAPABILITY command. An OK response will indicate which variant(s) of IMAP4 are supported by the server. If the client does not find any of its known variant in the response, it should treat the server as IMAP2bis. A BAD response indicates an IMAP2bis or older server.

サーバーの実装がIMAP4仕様をサポートしているかどうかを手早く確認するには、CAPABILITYコマンドを試してみます。OK応答であれば、サーバーがサポートしているIMAP4の変種が示されます。クライアントが応答の中に自分の知っている変種を1つも見つけられなかった場合は、そのサーバーをIMAP2bisとして扱うべきです。BAD応答は、IMAP2bis以前のサーバーであることを示します。

Most IMAP4 facilities are in IMAP2bis. The following exceptions exist:

IMAP4の機能のほとんどはIMAP2bisにもあります。例外は次のとおりです。

CAPABILITY command
The absense of this command indicates IMAP2bis (or older).
AUTHENTICATE command.
Use the LOGIN command.
LSUB, SUBSCRIBE, and UNSUBSCRIBE commands
No direct functional equivalent. IMAP2bis had a concept called "bboards" which is not in IMAP4. RFC 1176 supported these with the BBOARD and FIND BBOARDS commands. IMAP2bis augmented these with the FIND ALL.BBOARDS, SUBSCRIBE BBOARD, and UNSUBSCRIBE BBOARD commands. It is recommended that none of these commands be implemented in new software, including servers that support old clients.
LIST command
Use the command FIND ALL.MAILBOXES, which has a similar syntax and response to the FIND MAILBOXES command described in RFC 1176. The FIND MAILBOXES command is unlikely to produce useful information.
* in a sequence
Use the number of messages in the mailbox from the EXISTS unsolicited response.
SEARCH extensions (character set, additional criteria)
Reformulate the search request using only the RFC 1176 syntax. This may entail doing multiple searches to achieve the desired results.
BODYSTRUCTURE fetch data item
Use the non-extensible BODY data item.
body sections HEADER, TEXT, MIME, HEADER.FIELDS, HEADER.FIELDS.NOT
Use body section numbers only.
BODY.PEEK[section]
Use BODY[section] and manually clear the \Seen flag as necessary.
FLAGS.SILENT, +FLAGS.SILENT, and -FLAGS.SILENT store data items
Use the corresponding non-SILENT versions and ignore the untagged FETCH responses which come back.
UID fetch data item and the UID commands
No functional equivalent.
CLOSE command
No functional equivalent.
CAPABILITYコマンド
このコマンドがないことは、IMAP2bis（またはそれ以前）であることを示します。
AUTHENTICATEコマンド
LOGINコマンドを使ってください。
LSUB、SUBSCRIBE、UNSUBSCRIBEコマンド
機能的に直接同等なものはありません。IMAP2bisには「bboards」と呼ばれる概念がありましたが、これはIMAP4にはありません。RFC 1176は、これをBBOARDコマンドとFIND BBOARDSコマンドでサポートしていました。IMAP2bisは、これにFIND ALL.BBOARDS、SUBSCRIBE BBOARD、UNSUBSCRIBE BBOARDコマンドを追加しました。古いクライアントをサポートするサーバーも含め、新しいソフトウェアではこれらのコマンドをどれも実装しないことを推奨します。
LISTコマンド
FIND ALL.MAILBOXESコマンドを使ってください。このコマンドの構文と応答は、RFC 1176に記述されたFIND MAILBOXESコマンドと似ています。FIND MAILBOXESコマンドが有用な情報を返す可能性は低いです。
シーケンス中の*
EXISTS非請求応答（unsolicited response）から得られる、メールボックス内のメッセージ数を使ってください。
SEARCHの拡張（文字集合、追加の検索条件）
RFC 1176の構文だけを使って検索要求を組み立て直してください。望みの結果を得るために、複数回の検索が必要になる場合があります。
BODYSTRUCTUREフェッチデータ項目
拡張不可能なBODYデータ項目を使ってください。
本文セクションHEADER、TEXT、MIME、HEADER.FIELDS、HEADER.FIELDS.NOT
本文セクション番号だけを使ってください。
BODY.PEEK[section]
BODY[section]を使い、必要に応じて\Seenフラグを手動でクリアしてください。
FLAGS.SILENT、+FLAGS.SILENT、-FLAGS.SILENTストアデータ項目
対応するSILENTでない版を使い、返ってくるタグなしのFETCH応答を無視してください。
UIDフェッチデータ項目とUIDコマンド
機能的に同等なものはありません。
CLOSEコマンド
機能的に同等なものはありません。

In IMAP2bis, the TRYCREATE special information token is sent as a separate unsolicited OK response instead of inside the NO response.

IMAP2bisでは、TRYCREATE特殊情報トークンは、NO応答の中ではなく、別個の非請求OK応答として送られます。

IMAP2bis is ambiguous about whether or not flags or internal dates are preserved on COPY. It is impossible to know what behavior is supported by the server.

IMAP2bisは、COPYでフラグや内部日付が保持されるかどうかがあいまいです。サーバーがどちらの動作をサポートしているかを知ることはできません。

IMAP4 server interoperability with IMAP2bis clients

IMAP4サーバーとIMAP2bisクライアントとの相互運用性

The only interoperability problem between an IMAP4 server and a well-written IMAP2bis client is an incompatibility with the use of "\" in quoted strings. This is best avoided by using literals instead of quoted strings if "\" or <"> is embedded in the string.

IMAP4サーバーと、よく書かれたIMAP2bisクライアントとの間の唯一の相互運用性の問題は、引用符付き文字列の中での「\」の使い方に互換性がないことです。この問題は、文字列に「\」や<">が含まれる場合に、引用符付き文字列の代わりにリテラルを使うことで回避するのが最善です。
