RFC 38

Comments on Network Protocol from NWG/RFC #36

RFC 38

NWG/RFC #36のネットワークプロトコルに対するコメント

Abstract

概要

The proposed protocol does not allow for the possible multiplexing of connections over links.

提案されたプロトコルでは、リンク上でコネクションを多重化できるようになっていません。

Generally, this presents no problem, but it might cause loading restrictions in the future. Two cases where routing multiple connections over the same link are apparent:

一般にはこれで問題はありませんが、将来、負荷の面で制約になるかもしれません。複数のコネクションを同じリンクに通すことが明らかに有用な場合として、次の2つがあります。

  1. Where a user has several high speed connections, such as between processes that transmit files over the network. Assigning these connections to the same link limits the percentage of network resources that may be used by that user. This becomes particularly important when several store-and-forward IMP's are used by the network to effect the communication.
  2. When two hosts each have their own independent network and desire to allow access to the other hosts's network over the ARPA net, a shortage of links may develop. Again, the assignment of several connections to the same link could help solve the problem.
  1. ネットワーク越しにファイルを転送するプロセス間のコネクションのように、ユーザーが複数の高速なコネクションを持っている場合。これらのコネクションを同じリンクに割り当てれば、そのユーザーが使えるネットワーク資源の割合を制限できます。これは、通信を実現するためにネットワークが複数の蓄積交換型のIMPを使う場合に特に重要になります。
  2. 2つのホストがそれぞれ独自の独立したネットワークを持ち、ARPAネットを介して相手のホストのネットワークへのアクセスを許可したい場合、リンクが不足するおそれがあります。この場合も、複数のコネクションを同じリンクに割り当てることが問題の解決に役立つかもしれません。

The following changes in the protocol would make possible the future use of multiplexed links. It is not necessary to add the multiplexing, itself, to the protocol at this time.

プロトコルに次の変更を加えれば、将来、多重化したリンクを使えるようになります。現時点で多重化そのものをプロトコルに加える必要はありません。

  1. The END and RDY must specify relevant sockets in addition to the link number. Only the local socket name need be supplied.
  2. Problems arise with the RSM and SPD commands. Should they refer to an entire link, or just to a given connection? Since there is a proposal to modify the RFNM to accommodate these commands, it might be better to add another set of commands to block and unblock a connection, but I am not convinced that that is the best solution.
  3. The destintation socket must be added to the header of each message on the data link. Presumably this would consist of 32 bits immediately after the header and before the marking.
  1. ENDとRDYでは、リンク番号に加えて、関係するソケットを指定しなければなりません。指定する必要があるのはローカルのソケット名だけです。
  2. RSMコマンドとSPDコマンドについては問題が生じます。これらはリンク全体を対象とすべきでしょうか、それとも特定のコネクションだけを対象とすべきでしょうか？これらのコマンドに対応するためにRFNMを変更するという提案があるので、コネクションをブロックしたりブロックを解除したりするコマンドを別に追加するほうがよいかもしれません。ただし、私はそれが最善の解決策だとは確信していません。
  3. データリンク上の各メッセージのヘッダーに、宛先ソケットを追加しなければなりません。おそらく、これはヘッダーの直後、マーキングの前に置く32ビットになるでしょう。
