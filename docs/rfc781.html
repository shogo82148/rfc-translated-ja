RFC 781

Specification of the Internet Protocol (IP) timestamp option

RFC 781

インターネットプロトコル（IP）のタイムスタンプオプションの仕様

I. INTRODUCTION

I. はじめに

Packet switching is store-and-forward by nature. Network delay is a therefore a critical performance measure for packet-switching communications. A catenet is a system of packet-switched communication networks interconnected via gateways [Cerf 78]. The catenet "link" delays are thus variable. Their measurement, the measurement of delays across member networks of a catenet, becomes important for catenet investigations.

パケット交換は、本質的に蓄積交換（store-and-forward）です。したがって、ネットワークの遅延は、パケット交換通信にとって重要な性能指標です。カテネット（catenet）とは、ゲートウェイを介して相互接続されたパケット交換通信網のシステムです[Cerf 78]。そのため、カテネットの「リンク」の遅延は変動します。その測定、つまりカテネットを構成する各ネットワークを越える遅延の測定は、カテネットの調査にとって重要になります。

An effective way to measure catenet delays is by means of packet header timestamping. Header timestamping allows monitoring of catenet delays for user traffic, such as the case of Ft. Bragg users accessing ISID across the catenet. Packet header timestamping is also compatible with the use of test packets for catenet delay measurement. Another advantage of header timestamping is that since it is an IP option, the gateway imposes little difference in the treatment of such a packet. In this note, a specification of the timestamp option format for IP is presented.

カテネットの遅延を測定する効果的な方法は、パケットヘッダーにタイムスタンプを付けることです。ヘッダーのタイムスタンプを使えば、Ft. Braggのユーザーがカテネット越しにISIDにアクセスする場合など、ユーザートラフィックのカテネット遅延を監視できます。パケットヘッダーのタイムスタンプは、カテネットの遅延測定にテストパケットを使うこととも両立します。ヘッダーのタイムスタンプのもう1つの利点は、IPオプションなので、ゲートウェイでのそのようなパケットの扱いにほとんど違いが生じないことです。このノートでは、IPのタイムスタンプオプションの形式の仕様を示します。

Measurement of one-way delay, either end-to-end or across an individual network, requires that device clocks be synchronized, using such facilities as WWVB clocks [Mills 81]. This specification assumes this capability in the gateways and involved network hosts.

エンドツーエンドであれ個々のネットワークを越えるものであれ、片方向の遅延を測定するには、WWVB時計[Mills 81]などの設備を使って装置の時計を同期させる必要があります。この仕様では、ゲートウェイと関係するネットワークホストにこの能力があることを前提とします。

II. FORMAT SPECIFICATION

II. 形式の仕様

As an IP option, the contents of the first two octets are dictated by the IP header format to be option type and option length in octets [Postel 80]. The next two octets are used to control this option.

IPオプションであるため、最初の2オクテットの内容は、IPヘッダーの形式によって、オプションタイプとオクテット単位のオプション長と決められています[Postel 80]。次の2オクテットは、このオプションの制御に使います。

     +---------------+---------------+---------------+---------------+
     |     type      |    length     |    offset     |overflw| flags |
     +---------------+---------------+---------------+---------------+
     |                          internet ID                          |
     +---------------+---------------+---------------+---------------+
     |                          time stamp                           |
     +---------------+---------------+---------------+---------------+

     |                          internet ID                          |
     +---------------+---------------+---------------+---------------+

                                     .

option type =
68 decimal (i.e., option class = 2 and option number = 4);
option length =
the number of octets with a maximum of 40 (limited by IHL = 15);
offset =
the number of octets from the beginning of this option to the end of timestamps (i.e., the beginning of space for next timestamp). It is set to one, an odd number, when no more space remains in the header for timestamps;
overflow =
the number of IP modules that cannot register timestamps due to lack of space;
flag =
0 --
time stamps only
1 --
each timestamp is preceded with internet ID of the registering entity
3 --
the internet ID fields are prespecified. An IP module only registers its timestamp if it matches its own ID with the next specified internet ID;
internet ID =
ID for the timestamping device;
timestamp =
a right-justified, 32-bit timestamp in milliseconds modulo 24 hours from midnight UT.
option type =
10進数で68（つまり、オプションクラス = 2、オプション番号 = 4）。
option length =
オクテット数。最大は40です（IHL = 15による制限）。
offset =
このオプションの先頭からタイムスタンプの末尾まで（つまり、次のタイムスタンプ用の領域の先頭まで）のオクテット数。ヘッダーにタイムスタンプ用の領域が残っていない場合は、奇数である1に設定します。
overflow =
領域不足のためにタイムスタンプを記録できなかったIPモジュールの数。
flag =
0 --
タイムスタンプのみ
1 --
各タイムスタンプの前に、記録したエンティティーのインターネットIDを置きます。
3 --
インターネットIDフィールドをあらかじめ指定しておきます。IPモジュールは、自身のIDが次に指定されたインターネットIDと一致する場合にのみ、タイムスタンプを記録します。
internet ID =
タイムスタンプを付ける装置のID。
timestamp =
右詰めの32ビットのタイムスタンプで、UTの午前0時からのミリ秒を24時間を法として表したもの。

The timestamp option is not copied upon fragmentation. It is carried in the first fragment.

タイムスタンプオプションは、フラグメント化の際にコピーされません。最初のフラグメントで運ばれます。
