RFC 230

Toward reliable operation of minicomputer-based terminals on a TIP

RFC 230

TIPに接続したミニコンピューターベースの端末の信頼性の高い運用に向けて

Abstract

概要

The present protocol for communication between a TIP and attached terminals requires character-oriented transmission and provides for no error control. In the design of this protocol, it was apparently assumed that the majority of terminals attached to a TIP would be interactive, be normally used in a character-by-character mode both for transmission to and from the terminal, and normally support a human user who would in effect be in the communication loop. The human user would thus be in a position to detect any significant telecommunication-induced errors both by direct observation of the character stream and, more importantly, by examining the computer output in the context of his ongoing interaction.

TIPと接続された端末との間の現在の通信プロトコルは、文字単位の伝送を必要とし、エラー制御を何も提供していません。このプロトコルの設計にあたっては、TIPに接続される端末の大半は対話型であり、通常は端末への伝送と端末からの伝送の両方で1文字ずつのモードで使われ、通常は実質的に通信ループの中にいる人間のユーザーを支援するものと想定されていたようです。そのため人間のユーザーは、文字の流れを直接観察することによって、そしてより重要なことには、進行中の対話の文脈でコンピューターの出力を調べることによって、通信によって生じた重大なエラーを検出できる立場にあることになります。

The effectiveness of this means for error detection and initiation of corrective measures when necessary is not adequate in the following cases:

エラーを検出し、必要に応じて修正措置を開始するためのこの手段の有効性は、次の場合には十分ではありません。

  1. For terminal-TIP communication at a medium or higher data rate (say 1200 bps or higher) it is quite possible that the human will skim computer output and not be an effective character-by-character error detector. In particular, when both user input and computer output contain numerical data it is possible that significant undetected errors could occur.
  2. For terminals located at a distance from the TIP and connected either by a private line or the switched network more errors may be introduced than with a terminal local to the TIP (see Note 1). When a large number of user terminals are connected to TIP's through telecommunications facilities, whether within a single organization or, even more likely, when users and user groups not needing the full TIP capability are connected to a remote TIP, this problem may arise.
  3. For terminals containing a substantial amount of logic, including possibly a minicomputer, a human user is very likely not in the direct terminal-TIP communications loop. This case is important, since both alphanumeric and full graphics terminals containing minis are now becoming popular.
  4. An interesting potential application of the network is to provide support for minicomputers used for process control and other laboratory measurement functions. In providing software support for such minis as well as acquiring data from them usually there is no human user in the communication loop.
  5. A number of sites already offer a remote job entry service. Although the present sites assume that the unit record devices such as card readers and line printers are files within a multiprogrammed system at another site, it appears natural that remote batch terminals be attached to the network through TIP's. Here again, there would be no human in the loop between the terminal and the TIP.
  1. 中速以上のデータレート（たとえば1200bps以上）での端末とTIPとの通信では、人間はコンピューターの出力を流し読みしてしまい、1文字ずつのエラー検出者として有効に働かない可能性が十分にあります。特に、ユーザーの入力とコンピューターの出力の両方に数値データが含まれる場合には、検出されない重大なエラーが起こる可能性があります。
  2. TIPから離れた場所にあり、専用線または交換網のどちらかで接続された端末では、TIPの近くにある端末よりも多くのエラーが入り込む可能性があります（注1を参照）。多数のユーザー端末が通信設備を通じてTIPに接続される場合、それが単一の組織内であっても、あるいはさらにありそうなこととして、TIPのすべての機能を必要としないユーザーやユーザーグループが遠隔のTIPに接続される場合にも、この問題が生じることがあります。
  3. 相当量の論理回路を備えた端末（ミニコンピューターを含むこともあります）では、人間のユーザーが端末とTIPとの直接の通信ループの中にいない可能性が非常に高いです。ミニコンピューターを内蔵した英数字端末とフルグラフィックス端末の両方が現在普及しつつあるため、この場合は重要です。
  4. ネットワークの興味深い応用の候補として、プロセス制御やその他の実験室での計測機能に使われるミニコンピューターの支援があります。そのようなミニコンピューターに対してソフトウェアの支援を提供する場合や、それらからデータを取得する場合、通常は通信ループの中に人間のユーザーはいません。
  5. いくつかのサイトはすでにリモートジョブエントリーのサービスを提供しています。現在のサイトはカードリーダーやラインプリンターなどのユニットレコード装置を、別のサイトにあるマルチプログラミングシステム内のファイルとみなしていますが、リモートバッチ端末をTIPを通じてネットワークに接続するのは自然なことのように思われます。この場合もやはり、端末とTIPとの間のループの中に人間はいません。

In addition to some degree of error control on these types of terminal loops, it may be desirable to provide for block-oriented data transmission, at least for terminals of types (d) and (e) and possibly (c) above. It is possible that error control utilizing block transmission can be superimposed on the present TIP-terminal communication protocol. Data blocks, including error control and block delimiting information, can be multiples of a single character in length. The communication channel would still not be as fully utilized as for conventional synchronous block communication, since start and stop bits for each character would need to be transmitted. This loss is not substantial and does occur now for 2000 bps TIP-terminal communication.

この種の端末ループである程度のエラー制御をすることに加えて、少なくとも上記の（d）と（e）の種類の端末、そしておそらくは（c）の種類の端末に対して、ブロック単位のデータ伝送を提供することが望ましいかもしれません。ブロック伝送を利用したエラー制御を、現在のTIPと端末との間の通信プロトコルの上に重ねることは可能です。エラー制御とブロックの区切りの情報を含むデータブロックは、1文字の長さの倍数にできます。各文字のスタートビットとストップビットを伝送する必要があるため、通信チャネルは従来の同期式のブロック通信ほど十分には活用されないでしょう。この損失は大きなものではなく、2000bpsのTIPと端末との間の通信では現在でも生じています。

There are at least two ways to implement such a protocol on top of the existing TIP-terminal communication protocol. In both cases, the remote terminal would have to handle both originate and receive error and block control procedures:

このようなプロトコルを既存のTIPと端末との間の通信プロトコルの上に実装する方法は、少なくとも2つあります。どちらの場合も、遠隔の端末は、エラー制御とブロック制御の手順の発信と受信の両方を扱わなければならないでしょう。

  1. Through an addition to TIP software, the controlled communication loop could terminate in the TIP, thus providing error control only where it is most needed, between the TIP and the terminal. This, however, would involve additional TIP software and a block buffering capability which may put an excessive load on the TIP.
  2. The other end of the block transmission error control loop could be in the serving host system, either in an applications program or in system support software.
  1. TIPのソフトウェアに追加を行うことで、制御された通信ループをTIPで終端させ、エラー制御が最も必要とされる場所、つまりTIPと端末との間でだけエラー制御を提供できます。しかしこれには、TIPのソフトウェアの追加と、ブロックをバッファリングする機能が必要であり、TIPに過大な負荷をかけるおそれがあります。
  2. ブロック伝送のエラー制御ループのもう一方の端を、サービスを提供するホストシステム内の、アプリケーションプログラムまたはシステム支援ソフトウェアのどちらかに置くことができます。

If the remote end of the block transmission error control loop is in the serving host, then this software could possibly be used for host-to-host, end-to-end error control in addition to host-host-terminal end-to-end error control. For host-to-host communication, however, there would be a slight loss in efficiency due to the imbedded character-oriented format, unless an option were provided in which start/stop bits were not required.

ブロック伝送のエラー制御ループの遠隔側の端がサービスを提供するホストにあれば、このソフトウェアは、ホスト・ホスト・端末間のエンドツーエンドのエラー制御に加えて、ホスト間のエンドツーエンドのエラー制御にも使える可能性があります。ただしホスト間の通信では、スタートビットとストップビットを必要としないオプションが用意されない限り、埋め込まれた文字単位の形式のために効率がわずかに低下するでしょう。

Note 1: The most recent published data concerning data transmission error performance of the switched telecommunications network is provided in the 1969-70 Connection Survey conducted by Bell Laboratories. The results are published in The Bell System Technical Journal, Vol. 4, No. 50, April 1971. In this survey, 12 receiving and 92 transmitting sites in the U.S. and Canada were used with standard Bell System Dataphone datasets used at both ends. At both 1200 and 2000 bps, approximately 82% of the calls had error rates of 1 error in 10^5 bits or better, assuming an equal number of short, medium, and long hauls.

注1: 交換通信網のデータ伝送のエラー性能に関する最新の公表データは、Bell Laboratoriesが実施した1969〜70年のConnection Surveyで提供されています。その結果はThe Bell System Technical Journal, Vol. 4, No. 50, April 1971で公表されています。この調査では、米国とカナダの受信12地点と送信92地点が使われ、両端で標準のBell System Dataphoneデータセットが使われました。短距離、中距離、長距離の回線が同数であると仮定すると、1200bpsと2000bpsのどちらでも、約82%の通話のエラー率は10^5ビットあたり1エラー以下でした。

The results of this survey for low-speed, start/stop data transmission at rates up to 300 bps indicate a character error rate of 1 error in 10^4 characters or better on 77.6% of all calls made within the survey. It is interesting to note that only 48.3% of the low-speed data tests completed were error-free. These tests were nominally 40 minutes in length.

最大300bpsの低速の調歩式データ伝送に関するこの調査の結果は、調査内で行われたすべての通話の77.6%で、文字エラー率が10^4文字あたり1エラー以下であったことを示しています。完了した低速のデータテストのうち、エラーがなかったのは48.3%にすぎなかったことは注目に値します。これらのテストは、名目上40分間の長さでした。

For voice grade private line data channels, the Bell System technical reference, "Transmission Specifications for Voice Grade Private Line Data Channels," dated March 1969 reports "When a Bell System dataset is combined with the recommended channel, the expected long term average error rate of the system is 1 error in 10^5 bits or better during normal transmission conditions. "

音声帯域の専用線データチャネルについては、1969年3月付けのBell Systemの技術資料「Transmission Specifications for Voice Grade Private Line Data Channels」が、「Bell Systemのデータセットを推奨のチャネルと組み合わせた場合、システムの期待される長期平均エラー率は、通常の伝送条件のもとで10^5ビットあたり1エラー以下である」と報告しています。
