NICNAME/WHOIS

RFC 812

NICNAME/WHOIS

INTRODUCTION

はじめに

The NICNAME/WHOIS Server is an NCP/TCP transaction based query/response server, running on the SRI-NIC machine, that provides netwide directory service to ARPANET users. It is one of a series of ARPANET/Internet name services maintained by the Network Information Center (NIC) at SRI International on behalf of the Defense Communications Agency (DCA). The server is accessible across the ARPANET from user programs running on local hosts, and it delivers the full name, U.S. mailing address, telephone number, and network mailbox for ARPANET users.

NICNAME/WHOISサーバーは、SRI-NICマシン上で動作するNCP/TCPのトランザクションベースの問い合わせ・応答サーバーで、ARPANETのユーザーにネットワーク全体のディレクトリーサービスを提供します。これは、国防通信庁（Defense Communications Agency、DCA）に代わってSRI InternationalのNetwork Information Center（NIC）が保守している一連のARPANET/インターネット名前サービスの1つです。このサーバーには、ローカルホスト上で動作するユーザープログラムからARPANETを介してアクセスでき、ARPANETユーザーのフルネーム、米国の郵送先住所、電話番号、ネットワークメールボックスを返します。

This server, together with the corresponding Identification Data Base provides online directory look-up equivalent to the ARPANET Directory. DCA strongly encourages network hosts to provide their users with access to this network service.

このサーバーは、対応する識別データベース（Identification Data Base）とあわせて、ARPANETディレクトリーに相当するオンラインのディレクトリー検索を提供します。DCAは、ネットワークのホストが自分のユーザーにこのネットワークサービスへのアクセスを提供することを強く推奨します。

WHO SHOULD BE IN THE DATA BASE

データベースに登録すべき人

DCA requests that each individual with a directory on an ARPANET host, who is capable of passing traffic across the ARPANET, be registered in the NIC Identification Data Base. To register, send full name, middle initial, U.S. mailing address (including mail stop and full explanation of abbreviations and acronyms), ZIP code, telephone (including Autovon and FTS, if available), and one network mailbox, via electronic mail to NIC@SRI-NIC.

DCAは、ARPANETホスト上にディレクトリーを持ち、ARPANETを介してトラフィックをやり取りできる個人それぞれが、NIC識別データベースに登録されることを求めます。登録するには、フルネーム、ミドルネームのイニシャル、米国の郵送先住所（メールストップと、略語や頭字語の完全な説明を含む）、郵便番号（ZIP code）、電話番号（利用できる場合はAutovonとFTSを含む）、1つのネットワークメールボックスを、電子メールでNIC@SRI-NICへ送ってください。

PROTOCOL

プロトコル

The NICNAME protocol is similar to the NAME/FINGER protocol (RFC 742). To access the server:

NICNAMEプロトコルは、NAME/FINGERプロトコル（RFC 742）に似ています。サーバーにアクセスするには、次のようにします。

Connect to the service host (SRI-NIC)

サービスホスト（SRI-NIC）に接続します。

TCP:
service port 43 decimal
NCP:
ICP to socket 43 decimal, establishing two 8-bit connections
TCP:
サービスポート10進数で43
NCP:
10進数で43のソケットへICPを行い、2本の8ビットコネクションを確立します。

Send a single "command line", ending with <CRLF>.

<CRLF>で終わる1つの「コマンドライン」を送信します。

Receive information in response to the command line. The server closes its connections as soon as the output is finished.

コマンドラインへの応答として情報を受信します。サーバーは出力が終わるとすぐにコネクションを閉じます。

EXISTING USER PROGRAMS

既存のユーザープログラム

NICNAME has been chosen as the global name for the user program, although some sites may choose to use the more familiar name of "WHOIS". There are versions of NICNAME for Tenex, Tops-20, and Unix. The Tenex and Tops-20 programs are written in assembly language (FAIL/MACRO), and the Unix version is written in C. They are easy to invoke, taking one argument which is passed directly to the NICNAME server at SRI-NIC. Normally it is best to use the NIC-supplied programs, if possible, since the protocol will continue to evolve. Contact NIC@SRI-NIC for copies.

ユーザープログラムの全体共通の名前としてNICNAMEが選ばれましたが、より馴染みのある「WHOIS」という名前を使うサイトもあるかもしれません。NICNAMEには、Tenex、Tops-20、Unix向けのバージョンがあります。TenexとTops-20のプログラムはアセンブリー言語（FAIL/MACRO）で書かれており、UnixのバージョンはCで書かれています。これらは簡単に起動でき、1つの引数を取って、それをSRI-NICのNICNAMEサーバーへそのまま渡します。プロトコルは今後も発展し続けるため、通常は可能であればNICが提供するプログラムを使うのが最善です。コピーはNIC@SRI-NICに問い合わせてください。

COMMAND LINES AND REPLIES

コマンドラインと応答

A command line is normally a single name specification. The easiest way to obtain the most recent documentation on name specifications is to give the server a command line consisting of "?<CRLF>" (that is, a question-mark alone as the name specification). The response from the NICNAME server will list all possible formats that can be used.

コマンドラインは、通常は1つの名前指定です。名前指定に関する最新のドキュメントを得るいちばん簡単な方法は、「?<CRLF>」からなるコマンドライン（つまり、名前指定として疑問符だけ）をサーバーに与えることです。NICNAMEサーバーからの応答には、使用できるすべての形式が一覧表示されます。

The responses are not currently intended to be machine-readable; the information is meant to be passed back directly to a human user. The following three examples will illustrate the use of NICNAME.

現在のところ、応答は機械可読であることを意図していません。情報は人間のユーザーにそのまま渡されることを想定しています。次の3つの例で、NICNAMEの使い方を示します。
