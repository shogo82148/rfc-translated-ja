RFC 534

Lost Message Detection

RFC 534

紛失メッセージの検出

Abstract

概要

As an aside to RFC 533, note that if sending Hosts do uniquely identify messages on a given link using the extra four bits and receiving Hosts do look at these bits, a lost message detection system such as those suggested in RFCs 512 and 516 drops right out of using of the unique message-id. These extra four bits can be treated as Hathaway's SCB of RFC 512 providing a 16 element sequence number on a per connection basis. A 16 element sequence is sufficient as the IMPs never allow more than four outstanding messages at one time between a given pair of Hosts. As Hathaway also suggests, the 0 element in the sequence can be used to indicate to the receiving Host that sequence numbers are not being used.

RFC 533の補足として、次の点に注意してください。送信側ホストが追加の4ビットを使ってあるリンク上のメッセージを一意に識別し、受信側ホストがこのビットを確認するのであれば、RFC 512と516で提案されたような紛失メッセージ検出の仕組みは、一意なメッセージID（message-id）を使うことから自然に得られます。この追加の4ビットは、RFC 512のHathawayのSCBとして扱うことができ、コネクションごとに16要素のシーケンス番号を提供します。IMPは、ある2つのホストの間で同時に4つを超える未完了のメッセージを決して許さないので、16要素のシーケンスで十分です。Hathawayも提案しているとおり、シーケンスの0の要素は、シーケンス番号を使用していないことを受信側ホストに示すために使用できます。

To summarize, there appear to be three modes of using the message-id number under Host/Host protocol:

まとめると、Host/Hostプロトコルのもとでのメッセージ番号（message-id number）の使い方には、3つのモードがあるようです。

  1. The sender can always set the extra four bits to 0 and only transmit one message over a given link at a time -- this is slow but it allows orderly retransmission of messages without any help from the receiver.
  2. The receiver can give no help to the sender. In this case it doesn't matter whether the sender uses the extra four bits to uniquely identify the messages or not -- the sender has no method of orderly retransmission, although the sender can accurately identify which message was lost if the sender has uniquely identified the messages.
  3. The sender can have multiple messages outstanding (i.e., RFNMs not received) on a given link and the receiver can help the sender. In this case, if the sender uses the extra four bits to uniquely identify the messages in a way which can be synchronized with the receiver (e.g., sequential id numbers), the receiver can reliably detect lost messages.
  1. 送信側は、追加の4ビットを常に0に設定し、あるリンク上で一度に1つのメッセージだけを送信できます。この方法は遅いですが、受信側の助けを一切借りずに、メッセージを順序どおりに再送できます。
  2. 受信側が送信側をまったく助けない場合です。この場合、送信側が追加の4ビットを使ってメッセージを一意に識別するかどうかは問題になりません。送信側には順序どおりに再送する方法がありません。ただし、送信側がメッセージを一意に識別していれば、どのメッセージが失われたかを正確に特定できます。
  3. 送信側は、あるリンク上で複数の未完了の（つまり、RFNMを受信していない）メッセージを持つことができ、受信側は送信側を助けることができます。この場合、送信側が受信側と同期できる方法（例: 連番のID）で追加の4ビットを使ってメッセージを一意に識別すれば、受信側は紛失メッセージを確実に検出できます。

Although it probably will seem insufficient to some, if the sender and receiver use synchronized unique message-id numbers, very reliable retransmission schemes are readily available. For instance, the sender can retransmit the appropriate messages in response to incomplete transmissions and the receiver can use the unique message-ids to sort the retransmitted messages into the proper order with the other received messages. Alternatively, the receiver can discard all messages received out of order and the sender can back up and retransmit a message for which an incomplete transmission was received and all subsequent messages.

不十分だと感じる人もいるでしょうが、送信側と受信側が同期した一意なメッセージ番号を使えば、非常に信頼性の高い再送の方式がすぐに実現できます。たとえば、送信側は不完全な送信（incomplete transmission）の通知に応じて適切なメッセージを再送し、受信側は一意なメッセージIDを使って、再送されたメッセージをほかの受信済みのメッセージとともに正しい順序に並べ替えることができます。あるいは、受信側は順序どおりに届かなかったメッセージをすべて破棄し、送信側は不完全な送信の通知を受けたメッセージまでさかのぼって、そのメッセージとそれ以降のすべてのメッセージを再送することもできます。
