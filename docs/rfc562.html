RFC 562

Modifications to the TELNET Specification

RFC 562

TELNET仕様の修正

Abstract

概要

Almost four months have passed since the new TELNET Protocol specification was published. Since then, only two RFCs have been issued suggesting modifications, and the most recent of these was distributed two months ago. Further, the date from the old TELNET to the new TELNET (1 January 1974) is only four months away. It therefore seems appropriate to officially modify the specification to account for the suggested modifications, and to declare a moratorium on the incorporation of additional suggestions until after the switchover. (Of course, no moratorium on the specification of additional options is required.)

新しいTELNETプロトコル仕様が公開されてから、まもなく4か月が経ちます。その後、修正を提案するRFCは2件しか発行されておらず、そのうち最新のものが配布されたのは2か月前です。さらに、古いTELNETから新しいTELNETへ移行する期日（1974年1月1日）まで、あと4か月しかありません。したがって、提案された修正を反映するよう仕様を正式に改訂し、移行が完了するまでは追加の提案の取り込みを凍結（モラトリアム）すると宣言するのが適切だと思われます。（もちろん、追加のオプションの仕様策定を凍結する必要はありません。）

The two attached documents represent the revised TELNET Protocol specifications; they replace NIC #15372, TELNET Protocol Specification, and NIC #15373, TELNET Option Specifications. The remainder of this RFC summarizes the changes. Page numbers refer to the earlier documents.

添付の2つの文書が、改訂されたTELNETプロトコル仕様です。これらは、NIC #15372「TELNET Protocol Specification」とNIC #15373「TELNET Option Specifications」を置き換えます。このRFCの残りの部分では、変更点を要約します。ページ番号は、以前の文書のものです。

Changes to TELNET Protocol Specification

TELNET Protocol Specificationの変更点

Page 8
The phrase "blocked on input" is removed (see RFC #513).
Page 9, 10
An additional use of IP is mentioned (see RFC #529).
Page 10
The explanation of AO is expanded (see RFC #513).
Page 11
The definition of "'print position' (e.g., an overstrike)" is clarified (see RFC #513).
Page 11, 12
The description of the TELNET Synch Signal is reworked to be in conformance with the ideas of RFC #529 (also see RFC #513).
Page 14
The explanation of the CR-NUL convention is expanded (see RFC #513).
Page 16
An additional command, End of Subnegotiation Parameters (SE) is defined (see RFCs 513, 529).
8ページ
「blocked on input」という語句を削除しました（RFC #513を参照）。
9、10ページ
IPの追加の用途について記述しました（RFC #529を参照）。
10ページ
AOの説明を拡充しました（RFC #513を参照）。
11ページ
「'print position' (e.g., an overstrike)」の定義を明確にしました（RFC #513を参照）。
11、12ページ
TELNETのSynch信号の説明を、RFC #529の考え方に沿うように書き直しました（RFC #513も参照）。
14ページ
CR-NULの慣例の説明を拡充しました（RFC #513を参照）。
16ページ
追加のコマンドとして、サブネゴシエーションパラメーターの終了（End of Subnegotiation Parameters、SE）を定義しました（RFC 513、529を参照）。

Changes to TELNET Option Specifications

TELNET Option Specificationsの変更点

Pages 2, 3
Use of the command SE is explained (see RFCs 513, 529).
Page 3
Doubling of IAC in subnegotiation parameters is required (see RFC #513).
2、3ページ
SEコマンドの使い方を説明しました（RFC 513、529を参照）。
3ページ
サブネゴシエーションパラメーター中のIACを二重にすることを必須にしました（RFC #513を参照）。
