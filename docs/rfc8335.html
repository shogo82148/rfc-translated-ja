RFC 8335

PROBE: A Utility for Probing Interfaces

RFC 8335

PROBE：インターフェイスをプローブするためのユーティリティー

Abstract

概要

This document describes a network diagnostic tool called PROBE. PROBE is similar to PING in that it can be used to query the status of a probed interface, but it differs from PING in that it does not require bidirectional connectivity between the probing and probed interfaces. Instead, PROBE requires bidirectional connectivity between the probing interface and a proxy interface. The proxy interface can reside on the same node as the probed interface, or it can reside on a node to which the probed interface is directly connected. This document updates RFC 4884.

この文書は、PROBEと呼ばれるネットワーク診断ツールについて記述します。 PROBEは、プローブ対象インターフェイスの状態を問い合わせるために使用できるという点でPINGに似ていますが、プロービングインターフェイスとプローブ対象インターフェイスの間の双方向の接続性を必要としないという点でPINGとは異なります。 代わりに、PROBEはプロービングインターフェイスとプロキシーインターフェイスの間の双方向の接続性を必要とします。 プロキシーインターフェイスは、プローブ対象インターフェイスと同じノード上に存在することも、プローブ対象インターフェイスが直接接続されているノード上に存在することもできます。 この文書はRFC 4884を更新します。

1. Introduction

1. はじめに

Network operators use PING [RFC2151] to test bidirectional connectivity between two interfaces. For the purposes of this document, these interfaces are called the probing and probed interfaces. PING sends an ICMP [RFC792] [RFC4443] Echo Request message from the probing interface to the probed interface. The probing interface resides on a probing node while the probed interface resides on a probed node.

ネットワーク運用者は、2つのインターフェイス間の双方向の接続性をテストするためにPING [RFC2151]を使用します。 この文書では、これらのインターフェイスをプロービングインターフェイス（probing interface）およびプローブ対象インターフェイス（probed interface）と呼びます。 PINGは、ICMP [RFC792] [RFC4443]のEcho Requestメッセージを、プロービングインターフェイスからプローブ対象インターフェイスへ送信します。 プロービングインターフェイスはプロービングノード上に存在し、プローブ対象インターフェイスはプローブ対象ノード上に存在します。

If the probed interface receives the ICMP Echo Request message, it returns an ICMP Echo Reply. When the probing interface receives the ICMP Echo Reply, it has verified bidirectional connectivity between the probing and probed interfaces. Specifically, it has verified that:

プローブ対象インターフェイスは、ICMP Echo Requestメッセージを受信すると、ICMP Echo Replyを返します。 プロービングインターフェイスがICMP Echo Replyを受信した時点で、プロービングインターフェイスとプローブ対象インターフェイスの間の双方向の接続性が検証されたことになります。 具体的には、次のことが検証されています：

  • The probing node can reach the probed interface.
  • The probed interface is active.
  • The probed node can reach the probing interface.
  • The probing interface is active.
  • プロービングノードがプローブ対象インターフェイスに到達できること。
  • プローブ対象インターフェイスがアクティブであること。
  • プローブ対象ノードがプロービングインターフェイスに到達できること。
  • プロービングインターフェイスがアクティブであること。

This document describes a network diagnostic tool called PROBE. PROBE is similar to PING in that it can be used to query the status of a probed interface, but it differs from PING in that it does not require bidirectional connectivity between the probing and probed interfaces. Instead, PROBE requires bidirectional connectivity between the probing interface and a proxy interface. The proxy interface can reside on the same node as the probed interface, or it can reside on a node to which the probed interface is directly connected. Section 5 of this document describes scenarios in which this characteristic is useful.

この文書は、PROBEと呼ばれるネットワーク診断ツールについて記述します。 PROBEは、プローブ対象インターフェイスの状態を問い合わせるために使用できるという点でPINGに似ていますが、プロービングインターフェイスとプローブ対象インターフェイスの間の双方向の接続性を必要としないという点でPINGとは異なります。 代わりに、PROBEはプロービングインターフェイスとプロキシーインターフェイスの間の双方向の接続性を必要とします。 プロキシーインターフェイスは、プローブ対象インターフェイスと同じノード上に存在することも、プローブ対象インターフェイスが直接接続されているノード上に存在することもできます。 この文書のセクション5では、この特性が役立つシナリオについて説明します。

Like PING, PROBE executes on a probing node. It sends an ICMP Extended Echo Request message from a local interface, called the probing interface, to a proxy interface. The proxy interface resides on a proxy node.

PINGと同様に、PROBEはプロービングノード上で実行されます。 PROBEは、プロービングインターフェイスと呼ばれるローカルインターフェイスから、プロキシーインターフェイスへICMP Extended Echo Requestメッセージを送信します。 プロキシーインターフェイスはプロキシーノード上に存在します。

The ICMP Extended Echo Request contains an ICMP Extension Structure and the ICMP Extension Structure contains an Interface Identification Object. The Interface Identification Object identifies the probed interface. The probed interface can reside on or directly connect to the proxy node.

ICMP Extended Echo RequestはICMP拡張構造（ICMP Extension Structure）を含み、ICMP拡張構造はインターフェイス識別オブジェクト（Interface Identification Object）を含みます。 インターフェイス識別オブジェクトは、プローブ対象インターフェイスを識別します。 プローブ対象インターフェイスは、プロキシーノード上に存在することも、プロキシーノードに直接接続されていることもあります。

When the proxy interface receives the ICMP Extended Echo Request, the proxy node executes access control procedures. If access is granted, the proxy node determines the status of the probed interface and returns an ICMP Extended Echo Reply message. The ICMP Extended Echo Reply indicates the status of the probed interface.

プロキシーインターフェイスがICMP Extended Echo Requestを受信すると、プロキシーノードはアクセス制御の手続きを実行します。 アクセスが許可された場合、プロキシーノードはプローブ対象インターフェイスの状態を判定し、ICMP Extended Echo Replyメッセージを返します。 ICMP Extended Echo Replyは、プローブ対象インターフェイスの状態を示します。

If the probed interface resides on the proxy node, PROBE determines the status of the probed interface as it would determine its oper-status [RFC7223]. If oper-status is equal to 'up' (1), PROBE reports that the probed interface is active. Otherwise, PROBE reports that the probed interface is inactive.

プローブ対象インターフェイスがプロキシーノード上に存在する場合、PROBEは、プローブ対象インターフェイスのoper-status [RFC7223]を判定するのと同じ方法で、その状態を判定します。 oper-statusが'up'（1）に等しい場合、PROBEはプローブ対象インターフェイスがアクティブだと報告します。 そうでない場合、PROBEはプローブ対象インターフェイスが非アクティブだと報告します。

If the probed interface resides on a node that is directly connected to the proxy node, and the probed interface appears in the IPv4 Address Resolution Protocol (ARP) table [RFC826] or IPv6 Neighbor Cache [RFC4861], PROBE reports interface reachability. Otherwise, PROBE reports that the table entry does not exist.

プローブ対象インターフェイスがプロキシーノードに直接接続されたノード上に存在し、かつプローブ対象インターフェイスがIPv4のアドレス解決プロトコル（ARP）テーブル[RFC826]またはIPv6の近隣キャッシュ（Neighbor Cache）[RFC4861]に現れる場合、PROBEはインターフェイスの到達可能性を報告します。 そうでない場合、PROBEはテーブルエントリーが存在しないことを報告します。

1.1. Terminology

1.1. 用語

This document uses the following terms:

この文書では、次の用語を使用します：

  • Probing interface: The interface that sends the ICMP Extended Echo Request.
  • Probing node: The node upon which the probing interface resides.
  • Proxy interface: The interface to which the ICMP Extended Echo Request message is sent.
  • Proxy node: The node upon which the proxy interface resides.
  • Probed interface: The interface whose status is being queried.
  • Probed node: The node upon which the probed interface resides. If the proxy interface and the probed interface reside upon the same node, the proxy node is also the probed node. Otherwise, the proxy node is directly connected to the probed node.
  • プロービングインターフェイス（Probing interface）：ICMP Extended Echo Requestを送信するインターフェイス。
  • プロービングノード（Probing node）：プロービングインターフェイスが存在するノード。
  • プロキシーインターフェイス（Proxy interface）：ICMP Extended Echo Requestメッセージの送信先となるインターフェイス。
  • プロキシーノード（Proxy node）：プロキシーインターフェイスが存在するノード。
  • プローブ対象インターフェイス（Probed interface）：状態を問い合わせられているインターフェイス。
  • プローブ対象ノード（Probed node）：プローブ対象インターフェイスが存在するノード。 プロキシーインターフェイスとプローブ対象インターフェイスが同じノード上に存在する場合、プロキシーノードはプローブ対象ノードでもあります。 そうでない場合、プロキシーノードはプローブ対象ノードに直接接続されています。

2. ICMP Extended Echo Request

2. ICMP Extended Echo Request

The ICMP Extended Echo Request message is defined for both ICMPv4 and ICMPv6. Like any ICMP message, the ICMP Extended Echo Request message is encapsulated in an IP header. The ICMPv4 version of the Extended Echo Request message is encapsulated in an IPv4 header, while the ICMPv6 version is encapsulated in an IPv6 header.

ICMP Extended Echo Requestメッセージは、ICMPv4とICMPv6の両方に対して定義されます。 他のICMPメッセージと同様に、ICMP Extended Echo RequestメッセージはIPヘッダーでカプセル化されます。 Extended Echo RequestメッセージのICMPv4版はIPv4ヘッダーでカプセル化され、ICMPv6版はIPv6ヘッダーでカプセル化されます。

Figure 1 depicts the ICMP Extended Echo Request message.

図1に、ICMP Extended Echo Requestメッセージを示します。

IP Header fields:

IPヘッダーのフィールド：

  • Source Address: The Source Address identifies the probing interface. It MUST be a valid IPv4 or IPv6 unicast address.
  • Destination Address: The Destination Address identifies the proxy interface. It MUST be a unicast address.
  • Source Address：Source Addressは、プロービングインターフェイスを識別します。 これは有効なIPv4またはIPv6のユニキャストアドレスでなければなりません（MUST）。
  • Destination Address：Destination Addressは、プロキシーインターフェイスを識別します。 これはユニキャストアドレスでなければなりません（MUST）。

ICMP fields:

ICMPのフィールド：

  • Type: Extended Echo Request. The value for ICMPv4 is 42. The value for ICMPv6 is 160.
  • Code: MUST be set to 0 and MUST be ignored upon receipt.
  • Checksum: For ICMPv4, see RFC 792. For ICMPv6, see RFC 4443.
  • Identifier: An Identifier to aid in matching Extended Echo Replies to Extended Echo Requests. May be 0.
  • Sequence Number: A Sequence Number to aid in matching Extended Echo Replies to Extended Echo Requests. May be 0.
  • Reserved: This field MUST be set to 0 and ignored upon receipt.
  • L (local): The L-bit is set if the probed interface resides on the proxy node. The L-bit is clear if the probed interface is directly connected to the proxy node.
  • ICMP Extension Structure: The ICMP Extension Structure identifies the probed interface.
  • Type：Extended Echo Request。 ICMPv4での値は42です。 ICMPv6での値は160です。
  • Code：0に設定しなければなりません（MUST）。 また、受信時には無視しなければなりません（MUST）。
  • Checksum：ICMPv4についてはRFC 792を参照してください。 ICMPv6についてはRFC 4443を参照してください。
  • Identifier：Extended Echo ReplyをExtended Echo Requestと対応付けるのを助けるための識別子。 0でもかまいません。
  • Sequence Number：Extended Echo ReplyをExtended Echo Requestと対応付けるのを助けるためのシーケンス番号。 0でもかまいません。
  • Reserved：このフィールドは0に設定し、受信時には無視しなければなりません（MUST）。
  • L（local）：プローブ対象インターフェイスがプロキシーノード上に存在する場合、Lビットはセットされます。 プローブ対象インターフェイスがプロキシーノードに直接接続されている場合、Lビットはクリアされます。
  • ICMP Extension Structure：ICMP拡張構造は、プローブ対象インターフェイスを識別します。

Section 7 of [RFC4884] defines the ICMP Extension Structure. As per RFC 4884, the Extension Structure contains exactly one Extension Header followed by one or more objects. When applied to the ICMP Extended Echo Request message, the ICMP Extension Structure MUST contain exactly one instance of the Interface Identification Object (see Section 2.1).

[RFC4884]のセクション7は、ICMP拡張構造を定義しています。 RFC 4884によると、拡張構造は、ちょうど1つの拡張ヘッダーと、それに続く1つ以上のオブジェクトを含みます。 ICMP Extended Echo Requestメッセージに適用する場合、ICMP拡張構造はインターフェイス識別オブジェクト（セクション2.1を参照）のインスタンスをちょうど1つ含まなければなりません（MUST）。

If the L-bit is set, the Interface Identification Object can identify the probed interface by name, index, or address. If the L-bit is clear, the Interface Identification Object MUST identify the probed interface by address.

Lビットがセットされている場合、インターフェイス識別オブジェクトは、プローブ対象インターフェイスを名前、インデックス、またはアドレスで識別できます。 Lビットがクリアされている場合、インターフェイス識別オブジェクトは、プローブ対象インターフェイスをアドレスで識別しなければなりません（MUST）。

If the Interface Identification Object identifies the probed interface by address, that address can be a member of any address family. For example, an ICMPv4 Extended Echo Request message can carry an Interface Identification Object that identifies the probed interface by IPv4, IPv6, or IEEE 802 address. Likewise, an ICMPv6 Extended Echo Request message can carry an Interface Identification Object that identifies the probed interface by IPv4, IPv6, or IEEE 802 address.

インターフェイス識別オブジェクトがプローブ対象インターフェイスをアドレスで識別する場合、そのアドレスはどのアドレスファミリーに属するものでもかまいません。 たとえば、ICMPv4のExtended Echo Requestメッセージは、IPv4、IPv6、またはIEEE 802のアドレスでプローブ対象インターフェイスを識別するインターフェイス識別オブジェクトを運ぶことができます。 同様に、ICMPv6のExtended Echo Requestメッセージも、IPv4、IPv6、またはIEEE 802のアドレスでプローブ対象インターフェイスを識別するインターフェイス識別オブジェクトを運ぶことができます。

2.1. Interface Identification Object

2.1. インターフェイス識別オブジェクト

The Interface Identification Object identifies the probed interface by name, index, or address. Like any other ICMP Extension Object, it contains an Object Header and Object Payload. The Object Header contains the following fields:

インターフェイス識別オブジェクトは、プローブ対象インターフェイスを名前、インデックス、またはアドレスで識別します。 他のICMP拡張オブジェクトと同様に、インターフェイス識別オブジェクトはオブジェクトヘッダーとオブジェクトペイロードを含みます。 オブジェクトヘッダーは、次のフィールドを含みます：

  • Class-Num: Interface Identification Object. The value is 3.
  • C-Type: Values are (1) Identifies Interface by Name, (2) Identifies Interface by Index, and (3) Identifies Interface by Address.
  • Length: Length of the object, measured in octets, including the Object Header and Object Payload.
  • Class-Num：インターフェイス識別オブジェクト。 値は3です。
  • C-Type：値は、（1）Identifies Interface by Name、（2）Identifies Interface by Index、（3）Identifies Interface by Addressです。
  • Length：オブジェクトの長さ。 オブジェクトヘッダーとオブジェクトペイロードを含めて、オクテット単位で測ります。

If the Interface Identification Object identifies the probed interface by name, the Object Payload MUST be the interface name as defined in [RFC7223]. If the Object Payload would not otherwise terminate on a 32-bit boundary, it MUST be padded with ASCII NULL characters.

インターフェイス識別オブジェクトがプローブ対象インターフェイスを名前で識別する場合、オブジェクトペイロードは[RFC7223]で定義されているインターフェイス名でなければなりません（MUST）。 オブジェクトペイロードがそのままでは32ビット境界で終わらない場合、ASCIIのNULL文字でパディングしなければなりません（MUST）。

If the Interface Identification Object identifies the probed interface by index, the length is equal to 8 and the payload contains the if-index [RFC7223].

インターフェイス識別オブジェクトがプローブ対象インターフェイスをインデックスで識別する場合、長さは8に等しく、ペイロードにはif-index [RFC7223]が含まれます。

If the Interface Identification Object identifies the probed interface by address, the payload is as depicted in Figure 2.

インターフェイス識別オブジェクトがプローブ対象インターフェイスをアドレスで識別する場合、ペイロードは図2に示すとおりです。

Payload fields are defined as follows:

ペイロードのフィールドは、次のように定義されます：

  • Address Family Identifier (AFI): This 16-bit field identifies the type of address represented by the Address field. All values found in the IANA registry of Address Family Numbers (available from <https://www.iana.org/assignments/address-family-numbers>) are valid in this field.
  • Address Length: Number of significant bytes contained by the Address field. (The Address field contains significant bytes and padding bytes.)
  • Reserved: This field MUST be set to 0 and ignored upon receipt.
  • Address: This variable-length field represents an address associated with the probed interface. If the address field would not otherwise terminate on a 32-bit boundary, it MUST be padded with zeroes.
  • Address Family Identifier（AFI）：この16ビットのフィールドは、Addressフィールドが表すアドレスの種類を識別します。 IANAのAddress Family Numbersレジストリー（<https://www.iana.org/assignments/address-family-numbers>から入手できます）にあるすべての値が、このフィールドで有効です。
  • Address Length：Addressフィールドに含まれる有効なバイトの数。 （Addressフィールドは、有効なバイトとパディングのバイトを含みます。）
  • Reserved：このフィールドは0に設定し、受信時には無視しなければなりません（MUST）。
  • Address：この可変長のフィールドは、プローブ対象インターフェイスに関連付けられたアドレスを表します。 Addressフィールドがそのままでは32ビット境界で終わらない場合、ゼロでパディングしなければなりません（MUST）。

3. ICMP Extended Echo Reply

3. ICMP Extended Echo Reply

The ICMP Extended Echo Reply message is defined for both ICMPv4 and ICMPv6. Like any ICMP message, the ICMP Extended Echo Reply message is encapsulated in an IP header. The ICMPv4 version of the Extended Echo Reply message is encapsulated in an IPv4 header, while the ICMPv6 version is encapsulated in an IPv6 header.

ICMP Extended Echo Replyメッセージは、ICMPv4とICMPv6の両方に対して定義されます。 他のICMPメッセージと同様に、ICMP Extended Echo ReplyメッセージはIPヘッダーでカプセル化されます。 Extended Echo ReplyメッセージのICMPv4版はIPv4ヘッダーでカプセル化され、ICMPv6版はIPv6ヘッダーでカプセル化されます。

Figure 3 depicts the ICMP Extended Echo Reply message.

図3に、ICMP Extended Echo Replyメッセージを示します。

IP Header fields:

IPヘッダーのフィールド：

  • Source Address: Copied from the Destination Address field of the invoking Extended Echo Request message.
  • Destination Address: Copied from the Source Address field of the invoking Extended Echo Request message.
  • Source Address：応答のもととなったExtended Echo RequestメッセージのDestination Addressフィールドからコピーされます。
  • Destination Address：応答のもととなったExtended Echo RequestメッセージのSource Addressフィールドからコピーされます。

ICMP fields:

ICMPのフィールド：

  • Type: Extended Echo Reply. The value for ICMPv4 is 43. The value for ICMPv6 is 161.
  • Code: Values are (0) No Error, (1) Malformed Query, (2) No Such Interface, (3) No Such Table Entry, and (4) Multiple Interfaces Satisfy Query.
  • Checksum: For ICMPv4, see RFC 792. For ICMPv6, see RFC 4443.
  • Identifier: Copied from the Identifier field of the invoking Extended Echo Request packet.
  • Sequence Number: Copied from the Sequence Number field of the invoking Extended Echo Request packet.
  • State: If Code is not equal to 0, this field MUST be set to 0 and ignored upon receipt. Likewise, if the probed interface resides upon the proxy node, this field MUST be set to 0 and ignored upon receipt. Otherwise, this field reflects the state of the ARP table or Neighbor Cache entry associated with the probed interface. Values are (0) Reserved, (1) Incomplete, (2) Reachable, (3) Stale, (4) Delay, (5) Probe, and (6) Failed.
  • Res: This field MUST be set to 0 and ignored upon receipt.
  • A (Active): The A-bit is set if the Code is equal to 0, the probed interface resides on the proxy node, and the probed interface is active. Otherwise, the A-bit is clear.
  • 4 (IPv4): The 4-bit is set if the A-bit is also set and IPv4 is running on the probed interface. Otherwise, the 4-bit is clear.
  • 6 (IPv6): The 6-bit is set if the A-bit is also set and IPv6 is running on the probed interface. Otherwise, the 6-bit is clear.
  • Type：Extended Echo Reply。 ICMPv4での値は43です。 ICMPv6での値は161です。
  • Code：値は、（0）No Error、（1）Malformed Query、（2）No Such Interface、（3）No Such Table Entry、（4）Multiple Interfaces Satisfy Queryです。
  • Checksum：ICMPv4についてはRFC 792を参照してください。 ICMPv6についてはRFC 4443を参照してください。
  • Identifier：応答のもととなったExtended Echo RequestパケットのIdentifierフィールドからコピーされます。
  • Sequence Number：応答のもととなったExtended Echo RequestパケットのSequence Numberフィールドからコピーされます。
  • State：Codeが0に等しくない場合、このフィールドは0に設定し、受信時には無視しなければなりません（MUST）。 同様に、プローブ対象インターフェイスがプロキシーノード上に存在する場合も、このフィールドは0に設定し、受信時には無視しなければなりません（MUST）。 それ以外の場合、このフィールドは、プローブ対象インターフェイスに関連付けられたARPテーブルまたは近隣キャッシュのエントリーの状態を反映します。 値は、（0）Reserved、（1）Incomplete、（2）Reachable、（3）Stale、（4）Delay、（5）Probe、（6）Failedです。
  • Res：このフィールドは0に設定し、受信時には無視しなければなりません（MUST）。
  • A（Active）：Codeが0に等しく、プローブ対象インターフェイスがプロキシーノード上に存在し、かつプローブ対象インターフェイスがアクティブな場合、Aビットはセットされます。 そうでない場合、Aビットはクリアされます。
  • 4（IPv4）：Aビットもセットされていて、かつプローブ対象インターフェイス上でIPv4が動作している場合、「4」ビットはセットされます。 そうでない場合、「4」ビットはクリアされます。
  • 6（IPv6）：Aビットもセットされていて、かつプローブ対象インターフェイス上でIPv6が動作している場合、「6」ビットはセットされます。 そうでない場合、「6」ビットはクリアされます。

4. ICMP Message Processing

4. ICMPメッセージの処理

When a node receives an ICMP Extended Echo Request message and any of the following conditions apply, the node MUST silently discard the incoming message:

ノードがICMP Extended Echo Requestメッセージを受信し、次の条件のいずれかに該当する場合、ノードは受信したメッセージを黙って破棄しなければなりません（MUST）：

  • The node does not recognize ICMP Extended Echo Request messages.
  • The node has not explicitly enabled ICMP Extended Echo functionality.
  • The incoming ICMP Extend Echo Request carries a Source Address that is not explicitly authorized for the L-bit setting of the incoming ICMP Extended Echo Request.
  • The incoming ICMP Extend Echo Request carries a Source Address that is not explicitly authorized for the incoming ICMP Extended Echo Request type (i.e., by ifName, by IfIndex, or by Address).
  • The Source Address of the incoming message is not a unicast address.
  • The Destination Address of the incoming message is a multicast address.
  • ノードがICMP Extended Echo Requestメッセージを認識しません。
  • ノードがICMP Extended Echo機能を明示的に有効にしていません。
  • 受信したICMP Extended Echo Requestが、受信したICMP Extended Echo RequestのLビットの設定について明示的に許可されていないSource Addressを持っています。
  • 受信したICMP Extended Echo Requestが、受信したICMP Extended Echo Requestの種類（つまり、ifNameによるもの、IfIndexによるもの、またはAddressによるもの）について明示的に許可されていないSource Addressを持っています。
  • 受信したメッセージのSource Addressがユニキャストアドレスではありません。
  • 受信したメッセージのDestination Addressがマルチキャストアドレスになっています。

Otherwise, when a node receives an ICMPv4 Extended Echo Request, it MUST format an ICMP Extended Echo Reply as follows:

それ以外の場合、ノードはICMPv4のExtended Echo Requestを受信したとき、ICMP Extended Echo Replyを次のように構成しなければなりません（MUST）：

  • Don't Fragment (DF) flag is 1
  • More Fragments flag is 0
  • Fragment Offset is 0
  • TTL is 255
  • Protocol is ICMP
  • Don't Fragment（DF）フラグは1
  • More Fragmentsフラグは0
  • Fragment Offsetは0
  • TTLは255
  • ProtocolはICMP

When a node receives an ICMPv6 Extended Echo Request, it MUST format an ICMPv6 Extended Echo Reply as follows:

ノードはICMPv6のExtended Echo Requestを受信したとき、ICMPv6 Extended Echo Replyを次のように構成しなければなりません（MUST）：

  • Hop Limit is 255
  • Next Header is ICMPv6
  • Hop Limitは255
  • Next HeaderはICMPv6

In either case, the responding node MUST do the following:

いずれの場合も、応答するノードは次のことをしなければなりません（MUST）：

  • Copy the Source Address from the Extended Echo Request message to the Destination Address of the Extended Echo Reply.
  • Copy the Destination Address from the Extended Echo Request message to the Source Address of the Extended Echo Reply.
  • Set the DiffServ codepoint to CS0 [RFC4594].
  • Set the ICMP Type to Extended Echo Reply.
  • Copy the Identifier from the Extended Echo Request message to the Extended Echo Reply.
  • Copy the Sequence Number from the Extended Echo Request message to the Extended Echo Reply.
  • Set the Code field as described in Section 4.1.
  • Set the State field to 0.
  • Clear the A-bit, the 4-bit, and the 6-bit.
  • If (1) the Code Field is equal to (0) No Error, (2) the L-bit is set, and (3) the probed interface is active, set the A-bit. Also, set the 4-bit and the 6-bit as appropriate.
  • If the Code field is equal to (0) No Error and the L-bit is clear, then set the State field to reflect the state of the ARP table or Neighbor Cache entry that represents the probed interface.
  • Set the Checksum appropriately.
  • Forward the ICMP Extended Echo Reply to its destination.
  • Extended Echo RequestメッセージのSource Addressを、Extended Echo ReplyのDestination Addressにコピーします。
  • Extended Echo RequestメッセージのDestination Addressを、Extended Echo ReplyのSource Addressにコピーします。
  • DiffServコードポイントをCS0 [RFC4594]に設定します。
  • ICMP TypeをExtended Echo Replyに設定します。
  • Extended Echo RequestメッセージのIdentifierを、Extended Echo Replyにコピーします。
  • Extended Echo RequestメッセージのSequence Numberを、Extended Echo Replyにコピーします。
  • セクション4.1で説明するとおりにCodeフィールドを設定します。
  • Stateフィールドを0に設定します。
  • Aビット、「4」ビット、「6」ビットをクリアします。
  • （1）Codeフィールドが（0）No Errorに等しく、（2）Lビットがセットされていて、かつ（3）プローブ対象インターフェイスがアクティブな場合、Aビットをセットします。 また、「4」ビットと「6」ビットを適切にセットします。
  • Codeフィールドが（0）No Errorに等しく、かつLビットがクリアされている場合、プローブ対象インターフェイスを表すARPテーブルまたは近隣キャッシュのエントリーの状態を反映するように、Stateフィールドを設定します。
  • Checksumを適切に設定します。
  • ICMP Extended Echo Replyを宛先へ転送します。

4.1. Code Field Processing

4.1. Codeフィールドの処理

The Code field MUST be set to (1) Malformed Query if any of the following conditions apply:

次の条件のいずれかに該当する場合、Codeフィールドは（1）Malformed Queryに設定しなければなりません（MUST）：

  • The ICMP Extended Echo Request does not include an ICMP Extension Structure.
  • The ICMP Extension Structure does not include exactly one Interface Identification Object.
  • The L-bit is clear and the Interface Identification Object identifies the probed interface by ifName or ifIndex.
  • The query is otherwise malformed.
  • ICMP Extended Echo RequestがICMP拡張構造を含んでいません。
  • ICMP拡張構造に含まれるインターフェイス識別オブジェクトが、ちょうど1つではありません。
  • Lビットがクリアされていて、かつインターフェイス識別オブジェクトがプローブ対象インターフェイスをifNameまたはifIndexで識別しています。
  • クエリーがその他の点で不正な形式になっています。

The Code field MUST be set to (2) No Such Interface if the L-bit is set and the ICMP Extension Structure does not identify an interface that resides on the proxy node.

Lビットがセットされていて、かつICMP拡張構造がプロキシーノード上に存在するインターフェイスを識別しない場合、Codeフィールドは（2）No Such Interfaceに設定しなければなりません（MUST）。

The Code field MUST be set to (3) No Such Table Entry if the L-bit is clear and the address found in the Interface Identification Object does not appear in the IPv4 Address Resolution Protocol (ARP) table or the IPv6 Neighbor Cache.

Lビットがクリアされていて、かつインターフェイス識別オブジェクト内のアドレスがIPv4のアドレス解決プロトコル（ARP）テーブルにもIPv6の近隣キャッシュにも現れない場合、Codeフィールドは（3）No Such Table Entryに設定しなければなりません（MUST）。

The Code field MUST be set to (4) Multiple Interfaces Satisfy Query if any of the following conditions apply:

次の条件のいずれかに該当する場合、Codeフィールドは（4）Multiple Interfaces Satisfy Queryに設定しなければなりません（MUST）：

  • The L-bit is set and the ICMP Extension Structure identifies more than one interface that resides in the proxy node.
  • The L-bit is clear and the address found in the Interface Identification Object maps to multiple IPv4 ARP or IPv6 Neighbor Cache entries.
  • Lビットがセットされていて、かつICMP拡張構造が、プロキシーノード内に存在する2つ以上のインターフェイスを識別しています。
  • Lビットがクリアされていて、かつインターフェイス識別オブジェクト内のアドレスが、複数のIPv4 ARPエントリーまたはIPv6近隣キャッシュエントリーに対応しています。

Otherwise, the Code field MUST be set to (0) No Error.

それ以外の場合、Codeフィールドは（0）No Errorに設定しなければなりません（MUST）。

5. Use Cases

5. ユースケース

In the scenarios listed below, network operators can use PROBE to determine the status of a probed interface but cannot use PING for the same purpose. In all scenarios, assume bidirectional connectivity between the probing and proxy interfaces. However, bidirectional connectivity between the probing and probed interfaces is lacking.

以下に挙げるシナリオでは、ネットワーク運用者は、プローブ対象インターフェイスの状態を判定するためにPROBEを使用できますが、同じ目的でPINGを使用することはできません。 すべてのシナリオで、プロービングインターフェイスとプロキシーインターフェイスの間には双方向の接続性があるものとします。 しかし、プロービングインターフェイスとプローブ対象インターフェイスの間には双方向の接続性がありません。

  • The probed interface is unnumbered.
  • The probing and probed interfaces are not directly connected to one another. The probed interface has an IPv6 link-local address but does not have a more globally scoped address.
  • The probing interface runs IPv4 only while the probed interface runs IPv6 only.
  • The probing interface runs IPv6 only while the probed interface runs IPv4 only.
  • For lack of a route, the probing node cannot reach the probed interface.
  • プローブ対象インターフェイスがアンナンバード（unnumbered）です。
  • プロービングインターフェイスとプローブ対象インターフェイスが、互いに直接接続されていません。 プローブ対象インターフェイスは、IPv6リンクローカルアドレスを持っていますが、よりグローバルなスコープのアドレスを持っていません。
  • プロービングインターフェイスはIPv4のみで動作し、プローブ対象インターフェイスはIPv6のみで動作しています。
  • プロービングインターフェイスはIPv6のみで動作し、プローブ対象インターフェイスはIPv4のみで動作しています。
  • 経路がないため、プロービングノードがプローブ対象インターフェイスに到達できません。

6. RFC 4884の更新

Section 4.6 of [RFC4884] provides a list of extensible ICMP messages (i.e., messages that can carry the ICMP Extension Structure). This document adds the ICMP Extended Echo Request message and the ICMP Extended Echo Reply message to that list.

[RFC4884]のセクション4.6は、拡張可能なICMPメッセージ（つまり、ICMP拡張構造を運ぶことができるメッセージ）の一覧を提供しています。 この文書は、ICMP Extended Echo RequestメッセージとICMP Extended Echo Replyメッセージをその一覧に追加します。

8. Security Considerations

8. セキュリティーに関する考慮事項

The following are legitimate uses of PROBE:

PROBEの正当な用途は次のとおりです：

  • to determine the operational status of an interface.
  • to determine which protocols (e.g., IPv4 or IPv6) are active on an interface.
  • インターフェイスの運用状態を判定すること。
  • インターフェイス上でどのプロトコル（たとえば、IPv4やIPv6）がアクティブかを判定すること。

However, malicious parties can use PROBE to obtain additional information. For example, a malicious party can use PROBE to discover interface names. Having discovered an interface name, the malicious party may be able to infer additional information. Additional information may include:

しかし、悪意のある者が、PROBEを使用して追加の情報を得るおそれがあります。 たとえば、悪意のある者は、PROBEを使用してインターフェイス名を発見できます。 インターフェイス名を発見した悪意のある者は、追加の情報を推測できる可能性があります。 追加の情報には、次のものが含まれる可能性があります：

  • interface bandwidth
  • the type of device that supports the interface (e.g., vendor identity)
  • the operating system version that the above-mentioned device executes
  • インターフェイスの帯域幅
  • インターフェイスをサポートするデバイスの種類（たとえば、ベンダーの識別情報）
  • 前述のデバイスが実行しているオペレーティングシステムのバージョン

Understanding this risk, network operators establish policies that restrict access to ICMP Extended Echo functionality. In order to enforce these policies, nodes that support ICMP Extended Echo functionality MUST support the following configuration options:

このリスクを理解したうえで、ネットワーク運用者は、ICMP Extended Echo機能へのアクセスを制限するポリシーを定めます。 これらのポリシーを実施するため、ICMP Extended Echo機能をサポートするノードは、次の設定オプションをサポートしなければなりません（MUST）：

  • Enable/disable ICMP Extended Echo functionality. By default, ICMP Extend Echo functionality is disabled.
  • Define enabled L-bit settings. By default, the option to set the L-bit is enabled and the option to clear the L-bit is disabled.
  • Define enabled query types (i.e., by name, by index, or by address); by default, all query types are disabled.
  • For each enabled query type, define the prefixes from which ICMP Extended Echo Request messages are permitted.
  • For each interface, determine whether ICMP Echo Request messages are accepted.
  • ICMP Extended Echo機能の有効化／無効化。 デフォルトでは、ICMP Extended Echo機能は無効です。
  • 有効にするLビットの設定の定義。 デフォルトでは、Lビットをセットするオプションは有効で、Lビットをクリアするオプションは無効です。
  • 有効にするクエリーの種類（つまり、名前によるもの、インデックスによるもの、アドレスによるもの）の定義。 デフォルトでは、すべてのクエリーの種類が無効です。
  • 有効な各クエリーの種類について、ICMP Extended Echo Requestメッセージを許可する送信元のプレフィックスの定義。
  • 各インターフェイスについて、ICMP Echo Requestメッセージを受け付けるかどうかの決定。

When a node receives an ICMP Extended Echo Request message that it is not configured to support, it MUST silently discard the message. See Section 4 for details.

ノードは、サポートするように設定されていないICMP Extended Echo Requestメッセージを受信した場合、そのメッセージを黙って破棄しなければなりません（MUST）。 詳細はセクション4を参照してください。

PROBE must not leak information about one Virtual Private Network (VPN) into another. Therefore, when a node receives an ICMP Extended Echo Request and the proxy interface is in a different VPN than the probed interface, the node MUST return an ICMP Extended Echo Reply with error code equal to (2) No Such Interface.

PROBEは、ある仮想プライベートネットワーク（VPN）に関する情報を別のVPNに漏洩させてはいけません。 したがって、ノードがICMP Extended Echo Requestを受信し、プロキシーインターフェイスがプローブ対象インターフェイスとは異なるVPNに属している場合、ノードはエラーコードが（2）No Such InterfaceであるICMP Extended Echo Replyを返さなければなりません（MUST）。

In order to protect local resources, implementations SHOULD rate-limit incoming ICMP Extended Echo Request messages.

ローカルリソースを保護するため、実装は、受信するICMP Extended Echo Requestメッセージをレート制限すべきです（SHOULD）。

Appendix A. The PROBE Application

付録A. PROBEアプリケーション

The PROBE application accepts input parameters, sets a counter, and enters a loop to be exited when the counter is equal to 0. On each iteration of the loop, PROBE emits an ICMP Extended Echo Request, decrements the counter, sets a timer, and waits. The ICMP Extended Echo Request includes an Identifier and a Sequence Number.

PROBEアプリケーションは、入力パラメーターを受け取り、カウンターを設定し、カウンターが0に等しくなったときに抜けるループに入ります。 ループの各反復で、PROBEはICMP Extended Echo Requestを送出し、カウンターをデクリメントし、タイマーを設定して待機します。 ICMP Extended Echo Requestは、IdentifierとSequence Numberを含みます。

If an ICMP Extended Echo Reply carrying the same Identifier and Sequence Number arrives, PROBE relays information returned by that message to its user. However, on each iteration of the loop, PROBE waits for the timer to expire regardless of whether an Extended Echo Reply message arrives.

同じIdentifierとSequence Numberを持つICMP Extended Echo Replyが到着した場合、PROBEは、そのメッセージによって返された情報をユーザーに中継します。 ただし、ループの各反復において、PROBEは、Extended Echo Replyメッセージが到着したかどうかにかかわらず、タイマーが期限切れになるまで待機します。

PROBE accepts the following parameters:

PROBEは、次のパラメーターを受け付けます：

  • Count
  • Wait
  • Probing Interface Address
  • Hop Count
  • Proxy Interface Address
  • Local
  • Probed Interface Identifier
  • Count
  • Wait
  • Probing Interface Address
  • Hop Count
  • Proxy Interface Address
  • Local
  • Probed Interface Identifier

Count is a positive integer whose default value is 3. Count determines the number of times that PROBE iterates through the above-mentioned loop.

Countは正の整数で、デフォルト値は3です。 Countは、PROBEが前述のループを反復する回数を決定します。

Wait is a positive integer whose minimum and default values are 1. Wait determines the duration of the above-mentioned timer, measured in seconds.

Waitは正の整数で、最小値とデフォルト値は1です。 Waitは、前述のタイマーの長さを秒単位で決定します。

Probing Interface Address specifies the Source Address of the ICMP Extended Echo Request. The Probing Interface Address MUST be a unicast address and MUST identify an interface that resides on the probing node.

Probing Interface Addressは、ICMP Extended Echo RequestのSource Addressを指定します。 Probing Interface Addressは、ユニキャストアドレスでなければなりません（MUST）。 また、プロービングノード上に存在するインターフェイスを識別しなければなりません（MUST）。

The Proxy Interface Address identifies the interface to which the ICMP Extended Echo Request message is sent. It must be an IPv4 or IPv6 unicast address. If it is an IPv4 address, PROBE emits an ICMPv4 message. If it is an IPv6 address, PROBE emits an ICMPv6 message.

Proxy Interface Addressは、ICMP Extended Echo Requestメッセージの送信先となるインターフェイスを識別します。 これは、IPv4またはIPv6のユニキャストアドレスである必要があります。 IPv4アドレスの場合、PROBEはICMPv4メッセージを送出します。 IPv6アドレスの場合、PROBEはICMPv6メッセージを送出します。

Local is a boolean value. It is TRUE if the proxy and probed interfaces both reside on the same node. Otherwise, it is FALSE.

Localは真偽値です。 プロキシーインターフェイスとプローブ対象インターフェイスが両方とも同じノード上に存在する場合、TRUEになります。 そうでない場合、FALSEになります。

The Probed Interface Identifier identifies the probed interface. It is one of the following:

Probed Interface Identifierは、プローブ対象インターフェイスを識別します。 これは、次のいずれかです：

  • an interface name;
  • an address from any address family (e.g., IPv4, IPv6, IEEE 802, 48-bit MAC, or 64-bit MAC); or
  • an if-index.
  • インターフェイス名
  • 任意のアドレスファミリーのアドレス（たとえば、IPv4、IPv6、IEEE 802、48ビットMAC、または64ビットMAC）
  • if-index

If the Probed Interface Identifier is an address, it does not need to be of the same address family as the proxy interface address. For example, PROBE accepts an IPv4 Proxy Interface Address and an IPv6 Probed Interface Identifier.

Probed Interface Identifierがアドレスの場合、そのアドレスは、プロキシーインターフェイスのアドレスと同じアドレスファミリーのものである必要はありません。 たとえば、PROBEは、IPv4のProxy Interface AddressとIPv6のProbed Interface Identifierの組み合わせを受け付けます。
