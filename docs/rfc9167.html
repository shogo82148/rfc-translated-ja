Registry Maintenance Notification for the Extensible Provisioning Protocol (EPP)

RFC 9167

拡張可能プロビジョニングプロトコル（EPP）のためのレジストリーメンテナンス通知

Abstract

概要

This document describes an Extensible Provisioning Protocol (EPP) extension called "Registry Maintenance Notification", which is used by EPP servers to notify EPP clients and allow EPP clients to query EPP servers regarding maintenance events.

この文書は、「レジストリーメンテナンス通知（Registry Maintenance Notification）」と呼ばれる拡張可能プロビジョニングプロトコル（Extensible Provisioning Protocol: EPP）の拡張について説明します。 この拡張は、EPPサーバーがメンテナンスイベントについてEPPクライアントに通知し、EPPクライアントがメンテナンスイベントについてEPPサーバーに問い合わせられるようにするために使用されます。

1. Introduction

1. はじめに

The Extensible Provisioning Protocol (EPP), as defined in [RFC5730], is a protocol whose original motivation is to provide a standard Internet domain name registration protocol for use between registries and registrars.

[RFC5730]で定義されている拡張可能プロビジョニングプロトコル（Extensible Provisioning Protocol: EPP）は、もともとレジストリーとレジストラーの間で使用する標準的なインターネットドメイン名登録プロトコルを提供することを動機としたプロトコルです。

Registries routinely update systems to ensure a higher quality of service, implement new services, or upgrade protocols to the latest standards. These updates are pushed to various registry environments during time frames communicated to registrars as "maintenance events". Maintenance events may require making services unavailable for some limited time while the upgrade happens. Registries usually inform registrars about maintenance events in various formats, none of which are standardized between registries.

レジストリーは、より高いサービス品質を確保するため、新しいサービスを実装するため、またはプロトコルを最新の標準にアップグレードするために、定期的にシステムを更新します。 これらの更新は、「メンテナンスイベント（maintenance event）」としてレジストラーに通知された時間枠の間に、さまざまなレジストリー環境に適用されます。 メンテナンスイベントでは、アップグレードが行われている間、限られた時間だけサービスを利用できなくする必要がある場合があります。 レジストリーは通常、さまざまな形式でメンテナンスイベントについてレジストラーに知らせていますが、そのいずれもレジストリー間で標準化されていません。

The DNS namespace expansion has led to many additional registries that registrars must interact with, adding more maintenance events and formats. It is now desirable to provide an efficient approach to notify registrars.

DNS名前空間の拡大により、レジストラーがやり取りしなければならないレジストリーが大幅に増え、メンテナンスイベントとその形式も増えました。 そのため現在では、レジストラーに通知するための効率的な方法を提供することが望まれています。

This document describes an extension mapping for version 1.0 of the EPP to provide a mechanism by which EPP servers may notify EPP clients of and allow EPP clients to query EPP servers on upcoming maintenance events.

この文書は、EPPのバージョン1.0に対する拡張マッピングについて説明します。 この拡張マッピングは、EPPサーバーが今後のメンテナンスイベントについてEPPクライアントに通知でき、EPPクライアントがそれについてEPPサーバーに問い合わせられるようにするメカニズムを提供します。

XML [W3C.REC-xml-20081126] is case sensitive. Unless stated otherwise, XML specifications and examples provided in this document MUST be interpreted in the character case presented in order to develop a conforming implementation.

XML [W3C.REC-xml-20081126]は大文字と小文字を区別します。 特に明記しない限り、準拠した実装を開発するためには、この文書で提供するXMLの仕様と例を、示されたとおりの大文字・小文字で解釈しなければなりません（MUST）。

The XML namespace prefix "maint" is used for the namespace "urn:ietf:params:xml:ns:epp:maintenance-1.0", but implementations MUST NOT depend on it and instead employ a proper namespace-aware XML parser and serializer to interpret and output the XML documents.

XML名前空間プレフィックス「maint」は名前空間「urn:ietf:params:xml:ns:epp:maintenance-1.0」に対して使用されますが、実装はこれに依存してはなりません（MUST NOT）。 代わりに、適切な名前空間対応のXMLパーサーおよびシリアライザーを使用してXML文書を解釈および出力してください。

「ote」は「Operational Test and Evaluation（運用テストおよび評価）」の略語です。

In examples, "C:" represents lines sent by a protocol client, and "S:" represents lines returned by a protocol server. Indentation and white space in examples are provided only to illustrate element relationships and are not a required feature of this protocol.

例において、「C:」はプロトコルクライアントが送信する行を表し、「S:」はプロトコルサーバーが返す行を表します。 例のインデントと空白は、要素間の関係を示すためだけに提供されているものであり、このプロトコルで必須の機能ではありません。

2. Migrating to Newer Versions of This Extension

2. この拡張の新しいバージョンへの移行

Servers that implement this extension SHOULD provide a way for clients to progressively update their implementations when a new version of the extension is deployed. A newer version of the extension is expected to use an XML namespace with a higher version number than the prior versions.

この拡張を実装するサーバーは、拡張の新しいバージョンが展開されたときに、クライアントが段階的に実装を更新できる方法を提供すべきです（SHOULD）。 拡張の新しいバージョンは、以前のバージョンよりも大きいバージョン番号を持つXML名前空間を使用することが想定されています。

Servers SHOULD (for a temporary migration period up to server policy) provide support for older versions of the extension in parallel to the newest version and allow clients to execute their preferred version of the <info> command based on the maintenance <objURI> elements of the server <greeting>. The version of the maintenance <info> response MUST match the version of the maintenance <info> command executed by the server.

サーバーは、（サーバーポリシーに委ねられる一時的な移行期間の間）最新バージョンと並行して拡張の古いバージョンのサポートを提供し、サーバーの<greeting>のメンテナンスの<objURI>要素に基づいて、クライアントが希望するバージョンの<info>コマンドを実行できるようにすべきです（SHOULD）。 メンテナンスの<info>レスポンスのバージョンは、サーバーが実行したメンテナンスの<info>コマンドのバージョンと一致しなければなりません（MUST）。

Servers MUST return a Registry Maintenance Notification poll message matching the newest negotiated version of the maintenance extension, based on an intersection of the maintenance <objURI> elements in the server <greeting> and the client <login> command. If the intersection of the maintenance <objURI> elements of the server <greeting> and the client <login> command results in an empty set, the server MUST return the newest version of the Registry Maintenance Notification poll message supported by the server based on "Usage with Poll-Message EPP Responses" in Section 6 of [RFC9038].

サーバーは、サーバーの<greeting>とクライアントの<login>コマンドに含まれるメンテナンスの<objURI>要素の共通部分に基づいて、ネゴシエートされたメンテナンス拡張の最新バージョンに一致するレジストリーメンテナンス通知のポーリングメッセージを返さなければなりません（MUST）。 サーバーの<greeting>とクライアントの<login>コマンドのメンテナンスの<objURI>要素の共通部分が空集合になる場合、サーバーは、[RFC9038]のSection 6の「Usage with Poll-Message EPP Responses」に基づいて、サーバーがサポートするレジストリーメンテナンス通知のポーリングメッセージの最新バージョンを返さなければなりません（MUST）。

3. Object Attributes

3. オブジェクトの属性

3.1. Internationalized Domain Names

3.1. 国際化ドメイン名

Names of affected hosts MUST be provided in A-label form, according to [RFC5891].

影響を受けるホストの名前は、[RFC5891]に従ってAラベル形式で提供しなければなりません（MUST）。

3.2. Dates and Times

3.2. 日付と時刻

All date and time attribute values MUST be expressed in Universal Coordinated Time (UTC) using the Gregorian calendar. The date-time format defined as "date-time" in [RFC3339], with time-offset="Z", MUST be used.

すべての日付と時刻の属性値は、グレゴリオ暦を使用して協定世界時（UTC）で表現しなければなりません（MUST）。 [RFC3339]で「date-time」として定義されている日時形式を、time-offset="Z"として使用しなければなりません（MUST）。

3.3. Maintenance Elements

3.3. メンテナンス要素

The <maint:item> element describes a single registry maintenance event during a specific period. This element is used in a maintenance item EPP <info> command and response as well as in a <poll> response.

<maint:item>要素は、特定の期間における単一のレジストリーメンテナンスイベントを記述します。 この要素は、メンテナンス項目のEPP <info>コマンドとレスポンス、および<poll>レスポンスで使用されます。

If an element is not marked as optional, it is mandatory.

任意とマークされていない要素は必須です。

<maint:id>
The server-unique identifier for the maintenance event with the OPTIONAL "name" attribute that includes a human-readable name of the event. The server-unique identifier SHALL NOT be changed if the event is updated or deleted. When the "name" attribute is set, the OPTIONAL "lang" attribute, per the language structure in [RFC5646], MAY be present to identify the language if the negotiated value is something other than the default value of "en" (English).
<maint:type>
Zero or more OPTIONAL types of the maintenance event, with the possible set of values defined by server policy, such as "Routine Maintenance", "Software Update", "Software Upgrade", or "Extended Outage". The OPTIONAL "lang" attribute MAY be present to identify the language if the negotiated value is something other than the default value of "en" (English).
<maint:pollType>
The OPTIONAL <maint:pollType> element for a Registry Maintenance Notification poll message; values MUST be "create", "update", "delete", "courtesy", or "end". For the "create" and "update" types, the server includes the state of the maintenance event after the creation or update. For the "delete" type, the server includes the state of the event before the delete. The "courtesy" provides a reminder of an event, and the "end" provides a notification of the end of the event without updating the maintenance object and includes the latest state of the event. This element MUST be present only for poll messages.
<maint:systems>

One or more <maint:system> elements that are affected by the maintenance event.

<maint:system>

The <maint:system> element contains the following child elements:

<maint:name>
The name of the affected system, such as "EPP", "WHOIS", "DNS", "Portal", "RDAP", etc.
<maint:host>
The OPTIONAL affected maintained system's hostname, which SHALL be in A-label form, according to [RFC5891].
<maint:impact>
The impact level; the values MUST be "full", "partial", or "none". If access is expected to be intermittently unavailable, it is "partial". If access is expected to be completely unavailable, it is "full". If access is not affected, it is "none".
<maint:id>
メンテナンスイベントのサーバー内で一意な識別子です。 選択可能な（OPTIONAL）「name」属性には、イベントの人間が読める名前を含めます。 イベントが更新または削除されても、サーバー内で一意な識別子を変更することはありません（SHALL NOT）。 「name」属性が設定されている場合、ネゴシエートされた値がデフォルト値の「en」（英語）以外であるときに言語を識別するために、[RFC5646]の言語の構造に従った選択可能な（OPTIONAL）「lang」属性が存在してもよいです（MAY）。
<maint:type>
メンテナンスイベントの0個以上の選択可能な（OPTIONAL）種別です。 取りうる値の集合はサーバーポリシーによって定義され、たとえば「Routine Maintenance」、「Software Update」、「Software Upgrade」、「Extended Outage」などがあります。 ネゴシエートされた値がデフォルト値の「en」（英語）以外である場合に言語を識別するために、選択可能な（OPTIONAL）「lang」属性が存在してもよいです（MAY）。
<maint:pollType>
レジストリーメンテナンス通知のポーリングメッセージのための選択可能な（OPTIONAL）<maint:pollType>要素です。 値は「create」、「update」、「delete」、「courtesy」、「end」のいずれかでなければなりません（MUST）。 「create」と「update」の種別では、サーバーは作成または更新後のメンテナンスイベントの状態を含めます。 「delete」の種別では、サーバーは削除前のイベントの状態を含めます。 「courtesy」はイベントのリマインダーを提供し、「end」はメンテナンスオブジェクトを更新せずにイベントの終了の通知を提供し、イベントの最新の状態を含めます。 この要素は、ポーリングメッセージに対してのみ存在しなければなりません（MUST）。
<maint:systems>

メンテナンスイベントの影響を受ける1つ以上の<maint:system>要素です。

<maint:system>

<maint:system>要素は、次の子要素を含みます。

<maint:name>
影響を受けるシステムの名前です。たとえば「EPP」、「WHOIS」、「DNS」、「Portal」、「RDAP」などがあります。
<maint:host>
影響を受けるメンテナンス対象システムのホスト名で、選択できます（OPTIONAL）。 このホスト名は、[RFC5891]に従ってAラベル形式にすることになります（SHALL）。
<maint:impact>
影響のレベルです。値は「full」、「partial」、「none」のいずれかでなければなりません（MUST）。 アクセスが断続的に利用できなくなることが想定される場合は「partial」です。 アクセスが完全に利用できなくなることが想定される場合は「full」です。 アクセスが影響を受けない場合は「none」です。
<maint:environment>
The type of the affected system; the attribute "type" is REQUIRED and MUST be "production", "ote", "staging", "dev", or "custom". For extensibility, the <maint:environment> element includes the OPTIONAL "name" attribute that can define the name of the custom environment when the <maint:environment> element "type" attribute has the "custom" value. For example, for the custom "marketing" environment, the <maint:environment> element should be: <maint:environment type="custom" name="marketing"/>.
<maint:start>
The date and time of the start of the maintenance event.
<maint:end>
The date and time of the end of the maintenance event. The <maint:end> element MUST be greater than the <maint:start> element.
<maint:reason>
The reason behind the maintenance event; the values MUST be either "planned" or "emergency".
<maint:detail>
The OPTIONAL URI to the detailed maintenance event description, formatted according to [RFC3986].
<maint:description>
Zero or more OPTIONAL free-form descriptions of the maintenance event, usable without creating and traversing an external resource as defined by the <maint:detail> element. The OPTIONAL "lang" attribute MAY be present to identify the language if the negotiated value is something other than the default value of "en" (English). The OPTIONAL "type" attribute MAY be present to identify the format of the description. It MUST be either "plain" for plain text or "html" for HTML text, as defined in [HTML5], and XML-escaped, with a default value of "plain".
<maint:tlds>

The OPTIONAL <maint:tlds> element contains one or more <maint:tld> child elements. If the <maint:tlds> is not present, the entire system is affected.

<maint:tld>
The affected top-level domain or registry zone, which SHALL be in A-label form, according to [RFC5891].
<maint:intervention>

The OPTIONAL <maint:intervention> element contains the following child elements:

<maint:connection>
The value SHALL be boolean and indicates if a client needs to perform a connection-related action such as a reconnect. The attribute should only be used as a flag to indicate connections will be affected. Servers SHOULD include a description of how the connections are affected in the <maint:description> element or use the <maint:detail> element above.
<maint:implementation>
The value SHALL be boolean and indicates if a client needs to perform an implementation-related action such as a code change. The attribute should only be used as a flag to indicate implementation will be affected. Servers SHOULD include a description of how the implementation is affected in the <maint:description> element or use the <maint:detail> element above.
<maint:crDate>
The date and time of the maintenance object creation.
<maint:upDate>
The OPTIONAL date and time of the most recent maintenance object modification. This element MUST NOT be present if the maintenance object has never been modified.
<maint:environment>
影響を受けるシステムの種別です。 属性「type」は要求されています（REQUIRED）。 その値は「production」、「ote」、「staging」、「dev」、「custom」のいずれかでなければなりません（MUST）。 拡張性のために、<maint:environment>要素には選択可能な（OPTIONAL）「name」属性が含まれます。 この属性は、<maint:environment>要素の「type」属性が「custom」の値を持つ場合に、カスタム環境の名前を定義できます。 たとえば、カスタムの「marketing」環境の場合、<maint:environment>要素は <maint:environment type="custom" name="marketing"/> となるはずです。
<maint:start>
メンテナンスイベントの開始日時です。
<maint:end>
メンテナンスイベントの終了日時です。 <maint:end>要素は<maint:start>要素よりも大きくなければなりません（MUST）。
<maint:reason>
メンテナンスイベントの理由です。値は「planned」または「emergency」のいずれかでなければなりません（MUST）。
<maint:detail>
メンテナンスイベントの詳細な説明へのURIで、選択できます（OPTIONAL）。 このURIは[RFC3986]に従った形式です。
<maint:description>
メンテナンスイベントの0個以上の選択可能な（OPTIONAL）自由形式の説明です。 <maint:detail>要素で定義されるような外部リソースを作成してたどることなく使用できます。 ネゴシエートされた値がデフォルト値の「en」（英語）以外である場合に言語を識別するために、選択可能な（OPTIONAL）「lang」属性が存在してもよいです（MAY）。 説明の形式を識別するために、選択可能な（OPTIONAL）「type」属性が存在してもよいです（MAY）。 この属性は、プレーンテキストの場合は「plain」、[HTML5]で定義されているHTMLテキストの場合は「html」のいずれかでなければなりません（MUST）。 HTMLテキストはXMLエスケープされ、デフォルト値は「plain」です。
<maint:tlds>

選択可能な（OPTIONAL）<maint:tlds>要素は、1つ以上の<maint:tld>子要素を含みます。 <maint:tlds>が存在しない場合は、システム全体が影響を受けます。

<maint:tld>

4. EPP Command Mapping

4. EPPコマンドマッピング

A detailed description of the EPP syntax and semantics can be found in the EPP core protocol specification [RFC5730]. The command mappings described here are specifically used to notify registrars of registry maintenance events and object mapping.

EPPの構文とセマンティクスの詳細な説明は、EPPのコアプロトコル仕様[RFC5730]にあります。 ここで説明するコマンドマッピングは、特にレジストリーのメンテナンスイベントとオブジェクトマッピングをレジストラーに通知するために使用されます。

4.1. EPP Query Commands

4.1. EPPクエリーコマンド

EPP [RFC5730] provides three commands to retrieve object information: <check> to determine if an object is known to the server, <info> to retrieve detailed information associated with an object, and <transfer> to retrieve object transfer status information.

EPP [RFC5730]は、オブジェクトの情報を取得するための3つのコマンドを提供しています。 オブジェクトがサーバーに既知であるかどうかを判断する<check>、オブジェクトに関連する詳細な情報を取得する<info>、オブジェクトの移管ステータス情報を取得する<transfer>です。

This extension does not add any elements to EPP <check> and <transfer> commands or responses.

この拡張は、EPPの<check>コマンドと<transfer>コマンド、およびそれらのレスポンスに要素を追加しません。

4.1.1. EPP <info> Command

4.1.1. EPP <info>コマンド

EPP provides the <info> command that is used to retrieve registry maintenance information. In addition to the standard EPP command elements, the <info> command MUST contain a <maint:info> element that identifies the maintenance namespace.

EPPは、レジストリーのメンテナンス情報を取得するために使用する<info>コマンドを提供しています。 標準のEPPコマンド要素に加えて、<info>コマンドは、メンテナンス名前空間を識別する<maint:info>要素を含まなければなりません（MUST）。

The <maint:info> element MUST contain a child element. It is either the <maint:id> child element, described in Section 4.1.1.1, to query for a specific maintenance item or the <maint:list> child element, described in Section 4.1.1.2, to query all maintenance items.

<maint:info>要素は子要素を含まなければなりません（MUST）。 その子要素は、特定のメンテナンス項目を問い合わせるための<maint:id>子要素（Section 4.1.1.1で説明）か、すべてのメンテナンス項目を問い合わせるための<maint:list>子要素（Section 4.1.1.2で説明）のいずれかです。

7. Security Considerations

7. セキュリティーに関する考慮事項

The security considerations of [RFC5730] apply in this document. Additionally, a server MUST only provide maintenance information to clients that are authorized. Suppose a client queries a maintenance identifier that it is not authorized to access per Section 4.1.1.1, "Info Maintenance Item". In that case, the server SHOULD return an EPP error result code of 2201 ("Authorization error") or 2303 ("Object does not exist") [RFC5730]. The list of top-level domains or registry zones returned in the "Info Maintenance Item" response SHOULD be filtered based on the top-level domains or registry zones for which the client is authorized. Authorization of poll messages is done at the time of poll message insertion and not at the time of poll message consumption.

[RFC5730]のセキュリティーに関する考慮事項がこの文書にも適用されます。 加えて、サーバーは、認可されたクライアントにのみメンテナンス情報を提供しなければなりません（MUST）。 Section 4.1.1.1「メンテナンス項目のInfo」に従って、クライアントが、アクセスを認可されていないメンテナンス識別子を問い合わせたとします。 その場合、サーバーはEPPのエラー結果コード2201（"Authorization error"）または2303（"Object does not exist"）[RFC5730]を返すべきです（SHOULD）。 「メンテナンス項目のInfo」のレスポンスで返されるトップレベルドメインまたはレジストリーゾーンのリストは、クライアントが認可されているトップレベルドメインまたはレジストリーゾーンに基づいてフィルタリングすべきです（SHOULD）。 ポーリングメッセージの認可は、ポーリングメッセージの消費時ではなく、ポーリングメッセージの挿入時に行われます。
