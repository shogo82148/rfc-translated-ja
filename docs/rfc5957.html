RFC 5957

Display-Based Address Sorting for the IMAP4 SORT Extension

RFC 5957

IMAP4 SORT拡張のための表示名に基づくアドレスのソート

Abstract

概要

This document describes an IMAP protocol extension enabling server-side message sorting on the commonly displayed portion of the From and To header fields.

この文書は、FromヘッダーフィールドとToヘッダーフィールドのうち一般に表示される部分に基づいて、サーバー側でメッセージをソートできるようにするIMAPプロトコルの拡張について説明します。

1. Introduction

1. はじめに

The [SORT] extension to the [IMAP] protocol provides a means for the server-based sorting of messages. It defines a set of sort criteria and the mechanism for determining the sort value of a message for each such ordering.

[IMAP]プロトコルの[SORT]拡張は、サーバーベースでメッセージをソートする手段を提供します。この拡張は、ソート基準の集合と、そのような順序付けそれぞれについてメッセージのソート値を決定する仕組みを定義しています。

The [SORT] FROM and TO orderings sort messages lexically on the [IMAP] addr-mailbox of the first address in the message's From and To headers, respectively. This document provides two alternative orderings, DISPLAYFROM and DISPLAYTO, which sort messages based on the first From or To address's [IMAP] addr-name (generally the same as its [RFC5322] display-name), when present.

[SORT]のFROMおよびTOの順序付けは、それぞれメッセージのFromヘッダーおよびToヘッダーにある最初のアドレスの[IMAP] addr-mailboxに基づいて、メッセージを辞書順にソートします。この文書は、DISPLAYFROMとDISPLAYTOという2つの代替の順序付けを提供します。これらは、最初のFromアドレスまたはToアドレスの[IMAP] addr-name（一般にその[RFC5322] display-nameと同じ）が存在する場合に、それに基づいてメッセージをソートします。

A server that supports the full [SORT] extension as well as both the DISPLAYFROM and DISPLAYTO sort criteria indicates this by returning "SORT=DISPLAY" in its CAPABILITY response.

[SORT]拡張の全体と、DISPLAYFROMおよびDISPLAYTOの両方のソート基準をサポートするサーバーは、CAPABILITYレスポンスで「SORT=DISPLAY」を返すことでそれを示します。

3. DISPLAY Sort Value for an Address

3. アドレスのDISPLAYソート値

For the purposes of the sort criteria defined in this document, the sort value for an [IMAP] address structure is defined as follows:

この文書で定義するソート基準のために、[IMAP]のアドレス構造のソート値を次のように定義します。

  • If the address structure's [IMAP] addr-name is non-NIL, apply the procedure from [RFC5255], Section 4.6. (That is, decode any [RFC2047] encoded-words and convert the resulting character string into a charset valid for the currently active [RFC4790] collation, with a default of UTF-8.) If the resulting octet string is not the empty string, use it as the sort value for the address.
  • Otherwise, if the address structure's [IMAP] addr-mailbox and [IMAP] addr-host are both non-NIL, the sort value for the address is addr-mailbox@addr-host.
  • Otherwise, if the address structure's [IMAP] addr-mailbox is non-NIL, the sort value for the address is its addr-mailbox.
  • If none of the above conditions are met, the sort value for the address is the empty string.
  • アドレス構造の[IMAP] addr-nameがNILでない場合は、[RFC5255], セクション4.6の手順を適用します。（つまり、[RFC2047]のencoded-wordをすべてデコードし、その結果の文字列を、現在有効な[RFC4790]照合順序（collation）で有効な文字セットに変換します。デフォルトはUTF-8です。）その結果のオクテット文字列が空文字列でなければ、それをアドレスのソート値として使います。
  • そうでない場合、アドレス構造の[IMAP] addr-mailboxと[IMAP] addr-hostがどちらもNILでなければ、アドレスのソート値はaddr-mailbox@addr-hostです。
  • そうでない場合、アドレス構造の[IMAP] addr-mailboxがNILでなければ、アドレスのソート値はそのaddr-mailboxです。
  • 上記の条件のいずれも満たされない場合、アドレスのソート値は空文字列です。

4. The DISPLAYFROM and DISPLAYTO Sort Criteria

4. DISPLAYFROMおよびDISPLAYTOソート基準

This document introduces two new [SORT] sort criteria, DISPLAYFROM and DISPLAYTO. A message's sort value under these orderings MUST be derived as follows:

この文書は、DISPLAYFROMとDISPLAYTOという2つの新しい[SORT]ソート基準を導入します。これらの順序付けにおけるメッセージのソート値は、次のように導出しなければなりません（MUST）。

A "derived-addr" value is created from the [IMAP] envelope structure resulting from a FETCH ENVELOPE on the message. For DISPLAYFROM, the derived-addr value is the [IMAP] env-from value. For DISPLAYTO, the derived-addr value is the [IMAP] env-to value.

「derived-addr」値は、メッセージに対するFETCH ENVELOPEの結果として得られる[IMAP]のエンベロープ構造から作成します。DISPLAYFROMの場合、derived-addr値は[IMAP]のenv-from値です。DISPLAYTOの場合、derived-addr値は[IMAP]のenv-to値です。

  • If the derived-addr value is NIL, the message's sort value is the empty string.
  • Otherwise, the message's sort value is the DISPLAY sort value of the first [IMAP] address in the derived-addr value.
  • derived-addr値がNILの場合、メッセージのソート値は空文字列です。
  • そうでない場合、メッセージのソート値は、derived-addr値の最初の[IMAP]アドレスのDISPLAYソート値です。

5. Formal Syntax

5. 形式的構文

The following syntax specification uses the Augmented Backus-Naur Form (ABNF) notation as specified in [RFC5234]. [IMAP] defines the non-terminal "capability", and [SORT] defines "sort-key".

次の構文仕様は、[RFC5234]で規定されている拡張バッカス・ナウア記法（ABNF：Augmented Backus-Naur Form）を使用します。[IMAP]は非終端記号「capability」を定義し、[SORT]は「sort-key」を定義しています。

capability    =/ "SORT=DISPLAY"

sort-key      =/ "DISPLAYFROM" / "DISPLAYTO"

capability    =/ "SORT=DISPLAY"

sort-key      =/ "DISPLAYFROM" / "DISPLAYTO"

6. Security Considerations

6. セキュリティーに関する考慮事項

This document defines an additional IMAP4 capability. As such, it does not change the underlying security considerations of [IMAP]. The author believes that no new security issues are introduced with this additional IMAP4 capability.

この文書は、IMAP4の追加の能力（capability）を定義します。そのため、[IMAP]の基本的なセキュリティーに関する考慮事項を変更するものではありません。著者は、このIMAP4の追加の能力によって新たなセキュリティー上の問題が生じることはないと考えています。

7. Internationalization Considerations

7. 国際化に関する考慮事項

DISPLAYFROM and DISPLAYTO are string-based sort criteria. As stated in [SORT], the active [RFC4790] collation as per [RFC5255] MUST be used when sorting such strings.

DISPLAYFROMとDISPLAYTOは、文字列に基づくソート基準です。[SORT]で述べられているように、そのような文字列をソートする際には、[RFC5255]に従って有効な[RFC4790]照合順序を使用しなければなりません（MUST）。

The DISPLAYFROM and DISPLAYTO orderings sort on the full decoded [IMAP] addr-name, when present. They do not attempt to parse this string in a locale- or language-dependent manner in order to determine and sort on some semantically meaningful substring such as the surname.

DISPLAYFROMとDISPLAYTOの順序付けは、[IMAP] addr-nameが存在する場合、そのデコードされた全体に基づいてソートします。姓のような意味のある部分文字列を特定してそれに基づいてソートするために、この文字列をロケールや言語に依存した方法で解析しようとはしません。

8. IANA Considerations

8. IANAに関する考慮事項

[IMAP] capabilities are registered by publishing a Standards Track or IESG-approved Experimental RFC. This document constitutes registration of the SORT=DISPLAY capability in the [IMAP] capabilities registry.

[IMAP]の能力は、標準化過程のRFCまたはIESGが承認した実験的RFCを発行することで登録されます。この文書は、[IMAP]能力レジストリーへのSORT=DISPLAY能力の登録となります。
