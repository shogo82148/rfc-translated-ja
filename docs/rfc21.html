1. Changes to BBN Memo No. 1822 (underlined) As informally communicated by Dave Wa

1. BBN Memo No. 1822の変更点（下線部） Dave Waから非公式に伝えられたとおり

p. 11 "The IMP program can handle up to 63 active transmit links and 63 active receive links at a time. If the Host attempts to send a message on a new link when 63 active transmit links already exist, a "Link Table Full" message will be sent from the IMP to the Host, and the message will be discarded."

p. 11「IMPプログラムは、同時に最大63本のアクティブな送信リンクと63本のアクティブな受信リンクを扱えます。すでに63本のアクティブな送信リンクがあるときにホストが新しいリンクでメッセージを送ろうとすると、IMPからホストへ「Link Table Full」メッセージが送られ、そのメッセージは破棄されます。」

p. 11 "1. Any link that is not used for a period of 26 seconds will have its entry automatically deleted by the IMP program."

p. 11「1. 26秒間使われなかったリンクは、そのエントリーがIMPプログラムによって自動的に削除されます。」

[Cerf: How about deleting only if the transmit link table is full?

[Cerf：送信リンクテーブルがいっぱいのときだけ削除するのはどうでしょうか？

Crocker: No, because there is no other way for links to be deleted so they would always tend to accumulate. Furthermore, the table at one site may be full while another site may not be.]

Crocker：だめです。ほかにリンクを削除する方法がないので、リンクは常にたまっていく傾向があるからです。さらに、あるサイトのテーブルはいっぱいでも、別のサイトのテーブルはそうでないかもしれません。]

p. 13 "5 Regular with discard."

p. 13「5 Regular with discard」

This allows IMP systems to generate traffic which never actually reaches any Hosts since it will be discarded when it reaches the top of the IMP-HOST queue in the destination Host's IMP. The Network Measurement Center will make use of this feature.

これにより、IMPシステムは、実際にはどのホストにも届かないトラフィックを生成できます。そのトラフィックは、宛先ホストのIMPにあるIMP-HOSTキューの先頭に達したときに破棄されるからです。Network Measurement Centerはこの機能を利用する予定です。

p. 13 Message type 6 is no longer assigned, and message type 10 is really in octal so is actually type 8. Types 9-15 are unassigned.

p. 13 メッセージタイプ6はもう割り当てられていません。また、メッセージタイプ10は実は8進数なので、実際にはタイプ8です。タイプ9〜15は未割り当てです。

p. 17 Type 10 is really type 8.

p. 17 タイプ10は実際にはタイプ8です。

2. Revisions to NWG/RFC 11

2. NWG/RFC 11の改訂

This memo has been obsoleted by developments at UCLA and discussions with other nodes. NWG/RFC 22 contains some of the major changes. An updated version of NWG/RFC 11 is forthcoming.

このメモは、UCLAでの開発とほかのノードとの議論によって古くなりました。主な変更点の一部はNWG/RFC 22に記載しています。NWG/RFC 11の改訂版は近く公開します。

3. George Gregg of UCSB will publish NWG/RFC 23 concerning the transmission of multiple control messages over control links.

3. UCSBのGeorge Greggが、制御リンク上での複数の制御メッセージの送信について、NWG/RFC 23を発行する予定です。
