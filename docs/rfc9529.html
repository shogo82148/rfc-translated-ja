1. Introduction

1. はじめに

EDHOC [RFC9528] is a lightweight authenticated key exchange protocol designed for highly constrained settings. This document contains annotated traces of EDHOC sessions with input, output, and intermediate processing results to simplify testing of implementations. The traces have been verified by two independent implementations.

EDHOC [RFC9528]は、非常に制約の厳しい環境向けに設計された軽量な認証付き鍵交換プロトコルです。この文書には、実装のテストを簡単にするために、入力、出力、処理の中間結果を含む、注釈付きのEDHOCセッションのトレースが含まれています。これらのトレースは、2つの独立した実装によって検証されています。

1.1. Setup

1.1. セットアップ

EDHOC is run between an Initiator (I) and a Responder (R). The private/public key pairs and credentials of the Initiator and the Responder required to produce the protocol messages are shown in the traces when needed for the calculations.

EDHOCは、イニシエーター（I）とレスポンダー（R）の間で実行されます。プロトコルメッセージを生成するのに必要な、イニシエーターとレスポンダーの秘密鍵と公開鍵のペアおよびクレデンシャルは、計算に必要な場合にトレース内に示します。

EDHOC messages and intermediate results are encoded in Concise Binary Object Representation (CBOR) [RFC8949] and can therefore be displayed in CBOR diagnostic notation using, e.g., the CBOR playground [CborMe], which makes them easy to parse for humans. Credentials can also be encoded in CBOR, e.g., CBOR Web Tokens (CWTs) [RFC8392].

EDHOCのメッセージと中間結果は、Concise Binary Object Representation（CBOR）[RFC8949]でエンコードされます。そのため、たとえばCBOR playground [CborMe]を使用してCBOR診断記法で表示でき、人間が容易に解析できます。クレデンシャルもCBORでエンコードできます。たとえば、CBOR Web Token（CWT）[RFC8392]です。

The document contains two traces:

この文書には2つのトレースが含まれています。

  • Section 2 - Authentication with signature keys identified by the hash value of the X.509 certificates (provided in Section 2.8). The endpoints use Edwards-curve Digital Signature Algorithm (EdDSA) [RFC8032] for authentication and X25519 [RFC7748] for ephemeral-ephemeral Diffie-Hellman (DH) key exchange.
  • Section 3 - Authentication with static Diffie-Hellman keys identified by short key identifiers labeling CWT Claims Sets (CCSs) [RFC8392]. The endpoints use NIST P-256 [SP-800-186] for both ephemeral-ephemeral and ephemeral-static DH key exchange. This trace also illustrates the cipher suite negotiation and provides an example of low protocol overhead with messages sizes of 39, 45, and 19 bytes.
  • Section 2 - X.509証明書（Section 2.8に掲載）のハッシュ値で識別される署名鍵による認証。エンドポイントは、認証にEdwards-curve Digital Signature Algorithm（EdDSA）[RFC8032]を、エフェメラル-エフェメラル（ephemeral-ephemeral）のDiffie-Hellman（DH）鍵交換にX25519 [RFC7748]を使用します。
  • Section 3 - CWTクレームセット（CCS）[RFC8392]にラベル付けした短い鍵識別子で識別される静的Diffie-Hellman鍵による認証。エンドポイントは、エフェメラル-エフェメラル（ephemeral-ephemeral）とエフェメラル-静的（ephemeral-static）の両方のDH鍵交換にNIST P-256 [SP-800-186]を使用します。このトレースは、暗号スイートのネゴシエーションも示しており、メッセージサイズが39、45、19バイトという低いプロトコルオーバーヘッドの例にもなっています。

Examples of invalid EDHOC messages are found in Section 4.

無効なEDHOCメッセージの例はSection 4にあります。

  1. The same name is used for hexadecimal byte strings and their CBOR encodings. The traces contain both the raw byte strings and the corresponding CBOR-encoded data items.
  2. If not clear from the context, remember that CBOR sequences and CBOR arrays assume CBOR-encoded data items as elements.
  3. When the protocol transporting EDHOC messages does not inherently provide correlation across all messages, then some messages are typically prepended with connection identifiers and potentially a message_1 indicator (see Section 3.4.1 and Appendix A.2 of [RFC9528]).   1. 16進数のバイト文字列とそのCBORエンコーディングには、同じ名前を使用します。トレースには、生のバイト文字列と、対応するCBORエンコードされたデータ項目の両方が含まれています。
  2. 文脈から明らかでない場合でも、CBORシーケンスとCBOR配列は、CBORエンコードされたデータ項目を要素とすることに注意してください。
  3. EDHOCメッセージを運ぶプロトコルが、本質的にすべてのメッセージ間の対応付けを提供しない場合、通常、一部のメッセージの前にはコネクション識別子と、場合によってはmessage_1インジケーターが付加されます（[RFC9528]のセクション3.4.1と付録A.2を参照）。この文書のトレースには、それらのバイトは含まれていません。
