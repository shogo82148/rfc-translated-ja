RFC 1764

The PPP XNS IDP Control Protocol (XNSCP)

RFC 1764

PPPのXNS IDP制御プロトコル（XNSCP）

Abstract

概要

The Point-to-Point Protocol (PPP) [1] provides a standard method for transporting multi-protocol datagrams over point-to-point links. PPP defines an extensible Link Control Protocol, and proposes a family of Network Control Protocols for establishing and configuring different network-layer protocols.

ポイントツーポイントプロトコル（Point-to-Point Protocol、PPP）[1]は、ポイントツーポイントリンク上でマルチプロトコルのデータグラムを転送するための標準的な方法を提供します。PPPは、拡張可能なリンク制御プロトコル（Link Control Protocol）を定義し、さまざまなネットワーク層プロトコルを確立および設定するためのネットワーク制御プロトコル（Network Control Protocol）のファミリーを提案しています。

This document defines the Network Control Protocol for establishing and configuring the Xerox Network Systems (XNS) Internet Datagram Protocol (IDP) over PPP.

この文書は、PPP上でゼロックスネットワークシステムズ（Xerox Network Systems、XNS）のインターネットデータグラムプロトコル（Internet Datagram Protocol、IDP）を確立および設定するためのネットワーク制御プロトコルを定義します。

1. Introduction

1. はじめに

PPP has three main components:

PPPには、主に3つの構成要素があります。

  1. A method for encapsulating multi-protocol datagrams.
  2. A Link Control Protocol (LCP) for establishing, configuring, and testing the data-link connection.
  3. A family of Network Control Protocols for establishing and configuring different network-layer protocols.
  1. マルチプロトコルのデータグラムをカプセル化する方法。
  2. データリンクのコネクションを確立、設定、テストするためのリンク制御プロトコル（LCP）。
  3. さまざまなネットワーク層プロトコルを確立および設定するためのネットワーク制御プロトコルのファミリー。

In order to establish communications over a point-to-point link, each end of the PPP link must first send LCP packets to configure and test the data link. After the link has been established and optional facilities have been negotiated as needed by the LCP, PPP must send XNSCP packets to choose and configure the XNS IDP network-layer protocol. Once XNSCP has reached the Opened state, XNS IDP datagrams can be sent over the link.

ポイントツーポイントリンク上で通信を確立するには、PPPリンクの両端は、まずLCPパケットを送信してデータリンクを設定およびテストしなければなりません。リンクが確立され、LCPによって必要に応じてオプション機能がネゴシエートされた後、PPPはXNSCPパケットを送信して、XNS IDPネットワーク層プロトコルを選択および設定しなければなりません。XNSCPがOpened状態に達すると、XNS IDPデータグラムをリンク上で送信できるようになります。

The link will remain configured for communications until explicit LCP or XNSCP packets close the link down, or until some external event occurs (an inactivity timer expires or network administrator intervention).

リンクは、明示的なLCPパケットまたはXNSCPパケットによってリンクが閉じられるまで、あるいは何らかの外部イベント（非アクティブタイマーの満了やネットワーク管理者の介入）が発生するまで、通信用に設定されたままになります。

In this document, several words are used to signify the requirements of the specification. These words are often capitalized.

この文書では、仕様の要件を示すためにいくつかの語を使います。これらの語は、多くの場合大文字で書かれます。

MUST
This word, or the adjective "required", means that the definition is an absolute requirement of the specification.
MUST NOT
This phrase means that the definition is an absolute prohibition of the specification.
SHOULD
This word, or the adjective "recommended", means that there may exist valid reasons in particular circumstances to ignore this item, but the full implications must be understood and carefully weighed before choosing a different course.
MAY
This word, or the adjective "optional", means that this item is one of an allowed set of alternatives. An implementation which does not include this option MUST be prepared to interoperate with another implementation which does include the option.
MUST
この語、または形容詞「required」は、その定義が仕様の絶対的な要件であることを意味します。
MUST NOT
この語句は、その定義が仕様の絶対的な禁止事項であることを意味します。
SHOULD
この語、または形容詞「recommended」は、特定の状況においてはこの項目を無視する正当な理由が存在する場合もあるものの、別の方針を選択する前に、その影響のすべてを理解し、慎重に検討しなければならないことを意味します。
MAY
この語、または形容詞「optional」は、この項目が許可された選択肢の1つであることを意味します。このオプションを含まない実装は、このオプションを含む別の実装と相互運用できるように準備しなければなりません（MUST）。

1.2. Terminology

1.2. 用語

This document frequently uses the following terms:

この文書では、次の用語を頻繁に使います。

datagram
The unit of transmission in the network layer (such as IP). A datagram may be encapsulated in one or more packets passed to the data link layer.
frame
The unit of transmission at the data link layer. A frame may include a header and/or a trailer, along with some number of units of data.
packet
The basic unit of encapsulation, which is passed across the interface between the network layer and the data link layer. A packet is usually mapped to a frame; the exceptions are when data link layer fragmentation is being performed, or when multiple packets are incorporated into a single frame.
peer
The other end of the point-to-point link.
silently discard
This means the implementation discards the packet without further processing. The implementation SHOULD provide the capability of logging the error, including the contents of the silently discarded packet, and SHOULD record the event in a statistics counter.
datagram
データグラム。（IPなどの）ネットワーク層における伝送の単位です。データグラムは、データリンク層に渡される1つ以上のパケットにカプセル化される場合があります。
frame
フレーム。データリンク層における伝送の単位です。フレームには、いくつかのデータの単位とともに、ヘッダーやトレーラーが含まれる場合があります。
packet
パケット。カプセル化の基本単位であり、ネットワーク層とデータリンク層の間のインターフェイスを越えて渡されます。パケットは通常フレームに対応付けられます。例外は、データリンク層のフラグメンテーションが行われている場合と、複数のパケットが1つのフレームにまとめられている場合です。
peer
ピア。ポイントツーポイントリンクのもう一方の端です。
silently discard
黙って破棄する。実装がそれ以上の処理をせずにパケットを破棄することを意味します。実装は、黙って破棄したパケットの内容を含めてエラーを記録する機能を提供すべきです（SHOULD）。また、そのイベントを統計カウンターに記録すべきです（SHOULD）。

2. A PPP Network Control Protocol for XNS IDP

2. XNS IDPのためのPPPネットワーク制御プロトコル

The XNS IDP Control Protocol (XNSCP) is responsible for configuring, enabling, and disabling the XNS IDP protocol modules on both ends of the point-to-point link. XNSCP uses the same packet exchange mechanism as the Link Control Protocol (LCP). XNSCP packets may not be exchanged until PPP has reached the Network-Layer Protocol phase. XNSCP packets received before this phase is reached should be silently discarded.

XNS IDP制御プロトコル（XNS IDP Control Protocol、XNSCP）は、ポイントツーポイントリンクの両端でXNS IDPプロトコルモジュールを設定、有効化、無効化する役割を担います。XNSCPは、リンク制御プロトコル（LCP）と同じパケット交換メカニズムを使います。XNSCPパケットは、PPPがネットワーク層プロトコルフェーズ（Network-Layer Protocol phase）に達するまでは交換できません。このフェーズに達する前に受信したXNSCPパケットは、黙って破棄すべきです。

The XNS IDP Control Protocol is exactly the same as the Link Control Protocol [1] with the following exceptions:

XNS IDP制御プロトコルは、次の例外を除き、リンク制御プロトコル[1]とまったく同じです。

Frame Modifications
The packet may utilize any modifications to the basic frame format which have been negotiated during the Link Establishment phase.
Data Link Layer Protocol Field
Exactly one XNSCP packet is encapsulated in the Information field of a PPP Data Link Layer frame, where the PPP Protocol field indicates type hex 8025 (XNS IDP Control Protocol).
Code field
Only Codes 1 through 7 (Configure-Request, Configure-Ack, Configure-Nak, Configure-Reject, Terminate-Request, Terminate-Ack and Code-Reject) are used. Other Codes should be treated as unrecognized and should result in Code-Rejects.
Timeouts
XNSCP packets may not be exchanged until PPP has reached the Network-Layer Protocol phase. An implementation should be prepared to wait for Authentication and Link Quality Determination to finish before timing out waiting for a Configure-Ack or other response. It is suggested that an implementation give up only after user intervention or a configurable amount of time.
Configuration Option Types
XNSCP has no Configuration Options.
フレームの変更（Frame Modifications）
パケットは、リンク確立フェーズ（Link Establishment phase）でネゴシエートされた基本フレーム形式に対する任意の変更を利用できます。
データリンク層のプロトコルフィールド（Data Link Layer Protocol Field）
PPPのデータリンク層フレームのInformationフィールドには、XNSCPパケットをちょうど1つカプセル化します。このとき、PPPのProtocolフィールドは16進数の8025（XNS IDP制御プロトコル）を示します。
Codeフィールド（Code field）
コード1から7（Configure-Request、Configure-Ack、Configure-Nak、Configure-Reject、Terminate-Request、Terminate-Ack、Code-Reject）だけを使います。それ以外のコードは認識できないものとして扱い、Code-Rejectとなるようにすべきです。
タイムアウト（Timeouts）
XNSCPパケットは、PPPがネットワーク層プロトコルフェーズに達するまでは交換できません。実装は、Configure-Ackやその他のレスポンスの待機をタイムアウトさせる前に、認証とリンク品質判定（Link Quality Determination）が完了するのを待てるように準備しておくべきです。実装は、ユーザーの介入があった場合か、設定可能な時間が経過した後にだけ諦めることを提案します。
設定オプションの種類（Configuration Option Types）
XNSCPには設定オプション（Configuration Option）はありません。

2.1. Sending XNS IDP Datagrams

2.1. XNS IDPデータグラムの送信

Before any XNS IDP packets may be communicated, PPP must reach the Network-Layer Protocol phase, and the XNS IDP Control Protocol must reach the Opened state.

XNS IDPパケットを通信できるようになるには、その前に、PPPがネットワーク層プロトコルフェーズに達し、XNS IDP制御プロトコルがOpened状態に達していなければなりません。

Exactly one XNS IDP packet is encapsulated in the Information field of a PPP Data Link Layer frame where the Protocol field indicates type hex 0025 (XNS IDP datagram).

PPPのデータリンク層フレームのInformationフィールドには、XNS IDPパケットをちょうど1つカプセル化します。このとき、Protocolフィールドは16進数の0025（XNS IDPデータグラム）を示します。

The maximum length of a XNS IDP datagram transmitted over a PPP link is the same as the maximum length of the Information field of a PPP data link layer frame. Since there is no standard method for fragmenting and reassembling XNS IDP datagrams, PPP links supporting XNS IDP MUST allow at least 576 octets in the information field of a data link layer frame.

PPPリンク上で送信されるXNS IDPデータグラムの最大長は、PPPのデータリンク層フレームのInformationフィールドの最大長と同じです。XNS IDPデータグラムをフラグメント化および再構築する標準的な方法はないため、XNS IDPをサポートするPPPリンクは、データリンク層フレームのInformationフィールドで576オクテット以上を許容しなければなりません（MUST）。

The format of the Information field itself is the same as that defined in [2].

Informationフィールド自体の形式は、[2]で定義されているものと同じです。
