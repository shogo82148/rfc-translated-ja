RFC 247

Proferred Set of Standard Host Names

RFC 247

標準ホスト名の提案

Abstract

概要

In RFC #226, BBN's TENEX list of Host names was set up as a strawman set of standard Host names. Comments received since then (an RFC actually generated comments!!!) have influenced me to propose the following general rules for forming Host names.

RFC #226では、BBNのTENEXのHost名の一覧を、標準Host名のたたき台として示しました。それ以来受け取ったコメント（RFCが実際にコメントを生み出したのです!!!）を踏まえて、Host名を作るための次の一般的な規則を提案します。

The Host names will be 8 characters in length. The general form is

Host名の長さは8文字とします。一般的な形式は次のとおりです。

                     <site>  '-'  <machine>

                     <site>  '-'  <machine>

<site> will be at most 4 characters, formed as follows:

<site>は最大4文字で、次のように作ります。

  1. Use the keyword in the site name, if not more than four characters, e.g., NASA Ames, Case Western Reserve.
  2. Use the standard acronym, if not more than four characters, e.g., UCLA, RADC, NBS.
  3. If a standard abbreviation exists, use it, e.g., Ill.
  4. If none of the above apply, use the first four letters in the site name, e.g., Burr, Mitr, Harv.
  5. If none of the above is acceptable to the site, the technical liaison should select the site mnemonic.
  1. 4文字以下であれば、サイト名の中のキーワードを使います。例：NASA Ames、Case Western Reserve。
  2. 4文字以下であれば、標準の頭字語を使います。例：UCLA、RADC、NBS。
  3. 標準の略語があれば、それを使います。例：Ill。
  4. 上記のいずれも当てはまらない場合は、サイト名の最初の4文字を使います。例：Burr、Mitr、Harv。
  5. 上記のいずれもサイトにとって受け入れられない場合は、技術連絡担当者（technical liaison）がサイトの略称を選ぶべきです。

<machine> will be at most 4 characters of the form <mfg. #> <designator>. Examples of mfg. # are:

<machine>は、<mfg. #><designator>という形式の最大4文字とします。mfg. #（製造元の型番）の例は次のとおりです。

Table 1
IBM 360 2 digit model number
IBM 370 3 digit model number
PDP 1 - 2 digit model number
Burroughs 4 digits
CDC 4 digits
etc.
表1
IBM 360 2桁のモデル番号
IBM 370 3桁のモデル番号
PDP 1〜2桁のモデル番号
Burroughs 4桁
CDC 4桁
など

<designator> will be used when more than one machine of the same type is located at a site (e.g., 2 PDP-10s at MIT, at SRI, and at BBN).

<designator>は、同じ種類のマシンが1つのサイトに複数ある場合に使います（例：MIT、SRI、BBNにはそれぞれPDP-10が2台あります）。

Limiting <machine> to 4 characters does not permit distinctions to be made between machines with 4 digit mfg. #s. I expect the situation will be handled in an ad hoc manner by the NIC if it arises.

<machine>を4文字に制限すると、4桁のmfg. #を持つマシンどうしを区別できません。そのような状況が生じた場合は、NICが場当たり的に対処することになると思います。

TIPs are identified as 'TIP' rather than by '316'. If a Host is not to be permanently addressable, the machine is identified as 'TEST'.

TIPは、'316'ではなく'TIP'として識別します。恒久的にアドレス指定可能でないHostの場合、そのマシンは'TEST'として識別します。

A list of Host names, formed according to these rules, is attached. Alternate Host names should be provided, as suggested by Jon Postel (RFC #236). RFC's 206, 233, and 236 present lists with 4-character alternate names. The Technical Liaison should select the alternate name for his site and communicate the selection to the NIC.

これらの規則に従って作ったHost名の一覧を添付します。Jon Postelが提案したように（RFC #236）、代替のHost名も用意すべきです。RFC 206、233、236は、4文字の代替名の一覧を示しています。技術連絡担当者（Technical Liaison）は、自分のサイトの代替名を選び、その選択をNICに伝えるべきです。

The preceding rules and the attached list of Host names are subject to the approval of the NWG. Hereafter, the list will be generated and maintained by the NIC in cooperation with the Technical Liaison at each site, as suggested in RFC #237. Comments should be addressed to Dick Watson.

上記の規則と添付のHost名の一覧は、NWGの承認を受けるものとします。今後、この一覧は、RFC #237で提案されているように、NICが各サイトの技術連絡担当者と協力して作成・維持します。コメントはDick Watson宛てにお送りください。

An Implementation Scheme

実装方式

If the standard Host names are formed according to the proposed rules, the following implementation scheme, suggested by Steve Crocker, can be used.

標準Host名を提案した規則に従って作るなら、Steve Crockerが提案した次の実装方式を使えます。

        Map <site> into an 8-bit number, S and
        map <machine> into an 8-bit number, M,
        where
                  S + M = Network Address.

        Map <site> into an 8-bit number, S and
        map <machine> into an 8-bit number, M,
        where
                  S + M = Network Address.

S and M can be selected such that specification of <site> alone could cause a default to the "primary" Host at the site. Note that this scheme depends on a unique <site> designator for each IMP.

<site>だけを指定したときに、そのサイトの「主（primary）」Hostがデフォルトになるように、SとMを選ぶことができます。この方式は、IMPごとに一意な<site>指示子があることに依存している点に注意してください。

Some examples:

いくつかの例を示します。

If the "primary" Host at UCLA is the 91, let

UCLAの「主」Hostが91であれば、次のようにします。

        UCLA  -> S = X'41'
           7  -> M = X'40'
          91  -> M = X'00'
then for
        UCLA-7, S + M = X'01' = 1 base 10
        UCLA-91,S + M = X'41' = 65 base 10

and
        UCLA alone = X'41' = 65 base 10

        UCLA  -> S = X'41'
           7  -> M = X'40'
          91  -> M = X'00'
then for
        UCLA-7, S + M = X'01' = 1 base 10
        UCLA-91,S + M = X'41' = 65 base 10

and
        UCLA alone = X'41' = 65 base 10

If the primary Host at BBN is TENEX System A, let

BBNの主ホストがTENEXのSystem Aであれば、次のようにします。

        BBN  ->  S = X'45'
        516  ->  M = X'40'
        10A  ->  M = X'00'
        10B  ->  M = X'C0'
then for
        BBN-516, S + M = X'05' = 5 base 10
        BBN-10A, S + M = X'45' = 69 base 10
        BBN-10B, S + M = X'85' = 133 base 10

and
        BBN alone = X'45' = 69 base 10

        BBN  ->  S = X'45'
        516  ->  M = X'40'
        10A  ->  M = X'00'
        10B  ->  M = X'C0'
then for
        BBN-516, S + M = X'05' = 5 base 10
        BBN-10A, S + M = X'45' = 69 base 10
        BBN-10B, S + M = X'85' = 133 base 10

and
        BBN alone = X'45' = 69 base 10

The primary Host for each IMP would be designated by the site and such information disseminated by the NIC.

各IMPの主ホストはサイトが指定し、その情報はNICが広めることになります。
