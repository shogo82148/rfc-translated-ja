RFC 8809

Registries for Web Authentication (WebAuthn)

RFC 8809

Web認証（WebAuthn）のためのレジストリー

Abstract

概要

This specification defines IANA registries for W3C Web Authentication (WebAuthn) attestation statement format identifiers and extension identifiers.

この仕様は、W3CのWeb認証（WebAuthn）のアテステーションステートメント形式識別子と拡張識別子のためのIANAレジストリーを定義します。

1. Introduction

1. はじめに

This specification establishes IANA registries for W3C Web Authentication [WebAuthn] attestation statement format identifiers and extension identifiers. The initial values for these registries are in the IANA Considerations section of the [WebAuthn] specification.

この仕様は、W3CのWeb認証（WebAuthn）[WebAuthn]のアテステーションステートメント形式識別子と拡張識別子のためのIANAレジストリーを設立します。 これらのレジストリーの初期値は、[WebAuthn]仕様のIANAに関する考慮事項のセクションにあります。

1.1. Requirements Notation and Conventions

1.1. 要件の表記と規則

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

キーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、 「要求されています（REQUIRED）」、 「することになります（SHALL）」、「することはありません（SHALL NOT）」、 「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、 「推奨されます（RECOMMENDED）」、「推奨されません（NOT RECOMMENDED）」、 「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、 BCP 14 [RFC2119] [RFC8174]に記載されているとおりに解釈されるものとします。 ただし、ここに示すようにすべて大文字で表示される場合に限ります。

2. IANA Considerations

2. IANAに関する考慮事項

This specification establishes two registries:

この仕様は、次の2つのレジストリーを設立します。

  • the "WebAuthn Attestation Statement Format Identifiers" registry (see Section 2.1)
  • the "WebAuthn Extension Identifiers" registry (see Section 2.2)
  • 「WebAuthn Attestation Statement Format Identifiers」レジストリー（Section 2.1を参照）
  • 「WebAuthn Extension Identifiers」レジストリー（Section 2.2を参照）

Any additional processes established by the expert(s) after the publication of this document will be recorded on the registry web page at the discretion of the expert(s).

この文書の発行後に専門家が定めた追加の手続きは、専門家の裁量でレジストリーのWebページに記録されます。

2.1. WebAuthn Attestation Statement Format Identifiers Registry

2.1. WebAuthnアテステーションステートメント形式識別子レジストリー

WebAuthn attestation statement format identifiers are strings whose semantic, syntactic, and string-matching criteria are specified in the "Attestation Statement Format Identifiers" section of [WebAuthn], along with the concepts of attestation and attestation statement formats.

WebAuthnのアテステーションステートメント形式識別子は文字列であり、その意味、構文、文字列照合の基準は、アテステーションとアテステーションステートメント形式の概念とともに、[WebAuthn]の「Attestation Statement Format Identifiers」セクションで規定されています。

Registered attestation statement format identifiers are those that have been added to the registry by following the procedure in Section 2.1.1.

登録済みのアテステーションステートメント形式識別子とは、Section 2.1.1の手順に従ってレジストリーに追加されたものです。

Each attestation statement format identifier added to this registry MUST be unique amongst the set of registered attestation statement format identifiers.

このレジストリーに追加される各アテステーションステートメント形式識別子は、登録済みのアテステーションステートメント形式識別子の集合の中で一意でなければなりません（MUST）。

Registered attestation statement format identifiers MUST be a maximum of 32 octets in length and MUST consist only of printable ASCII [RFC20] characters, excluding backslash and double quote, i.e., VCHAR as defined in [RFC5234] but without %x22 and %x5c. Attestation statement format identifiers are case sensitive and may not match other registered identifiers in a case-insensitive manner unless the designated experts determine that there is a compelling reason to allow an exception.

登録済みのアテステーションステートメント形式識別子は、長さが最大32オクテットでなければなりません（MUST）。 また、バックスラッシュと二重引用符を除く印字可能なASCII[RFC20]文字だけで構成されなければなりません（MUST）。 つまり、[RFC5234]で定義されているVCHARから%x22と%x5cを除いたものです。 アテステーションステートメント形式識別子は大文字と小文字を区別します。 また、例外を認めるやむを得ない理由があると指定専門家が判断しない限り、大文字と小文字を区別せずに比較したときに他の登録済み識別子と一致するものは登録できません。

2.1.1. Registering Attestation Statement Format Identifiers

2.1.1. アテステーションステートメント形式識別子の登録

WebAuthn attestation statement format identifiers are registered using the Specification Required policy (see Section 4.6 of [RFC8126]).

WebAuthnのアテステーションステートメント形式識別子は、Specification Requiredポリシー（[RFC8126]のSection 4.6を参照）を使用して登録されます。

The "WebAuthn Attestation Statement Format Identifiers" registry is located at <https://www.iana.org/assignments/webauthn>. Registration requests can be made by following the instructions located there or by sending an email to the webauthn-reg-review@ietf.org mailing list.

「WebAuthn Attestation Statement Format Identifiers」レジストリーは<https://www.iana.org/assignments/webauthn>にあります。 登録リクエストは、そこにある指示に従うか、webauthn-reg-review@ietf.orgメーリングリストに電子メールを送ることで行えます。

Registration requests consist of at least the following information:

登録リクエストは、少なくとも次の情報で構成されます。

WebAuthn Attestation Statement Format Identifier:
An identifier meeting the requirements given in Section 2.1.
Description:
A relatively short description of the attestation format.
Specification Document(s):
Reference to the document or documents that specify the attestation statement format.
Change Controller:
For Standards Track RFCs, list "IETF". For others, give the name of the responsible party. Other details (e.g., postal address, email address, home page URI) may also be included.
Notes:
[optional]
WebAuthnアテステーションステートメント形式識別子（WebAuthn Attestation Statement Format Identifier）：
Section 2.1で示した要件を満たす識別子。
説明（Description）：
アテステーション形式の比較的短い説明。
仕様文書（Specification Document(s)）：
アテステーションステートメント形式を規定する文書（1つまたは複数）への参照。
変更管理者（Change Controller）：
標準化過程のRFCの場合は「IETF」と記載します。 それ以外の場合は、責任者の名前を記載します。 その他の詳細（たとえば、郵便の宛先、電子メールアドレス、ホームページのURI）を含めることもできます。
注記（Notes）：
［任意］

Registrations MUST reference a freely available, stable specification, e.g., as described in Section 4.6 of [RFC8126]. This specification MUST include security and privacy considerations relevant to the attestation statement format.

登録は、自由に入手可能で安定した仕様（たとえば、[RFC8126]のSection 4.6で説明されているもの）を参照しなければなりません（MUST）。 この仕様には、そのアテステーションステートメント形式に関連するセキュリティーとプライバシーに関する考慮事項を含めなければなりません（MUST）。

Note that WebAuthn attestation statement format identifiers can be registered by third parties (including the expert(s) themselves), if the expert(s) determines that an unregistered attestation statement format is widely deployed and not likely to be registered in a timely manner otherwise. Such registrations still are subject to the requirements defined, including the need to reference a specification.

登録されていないアテステーションステートメント形式が広く展開されており、ほかの方法では適時に登録されそうにないと専門家が判断した場合には、WebAuthnのアテステーションステートメント形式識別子を第三者（専門家自身を含む）が登録できることに注意してください。 そのような登録であっても、仕様を参照する必要があることを含め、定められた要件に従います。

2.1.2. Registration Request Processing

2.1.2. 登録リクエストの処理

As noted in Section 2.1.1, WebAuthn attestation statement format identifiers are registered using the Specification Required policy.

Section 2.1.1で述べたように、WebAuthnのアテステーションステートメント形式識別子はSpecification Requiredポリシーを使用して登録されます。

The expert(s) will clearly identify any issues that cause a registration to be refused, such as an incompletely specified attestation format.

専門家は、アテステーション形式の規定が不完全であるなど、登録が拒否される原因となる問題を明確に指摘します。

When a request is approved, the expert(s) will inform IANA, and the registration will be processed. The IESG is the arbiter of any objection.

リクエストが承認されると、専門家はIANAに通知し、登録が処理されます。 異議がある場合はIESGが裁定します。

2.1.3. Initial Values in the WebAuthn Attestation Statement Format Identifiers Registry

2.1.3. WebAuthnアテステーションステートメント形式識別子レジストリーの初期値

The initial values for the "WebAuthn Attestation Statement Format Identifiers" registry have been populated with the values listed in the "WebAuthn Attestation Statement Format Identifier Registrations" section of [WebAuthn]. Also, the Change Controller entry for each of those registrations is:

「WebAuthn Attestation Statement Format Identifiers」レジストリーの初期値には、[WebAuthn]の「WebAuthn Attestation Statement Format Identifier Registrations」セクションに記載されている値が設定されています。 また、それらの各登録の変更管理者（Change Controller）のエントリーは次のとおりです。

Change Controller:
W3C Web Authentication Working Group (public‑webauthn@w3.org)
変更管理者（Change Controller）：
W3C Web Authentication Working Group (public‑webauthn@w3.org)

2.2. WebAuthn Extension Identifiers Registry

2.2. WebAuthn拡張識別子レジストリー

WebAuthn extension identifiers are strings whose semantic, syntactic, and string-matching criteria are specified in the "Extension Identifiers" section of [WebAuthn].

WebAuthnの拡張識別子は文字列であり、その意味、構文、文字列照合の基準は、[WebAuthn]の「Extension Identifiers」セクションで規定されています。

Registered extension identifiers are those that have been added to the registry by following the procedure in Section 2.2.1.

登録済みの拡張識別子とは、Section 2.2.1の手順に従ってレジストリーに追加されたものです。

Each extension identifier added to this registry MUST be unique amongst the set of registered extension identifiers.

このレジストリーに追加される各拡張識別子は、登録済みの拡張識別子の集合の中で一意でなければなりません（MUST）。

Registered extension identifiers MUST be a maximum of 32 octets in length and MUST consist only of printable ASCII characters, excluding backslash and double quote, i.e., VCHAR as defined in [RFC5234] but without %x22 and %x5c. Extension identifiers are case sensitive and may not match other registered identifiers in a case-insensitive manner unless the designated experts determine that there is a compelling reason to allow an exception.

登録済みの拡張識別子は、長さが最大32オクテットでなければなりません（MUST）。 また、バックスラッシュと二重引用符を除く印字可能なASCII文字だけで構成されなければなりません（MUST）。 つまり、[RFC5234]で定義されているVCHARから%x22と%x5cを除いたものです。 拡張識別子は大文字と小文字を区別します。 また、例外を認めるやむを得ない理由があると指定専門家が判断しない限り、大文字と小文字を区別せずに比較したときに他の登録済み識別子と一致するものは登録できません。

2.2.1. Registering Extension Identifiers

2.2.1. 拡張識別子の登録

WebAuthn extension identifiers are registered using the Specification Required policy (see Section 4.6 of [RFC8126]).

WebAuthnの拡張識別子は、Specification Requiredポリシー（[RFC8126]のSection 4.6を参照）を使用して登録されます。

The "WebAuthn Extension Identifiers" registry is located at <https://www.iana.org/assignments/webauthn>. Registration requests can be made by following the instructions located there or by sending an email to the webauthn-reg-review@ietf.org mailing list.

「WebAuthn Extension Identifiers」レジストリーは<https://www.iana.org/assignments/webauthn>にあります。 登録リクエストは、そこにある指示に従うか、webauthn-reg-review@ietf.orgメーリングリストに電子メールを送ることで行えます。

Registration requests consist of at least the following information:

登録リクエストは、少なくとも次の情報で構成されます。

WebAuthn Extension Identifier:
An identifier meeting the requirements given in Section 2.2.
Description:
A relatively short description of the extension.
Specification Document(s):
Reference to the document or documents that specify the extension.
Change Controller:
For Standards Track RFCs, list "IETF". For others, give the name of the responsible party. Other details (e.g., postal address, email address, home page URI) may also be included.
Notes:
[optional]
WebAuthn拡張識別子（WebAuthn Extension Identifier）：
Section 2.2で示した要件を満たす識別子。
説明（Description）：
拡張の比較的短い説明。
仕様文書（Specification Document(s)）：
拡張を規定する文書（1つまたは複数）への参照。
変更管理者（Change Controller）：
標準化過程のRFCの場合は「IETF」と記載します。 それ以外の場合は、責任者の名前を記載します。 その他の詳細（たとえば、郵便の宛先、電子メールアドレス、ホームページのURI）を含めることもできます。
注記（Notes）：
［任意］

Registrations MUST reference a freely available, stable specification, e.g., as described in Section 4.6 of [RFC8126]. This specification MUST include security and privacy considerations relevant to the extension.

登録は、自由に入手可能で安定した仕様（たとえば、[RFC8126]のSection 4.6で説明されているもの）を参照しなければなりません（MUST）。 この仕様には、その拡張に関連するセキュリティーとプライバシーに関する考慮事項を含めなければなりません（MUST）。

Note that WebAuthn extensions can be registered by third parties (including the expert(s) themselves), if the expert(s) determines that an unregistered extension is widely deployed and not likely to be registered in a timely manner otherwise. Such registrations still are subject to the requirements defined, including the need to reference a specification.

登録されていない拡張が広く展開されており、ほかの方法では適時に登録されそうにないと専門家が判断した場合には、WebAuthnの拡張を第三者（専門家自身を含む）が登録できることに注意してください。 そのような登録であっても、仕様を参照する必要があることを含め、定められた要件に従います。

2.2.2. Registration Request Processing

2.2.2. 登録リクエストの処理

As noted in Section 2.2.1, WebAuthn extension identifiers are registered using the Specification Required policy.

Section 2.2.1で述べたように、WebAuthnの拡張識別子はSpecification Requiredポリシーを使用して登録されます。

The expert(s) will clearly identify any issues that cause a registration to be refused, such as an incompletely specified extension.

専門家は、拡張の規定が不完全であるなど、登録が拒否される原因となる問題を明確に指摘します。

When a request is approved, the expert(s) will inform IANA, and the registration will be processed. The IESG is the arbiter of any objection.

リクエストが承認されると、専門家はIANAに通知し、登録が処理されます。 異議がある場合はIESGが裁定します。

「WebAuthn Extension Identifiers」レジストリーの初期値には、[WebAuthn]の「WebAuthn Extension Identifier Registrations」セクションに記載されている値が設定されています。 また、それらの各登録の変更管理者（Change Controller）のエントリーは次のとおりです。
