RFC 10079

Updates to the SFrame Cipher Suites Registry

RFC 10079

SFrame暗号スイートレジストリーの更新

Abstract

概要

This document addresses two omissions in the Secure Frame (SFrame) protocol specification. First, the definition of the IANA "SFrame Cipher Suites" registry in RFC 9605 omits several important fields. This document updates the IANA registry by adding those fields and defining the contents of those fields for current entries. Second, the Authenticated Encryption with Associated Data (AEAD) construction based on AES-CTR and HMAC is defined only for the 128-bit security level. This document registers parallel constructions at the 256-bit security level.

この文書は、Secure Frame（SFrame）プロトコル仕様における2つの欠落に対処します。 第一に、RFC 9605におけるIANAの「SFrame Cipher Suites」レジストリーの定義には、いくつかの重要なフィールドが欠けています。 この文書は、それらのフィールドを追加し、既存のエントリーについてそれらのフィールドの内容を定義することで、IANAレジストリーを更新します。 第二に、AES-CTRとHMACに基づく認証付き暗号（Authenticated Encryption with Associated Data、AEAD）の構成は、128ビットのセキュリティーレベルについてのみ定義されています。 この文書は、256ビットのセキュリティーレベルで同様の構成を登録します。

1. Introduction

1. はじめに

This document addresses two omissions in the Secure Frame (SFrame) protocol specification [RFC9605]. First, in Section 8.1 of [RFC9605], the definition of the IANA "SFrame Cipher Suites" registry omits several important fields. This document defines the required fields and the contents of those fields for current entries. IANA has updated the registry accordingly. Second, the AEAD construction based on AES-CTR and HMAC (in Section 4.5.1 of [RFC9605]) is defined only for the 128-bit security level. This document registers parallel constructions at the 256-bit security level.

この文書は、Secure Frame（SFrame）プロトコル仕様[RFC9605]における2つの欠落に対処します。 第一に、[RFC9605]のSection 8.1におけるIANAの「SFrame Cipher Suites」レジストリーの定義には、いくつかの重要なフィールドが欠けています。 この文書は、必要なフィールドと、既存のエントリーにおけるそれらのフィールドの内容を定義します。 IANAは、これに従ってレジストリーを更新しました。 第二に、AES-CTRとHMACに基づくAEADの構成（[RFC9605]のSection 4.5.1）は、128ビットのセキュリティーレベルについてのみ定義されています。 この文書は、256ビットのセキュリティーレベルで同様の構成を登録します。

2. AES-256-CTR with HMAC-SHA512

2. HMAC-SHA512を伴うAES-256-CTR

Section 4.5.1 of [RFC9605] defines a compound authenticated encryption construction, using the unauthenticated Counter (CTR) mode of AES for encryption and HMAC for authentication.

[RFC9605]のSection 4.5.1は、暗号化に認証なしのAESカウンター（Counter、CTR）モードを使用し、認証にHMACを使用する、複合的な認証付き暗号の構成を定義しています。

The original specification only defines cipher suite values for instances of this construction using AES-128-CTR and HMAC-SHA256. The construction works the same way when used with AES-256-CTR and HMAC-SHA512. The only differences are in the lengths of some SFrame intermediate values:

元の仕様では、AES-128-CTRとHMAC-SHA256を使用するこの構成のインスタンスについてのみ、暗号スイートの値を定義しています。 この構成は、AES-256-CTRとHMAC-SHA512で使用する場合も同じように動作します。 違いは、いくつかのSFrameの中間値の長さだけです。

  • The keys generated by SFrame key derivation (derive_key_salt) are longer to match the needs of AES-256-CTR and HMAC-SHA512 (96 bytes vs. 48 bytes for AES-128-CTR and HMAC-SHA256).

  • The initial tag value tag in compute_tag is 64 bytes instead of 32 bytes.

  • SFrameの鍵導出（derive_key_salt）で生成する鍵は、AES-256-CTRとHMAC-SHA512の必要に合わせて長くなります（AES-128-CTRとHMAC-SHA256の48バイトに対して96バイト）。

  • compute_tagにおけるタグの初期値tagは、32バイトではなく64バイトになります。

Identifiers for cipher suites using AES-256-CTR and HMAC-SHA512 are defined in Section 4.2.

AES-256-CTRとHMAC-SHA512を使用する暗号スイートの識別子は、Section 4.2で定義します。

3. Security Considerations

3. セキュリティーに関する考慮事項

The registry changes in this document have no effect on the security of SFrame.

この文書によるレジストリーの変更は、SFrameのセキュリティーに影響しません。

The new algorithms registered by this document allow the construction combining AES-CTR with HMAC to be used in environments that require a 256-bit security level.

この文書で登録する新しいアルゴリズムにより、AES-CTRとHMACを組み合わせた構成を、256ビットのセキュリティーレベルを必要とする環境で使用できるようになります。

4. IANA Considerations

4. IANAに関する考慮事項

Per this document, IANA has updated the columns in the "SFrame Cipher Suites" registry (see Section 4.1), added entries to the updated registry for the new cipher suites defined in this document (see Section 4.2), and added this document as an additional reference for this registry.

この文書に従って、IANAは「SFrame Cipher Suites」レジストリーの列を更新し（Section 4.1を参照）、この文書で定義する新しい暗号スイートのエントリーを更新後のレジストリーに追加し（Section 4.2を参照）、このレジストリーの追加の参照先としてこの文書を加えました。

4.1. Updates to the SFrame Cipher Suites Registry

4.1. SFrame暗号スイートレジストリーの更新

IANA has added the following columns to the "SFrame Cipher Suites" registry. This document also updates the registration template in Section 8.1 of [RFC9605] to include these fields, which are placed between the "Name" and "Recommended" fields.

IANAは、「SFrame Cipher Suites」レジストリーに次の列を追加しました。 この文書は、[RFC9605]のSection 8.1の登録テンプレートも更新し、これらのフィールドを含めます。 これらのフィールドは、「Name」フィールドと「Recommended」フィールドの間に置きます。

  • Nh: The size in bytes of the output of the hash function.

  • Nka: For cipher suites using the compound AEAD described in Section 4.5.1 of [RFC9605], the size in bytes of a key for the underlying encryption algorithm; for other cipher suites, the value is "n/a".

  • Nk: The size in bytes of a key for the encryption algorithm.

  • Nn: The size in bytes of a nonce for the encryption algorithm.

  • Nt: The overhead in bytes of the encryption algorithm (typically the size of a "tag" that is added to the plaintext).

  • Nh：ハッシュ関数の出力のバイト単位のサイズ。

  • Nka：[RFC9605]のSection 4.5.1で説明する複合AEADを使用する暗号スイートでは、下位の暗号化アルゴリズムの鍵のバイト単位のサイズ。 その他の暗号スイートでは、値は「n/a」です。

  • Nk：暗号化アルゴリズムの鍵のバイト単位のサイズ。

  • Nn：暗号化アルゴリズムのノンスのバイト単位のサイズ。

  • Nt：暗号化アルゴリズムのバイト単位のオーバーヘッド（通常は、平文に付加する「タグ」のサイズ）。

The registration procedures in Section 8.1 of [RFC9605] are otherwise unchanged.

それ以外の点では、[RFC9605]のSection 8.1の登録手続きに変更はありません。

Appendix A. Test Vectors

Appendix A. テストベクター

This appendix provides a set of test vectors that implementations can use to verify that they correctly implement SFrame encryption and decryption with the cipher suites registered in this document. Test vectors are provided for both the AES-256-CTR-HMAC construction and full SFrame encryption with the new cipher suites.

この付録では、この文書で登録する暗号スイートを使ったSFrameの暗号化と復号を正しく実装していることを検証するために、実装が使用できる一連のテストベクターを提供します。 テストベクターは、AES-256-CTR-HMACの構成と、新しい暗号スイートを使ったSFrameの暗号化全体の両方について提供します。

All values are either numeric or byte strings. Numeric values are represented as hex values, prefixed with 0x. Byte strings are represented in hex encoding.

すべての値は、数値またはバイト文字列のいずれかです。 数値は、0xを前に付けた16進数の値で表します。 バイト文字列は、16進数エンコーディングで表します。

Line breaks and whitespace within values are inserted to conform to the width requirements of the RFC format. They should be removed before use.

値の中の改行や空白は、RFCフォーマットの幅の要件にあわせるために挿入したものです。 使用する前に取り除いてください。

These test vectors are also available in JSON format at [TestVectors]. In the JSON test vectors, numeric values are JSON numbers and byte string values are JSON strings containing the hex encoding of the byte strings.

これらのテストベクターは、JSON形式でも[TestVectors]から入手できます。 JSON形式のテストベクターでは、数値はJSONの数値であり、バイト文字列の値はバイト文字列を16進数エンコーディングしたものを含むJSONの文字列です。

For each case, we provide:

各ケースについて、次の値を提供します。

  • key: The key input to encryption/decryption

  • enc_key: The encryption subkey produced by the derive_subkeys() algorithm

  • auth_key: The authentication subkey produced by the derive_subkeys() algorithm

  • nonce: The nonce input to encryption/decryption

  • aad: The aad input to encryption/decryption

  • ct: The ciphertext

  • nonce：暗号化／復号へのnonce入力

  • aad：暗号化／復号へのaad入力

  • pt：平文

  • ct：暗号文

An implementation should verify that the following are true, where AEAD.Encrypt and AEAD.Decrypt are as defined in Section 4.5.1 of [RFC9605]:

  • AEAD.Decrypt(key, nonce, aad, ct) == pt
