RFC 2842

Capabilities Advertisement with BGP-4

RFC 2842

BGP-4による能力広告

Abstract

概要

Currently BGP-4 [BGP-4] requires that when a BGP speaker receives an OPEN message with one or more unrecognized Optional Parameters, the speaker must terminate BGP peering. This complicates introduction of new capabilities in BGP.

現在のBGP-4[BGP-4]では、BGPスピーカーは、認識できないオプションパラメーター（Optional Parameter）を1つ以上含むOPENメッセージを受信した場合、BGPピアリングを終了しなければならないとされています。このことが、BGPに新しい能力を導入することを難しくしています。

This document defines new Optional Parameter, called Capabilities, that is expected to facilitate introduction of new capabilities in BGP by providing graceful capability advertisement without requiring that BGP peering be terminated.

この文書は、「能力（Capabilities）」と呼ぶ新しいオプションパラメーターを定義します。このパラメーターは、BGPピアリングを終了させることなく能力を穏やかに広告する手段を提供することで、BGPに新しい能力を導入しやすくすることが期待されます。

1. Overview of Operations

1. 動作の概要

When a BGP speaker that supports capabilities advertisement sends an OPEN message to its BGP peer, the message may include an Optional Parameter, called Capabilities. The parameter lists the capabilities supported by the speaker.

能力広告をサポートするBGPスピーカーがBGPピアにOPENメッセージを送信する場合、そのメッセージに「能力（Capabilities）」と呼ぶオプションパラメーターを含めることがあります。このパラメーターは、そのスピーカーがサポートする能力を列挙します。

A BGP speaker determines the capabilities supported by its peer by examining the list of capabilities present in the Capabilities Optional Parameter carried by the OPEN message that the speaker receives from the peer.

BGPスピーカーは、ピアから受信したOPENメッセージで運ばれる能力オプションパラメーターに含まれる能力の一覧を調べることで、そのピアがサポートする能力を判断します。

A BGP speaker that supports a particular capability may use this capability with its peer after the speaker determines (as described above) that the peer supports this capability.

特定の能力をサポートするBGPスピーカーは、（上で説明したように）ピアがその能力をサポートしていると判断した後に、そのピアとの間でその能力を使用できます。

A BGP speaker determines that its peer doesn't support capabilities advertisement, if in response to an OPEN message that carries the Capabilities Optional Parameter, the speaker receives a NOTIFICATION message with the Error Subcode set to Unsupported Optional Parameter. In this case the speaker should attempt to re-establish a BGP connection with the peer without sending to the peer the Capabilities Optional Parameter.

能力オプションパラメーターを含むOPENメッセージへの応答として、エラーサブコード（Error Subcode）がUnsupported Optional Parameterに設定されたNOTIFICATIONメッセージを受信した場合、BGPスピーカーは、ピアが能力広告をサポートしていないと判断します。この場合、スピーカーは、能力オプションパラメーターをピアに送信せずに、ピアとのBGPコネクションの再確立を試みるべきです。

If a BGP speaker that supports a certain capability determines that its peer doesn't support this capability, the speaker may send a NOTIFICATION message to the peer, and terminate peering. The Error Subcode in the message is set to Unsupported Capability. The message should contain the capability (capabilities) that causes the speaker to send the message. The decision to send the message and terminate peering is local to the speaker. Such peering should not be re-established automatically.

ある能力をサポートするBGPスピーカーが、ピアがその能力をサポートしていないと判断した場合、スピーカーはピアにNOTIFICATIONメッセージを送信して、ピアリングを終了することがあります。このメッセージのエラーサブコードはUnsupported Capabilityに設定します。このメッセージには、スピーカーがメッセージを送信する原因となった能力を含めるべきです。メッセージを送信してピアリングを終了するかどうかの決定は、そのスピーカーのローカルな判断です。そのようなピアリングは自動的に再確立すべきではありません。

2. Capabilities Optional Parameter (Parameter Type 2):

2. 能力オプションパラメーター（パラメータータイプ2）：

This is an Optional Parameter that is used by a BGP speaker to convey to its BGP peer the list of capabilities supported by the speaker.

これは、BGPスピーカーが、自身がサポートする能力の一覧をBGPピアに伝えるために使用するオプションパラメーターです。

The parameter contains one or more triples <Capability Code, Capability Length, Capability Value>, where each triple is encoded as shown below:

このパラメーターは、<Capability Code, Capability Length, Capability Value>の3つ組を1つ以上含みます。それぞれの3つ組は次のように符号化されます。

      +------------------------------+
      | Capability Code (1 octet)    |
      +------------------------------+
      | Capability Length (1 octet)  |
      +------------------------------+
      | Capability Value (variable)  |
      +------------------------------+

      +------------------------------+
      | Capability Code (1 octet)    |
      +------------------------------+
      | Capability Length (1 octet)  |
      +------------------------------+
      | Capability Value (variable)  |
      +------------------------------+

The use and meaning of these fields are as follows:

これらのフィールドの用途と意味は次のとおりです。

Capability Code:
Capability Code is a one octet field that unambiguously identifies individual capabilities.
Capability Length:
Capability Length is a one octet field that contains the length of the Capability Value field in octets.
Capability Value:
Capability Value is a variable length field that is interpreted according to the value of the Capability Code field.
Capability Code：
Capability Codeは、個々の能力を一意に識別する1オクテットのフィールドです。
Capability Length：
Capability Lengthは、Capability Valueフィールドの長さをオクテット単位で格納する1オクテットのフィールドです。
Capability Value：
Capability Valueは、Capability Codeフィールドの値に従って解釈される可変長のフィールドです。

A particular capability, as identified by its Capability Code, may occur more than once within the Optional Parameter.

Capability Codeで識別される特定の能力が、オプションパラメーター内に2回以上現れることがあります。

3. Extensions to Error Handling

3. エラー処理の拡張

This document defines new Error Subcode - Unsupported Capability. The value of this Subcode is 7. The Data field in the NOTIFICATION message lists the set of capabilities that cause the speaker to send the message. Each such capability is encoded the same way as it was encoded in the received OPEN message.

この文書は、新しいエラーサブコードとしてUnsupported Capabilityを定義します。このサブコードの値は7です。NOTIFICATIONメッセージのDataフィールドには、スピーカーがメッセージを送信する原因となった能力の集合を列挙します。そのような能力はそれぞれ、受信したOPENメッセージで符号化されていたのと同じ方法で符号化します。

4. IANA Considerations

4. IANAに関する考慮事項

Section 4 defines a Capability Optional Parameter along with an Capability Code field. IANA is expected to create and maintain the registry for Capability Code values. Capability Code value 0 is reserved. Capability Code values 1 through 63 are to be assigned by IANA using the "IETF Consensus" policy defined in RFC2434. Capability Code values 64 through 127 are to be assigned by IANA, using the "First Come First Served" policy defined in RFC2434. Capability Code values 128 through 255 are for "Private Use" as defined in RFC2434.

セクション4は、Capability Codeフィールドとともに能力オプションパラメーターを定義します。IANAは、Capability Codeの値のレジストリーを作成し、維持することが期待されます。Capability Codeの値0は予約済みです。Capability Codeの値1から63は、RFC2434で定義された「IETF Consensus」ポリシーを用いてIANAが割り当てます。Capability Codeの値64から127は、RFC2434で定義された「First Come First Served」ポリシーを用いてIANAが割り当てます。Capability Codeの値128から255は、RFC2434で定義された「Private Use」のためのものです。

5. Security Considerations

5. セキュリティーに関する考慮事項

This extension to BGP does not change the underlying security issues inherent in the existing BGP [Heffernan].

このBGPの拡張は、既存のBGP[Heffernan]に内在する根本的なセキュリティーの問題を変えるものではありません。
