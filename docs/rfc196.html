RFC 196

Mail Box Protocol

RFC 196

メールボックスプロトコル

Abstract

概要

The purpose of this protocol is to provide at each site a standard mechanism to receive sequential files for immediate or deferred printing or other uses. The files for deferred printing would probably be stored on intermediate disk files, although details of how a file is handled, stored, manipulated, or printed at a site are not the concern of this protocol.

このプロトコルの目的は、即時もしくは後での印刷、またはその他の用途のためのシーケンシャルファイルを受信する標準的な仕組みを各サイトに提供することです。後で印刷するファイルは、おそらく中間のディスクファイルに格納されることになりますが、サイトでファイルをどのように扱い、格納し、操作し、印刷するかの詳細は、このプロトコルの関知するところではありません。

It is also assumed that there would be a program at the sending site which sends the file in the format given below with the optional control codes when appropriate. This program could probably be accessed as a subcommand of the Telnet program.

また、送信側のサイトには、必要に応じてオプションの制御コードを付けて、以下に示す形式でファイルを送信するプログラムがあることを想定しています。このプログラムには、おそらくTelnetプログラムのサブコマンドとしてアクセスできるでしょう。

The motivation for developing this protocol is the Network Information Center's (NIC) need to be able to deliver messages and documents to remote sites, and to be able to receive documents for cataloging, redistribution, and other purposes from remote site without having to know the details of path name conventions and file system commands at each site. Multiple mail boxes (128) are allowed at each site and are identified as described below. The default is mail box number 0 for use with the standard mail printer defined below.

このプロトコルを開発した動機は、ネットワークインフォメーションセンター（NIC）が、各サイトのパス名の規則やファイルシステムのコマンドの詳細を知らなくても、リモートのサイトにメッセージや文書を届けられるようにし、また目録作成、再配布、その他の目的のためにリモートのサイトから文書を受け取れるようにする必要があることです。各サイトでは複数のメールボックス（128個）を使用でき、以下で説明するように識別されます。デフォルトはメールボックス番号0で、以下で定義する標準のメールプリンターで使用します。

A mail box, as we see it, is simply a sequential file to which messages and documents are appended, separated by an appropriate site dependent code.

私たちの考えでは、メールボックスとは単に、メッセージや文書がサイトに依存する適切なコードで区切られて追記されていくシーケンシャルファイルのことです。

Although this protocol will enable people to transmit messages directly without going through the NIC, we want to encourage people to use the NIC as much as possible, so that dialogue will be recorded, cataloged and available for viewing online at NIC, using the powerful facilities of the ARC on Line System (NLS).

このプロトコルによって、NICを経由せずに直接メッセージを送信できるようになりますが、私たちはできるだけNICを使うことを推奨したいと考えています。そうすれば、やり取りが記録され、目録化され、ARC on Line System（NLS）の強力な機能を使ってNICでオンラインで閲覧できるようになるからです。

The Mail Box Protocol will use established network conventions, specifically the Network Control Program, Initial Connection Protocol, and Data Transfer Protocol, NIC 7104.

メールボックスプロトコルは、確立されたネットワークの規約、具体的にはネットワーク制御プログラム（Network Control Program）、初期接続プロトコル（Initial Connection Protocol）、データ転送プロトコル（Data Transfer Protocol、NIC 7104）を使用します。

The normal transmission is to be full 7-bit ASCII in 8-bit bytes, the high order bit set to zero.

通常の伝送は、上位ビットを0にした8ビットバイトでの完全な7ビットASCIIとします。

The standard receiving mail printer for mail box number 0 is assumed to have a print line 72 characters wide, and a page of 66 lines. The new line convention will be carriage return (X'OD') followed by line feed (X'OA') as per the Telnet Protocol RFC 158, NIC 6768. The standard printer will accept form feed (X'OC') as meaning move paper to the top of a new page.

メールボックス番号0の標準の受信メールプリンターは、印字行の幅が72文字、1ページが66行であると想定します。改行の規約は、TelnetプロトコルのRFC 158（NIC 6768）に従い、キャリッジリターン（X'OD'）に続くラインフィード（X'OA'）とします。標準のプリンターは、改ページ（X'OC'）を、用紙を新しいページの先頭に移動するという意味として受け付けます。

It is the senders responsibility to control the length of the print line and page. If more than 72 characters per line are sent or if more than 66 lines are sent without a form feed, than the receiving site can handle these situations as appropriate for them. These conventions can be changed by control codes as described below.

印字行とページの長さを制御するのは送信者の責任です。1行に72文字を超えて送信された場合や、改ページなしで66行を超えて送信された場合、受信側のサイトはそれらの状況を自身にとって適切なように処理できます。これらの規約は、以下で説明するように制御コードによって変更できます。

A message or document being sent to any mail box is a string of 8 bit bytes.

任意のメールボックスに送信されるメッセージや文書は、8ビットバイトの列です。

At the head of the message or document sent to mail box number 0 there is to be an initial address string terminated by a form feed. This address string is to contain the sender's name and address, and the receiver's name and address formatted in some reasonable, easy-to-read form for a clerk to read and distribute. Comments could also be included in the address string.

メールボックス番号0に送信するメッセージや文書の先頭には、改ページで終わる最初のアドレス文字列を置きます。このアドレス文字列には、送信者の名前と住所、および受信者の名前と住所を、事務員が読んで配布できるような、妥当で読みやすい形式で含めます。アドレス文字列にはコメントを含めることもできます。

The format of information in mail boxes other than mail box number 0 is not explicitly defined by this protocol.

メールボックス番号0以外のメールボックス内の情報の形式は、このプロトコルでは明示的に定義しません。

Initial Connection

初期接続

Initial Connection will be as per the Official Initial Connection Protocol, Documents #2, NIC 7101, to a standard socket not yet assigned. A candidate socket number would be socket #5.

初期接続は、公式の初期接続プロトコル（Official Initial Connection Protocol、Documents #2、NIC 7101）に従い、まだ割り当てられていない標準のソケットに対して行います。候補となるソケット番号は、ソケット#5です。

Data Transmission

データ伝送

Data Transmission will be as per the Data Transfer Protocol, RFC 171, NIC 6793. That is, there will be a Modes Available handshake, and then transmission of special control information and data. A message or document is defined to be a block of data. Control information is to be global. That is, once a control mode is set it is assumed to apply during the life of the connection unless explicitly changed. More than one document may be sent during the life of the connection unless the infinite bit stream mode is used. In the latter case there will be one message or document per connection. A reasonable convention for control information sent using the infinite bit stream mode seems to be to assume that is applies only to the next data stream connection from the host which sent the control stream.

データ伝送は、データ転送プロトコル（Data Transfer Protocol、RFC 171、NIC 6793）に従います。つまり、Modes Availableのハンドシェイクを行い、その後に特別な制御情報とデータを伝送します。メッセージや文書は、データの1ブロックとして定義します。制御情報はグローバルです。つまり、いったん制御モードを設定すると、明示的に変更しない限り、コネクションが存続する間はそれが適用されるものとみなします。無限ビットストリームモードを使用しない限り、コネクションが存続する間に複数の文書を送信できます。無限ビットストリームモードの場合は、1つのコネクションにつき1つのメッセージまたは文書になります。無限ビットストリームモードを使って送信される制御情報についての妥当な規約は、それが、その制御ストリームを送信したホストからの次のデータストリームのコネクションにのみ適用されるとみなすことでしょう。

Control Information

制御情報

The sending process should be capable of allowing the user to indicate the control codes associated with the transmission of a mail item. The control codes can be used with any mail box number.

送信プロセスは、メール項目の伝送に関連する制御コードをユーザーが指定できるようにすべきです。制御コードは、任意のメールボックス番号で使用できます。

Mail Box Number

メールボックス番号

A site may find, as is the case at NIC, that it is useful to have more than one receiving mail box, each to be associated with a different process.

NICの場合のように、それぞれ異なるプロセスに関連付けた複数の受信メールボックスを持つと便利だと考えるサイトもあるでしょう。

The mail box number for material to be printed by the standard mail printer is mail box number 0 and is used by default.

標準のメールプリンターで印刷する資料のメールボックス番号はメールボックス番号0であり、デフォルトで使用されます。

Code X'DO'
Meaning: A seven bit binary number in an eight bit field with the high order bit set to zero is to follow indicating the receiving mail box number.
Code X'DO'
意味: 上位ビットを0にした8ビットのフィールドに入れた7ビットの2進数が続き、受信メールボックス番号を示します。

Transmission Code Type

伝送コードの種類

The default code type is 7-bit ASCII in an 8 bit field, high order bit to zero.

デフォルトのコードの種類は、上位ビットを0にした8ビットのフィールドでの7ビットASCIIです。

'Code X'AO'
Meaning: A Data Type signal indicating that the transmission code is 7-bit ASCII in an 8-bit field, high order set to zero.
Code X'A1'
Meaning: Transparency, i.e. a stream of 8 bit bytes.
Code X'A2'
Meaning: EBCDIC
'Code X'AO'
意味: 伝送コードが、上位ビットを0にした8ビットのフィールドでの7ビットASCIIであることを示すデータタイプ（Data Type）信号です。
Code X'A1'
意味: 透過（Transparency）、すなわち8ビットバイトのストリームです。
Code X'A2'
意味: EBCDICです。

Other character codes could be added in the future.

将来、他の文字コードを追加することもできます。

Printer Control Codes

プリンター制御コード

The default settings are a print line of 72 characters and a print page of 66 lines.

デフォルトの設定は、印字行が72文字、印字ページが66行です。

Code X'D1
Meaning: Set line width to 72 characters.
Code X'D2'
Meaning: Use the full width of your printer.
Code X'D3'
Meaning: Set page size to 66 lines.
Code X'D4'
Meaning: Set page size to infinite.
Code X'D1
意味: 行の幅を72文字に設定します。
Code X'D2'
意味: プリンターの幅全体を使用します。
Code X'D3'
意味: ページサイズを66行に設定します。
Code X'D4'
意味: ページサイズを無限に設定します。

Other virtual printer control codes can be added in the future.

将来、他の仮想プリンター制御コードを追加することもできます。

Other classes of control codes can be added as the need arises.

必要に応じて、他の種類の制御コードを追加することもできます。
