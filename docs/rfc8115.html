RFC 8115

DHCPv6 Option for IPv4-Embedded Multicast and Unicast IPv6 Prefixes

RFC 8115

IPv4埋め込みマルチキャストおよびユニキャストIPv6プレフィックスのためのDHCPv6オプション

Abstract

概要

This document defines a Dynamic Host Configuration Protocol version 6 (DHCPv6) Option for multicast IPv4 service continuity solutions, which is used to carry the IPv6 prefixes to be used to build unicast and multicast IPv4-embedded IPv6 addresses.

この文書は、マルチキャストのIPv4サービスの継続性を実現するソリューションのための、Dynamic Host Configuration Protocol version 6（DHCPv6）オプションを定義します。このオプションは、ユニキャストおよびマルチキャストのIPv4埋め込みIPv6アドレスを構築するために使用するIPv6プレフィックスを運ぶために使用されます。

1. Introduction

1. はじめに

Several solutions (e.g., [RFC8114]) are proposed for the delivery of multicast services in the context of transition to IPv6. Even if these solutions may have different applicable use cases, they all use specific IPv6 addresses that embed IPv4 addresses, for both multicast group and source addresses.

IPv6への移行という状況においてマルチキャストサービスを配送するために、いくつかのソリューション（たとえば[RFC8114]）が提案されています。これらのソリューションは適用されるユースケースが異なる場合もありますが、いずれも、マルチキャストグループアドレスと送信元アドレスの両方について、IPv4アドレスを埋め込んだ特定のIPv6アドレスを使用します。

This document defines a DHCPv6 option [RFC3315] that carries the IPv6 prefixes to be used for constructing these IPv4-embedded IPv6 addresses.

この文書は、これらのIPv4埋め込みIPv6アドレスを構築するために使用するIPv6プレフィックスを運ぶDHCPv6オプション[RFC3315]を定義します。

In particular, this option can be used in the context of Dual-Stack Lite (DS-Lite) [RFC6333], Stateless Address plus Port (A+P) [RFC6346], and other IPv4-IPv6 transition techniques.

特に、このオプションは、Dual-Stack Lite（DS-Lite）[RFC6333]、Stateless Address plus Port（A+P）[RFC6346]、およびその他のIPv4-IPv6移行技術の文脈で使用できます。

1.1. Requirements Language

1.1. 要件言語

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in RFC 2119 [RFC2119].

キーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、 「要求されています（REQUIRED）」、 「することになります（SHALL）」、「することはありません（SHALL NOT）」、 「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、 「推奨されます（RECOMMENDED）」、 「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、 RFC 2119[RFC2119]に記載されているとおりに解釈されるものとします。

2. Terminology

2. 用語

This document makes use of the following terms:

この文書では、次の用語を使用します。

IPv4-embedded IPv6 address:
an IPv6 address that embeds a 32-bit-encoded IPv4 address [RFC6052]. An IPv4-embedded IPv6 address can be a unicast or a multicast address.
Prefix64:

an IPv6 prefix used for synthesizing IPv4-embedded IPv6 addresses. A Prefix64 can be unicast or multicast.

Note: "64" is used as an abbreviation for IPv6-IPv4 interconnection.

ASM_mPrefix64:
a multicast Prefix64 that belongs to the Any-Source Multicast (ASM) range.
SSM_mPrefix64:
a multicast Prefix64 which belongs to the Source-Specific Multicast (SSM) [RFC4607] range.
uPrefix64:
a unicast Prefix64 for building the IPv4-embedded IPv6 addresses of multicast sources in SSM mode.
IPv4埋め込みIPv6アドレス（IPv4-embedded IPv6 address）：
32ビットで符号化されたIPv4アドレスを埋め込んだIPv6アドレスです[RFC6052]。IPv4埋め込みIPv6アドレスは、ユニキャストアドレスの場合もマルチキャストアドレスの場合もあります。
Prefix64:

IPv4埋め込みIPv6アドレスを合成するために使用するIPv6プレフィックスです。Prefix64は、ユニキャストの場合もマルチキャストの場合もあります。

注：「64」は、IPv6とIPv4の相互接続を表す略語として使用しています。

ASM_mPrefix64:
任意ソースマルチキャスト（Any-Source Multicast: ASM）の範囲に属するマルチキャストPrefix64です。
SSM_mPrefix64:
ソース固有マルチキャスト（Source-Specific Multicast: SSM）[RFC4607]の範囲に属するマルチキャストPrefix64です。
uPrefix64:
SSMモードにおけるマルチキャストの送信元のIPv4埋め込みIPv6アドレスを構築するためのユニキャストPrefix64です。

3. OPTION_V6_PREFIX64 DHCPv6 Option

3. OPTION_V6_PREFIX64 DHCPv6オプション

OPTION_V6_PREFIX64 (Figure 1) conveys the IPv6 prefix(es) to be used (e.g., by an mB4 [RFC8114]) to synthesize IPv4-embedded IPv6 addresses.

OPTION_V6_PREFIX64（図1）は、IPv4埋め込みIPv6アドレスを合成するために（たとえばmB4[RFC8114]によって）使用されるIPv6プレフィックスを運びます。

The fields of the option shown in Figure 1 are as follows:

図1に示したオプションのフィールドは次のとおりです。

option-code:
OPTION_V6_PREFIX64 (see Section 6).
option-length:
length of the option, in octets.
asm-length:
the prefix length for the ASM IPv4-embedded prefix, as an 8-bit unsigned integer. This field represents the number of valid leading bits in the prefix. This field MUST be set to 96.
ASM_mPrefix64:
this field identifies the IPv6 multicast prefix to be used to synthesize the IPv4-embedded IPv6 addresses of the multicast groups in the ASM mode. The conveyed multicast IPv6 prefix MUST belong to the ASM range.
ssm-length:
the prefix length for the SSM IPv4-embedded prefix, as an 8-bit unsigned integer. This field represents the number of valid leading bits in the prefix. This field MUST be set to 96.
SSM_mPrefix64:
this field identifies the IPv6 multicast prefix to be used to synthesize the IPv4-embedded IPv6 addresses of the multicast groups in SSM mode. The conveyed multicast IPv6 prefix MUST belong to the SSM range.
unicast-length:
the prefix length for the IPv6 unicast prefix to be used to synthesize the IPv4-embedded IPv6 addresses of the multicast sources, as an 8-bit unsigned integer. As specified in [RFC6052], the unicast-length MUST be one of 32, 40, 48, 56, 64, or 96. This field represents the number of valid leading bits in the prefix.
uPrefix64:
this field identifies the IPv6 unicast prefix to be used in SSM mode for constructing the IPv4-embedded IPv6 addresses representing the IPv4 multicast sources in the IPv6 domain. uPrefix64 may also be used to extract the IPv4 address from the received multicast data flows. It is a variable-size field with the length of the field defined by the unicast-length field and is rounded up to the nearest octet boundary. In this case, any additional padding bits must be zeroed. The address mapping MUST follow the guidelines documented in [RFC6052].
option-code:
OPTION_V6_PREFIX64（セクション6を参照）。
option-length:
オプションの長さ（オクテット単位）。
asm-length:
ASMのIPv4埋め込みプレフィックスのプレフィックス長を表す8ビット符号なし整数です。このフィールドは、プレフィックスの先頭から有効なビットの数を表します。このフィールドは96に設定しなければなりません（MUST）。
ASM_mPrefix64:
このフィールドは、ASMモードにおけるマルチキャストグループのIPv4埋め込みIPv6アドレスを合成するために使用するIPv6マルチキャストプレフィックスを識別します。運ばれるマルチキャストIPv6プレフィックスは、ASMの範囲に属さなければなりません（MUST）。
ssm-length:
SSMのIPv4埋め込みプレフィックスのプレフィックス長を表す8ビット符号なし整数です。このフィールドは、プレフィックスの先頭から有効なビットの数を表します。このフィールドは96に設定しなければなりません（MUST）。
SSM_mPrefix64:
このフィールドは、SSMモードにおけるマルチキャストグループのIPv4埋め込みIPv6アドレスを合成するために使用するIPv6マルチキャストプレフィックスを識別します。運ばれるマルチキャストIPv6プレフィックスは、SSMの範囲に属さなければなりません（MUST）。
unicast-length:
マルチキャストの送信元のIPv4埋め込みIPv6アドレスを合成するために使用するIPv6ユニキャストプレフィックスのプレフィックス長を表す8ビット符号なし整数です。[RFC6052]で規定されているとおり、unicast-lengthは32、40、48、56、64、96のいずれかでなければなりません（MUST）。このフィールドは、プレフィックスの先頭から有効なビットの数を表します。
uPrefix64:
このフィールドは、IPv6ドメイン内でIPv4マルチキャストの送信元を表すIPv4埋め込みIPv6アドレスを構築するために、SSMモードで使用するIPv6ユニキャストプレフィックスを識別します。uPrefix64は、受信したマルチキャストデータフローからIPv4アドレスを抽出するためにも使用されることがあります。このフィールドは可変長で、その長さはunicast-lengthフィールドによって定義され、最も近いオクテット境界に切り上げられます。この場合、追加のパディングビットはすべて0にする必要があります。アドレスマッピングは、[RFC6052]に記載されたガイドラインに従わなければなりません（MUST）。

Multiple instances of OPTION_V6_PREFIX64 may be returned to a DHCPv6 client. Configuration recommendations for DHCP servers are listed in Appendix A.

DHCPv6クライアントには、複数のOPTION_V6_PREFIX64のインスタンスが返されることがあります。DHCPサーバーの設定に関する推奨事項は付録Aに示します。

Note that it was tempting to define three distinct DHCPv6 options, but that approach was not adopted because it has a side effect: the specification of a DHCPv6 option that could be used to discover unicast Prefix64s in environments where multicast is not enabled. Such a side effect conflicts with the recommendation to support the Well-Known DNS Name heuristic discovery-based method for unicast-only environments (Section 6 of [RFC7051]).

3つの別々のDHCPv6オプションを定義したくなるところですが、その方法には副作用があるため採用しなかったことに注意してください。その副作用とは、マルチキャストが有効になっていない環境でユニキャストのPrefix64を発見するために使用できるDHCPv6オプションを規定することになるというものです。この副作用は、ユニキャストだけの環境ではウェルノウンDNS名（Well-Known DNS Name）のヒューリスティックによる発見に基づく方法をサポートするという推奨事項（[RFC7051]のセクション6）と矛盾します。

4. DHCPv6 Client Behavior

4. DHCPv6クライアントの動作

To retrieve the IPv6 prefixes that will be used to synthesize unicast and multicast IPv4-embedded IPv6 addresses, the DHCPv6 client MUST include the OPTION_V6_PREFIX64 code in its OPTION_ORO. If the DHCPv6 client receives more than one OPTION_V6_PREFIX64 option from the DHCPv6 server:

ユニキャストおよびマルチキャストのIPv4埋め込みIPv6アドレスを合成するために使用するIPv6プレフィックスを取得するために、DHCPv6クライアントは、自身のOPTION_OROにOPTION_V6_PREFIX64のコードを含めなければなりません（MUST）。DHCPv6クライアントがDHCPv6サーバーから2つ以上のOPTION_V6_PREFIX64オプションを受信した場合は、次のようにします。

  • If each enclosed IPv6 multicast prefix has a distinct scope [RFC7346], the client MUST select the appropriate IPv6 multicast prefix whose scope matches the IPv4 multicast address used to synthesize an IPv4-embedded IPv6 multicast address.
  • If at least two of the received options convey IPv6 multicast prefixes that have the same scope, the said options MUST be discarded.
  • 含まれている各IPv6マルチキャストプレフィックスのスコープ[RFC7346]がそれぞれ異なる場合、クライアントは、IPv4埋め込みIPv6マルチキャストアドレスを合成するために使用するIPv4マルチキャストアドレスにスコープが一致する、適切なIPv6マルチキャストプレフィックスを選択しなければなりません（MUST）。
  • 受信したオプションのうち少なくとも2つが同じスコープを持つIPv6マルチキャストプレフィックスを運んでいる場合、それらのオプションは破棄しなければなりません（MUST）。

If asm-length, ssm-length and unicast-length fields are all set to 0, the DHCPv6 client MUST behave as if OPTION_V6_PREFIX64 had not been received in the response received from the DHCPv6 server.

asm-length、ssm-length、unicast-lengthの各フィールドがすべて0に設定されている場合、DHCPv6クライアントは、DHCPv6サーバーから受信したレスポンスでOPTION_V6_PREFIX64を受信しなかったかのように動作しなければなりません（MUST）。

If the asm-length field is non-null, the IPv6 prefix identified by ASM_mPrefix64 is used to synthesize IPv4-embedded IPv6 multicast addresses in the ASM range. This is achieved by concatenating the ASM_mPrefix64 and the IPv4 multicast address; the IPv4 multicast address is inserted in the last 32 bits of the IPv4-embedded IPv6 multicast address.

asm-lengthフィールドが0以外（non-null）の場合、ASM_mPrefix64によって識別されるIPv6プレフィックスは、ASMの範囲のIPv4埋め込みIPv6マルチキャストアドレスを合成するために使用されます。これは、ASM_mPrefix64とIPv4マルチキャストアドレスを連結することによって行います。IPv4マルチキャストアドレスは、IPv4埋め込みIPv6マルチキャストアドレスの最後の32ビットに挿入されます。

If the ssm-length field is non-null, the IPv6 prefix identified by SSM_mPrefix64 is used to synthesize IPv4-embedded IPv6 multicast addresses in the SSM range. This is achieved by concatenating the SSM_mPrefix64 and the IPv4 multicast address; the IPv4 multicast address is inserted in the last 32 bits of the IPv4-embedded IPv6 multicast address.

ssm-lengthフィールドが0以外（non-null）の場合、SSM_mPrefix64によって識別されるIPv6プレフィックスは、SSMの範囲のIPv4埋め込みIPv6マルチキャストアドレスを合成するために使用されます。これは、SSM_mPrefix64とIPv4マルチキャストアドレスを連結することによって行います。IPv4マルチキャストアドレスは、IPv4埋め込みIPv6マルチキャストアドレスの最後の32ビットに挿入されます。

If the unicast-length field is non-null, the IPv6 prefix identified by uPrefix64 is used to synthesize IPv4-embedded IPv6 unicast addresses as specified in [RFC6052].

unicast-lengthフィールドが0以外（non-null）の場合、uPrefix64によって識別されるIPv6プレフィックスは、[RFC6052]で規定されているとおりに、IPv4埋め込みIPv6ユニキャストアドレスを合成するために使用されます。

Appendix A. Configuration Recommendations for DHCP Servers

付録A. DHCPサーバーの設定に関する推奨事項

This appendix details a set of non-normative configuration recommendations:

この付録では、規範的ではない設定上の推奨事項を詳しく説明します。

  • DHCP servers supporting OPTION_V6_PREFIX64 must be configured with ASM_mPrefix64 or SSM_mPrefix64, and may be configured with both.
  • uPrefix64 must also be configured when SSM_mPrefix64 is provided.

  • uPrefix64 may be configured when ASM_mPrefix64 is provided.

    Note that uPrefix64 is not mandatory for the ASM case if, for example, a local address mapping algorithm is supported or the Well-Known Prefix (64:ff9b::/96) is used.

  • Both ASM_mPrefix64 and SSM_mPrefix64 may be configured and therefore be returned to a requesting DHCP client in the same OPTION_V6_PREFIX64. In particular, if both SSM and ASM modes are supported, ASM_mPrefix64 and SSM_mPrefix64 prefixes must be configured. For SSM deployments, both SSM_mPrefix64 and uPrefix64 must be configured.
  • When a multicast Prefix64 (ASM_mPrefix64 or SSM_mPrefix64) is configured, the length of the prefix must be /96.
  • When distinct IPv6 multicast address scopes [RFC7346] are required to preserve the scope when translating IPv4 multicast addresses (Section 8 of [RFC2365]), each scope is configured as a separate OPTION_V6_PREFIX64. How DHCP servers are configured to separate multicast Prefix64 per scope is implementation specific and not covered by this document.
  • When scope preservation is not required, only one instance of OPTION_V6_PREFIX64 is configured.
  • OPTION_V6_PREFIX64をサポートするDHCPサーバーには、ASM_mPrefix64またはSSM_mPrefix64を設定する必要があり、その両方を設定してもかまいません。
  • SSM_mPrefix64を提供する場合は、uPrefix64も設定する必要があります。

  • ASM_mPrefix64を提供する場合は、uPrefix64を設定してもかまいません。

    たとえば、ローカルのアドレスマッピングアルゴリズムがサポートされている場合や、ウェルノウンプレフィックス（64:ff9b::/96）が使用される場合には、ASMのケースでuPrefix64は必須ではないことに注意してください。

  • ASM_mPrefix64とSSM_mPrefix64の両方を設定し、その結果、要求してきたDHCPクライアントに同じOPTION_V6_PREFIX64で両方を返してもかまいません。特に、SSMモードとASMモードの両方をサポートする場合は、ASM_mPrefix64とSSM_mPrefix64の両方のプレフィックスを設定する必要があります。SSMを展開する場合は、SSM_mPrefix64とuPrefix64の両方を設定する必要があります。
  • マルチキャストPrefix64（ASM_mPrefix64またはSSM_mPrefix64）を設定する場合、プレフィックスの長さは/96である必要があります。
  • IPv4マルチキャストアドレスを変換する際にスコープを維持するために（[RFC2365]のセクション8）、別々のIPv6マルチキャストアドレススコープ[RFC7346]が必要な場合は、各スコープを別々のOPTION_V6_PREFIX64として設定します。スコープごとにマルチキャストPrefix64を分けるためにDHCPサーバーをどのように設定するかは実装固有であり、この文書では扱いません。
  • スコープの維持が必要ない場合は、OPTION_V6_PREFIX64のインスタンスを1つだけ設定します。
