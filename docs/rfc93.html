RFC 93

Initial Connection Protocol

RFC 93

初期接続プロトコル

Abstract

概要

A review of the Initial Connection Protocol (ICP) first described in RFC #66 and restated in RFC #80 has revealed an area of ambiguity, which in turn reflects an ambiguity in the Host-Host Protocol Document No. 1. This is the definition of the message sent over the connection from "Server socket #1". In both referenced RFC's, the message is defined as "exactly an even 32 bit number". It is not clear, however, whether this 32 bit number is meant to follow an eight-bit "message data type" code or not, stemming from the fact that the Host-Host Protocol makes provision for such codes but does not seem to absolutely demand them.

RFC #66で最初に記述され、RFC #80で改めて記述された初期接続プロトコル（Initial Connection Protocol; ICP）を見直したところ、あいまいな箇所が見つかりました。これは、ホスト間プロトコル文書第1号（Host-Host Protocol Document No. 1）にあるあいまいさを反映したものです。問題となるのは、「Server socket #1」からの接続を通じて送られるメッセージの定義です。参照したどちらのRFCでも、このメッセージは「ちょうど32ビットの偶数（exactly an even 32 bit number）」と定義されています。しかし、この32ビットの偶数の前に8ビットの「メッセージデータ型（message data type）」コードを置くことを意図しているのかどうかは明らかではありません。これは、ホスト間プロトコルがそのようなコードについて規定してはいるものの、それを絶対的に必須とはしていないように見えることに起因します。

Only one implementation of an ICP has been documented in the NWG literature - that at UCSB (RFC #74). The implementers of this ICP have apparently interpreted the Host-Host Protocol as demanding a message data type code, and therefore do transmit a code of zero.

NWGの文献に記録されているICPの実装は、UCSBのもの（RFC #74）の1つだけです。このICPの実装者は、ホスト間プロトコルがメッセージデータ型コードを必須としていると解釈したようで、そのためゼロのコードを送信しています。

Steve Crocker indicates (private communication) that the Host-Host Protocol was intended to require a message data type code. We therefore recommend that RFC numbers 66 and 80 be amended to show that the "even 32 bit number" is preceded by a message data type code of zero (zero is the only code currently defined).

Steve Crockerは（私信で）、ホスト間プロトコルはメッセージデータ型コードを必須とすることを意図していたと述べています。そのため私たちは、RFC番号66と80を修正して、「32ビットの偶数（even 32 bit number）」の前にゼロのメッセージデータ型コード（現在定義されているコードはゼロだけです）が置かれることを示すよう勧めます。
