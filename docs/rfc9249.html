A YANG Data Model for NTP

RFC 9249

Abstract

概要

This document defines a YANG data model that can be used to configure and manage Network Time Protocol (NTP) version 4. It can also be used to configure and manage version 3. The data model includes configuration data and state data.

この文書は、ネットワークタイムプロトコル（NTP）バージョン4の設定と管理に使用できるYANGデータモデルを定義します。このモデルは、バージョン3の設定と管理にも使用できます。このデータモデルには、設定データと状態データが含まれます。

1. Introduction

1. はじめに

This document defines a YANG data model [RFC7950] that can be used to configure and manage Network Time Protocol version 4 [RFC5905]. Note that the model could also be used to configure and manage NTPv3 [RFC1305] (see Section 7).

この文書は、ネットワークタイムプロトコルバージョン4[RFC5905]の設定と管理に使用できるYANGデータモデル[RFC7950]を定義します。このモデルはNTPv3[RFC1305]の設定と管理にも使用できることに注意してください（Section 7を参照）。

The data model covers configuration of system parameters of NTP such as access rules, authentication and VPN Routing and Forwarding (VRF) binding, and various modes of NTP and per-interface parameters. It also provides access to information about running state of NTP implementations.

このデータモデルは、アクセス規則、認証、VPNルーティング・転送（VRF）バインディングなどのNTPのシステムパラメーター、NTPのさまざまなモード、およびインターフェイスごとのパラメーターの設定を対象とします。また、NTP実装の実行状態に関する情報へのアクセスも提供します。

1.1. Operational State

1.1. 運用状態

NTP operational state is included in the same tree as NTP configuration, consistent with "Network Management Datastore Architecture (NMDA)" [RFC8342]. NTP current state and statistics are also maintained in the operational state. The operational state also includes the NTP association state.

NTPの運用状態は、「Network Management Datastore Architecture (NMDA)」[RFC8342]に準拠して、NTPの設定と同じツリーに含まれます。NTPの現在の状態と統計情報も運用状態の中で維持されます。運用状態にはNTPアソシエーションの状態も含まれます。

1.2. Terminology

1.2. 用語

The terminology used in this document is aligned with [RFC5905] and [RFC1305].

この文書で使用する用語は、[RFC5905]および[RFC1305]に合わせています。

5. Access Rules

5. アクセス規則

The access rules in this section refer to the on-the-wire access control to the NTP service and are completely independent of any management API access control, e.g., NETCONF Access Control Model (NACM) [RFC8341].

このセクションのアクセス規則は、NTPサービスに対する通信路上でのアクセス制御を指しており、NETCONFアクセス制御モデル（NACM）[RFC8341]などの管理APIのアクセス制御とは完全に独立しています。

An Access Control List (ACL) is one of the basic elements used to configure device-forwarding behavior. An ACL is a user-ordered set of rules that is used to filter traffic on a networking device.

アクセス制御リスト（ACL）は、デバイスの転送の振る舞いを設定するために使用される基本要素の1つです。ACLは、ネットワークデバイス上のトラフィックをフィルタリングするために使用される、ユーザーが順序付けた規則の集合です。

As per [RFC1305] (for NTPv3) and [RFC5905] (for NTPv4), NTP could include an access-control feature that prevents unauthorized access and that controls which peers are allowed to update the local clock. Further, it is useful to differentiate between the various kinds of access and attach a different acl-rule to each. For this, the YANG module allows such configuration via /ntp/access-rules. The access-rule itself is configured via [RFC8519].

[RFC1305]（NTPv3の場合）および[RFC5905]（NTPv4の場合）によれば、NTPは、不正なアクセスを防ぎ、どのピアがローカル時計を更新できるかを制御するアクセス制御機能を備えることができます。さらに、さまざまな種類のアクセスを区別し、それぞれに異なるacl-ruleを付与できると便利です。そのため、このYANGモジュールでは、/ntp/access-rulesを介してそのような設定ができます。access-rule自体は[RFC8519]を介して設定します。

The following access-modes are supported:

次のアクセスモードがサポートされています。

Peer:
Permit others to synchronize their time with the NTP entity or vice versa. NTP control queries are also accepted.
Server:
Permit others to synchronize their time with the NTP entity, but vice versa is not supported. NTP control queries are accepted.
Server-only:
Permit others to synchronize their time with the NTP entity, but vice versa is not supported. NTP control queries are not accepted.
Query-only:
Only control queries are accepted.
ピア：
他者がNTPエンティティーと時刻を同期すること、およびその逆を許可します。NTPの制御クエリーも受け付けます。
サーバー：
他者がNTPエンティティーと時刻を同期することを許可しますが、その逆はサポートしません。NTPの制御クエリーを受け付けます。
サーバーのみ：
他者がNTPエンティティーと時刻を同期することを許可しますが、その逆はサポートしません。NTPの制御クエリーは受け付けません。
クエリーのみ：
制御クエリーのみを受け付けます。

Query-only is the most restricted whereas the peer is the full access authority. The ability to give different ACL rules for different access-modes allows for a greater control by the operator.

クエリーのみが最も制限が厳しく、ピアは完全なアクセス権限を持ちます。アクセスモードごとに異なるACL規則を指定できるため、運用者はより細かく制御できます。

6. Key Management

6. 鍵管理

As per [RFC1305] (for NTPv3) and [RFC5905] (for NTPv4), when authentication is enabled, NTP employs a crypto-checksum, computed by the sender and checked by the receiver, together with a set of predistributed algorithms, and cryptographic keys indexed by a key identifier included in the NTP message. This keyid is a 32-bit unsigned integer that MUST be configured on the NTP peers before the authentication can be used. For this reason, this YANG module allows such configuration via /ntp/authentication/authentication-keys/. Further at the time of configuration of NTP association (for example, unicast server), the keyid is specified.

[RFC1305]（NTPv3の場合）および[RFC5905]（NTPv4の場合）によれば、認証が有効な場合、NTPは、送信者が計算して受信者が検査する暗号チェックサムを、事前に配布されたアルゴリズムの集合、およびNTPメッセージに含まれる鍵識別子でインデックス付けされた暗号鍵とともに使用します。このkeyidは32ビットの符号なし整数であり、認証を使用する前にNTPピアで設定しなければなりません（MUST）。このため、このYANGモジュールでは、/ntp/authentication/authentication-keys/を介してそのような設定ができます。さらに、NTPアソシエーション（たとえば、ユニキャストサーバー）を設定する際に、keyidを指定します。

The 'nacm:default-deny-all' is used to prevent retrieval of the actual key information after it is set.

「nacm:default-deny-all」は、実際の鍵情報が設定された後に、その鍵情報が取得されるのを防ぐために使用します。

7. NTP Version

7. NTPバージョン

This YANG data model allows a version to be configured for the NTP association, i.e., an operator can control the use of NTPv3 [RFC1305] or NTPv4 [RFC5905] for each association it forms. This allows backward compatibility with a legacy system. Note that NTPv3 [RFC1305] is obsoleted by NTPv4 [RFC5905].

このYANGデータモデルでは、NTPアソシエーションにバージョンを設定できます。つまり、運用者は、形成する各アソシエーションについて、NTPv3[RFC1305]とNTPv4[RFC5905]のどちらを使用するかを制御できます。これにより、レガシーシステムとの後方互換性が得られます。NTPv3[RFC1305]はNTPv4[RFC5905]によって廃止されていることに注意してください。

11. Security Considerations

11. セキュリティーに関する考慮事項

The YANG module specified in this document defines a schema for data that is designed to be accessed via network management protocols such as NETCONF [RFC6241] or RESTCONF [RFC8040]. The lowest NETCONF layer is the secure transport layer, and the mandatory-to-implement secure transport is Secure Shell (SSH) [RFC6242]. The lowest RESTCONF layer is HTTPS, and the mandatory-to-implement secure transport is TLS [RFC8446].

この文書で規定するYANGモジュールは、NETCONF[RFC6241]やRESTCONF[RFC8040]などのネットワーク管理プロトコルを介してアクセスされるように設計されたデータのスキーマを定義します。NETCONFの最下層はセキュアなトランスポート層であり、実装必須のセキュアなトランスポートはセキュアシェル（SSH）[RFC6242]です。RESTCONFの最下層はHTTPSであり、実装必須のセキュアなトランスポートはTLS[RFC8446]です。

The Network Configuration Access Control Model (NACM) [RFC8341] provides the means to restrict access for particular NETCONF or RESTCONF users to a preconfigured subset of all available NETCONF or RESTCONF protocol operations and content. The 'nacm:default-deny-all' is used to prevent retrieval of the key information.

ネットワーク構成アクセス制御モデル（NACM）[RFC8341]は、特定のNETCONFユーザーやRESTCONFユーザーのアクセスを、利用可能なすべてのNETCONFプロトコル操作やRESTCONFプロトコル操作とコンテンツのうち、事前に設定されたサブセットに制限する手段を提供します。「nacm:default-deny-all」は、鍵情報の取得を防ぐために使用します。

There are a number of data nodes defined in this YANG module that are writable/creatable/deletable (i.e., config true, which is the default). These data nodes may be considered sensitive or vulnerable in some network environments. Write operations (e.g., edit-config) to these data nodes without proper protection can have a negative effect on network operations. These are the subtrees and data nodes and their sensitivity/vulnerability:

このYANGモジュールには、書き込み可能／作成可能／削除可能な（つまり、デフォルトであるconfig trueの）データノードが多数定義されています。これらのデータノードは、一部のネットワーク環境では機密性が高い、または脆弱であると考えられる場合があります。適切な保護なしにこれらのデータノードに対して書き込み操作（たとえば、edit-config）を行うと、ネットワークの運用に悪影響を及ぼす可能性があります。サブツリーとデータノード、およびそれらの機密性／脆弱性は次のとおりです。

/ntp/port:
This data node specifies the port number to be used to send NTP packets. Unexpected changes could lead to disruption and/or network misbehavior.
/ntp/authentication and /ntp/access-rules:
The entries in the list include the authentication and access control configurations. Care should be taken while setting these parameters.
/ntp/unicast-configuration:
The entries in the list include all unicast configurations (server or peer mode) and indirectly creates or modifies the NTP associations. Unexpected changes could lead to disruption and/or network misbehavior.
/ntp/interfaces/interface:
The entries in the list include all per-interface configurations related to broadcast, multicast, and manycast mode, and indirectly creates or modifies the NTP associations. Unexpected changes could lead to disruption and/or network misbehavior. It could also lead to synchronization over an untrusted source over trusted ones.
/ntp/port:
このデータノードは、NTPパケットの送信に使用するポート番号を指定します。予期しない変更は、サービスの中断やネットワークの誤動作につながる可能性があります。
/ntp/authenticationと/ntp/access-rules:
リスト内のエントリーには、認証とアクセス制御の設定が含まれます。これらのパラメーターを設定する際には注意が必要です。
