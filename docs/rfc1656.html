RFC 1656

BGP-4 Protocol Document Roadmap and Implementation Experience

RFC 1656

BGP-4プロトコル文書のロードマップと実装経験

Status of This Memo

このメモのステータス

This memo provides information for the Internet community. This memo does not specify an Internet standard of any kind. Distribution of this memo is unlimited.

このメモは、インターネットコミュニティーに情報を提供するものです。いかなる種類のインターネット標準も規定するものではありません。このメモの配布は無制限です。

Introduction

はじめに

Border Gateway Protocol v4 (BGP-4) [1] is an inter-Autonomous System routing protocol. It is built on experience gained with BGP as defined in RFC-1267 [2] and BGP usage in the connected Internet as described in RFC-1268 [3].

Border Gateway Protocol v4（BGP-4）[1]は、自律システム（Autonomous System）間のルーティングプロトコルです。BGP-4は、RFC-1267[2]で定義されたBGPで得られた経験と、RFC-1268[3]で説明されている接続されたインターネットにおけるBGPの使用経験に基づいて作られています。

The primary function of a BGP speaking system is to exchange network reachability information with other BGP systems. This network reachability information includes information on the list of Autonomous Systems (ASs) that reachability information traverses. This information is sufficient to construct a graph of AS connectivity from which routing loops may be pruned and some policy decisions at the AS level may be enforced.

BGPを話すシステムの主な機能は、ほかのBGPシステムとネットワーク到達可能性情報を交換することです。このネットワーク到達可能性情報には、到達可能性情報が通過する自律システム（AS）のリストに関する情報が含まれます。この情報は、ASの接続性のグラフを構築するのに十分なものです。このグラフから、ルーティングループを取り除いたり、ASレベルでのいくつかのポリシー決定を強制したりできます。

BGP-4 provides a new set of mechanisms for supporting classless inter-domain routing. These mechanisms include support for advertising an IP prefix and eliminates the concept of network "class" within BGP. BGP-4 also introduces mechanisms which allow aggregation of routes, including aggregation of AS paths. These changes provide support for the proposed supernetting scheme [4].

BGP-4は、クラスレスなドメイン間ルーティングをサポートするための新しい一連のメカニズムを提供します。これらのメカニズムには、IPプレフィックスの広告のサポートが含まれ、BGP内でのネットワークの「クラス」という概念をなくします。BGP-4は、ASパスの集約を含む、経路の集約を可能にするメカニズムも導入します。これらの変更により、提案されているスーパーネット化の方式[4]がサポートされます。

The management information base has been defined [5] and security considerations are discussed in the protocol definition document [1].

管理情報ベース（management information base）は定義済みであり[5]、セキュリティーに関する考慮事項はプロトコル定義の文書[1]で論じられています。

Applicability Statement for BGP-4

BGP-4の適用性声明

BGP-4 is explicitly designed for carrying reachability information between Autonomous Systems. BGP-4 is not intended to replace interior gateway protocols such as OSPF [7] or RIP [6].

BGP-4は、自律システム間で到達可能性情報を運ぶために明示的に設計されています。BGP-4は、OSPF[7]やRIP[6]のような内部ゲートウェイプロトコルを置き換えることを意図していません。

Implementation Testing

実装のテスト

One implementation has been extensively tested in a network designed to mirror the complex connectivity present at many major Internet borders. This network consists of multiple BGP-3 and BGP-4 speakers carrying full routing information injected from Alternet, EBone, Sprint, CERFnet, and cisco. In many cases additional AS adjacencies are simulated via the use of IP over IP tunnels to increase the complexity of the routing topology.

ある1つの実装は、インターネットの多くの主要な境界に存在する複雑な接続性を再現するように設計されたネットワークで、広範にテストされています。このネットワークは、Alternet、EBone、Sprint、CERFnet、ciscoから注入された完全なルーティング情報を運ぶ、複数のBGP-3とBGP-4のスピーカーで構成されています。多くの場合、ルーティングトポロジーの複雑さを増すために、IP over IPトンネルを使って追加のASの隣接関係をシミュレートしています。

The primary feature of BGP-4 is the ability to carry network reachability information without regard to classfull routing. In addition to canonical routing information, CIDR prefixes (both supernets and subnets) are being injected from IGP information and aggregated using the methods described in BGP-4. AS set aggregation and policy decisions based upon AS sets have been tested.

BGP-4の主な機能は、クラスフル（classfull）ルーティングに関係なくネットワーク到達可能性情報を運べることです。正規のルーティング情報に加えて、CIDRプレフィックス（スーパーネットとサブネットの両方）がIGPの情報から注入され、BGP-4で説明されている方法を使って集約されています。AS setの集約と、AS setに基づくポリシー決定はテスト済みです。

Secondary extensions incorporated as part of version 4 of this protocol include enhancements to use of the INTER_AS_METRIC (now called MULTI_EXIT_DISC), the addition of a LOCAL_PREF parameter to influence route selection within an AS, and a specified method of damping route fluctuations. All of these features have been tested in at least one implementation.

このプロトコルのバージョン4の一部として取り込まれた副次的な拡張には、INTER_AS_METRIC（現在はMULTI_EXIT_DISCと呼ばれる）の使い方の強化、AS内での経路選択に影響を与えるためのLOCAL_PREFパラメーターの追加、経路の変動を抑制（damping）するための方法の規定が含まれます。これらの機能はすべて、少なくとも1つの実装でテストされています。

Observations

所見

All implementations, are able to carry and exchange network reachability information.

すべての実装が、ネットワーク到達可能性情報を運び、交換できます。

Not all implementations are capable of generating aggregate information based upon the existence of more specific routes.

より詳細な経路の存在に基づいて集約情報を生成できる実装ばかりではありません。

No implementation supports automatic deaggregation (enumeration of all networks in an aggregate block for backwards compatibility with routing protocols that do not carry mask information (e.g. BGP-3)). However, most implementations do allow for staticly configured controlled deaggregation for minimal backwards compatibility with non-CIDR capable routers.

自動的な集約解除（deaggregation、つまり、マスク情報を運ばないルーティングプロトコル（たとえばBGP-3）との後方互換性のために、集約されたブロック内のすべてのネットワークを列挙すること）をサポートする実装はありません。ただし、ほとんどの実装では、CIDRに対応していないルーターとの最小限の後方互換性のために、静的に設定された制御された集約解除が可能です。

At least one implementation capable of running earlier versions of BGP deliberately does not automaticly negotiate to earlier versions. Connections to BGP-4 peers must be explicitly configured as such.

以前のバージョンのBGPを実行できる実装のうち少なくとも1つは、意図的に以前のバージョンへの自動ネゴシエーションを行いません。BGP-4ピアへのコネクションは、明示的にそのように設定しなければなりません。

Conclusions

結論

The ability to carry and inject natural networks and CIDR supernets is the immediate requirement for BGP-4. The ability to carry subnet information (useful when reassigning parts of class A networks to organizations with different routing policies) is of secondary concern.

ナチュラルネットワーク（natural network）とCIDRスーパーネットを運び、注入できることは、BGP-4にとって当面の要件です。サブネットの情報を運べること（クラスAネットワークの一部を、異なるルーティングポリシーを持つ組織に再割り当てする場合に役立ちます）は、二次的な関心事です。

The ability to conditionally aggregate routing information may be worked around by injecting static or IGP network information into BGP, or aggregation may be performed by an upstream router that is capable.

ルーティング情報を条件付きで集約する機能がなくても、静的なネットワーク情報やIGPのネットワーク情報をBGPに注入することで回避できます。あるいは、集約の能力がある上流のルーターで集約を行うこともできます。

Deaggregation is dangerous. It leads to information loss and unless tightly controlled by a manual mechanism, will create a routing information explosion.

集約解除は危険です。集約解除は情報の損失につながり、手動のメカニズムによって厳密に制御しない限り、ルーティング情報の爆発的な増加を引き起こします。

Automatic version negotiation is dangerous due to the state-less nature. Given packet losses or spontaneous restarts, it is possible for two BGP peers capable of BGP-4 to negotiate a BGP-3 or BGP-2 connection, which is incapable of carrying super/subnet reachability information and AS set information.

自動的なバージョンネゴシエーションは、状態を持たないという性質のために危険です。パケットの損失や突然の再起動があると、BGP-4に対応した2つのBGPピアが、BGP-3やBGP-2のコネクションをネゴシエートしてしまう可能性があります。BGP-3やBGP-2のコネクションでは、スーパーネットやサブネットの到達可能性情報と、AS setの情報を運べません。
