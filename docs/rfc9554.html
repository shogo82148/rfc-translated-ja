RFC 9554

vCard Format Extensions for JSContact

RFC 9554

JSContactのためのvCard形式の拡張

Abstract

概要

This document defines a set of new properties for vCard and extends the use of existing ones. Their primary purpose is to align the same set of features between the JSContact and vCard formats, but the new definitions also aim to be useful within just the vCard format. This document updates RFC 6350 ("vCard Format Specification").

この文書は、vCardの新しいプロパティー群を定義し、既存のプロパティーの用途を拡張します。これらの主な目的は、JSContactとvCardの形式の間で同じ機能のセットをそろえることですが、新しい定義はvCard形式単体の中でも役に立つことを目指しています。この文書は、RFC 6350（「vCard Format Specification」）を更新します。

1. Introduction

1. はじめに

The JSContact [RFC9553] format aims to be an alternative to the vCard [RFC6350] format for representation of contact and address book data. As such, it introduces new semantics that are not covered in the current definition of vCard and its various extensions. Converting contact data between the two formats is defined in [RFC9555] with the goal of not losing any semantics during conversion. To achieve this, this document defines a new set of properties for vCard and extends existing definitions.

JSContact[RFC9553]形式は、連絡先およびアドレス帳のデータを表現するための、vCard[RFC6350]形式の代替となることを目指しています。 そのため、JSContactは、現在のvCardとそのさまざまな拡張の定義ではカバーされていない新しいセマンティクスを導入しています。 2つの形式の間での連絡先データの変換は、変換中にセマンティクスを一切失わないことを目標として、[RFC9555]で定義されています。 これを実現するため、この文書は、vCardの新しいプロパティー群を定義し、既存の定義を拡張します。

2.2. N

2.2. N

This specification modifies the definition of the N property. It extends its structured value with additional name components to better support international names and generation markers. In doing so, this also facilitates formatting N property values using the Unicode Common Locale Data Repository (CLDR) Person Name [CLDRPersonName] formatting standard.

この仕様は、Nプロパティーの定義を変更します。国際的な名前と世代を表す標識をよりよくサポートするため、Nプロパティーの構造化された値に名前のコンポーネントを追加して拡張します。これにより、Unicode Common Locale Data Repository（CLDR）のPerson Name[CLDRPersonName]書式標準を使ったNプロパティーの値の書式化も容易になります。

One new component is for secondary surnames, because in some cultures, such secondary surname kinds are used to indicate the paternal and maternal family names or generational names indicating father or grandfather. Another new component indicates a generation ("II", "XVI") or parental relation ("Jr.", "Sr.").

新しいコンポーネントの1つは、第2姓のためのものです。一部の文化では、このような種類の第2姓が、父方と母方の姓、あるいは父や祖父を示す世代名を表すために使われるためです。もう1つの新しいコンポーネントは、世代（「II」、「XVI」）や親子関係（「Jr.」、「Sr.」）を示します。

Currently, implementations typically place secondary surnames in the family name component and generational markers in the honorific suffixes component. For backwards compatibility, implementations SHOULD add such values to both the newly defined components and their backwards-compatible counterpart. Reading N property values, implementations SHOULD ignore any value in the backwards-compatible component if an equal value is set in the new component accordingly. For example, a "Jr." that occurs in both honorific suffixes and generation should only be handled as a generational marker.

現在、実装は通常、第2姓を姓（family name）コンポーネントに、世代を表す標識を敬称接尾辞（honorific suffixes）コンポーネントに格納しています。後方互換性のために、実装はこのような値を、新しく定義されたコンポーネントと、後方互換性のための対応するコンポーネントの両方に追加すべきです（SHOULD）。Nプロパティーの値を読み取る際、新しいコンポーネントに同じ値がそれに応じて設定されている場合、実装は後方互換性のためのコンポーネントの値を無視すべきです（SHOULD）。たとえば、敬称接尾辞と世代の両方に現れる「Jr.」は、世代を表す標識としてのみ扱われるべきです。

3.1. CREATED

Property name:
CREATED
Purpose:
Defines the date and time when the vCard was created.
Value type:
A single timestamp value.
Cardinality:
*1

VALUE

                 ;
                 (";" any-param)
                 ;
                 )

CREATED

4.6. PHONETIC

4.6. PHONETIC

Parameter name:
PHONETIC
Purpose:
Defines how to pronounce the value of another property in the same vCard.
Description:

This property parameter indicates that the value of its property contains the phonetic representation of another same-named property in the same vCard. Exemplary uses are defining how to pronounce Japanese names and romanizing Mandarin or Cantonese names and address components.

The parameter value indicates the phonetic system and MUST be one of the values enumerated in the IANA Section 7.4. This specification defines the following values:

"ipa":
denotes the International Phonetic Alphabet [IPA].
"jyut":
denotes the Cantonese romanization system "Jyutping".
"piny":
denotes the Standard Mandarin romanization system "Hanyu Pinyin".
"script":
denotes the unknown phonetic system. The Section 4.8 parameter MUST be set in addition to the PHONETIC parameter.

The value type of the property on which the PHONETIC parameter is set MUST be of the same type as its related property. If a component value is set in the property on which the PHONETIC parameter is set, then a component value also MUST be set at that same position in the related property. On the other hand, not every component value in the related property needs to have a phonetic representation.

The ALTID (Section 5.4 of [RFC6350]) parameter MUST be set with equal values on both the related property and the property having the PHONETIC parameter set. If more than one same-named property has both the PHONETIC parameter set and an equal ALTID parameter value, then at most, one of these properties MAY not have the LANGUAGE parameter set, and all others MUST have the LANGUAGE parameter set. The LANGUAGE parameters MUST NOT have equal values. The LANGUAGE parameter value SHOULD NOT contain a script subtag in its Language-Tag value, and any such subtag MUST be ignored in favor of the Section 4.8 parameter value.

This specification defines the PHONETIC parameter for use with the ADR and N properties.

Format definition:
phonetic-param = "PHONETIC=" phonetic-value

phonetic-value = "ipa" / "piny" / "jyut" / "script" /
                 iana-token / x-name
Example(s):
N;ALTID=1;LANGUAGE=zh-Hant:孫;中山;文,逸仙;;;;
N;ALTID=1;PHONETIC=jyut;
  SCRIPT=Latn;LANGUAGE=yue:syun1;zung1saan1;man4,jat6sin1;;;;
パラメーター名：
PHONETIC
目的：
同じvCard内の別のプロパティーの値の発音方法を定義します。
説明：

このプロパティーパラメーターは、そのプロパティーの値に、同じvCard内の同じ名前の別のプロパティーの音声表記が含まれていることを示します。使用例としては、日本人の名前の発音方法を定義することや、北京語や広東語の名前や住所のコンポーネントをローマ字表記することが挙げられます。

パラメーターの値は表音体系を示し、IANAのSection 7.4に列挙された値のいずれかでなければなりません（MUST）。この仕様は、次の値を定義します。

"ipa":
国際音声記号（International Phonetic Alphabet）[IPA]を表します。
"jyut":
広東語のローマ字表記体系「Jyutping（粤拼）」を表します。
"piny":
標準中国語（北京語）のローマ字表記体系「Hanyu Pinyin（漢語拼音）」を表します。
"script":
未知の表音体系を表します。PHONETICパラメーターに加えて、Section 4.8パラメーターを設定しなければなりません（MUST）。

PHONETICパラメーターが設定されたプロパティーの値の型は、関連するプロパティーと同じ型でなければなりません（MUST）。PHONETICパラメーターが設定されたプロパティーでコンポーネントの値が設定されている場合、関連するプロパティーの同じ位置にもコンポーネントの値が設定されていなければなりません（MUST）。一方で、関連するプロパティーのすべてのコンポーネントの値が音声表記を持つ必要はありません。

ALTID（[RFC6350]のSection 5.4）パラメーターは、関連するプロパティーとPHONETICパラメーターが設定されたプロパティーの両方に、等しい値で設定しなければなりません（MUST）。同じ名前の複数のプロパティーが、PHONETICパラメーターの設定と等しいALTIDパラメーターの値の両方を持つ場合、それらのプロパティーのうち多くとも1つは、LANGUAGEパラメーターを設定しなくてもよいです（MAY）。それ以外のすべてのプロパティーは、LANGUAGEパラメーターを設定していなければなりません（MUST）。LANGUAGEパラメーターは等しい値を持ってはなりません（MUST NOT）。LANGUAGEパラメーターの値は、そのLanguage-Tagの値にスクリプトサブタグを含めるべきではありません（SHOULD NOT）。そのようなサブタグは無視し、Section 4.8パラメーターの値を優先しなければなりません（MUST）。

この仕様は、ADRプロパティーとNプロパティーで使用するためのPHONETICパラメーターを定義します。

形式の定義：
phonetic-param = "PHONETIC=" phonetic-value

phonetic-value = "ipa" / "piny" / "jyut" / "script" /
                 iana-token / x-name
例：
N;ALTID=1;LANGUAGE=zh-Hant:孫;中山;文,逸仙;;;;
N;ALTID=1;PHONETIC=jyut;
  SCRIPT=Latn;LANGUAGE=yue:syun1;zung1saan1;man4,jat6sin1;;;;

4.7. PROP-ID

4.7. PROP-ID

Parameter name:
PROP-ID
Purpose:
Identifies a property among all its siblings of the same property name.
Description:

This parameter uniquely identifies a property among all of its siblings with the same name within a vCard. A valid PROP-ID value must be of 1 and a maximum of 255 octets in size, and it MUST only contain the ASCII alphanumeric characters ("A-Za-z0-9"), hyphen (-), and underscore ("_"). The identifier's only purpose is to uniquely identify siblings; its value has no other meaning. If an application makes use of PROP-ID, it SHOULD assign a unique identifier to each sibling property of the same name within their embedding component. The same identifier MAY be used for properties of a different name, and it MAY also be assigned to a same-named property that is not a sibling.

Resolving duplicate identifier conflicts is specific to the application. Similarly, handling properties where some but not all siblings have a PROP-ID assigned is application-specific.

Format definition:
prop-id-param  = "PROP-ID" "=" 1*255(ALPHA / DIGIT / "-"/ "_")
Example(s):
PHOTO;PROP-ID=p827:data:image/jpeg;base64,MIICajCCAdOgAwIBAg
        <...remainder of base64-encoded data...>
パラメーター名：
PROP-ID
目的：
同じプロパティー名を持つすべての兄弟の中で、あるプロパティーを識別します。
説明：

このパラメーターは、vCard内で同じ名前を持つすべての兄弟の中で、あるプロパティーを一意に識別します。有効なPROP-IDの値は、サイズが1オクテット以上255オクテット以下でなければならず、ASCIIの英数字（"A-Za-z0-9"）、ハイフン（-）、アンダースコア（"_"）のみを含まなければなりません（MUST）。この識別子の唯一の目的は兄弟を一意に識別することであり、その値に他の意味はありません。アプリケーションがPROP-IDを利用する場合、それらを含むコンポーネント内の同じ名前の各兄弟プロパティーに、一意な識別子を割り当てるべきです（SHOULD）。異なる名前のプロパティーに同じ識別子を使ってもよいです（MAY）。また、兄弟ではない同じ名前のプロパティーに同じ識別子を割り当ててもよいです（MAY）。

識別子の重複による衝突の解決は、アプリケーション固有です。同様に、一部の兄弟にのみPROP-IDが割り当てられているプロパティーの扱いも、アプリケーション固有です。

形式の定義：
prop-id-param  = "PROP-ID" "=" 1*255(ALPHA / DIGIT / "-"/ "_")
例：
PHOTO;PROP-ID=p827:data:image/jpeg;base64,MIICajCCAdOgAwIBAg
        <...remainder of base64-encoded data...>

4.8. SCRIPT

4.8. SCRIPT

Parameter name:
SCRIPT
Purpose:
Defines the script that a property value is written in.
Description:

This parameter allows defining a script for a property value without also defining a language as the LANGUAGE parameter would. The value MUST be a script subtag as defined in Section 2.2.3 of [RFC5646]. This specification makes use of the SCRIPT parameter in combination with the Section 4.6 parameter.

Format definition:
script-param = 4ALPHA
Example(s):
SCRIPT=Latn
パラメーター名：
SCRIPT
目的：
プロパティーの値が書かれている文字体系（script）を定義します。
説明：

このパラメーターを使うと、LANGUAGEパラメーターのように言語まで定義することなく、プロパティーの値の文字体系を定義できます。値は、[RFC5646]のSection 2.2.3で定義されているスクリプトサブタグでなければなりません（MUST）。この仕様では、SCRIPTパラメーターをSection 4.6パラメーターと組み合わせて利用します。

形式の定義：
script-param = 4ALPHA
例：
SCRIPT=Latn

4.9. SERVICE-TYPE

4.9. SERVICE-TYPE

Parameter name:
SERVICE-TYPE
Purpose:
Defines the online service name associated with a messaging or social media profile.
Description:

This parameter MAY be specified on an Instant Messaging and Presence Protocol (IMPP) or a SOCIALPROFILE property to name the online service associated with that property value. Its value is case-sensitive; its letter cases MUST be preserved.

Several vCard address book implementations currently use an experimental X-SERVICE-TYPE parameter. This specification provides an IANA-registered parameter for the same purpose.

Format definition:
service-type-param    = "SERVICE-TYPE" "=" param-value
Example(s):
SOCIALPROFILE;SERVICE-TYPE=Mastodon:https://example.com/@foo
パラメーター名：
SERVICE-TYPE
目的：
メッセージングまたはソーシャルメディアのプロファイルに関連付けられたオンラインサービスの名前を定義します。
説明：

このパラメーターは、プロパティーの値に関連付けられたオンラインサービスの名前を示すために、Instant Messaging and Presence Protocol（IMPP）プロパティーまたはSOCIALPROFILEプロパティーに指定してもよいです（MAY）。その値は大文字と小文字を区別します。大文字と小文字の違いは保持しなければなりません（MUST）。

現在、いくつかのvCardアドレス帳の実装は、実験的なX-SERVICE-TYPEパラメーターを使っています。この仕様は、同じ目的のためのIANAに登録されたパラメーターを提供します。

形式の定義：
service-type-param    = "SERVICE-TYPE" "=" param-value
例：
SOCIALPROFILE;SERVICE-TYPE=Mastodon:https://example.com/@foo

形式の定義：
username-param    = "USERNAME" "=" param-value

SOCIALPROFILE;USERNAME="The Foo":https://example.com/@foo
