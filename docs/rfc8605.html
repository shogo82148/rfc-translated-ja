RFC 8605

vCard Format Extensions: ICANN Extensions for the Registration Data Access Protocol (RDAP)

RFC 8605

vCard形式の拡張：Registration Data Access Protocol（RDAP）のためのICANN拡張

Abstract

概要

This document defines extensions to the vCard data format for representing and exchanging contact information used to implement the Internet Corporation for Assigned Names and Numbers (ICANN) operational profile for the Registration Data Access Protocol (RDAP). The property and parameter defined here are used to add values to RDAP responses that are consistent with ICANN policies.

この文書は、Registration Data Access Protocol（RDAP）のためのInternet Corporation for Assigned Names and Numbers（ICANN）運用プロファイルを実装するために使用される連絡先情報を表現し交換するための、vCardデータ形式の拡張を定義します。ここで定義するプロパティーとパラメーターは、ICANNのポリシーに沿った値をRDAPレスポンスに追加するために使用されます。

1. Introduction

1. はじめに

The "Temporary Specification for gTLD Registration Data" available at <https://www.icann.org/resources/pages/gtld-registration-data-specs-en> was published by the Internet Corporation for Assigned Named and Numbers (ICANN) in 2018. The Temporary Specification includes requirements that cannot currently be met by the Registration Data Access Protocol (RDAP, [RFC7483]) without extending the underlying vCard [RFC6350] specification used to represent RDAP entity objects. This document includes specifications for an additional vCard property and an additional vCard parameter to meet the requirements of the Temporary Specification.

<https://www.icann.org/resources/pages/gtld-registration-data-specs-en>で入手できる「Temporary Specification for gTLD Registration Data」（gTLD登録データに関する暫定仕様）は、2018年にInternet Corporation for Assigned Named and Numbers（ICANN）によって公開されました。この暫定仕様（Temporary Specification）には、RDAPエンティティーオブジェクトを表現するために使用される基盤のvCard [RFC6350]仕様を拡張しなければ、Registration Data Access Protocol（RDAP、[RFC7483]）では現在満たすことのできない要件が含まれています。この文書は、暫定仕様の要件を満たすための、追加のvCardプロパティーと追加のvCardパラメーターの仕様を含みます。

1.1. Terminology Used in This Document

1.1. この文書で使用する用語

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

この文書のキーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、「要求されています（REQUIRED）」、「することになります（SHALL）」、「することはありません（SHALL NOT）」、「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、「推奨されます（RECOMMENDED）」、「推奨されません（NOT RECOMMENDED）」、「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、ここに示すようにすべて大文字で表示されている場合に限り、BCP 14 [RFC2119] [RFC8174]で説明されているように解釈されます。

Syntax specifications shown here use the augmented Backus-Naur Form (ABNF) as described in [RFC5234] and are specified as in the base vCard specification [RFC6350].

ここで示す構文仕様は、[RFC5234]で説明されている拡張バッカス・ナウア記法（ABNF）を使用し、基本となるvCard仕様[RFC6350]と同様に規定されます。

2. vCard Extensions: Properties

2. vCard拡張：プロパティー

This document describes one new vCard extension property.

この文書は、新しいvCard拡張プロパティーを1つ記述します。

2.1. Property: CONTACT-URI

2.1. プロパティー：CONTACT-URI

Namespace:
Property name:
CONTACT-URI
Purpose:
RDAP entity information can be redacted under certain circumstances (e.g., privacy). The Temporary Specification requires that RDAP entity objects representing "Registrant", "Admin", and "Tech" contacts contain an email address or a location for a web form to facilitate email communication with the relevant contact in a way that does not identify the associated individual. The CONTACT-URI property can be used to include URIs representing an email address or a location for a web form.
Value type:
A single URI value.
Cardinality:
*
Property parameters:
PREF
Description:
At least one "mailto", "http", or "https" URI value MUST be provided. Additional CONTACT-URI properties MAY be provided to describe other contact methods. If multiple CONTACT-URI properties are used, the vCard PREF parameter MUST be used to describe the most preferred property as described in Section 5.3 of RFC 6350 [RFC6350].
Format definition:
CONTACT-URI-param = "VALUE=uri" / pref-param ; pref-param from
[RFC6350]

CONTACT-URI-value = uri ; uri from [RFC3986]
Examples:
CONTACT-URI:https://contact.example.com

CONTACT-URI;PREF=1:mailto:contact@example.com
名前空間：
プロパティー名：
CONTACT-URI
目的：
RDAPエンティティー情報は、特定の状況（たとえば、プライバシー）において秘匿化されることがあります。暫定仕様は、「Registrant」、「Admin」、「Tech」の連絡先を表すRDAPエンティティーオブジェクトに、関連する個人を特定しない方法で該当する連絡先との電子メールによる連絡を容易にするための、電子メールアドレスまたはWebフォームの場所を含めることを要求しています。CONTACT-URIプロパティーは、電子メールアドレスまたはWebフォームの場所を表すURIを含めるために使用できます。
値の型：
単一のURI値。
カーディナリティー：
*
プロパティーパラメーター：
PREF
説明：
少なくとも1つの「mailto」、「http」、または「https」のURI値を提供しなければなりません（MUST）。他の連絡方法を記述するために、追加のCONTACT-URIプロパティーを提供してもよいです（MAY）。複数のCONTACT-URIプロパティーを使用する場合は、RFC 6350 [RFC6350]のセクション5.3で説明されているように、最も優先されるプロパティーを示すためにvCardのPREFパラメーターを使用しなければなりません（MUST）。
形式の定義：
CONTACT-URI-param = "VALUE=uri" / pref-param ; pref-param from
[RFC6350]

CONTACT-URI-value = uri ; uri from [RFC3986]
例：
CONTACT-URI:https://contact.example.com

CONTACT-URI;PREF=1:mailto:contact@example.com

3. vCard Extensions: Parameters

3. vCard拡張：パラメーター

This document describes one new vCard extension parameter.

この文書は、新しいvCard拡張パラメーターを1つ記述します。

3.1. Parameter: CC

3.1. パラメーター：CC

Namespace:
Parameter name:
CC
Purpose:
ICANN requires the use of ISO 3166 [ISO.3166.1988] two-letter codes, not "country names", in RDAP entity responses. This parameter is used to extend the ADR property described in Section 6.3.1 of RFC 6350 [RFC6350].
Description:
This parameter contains the ISO 3166 [ISO.3166.1988] two-character country code associated with the "country name" ADR component described in Section 6.3.1 of RFC 6350 [RFC6350].
Format definition:
CC-param = "CC=" 2ALPHA
Examples:
ADR;TYPE=work;CC=US:;;54321 Oak St;Reston;VA;20190;USA

ADR;TYPE=home;CC=US:;;12345 Elm St;Reston;VA;20190;USA
名前空間：
パラメーター名：
CC
目的：
ICANNは、RDAPエンティティーレスポンスにおいて、「国名」ではなくISO 3166 [ISO.3166.1988]の2文字のコードを使用することを要求しています。このパラメーターは、RFC 6350 [RFC6350]のセクション6.3.1で説明されているADRプロパティーを拡張するために使用されます。
説明：
このパラメーターは、RFC 6350 [RFC6350]のセクション6.3.1で説明されているADRの「国名（country name）」コンポーネントに関連付けられた、ISO 3166 [ISO.3166.1988]の2文字の国コードを含みます。
形式の定義：
CC-param = "CC=" 2ALPHA
例：
ADR;TYPE=work;CC=US:;;54321 Oak St;Reston;VA;20190;USA

ADR;TYPE=home;CC=US:;;12345 Elm St;Reston;VA;20190;USA

5. Security Considerations

5. セキュリティーに関する考慮事項

The CONTACT-URI value is purposefully intended to be a publicly visible contact reference; as such, it cannot require confidentiality protection. There are, however, privacy implications in the choice of a URI scheme for the web form contact method. An "https" URI value can be used to indicate support for confidentiality protection for connections to the server that publishes the web form. This document presents no other security considerations beyond those described in Section 9 of the base vCard specification [RFC6350].

CONTACT-URIの値は、意図的に公開される連絡先の参照として意図されています。そのため、機密性の保護を要求することはできません。ただし、Webフォームによる連絡方法のURIスキームの選択には、プライバシー上の影響があります。「https」のURI値は、Webフォームを公開するサーバーへの接続について機密性の保護をサポートしていることを示すために使用できます。この文書は、基本となるvCard仕様[RFC6350]のセクション9で説明されているもの以外に、セキュリティー上の考慮事項を提示しません。
