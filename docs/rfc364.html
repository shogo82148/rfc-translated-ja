RFC 364

Serving Remote Users on the ARPANET

RFC 364

ARPANETでのリモートユーザーへのサービス提供

Problem Statement

問題の記述

Second only to the unavailability of the serving host, the most vexing problem encountered in attempting to use the service hosts on the NET has been the inadequacy of administrative procedure and information dissemination for remote users. This paper explores the problem and proposes solutions.

サービスを提供するホストが利用できないことに次いで、NET上のサービスホストを使おうとする際に遭遇する最も厄介な問題は、リモートユーザー向けの管理手続きと情報の周知が不十分なことです。この論文では、この問題を検討し、解決策を提案します。

When computer systems begin to service remote users, some of the operating procedures which produced a functioning environment for local users may not be satisfactory for those who are off-site. It may be that these procedures were already inadequate, but the local community developed a set of informal procedures to augment the formal ones. It may also be true that the established formal procedures were completely satisfactory for local users, but failed when an attempt was made to extend them to the remote user. In either case, this paper asserts that a problem exists and offers a set of suggestions for its amelioration.

コンピューターシステムがリモートユーザーへのサービスを始めると、ローカルユーザーにとっては機能する環境を生み出していた運用手続きの一部が、拠点の外にいる人々にとっては満足のいくものでなくなる場合があります。それらの手続きはもともと不十分だったものの、ローカルのコミュニティーが正式な手続きを補う一連の非公式な手続きを作り上げていたのかもしれません。あるいは、確立された正式な手続きはローカルユーザーにとって完全に満足のいくものだったものの、それをリモートユーザーに拡張しようとしたときにうまくいかなかったのかもしれません。いずれの場合も、この論文は問題が存在することを主張し、その改善のための一連の提案を示します。

Existing Information

既存の情報

Having used (or attempted to use) the information currently available, I should first summarize the existing sources and indicate that they don't meet total needs. There is the resource notebook index. The index is an ordered list of attributes which refer one to the appropriate main entry for hosts exhibiting that attribute. When the index is completed, it will reference the main entries in the resource notebook, to which we now turn out attention. On the whole, the main entry contains a summary of the hardware and software services available. At this site, these entries serve as a "shopping list" from which we may select the service center hosts which may be suitable for the computing we wish to undertake. Some administrative information is also provided. Using the outline of a host-site subsection, this information consists of: I. Personnel; V.B. Rate structure; V.D. Long-term storage; VII. Login; VIII. Operator Communication; IX. Miscellaneous; and X. Programs. The discussion under "IX. Miscellaneous" included a statement of intention to include an elaborated documentation section in a future revision of the resource book. This is most urgently required. This paper contains a proposal which might constitute the outline for that section.

現在利用できる情報を使ってみた（あるいは使おうとした）経験から、まず既存の情報源を要約し、それらが必要なものをすべて満たしてはいないことを示しておきます。まず、リソースノートブック（resource notebook）の索引があります。この索引は属性を並べた一覧で、それぞれの属性から、その属性を持つホストの該当する主項目を参照できるようになっています。索引が完成すれば、リソースノートブックの主項目を参照することになります。そこで、次に主項目に目を向けます。主項目には、全体として、利用できるハードウェアとソフトウェアのサービスの概要が含まれています。私たちの拠点では、これらの項目を「買い物リスト」として使い、行おうとしている計算に適したサービスセンターのホストを選んでいます。管理に関する情報もいくらか提供されています。ホストサイトの小節の概要に従うと、この情報は次のもので構成されています。I. 担当者、V.B. 料金体系、V.D. 長期保存、VII. ログイン、VIII. オペレーターとの連絡、IX. その他、X. プログラム。「IX. その他」の中で、リソースブックの将来の改訂版に詳しい文書のセクションを含める意向が述べられていました。これは最も緊急に必要とされているものです。この論文には、そのセクションの概要となりうる提案が含まれています。

Another source of information concerning serving hosts is the NIC. Some sites have submitted existing documentation to the NIC; some have even written special documents to assist network users. There are several problems however: It may be difficult to learn about said documents, especially for someone new to the ARPANET and/or the NIC. NIC policy is to lend the documents, which is fine for browsing but unacceptable for reference.

サービスを提供するホストに関するもう1つの情報源はNICです。既存の文書をNICに提出しているサイトもあり、ネットワークユーザーを支援するための特別な文書を書いたサイトさえあります。しかし、いくつかの問題があります。そのような文書について知ることは、特にARPANETやNICに慣れていない人にとっては難しい場合があります。NICの方針は文書を貸し出すというもので、ざっと目を通すには問題ありませんが、参照用としては受け入れられません。

必要な情報

ここからは、アンケート形式を用いて、NIC 6801を補うために使える追加の概要項目を示します。

XI. 財務上の取り決めに関する管理手続き

利用を検討しているユーザーは誰に連絡すればよいですか？

システムを（無料で）試用する方法はありますか？

コンピューターサービスのアカウントはどのように開設しますか？

How does one obtain the necessary blank administrative forms?

必要な管理用の書式の用紙はどのように入手しますか？

すべての経費（たとえばマニュアルや郵送料）をコンピューターサービスのアカウントに請求できますか？

How does one determine the status of his account?

自分のアカウントの状況はどのように確認しますか？

複数のユーザーとアカウントの関係はどうなっていますか？

セッション中に発生している料金はどのように確認できますか？

アカウントの明細書はどのくらいの頻度で発行されますか？

発行された明細書は、どのくらい最新の状態を反映していますか？

各サブシステムとアプリケーションプログラムの文書は利用できますか？

Implementation

実施

Much of the information suggested herein as being beneficial for remote user would also apply to local users. Perhaps much of it already exists in local documentation. I assert that the remote user is usually unable to easily find the information, especially when he works with several remote hosts. Presenting the information in a format that followed a standard outline would certainly be a service. I also recognize that preparation of this information might involve a duplication of effort, and would possibly produce two documents which had to be updated when changes occurred. One solution is to follow the outline in producing a guide to the literature available from the host site.

リモートユーザーにとって有益であるとしてここで提案した情報の多くは、ローカルユーザーにも当てはまるでしょう。おそらく、その多くはすでにローカルの文書に存在しています。しかし私は、リモートユーザーは、特に複数のリモートホストを使って作業する場合、通常はその情報を簡単に見つけられないと主張します。標準的な概要に従った形式で情報を提示することは、間違いなく役に立つサービスになるでしょう。また、この情報を準備するには作業の重複が生じる可能性があり、変更が生じたときに更新しなければならない文書が2つできてしまうかもしれないことも認識しています。1つの解決策は、この概要に従って、ホストサイトから入手できる文献へのガイドを作成することです。
