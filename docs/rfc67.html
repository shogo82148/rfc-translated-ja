RFC 67

Proposed Change to Host/IMP Spec to Eliminate Marking

RFC 67

マーキングをなくすためのホスト/IMP仕様の変更の提案

Abstract

概要

[IMPORTANT]

[重要]

Before he left for Norway, Dave Walden observed that there was a simple change to the Host/IMP specifications which would eliminate all "marking" problems. The change is to separate the leader from the text of regular messages, and then to send them as consecutive messages instead of one packed message. The text would then start on a word boundary no matter what the word lengths of the machines involved. The process would take place on both IMP-to-Host and Host-to-IMP messages.

Dave Waldenはノルウェーへ発つ前に、ホスト/IMP仕様に簡単な変更を加えるだけで、「マーキング」の問題をすべてなくせることに気づきました。その変更とは、通常のメッセージのリーダーとテキストを分離し、1つにまとめたメッセージとしてではなく、連続した別々のメッセージとして送るというものです。そうすれば、関係するマシンのワード長が何であっても、テキストはワード境界から始まることになります。この処理は、IMPからホストへのメッセージとホストからIMPへのメッセージの両方で行います。

We can see no disadvantages to this scheme, and a sampling of Host reactions range from neutral to wildly enthusiastic. Therefore, we tentatively plan to implement this change. We recognize that this change will involve Host program changes, and that the new release must be scheduled to coincide with those changes. We propose providing modified Host spec text along with a one week notice of the new release.

私たちはこの方式に欠点を見いだせず、いくつかのホストに反応を聞いてみたところ、中立的なものから熱烈に歓迎するものまでさまざまでした。そこで、暫定的にこの変更を実装する予定です。この変更によってホストのプログラムの変更が必要になること、そして新しいリリースの時期をそれらの変更に合わせなければならないことは承知しています。私たちは、修正したホスト仕様の文書を、新しいリリースの1週間前の予告とともに提供することを提案します。

If anyone sees a flaw in this scheme, or is unhappy about it, please contact BBN quickly, since a new version of the IMP program is already in the works.

この方式に欠陥を見つけた方や、この方式に不満がある方は、すでにIMPプログラムの新しい版の作業が進んでいるので、早めにBBNまでご連絡ください。
