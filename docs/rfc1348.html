このメモは、インターネットコミュニティーのための実験的プロトコル（Experimental Protocol）を定義します。改善のための議論と提案を求めます。このプロトコルの標準化の状態とステータスについては、「IAB Official Protocol Standards」の最新版を参照してください。このメモの配布は無制限です。

Introduction

はじめに

This RFC defines the format of two new Resource Records (RRs) for the Domain Name System (DNS), and reserves corresponding DNS type mnemonic and numerical codes. This format may be used with the any proposal that has variable length addresses, but is targeted for CLNP use.

このRFCは、ドメインネームシステム（DNS）のための2つの新しいリソースレコード（RR）の形式を定義し、対応するDNSのタイプのニーモニックと数値コードを予約します。この形式は可変長アドレスを持つどのような提案でも使用できますが、CLNPでの使用を対象としています。

This memo assumes that the reader is familiar with the DNS [3],[4].

このメモは、読者がDNS[3],[4]に精通していることを前提としています。

Background

背景

This section describes an experimental representation of NSAP addresses in the DNS. There are several reasons to take this approch. First, it provides simple documentation of the correct addresses to use in static configurations of CLNP compliant hosts and routers.

このセクションでは、DNSにおけるNSAPアドレスの実験的な表現について説明します。この方式をとる理由はいくつかあります。第一に、CLNPに準拠したホストやルーターの静的な設定で使う正しいアドレスを、簡単に文書化できます。

NSAP support requires that a new DNS resource record entry type ("NSAP") be defined, to store longer Internet (i.e., NSAP) addresses. This resource record allows mapping from DNS names to NSAP addresses, and will contain entries for systems which are able to run Internet applications, over TCP or UDP, over CLNP.

NSAPをサポートするには、より長いインターネット（つまりNSAP）アドレスを格納するために、新しいDNSリソースレコードのエントリータイプ（「NSAP」）を定義する必要があります。このリソースレコードにより、DNS名からNSAPアドレスへの対応づけが可能になります。このリソースレコードには、CLNP上のTCPやUDPの上でインターネットアプリケーションを実行できるシステムのエントリーが含まれます。

The backward translation (from NSAP address to DNS name) is facilitated by definition of an associated resource record. This resource record is known as "NSAP-PTR", and is used in a manner analogous to the existing "in-addr.arpa".

逆方向の変換（NSAPアドレスからDNS名へ）は、関連するリソースレコードを定義することで容易になります。このリソースレコードは「NSAP-PTR」と呼ばれ、既存の「in-addr.arpa」と同様の方法で使用します。

These RRs are intended for use in a proposal [6] by one of the members of the NOOP WG to address the next-generation internet.

これらのRRは、次世代インターネットに取り組むためにNOOP WGのメンバーの1人が出した提案[6]で使用することを意図しています。

The NSAP RR

NSAP RR

The NSAP RR is defined with mnemonic NSAP and type code 22 (decimal).

NSAP RRは、ニーモニックNSAP、タイプコード22（10進数）で定義します。

An NSAP (Network Service Access Protocol) number is a unique string to OSI transport service.

NSAP（Network Service Access Protocol）番号は、OSIトランスポートサービスに対して一意な文字列です。

The numbering plan follows RFC 1237 and associated OSI definitions for NSAP format.

番号計画は、RFC 1237と、NSAPの形式に関する関連するOSIの定義に従います。

NSAP has the following format:

NSAPの形式は次のとおりです。

<owner> <ttl> <class> NSAP <length> <NSAP-address>

<owner> <ttl> <class> NSAP <length> <NSAP-address>

All fields are required.

すべてのフィールドが必須です。

<length> identifies the number of octets in the <NSAP-address> as defined by the various national and international authorities.

<length>は、さまざまな国内および国際的な機関によって定義された<NSAP-address>のオクテット数を示します。

<NSAP-address> enumerates the actual octet values assigned by the assigning authority. Its format in master files is a <character-string> syntactically identical to that used in TXT and HINFO.

<NSAP-address>は、割り当て機関によって割り当てられた実際のオクテット値を列挙したものです。マスターファイルにおける形式は<character-string>で、TXTやHINFOで使われるものと構文上同一です。

The format of NSAP is class insensitive. NSAP RR causes no additional section processing.

NSAPの形式はクラスに依存しません。NSAP RRによって追加セクションの処理が発生することはありません。

For example:

たとえば、次のようになります。

foo.bar.com.    IN  NSAP   21 47000580ffff000000321099991111222233334444
host.school.de  IN  NSAP   17 39276f3100111100002222333344449876

foo.bar.com.    IN  NSAP   21 47000580ffff000000321099991111222233334444
host.school.de  IN  NSAP   17 39276f3100111100002222333344449876

The RR data is the ASCII representation of the digits. It is encoded as two <character-strings>, i.e., count followed by characters.

RRデータは、数字をASCIIで表現したものです。これは2つの<character-strings>、つまり、文字数とそれに続く文字としてエンコードされます。

The NSAP-PTR RR

NSAP-PTR RR

The NSAP-PTR RR is defined with mnemonic NSAP-PTR and a type code 23 (decimal).

NSAP-PTR RRは、ニーモニックNSAP-PTR、タイプコード23（10進数）で定義します。

Its function is analogous to the PTR record used for IP addresses [4],[7].

その機能は、IPアドレスに使われるPTRレコード[4],[7]と同様です。

NSAP-PTR has the following format:

NSAP-PTRの形式は次のとおりです。

<NSAP-suffix> <ttl> <class> NSAP-PTR <owner>

<NSAP-suffix> <ttl> <class> NSAP-PTR <owner>

All fields are required.

すべてのフィールドが必須です。

<NSAP-suffix> enumerates the actual octet values assigned by the assigning authority for the LOCAL network. Its format in master files is a <character-string> syntactically identical to that used in TXT and HINFO.

<NSAP-suffix>は、ローカル（LOCAL）ネットワークに対して割り当て機関が割り当てた実際のオクテット値を列挙したものです。マスターファイルにおける形式は<character-string>で、TXTやHINFOで使われるものと構文上同一です。

The format of NSAP-PTR is class insensitive. NSAP-PTR RR causes no additional section processing.

NSAP-PTRの形式はクラスに依存しません。NSAP-PTR RRによって追加セクションの処理が発生することはありません。

For example:

たとえば、次のようになります。

In net ff08000574.nsap-in-addr.arpa:

ネットff08000574.nsap-in-addr.arpaでは次のとおりです。

444433332222111199990123000000ff    NSAP-PTR   foo.bar.com.

444433332222111199990123000000ff    NSAP-PTR   foo.bar.com.

Or in net 11110031f67293.nsap-in-addr.arpa:

また、ネット11110031f67293.nsap-in-addr.arpaでは次のとおりです。

67894444333322220000  NSAP-PTR        host.school.de.

67894444333322220000  NSAP-PTR        host.school.de.

The RR data is the ASCII representation of the digits. It is encoded as a <character-string>.

RRデータは、数字をASCIIで表現したものです。これは<character-string>としてエンコードされます。
