RFC 79

Logger Protocol Error

RFC 79

ロガープロトコルの誤り

Abstract

概要

A conflict was recently discovered between the official NCP protocol as described in protocol document 1 and the logger protocol as described in RFC 66 by Steve Crocker. Steve suggested that we put out an RFC to alert the network community to this point.

プロトコル文書1に記述された公式のNCPプロトコルと、Steve CrockerがRFC 66で記述したロガープロトコルとの間に矛盾があることが最近わかりました。Steveから、この点をネットワークコミュニティーに知らせるためにRFCを出してはどうかと提案がありました。

In RFC 66, it is proposed that an ALL allocate command be sent immediately following an RTS or STR request for connection. This conflicts with the restriction stated in Protocol Document 1 that an ALL command can be given only for an "open" connection.

RFC 66では、接続を要求するRTSまたはSTRの直後にALL（割り当て）コマンドを送信することが提案されています。これは、ALLコマンドは「オープン」した接続に対してのみ発行できるという、プロトコル文書1に記述された制約と矛盾します。

To not be required to handle an ALL command before a connection is established is a simplifying restriction that an NCP implementation may take advantage of. For example, the Multics NCP is currently designed this way. For this reason, and also because we believe that the NCP protocol should not be changed now except for critical reasons it is felt that the proposed logger protocol should be modified to agree with the existing NCP protocol.

接続が確立する前にALLコマンドを処理しなくてよいというのは、NCPの実装が利用できる、実装を単純にする制約です。たとえば、MulticsのNCPは現在このように設計されています。この理由から、また、重大な理由がない限り今はNCPプロトコルを変更すべきではないと考えていることからも、提案されたロガープロトコルを既存のNCPプロトコルに合わせて修正すべきだと考えます。
