An IETF URN Sub-Namespace for OAuth

RFC 6755

OAuthのためのIETF URNサブ名前空間

Abstract

概要

This document establishes an IETF URN Sub-namespace for use with OAuth-related specifications.

この文書は、OAuth関連の仕様で使用するためのIETF URNサブ名前空間（Sub-namespace）を確立します。

1. Introduction

1. はじめに

Various extensions and companion specifications to the OAuth 2.0 Authorization Framework [OAUTH-V2] utilize URIs to identify the extension in use or other relevant context. This document creates and registers an IETF URN Sub-namespace, as documented in RFC 3553 [RFC3553], for use with such specifications. The new 'oauth' Sub-namespace is urn:ietf:params:oauth, and OAuth relevant parameters will be established underneath it.

OAuth 2.0認可フレームワーク[OAUTH-V2]に対するさまざまな拡張や関連仕様は、使用中の拡張やその他の関連するコンテキストを識別するためにURIを利用しています。この文書は、そのような仕様で使用するために、RFC 3553[RFC3553]に記載されているとおりにIETF URNサブ名前空間を作成し、登録します。新しい'oauth'サブ名前空間はurn:ietf:params:oauthであり、OAuthに関連するパラメーターはその下に確立されます。

2. Registration Template

2. 登録テンプレート

If a registrant wishes to have an OAuth URI registered, then a URN of the form urn:ietf:params:oauth:<value> will be requested where <value> is a suitable representation of the functionality or concept being registered.

登録者がOAuth URIの登録を希望する場合は、urn:ietf:params:oauth:<value>という形式のURNを要求することになります。ここで、<value>は登録する機能や概念を適切に表現したものです。

The registration procedure for new entries requires a request in the form of the following template and is "Specification Required" per RFC 5226 [RFC5226].

新しいエントリーの登録手順では、次のテンプレートの形式による要求が必要であり、RFC 5226[RFC5226]に基づく「Specification Required（仕様が必要）」となります。

URN:
The URI that identifies the registered functionality.
Common Name:
The name by which the functionality being registered is generally known.
Change Controller:
For Standards Track RFCs, state "IETF". For others, give the name of the responsible party. Other details (e.g., postal address, email address, and home page URI) may also be included.
Specification Document(s):
Reference to the document that specifies the URI, preferably including a URI that can be used to retrieve a copy of the document. An indication of the relevant sections may also be included but is not required.
URN:
登録する機能を識別するURI。
一般名（Common Name）:
登録する機能が一般に知られている名前。
変更管理者（Change Controller）:
標準化過程のRFCの場合は「IETF」と記載します。それ以外の場合は、責任者の名前を記載します。その他の詳細（たとえば、郵送先住所、電子メールアドレス、ホームページのURI）を含めてもかまいません。
仕様文書（Specification Document(s)）:
そのURIを規定している文書への参照。できれば、その文書のコピーを取得するために使用できるURIを含めます。関連するセクションを示してもかまいませんが、必須ではありません。

The registration request for the urn:ietf:params:oauth URN Sub-namespace is found in the IANA Considerations section of this document (Section 4).

urn:ietf:params:oauth URNサブ名前空間の登録要求は、この文書のIANAに関する考慮事項のセクション（セクション4）にあります。

2.1. Example Registration Request

2.1. 登録要求の例

The following is an example registration request for a URI underneath the urn:ietf:params:oauth Sub-namespace. The requested URI represents a new OAuth 2.0 grant type.

次は、urn:ietf:params:oauthサブ名前空間の下のURIに対する登録要求の例です。要求されているURIは、新しいOAuth 2.0のグラントタイプを表します。

This is a request to IANA to please register the value "grant-type:example" in the registry urn:ietf:params:oauth established in an IETF URN Sub-namespace for OAuth.

これは、OAuthのためのIETF URNサブ名前空間に確立されたレジストリーurn:ietf:params:oauthに値「grant-type:example」を登録するよう、IANAに依頼するものです。

  • URN: urn:ietf:params:oauth:grant-type:example
  • Common Name: An Example Grant Type for OAuth 2.0
  • Change controller: IETF
  • Specification Document: [the document URI]
  • URN: urn:ietf:params:oauth:grant-type:example
  • 一般名（Common Name）: An Example Grant Type for OAuth 2.0
  • 変更管理者（Change controller）: IETF
  • 仕様文書（Specification Document）: [文書のURI]

3. Security Considerations

3. セキュリティーに関する考慮事項

There are no additional security considerations beyond those already inherent to using URNs. Security considerations for URNs in general can be found in RFC 2141 [RFC2141].

URNの使用にもともと伴うもの以外に、追加のセキュリティーに関する考慮事項はありません。URN全般のセキュリティーに関する考慮事項は、RFC 2141[RFC2141]にあります。

Any work that is related to OAuth would benefit from familiarity with the security considerations of the OAuth 2.0 Authorization Framework [OAUTH-V2].

OAuthに関連するあらゆる作業は、OAuth 2.0認可フレームワーク[OAUTH-V2]のセキュリティーに関する考慮事項をよく理解しておくことで恩恵を受けるでしょう。

4. IANA Considerations

4. IANAに関する考慮事項

IANA has created the following:

IANAは次のものを作成しました。

  • The registration of a new IANA URN Sub-namespace, urn:ietf:params:oauth:, per RFC 3553 [RFC3553]. The registration request can be found in Section 4.1 below.
  • A new registry called the "OAuth URI" registry for URNs subordinate to urn:ietf:params:oauth. The registry "OAuth URI" has been added to a new top-level registry called "OAuth Parameters" as defined by [OAUTH-V2]. Instructions for a registrant to request the registration of such a URN are in Section 2.
  • RFC 3553[RFC3553]に基づく、新しいIANA URNサブ名前空間urn:ietf:params:oauth:の登録。登録要求は、後述のセクション4.1にあります。
  • urn:ietf:params:oauthに従属するURNのための「OAuth URI」レジストリーという新しいレジストリー。レジストリー「OAuth URI」は、[OAUTH-V2]で定義された「OAuth Parameters」という新しいトップレベルのレジストリーに追加されました。登録者がそのようなURNの登録を要求するための手順は、セクション2にあります。

4.1. IETF URN Sub-Namespace Registration urn:ietf:params:oauth

4.1. urn:ietf:params:oauthのIETF URNサブ名前空間の登録

Per RFC 3553 [RFC3553], IANA has registered a new URN Sub-namespace, urn:ietf:params:oauth.

RFC 3553[RFC3553]に基づき、IANAは新しいURNサブ名前空間urn:ietf:params:oauthを登録しました。

  • Registry name: oauth
  • Specification: [this document]
  • Repository: [The registry created in Section 2.]
  • Index value: values subordinate to urn:ietf:params:oauth are of the form urn:ietf:params:oauth:<value> with <value> as the index value. It is suggested that <value> include both a "class" and an "identifier-within-class" component, with the two components being separated by a colon (":"); other compositions of the <value> may also be used.
  • レジストリー名（Registry name）: oauth
  • 仕様（Specification）: [この文書]
  • リポジトリー（Repository）: [セクション2で作成したレジストリー。]
  • インデックス値（Index value）: urn:ietf:params:oauthに従属する値は、urn:ietf:params:oauth:<value>という形式であり、<value>がインデックス値となります。<value>には「class」と「identifier-within-class」の両方の構成要素を含め、2つの構成要素をコロン（「:」）で区切ることを提案します。<value>のほかの構成を使用してもかまいません。
