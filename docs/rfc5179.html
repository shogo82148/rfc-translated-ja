Generic Security Service Application Program Interface (GSS-API) Domain-Based Service Names Mapping for the Kerberos V GSS Mechanism

RFC 5179

Kerberos V GSSメカニズムにおける汎用セキュリティーサービスアプリケーションプログラムインターフェイス（GSS-API）のドメインベースのサービス名のマッピング

Abstract

概要

This document describes the mapping of Generic Security Service Application Program Interface (GSS-API) domain-name-based service principal names onto Kerberos V principal names.

この文書は、汎用セキュリティーサービスアプリケーションプログラムインターフェイス（Generic Security Service Application Program Interface: GSS-API）のドメイン名ベースのサービスプリンシパル名を、Kerberos Vのプリンシパル名にマッピングする方法を説明します。

1. Domain-Based Names for the Kerberos V GSS-API Mechanism

1. Kerberos V GSS-APIメカニズムにおけるドメインベースの名前

In accordance with [RFC5178], this document provides the mechanism-specific details needed to implement GSS-API [RFC2743] domain-based service names with the Kerberos V GSS-API mechanism [RFC4121].

[RFC5178]に従い、この文書は、Kerberos V GSS-APIメカニズム[RFC4121]でGSS-API[RFC2743]のドメインベースのサービス名を実装するために必要な、メカニズム固有の詳細を提供します。

GSS_C_NT_DOMAINBASED_SERVICE name SHOULD be mapped to Kerberos V principal names as follows:

GSS_C_NT_DOMAINBASED_SERVICE名は、次のようにKerberos Vのプリンシパル名にマッピングされるべきです（SHOULD）。

  • the <service> name becomes the first (0th) component of the Kerberos V principal name;
  • the <hostname> becomes the second component of the Kerberos V principal name;
  • the <domain> name becomes the third component of the Kerberos V principal name;
  • the realm of the resulting principal name is that which corresponds to the domain name, treated as a hostname.
  • <service>名は、Kerberos Vのプリンシパル名の最初の（0番目の）コンポーネントになります。
  • <hostname>は、Kerberos Vのプリンシパル名の2番目のコンポーネントになります。
  • <domain>名は、Kerberos Vのプリンシパル名の3番目のコンポーネントになります。
  • 結果として得られるプリンシパル名のレルムは、ホスト名として扱ったドメイン名に対応するレルムです。

The same name canonicalization considerations and methods as used elsewhere in the Kerberos V GSS-API mechanism [RFC4121] and Kerberos V [RFC4120] in general apply here.

Kerberos V GSS-APIメカニズム[RFC4121]や、Kerberos V[RFC4120]全般のほかの箇所で使用されているのと同じ、名前の正規化に関する考慮事項と方法がここでも適用されます。

Implementations SHOULD use a Kerberos V name-type of NTT-SRVT-HST-DOMAIN (which has the value 12) but MAY use NT-UNKNOWN instead.

実装は、Kerberos Vの名前タイプとしてNTT-SRVT-HST-DOMAIN（値は12）を使用すべきです（SHOULD）が、代わりにNT-UNKNOWNを使用してもよいです（MAY）。

3. Internationalization Considerations

3. 国際化に関する考慮事項

It is unclear, at this time, how best to address internationalization of Kerberos V domain-based principal names. This is because the Kerberos V core protocol internationalization project is incomplete.

現時点では、Kerberos Vのドメインベースのプリンシパル名の国際化にどう対処するのが最善かは明らかではありません。これは、Kerberos Vのコアプロトコルの国際化プロジェクトが完了していないためです。

However, clearly the best way to interoperate when using Kerberos V domain-based principal names is to use ACE-encoded internationalized domain names [RFC3490] for the hostname and domain name slots of a Kerberos V domain-based principal name. Therefore Kerberos V GSS-API mechanism implementations MUST do just that.

しかし、Kerberos Vのドメインベースのプリンシパル名を使用する際に相互運用するための最善の方法が、Kerberos Vのドメインベースのプリンシパル名のホスト名とドメイン名のスロットに、ACEエンコードされた国際化ドメイン名[RFC3490]を使用することであるのは明らかです。したがって、Kerberos V GSS-APIメカニズムの実装は、まさにそのようにしなければなりません（MUST）。

4. Examples

4. 例

  • The domain-based name, of generic form, "ldap@foo.example@ds1.foo.example" may map to a Kerberos V principal name like: "ldap/ds1.foo.example/foo.example@FOO.EXAMPLE"
  • The domain-based name, of generic form, "kadmin@foo.example@kdc1.foo.example" may map to a Kerberos V principal name like: "kadmin/kdc1.foo.example/foo.example@FOO.EXAMPLE"
  • 一般形式のドメインベースの名前「ldap@foo.example@ds1.foo.example」は、「ldap/ds1.foo.example/foo.example@FOO.EXAMPLE」のようなKerberos Vのプリンシパル名にマッピングされる場合があります。
  • 一般形式のドメインベースの名前「kadmin@foo.example@kdc1.foo.example」は、「kadmin/kdc1.foo.example/foo.example@FOO.EXAMPLE」のようなKerberos Vのプリンシパル名にマッピングされる場合があります。

5. Security Considerations

5. セキュリティーに関する考慮事項

See [RFC5178].

[RFC5178]を参照してください。

It is important for the security of protocols using the Kerberos V GSS-API mechanism and domain-based names, that the realm of domain-based principal names be derived from the hostname, rather than the domain name slots of the input domain-based name string.

Kerberos V GSS-APIメカニズムとドメインベースの名前を使用するプロトコルのセキュリティーにとって、ドメインベースのプリンシパル名のレルムを、入力されたドメインベースの名前文字列のドメイン名スロットからではなく、ホスト名から導出することが重要です。
