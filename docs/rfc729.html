RFC 729

TELNET Byte Macro Option

RFC 729

Telnetのバイトマクロオプション

1. Command name and code:

1. コマンド名とコード

BM 19

BM 19

2. Command Meanings:

2. コマンドの意味

IAC WILL BM
The sender of this command REQUESTS or AGREES to use the BM option, and will send sing1e data characters which are to be interpreted as if longer data strings had been sent.
IAC WON'T BM
The sender of this option REFUSES to send single data characters which are to be interpreted as if longer data strings had been sent.
IAC DO BM
The sender REQUESTS or AGREES to have the other side (send of WILL BM) issue send single data characters which are to be interpreted as if longer data strings had been sent.
IAC DON'T BM
The sender REFUSES to allow the other side to send single data characters which are to be interpreted as if longer data strings had been sent.
IAC SB BM <DEFINE> <macro byte> <count> <expansion string> IAC SE

where:

<macro byte>
is the data byte actually to be sent across the network; it may NOT be Telnet IAC (decimal 255).
<count>
is a one-byte binary number, indicating how many <expansion string> characters follow, up to the ending IAC SE, but not including it.
<expansion string>
is a string of one or more Telnet ASCII characters and/or commands, which the <macro byte> is to represent; any character may occur within an <expansion string>.

The indicated <macro byte> will be sent instead of the indicated <expansion string>. The receiver of the <macro byte> (the sender of the DO BM) is to behave EXACTLY as if the <expansion string> of bytes had instead been received from the network. This interpretation is to occur before any other Telnet interpretations, unless the <macro byte> occurs as part of a BM subcommand; in this case no special interpretation is to be made.

Note that the effect of a particular <macro byte> may be negated by reseting it to "expand" into itself.

<DEFINE> is decimal 01.

IAC SB BM <ACCEPT> <macro byte> IAC SE

The receiver of the <DEFINE> for <macro byte> accepts the requested definition and will perform the indicating expansion whenever a <macro byte> is received and is not part of a BM subcommand.

<ACCEPT> is decimal 02.

IAC SB BM <REFUSE> <macro byte> <REASON> IAC SE

The receive of the <DEFINE> for <macro byte> refuses to perform the indicated translation from <macro byte> to <expansion string> either because the particular <macro byte> is not an acceptable choice or because the length of the <expansion string> exceeds available storage.

<REFUSE> is decimal 03.

<REASON> may be

  • <BAD CHOICE> which is decimal 01; or
  • <TOO LONG> which is decimal 02.
IAC SB BM <LITERAL> <macro byte> IAC SE

The <macro byte> is to be treated as real data, rather than as representative of the <expansion string>

<LITERAL> is decimal 03.

IAC WILL BM
このコマンドの送信者は、BMオプションを使用することを要求する（REQUESTS）か、それに同意し（AGREES）、より長いデータ文字列が送信されたかのように解釈される単一のデータ文字を送信します。
IAC WON'T BM
このオプションの送信者は、より長いデータ文字列が送信されたかのように解釈される単一のデータ文字を送信することを拒否します（REFUSES）。
IAC DO BM
送信者は、相手側（WILL BMの送信者）が、より長いデータ文字列が送信されたかのように解釈される単一のデータ文字を送信することを要求する（REQUESTS）か、それに同意します（AGREES）。
IAC DON'T BM
送信者は、相手側が、より長いデータ文字列が送信されたかのように解釈される単一のデータ文字を送信することを許可しません（REFUSES）。
IAC SB BM <DEFINE> <macro byte> <count> <expansion string> IAC SE

ここで、

<macro byte>
は、実際にネットワークを越えて送信されるデータバイトです。TelnetのIAC（10進数の255）であってはなりません（NOT）。
<count>
は、1バイトの2進数であり、末尾のIAC SEまで（ただしIAC SEは含まない）に続く<expansion string>の文字数を示します。
<expansion string>
は、<macro byte>が表す、1つ以上のTelnet ASCII文字またはコマンド（あるいはその両方）からなる文字列です。<expansion string>の中には、どの文字が現れてもかまいません。

指定した<expansion string>の代わりに、指定した<macro byte>が送信されます。<macro byte>の受信者（DO BMの送信者）は、その代わりに<expansion string>のバイト列をネットワークから受信したのとまったく同じように（EXACTLY）振る舞わなければなりません。この解釈は、他のどのTelnetの解釈よりも先に行います。ただし、<macro byte>がBMサブコマンドの一部として現れる場合は例外で、この場合は特別な解釈を行いません。

特定の<macro byte>の効果は、それ自身に「展開」されるように再設定することで打ち消せることに注意してください。

<DEFINE>は10進数の01です。

IAC SB BM <ACCEPT> <macro byte> IAC SE

<macro byte>に対する<DEFINE>の受信者は、要求された定義を受け入れ、BMサブコマンドの一部でない<macro byte>を受信するたびに、指定された展開を行います。

<ACCEPT>は10進数の02です。

IAC SB BM <REFUSE> <macro byte> <REASON> IAC SE

<macro byte>に対する<DEFINE>の受信者は、その<macro byte>が受け入れられない選択であるか、<expansion string>の長さが利用可能な記憶領域を超えるかのいずれかの理由で、<macro byte>から<expansion string>への指定された変換を行うことを拒否します。

<REFUSE>は10進数の03です。

<REASON>は次のいずれかです。

  • <BAD CHOICE>（10進数の01）
  • <TOO LONG>（10進数の02）
IAC SB BM <LITERAL> <macro byte> IAC SE

<macro byte>を、<expansion string>を表すものとしてではなく、実際のデータとして扱います。

<LITERAL>は10進数の03です。

3. Default:

3. デフォルト

WON'T BM -- DON'T BM
No reinterpretation of data is allowed.
WON'T BM -- DON'T BM
データの再解釈は許可されません。

4. Motivation for the option:

4. このオプションの動機

Subcommands for Telnet options currently require a minimum of five characters to be sent over the network (i.e., IAC SB <Option name> IAC SE). For sub-commands which are employed infrequently, in absolute numbers and in relation to normal data, this overhead is tolerable. In other cases, however, it is not. For example, data which is sent in a block-oriented fashion may need a "block separator" mark. If blocks are commonly as small as five or ten bytes, then most of the cross-net data will be control information. The BM option is intended as a simple data compression technique, to remove this overhead from the communication channel.

現在、Telnetオプションのサブコマンドでは、ネットワーク上で最低5文字（つまり、IAC SB <Option name> IAC SE）を送信する必要があります。絶対数の面でも通常のデータとの比較の面でもあまり使われないサブコマンドであれば、このオーバーヘッドは許容できます。しかし、そうでない場合もあります。たとえば、ブロック指向の方式で送信されるデータには、「ブロック区切り」のマークが必要になることがあります。ブロックが通常5バイトや10バイト程度の小ささであれば、ネットワークを越えるデータの大部分は制御情報になってしまいます。BMオプションは、通信路からこのオーバーヘッドを取り除くための、単純なデータ圧縮技術として意図されています。

5. Description of the option

5. このオプションの説明

The option is enabled through the standard Telnet Option negotiation process. Afterwards, the SENDER of data (the side which sends the IAC WILL BM) is free to define and use mappings between single and multiple NOT characters. Except for the ability to offer a blanket refusal, the receiver of data has no control over the definition and use of mappings.

このオプションは、標準的なTelnetオプションのネゴシエーション手順によって有効になります。その後、データの送信者（IAC WILL BMを送信した側）は、単一の文字と複数の文字（原文は「multiple NOT characters」）との間の対応付けを自由に定義して使用できます。一括して拒否できることを除いて、データの受信者は対応付けの定義と使用を制御できません。

The sender (of the WILL BM) is prohibited from using or redefining a <macro byte> until it has received an <ACCEPT> or <REFUSE>, in reply to a <DEFINE>.

（WILL BMの）送信者は、<DEFINE>への応答として<ACCEPT>または<REFUSE>を受信するまで、その<macro byte>を使用することも再定義することも禁止されています。

NOTE: The Telnet command character IAC (decimal 255) may be a member of an <expansion string> but is the ONLY character which may NOT be defined as a <macro byte>. ALL OTHER Telnet command characters use IAC as a preface and therefore occupy a SEPARATE portion of the data space than do regular data bytes.

注：Telnetのコマンド文字IAC（10進数の255）は、<expansion string>の一部にはなれますが、<macro byte>として定義できない唯一の（ONLY）文字です。その他のすべての（ALL OTHER）Telnetのコマンド文字は、IACを前置きとして使用するため、通常のデータバイトとは別の（SEPARATE）データ空間の部分を占めます。

With the exception of IAC, data transfered as part of BM subcommands are NOT to be interpreted. They are to be taken only as their normal character values. This avoids the problem of distinguishing between a character which is to be taken as a <macro byte>, and interpreted as its corresponding <expansion string>, and that same character to be taken as its usual Telnet NVT value. In all other cases, however, <macro byte>s are to be interpreted immediately, as if the <expansion string> had actually been sent across the network. Expanded strings are not subject to reinterpretation, so that recursive definitions cannot be made.

IACを除き、BMサブコマンドの一部として転送されるデータは解釈してはなりません（NOT）。それらは通常の文字の値としてのみ扱います。これにより、<macro byte>として扱われ、対応する<expansion string>として解釈されるべき文字と、通常のTelnet NVTの値として扱われるべき同じ文字とを区別するという問題を回避できます。ただし、それ以外のすべての場合には、<macro byte>は、<expansion string>が実際にネットワークを越えて送信されたかのように、ただちに解釈します。展開された文字列は再解釈の対象にならないため、再帰的な定義はできません。

The <count> in the <DEFINE> subcommand allows the receiver to allocate storage. IAC interpretation is not over-ridden during BM subcommands so that IAC SE will continue to safely terminate malformed subcommands. To include IAC as part of a <DEFINE>, the string "IAC IAC" must be sent.

<DEFINE>サブコマンドの<count>により、受信者は記憶領域を確保できます。BMサブコマンドの間もIACの解釈は無効にならないため、IAC SEで不正な形式のサブコマンドを引き続き安全に終了させられます。<DEFINE>の一部としてIACを含めるには、「IAC IAC」という文字列を送信しなければなりません。

The BM option is notably inefficient with regard to problems during <macro byte> definition and use of <macro byte>s as real data. It is expected that relatively few <macro byte>s will be defined and that they will represent relatively short strings. Since the Telnet data space between decimal 128 and decimal 254 is not normally used, except by implementations employing the original Telnet protocol, it is recommended that <macro byte>s normally be drawn from that pool.

BMオプションは、<macro byte>の定義中の問題や、<macro byte>を実際のデータとして使用することに関しては、明らかに非効率です。定義される<macro byte>は比較的少なく、それらが表すのは比較的短い文字列であると想定しています。Telnetのデータ空間のうち10進数の128から254までは、元のTelnetプロトコルを採用している実装を除いて通常は使われないので、<macro byte>は通常その範囲から選ぶことを推奨します。
