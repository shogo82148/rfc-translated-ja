RFC 660

Some changes to the IMP and the IMP/Host interface

RFC 660

IMPとIMP/Hostインターフェイスに対するいくつかの変更

Abstract

概要

In the next few weeks several changes will be made to the IMP software including changes to the IMP/Host software interface as specified in BBN Report No. 1822, Specifications for the Interconnection of a Host and an IMP. These changes come in four areas: a) decoupling of the message number sequences of Hosts; b) Host/Host access control; c) expansion of the message number window from four to eight; and d) provision for messages outside the normal message number mechanism. All changes are backward compatible with possible minor exceptions in timing.

今後数週間のうちに、IMPソフトウェアにいくつかの変更を加えます。これには、BBN Report No. 1822「Specifications for the Interconnection of a Host and an IMP」で規定されているIMP/Hostソフトウェアインターフェイスの変更も含まれます。これらの変更は、a) ホストのメッセージ番号シーケンスの分離、b) Host/Hostアクセス制御、c) メッセージ番号ウィンドウの4から8への拡大、d) 通常のメッセージ番号の仕組みの外でのメッセージの提供、という4つの分野にわたります。タイミングに関する軽微な例外がありうることを除いて、すべての変更は後方互換性を保っています。

a. Decoupling of the Host/Host message number sequences:

Since 1972 the IMP system has provided for exactly four messages to be outstanding at a time between any pair of IMPs, and thus, a total of only four messages between all the possible pairs of Hosts on the two IMPs. Because all the pairs of Hosts on the two IMPs have had to share the four outstanding messages, it has been quite possible for the various Hosts to interfere with each other. To remove this possibility of interference, the IMP's message number logic will soon be changed to allow a separate message number sequence between each pair of Hosts.

To keep manageable the space required to maintain the Host/Host message sequences above that presently are required for the IMP/IMP message sequences, the Host/Host sequences will be taken dynamically from a limited pool of possible sequences. The pool will be sufficiently large to seldom interfere with a pair of Hosts wishing to communicate. In no case will Hosts be prevented from communicating. In the event that the Hosts on an IMP desire to simultaneously communicate with so many other Hosts that the pool would be exhausted, the space in the pool is quickly multiplexed in time among all the desired Host/Host conversations so that none is stopped although all are possibly slowed.

b. Host/Host access control:
Upon instructions from ARPA, we will soon add a Host/Host access control mechanism to the IMPs. Any pair of Hosts wishing to communicate is checked (via bits in the IMP) to verify that they have administrative permission to communicate. This check normally is made whenever a pair of Hosts attempts to communicate after not having communicated for two minutes. If the pair of Hosts is not allowed to communicate, a special type of Destination Dead Message (sub-code 3) is returned to the source Host. The default case initially will be to allow all Hosts to communicate with each other.
c. Message number window.:
Once the message number sequences are on a Host/Host rather than IMP/IMP basis, the number of messages that will be permitted to be outstanding at a time between a pair of Hosts will be expanded from four to eight, permitting increased Host/Host throughput in some cases.
d. Message outside the normal mechanism:.
For certain limited experiments which are being carried on using the network, it is thought to be desirable for specified Hosts to be able to communicate outside the normal ordered, error controlled message sequences. Thus, the following expansion to the IMP/Host protocol is being provided.
a. Host/Hostのメッセージ番号シーケンスの分離：

1972年以来、IMPシステムは、任意のIMPの組の間で同時に未処理にできるメッセージをちょうど4つとしてきました。したがって、2つのIMP上のホストのありうるすべての組の間で、合計4つのメッセージしか扱えませんでした。2つのIMP上のホストのすべての組が4つの未処理メッセージを共有しなければならなかったため、さまざまなホストが互いに干渉することは十分に起こりえました。この干渉の可能性を取り除くため、IMPのメッセージ番号のロジックを近いうちに変更し、ホストの組ごとに別々のメッセージ番号シーケンスを使えるようにします。

Host/Hostのメッセージシーケンスを保持するのに必要な領域を、現在IMP/IMPのメッセージシーケンスに必要な量を超えても管理可能な範囲に抑えるため、Host/Hostのシーケンスは、利用可能なシーケンスの限られたプールから動的に割り当てます。このプールは十分に大きくするので、通信したいホストの組が妨げられることはめったにありません。ホストが通信を妨げられることは決してありません。あるIMP上のホストが、プールを使い果たすほど多くのほかのホストと同時に通信しようとした場合は、プール内の領域を、必要とされるすべてのHost/Host間の会話の間で時間的にすばやく多重化します。そのため、すべての会話が遅くなる可能性はありますが、止まる会話はありません。

b. Host/Hostアクセス制御：
ARPAの指示により、近いうちにHost/Hostアクセス制御の仕組みをIMPに追加します。通信しようとするホストの組はいずれも、通信する管理上の許可を得ているかどうかが（IMP内のビットによって）検査されます。この検査は通常、ホストの組が2分間通信しなかった後に通信しようとするたびに行われます。そのホストの組が通信を許可されていない場合は、特別な種類のDestination Deadメッセージ（サブコード3）が送信元ホストに返されます。当初のデフォルトでは、すべてのホストが互いに通信できるようにします。
c. メッセージ番号ウィンドウ：
メッセージ番号シーケンスがIMP/IMP単位ではなくHost/Host単位になると、ホストの組の間で同時に未処理にできるメッセージの数を4から8に拡大します。これにより、場合によってはHost/Hostのスループットが向上します。
d. 通常の仕組みの外でのメッセージ：
ネットワークを使って行われている一部の限られた実験のために、特定のホストが、通常の順序付けられ誤り制御されたメッセージシーケンスの外で通信できることが望ましいと考えられています。そこで、IMP/Hostプロトコルに次の拡張を提供します。
  1. a single packet message coming from the source Host to the source IMP with a (new) special message type, 3, will be put directly into the IMP store-and-forward logic with a mark saying the packet is this special kind of message. A multi-packet message of type 3 will be discarded.
  2. such messages (packets) are routed normally to the destination IMP, possibly arriving out of order.
  3. at the destination IMP, messages of the special type will be put directly on the destination Host output queue skipping the reassembly logic and marked with a special (new) IMP to Host message type, also 3.
  4. there is no source-to-destination retransmission logic, no reassembly, no RFNMs, no incomplete transmissions, etc.
  5. if at any time there are insufficient resources in the network to handle one of these special messages (e.g., the destination Host won't take it), the message will be discarded.
  6. by using the special message type between the Host and the IMP, the normal message number mechanism is preserved for all the Host/Host transmissions which presently depend on it.
  1. 送信元ホストから送信元IMPに届いた、（新しい）特別なメッセージタイプ3を持つ単一パケットのメッセージは、そのパケットがこの特別な種類のメッセージであることを示す印を付けて、IMPの蓄積交換（store-and-forward）ロジックに直接入れられます。タイプ3の複数パケットのメッセージは破棄されます。
  2. そのようなメッセージ（パケット）は通常どおり宛先IMPまで経路制御され、順序どおりに到着しないこともあります。
  3. 宛先IMPでは、特別なタイプのメッセージは、再組み立てのロジックを飛ばして宛先ホストの出力キューに直接入れられ、特別な（新しい）IMPからホストへのメッセージタイプ（これも3）の印が付けられます。
  4. 送信元から宛先への再送ロジック、再組み立て、RFNM、不完全な伝送の通知などは一切ありません。
  5. これらの特別なメッセージを処理するのに十分な資源がネットワーク内にないときは（たとえば、宛先ホストがそれを受け取らない場合）、いつでもそのメッセージは破棄されます。
  6. ホストとIMPの間で特別なメッセージタイプを使うことにより、現在通常のメッセージ番号の仕組みに依存しているすべてのHost/Hostの伝送のために、その仕組みは維持されます。

Because the uncontrolled use of this mechanism will degrade the performance of the network for all users, the set of Hosts permitted to use this mechanism will be regulated by the Network Control Center.

この仕組みを無制限に使うと、すべてのユーザーにとってネットワークの性能が低下するため、この仕組みの使用を許可されるホストの集合は、ネットワーク制御センター（Network Control Center）が管理します。
