RFC 8096

The IPv6-Specific MIB Modules Are Obsolete

RFC 8096

IPv6固有のMIBモジュールは廃止されました

Abstract

概要

In 2005-2006, the IPv6 MIB update group published updated versions of the IP-MIB, UDP-MIB, TCP-MIB, and IP-FORWARD-MIB modules, which use the InetAddressType/InetAddress construct to handle IPv4 and IPv6 in the same table. This document contains versions of the obsoleted IPV6-MIB, IPV6-TC, IPV6-ICMP-MIB, IPV6-TCP-MIB, and IPV6-UDP-MIB modules for the purpose of updating MIB module repositories. This document obsoletes RFCs 2452, 2454, 2465, and 2466 (i.e., the RFCs containing these MIBs) and reclassifies them as Historic.

2005〜2006年に、IPv6 MIB更新グループは、IP-MIB、UDP-MIB、TCP-MIB、IP-FORWARD-MIBの各モジュールの更新版を発行しました。これらはInetAddressType/InetAddressの構成を使用して、IPv4とIPv6を同じテーブルで扱います。この文書には、MIBモジュールリポジトリーを更新する目的で、廃止されたIPV6-MIB、IPV6-TC、IPV6-ICMP-MIB、IPV6-TCP-MIB、IPV6-UDP-MIBの各モジュールの版を収録しています。この文書は、RFC 2452、2454、2465、2466（つまり、これらのMIBを収録したRFC）を廃止し、それらを歴史的（Historic）に再分類します。

1. Motivation

1. 動機

In 2005-2006, the IPv6 MIB update group published updated versions of the IP-MIB [RFC4293], UDP-MIB [RFC4113], TCP-MIB [RFC4022], and IP-FORWARD-MIB [RFC4292] modules, which use the InetAddressType/InetAddress construct to handle IPv4 and IPv6 in the same table. The RFC Editor marked these documents as obsoleting the corresponding IPV6-MIBs, but the extracted content of these MIBs never changed in MIB repositories, and the original RFCs (as is normal IETF policy) never changed from being Proposed Standard.

2005〜2006年に、IPv6 MIB更新グループは、IP-MIB[RFC4293]、UDP-MIB[RFC4113]、TCP-MIB[RFC4022]、IP-FORWARD-MIB[RFC4292]の各モジュールの更新版を発行しました。これらはInetAddressType/InetAddressの構成を使用して、IPv4とIPv6を同じテーブルで扱います。RFC編集者はこれらの文書を、対応するIPV6-MIBを廃止するものとして記載しましたが、MIBリポジトリーにある、これらのMIBから抽出された内容は変更されないままでした。また、もとのRFCは（IETFの通常の方針どおり）提案標準（Proposed Standard）から変更されませんでした。

Note that the timeline of these MIB modules is as shown below (and it is the added support for IPv6 in the later revision of the original modules that people often overlook).

これらのMIBモジュールの経緯は次の図のとおりであることに注意してください（人々が見落としがちなのは、もとのモジュールの後の改訂でIPv6のサポートが追加されたことです）。

                       IPv6-MIB--------X
                                        \
              IP-MIB-------------------IP-MIB--->

                       IPv6-MIB--------X
                                        \
              IP-MIB-------------------IP-MIB--->

This causes an unclear situation when simply looking at MIB repositories, so we are simply republishing these MIB modules with the Structure of Management Information (SMI) status changed to obsolete. This is an unusual step, and it is not the intended path with every obsolete MIB module; the special history of these modules led to this special step.

このため、単にMIBリポジトリーを見ただけでは状況がはっきりしません。そこで、管理情報構造（SMI: Structure of Management Information）のステータスをobsoleteに変更して、これらのMIBモジュールを単純に再発行します。これは異例の措置であり、廃止されるすべてのMIBモジュールに対して意図された手順ではありません。これらのモジュールの特殊な経緯が、この特別な措置につながりました。

8. Security Considerations

8. セキュリティーに関する考慮事項

This document contains only obsolete objects, which [RFC2578] says "should not be implemented and/or can be removed if previously implemented". Since the contents of this document should not be implemented, it has no security implications. If there were any security implications based on these objects in an implementation, removing these objects as [RFC2578] suggests would improve the security of that implementation.

この文書に含まれるのは廃止された（obsolete）オブジェクトだけです。[RFC2578]は、そのようなオブジェクトについて「実装すべきではなく、以前に実装されていた場合は削除してもよい」と述べています。この文書の内容は実装すべきではないので、この文書にはセキュリティー上の影響はありません。もし実装においてこれらのオブジェクトに基づくセキュリティー上の影響があったとしても、[RFC2578]が提案するとおりにこれらのオブジェクトを削除すれば、その実装のセキュリティーは向上するでしょう。
