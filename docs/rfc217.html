RFC 217

Specification Changes for OLS, RJE/RJOR, and SMFS

RFC 217

OLS、RJE/RJOR、SMFSの仕様変更

Abstract

概要

The following documents are hereby revised:

ここに、次の文書を改訂します：

  1. 'Specifications for Network Use of the UCSB On-Line System [16 October 70, RFC 74, NIC 5417],
  2. 'Network Specifications for Remote Job Entry and Remote Job Output Retrieval at UCSB' [22 March 71, RFC 105, NIC 5775], and
  3. 'Network Specifications for UCSB's Simple-Minded File System' [26 April 71, RFC 122, NIC 5834].
  1. 『Specifications for Network Use of the UCSB On-Line System』[16 October 70, RFC 74, NIC 5417]、
  2. 『Network Specifications for Remote Job Entry and Remote Job Output Retrieval at UCSB』[22 March 71, RFC 105, NIC 5775]、および
  3. 『Network Specifications for UCSB's Simple-Minded File System』[26 April 71, RFC 122, NIC 5834]。

Revisions are as follows:

改訂内容は次のとおりです：

  1. As far as can be determined, no Network site has written code to interface to the UCSB software documented in RFC 74 last October. Accordingly, UCSB has terminated support for that software, and hence RFC 74 is obsolete.
  2. In accordance with subsequent Host-Host protocol changes, the notion of 'message type' has been dropped from the specifications for RJE and RJOR, RFC 105. RJE/RJOR no longer send, nor expect to receive 8 bits of zeros as the first byte transmitted over a connection.
  3. In accordance with Document 2, RJE and RJOR now employ a standard ICP to create a full duplex connection to the user. Accordingly, RJE and RJOR listen on sockets x'201' and x'301', respectively (rather than on x'200' and x'300' as before). As documented in RFC 105, RJE required only a simplex connection to the user. A full duplex connection is now supported, but no data is transmitted to the user over the added simplex connection. RJOR now also supports a full duplex connection. However, if RJOR is required to call the user back when a requested job's output is ready, it still does so employing a simplex connection to the user's receive socket.
  4. RJE/RJOR and SMFS specify a byte size of eight for their connection to the user's receive socket. The user may choose the byte size for the other simplex connection to suit himself; any valid byte size is acceptable to UCSB.
  1. 確認できたかぎりでは、昨年10月にRFC 74で文書化したUCSBのソフトウェアとのインターフェースとなるコードを書いたネットワークサイトはありません。そのため、UCSBはそのソフトウェアのサポートを終了しました。したがって、RFC 74は廃止されます。
  2. その後のホスト間（Host-Host）プロトコルの変更に従い、RJEとRJORの仕様（RFC 105）から「メッセージタイプ」という概念を削除しました。RJE/RJORは、接続上で最初に送信されるバイトとして8ビットのゼロを送信することも、受信することを期待することもなくなりました。
  3. Document 2に従い、RJEとRJORは標準のICPを用いて、ユーザーとの全二重接続を作成するようになりました。そのため、RJEとRJORは、（以前のx'200'とx'300'ではなく）それぞれソケットx'201'とx'301'でlistenします。RFC 105で文書化したとおり、RJEはユーザーとの単方向接続だけを必要としていました。現在は全二重接続をサポートしていますが、追加された単方向接続を通じてユーザーにデータを送信することはありません。RJORも全二重接続をサポートするようになりました。ただし、要求されたジョブの出力の準備ができたときにRJORがユーザーにコールバックする必要がある場合は、これまでどおり、ユーザーの受信ソケットへの単方向接続を用いてコールバックします。
  4. RJE/RJORとSMFSは、ユーザーの受信ソケットへの接続のバイトサイズとして8を指定します。もう一方の単方向接続のバイトサイズは、ユーザーが都合に合わせて選んでかまいません。有効なバイトサイズであれば、UCSBはどれでも受け付けます。
