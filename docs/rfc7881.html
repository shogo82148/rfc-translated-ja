Seamless Bidirectional Forwarding Detection (S-BFD) for IPv4, IPv6, and MPLS

RFC 7881

IPv4、IPv6、MPLSのためのシームレス双方向フォワーディング検出（S-BFD）

Abstract

概要

This document defines procedures for using Seamless Bidirectional Forwarding Detection (S-BFD) in IPv4, IPv6, and MPLS environments.

この文書は、IPv4、IPv6、MPLSの環境でシームレス双方向フォワーディング検出（Seamless Bidirectional Forwarding Detection、S-BFD）を使うための手順を定義します。

1. Introduction

1. はじめに

Seamless Bidirectional Forwarding Detection (S-BFD) [RFC7880] defines a generalized mechanism to allow network nodes to seamlessly perform continuity checks to remote entities. This document defines necessary procedures for using S-BFD in IPv4, IPv6, and MPLS environments.

シームレス双方向フォワーディング検出（Seamless Bidirectional Forwarding Detection、S-BFD）[RFC7880]は、ネットワークノードがリモートエンティティーに対する導通確認（continuity check）をシームレスに実行できるようにするための汎用的なメカニズムを定義しています。この文書は、IPv4、IPv6、MPLSの環境でS-BFDを使うために必要な手順を定義します。

The reader is expected to be familiar with the IP [RFC791] [RFC2460], BFD [RFC5880], MPLS BFD [RFC5884], and S-BFD [RFC7880] terms and protocol constructs.

読者は、IP[RFC791][RFC2460]、BFD[RFC5880]、MPLS BFD[RFC5884]、S-BFD[RFC7880]の用語とプロトコル構成要素に精通していることを想定しています。

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in RFC 2119 [RFC2119].

この文書におけるキーワード「MUST」、「MUST NOT」、「REQUIRED」、「SHALL」、「SHALL NOT」、「SHOULD」、「SHOULD NOT」、「RECOMMENDED」、「MAY」、および「OPTIONAL」は、RFC 2119 [RFC2119]で説明されているとおりに解釈されます。

2. S-BFD UDP Port

2. S-BFDのUDPポート

A new UDP port is defined for use by S-BFD in IPv4, IPv6, and MPLS environments: 7784.

IPv4、IPv6、MPLSの環境でS-BFDが使うための新しいUDPポートとして、7784を定義します。

In S-BFD Control packets from the SBFDInitiator to the SBFDReflector, the SBFDReflector session MUST listen for incoming S-BFD Control packets on port 7784. SBFDInitiator sessions MUST transmit S-BFD Control packets with destination port 7784. The source port of the S-BFD Control packets transmitted by SBFDInitiator sessions can be any port, with one exception: it MUST NOT be 7784. The same UDP source port number MUST be used for all S-BFD Control packets associated with a particular SBFDInitiator session. The source port number is unique among all SBFDInitiator sessions on the system.

SBFDInitiatorからSBFDReflectorへのS-BFD制御パケットについては、SBFDReflectorセッションはポート7784で受信S-BFD制御パケットを待ち受けなければなりません（MUST）。SBFDInitiatorセッションは、宛先ポートを7784としてS-BFD制御パケットを送信しなければなりません（MUST）。SBFDInitiatorセッションが送信するS-BFD制御パケットの送信元ポートは任意のポートでかまいませんが、例外が1つあります。それは7784であってはなりません（MUST NOT）。特定のSBFDInitiatorセッションに関連付けられたすべてのS-BFD制御パケットには、同じUDP送信元ポート番号を使わなければなりません（MUST）。送信元ポート番号は、システム上のすべてのSBFDInitiatorセッションの間で一意です。

In S-BFD Control packets from the SBFDReflector to the SBFDInitiator, the SBFDInitiator session MUST listen for reflected S-BFD Control packets at its source port.

SBFDReflectorからSBFDInitiatorへのS-BFD制御パケットについては、SBFDInitiatorセッションは、反射されたS-BFD制御パケットを自身の送信元ポートで待ち受けなければなりません（MUST）。

3. S-BFD Echo UDP Port

3. S-BFDエコーのUDPポート

The BFD Echo port defined by [RFC5881], port 3785, is used for the S-BFD Echo function in IPv4, IPv6, and MPLS environments. SBFDInitiator sessions MUST transmit S-BFD Echo packets with destination port 3785. The setting of the UDP source port [RFC5881] and the procedures [RFC7880] for the S-BFD Echo function are outside the scope of this document.

IPv4、IPv6、MPLSの環境におけるS-BFDエコー機能には、[RFC5881]で定義されているBFDエコーポートであるポート3785を使います。SBFDInitiatorセッションは、宛先ポートを3785としてS-BFDエコーパケットを送信しなければなりません（MUST）。S-BFDエコー機能のためのUDP送信元ポートの設定[RFC5881]と手順[RFC7880]は、この文書の範囲外です。

4. S-BFD Control Packet Demultiplexing

4. S-BFD制御パケットの多重分離

S-BFD Control packet demultiplexing follows the procedure specified in Section 7.1 of [RFC7880]. A received S-BFD Control packet MUST be demultiplexed with the destination UDP port field.

S-BFD制御パケットの多重分離（demultiplexing）は、[RFC7880]のセクション7.1で規定されている手順に従います。受信したS-BFD制御パケットは、宛先UDPポートフィールドによって多重分離しなければなりません（MUST）。

This procedure for an S-BFD packet is executed on both the initiator and the reflector. If the port is 7784 (i.e., an S-BFD packet for the SBFDReflector), then the packet MUST be looked up to locate a corresponding SBFDReflector session based on the value from the Your Discriminator field in the table describing S-BFD Discriminators. If the port is not 7784 but the packet is demultiplexed to be for an SBFDInitiator, then the packet MUST be looked up to locate a corresponding SBFDInitiator session based on the value from the Your Discriminator field in the table describing BFD Discriminators. In that case, the destination IP address of the packet SHOULD be validated to be for itself. If the packet demultiplexes to a classical BFD session, then the procedures from [RFC5880] apply.

S-BFDパケットに対するこの手順は、イニシエーターとリフレクターの両方で実行されます。ポートが7784である（つまり、SBFDReflector宛てのS-BFDパケットである）場合、S-BFDディスクリミネーターを記述するテーブルでYour Discriminatorフィールドの値に基づいてパケットを検索し、対応するSBFDReflectorセッションを見つけなければなりません（MUST）。ポートが7784ではないものの、パケットがSBFDInitiator宛てであると多重分離された場合は、BFDディスクリミネーターを記述するテーブルでYour Discriminatorフィールドの値に基づいてパケットを検索し、対応するSBFDInitiatorセッションを見つけなければなりません（MUST）。その場合、パケットの宛先IPアドレスが自分自身宛てであることを検証すべきです（SHOULD）。パケットが従来のBFDセッションに多重分離された場合は、[RFC5880]の手順が適用されます。

5. Initiator Procedures

5. イニシエーターの手順

S-BFD Control packets are transmitted with an IP header, UDP header, and BFD Control packet ([RFC5880]). When S-BFD Control packets are explicitly label switched (i.e., not IP routed and forwarded over a Label Switched Path (LSP), but explicitly sent on a specific LSP), the former is prepended with a label stack. Note that this document does not make a distinction between a single-hop S-BFD scenario and a multi-hop S-BFD scenario; both scenarios are supported.

S-BFD制御パケットは、IPヘッダー、UDPヘッダー、およびBFD制御パケット（[RFC5880]）とともに送信されます。S-BFD制御パケットが明示的にラベルスイッチされる（つまり、IPルーティングされてラベルスイッチパス（Label Switched Path、LSP）上で転送されるのではなく、特定のLSP上に明示的に送信される）場合は、前者の先頭にラベルスタックが付加されます。この文書は、シングルホップのS-BFDシナリオとマルチホップのS-BFDシナリオを区別しないことに注意してください。どちらのシナリオもサポートされます。

The necessary values in the BFD control headers are described in [RFC7880]. Section 5.1 describes necessary values in the MPLS header, IP header, and UDP header when an SBFDInitiator on the initiator is sending S-BFD Control packets.

BFD制御ヘッダーに必要な値は、[RFC7880]で説明されています。セクション5.1では、イニシエーター上のSBFDInitiatorがS-BFD制御パケットを送信する際の、MPLSヘッダー、IPヘッダー、UDPヘッダーに必要な値を説明します。

5.1. Details of S-BFD Control Packets Sent by SBFDInitiator

5.1. SBFDInitiatorが送信するS-BFD制御パケットの詳細

  • Specifications common to both IP-routed S-BFD Control packets and explicitly label-switched S-BFD Control packets:

    • The Source IP Address field of the IP header MUST be set to a local IP address that is expected to be routable by the target (i.e., not an IPv6 link-local address when the target is multiple hops away).
    • The UDP destination port MUST be set to a well-known UDP destination port assigned for S-BFD, i.e., 7784.
    • The UDP source port MUST NOT be set to 7784.

  • Specifications for IP-routed S-BFD Control packets:

    • The Destination IP Address field of the IP header MUST be set to an IP address of the target.
    • The TTL / Hop Limit field of the IP header SHOULD be set to 255.

  • Specifications for explicitly label-switched S-BFD Control packets:

    • S-BFD Control packets MUST have the label stack that is expected to reach the target.
    • The TTL field of the topmost label SHOULD be 255.
    • The destination IP address MUST be chosen from the 127/8 range for IPv4 and from the 0:0:0:0:0:ffff:7f00:0/104 range for IPv6, as per [RFC5884].
    • The TTL / Hop Limit field of the IP header MUST be set to 1.

  • IPルーティングされるS-BFD制御パケットと、明示的にラベルスイッチされるS-BFD制御パケットの両方に共通する仕様：

    • IPヘッダーの送信元IPアドレス（Source IP Address）フィールドは、ターゲットからルーティング可能であると期待されるローカルIPアドレス（つまり、ターゲットが複数ホップ離れている場合はIPv6リンクローカルアドレス以外のアドレス）に設定しなければなりません（MUST）。
    • UDP宛先ポートは、S-BFDに割り当てられたウェルノウンUDP宛先ポート、つまり7784に設定しなければなりません（MUST）。
    • UDP送信元ポートを7784に設定してはなりません（MUST NOT）。

  • IPルーティングされるS-BFD制御パケットの仕様：

    • IPヘッダーの宛先IPアドレス（Destination IP Address）フィールドは、ターゲットのIPアドレスに設定しなければなりません（MUST）。
    • IPヘッダーのTTL／ホップリミット（Hop Limit）フィールドは、255に設定すべきです（SHOULD）。

  • 明示的にラベルスイッチされるS-BFD制御パケットの仕様：

    • S-BFD制御パケットは、ターゲットに到達すると期待されるラベルスタックを持たなければなりません（MUST）。
    • 最上位のラベルのTTLフィールドは255であるべきです（SHOULD）。
    • [RFC5884]に従い、宛先IPアドレスは、IPv4では127/8の範囲から、IPv6では0:0:0:0:0:ffff:7f00:0/104の範囲から選択しなければなりません（MUST）。
    • IPヘッダーのTTL／ホップリミット（Hop Limit）フィールドは、1に設定しなければなりません（MUST）。

5.1.1. Target versus Remote Entity (S-BFD Discriminator)

5.1.1. ターゲットとリモートエンティティー（S-BFDディスクリミネーター）

Typically, an S-BFD Control packet will have the Your Discriminator field corresponding to an S-BFD Discriminator of the remote entity located on the target network node defined by the destination IP address or the label stack. It is, however, possible for an SBFDInitiator to carefully set the Your Discriminator and TTL fields to perform a continuity test in the direction towards a target, but destined to a transit network node and not to the target itself.

通常、S-BFD制御パケットのYour Discriminatorフィールドは、宛先IPアドレスまたはラベルスタックによって定まるターゲットのネットワークノード上に位置するリモートエンティティーのS-BFDディスクリミネーターに対応します。しかし、SBFDInitiatorがYour DiscriminatorフィールドとTTLフィールドを慎重に設定することで、ターゲットに向かう方向に導通テストを実行しつつ、ターゲット自体ではなく途中の中継ネットワークノードを宛先とすることも可能です。

Section 5.1 intentionally uses the word "target" instead of "remote entity" to accommodate this possible S-BFD usage through TTL expiry. This also requires that S-BFD Control packets not be dropped by the responder node due to TTL expiry. Thus, implementations on the responder MUST allow received S-BFD Control packets taking a TTL expiry exception path to reach the corresponding SBFDReflector session. This is an existing packet-processing exception practice for Operations, Administration, and Maintenance (OAM) packets, where the control plane further identifies the type of OAM by the protocol and port numbers.

セクション5.1では、TTL満了を利用したこのようなS-BFDの使い方に対応できるよう、意図的に「リモートエンティティー（remote entity）」ではなく「ターゲット（target）」という語を使っています。これはまた、TTL満了によってS-BFD制御パケットがレスポンダーノードで破棄されないことも要求します。したがって、レスポンダー上の実装は、TTL満了の例外パスを通る受信S-BFD制御パケットが、対応するSBFDReflectorセッションに到達できるようにしなければなりません（MUST）。これは、運用・管理・保守（Operations, Administration, and Maintenance、OAM）パケットに対する既存のパケット処理上の例外の慣行であり、そこではコントロールプレーンがプロトコルとポート番号によってOAMの種類をさらに識別します。

6. Responder Procedures

6. レスポンダーの手順

S-BFD Control packets are IP routed back to the initiator and will have an IP header, UDP header, and BFD control header. If an SBFDReflector receives an S-BFD Control packet with a UDP source port of 7784, the packet MUST be discarded. Necessary values in the BFD control header are described in [RFC7880]. Section 6.1 describes necessary values in the IP header and UDP header when an SBFDReflector on the responder is sending S-BFD Control packets.

S-BFD制御パケットは、IPルーティングによってイニシエーターに送り返され、IPヘッダー、UDPヘッダー、およびBFD制御ヘッダーを持ちます。SBFDReflectorがUDP送信元ポート7784のS-BFD制御パケットを受信した場合、そのパケットを破棄しなければなりません（MUST）。BFD制御ヘッダーに必要な値は、[RFC7880]で説明されています。セクション6.1では、レスポンダー上のSBFDReflectorがS-BFD制御パケットを送信する際の、IPヘッダーとUDPヘッダーに必要な値を説明します。

6.1. Details of S-BFD Control Packets Sent by SBFDReflector

6.1. SBFDReflectorが送信するS-BFD制御パケットの詳細

  • The Destination IP Address field of the IP header MUST be copied from the Source IP Address field of the received S-BFD Control packet.
  • The Source IP Address field of the IP header MUST be set to a local IP address that the initiator expects to be visible (i.e., not an IPv6 link-local address when the initiator is multiple hops away). The source IP address SHOULD be copied from the Destination IP Address field of the received S-BFD Control packet, except when it is from the 127/8 range for IPv4 or from the 0:0:0:0:0:ffff:7f00:0/104 range for IPv6.
  • The TTL / Hop Limit field of the IP header MUST be set to 255.
  • The UDP destination port MUST be copied from the received UDP source port.
  • The UDP source port MUST be copied from the received UDP destination port.
  • IPヘッダーの宛先IPアドレス（Destination IP Address）フィールドは、受信したS-BFD制御パケットの送信元IPアドレス（Source IP Address）フィールドからコピーしなければなりません（MUST）。
  • IPヘッダーの送信元IPアドレス（Source IP Address）フィールドは、イニシエーターから見えるとイニシエーターが期待するローカルIPアドレス（つまり、イニシエーターが複数ホップ離れている場合はIPv6リンクローカルアドレス以外のアドレス）に設定しなければなりません（MUST）。送信元IPアドレスは、受信したS-BFD制御パケットの宛先IPアドレス（Destination IP Address）フィールドからコピーすべきです（SHOULD）。ただし、それがIPv4の127/8の範囲、またはIPv6の0:0:0:0:0:ffff:7f00:0/104の範囲のアドレスである場合を除きます。
  • IPヘッダーのTTL／ホップリミット（Hop Limit）フィールドは、255に設定しなければなりません（MUST）。
  • UDP宛先ポートは、受信したUDP送信元ポートからコピーしなければなりません（MUST）。
  • UDP送信元ポートは、受信したUDP宛先ポートからコピーしなければなりません（MUST）。

7. Security Considerations

7. セキュリティーに関する考慮事項

Security considerations for S-BFD are discussed in [RFC7880]. Additionally, implementing the following measures will strengthen security aspects of the mechanism described by this document:

S-BFDのセキュリティーに関する考慮事項は、[RFC7880]で議論されています。加えて、次の対策を実装することで、この文書で説明するメカニズムのセキュリティー面が強化されます。

  • Implementations MUST provide filtering capability based on source IP addresses of received S-BFD Control packets; see [RFC2827].
  • Implementations MUST NOT act on received S-BFD Control packets containing source Martian IP addresses (i.e., addresses that, by application of the current forwarding tables, would not have their return traffic routed back to the sender).
  • Implementations MUST ensure that response S-BFD Control packets generated by the SBFDReflector and sent to the initiator have a reachable target (e.g., destination IP address).
  • 実装は、受信したS-BFD制御パケットの送信元IPアドレスに基づくフィルタリング機能を提供しなければなりません（MUST）。[RFC2827]を参照してください。
  • 実装は、送信元にマーシャン（Martian）IPアドレス（つまり、現在の転送テーブルを適用すると、その戻りトラフィックが送信者にルーティングされないアドレス）を含む受信S-BFD制御パケットに基づいて動作してはなりません（MUST NOT）。
  • 実装は、SBFDReflectorが生成してイニシエーターに送信する応答S-BFD制御パケットが、到達可能なターゲット（例：宛先IPアドレス）を持つことを保証しなければなりません（MUST）。
