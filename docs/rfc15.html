RFC 15

Network Subsystem for Time Sharing Hosts

RFC 15

タイムシェアリングホストのためのネットワークサブシステム

Introduction

はじめに

A set of network primitives has been defined (Network Working Group Note 11) for inclusion in the monitor systems of the respective HOSTS. These primitives are at the level of system calls: SPOP's or BRS's on the 940; UUO's on the PDP-10. Presumably these UUO's are accessible to all user programs when executing for users whose status bits allow network access.

各ホストのモニターシステムに組み込むためのネットワークプリミティブの集合が定義されています（Network Working Group Note 11）。これらのプリミティブはシステムコールのレベルのもので、940ではSPOPやBRS、PDP-10ではUUOにあたります。おそらく、これらのUUOは、ステータスビットでネットワークへのアクセスが許可されているユーザーのために実行されるすべてのユーザープログラムから利用できるでしょう。

In addition to user program access, a convenient means for direct network access from the terminal is desirable. A sub-system called "Telnet" is proposed which is a shell program around the network system primitives, allowing a teletype or similar terminal at a remote host to function as a teletype at the serving host.

ユーザープログラムからのアクセスに加えて、端末から直接ネットワークにアクセスする便利な手段が望まれます。そこで、「Telnet」と呼ぶサブシステムを提案します。これはネットワークシステムプリミティブを包むシェルプログラムで、リモートホストにあるテレタイプや同様の端末を、サービスを提供するホストのテレタイプとして機能させます。

System Primitives

システムプリミティブ

G. Deloche of U.C.L.A. has documented a proposed set of basic network primitives for inclusion in the operating systems of the respective HOSTs (NWG Note: 11). The primitives are:

U.C.L.A.のG. Delocheは、各ホストのオペレーティングシステムに組み込むための基本的なネットワークプリミティブの集合の提案を文書にまとめています（NWG Note: 11）。そのプリミティブは次のとおりです。

  • Open primary connection
  • Open auxiliary connection
  • Transmit over connection
  • Close connection.
  • 一次接続（primary connection）を開く
  • 補助接続（auxiliary connection）を開く
  • 接続を介して送信する
  • 接続を閉じる

The details and terminology are defined by Deloche and others in previous memos. The primitives are system calls, available to programmers, and are most likely a part of the resident monitor, rather than the swappable executive.

詳細と用語は、Delocheらが以前のメモで定義しています。これらのプリミティブはプログラマーが利用できるシステムコールであり、スワップ可能なエグゼクティブではなく、常駐モニターの一部となる可能性が最も高いでしょう。

Basic Terminal Access

基本的な端末アクセス

In addition to user programming access, it is desirable to have a subsystem program at each HOST which makes the network immediately accessible from the teletype without special programming. Subsystems are commonly used system components such as text editors, compilers and interpreters. The first network-related subsystem should allow users at HOST A to connect to HOST B and appear as a regular terminal user to HOST B. It is expected that more sophisticated subsystems will be developed in time, but this basic one will render the early net immediately useful.

ユーザーのプログラミングによるアクセスに加えて、特別なプログラミングなしにテレタイプからすぐにネットワークを利用できるようにするサブシステムプログラムが各ホストにあることが望まれます。サブシステムとは、テキストエディター、コンパイラー、インタープリターなどの、よく使われるシステムコンポーネントのことです。ネットワークに関連する最初のサブシステムは、ホストAのユーザーがホストBに接続し、ホストBからは通常の端末ユーザーとして見えるようにするものであるべきです。いずれはもっと洗練されたサブシステムが開発されるでしょうが、この基本的なサブシステムによって、初期のネットワークがすぐに役立つものになるでしょう。

The Telnet Subsystem

Telnetサブシステム

The Telnet subsystem coding should fit easily into one core page, for it does very little. It effectively establishes a shunt in the user HOST between the remote user and the serving HOST. Telnet commands are:

Telnetサブシステムはほとんど何もしないので、そのコードは1コアページに楽に収まるはずです。Telnetサブシステムは、実質的に、ユーザーのホストの中で、リモートユーザーとサービスを提供するホストとの間に分路（shunt）を確立します。Telnetのコマンドは次のとおりです。

ESCAPE CHAR IS ___________<CR>
Declares a character which Telnet will watch for. Subsequent strings typed between this character and a carriage return are not shunted through to the serving host, but sent instead to the Telnet program in the user's local HOST.
ESCAPE CHAR IS ___________<CR>
Telnetが監視する文字を宣言します。以降、この文字と復帰（キャリッジリターン）の間に入力された文字列は、サービスを提供するホストへは素通しされず、代わりにユーザーのローカルホストにあるTelnetプログラムに送られます。

This escape character is not the same as the user's host rubout character.

このエスケープ文字は、ユーザーのホストのrubout文字とは別のものです。

CONNECT TO __________________<CR>
The official site name of the desired serving HOST is typed (i.e.: SRI, UTAH, UCLA, UCSB). Telnet attempts to establish a connection. If the attempt is successful, the following characters are shunted through the user's local machine. The connection places the user in the pre-logged in state at the serving HOST.
LOGOUT<CR>
Telnet issues the logout command sequence to the serving HOST. If the user simply rubs out and kills his PDP-10 job, the PDP-10 will indicate to the 940 that the connection is closed. The 940 system primitives do whatever they do when a normal dataphone connection is suddenly broken.
COPY FILE
A file copying command is available in TELNET to move data along on auxiliary connections from the user's HOST file system to the serving HOST.
CONNECT TO __________________<CR>
接続したいサービスを提供するホストの公式のサイト名（すなわち、SRI、UTAH、UCLA、UCSB）を入力します。Telnetは接続の確立を試みます。その試みが成功すると、以降の文字はユーザーのローカルマシンを素通しされます。接続によって、ユーザーはサービスを提供するホストでログイン前の状態になります。
LOGOUT<CR>
Telnetは、サービスを提供するホストにログアウトのコマンドシーケンスを発行します。ユーザーが単にruboutしてPDP-10のジョブを終了させた場合、PDP-10は940に接続が閉じられたことを伝えます。940のシステムプリミティブは、通常のデータフォン接続が突然切断されたときと同じ処理を行います。
COPY FILE
TELNETには、ユーザーのホストのファイルシステムから、サービスを提供するホストへ、補助接続を介してデータを移動させるファイルコピーコマンドがあります。

On the 940 this is:

940では、次のようになります。

COPY <file name> TO NETWRK.
-                   -     -

COPY <file name> TO NETWRK.
-                   -     -

On the PDP-10:

PDP-10では、次のようになります。

NETWRK <- DSK: <file name>
--------------------------

NETWRK <- DSK: <file name>
--------------------------

These TELNET commands are accepted when the TELNET subsystem is first entered or following the declared escape character.

これらのTELNETコマンドは、TELNETサブシステムに最初に入ったとき、または宣言したエスケープ文字の後に受け付けられます。

CONCLUSION

結論

Given the basic system primitives, the TELNET subsystem at the user host and a manual for the serving host, the network can be profitably employed by a remote user. TELNET subsystem constitutes a "level 0" network program which will quickly be surpassed. It is, however, simple enough to be working fairly soon.

基本的なシステムプリミティブ、ユーザーのホストのTELNETサブシステム、そしてサービスを提供するホストのマニュアルがあれば、リモートユーザーはネットワークを有益に利用できます。TELNETサブシステムは「レベル0」のネットワークプログラムであり、すぐに追い越されるでしょう。しかし、これは十分に単純なので、かなり早く動くようになるでしょう。
