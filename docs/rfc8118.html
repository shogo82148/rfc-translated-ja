RFC 8118

The application/pdf Media Type

RFC 8118

application/pdfメディアタイプ

Abstract

概要

The Portable Document Format (PDF) is an ISO standard (ISO 32000-1:2008) defining a final-form document representation language in use for document exchange, including on the Internet, since 1993. This document provides an overview of the PDF format and updates the media type registration of "application/pdf". It obsoletes RFC 3778.

Portable Document Format（PDF）は、ISO規格（ISO 32000-1:2008）であり、1993年以来、インターネット上を含めて文書の交換に使われている最終形式の文書表現言語を定義しています。この文書は、PDF形式の概要を示し、「application/pdf」のメディアタイプ登録を更新します。この文書はRFC 3778を廃止します。

1. Introduction

1. はじめに

This document is intended to provide updated information on the registration of the MIME Media Type "application/pdf" for documents in the PDF (Portable Document Format) syntax. It obsoletes [RFC3778].

この文書は、PDF（Portable Document Format）構文の文書のためのMIMEメディアタイプ「application/pdf」の登録について、最新の情報を提供することを目的としています。この文書は[RFC3778]を廃止します。

PDF was originally envisioned as a way to reliably communicate and view printed information electronically across a wide variety of machine configurations, operating systems, and communication networks.

PDFはもともと、多種多様なマシン構成、オペレーティングシステム、通信ネットワークにまたがって、印刷された情報を電子的に確実に伝達し、閲覧する方法として構想されました。

PDF is used to represent "final form" formatted documents. PDF pages may include text, images, graphics, and multimedia content such as video and audio. PDF is also capable of containing auxiliary structures, including annotations, bookmarks, file attachments, hyperlinks, logical structures, and metadata. These features are useful for navigation and building collections of related documents, as well as for reviewing and commenting on documents. A rich JavaScript model has been defined for interacting with PDF documents.

PDFは、「最終形式（final form）」の体裁が整った文書を表現するために使われます。PDFのページには、テキスト、画像、グラフィックス、そしてビデオやオーディオなどのマルチメディアコンテンツを含められます。PDFは、注釈、ブックマーク、添付ファイル、ハイパーリンク、論理構造、メタデータなどの補助的な構造を含むこともできます。これらの機能は、ナビゲーションや関連文書の集まりの構築に役立つほか、文書のレビューやコメント付けにも役立ちます。PDF文書を操作するための豊富なJavaScriptモデルが定義されています。

The imaging model for PDF was originally based on the PostScript [PS] page description language, used to render complex text, images, and graphics in a device-independent and resolution-independent manner.

PDFのイメージングモデルは、もともとPostScript[PS]ページ記述言語に基づいていました。PostScriptは、複雑なテキスト、画像、グラフィックスを、デバイスにも解像度にも依存しない方法で描画するために使われます。

PDF supports encryption and digital signatures. The encryption capability is combined with access control information to facilitate management of the functionality available to the recipient. PDF supports the inclusion of document and object-level metadata through the eXtensible Metadata Platform [XMP].

PDFは暗号化とデジタル署名をサポートしています。暗号化の機能はアクセス制御情報と組み合わされ、受信者が利用できる機能の管理を容易にします。PDFは、eXtensible Metadata Platform[XMP]によって、文書レベルとオブジェクトレベルのメタデータを含めることをサポートしています。

2. History

2. 歴史

PDF is used widely in the Internet community. The first version of PDF, 1.0, was published in 1993 by Adobe Systems Incorporated. Since then, PDF has grown to be a widely used format for capturing and exchanging formatted documents electronically across the Web, via email and virtually every other document-exchange mechanism. In 2008, PDF 1.7 was adopted as an ISO standard (ISO 32000-1:2008 [ISOPDF]) using the ISO "Fast-Track" process. That specification is technically identical to Adobe Portable Document Format version 1.7 [AdobePDF].

PDFはインターネットコミュニティーで広く使われています。PDFの最初のバージョンである1.0は、1993年にAdobe Systems Incorporatedによって公開されました。それ以来PDFは、Web上で、電子メールで、そして事実上ほかのあらゆる文書交換の仕組みで、体裁の整った文書を電子的に取り込み、交換するために広く使われる形式に成長しました。2008年には、PDF 1.7がISOの「ファストトラック（Fast-Track）」プロセスを用いてISO規格（ISO 32000-1:2008[ISOPDF]）として採択されました。その仕様は、Adobe Portable Document Formatバージョン1.7[AdobePDF]と技術的に同一です。

The ISO TC-171 committee developed a "refresh" of PDF, known as ISO 32000-2; the version is PDF 2.0 [ISOPDF2].

ISO TC-171委員会は、ISO 32000-2として知られるPDFの「刷新版」を策定しました。そのバージョンはPDF 2.0[ISOPDF2]です。

In addition to ISO 32000-1:2008 and ISO 32000-2, several subset standards have been defined to address specific use cases and standardized by the ISO. These standards include PDF for Archival (PDF/A) [ISOPDFA], PDF for Engineering (PDF/E) [ISOPDFE], PDF for Universal Accessibility (PDF/UA) [ISOPDFUA], PDF for Variable Data and Transactional Printing (PDF/VT) [ISOPDFVT], and PDF for Prepress Digital Data Exchange (PDF/X) [ISOPDFX]. The subset standards are fully compliant PDF files capable of being displayed in a general PDF viewer.

ISO 32000-1:2008とISO 32000-2に加えて、特定のユースケースに対処するためのいくつかのサブセット規格が定義され、ISOによって標準化されています。これらの規格には、アーカイブ用のPDF（PDF/A）[ISOPDFA]、エンジニアリング用のPDF（PDF/E）[ISOPDFE]、ユニバーサルアクセシビリティーのためのPDF（PDF/UA）[ISOPDFUA]、可変データおよびトランザクション印刷のためのPDF（PDF/VT）[ISOPDFVT]、プリプレスのデジタルデータ交換のためのPDF（PDF/X）[ISOPDFX]があります。サブセット規格のファイルは、完全に準拠したPDFファイルであり、一般的なPDFビューアーで表示できます。

3. Fragment Identifiers

3. フラグメント識別子

Fragment identifiers appear at the end of a URI and provide a way to reference an anchor to subordinate content within the target of the URI, or additional parameters to the process of opening the identified content. The syntax and semantics of fragment identifiers are referenced in the media type definition.

フラグメント識別子はURIの末尾に現れ、URIのターゲット内の下位のコンテンツへのアンカーを参照する方法や、識別されたコンテンツを開く処理への追加のパラメーターを指定する方法を提供します。フラグメント識別子の構文とセマンティクスは、メディアタイプの定義の中で参照されます。

The specification of fragment identifiers for PDF appeared originally in [RFC3778] and is now included in ISO 32000-2 [ISOPDF2]. This section is a summary of that material. Any disagreements between [ISOPDF2] and this document should be resolved in favor of the ISO 32000-2 definition.

PDFのフラグメント識別子の仕様は、もともと[RFC3778]に記載されていましたが、現在はISO 32000-2[ISOPDF2]に含まれています。このセクションは、その内容の要約です。[ISOPDF2]とこの文書との間に食い違いがある場合は、ISO 32000-2の定義を優先して解決すべきです。

A fragment identifier for PDF has one or more parameters, separated by the ampersand (&) or pound (#) character. Each parameter consists of the parameter name, "=" (equal), and the parameter value; lists of values are comma-separated, and parameter value strings may be URI-encoded [RFC3986]. Parameters are processed left to right.

PDFのフラグメント識別子は1つ以上のパラメーターを持ち、パラメーターはアンパサンド（&）またはシャープ（#）文字で区切られます。各パラメーターは、パラメーター名、「=」（等号）、パラメーター値で構成されます。値のリストはカンマで区切られ、パラメーター値の文字列はURIエンコード[RFC3986]してもかまいません。パラメーターは左から右へ処理されます。

Coordinate values (such as <left>, <right>, and <width>) are expressed in the default user space coordinate system of the document: 1/72 of an inch measured down and to the right from the upper left corner of the (current) page ([ISOPDF2] 8.3.2.3 "User Space").

座標値（<left>、<right>、<width>など）は、文書のデフォルトのユーザー空間座標系で表現されます。これは、（現在の）ページの左上隅から下方向と右方向に測った1/72インチを単位とします（[ISOPDF2]の8.3.2.3「User Space」）。

The following parameters identify subordinate content of a PDF file but also may be used to set the document view to make the (start of) the identified content visible:

次のパラメーターは、PDFファイルの下位のコンテンツを識別しますが、識別されたコンテンツ（の先頭）が見えるように文書の表示を設定するためにも使えます。

page=<pageNum>
Identifies a specified (physical) page; the first page in the document has a pageNum value of 1.
nameddest=<name>
Identifies a named destination ([ISOPDF2] 12.3.2.4 "Named destinations").
structelem=<structID>
A byte string with URI encoding; identifies the structure element with the ID key within a StructElem dictionary of the document.
comment=<commentID>
The value of an annotation name, which is defined by the NM key in the corresponding annotation dictionary of the selected page ([ISOPDF2] 12.5.2 "Annotation dictionaries").
ef=<name>

Identifies the embedded file where the parameter string <name> matches a file specification dictionary in the EmbeddedFiles name tree. If the "ef" parameter is not at the end of the fragment identifier, then the rest of the fragment identifier (after the ampersand or hash delimiter) is applied to the embedded file according to its own media type. This allows identification of content within the embedded file (which itself might be a PDF file).

NOTE: When attempting to open a PDF file that is not from a trusted source, the processor may choose to prompt the user or even prevent the file from being opened.

page=<pageNum>
指定された（物理的な）ページを識別します。文書の最初のページのpageNumの値は1です。
nameddest=<name>
名前付き移動先（named destination）を識別します（[ISOPDF2]の12.3.2.4「Named destinations」）。
structelem=<structID>
URIエンコードされたバイト文字列です。文書のStructElem辞書内のIDキーによって構造要素を識別します。
comment=<commentID>
注釈名の値です。注釈名は、選択されたページの対応する注釈辞書のNMキーによって定義されます（[ISOPDF2]の12.5.2「Annotation dictionaries」）。
ef=<name>

EmbeddedFiles名前ツリー内のファイル指定辞書にパラメーター文字列<name>が一致する埋め込みファイルを識別します。「ef」パラメーターがフラグメント識別子の末尾にない場合、フラグメント識別子の残りの部分（アンパサンドまたはハッシュの区切り文字の後）は、埋め込みファイル自身のメディアタイプに従ってそのファイルに適用されます。これにより、埋め込みファイル（それ自体がPDFファイルであることもあります）内のコンテンツを識別できます。

注記：信頼できる提供元からのものではないPDFファイルを開こうとするとき、プロセッサーは、ユーザーに確認を求めることや、ファイルが開かれるのを阻止することさえ選択できます。

These parameters operate on the view of the PDF document when it is opened:

次のパラメーターは、PDF文書が開かれたときの表示に作用します。

zoom=<scale>,<left>,<top>
<scale> is the percentage to which the document should be zoomed, where a value of 100 corresponds to a zoom of 100%. <left> and <top> are optional, but both must be specified if either is included.
view=<keyword>,<position>
The arguments correspond to those found in [ISOPDF2] 12.3.2.2 "Explicit destinations". <keyword> is one of the keywords defined in [ISOPDF2] "Table 149: Destination syntax" with appropriate position values.
viewrect=<left>,<top>,<width>,<height>
Set the view rectangle.
highlight=<left>,<right>,<top>,<bottom>
Highlight the specified rectangle.
search=<wordList>
Open the document and search for one or more words, selecting the first matching word in the document. <wordList> is a string enclosed in quotation marks, where individual words are separated by the space character (or %20).
fdf=<URI>
This parameter imports data into PDF form fields. The URI is either a relative or absolute URI to a Forms Data Format (FDF) or XML FDF (XFDF) file. The fdf parameter should be specified as the last parameter to a given URI.
zoom=<scale>,<left>,<top>
<scale>は文書を拡大縮小する割合（パーセント）で、値100は100%の拡大率に相当します。<left>と<top>は省略可能ですが、どちらか一方を含める場合は両方を指定しなければなりません。
view=<keyword>,<position>
引数は、[ISOPDF2]の12.3.2.2「Explicit destinations」にあるものに対応します。<keyword>は、[ISOPDF2]の「Table 149: Destination syntax」で定義されているキーワードのいずれかで、適切な位置の値を伴います。
viewrect=<left>,<top>,<width>,<height>
表示矩形を設定します。
highlight=<left>,<right>,<top>,<bottom>
指定された矩形を強調表示します。
search=<wordList>
文書を開いて1つ以上の単語を検索し、文書内で最初に一致した単語を選択します。<wordList>は引用符で囲まれた文字列で、個々の単語はスペース文字（または%20）で区切られます。
fdf=<URI>
このパラメーターは、PDFのフォームフィールドにデータを取り込みます。URIは、Forms Data Format（FDF）ファイルまたはXML FDF（XFDF）ファイルへの相対URIまたは絶対URIです。fdfパラメーターは、URIの最後のパラメーターとして指定すべきです。

4. Subset Standards

4. サブセット規格

Several subsets of PDF have been published as distinct ISO standards:

PDFのいくつかのサブセットが、個別のISO規格として公開されています。

  • PDF/X [ISOPDFX], initially released in 2001 as PDF/X-1a, specifies how to use PDF for graphics exchange, with the aim to facilitate correct and predictable printing by print service providers. The standard has gone through multiple revisions over the years and has several published parts, the most recently released being part 8, specifying different levels of conformance: PDF/X-1a:2001, PDF/X-3:2002, PDF/X-1a:2003, PDF/X-3:2003, PDF/X-4, PDF/X-4p, PDF/X-5g, PDF/X-5pg, and PDF/X-5n.
  • PDF/A [ISOPDFA], initially released in 2005, specifies how to use PDF for long-term preservation (archiving) of electronic documents. It prohibits PDF features that are not well suited to long-term archiving of documents, including JavaScript or executable file launches. Its requirements for PDF/A viewers include color management guidelines and support for embedded fonts. There are three parts of this standard and a total of eight conformance levels: PDF/A-1a, PDF/A-1b, PDF/A-2a, PDF/A-2b, PDF/A-2u, PDF/A-3a, PDF/A-3b, and PDF/A-3u.
  • PDF/E, initially released in 2008 as PDF/E-1 [ISOPDFE], specifies how to use PDF in engineering workflows, such as manufacturing, construction, and geospatial analysis. Future revisions of PDF/E are supposed to include support for 3D PDF workflows.
  • PDF/VT, initially released in 2010, specifies how to use PDF in variable and transactional printing. It is based on PDF/X and places additional restrictions on PDF content elements and supporting metadata. It specifies three conformance levels: PDF/VT-1, PDF/VT-2, and PDF/VT-2s [ISOPDFVT].
  • PDF/UA [ISOPDFUA], initially released in 2012 as PDF/UA-1, specifies how to create accessible electronic documents. It requires the use of ISO 32000's Tagged PDF feature and adds many requirements regarding semantic correctness in applying logical structures to content in PDF documents.
  • PDF/X[ISOPDFX]は、2001年にPDF/X-1aとして最初にリリースされ、印刷サービス事業者による正確で予測可能な印刷を容易にすることを目的として、グラフィックス交換にPDFを使う方法を規定しています。この規格は長年にわたって何度も改訂され、公開されたパートがいくつかあります。最も新しくリリースされたのはパート8で、さまざまな適合レベル（PDF/X-1a:2001、PDF/X-3:2002、PDF/X-1a:2003、PDF/X-3:2003、PDF/X-4、PDF/X-4p、PDF/X-5g、PDF/X-5pg、PDF/X-5n）を規定しています。
  • PDF/A[ISOPDFA]は、2005年に最初にリリースされ、電子文書の長期保存（アーカイブ）にPDFを使う方法を規定しています。この規格は、JavaScriptや実行可能ファイルの起動など、文書の長期アーカイブに適さないPDFの機能を禁止しています。PDF/Aビューアーに対する要件には、カラーマネジメントのガイドラインと埋め込みフォントのサポートが含まれます。この規格には3つのパートがあり、合計8つの適合レベル（PDF/A-1a、PDF/A-1b、PDF/A-2a、PDF/A-2b、PDF/A-2u、PDF/A-3a、PDF/A-3b、PDF/A-3u）があります。
  • PDF/Eは、2008年にPDF/E-1[ISOPDFE]として最初にリリースされ、製造、建設、地理空間分析などのエンジニアリングのワークフローでPDFを使う方法を規定しています。PDF/Eの今後の改訂では、3D PDFのワークフローのサポートが含まれる予定です。
  • PDF/VTは、2010年に最初にリリースされ、可変印刷およびトランザクション印刷でPDFを使う方法を規定しています。この規格はPDF/Xに基づいており、PDFのコンテンツ要素とそれを支えるメタデータに追加の制約を課しています。この規格は3つの適合レベル（PDF/VT-1、PDF/VT-2、PDF/VT-2s）を規定しています[ISOPDFVT]。
  • PDF/UA[ISOPDFUA]は、2012年にPDF/UA-1として最初にリリースされ、アクセシブルな電子文書を作成する方法を規定しています。この規格は、ISO 32000のタグ付きPDF（Tagged PDF）機能の使用を要求し、PDF文書のコンテンツに論理構造を適用する際の意味的な正しさに関する多くの要件を追加しています。

All of these subset standards use the "application/pdf" media type. The subset standards are generally not exclusive, so it is possible to construct a PDF file that conforms to, for example, both PDF/A-2b and PDF/X-4 subset standards.

これらのサブセット規格はすべて「application/pdf」メディアタイプを使います。サブセット規格は一般に排他的ではないため、たとえばPDF/A-2bとPDF/X-4の両方のサブセット規格に準拠するPDFファイルを作成することも可能です。

PDF documents claiming conformance to one or more of the subset standards use XMP metadata to identify levels of conformance. PDF processors should examine document metadata streams for such subset standards identifiers and, if appropriate, label documents as such when presenting them to the user.

1つ以上のサブセット規格への適合を主張するPDF文書は、XMPメタデータを使って適合レベルを識別します。PDFプロセッサーは、文書のメタデータストリームにそのようなサブセット規格の識別子がないか調べ、適切であれば、ユーザーに文書を提示する際にその旨のラベルを付けるべきです。

5. PDF Versions

5. PDFのバージョン

The PDF format has gone through several revisions, primarily for the addition of features. PDF features have generally been added in a way that older viewers "fail gracefully", because they can just ignore features they do not recognize. Even so, the older the PDF version produced, the more legacy viewers will support that version, but the fewer features will be enabled. The "application/pdf" media type is used for all versions. See [ISOPDF2] Annex I, "PDF Versions and Compatibility".

PDF形式は、主に機能の追加のために何度か改訂されてきました。PDFの機能は一般に、古いビューアーが「穏やかに失敗する（fail gracefully）」ように追加されてきました。古いビューアーは、認識できない機能を単に無視できるからです。それでも、生成するPDFのバージョンが古いほど、そのバージョンをサポートするレガシーなビューアーは多くなりますが、有効になる機能は少なくなります。「application/pdf」メディアタイプは、すべてのバージョンに使われます。[ISOPDF2]の附属書I「PDF Versions and Compatibility」を参照してください。

6. PDF Implementations

6. PDFの実装

PDF files are experienced through a reader or viewer of PDF files. For most of the common platforms in use (iOS, OS X, Windows, Android, ChromeOS, Kindle) and for most browsers (Edge, Safari, Chrome, Firefox), PDF viewing is built in. In addition, there are many PDF viewers available for download and installation. The PDF specification was published and freely available since the format was introduced in 1993, so hundreds of companies and organizations make tools for PDF creation, viewing, and manipulation.

PDFファイルは、PDFファイルのリーダーやビューアーを通じて利用されます。使われている一般的なプラットフォームのほとんど（iOS、OS X、Windows、Android、ChromeOS、Kindle）と、ほとんどのブラウザー（Edge、Safari、Chrome、Firefox）には、PDFの表示機能が組み込まれています。さらに、ダウンロードしてインストールできるPDFビューアーも数多くあります。PDFの仕様は、この形式が1993年に導入されて以来、公開され自由に入手できるため、何百もの企業や組織がPDFの作成、表示、操作のためのツールを作っています。

7. Security Considerations

7. セキュリティーに関する考慮事項

PDF is certainly a complex media type as per Section 4.6 of [RFC6838], which sets requirements for security analysis of media type registrations. [RFC3778] (which this document obsoletes) contained a detailed analysis of some of the security issues for PDF implementations known at the time. While the analysis isn't necessarily wrong, the threat analysis is much too limited, and the mitigations are somewhat out of date. There is now extensive literature on security threats involving PDF implementations and how to avoid them, consistent with broad implementation over decades. We are not registering a new media type but rather are making a primarily administrative update. With those caveats:

メディアタイプ登録のセキュリティー分析に対する要件を定めている[RFC6838]のセクション4.6に照らして、PDFは間違いなく複雑なメディアタイプです。[RFC3778]（この文書によって廃止されます）には、当時知られていたPDF実装のセキュリティー問題の一部についての詳細な分析が含まれていました。その分析は必ずしも誤りではありませんが、脅威の分析はあまりにも限定的であり、緩和策もいくぶん時代遅れになっています。現在では、数十年にわたって広く実装されてきたことを反映して、PDF実装に関わるセキュリティー上の脅威とその回避方法についての多くの文献があります。私たちは新しいメディアタイプを登録するのではなく、主に事務的な更新を行っています。これらの但し書きを踏まえたうえで、次のことを述べます。

The PDF file format allows several constructs that may compromise security if handled inadequately by PDF processors. For example:

PDFファイル形式では、PDFプロセッサーによる取り扱いが不十分な場合にセキュリティーを損なうおそれのある構成要素がいくつか許されています。たとえば、次のとおりです。

  • PDF may contain scripts to customize the displaying and processing of PDF files. These scripts are expressed in a version of JavaScript and are intended for execution by the PDF processor.
  • A PDF file may refer to other PDF files for portions of content. PDF processors may be expected to find and use these external files when processing the document.
  • PDF may act as a container for various files embedded in it (for example, as attached files). PDF processors may offer functionality to open and display such files or store them on the system, such as with the "ef" open action. The PDF specification places no restrictions on types of files that may be embedded, so PDF processors should be extremely careful to prevent unwanted execution of attached executables or decompression of attached archives that may store dangerous files in the host file system.
  • PDF files may contain links to content on the Internet. PDF processors may offer functionality to show such content upon following the link.
  • The fragment identifier syntax (Section 3) contains directives for opening ("ef") or including ("fdf") additional material.
  • PDFには、PDFファイルの表示と処理をカスタマイズするためのスクリプトを含められます。これらのスクリプトはJavaScriptの一種で記述され、PDFプロセッサーによって実行されることを意図しています。
  • PDFファイルは、コンテンツの一部として他のPDFファイルを参照できます。PDFプロセッサーは、文書を処理する際にこれらの外部ファイルを見つけて使うことを期待される場合があります。
  • PDFは、その中に埋め込まれたさまざまなファイルのコンテナー（たとえば添付ファイルとして）として機能できます。PDFプロセッサーは、「ef」オープンアクションなどによって、そのようなファイルを開いて表示したり、システムに保存したりする機能を提供することがあります。PDFの仕様では、埋め込めるファイルの種類に制限を設けていないため、PDFプロセッサーは、添付された実行可能ファイルの意図しない実行や、ホストのファイルシステムに危険なファイルを格納するおそれのある添付アーカイブの展開を防ぐよう、細心の注意を払うべきです。
  • PDFファイルには、インターネット上のコンテンツへのリンクを含められます。PDFプロセッサーは、リンクをたどってそのようなコンテンツを表示する機能を提供することがあります。
  • フラグメント識別子の構文（セクション3）には、追加の素材を開く（「ef」）ディレクティブや取り込む（「fdf」）ディレクティブが含まれています。

PDF interpreters executing any scripts or programs related to these constructs must be extremely careful to ensure that untrusted software is executed in a protected environment.

これらの構成要素に関連するスクリプトやプログラムを実行するPDFインタープリターは、信頼できないソフトウェアが保護された環境で実行されるよう、細心の注意を払わなければなりません。

In addition, the PDF processor itself, as well as its plugins, scripts, etc., may be a source of insecurity, by either obvious or subtle means.

さらに、PDFプロセッサー自体も、そのプラグインやスクリプトなども、明白な方法や巧妙な方法によって、セキュリティー上の弱点の原因になる可能性があります。

Appendix A. Changes since RFC 3778

付録A. RFC 3778からの変更点

This specification replaces RFC 3778, which previously defined the "application/pdf" Media Type. Differences include the following:

この仕様は、以前に「application/pdf」メディアタイプを定義していたRFC 3778を置き換えます。相違点には次のものがあります。

  • To reflect the transition from a proprietary specification by Adobe to an open ISO standard, the Change Controller has changed from Adobe to ISO, and references have been updated.
  • The overview of PDF capabilities, the history of PDF, and the descriptions of PDF subsets were updated to reflect more recent relevant history.
  • The section on fragment identifiers was updated to closely reflect the material that has been added to ISO-32000-2.
  • The status of popular PDF implementations was updated.
  • The Security Considerations section was updated to match the current understanding of PDF vulnerabilities.
  • The registration template was updated to match RFC 6838.
  • Adobeの独自仕様からオープンなISO規格への移行を反映するため、変更管理者をAdobeからISOに変更し、参考文献を更新しました。
  • PDFの機能の概要、PDFの歴史、PDFのサブセットの説明を、より最近の関連する経緯を反映するように更新しました。
  • フラグメント識別子に関するセクションを、ISO-32000-2に追加された内容を忠実に反映するように更新しました。
  • よく使われているPDF実装の状況を更新しました。
  • セキュリティーに関する考慮事項のセクションを、PDFの脆弱性に関する現在の理解に合わせて更新しました。
  • 登録テンプレートをRFC 6838に合わせて更新しました。
