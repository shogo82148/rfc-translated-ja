RFC 71

Reallocation in Case of Input Error

RFC 71

入力エラー時の再割り当て

Abstract

概要

In case of reading a message from the IMP, it may be impossible for the receiving NCP to determine the length of the message if an input error occurs. The following protocol will be used at the CCN-Host at UCLA to resynchronize flow control.

IMPからのメッセージを読み込む際に入力エラーが発生すると、受信側のNCPはメッセージの長さを判断できない場合があります。UCLAのCCN-Hostでは、フロー制御を再同期するために次のプロトコルを使用します。

If an input error is detected and the NCP can find the intended link number, it will send a GVB with frac = O to the sending Host and disregard further incoming messages on that link. When the RET has been received, a new ALL will be sent.

入力エラーを検出し、NCPが本来のリンク番号を特定できた場合、NCPは送信側のホストにfrac = OのGVBを送信し、そのリンクでそれ以降に届くメッセージを破棄します。RETを受信したら、新しいALLを送信します。

If the sending Host is not waiting for a RFNM when the GVB arrives, it will send the RET immediately. If it is waiting for a RFNM corresponding to the message with the error or a RFNM corresponding to a following message, it will send the RET after the RFNM has been received.

GVBが届いたときに送信側のホストがRFNMを待っていなければ、送信側のホストはただちにRETを送信します。エラーのあったメッセージに対応するRFNM、またはそれに続くメッセージに対応するRFNMを待っている場合は、そのRFNMを受信した後にRETを送信します。

In this way, the receiving Host will know that the link is clear before it issues a new ALL.

こうすることで、受信側のホストは、新しいALLを発行する前にリンクが空いていることを知ることができます。
