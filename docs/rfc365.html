RFC 365

Letter to All TIP Users

RFC 365

すべてのTIPユーザーへの手紙

Abstract

概要

Dear TIP Users,

TIPユーザーの皆さま

You will shortly be sent a revised version of the "TIP User's Guide." Besides now having a loose leaf format, mainly descriptions of new commands have been added. Appendix B will be an alphabetical list of all TIP commands. The new commands are:

まもなく「TIP User's Guide」の改訂版をお送りします。ルーズリーフ形式になったことに加えて、主に新しいコマンドの説明が追加されています。付録Bは、すべてのTIPコマンドのアルファベット順の一覧になる予定です。新しいコマンドは次のとおりです。

     @BINARY INPUT START
     @BINARY INPUT END
     @BINARY OUTPUT START
     @BINARY OUTPUT END
     @CLEAR DEVICE WILD
     @CLEAR INSERT LINEFEED
     @INSERT LINEFEED
     @SEND COMMAND
     @RECEIVE FROM WILD
     @SEND TO WILD
     @SET DEVICE WILD
     @MAG ABORT
     @MAG BACKSPACE FILE
     @MAG BACKSPACE RECORD
     @MAG READ FILE
     @MAG READ RECORD
     @MAG SETUP COPY
     @MAG SPACE FILE
     @MAG SPACE RECORD
     @MAG UNLOAD
     @MAG WRITE EOF
     @MAG WRITE TAPE

     @BINARY INPUT START
     @BINARY INPUT END
     @BINARY OUTPUT START
     @BINARY OUTPUT END
     @CLEAR DEVICE WILD
     @CLEAR INSERT LINEFEED
     @INSERT LINEFEED
     @SEND COMMAND
     @RECEIVE FROM WILD
     @SEND TO WILD
     @SET DEVICE WILD
     @MAG ABORT
     @MAG BACKSPACE FILE
     @MAG BACKSPACE RECORD
     @MAG READ FILE
     @MAG READ RECORD
     @MAG SETUP COPY
     @MAG SPACE FILE
     @MAG SPACE RECORD
     @MAG UNLOAD
     @MAG WRITE EOF
     @MAG WRITE TAPE

The MAG commands are, of course, not relevant to users of TIPs without the magnetic tape option.

もちろん、MAGコマンドは、磁気テープオプションのないTIPのユーザーには関係ありません。

A TIP system including the above commands has been in operation since late June. We think this system is a substantial improvement over previous versions.

上記のコマンドを含むTIPシステムは、6月下旬から稼働しています。このシステムは、以前のバージョンから大幅に改善されていると考えています。

In case you've not been keeping track, there are now eleven TIPs in the ARPA Network. These are ETAC, GWC, AMES, ARPA, MITRE, NBS, BBN, USC, NOAA, ROME, and SAAC. Also, a TIP will soon be installed at CCA.

把握していない方のためにお知らせすると、現在ARPAネットワークには11台のTIPがあります。ETAC、GWC、AMES、ARPA、MITRE、NBS、BBN、USC、NOAA、ROME、SAACです。また、まもなくCCAにもTIPが設置される予定です。

I'll now briefly discuss a number of topics I think may be interesting to you.

ここからは、皆さんが興味を持ちそうないくつかの話題について簡単に説明します。

Getting TIP status information. As we develop new features for the TIP and fix bugs, we are continually releasing new versions of the TIP program. We do this by just reloading your TIP when you're not looking (i.e., when no one is using your TIP). In the future we will notify you whenever a new version of the TIP program is loaded into your TIP by adding a tiny "status message" to the "HELLO" you get when you "log onto" the TIP. This status message will usually be merely the TIP's version number; however, occasionally the message will indicate (by typing "NEWS") that there is some news about the TIP's status which you should read before continuing your session with the TIP. The NEWS can be retrieved by typing the command @NEWS which will ICP to a special socket at BBN's TENEX or PDP-1D which will print the news. Of course, either of these systems may sometimes be down, but we won't worry about the problem until we see how serious it is.

TIPのステータス情報の入手。私たちはTIPの新機能を開発し、バグを修正するのに合わせて、TIPプログラムの新しいバージョンを継続的にリリースしています。これは、皆さんが見ていないとき（つまり、誰もそのTIPを使っていないとき）に、そのTIPをリロードするだけでおこなっています。今後は、TIPプログラムの新しいバージョンが皆さんのTIPにロードされるたびに、TIPに「ログオン」したときに表示される「HELLO」に小さな「ステータスメッセージ」を追加してお知らせします。このステータスメッセージは通常、単なるTIPのバージョン番号です。しかし、ときには（「NEWS」と表示することで）TIPのセッションを続ける前に読むべき、TIPの状態に関するニュースがあることを示す場合があります。NEWSは、@NEWSコマンドを入力すると取得できます。このコマンドは、BBNのTENEXまたはPDP-1Dの特別なソケットにICPし、そこでニュースが表示されます。もちろん、これらのシステムのどちらかがダウンしていることもあるでしょうが、それがどれほど深刻な問題かがわかるまでは気にしないことにします。

To whom to complain or make suggestions. Many of you have had occasion to complain about the operation of your TIP system or to make suggestions for its improvement. All too frequently, however, these complaints have been directed to the Host system you are using from the TIP instead of to us. BBN maintains a Network Control Center which is always manned. Its telephone number is 617-661-0100. All TIP problems should be reported immediately to the Network Control Center. If you have a suggestion for a new command, or if you think you've found a subtle bug in the TIP program, ask to talk to Dave Walden or Bernie Cosell when you call the Network Control Center.

苦情や提案の連絡先。皆さんの多くは、TIPシステムの動作について苦情を言ったり、改善の提案をしたりする機会があったことでしょう。しかし、こうした苦情が、私たちではなく、TIPから使っているホストシステムに向けられることがあまりにも多くありました。BBNは、常に人員が配置されたネットワークコントロールセンター（Network Control Center）を運営しています。その電話番号は617-661-0100です。TIPの問題はすべて、ただちにネットワークコントロールセンターに報告してください。新しいコマンドの提案がある場合や、TIPプログラムに微妙なバグを見つけたと思う場合は、ネットワークコントロールセンターに電話するときに、Dave WaldenかBernie Cosellと話したいと伝えてください。

Device buffers. In general, each TIP MLC port has a different size buffer allocated to it and therefore to the device connected to the port. Devices which operate at higher speeds, of course, require larger buffers, especially output buffers. If you need more buffering than you have (frequently indicated by output coming in short bursts), try to arrange with whomever is locally responsible for the TIP you're using to come in through a port with a larger buffer allocation. If necessary, this person can arrange with us to specially tailor the buffer allocation for your TIP.

デバイスバッファー。一般に、TIPの各MLCポートには、それぞれ異なるサイズのバッファーが割り当てられており、したがってそのポートに接続されたデバイスにも異なるサイズのバッファーが割り当てられます。もちろん、高速で動作するデバイスには、より大きなバッファー、特に出力バッファーが必要です。今あるよりも多くのバッファーが必要な場合は（出力が短いバーストで届くことがその兆候であることがよくあります）、使っているTIPのローカルな責任者と相談して、より大きなバッファーが割り当てられたポートから接続するようにしてください。必要であれば、その責任者が私たちと相談して、そのTIPのバッファー割り当てを特別に調整することもできます。

There are presently only about 2500 characters of buffers available for the TIPs terminal devices. Since each device has an input buffer and two output buffers (output is double buffered), each of the 63 devices has available an average of about 13 charac- ters for input and 13 characters for each output buffer. Since there is continual pressure for new features in the TIP and for old features to work more conveniently, the space available for device buffers is steadily decreasing. There seem to be two ways to increase the space available for device buffers; the first is to get more core memory; the second is to modularize the program so that unneeded features can be removed from particular sites. For instance, the 2741 code and character conversion tables might be removed from a site at which they were never used. You always have the option of getting more core for your TIP; we are presently working on the latter method and should have it ready in a few months. In the mean time, the space available for device buffers will probably continue to slowly diminish.

現在、TIPの端末デバイスに使えるバッファーは約2500文字分しかありません。各デバイスには入力バッファーが1つと出力バッファーが2つ（出力はダブルバッファリングされます）あるので、63台のデバイスがそれぞれ使えるのは、平均して入力用に約13文字、各出力バッファーに約13文字です。TIPには新機能の追加や既存機能の使い勝手の改善を求める声が絶えずあるため、デバイスバッファーに使える領域は着実に減少しています。デバイスバッファーに使える領域を増やす方法は2つあると思われます。1つ目はコアメモリーを増やすことで、2つ目はプログラムをモジュール化して、特定のサイトから不要な機能を取り除けるようにすることです。たとえば、2741用のコードや文字変換テーブルは、それらを一度も使ったことのないサイトからは取り除けるかもしれません。TIPのコアを増やすという選択肢はいつでもあります。私たちは現在後者の方法に取り組んでおり、数か月で準備できるはずです。それまでの間、デバイスバッファーに使える領域はおそらく少しずつ減り続けるでしょう。

現在の標準の（調整していない）バッファーサイズは、おおよそ次のとおりです。

Echoing. The TIP's echoing capability has been a controversial item in the past. We have recently fixed it up a little and we think that if you try it now, you'll like it a lot better. Unfortunately, "@@" is still not echoed correctly very often; this is a bug and we are going to fix it, but it's hairy to fix.

エコー。TIPのエコー機能は、これまで議論の的となってきました。最近少し修正したので、今試していただければ、ずっと気に入っていただけると思います。残念ながら、「@@」はいまだに正しくエコーされないことがよくあります。これはバグなので修正するつもりですが、修正は厄介です。

We will shortly be removing three of the ECHO commands (ECHO ALL, ECHO HALFDUPLEX, and ECHO NONE) and be slightly changing the meaning of the two other ECHO commands (ECHO REMOTE and ECHO LOCAL). We will also add two new ECHO commands (PHYSICAL HALFDUPLEX and PHYSICAL FULLDUPLEX.) Thus the new set of ECHO commands will be:

まもなく、ECHOコマンドのうち3つ（ECHO ALL、ECHO HALFDUPLEX、ECHO NONE）を削除し、残りの2つのECHOコマンド（ECHO REMOTEとECHO LOCAL）の意味を少し変更します。また、新しいECHOコマンドを2つ（PHYSICAL HALFDUPLEXとPHYSICAL FULLDUPLEX）追加します。したがって、新しいECHOコマンドの一式は次のようになります。

     @PHYSICAL HALFDUPLEX
     @PHYSICAL FULLDUPLEX
     @ECHO LOCAL
     @ECHO REMOTE

     @PHYSICAL HALFDUPLEX
     @PHYSICAL FULLDUPLEX
     @ECHO LOCAL
     @ECHO REMOTE

The ECHO LOCAL and ECHO REMOTE commands will probably be ignored for physical halfduplex devices. Therefore, for physical full- duplex devices, ECHO LOCAL and ECHO REMOTE will have the effect of declaring the device to be virtual halfduplex or virtual full- duplex. Devices which are known to be physical halfduplex (e.g., IBM 2741's) will come up in physical halfduplex mode. All other devices will come up in physical fullduplex mode and local echo mode (i.e., virtual halfduplex mode). Whenever a connection is opened, the TIP will automatically send off the current virtual echo mode to the server. Whenever a ECHO LOCAL or ECHO REMOTE command is given, the virtual mode will be appropriately updated and forwarded to the server. When the Telnet ECHO (code 132) (=virtual fullduplex) or Telnet NO ECHO (code 131) (=virtual half- duplex) characters are received by the TIP, it will follow the following rules:

物理的に半二重のデバイスでは、ECHO LOCALコマンドとECHO REMOTEコマンドはおそらく無視されます。したがって、物理的に全二重のデバイスでは、ECHO LOCALとECHO REMOTEは、そのデバイスを仮想的に半二重または仮想的に全二重であると宣言する効果を持ちます。物理的に半二重であることがわかっているデバイス（たとえばIBM 2741）は、物理半二重モードで起動します。その他のデバイスはすべて、物理全二重モードかつローカルエコーモード（つまり、仮想半二重モード）で起動します。コネクションがオープンされるたびに、TIPは現在の仮想エコーモードを自動的にサーバーに送信します。ECHO LOCALコマンドまたはECHO REMOTEコマンドが与えられるたびに、仮想モードは適切に更新され、サーバーに転送されます。TelnetのECHO（コード132）（=仮想全二重）またはTelnetのNO ECHO（コード131）（=仮想半二重）の文字を受信すると、TIPは次の規則に従います。

     ECHO received and
          TIP is physical halfduplex -- NO ECHO  sent to server
          TIP is virtual halfduplex  -- ECHO sent to server and
                                        mode changed to virtual
                                        fullduplex
          TIP is virtual fullduplex  -- nothing

     NO ECHO received and
          TIP is physical halfduplex -- nothing
          TIP is virtual halfduplex  -- nothing

          TIP is virtual fullduplex  -- NO ECHO sent to server and
                                        mode changed to virtual
                                        halfduplex

     ECHO received and
          TIP is physical halfduplex -- NO ECHO  sent to server
          TIP is virtual halfduplex  -- ECHO sent to server and
                                        mode changed to virtual
                                        fullduplex
          TIP is virtual fullduplex  -- nothing

     NO ECHO received and
          TIP is physical halfduplex -- nothing
          TIP is virtual halfduplex  -- nothing

          TIP is virtual fullduplex  -- NO ECHO sent to server and
                                        mode changed to virtual
                                        halfduplex

When a connection is broken, devices in physical fullduplex mode will be reset to virtual halfduplex mode.

コネクションが切断されると、物理全二重モードのデバイスは仮想半二重モードにリセットされます。

Some other command changes we are planning to make.

予定しているその他のコマンドの変更。

  1. PROTOCOL TO LOGIN will be removed. It has been replaced by LOGIN.
  2. LOGIN will take a parameter, the Host number, so it will not be necessary to give both HOST and LOGIN commands.
  1. PROTOCOL TO LOGINは削除します。LOGINで置き換えられました。
  2. LOGINはパラメーターとしてホスト番号を取るようになるので、HOSTコマンドとLOGINコマンドの両方を与える必要はなくなります。

Some things which we are presently doing.

現在取り組んでいること。

  1. When a terminal hangs up, any captured devices will be given back.
  2. Output to high speed devices will be possible.
  3. Data sets will automatically be hung up when the caller disconnects even though the caller never "logged in".
  4. 202C modems will work.
  5. Major improvements on the magnetic tape option.
  6. Trying to find the "R half" of the "R T CLOSED" message.
  7. We have received numerous complaints that the TIP once in a while loses an allocate. We will fix this or else demonstrate it's not the TIP's fault.
  1. 端末が切断されたときに、確保されていたデバイスを返却するようにします。
  2. 高速デバイスへの出力ができるようにします。
  3. 発信者が一度も「ログイン」しなかった場合でも、発信者が切断したときにデータセットが自動的に回線を切るようにします。
  4. 202Cモデムが動作するようにします。
  5. 磁気テープオプションの大幅な改善。
  6. 「R T CLOSED」メッセージの「R half」を探しています。
  7. TIPがときどきallocateを失うという苦情を多数受けています。これを修正するか、そうでなければTIPのせいではないことを示します。

Some things we are thinking about.

検討していること。

  1. Adding a lower case capability for Model 33 Teletypes.
  2. Adding a mechanism so the TIP's status or a device's status (e.g., its device number) can be obtained by the user.
  1. Model 33 Teletypeに小文字の機能を追加すること。
  2. TIPのステータスやデバイスのステータス（たとえば、そのデバイス番号）をユーザーが取得できるメカニズムを追加すること。

Each of the above mentioned changes will be preceded by notification via the NEWS and we plan to issue frequent updates to the TIP User's Guide from now on.

上記の各変更に先立ってNEWSで通知します。また、今後はTIP User's Guideの更新を頻繁に発行する予定です。

We are trying hard to improve the TIP. If you've got a suggestion (especially if it doesn't take any memory), let me hear from you.

私たちはTIPの改善に懸命に取り組んでいます。提案があれば（特にメモリーをまったく必要としないものであれば）、ぜひお聞かせください。

Regards,
