RFC 8527

RESTCONF Extensions to Support the Network Management Datastore Architecture

RFC 8527

ネットワーク管理データストアアーキテクチャーをサポートするためのRESTCONFの拡張

Abstract

概要

This document extends the RESTCONF protocol defined in RFC 8040 in order to support the Network Management Datastore Architecture (NMDA) defined in RFC 8342.

この文書は、RFC 8342で定義されたネットワーク管理データストアアーキテクチャー（NMDA: Network Management Datastore Architecture）をサポートするために、RFC 8040で定義されたRESTCONFプロトコルを拡張します。

This document updates RFC 8040 by introducing new datastore resources, adding a new query parameter, and requiring the usage of the YANG library (described in RFC 8525) by RESTCONF servers implementing the NMDA.

この文書は、新しいデータストアリソースを導入し、新しいクエリーパラメーターを追加し、NMDAを実装するRESTCONFサーバーに（RFC 8525で説明されている）YANGライブラリーの使用を要求することによって、RFC 8040を更新します。

1. Introduction

1. はじめに

This document extends the RESTCONF protocol defined in [RFC8040] in order to support the Network Management Datastore Architecture (NMDA) defined in [RFC8342].

この文書は、[RFC8342]で定義されたネットワーク管理データストアアーキテクチャー（NMDA: Network Management Datastore Architecture）をサポートするために、[RFC8040]で定義されたRESTCONFプロトコルを拡張します。

This document updates [RFC8040] in order to enable RESTCONF clients to discover which datastores are supported by the RESTCONF server, determine which modules are supported in each datastore, and interact with all the datastores supported by the NMDA. Specifically, the update introduces new datastore resources, adds a new query parameter, and requires the usage of the YANG library [RFC8525] by RESTCONF servers implementing the NMDA.

この文書は、RESTCONFクライアントが、RESTCONFサーバーがどのデータストアをサポートしているかを発見し、各データストアでどのモジュールがサポートされているかを判断し、NMDAがサポートするすべてのデータストアとやり取りできるようにするために、[RFC8040]を更新します。具体的には、この更新は、新しいデータストアリソースを導入し、新しいクエリーパラメーターを追加し、NMDAを実装するRESTCONFサーバーにYANGライブラリー[RFC8525]の使用を要求します。

The solution presented in this document is backwards compatible with [RFC8040]. This is achieved by only adding new resources and leaving the semantics of the existing resources unchanged.

この文書で示す解決策は、[RFC8040]と後方互換性があります。これは、新しいリソースを追加するだけで、既存のリソースのセマンティクスを変更しないことによって実現されています。

1.1. Terminology

1.1. 用語

This document uses the terminology defined by the NMDA [RFC8342].

この文書は、NMDA [RFC8342]で定義された用語を使用します。

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

この文書におけるキーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、「要求されています（REQUIRED）」、「することになります（SHALL）」、「することはありません（SHALL NOT）」、「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、「推奨されます（RECOMMENDED）」、「推奨されません（NOT RECOMMENDED）」、「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、ここで示すようにすべて大文字で表記されている場合のみ、BCP 14 [RFC2119] [RFC8174]に記載されているとおりに解釈されるものとします。

2. Datastore and YANG Library Requirements

2. データストアとYANGライブラリーの要件

An NMDA-compliant RESTCONF server MUST support the operational state datastore and MUST implement at least revision 2019-01-04 of the "ietf-yang-library" module defined in [RFC8525].

NMDAに準拠したRESTCONFサーバーは、運用状態データストア（operational state datastore）をサポートしなければなりません（MUST）。また、[RFC8525]で定義された"ietf-yang-library"モジュールの少なくともリビジョン2019-01-04を実装しなければなりません（MUST）。

Such a server identifies that it supports the NMDA both by implementing the {+restconf}/ds/ietf-datastores:operational resource and by implementing at least revision 2019-01-04 of the "ietf-yang-library" module.

このようなサーバーは、{+restconf}/ds/ietf-datastores:operationalリソースを実装することと、"ietf-yang-library"モジュールの少なくともリビジョン2019-01-04を実装することの両方によって、NMDAをサポートしていることを示します。

A RESTCONF client can test if a server supports the NMDA by using either the HEAD or GET methods on {+restconf}/ds/ietf-datastores:operational.

RESTCONFクライアントは、{+restconf}/ds/ietf-datastores:operationalに対してHEADメソッドかGETメソッドのいずれかを使用することで、サーバーがNMDAをサポートしているかどうかを確認できます。

A RESTCONF client can discover which datastores and YANG modules the server supports by reading the YANG library information from the operational state datastore.

RESTCONFクライアントは、運用状態データストアからYANGライブラリーの情報を読み取ることで、サーバーがどのデータストアとYANGモジュールをサポートしているかを発見できます。

3. RESTCONF Extensions

3. RESTCONFの拡張

This section describes the RESTCONF extensions needed to support the NMDA.

このセクションでは、NMDAをサポートするために必要なRESTCONFの拡張について説明します。

3.1. New Datastore Resources

3.1. 新しいデータストアリソース

This document defines a set of new resources representing datastores as defined in [RFC8342]. These resources are available using the following resource path template:

この文書は、[RFC8342]で定義されたデータストアを表す一連の新しいリソースを定義します。これらのリソースは、次のリソースパステンプレートを使用して利用できます。

  {+restconf}/ds/<datastore>

  {+restconf}/ds/<datastore>

The <datastore> path component is encoded as an "identityref" according to the JSON encoding rules for identities, defined in Section 6.8 of [RFC7951]. The namespace-qualified form MUST be used. Such an identity MUST be derived from the "datastore" identity defined in the "ietf-datastores" YANG module [RFC8342].

<datastore>パスコンポーネントは、[RFC7951]のSection 6.8で定義されたアイデンティティーのJSONエンコーディング規則に従って、"identityref"としてエンコードされます。名前空間で修飾された形式を使用しなければなりません（MUST）。そのようなアイデンティティーは、"ietf-datastores" YANGモジュール[RFC8342]で定義された"datastore"アイデンティティーから派生したものでなければなりません（MUST）。

Specifically:

具体的には次のとおりです。

  • The resource {+restconf}/ds/ietf-datastores:operational refers to the operational state datastore.
  • The resource {+restconf}/ds/ietf-datastores:running refers to the running configuration datastore.
  • The resource {+restconf}/ds/ietf-datastores:intended refers to the intended configuration datastore.
  • リソース{+restconf}/ds/ietf-datastores:operationalは、運用状態データストアを指します。
  • リソース{+restconf}/ds/ietf-datastores:runningは、実行設定データストア（running configuration datastore）を指します。
  • リソース{+restconf}/ds/ietf-datastores:intendedは、意図された設定データストア（intended configuration datastore）を指します。

An NMDA-compliant server MUST implement {+restconf}/ds/ietf-datastores:operational. Other datastore resources MAY be implemented.

NMDAに準拠したサーバーは、{+restconf}/ds/ietf-datastores:operationalを実装しなければなりません（MUST）。その他のデータストアリソースを実装してもよいです（MAY）。

YANG actions can only be invoked in {+restconf}/ds/ietf-datastores:operational.

YANGアクションは、{+restconf}/ds/ietf-datastores:operationalでのみ呼び出すことができます。

As an example, if a server implements a datastore called "ds-ephemeral", defined in a module called "example-ds-ephemeral", then the server would implement the resource {+restconf}/ds/example-ds-ephemeral:ds-ephemeral.

例として、サーバーが"example-ds-ephemeral"というモジュールで定義された"ds-ephemeral"というデータストアを実装する場合、そのサーバーはリソース{+restconf}/ds/example-ds-ephemeral:ds-ephemeralを実装することになります。

3.2. Protocol Operations

3.2. プロトコル操作

The protocol operations available for the new datastore resources (see Section 3.1) are the same as the protocol operations defined in [RFC8040] for the {+restconf}/data resource with the following exceptions:

新しいデータストアリソース（Section 3.1を参照）で利用できるプロトコル操作は、[RFC8040]で{+restconf}/dataリソースに対して定義されたプロトコル操作と同じですが、次の例外があります。

  • Dynamic configuration datastores are excluded, as each dynamic configuration datastore definition needs to be reviewed for what protocol operations it supports.
  • Some datastores are read-only by nature (e.g., <intended>); hence, any attempt to modify these datastores will fail. A server MUST return a response with a "405 Method Not Allowed" status-line and an error-tag value of "operation-not-supported".
  • The semantics of the "with-defaults" query parameter (Section 4.8.9 of [RFC8040]) differ when interacting with the operational state datastore. The semantics are described in Section 3.2.1.
  • [RFC8040], Section 3.5.4, paragraph 3 does not apply when interacting with any resource under {+restconf}/ds.
  • 動的設定データストア（dynamic configuration datastore）は除外されます。動的設定データストアの定義ごとに、どのプロトコル操作をサポートするかを検討する必要があるためです。
  • 一部のデータストアは本質的に読み取り専用です（例: <intended>）。そのため、これらのデータストアを変更しようとする試みはすべて失敗します。サーバーは、"405 Method Not Allowed"のステータス行と"operation-not-supported"のerror-tag値を持つレスポンスを返さなければなりません（MUST）。
  • 運用状態データストアとやり取りする場合、"with-defaults"クエリーパラメーター（[RFC8040]のSection 4.8.9）のセマンティクスは異なります。そのセマンティクスはSection 3.2.1で説明します。
  • {+restconf}/ds配下のリソースとやり取りする場合、[RFC8040], Section 3.5.4の第3段落は適用されません。

3.2.1. The "with-defaults" Query Parameter on the Operational State Datastore

3.2.1. 運用状態データストアにおける"with-defaults"クエリーパラメーター

Support for the "with-defaults" query parameter (Section 4.8.9 of [RFC8040]) is OPTIONAL when interacting with {+restconf}/ds/ietf-datastores:operational. The associated capability to indicate a server's support is identified with the URI:

{+restconf}/ds/ietf-datastores:operationalとやり取りする場合、"with-defaults"クエリーパラメーター（[RFC8040]のSection 4.8.9）のサポートは選択できます（OPTIONAL）。サーバーがサポートしていることを示す関連能力は、次のURIで識別されます。

  urn:ietf:params:restconf:capability:with-operational-defaults:1.0

  urn:ietf:params:restconf:capability:with-operational-defaults:1.0

For servers that support it, the behavior of the "with-defaults" query parameter on the operational state datastore is defined as follows:

これをサポートするサーバーでは、運用状態データストアにおける"with-defaults"クエリーパラメーターの振る舞いは次のように定義されます。

  • If no "with-defaults" query parameter is specified, or if it is set to "explicit", "report-all", or "report-all-tagged", then the "in use" values, as defined in Section 5.3 of [RFC8342], are returned from the operational state datastore, even if a node happens to have a default statement in the YANG module and this default value is being used by the server. If the "with-defaults" parameter is set to "report-all-tagged", any values that match the schema default are tagged with additional metadata, as described in Section 4.8.9 of [RFC8040].
  • If the "with-defaults" query parameter is set to "trim", all "in use" values are returned, except that the output is filtered to exclude any values that match the default defined in the YANG schema.
  • "with-defaults"クエリーパラメーターが指定されていない場合、または"explicit"、"report-all"、"report-all-tagged"のいずれかに設定されている場合は、たとえノードがYANGモジュールでdefault文を持っていて、そのデフォルト値がサーバーで使用されている場合であっても、[RFC8342]のSection 5.3で定義された「使用中（in use）」の値が運用状態データストアから返されます。"with-defaults"パラメーターが"report-all-tagged"に設定されている場合は、[RFC8040]のSection 4.8.9で説明されているように、スキーマのデフォルトと一致する値には追加のメタデータでタグが付けられます。
  • "with-defaults"クエリーパラメーターが"trim"に設定されている場合は、「使用中」の値がすべて返されますが、出力はYANGスキーマで定義されたデフォルトと一致する値を除外するようにフィルタリングされます。

Servers are not required to support all values in the "with-defaults" query parameter on the operational state datastore. If a request is made using a value that is not supported, then the error handling behavior is as described in Section 4.8.9 of [RFC8040].

サーバーは、運用状態データストアにおいて"with-defaults"クエリーパラメーターのすべての値をサポートすることは求められていません。サポートされていない値を使用してリクエストが行われた場合のエラー処理の振る舞いは、[RFC8040]のSection 4.8.9で説明されているとおりです。

3.2.2. New "with-origin" Query Parameter

3.2.2. 新しい"with-origin"クエリーパラメーター

A new query parameter named "with-origin" is added to the GET operation. If present, it requests that the server includes "origin" metadata annotations in its response, as detailed in the NMDA. This parameter is only valid when querying {+restconf}/ds/ietf-datastores:operational or any datastores with identities derived from the "operational" identity. Otherwise, if an invalid datastore is specified, then the server MUST return a response with a "400 Bad Request" status-line, using an error-tag value of "invalid-value". "origin" metadata annotations are not included unless a client explicitly requests them.

GET操作に、"with-origin"という名前の新しいクエリーパラメーターを追加します。このパラメーターが存在する場合、NMDAで詳しく説明されているように、サーバーがレスポンスに"origin"メタデータアノテーションを含めることを要求します。このパラメーターは、{+restconf}/ds/ietf-datastores:operational、または"operational"アイデンティティーから派生したアイデンティティーを持つデータストアを問い合わせる場合にのみ有効です。それ以外の場合、つまり無効なデータストアが指定された場合は、サーバーは"400 Bad Request"のステータス行と"invalid-value"のerror-tag値を使用したレスポンスを返さなければなりません（MUST）。"origin"メタデータアノテーションは、クライアントが明示的に要求しない限り含まれません。

Data in the operational state datatstore can come from multiple sources. The server should return the "origin" metadata annotation value that most accurately indicates the source of the operational value, as specified in Section 5.3.4 of [RFC8342].

運用状態データストアのデータは、複数のソースから来る可能性があります。[RFC8342]のSection 5.3.4で規定されているように、サーバーは、運用値のソースを最も正確に示す"origin"メタデータアノテーションの値を返すのが望ましいです。

When encoding the "origin" metadata annotation for a hierarchy of returned nodes, the annotation can be omitted for a child node when the value matches that of the parent node, as described in the "ietf-origin" YANG module [RFC8342].

返されるノードの階層に対して"origin"メタデータアノテーションをエンコードする場合、"ietf-origin" YANGモジュール[RFC8342]で説明されているように、子ノードの値が親ノードの値と一致するときは、その子ノードのアノテーションを省略できます。

Support for the "with-origin" query parameter is OPTIONAL. It is identified with the URI:

"with-origin"クエリーパラメーターのサポートは選択できます（OPTIONAL）。これは次のURIで識別されます。

  urn:ietf:params:restconf:capability:with-origin:1.0

  urn:ietf:params:restconf:capability:with-origin:1.0

5. Security Considerations

5. セキュリティーに関する考慮事項

This document extends the RESTCONF protocol by introducing new datastore resources. The lowest RESTCONF layer is HTTPS, and the mandatory-to-implement secure transport is TLS [RFC8446]. The RESTCONF protocol uses the network configuration access control model [RFC8341], which provides the means to restrict access for particular RESTCONF users to a preconfigured subset of all available RESTCONF protocol operations and content.

この文書は、新しいデータストアリソースを導入することによってRESTCONFプロトコルを拡張します。RESTCONFの最下位層はHTTPSであり、実装必須のセキュアなトランスポートはTLS [RFC8446]です。RESTCONFプロトコルは、ネットワーク設定アクセス制御モデル[RFC8341]を使用します。このモデルは、特定のRESTCONFユーザーのアクセスを、利用可能なすべてのRESTCONFプロトコル操作とコンテンツのうち、あらかじめ設定されたサブセットに制限する手段を提供します。

The security constraints for the base RESTCONF protocol (see Section 12 of [RFC8040]) apply to the new RESTCONF datastore resources defined in this document.

基本のRESTCONFプロトコルに対するセキュリティー上の制約（[RFC8040]のSection 12を参照）は、この文書で定義する新しいRESTCONFデータストアリソースにも適用されます。
