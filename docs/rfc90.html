RFC 90

CCN as a Network Service Center

RFC 90

ネットワークサービスセンターとしてのCCN

A. INTRODUCTION

A. はじめに

CCN, the Campus Computing network of UCLA, will shortly be connected to the ARPA Network as a host of the "Service Center" type. The purpose of this RFC is to describe the hardware and software available at CCN and the services we are now planning to provide to other Network Hosts.

UCLAのキャンパスコンピューティングネットワークであるCCNは、まもなく「サービスセンター（Service Center）」型のホストとしてARPAネットワークに接続されます。このRFCの目的は、CCNで利用できるハードウェアとソフトウェア、および現在他のネットワークホストに提供する予定のサービスを説明することです。

These services and their implementation priority were chosen in consultation with a particular site (RAND) which plans to use CCN via the Network. We would welcome requests and comments from other sites.

これらのサービスとその実装の優先順位は、ネットワーク経由でCCNを利用する予定の特定のサイト（RAND）と相談して選びました。他のサイトからの要望やコメントも歓迎します。

B. CCN HARDWARE

B. CCNのハードウェア

CCN operates an IBM 360/91KK, i.e., a Model 91 CPU with a 4 million byte fast memory.

CCNはIBM 360/91KK、すなわち400万バイトの高速メモリーを備えたModel 91 CPUを運用しています。

CPU Speed:
Highly program-dependent; 2-6 Mips, with 3 Mips as a useful average. The upper end of this range occurs heavy floating point in the inner loops. The decimal arithmetic operation of a 360 should be avoided as they are executed interpretively by the 91.
Memory Speed:
Memory is interleaved 16 ways and extensively buffered. Effective memory fetch time is 600 ns in lower 2 million bytes, 900 ns in upper 2 million bytes.
I/O Configuration
  1. 6 2860 Selector Channels
  2. 1 2870 Multiplexor Channcl (with 16 control unit RPQ)
  3. 5 2314 Disk Storage Units (i.e., 40 disk drives).
  4. 1 2301 Drum (Systems residence and catalog only.)
  5. 5 (245x) 9 track tape drives (80O bpi)
  6. 3 (240x) 7 tracts tape drives (200/556/800 bpi)
  7. 1 2291 (Modified 2250 CRT) Operator/ Maintenance Console.

Also on the Multiplexor Channel are:

  1. 2 card readers and 4 high speed printers at CCN;
  2. Four 40,000 baud interfaces for CCI alphanumeric TV display consoles (currently supporting 40 consoles);
  3. Six data communication ports (3 dial @ 2000 baud, 1 dedicated @ 4800 baud, and 2 dedicated @ 50,000 baud) for remote batch entry terminals;
  4. a Calcomp plotter;
  5. an interface for BBS Teleputers (the Culler-Fried system);
  6. Ten dial ports for 2741 typewriter terminals; and finally:
  7. the IMP Interface
CPU速度:
プログラムに大きく依存します。2〜6 Mipsで、平均すると3 Mipsが実用的な値です。この範囲の上限は、内側のループで浮動小数点演算を多用する場合に現れます。360の10進演算命令は91では解釈実行されるため、避けるべきです。
メモリー速度:
メモリーは16ウェイでインターリーブされ、広範にバッファリングされています。実効的なメモリーフェッチ時間は、下位の200万バイトでは600 ns、上位の200万バイトでは900 nsです。
I/O構成
  1. 6台の2860セレクターチャネル
  2. 1台の2870マルチプレクサーチャネル（16台の制御装置RPQ付き）
  3. 5台の2314ディスク記憶装置（つまり40台のディスクドライブ）。
  4. 1台の2301ドラム（システム常駐用とカタログ用のみ）
  5. 5台の(245x) 9トラックテープドライブ（800 bpi）
  6. 3台の(240x) 7トラックテープドライブ（200/556/800 bpi）
  7. 1台の2291（改造した2250 CRT）オペレーター／保守コンソール

マルチプレクサーチャネルには、次のものも接続されています。

  1. CCNのカードリーダー2台と高速プリンター4台
  2. CCIの英数字TVディスプレイコンソール用の40,000ボーのインターフェース4つ（現在40台のコンソールをサポートしています）
  3. リモートバッチ入力端末用のデータ通信ポート6つ（2000ボーのダイヤルポート3つ、4800ボーの専用ポート1つ、50,000ボーの専用ポート2つ）
  4. Calcompプロッター
  5. BBS Teleputers（Culler-Friedシステム）用のインターフェース
  6. 2741タイプライター端末用のダイヤルポート10個
  7. そして最後に、IMPインターフェース

C. OPERATING SYSTEM

C. オペレーティングシステム

The Model 91 operates under the IBM-supplied MVT version of OS/360, currently Release 18.6. This system contains a set of modifications developed at CCN for control of batch job flow. MVT is a realization of the general process model of multiprogramming, although this fact is obscured by IBM's terminology. For example, a process is called a task in MVT, while the fork primitive is called "ATTACH".

Model 91は、IBM提供のOS/360のMVT版（現在はRelease 18.6）で動作します。このシステムには、バッチジョブの流れを制御するためにCCNで開発した一連の変更が含まれています。MVTは、マルチプログラミングの一般的なプロセスモデルを実現したものですが、IBMの用語のせいでこの事実はわかりにくくなっています。たとえば、MVTではプロセスはタスク（task）と呼ばれ、forkプリミティブは「ATTACH」と呼ばれます。

2. Interactive Systems

2. 対話型システム

a) URSA
Conversational remote job entry system based on alphanumeric display consoles (IBM 2260 and CCI CC301 consoles). URSA provides a number of other services, including a "desk calculator", an interactive/interpretive assembler, and on-line utilities for manipulation of the OS file system. It also contains the CCN operator interface to MVT. URSA is not suitable for typewriter interaction because it is designed for "instantaneous" display of at least 480 characters at a time.
b) APL
IBM Program Product version of this well-known interactive system. Currently supports IBM 2741's (Selectric typewriter terminals) only.
c) OLMS
UCLA implementation of the Culler-Fried system; nearly identical in language to the UCSX On-line System.
d) TSO
IBM's new general purpose time-sharing subsystem under MVT, to be available at CCS sometime during 1971. TSO supports 2741's and Teletypes (and at CCN it will support CCI consoles). TSO is reminiscent of CTSS in its capabilities and command language.
a) URSA
英数字ディスプレイコンソール（IBM 2260とCCI CC301コンソール）を使った、会話型のリモートジョブ入力システムです。URSAは、「卓上計算機」、対話型／インタープリター方式のアセンブラー、OSファイルシステムを操作するオンラインユーティリティーなど、ほかにも多くのサービスを提供します。また、MVTに対するCCNのオペレーターインターフェースも含んでいます。URSAは、少なくとも480文字を一度に「瞬時に」表示するように設計されているため、タイプライターによる対話には適していません。
b) APL
この有名な対話型システムのIBM Program Product版です。現在はIBM 2741（Selectricタイプライター端末）のみをサポートしています。
c) OLMS
Culler-Friedシステムの、UCLAによる実装です。言語はUCSXオンラインシステムとほぼ同一です。
d) TSO
MVT上で動作する、IBMの新しい汎用タイムシェアリングサブシステムで、1971年中のいつかにCCSで利用可能になる予定です。TSOは2741とTeletypeをサポートします（CCNではCCIコンソールもサポートします）。TSOは、機能とコマンド言語の点でCTSSを思わせます。

E. REMOTE JOB SERVICE

E. リモートジョブサービス

The RJS ("remote Job service") subsystem, was written by CCN to support remote batch terminals communicating over dial and leased lines. A remote batch terminal consists of a set of unit record devices (one or more card readers, printers, and punches) driven either by a hardwired controller or by a small CPU (e.g., IBM Model 20 or 1130). A remote RJS user enters OS/360 jobs, complete with JCL, into the remote reader; the jobs are spooled into the operating system and run in their turn, and the printed and/or punched output is returned to the remote terminal from which the jobs originated (unless the user or operator re-routes the output). The remote terminal may also include a console typewriter to be used by the remote operator to receive and send messages and to exert control over his terminal.

RJS（「リモートジョブサービス（remote Job service）」）サブシステムは、ダイヤル回線と専用回線で通信するリモートバッチ端末をサポートするために、CCNが作成しました。リモートバッチ端末は、ハードワイヤードのコントローラーまたは小型のCPU（たとえばIBM Model 20や1130）で駆動される、一組のユニットレコード装置（1台以上のカードリーダー、プリンター、パンチ）で構成されます。リモートのRJSユーザーは、JCLを含むOS/360のジョブをリモートのリーダーに入力します。ジョブはオペレーティングシステムにスプールされ、順番に実行され、印刷出力やパンチ出力、またはその両方は、（ユーザーまたはオペレーターが出力の送り先を変更しない限り）ジョブの発行元であるリモート端末に返されます。リモート端末には、リモートオペレーターがメッセージを送受信し、端末を制御するために使うコンソールタイプライターを含めることもできます。

F. FAST BATCH SUBSYSTEM

F. 高速バッチサブシステム

CCN has written a fast batch subsystem called QUICKRUN to provide "instant" turnaround for small, simple batch jobs which are common in a university computing center. QUICKRUN accepts a very simple job control language ("QCL") without much of the generality of OS/360 JCL.

CCNは、大学の計算センターでよくある小規模で単純なバッチジョブに「即時」のターンアラウンドを提供するために、QUICKRUNという高速バッチサブシステムを作成しました。QUICKRUNは、OS/360 JCLのような汎用性をあまり持たない、非常に単純なジョブ制御言語（「QCL」）を受け付けます。

QUICKRUN is really a batch job control subsystem which itself runs essentially as a job within MVT. Because of its lack of generality, the QUICKRUN subsystem creates much less system overhead than normal OS batch; this is reflected in lower cost per job in QUICKRUN.

QUICKRUNは実際にはバッチジョブ制御サブシステムであり、それ自体が基本的にMVT内の1つのジョブとして動作します。汎用性がないため、QUICKRUNサブシステムは通常のOSバッチよりもシステムのオーバーヘッドがはるかに小さく、これはQUICKRUNでのジョブあたりのコストの低さに反映されています。

QUICKRUN is available at remote batch terminals through RJS as well as through a self-service card reader at CCN.

QUICKRUNは、RJSを通じてリモートバッチ端末から利用できるほか、CCNにあるセルフサービスのカードリーダーからも利用できます。

G. SPECIAL CONSIDERATIONS

G. 特記事項

1. Core Memory for Batch Jobs

1. バッチジョブのコアメモリー

CCN can easily run batch jobs requiring up to 3 million bytes, although jobs over 600K bytes will normally not run during prime time.

CCNは、最大300万バイトを必要とするバッチジョブを容易に実行できますが、600Kバイトを超えるジョブは、通常、ピーク時間帯には実行されません。

2. Disk Space

2. ディスク容量

CCN provides extensive on-line disk space for permanent files. The resident disk pack configuration includes:

CCNは、永続的なファイル用に、広大なオンラインディスク容量を提供しています。常駐のディスクパック構成には、次のものが含まれます。

220 M bytes (8 packs) of user source programs, for use through URSA.

URSA経由で使用する、ユーザーのソースプログラム用の220 Mバイト（8パック）。

170 M bytes (6 packs) of user object and load modules ("binary decks") and other files.

ユーザーのオブジェクトモジュールおよびロードモジュール（「バイナリーデック」）とその他のファイル用の170 Mバイト（6パック）。

100 M bytes of limited-time storage (n days, where n is published number satisfying 7<= n < 0)

期限付きストレージ用の100 Mバイト（n日間。nは公表されている数で、7<= n < 0を満たします）

This space is charged for, at about 5s per kilobyte per month.

この容量は有料で、1キロバイトあたり月額約5セントです。

In the future, we plan to significantly extend this on-line space by implementing a tertiary storage system using magnetic tapes. In addition, a batch job may always request that the user's own disk pack be mounted, thus allowing very large private collections of files.

将来は、磁気テープを使った三次記憶システムを実装して、このオンライン容量を大幅に拡張する予定です。さらに、バッチジョブは、ユーザー自身のディスクパックをマウントするよう常に要求できるため、非常に大規模な個人用のファイルコレクションを置くことができます。

一般に、CCNのModel 91の費用は、計算中心で浮動小数点演算の多い計算、特に大きなリージョンが必要な計算にとって非常に魅力的です。それ以外のほとんどのジョブでは、CCNのマシンは、特別な補助金なしで運営されている、他の独立採算の計算センターと競争できる水準です。

G. SERVICE TO NETWORK

G. ネットワークへのサービス

CCN currently plans to provide RJS, URSA, and (eventually) TSO service to the Network. Each of these will have its own third- level protocol. In addition, there will be a "transparent" third level protocol to allow a user-written program running in batch or TSO at CCN to converse directly with the Network.

CCNは現在、RJS、URSA、および（最終的には）TSOのサービスをネットワークに提供する予定です。これらにはそれぞれ独自の第3レベルのプロトコルがあります。加えて、CCNのバッチまたはTSOで動作するユーザー作成のプログラムがネットワークと直接やり取りできるようにする、「トランスペアレント」な第3レベルのプロトコルも用意します。

The third-level protocols, in the order in which we plan to implement them, are as follows:

第3レベルのプロトコルを、実装する予定の順に示すと次のとおりです。

1. NETRJS

1. NETRJS

NETRJS is the name of the third level protocol by which a user process in a remote host will simulate a remote batch terminal connected to CCN's RJS system. Thus, NETRJS will allow a user to submit complete batch jobs to the 360/91 and receive their print and punch output streams back over the Network. NETRJS has been specified in RFC #88 and implementation is targeted for March, 1971.

NETRJSは、リモートホスト上のユーザープロセスが、CCNのRJSシステムに接続されたリモートバッチ端末を模擬するための、第3レベルのプロトコルの名前です。これにより、NETRJSを使うと、ユーザーは完全なバッチジョブを360/91に投入し、その印刷出力とパンチ出力のストリームをネットワーク経由で受け取れるようになります。NETRJSはRFC #88で規定されており、1971年3月の実装を目標としています。

2. NETCRT

2. NETCRT

This protocol will allow a Network user to simulate an (idealized) CCI alphanumeric display console and use CCN's URSA system (and eventually TS0). An initial version of NETCRT will be circulated shortly as an RFC.

このプロトコルにより、ネットワークのユーザーは、（理想化された）CCIの英数字ディスプレイコンソールを模擬して、CCNのURSAシステム（および最終的にはTS0）を使えるようになります。NETCRTの初版は、まもなくRFCとして配布されます。

3. NETTRANS

3. NETTRANS

This is the "transparent" protocol allowing a user process at CCN to talk over the Network. It has not yet been specified.

これは、CCN上のユーザープロセスがネットワーク経由で通信できるようにする「トランスペアレント」なプロトコルです。まだ規定されていません。

4. NETTYPE

4. NETTYPE

This protocol will allow a real or simulated 2741 to use TS0 (and perhaps APL) via the Network.

このプロトコルにより、実機または模擬の2741から、ネットワーク経由でTS0（そしておそらくAPL）を使えるようになります。
