RFC 8850

Controlling Multiple Streams for Telepresence (CLUE) Protocol Data Channel

RFC 8850

テレプレゼンスのための複数ストリームの制御（CLUE）のプロトコルデータチャネル

Abstract

概要

This document defines how to use the WebRTC data channel mechanism to realize a data channel, referred to as a Controlling Multiple Streams for Telepresence (CLUE) data channel, for transporting CLUE protocol messages between two CLUE entities.

この文書は、2つのCLUEエンティティー間でCLUEプロトコルメッセージを転送するためのデータチャネル（テレプレゼンスのための複数ストリームの制御（Controlling Multiple Streams for Telepresence、CLUE）データチャネルと呼びます）を、WebRTCデータチャネルのメカニズムを使用して実現する方法を定義します。

1. Introduction

1. はじめに

This document defines how to use the WebRTC data channel mechanism [RFC8831] to realize a data channel, referred to as a Controlling Multiple Streams for Telepresence (CLUE) data channel, for transporting CLUE protocol messages [RFC8847] between two CLUE entities.

この文書は、2つのCLUEエンティティー間でCLUEプロトコルメッセージ[RFC8847]を転送するためのデータチャネル（テレプレゼンスのための複数ストリームの制御（Controlling Multiple Streams for Telepresence、CLUE）データチャネルと呼びます）を、WebRTCデータチャネルのメカニズム[RFC8831]を使用して実現する方法を定義します。

This document also defines how to describe the SCTPoDTLS association [RFC8261] (also referred to as "SCTP over DTLS" in this document) used to realize the CLUE data channel using the Session Description Protocol (SDP) [RFC4566] and defines usage of the SDP-based "SCTP over DTLS" data channel negotiation mechanism [RFC8864]. ("SCTP" stands for "Stream Control Transmission Protocol".) This includes SCTP considerations specific to a CLUE data channel, the SDP media description ("m=" line) values, and usage of SDP attributes specific to a CLUE data channel.

この文書はまた、CLUEデータチャネルを実現するために使用するSCTPoDTLSアソシエーション[RFC8261]（この文書では「SCTP over DTLS」とも呼びます）を、セッション記述プロトコル（Session Description Protocol、SDP）[RFC4566]を使用して記述する方法を定義し、SDPに基づく「SCTP over DTLS」データチャネルネゴシエーションメカニズム[RFC8864]の使い方を定義します（「SCTP」は「Stream Control Transmission Protocol」の略です）。 これには、CLUEデータチャネルに固有のSCTPに関する考慮事項、SDPメディア記述（"m="行）の値、CLUEデータチャネルに固有のSDP属性の使い方が含まれます。

Details and procedures associated with the CLUE protocol, and the SDP Offer/Answer procedures [RFC3264] for negotiating usage of a CLUE data channel, are outside the scope of this document.

CLUEプロトコルに関連する詳細と手順、およびCLUEデータチャネルの使用をネゴシエートするためのSDPオファー/アンサー手順[RFC3264]は、この文書の範囲外です。

NOTE: The usage of the Data Channel Establishment Protocol (DCEP) [RFC8832] for establishing a CLUE data channel is outside the scope of this document.

注：CLUEデータチャネルを確立するためのデータチャネル確立プロトコル（Data Channel Establishment Protocol、DCEP）[RFC8832]の使用は、この文書の範囲外です。

2. Conventions

2. 表記規則

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

キーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、 「要求されています（REQUIRED）」、 「することになります（SHALL）」、「することはありません（SHALL NOT）」、 「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、 「推奨されます（RECOMMENDED）」、「推奨されません（NOT RECOMMENDED）」、 「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、 BCP 14 [RFC2119] [RFC8174]に記載されているとおりに解釈されるものとします。 ただし、ここに示すようにすべて大文字で表示される場合に限ります。

SCTPoDTLS association
Refers to an SCTP association carried over a DTLS connection [RFC8261].
WebRTC data channel
Refers to a pair of SCTP streams over an SCTPoDTLS association that is used to transport non-media data between two entities, as defined in [RFC8831].
CLUE data channel
Refers to a WebRTC data channel realization [RFC8831], with a specific set of SCTP characteristics, with the purpose of transporting CLUE protocol messages [RFC8847] between two CLUE entities.
CLUE entity
Refers to a SIP User Agent (UA) [RFC3261] that supports the CLUE data channel and the CLUE protocol.
CLUE session
Refers to a SIP session [RFC3261] between two SIP UAs, where a CLUE data channel, associated with the SIP session, has been established between the SIP UAs.
SCTP stream
Defined in [RFC4960] as a unidirectional logical channel established from one to another associated SCTP endpoint, within which all user messages are delivered in sequence except for those submitted to the unordered delivery service.
SCTP stream identifier
Defined in [RFC4960] as an unsigned integer. Identifies an SCTP stream.
SCTPoDTLSアソシエーション（SCTPoDTLS association）
DTLSコネクション上で運ばれるSCTPアソシエーション[RFC8261]を指します。
WebRTCデータチャネル（WebRTC data channel）
[RFC8831]で定義されているように、2つのエンティティー間でメディア以外のデータを転送するために使用される、SCTPoDTLSアソシエーション上のSCTPストリームの対を指します。
CLUEデータチャネル（CLUE data channel）
2つのCLUEエンティティー間でCLUEプロトコルメッセージ[RFC8847]を転送することを目的とした、特定のSCTP特性の組を持つWebRTCデータチャネルの実現形態[RFC8831]を指します。
CLUEエンティティー（CLUE entity）
CLUEデータチャネルとCLUEプロトコルをサポートするSIPユーザーエージェント（User Agent、UA）[RFC3261]を指します。
CLUEセッション（CLUE session）
2つのSIP UA間のSIPセッション[RFC3261]のうち、そのSIPセッションに関連付けられたCLUEデータチャネルがそれらのSIP UA間で確立されているものを指します。
SCTPストリーム（SCTP stream）
[RFC4960]で、一方のSCTPエンドポイントから関連付けられたもう一方のSCTPエンドポイントへ確立される単方向の論理チャネルとして定義されています。その中では、順序なし配送サービスに渡されたものを除き、すべてのユーザーメッセージが順序どおりに配送されます。
SCTPストリーム識別子（SCTP stream identifier）
[RFC4960]で符号なし整数として定義されています。SCTPストリームを識別します。

3. CLUE Data Channel

3. CLUEデータチャネル

3.1. General

3.1. 一般

This section describes the realization of a CLUE data channel, using the WebRTC data channel mechanism. This includes a set of SCTP characteristics specific to a CLUE data channel, the values of the "m=" line describing the SCTPoDTLS association associated with the WebRTC data channel, and the usage of the SDP-based "SCTP over DTLS" data channel negotiation mechanism for creating the CLUE data channel.

このセクションでは、WebRTCデータチャネルのメカニズムを使用したCLUEデータチャネルの実現について説明します。 これには、CLUEデータチャネルに固有のSCTP特性の組、WebRTCデータチャネルに関連付けられたSCTPoDTLSアソシエーションを記述する"m="行の値、およびCLUEデータチャネルを作成するための、SDPに基づく「SCTP over DTLS」データチャネルネゴシエーションメカニズムの使い方が含まれます。

As described in [RFC8831], the SCTP streams realizing a WebRTC data channel must be associated with the same SCTP association. In addition, both SCTP streams realizing the WebRTC data channel must use the same SCTP stream identifier value. These rules also apply to a CLUE data channel.

[RFC8831]で説明されているように、WebRTCデータチャネルを実現するSCTPストリームは、同じSCTPアソシエーションに関連付けられている必要があります。 さらに、WebRTCデータチャネルを実現する両方のSCTPストリームは、同じSCTPストリーム識別子の値を使用する必要があります。 これらの規則は、CLUEデータチャネルにも適用されます。

Within a given CLUE session, a CLUE entity MUST use a single CLUE data channel for transport of all CLUE messages towards its peer.

あるCLUEセッション内では、CLUEエンティティーは、ピアに向けたすべてのCLUEメッセージの転送に単一のCLUEデータチャネルを使用しなければなりません（MUST）。

3.2. SCTP Considerations

3.2. SCTPに関する考慮事項

3.2.1. General

3.2.1. 一般

As described in [RFC8831], different SCTP options (e.g., regarding ordered delivery) can be used for a data channel. This section describes the SCTP options used for a CLUE data channel. Section 3.3 describes how SCTP options are signaled using SDP.

[RFC8831]で説明されているように、データチャネルにはさまざまなSCTPオプション（たとえば、順序どおりの配送に関するもの）を使用できます。 このセクションでは、CLUEデータチャネルに使用するSCTPオプションについて説明します。 SDPを使用してSCTPオプションをシグナリングする方法は、Section 3.3で説明します。

3.2.2. SCTP Payload Protocol Identifier (PPID)

3.2.2. SCTPペイロードプロトコル識別子（PPID）

A CLUE entity MUST use the PPID value 51 when sending a CLUE message on a CLUE data channel.

CLUEエンティティーは、CLUEデータチャネル上でCLUEメッセージを送信するときに、PPID値51を使用しなければなりません（MUST）。

NOTE: As described in [RFC8831], the PPID value 51 indicates that the SCTP message contains data encoded in UTF-8 format. The PPID value 51 does not indicate which application protocol the SCTP message is associated with -- only the format in which the data is encoded.

注：[RFC8831]で説明されているように、PPID値51は、SCTPメッセージにUTF-8形式でエンコードされたデータが含まれていることを示します。 PPID値51は、SCTPメッセージがどのアプリケーションプロトコルに関連付けられているかを示すものではなく、データがエンコードされている形式だけを示します。

3.2.3. Reliability

3.2.3. 信頼性

The usage of SCTP for the CLUE data channel ensures reliable transport of CLUE protocol messages [RFC8847].

CLUEデータチャネルにSCTPを使用することで、CLUEプロトコルメッセージ[RFC8847]の信頼性のある転送が保証されます。

[RFC8831] requires the support of the partial reliability extension defined in [RFC3758] and the limited retransmission policy defined in [RFC7496]. A CLUE entity MUST NOT use these extensions, as messages are required to always be sent reliably. A CLUE entity MUST terminate the session if it detects that the peer entity uses any of the extensions.

[RFC8831]は、[RFC3758]で定義された部分信頼性拡張と、[RFC7496]で定義された再送回数制限ポリシーのサポートを要求しています。 メッセージは常に信頼性のある方法で送信することが要求されるため、CLUEエンティティーはこれらの拡張を使用してはなりません（MUST NOT）。 CLUEエンティティーは、ピアエンティティーがこれらの拡張のいずれかを使用していることを検出した場合、セッションを終了しなければなりません（MUST）。

3.2.4. Order

3.2.4. 順序

A CLUE entity MUST use the ordered delivery SCTP service, as described in [RFC4960], for the CLUE data channel.

CLUEエンティティーは、CLUEデータチャネルに対して、[RFC4960]で説明されているSCTPの順序どおりの配送サービスを使用しなければなりません（MUST）。

3.2.5. Stream Reset

3.2.5. ストリームのリセット

A CLUE entity MUST support the stream reset extension defined in [RFC6525].

CLUEエンティティーは、[RFC6525]で定義されたストリームリセット拡張をサポートしなければなりません（MUST）。

Per [RFC8831], the dynamic address reconfiguration extension parameter ('Supported Extensions Parameter') defined in [RFC5061] must be used to signal the support of the stream reset extension defined in [RFC6525]. Other features defined in [RFC5061] MUST NOT be used for CLUE data channels.

[RFC8831]にしたがい、[RFC6525]で定義されたストリームリセット拡張のサポートをシグナリングするには、[RFC5061]で定義された動的アドレス再構成の拡張パラメーター（'Supported Extensions Parameter'）を使用する必要があります。 [RFC5061]で定義されたその他の機能は、CLUEデータチャネルに使用してはなりません（MUST NOT）。

3.2.6. SCTP Multihoming

3.2.6. SCTPマルチホーミング

SCTP multihoming is not supported for SCTPoDTLS associations and therefore cannot be used for a CLUE data channel.

SCTPマルチホーミングはSCTPoDTLSアソシエーションではサポートされていないため、CLUEデータチャネルには使用できません。

3.2.7. Closing the CLUE Data Channel

3.2.7. CLUEデータチャネルのクローズ

As described in [RFC8831], to close a data channel, an entity sends an SCTP reset message [RFC6525] on its outgoing SCTP stream associated with the data channel. When the remote peer receives the reset message, it also sends (unless already sent) a reset message on its outgoing SCTP stream associated with the data channel. The SCTPoDTLS association, and other data channels established on the same association, are not affected by the SCTP reset messages.

[RFC8831]で説明されているように、データチャネルをクローズするには、エンティティーは、そのデータチャネルに関連付けられた自身の送信方向のSCTPストリーム上でSCTPリセットメッセージ[RFC6525]を送信します。 リモートピアは、リセットメッセージを受信すると、（まだ送信していなければ）そのデータチャネルに関連付けられた自身の送信方向のSCTPストリーム上でリセットメッセージを送信します。 SCTPoDTLSアソシエーションと、同じアソシエーション上で確立された他のデータチャネルは、SCTPリセットメッセージの影響を受けません。

3.3. SDP Considerations

3.3. SDPに関する考慮事項

3.3.1. General

3.3.1. 一般

This section defines how to (1) construct the SDP media description ("m=" line) for describing the SCTPoDTLS association used to realize a CLUE data channel and (2) use the SDP-based "SCTP over DTLS" data channel negotiation mechanism [RFC8864] for establishing a CLUE data channel on the SCTPoDTLS association.

このセクションでは、（1）CLUEデータチャネルを実現するために使用するSCTPoDTLSアソシエーションを記述するためのSDPメディア記述（"m="行）を構築する方法と、（2）SCTPoDTLSアソシエーション上でCLUEデータチャネルを確立するために、SDPに基づく「SCTP over DTLS」データチャネルネゴシエーションメカニズム[RFC8864]を使用する方法を定義します。

NOTE: Protocols other than SDP for negotiating usage of an SCTPoDTLS association for realizing a CLUE data channel are outside the scope of this specification.

注：CLUEデータチャネルを実現するためのSCTPoDTLSアソシエーションの使用をネゴシエートするための、SDP以外のプロトコルは、この仕様の範囲外です。

[RFC8848] describes the SDP Offer/Answer procedures for negotiating a CLUE session, including the CLUE-controlled media streams and the CLUE data channel.

[RFC8848]は、CLUEで制御されるメディアストリームとCLUEデータチャネルを含め、CLUEセッションをネゴシエートするためのSDPオファー/アンサー手順を説明しています。

3.3.1.1. SDP Media Description Fields
3.3.1.1. SDPメディア記述のフィールド

[RFC8841] defines how to set the values of an "m=" line describing an SCTPoDTLS association. As defined in [RFC8841], for a CLUE data channel the values are set as follows:

[RFC8841]は、SCTPoDTLSアソシエーションを記述する"m="行の値の設定方法を定義しています。 [RFC8841]で定義されているとおり、CLUEデータチャネルの場合、値は次のように設定します。

Table 1: SDP "proto" Field Values
media port proto fmt
"application" UDP port value "UDP/DTLS/SCTP" "webrtc-datachannel"
"application" TCP port value "TCP/DTLS/SCTP" "webrtc-datachannel"
表 1: SDPの"proto"フィールドの値
media port proto fmt
"application" UDPポート値 "UDP/DTLS/SCTP" "webrtc-datachannel"
"application" TCPポート値 "TCP/DTLS/SCTP" "webrtc-datachannel"

CLUE entities SHOULD NOT transport the SCTPoDTLS association used to realize the CLUE data channel over TCP (using the "TCP/DTLS/SCTP" proto value), unless it is known that UDP/DTLS/SCTP will not work (for instance, when the Interactive Connectivity Establishment (ICE) mechanism [RFC8445] is used and the ICE procedures determine that TCP transport is required).

CLUEエンティティーは、UDP/DTLS/SCTPが機能しないことがわかっている場合（たとえば、Interactive Connectivity Establishment（ICE）メカニズム[RFC8445]が使用され、ICEの手順によってTCPトランスポートが必要だと判断された場合）を除き、CLUEデータチャネルを実現するために使用するSCTPoDTLSアソシエーションを（"TCP/DTLS/SCTP"というproto値を使用して）TCP上で転送すべきではありません（SHOULD NOT）。

3.3.1.2. SDP sctp-port Attribute
3.3.1.2. SDPのsctp-port属性

As defined in [RFC8841], the SDP sctp-port attribute value is set to the SCTP port of the SCTPoDTLS association. A CLUE entity can choose any valid SCTP port value [RFC8841].

[RFC8841]で定義されているとおり、SDPのsctp-port属性の値には、SCTPoDTLSアソシエーションのSCTPポートを設定します。 CLUEエンティティーは、任意の有効なSCTPポート値[RFC8841]を選択できます。

3.3.2. SDP dcmap Attribute

4. Security Considerations

4. セキュリティーに関する考慮事項

This specification relies on the security properties of the WebRTC data channel described in [RFC8831], including reliance on DTLS. Since CLUE sessions are established using SIP/SDP, protecting the data channel against message modification and recovery requires the use of SIP authentication and authorization mechanisms described in [RFC3261] for session establishment prior to establishing the data channel.

この仕様は、DTLSへの依存を含め、[RFC8831]で説明されているWebRTCデータチャネルのセキュリティー特性に依存しています。 CLUEセッションはSIP/SDPを使用して確立されるため、メッセージの改ざんと復元からデータチャネルを保護するには、データチャネルを確立する前のセッション確立のために、[RFC3261]で説明されているSIPの認証メカニズムと認可メカニズムを使用する必要があります。
