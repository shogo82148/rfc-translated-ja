YANG Modules for IPv4-in-IPv6 Address plus Port (A⁠+P) Softwires

RFC 8676

IPv4-in-IPv6 Address plus Port（A⁠+P）ソフトワイヤーのためのYANGモジュール

Abstract

概要

This document defines YANG modules for the configuration and operation of IPv4-in-IPv6 softwire Border Relays and Customer Premises Equipment for the Lightweight 4over6, Mapping of Address and Port with Encapsulation (MAP-E), and Mapping of Address and Port using Translation (MAP-T) softwire mechanisms.

この文書は、Lightweight 4over6、Mapping of Address and Port with Encapsulation（MAP-E）、Mapping of Address and Port using Translation（MAP-T）の各ソフトワイヤーメカニズムについて、IPv4-in-IPv6ソフトワイヤーのボーダーリレーと顧客宅内機器を設定および運用するためのYANGモジュールを定義します。

1. Introduction

1. はじめに

The IETF Softwire Working Group has developed several IPv4-in-IPv6 softwire mechanisms to address various deployment contexts and constraints. As a companion to the architectural specification documents, this document focuses on the provisioning of Address plus Port (A+P) softwire functional elements: Border Routers (BRs) and Customer Edge (CE) (called "Customer Premises Equipment (CPE)" in [RFC7596]). The softwire mechanisms covered in this document are Lightweight 4over6 (lw4o6) [RFC7596], Mapping of Address and Port with Encapsulation (MAP-E) [RFC7597], and Mapping of Address and Port using Translation (MAP-T) [RFC7599].

IETFのSoftwireワーキンググループは、さまざまな展開状況と制約に対処するために、いくつかのIPv4-in-IPv6ソフトワイヤーメカニズムを開発してきました。アーキテクチャー仕様の文書群を補完するものとして、この文書は、Address plus Port（A+P）ソフトワイヤーの機能要素であるボーダールーター（BR）とカスタマーエッジ（CE）（[RFC7596]では「顧客宅内機器（CPE）」と呼ばれます）のプロビジョニングに焦点を当てます。この文書で扱うソフトワイヤーメカニズムは、Lightweight 4over6（lw4o6）[RFC7596]、Mapping of Address and Port with Encapsulation（MAP-E）[RFC7597]、Mapping of Address and Port using Translation（MAP-T）[RFC7599]です。

This document focuses on A+P mechanisms [RFC6346]; the reader can refer to [RFC8513] for a YANG module for Dual-Stack Lite (DS-Lite) [RFC6333].

この文書はA+Pメカニズム[RFC6346]に焦点を当てています。Dual-Stack Lite（DS-Lite）[RFC6333]のためのYANGモジュールについては、[RFC8513]を参照してください。

This document defines YANG modules [RFC7950] that can be used to configure and manage A+P softwire elements using the NETCONF [RFC6241] or RESTCONF [RFC8040] protocols for:

この文書は、NETCONF[RFC6241]またはRESTCONF[RFC8040]プロトコルを使用してA+Pソフトワイヤー要素を設定および管理するために使用できるYANGモジュール[RFC7950]を、次の目的のために定義します。

  • Configuration
  • Operational State
  • Notifications
  • 設定
  • 運用状態
  • 通知

2. Terminology

2. 用語

The reader should be familiar with the concepts and terms defined in [RFC7596], [RFC7597], [RFC7599], and the YANG data modeling language defined in [RFC7950].

読者は、[RFC7596]、[RFC7597]、[RFC7599]で定義されている概念と用語、および[RFC7950]で定義されているYANGデータモデリング言語に精通している必要があります。

The YANG modules in this document adopt the Network Management Datastore Architecture (NMDA) [RFC8342]. The meanings of the symbols used in tree diagrams are defined in [RFC8340].

この文書のYANGモジュールは、ネットワーク管理データストアアーキテクチャー（NMDA）[RFC8342]を採用しています。ツリー図で使用する記号の意味は[RFC8340]で定義されています。

The document uses the abbreviation 'BR' as a general term for softwire tunnel concentrators, including both MAP Border Routers [RFC7597] and Lightweight 4over6 lwAFTRs [RFC7596].

この文書では、略語「BR」を、MAPボーダールーター[RFC7597]とLightweight 4over6のlwAFTR[RFC7596]の両方を含む、ソフトワイヤーのトンネルコンセントレーターの総称として使用します。

For brevity, "algorithm" is used to refer to the "mapping algorithm" defined in [RFC7597].

簡潔にするために、「アルゴリズム（algorithm）」は[RFC7597]で定義されている「マッピングアルゴリズム（mapping algorithm）」を指すものとして使用します。

A network element may support one or multiple instances of a softwire mechanism; each of these instances (i.e., binding instances, MAP-E instances, or MAP-T instances) may have its own configuration and parameters. The term 'algo-instance' is used to denote both MAP-E and MAP-T instances.

ネットワーク要素は、1つのソフトワイヤーメカニズムについて1つまたは複数のインスタンスをサポートする場合があります。これらの各インスタンス（つまり、バインディングインスタンス、MAP-Eインスタンス、MAP-Tインスタンス）は、独自の設定とパラメーターを持つことができます。用語「algo-instance」は、MAP-EインスタンスとMAP-Tインスタンスの両方を表すために使用します。

3. Overview of the Modules

3. モジュールの概要

3.1. Overall Structure

3.1. 全体構造

The document defines the following two YANG modules for the configuration and monitoring of softwire functional elements:

この文書は、ソフトワイヤーの機能要素の設定と監視のために、次の2つのYANGモジュールを定義します。

  • ietf-softwire-ce
    Provides configuration and monitoring for softwire CE element. This module is defined as augments to the interface YANG module [RFC8343].
    ietf-softwire-br
    Provides configuration and monitoring for softwire BR element.
  • ietf-softwire-ce
    ソフトワイヤーのCE要素の設定と監視を提供します。このモジュールは、インターフェイスYANGモジュール[RFC8343]に対する拡張（augment）として定義されています。
    ietf-softwire-br
    ソフトワイヤーのBR要素の設定と監視を提供します。

In addition, the following module is defined:

さらに、次のモジュールを定義します。

  • ietf-softwire-common
    Contains groups of common functions that are imported into the CE and BR modules.
  • ietf-softwire-common
    CEモジュールとBRモジュールにインポートされる共通機能のグループを含みます。

This approach has been taken so that the various modules can be easily extended to support additional softwire mechanisms, if required.

この手法は、必要に応じて追加のソフトワイヤーメカニズムをサポートするように各モジュールを容易に拡張できるようにするために採用されました。

Within the BR and CE modules, the YANG "feature" statement is used to distinguish which of the different softwire mechanism(s) is relevant for a specific element's configuration. For each module, a choice statement 'ce-type' is included for either 'binding' or 'algorithm'. 'Binding' is used for configuring Lightweight 4over6, whereas 'algorithm' is used for configuring MAP-T or MAP-E.

BRモジュールとCEモジュールでは、YANGの「feature」文を使用して、異なるソフトワイヤーメカニズムのうちどれが特定の要素の設定に関係するかを区別します。各モジュールには、「binding」または「algorithm」のいずれかを選ぶchoice文「ce-type」が含まれています。「binding」はLightweight 4over6の設定に使用し、「algorithm」はMAP-TまたはMAP-Eの設定に使用します。

NETCONF notifications are also included.

NETCONF通知も含まれています。

Earlier draft versions of this specification combined the softwire mechanisms by their associated technologies rather than their function in the architecture. As the document was revised, it became apparent that dividing the modules by their role in the architecture (CE or BR) was a better approach as this follows the intended function and existing implementation approaches more closely.

この仕様の初期のドラフト版では、ソフトワイヤーメカニズムを、アーキテクチャーにおける機能ではなく、関連する技術ごとにまとめていました。文書を改訂するうちに、アーキテクチャーにおける役割（CEまたはBR）によってモジュールを分割する方が、意図された機能と既存の実装手法により近いため、よりよい手法であることが明らかになりました。

3.2. Configuration for Additional Components

3.2. 追加のコンポーネントの設定

The softwire modules only aim to provide configuration relevant for softwires. In order to fully provision a CE element, the following may also be necessary:

ソフトワイヤーモジュールは、ソフトワイヤーに関係する設定を提供することだけを目的としています。CE要素を完全にプロビジョニングするには、次のものも必要になる場合があります。

  • IPv6 forwarding and routing configuration, to enable the CE to obtain one or more IPv6 prefixes for softwire usage. A YANG module for routing management is described in [RFC8349].
  • IPv4 routing configuration, to add one or more IPv4 destination prefix(es) reachable via the configured softwire. A YANG module for routing management is described in [RFC8349].
  • Stateful NAT44/NAPT management, to optionally specify a port set (Port Set Identifier (PSID)) along with its length. A YANG module for NAT management is described in [RFC8512].
  • Stateless NAT46 management, which is required by softwire-translation-based mechanisms (i.e., the assignment of a Network-Specific Prefix to use for IPv4/IPv6 translation). A YANG module for NAT management is described in [RFC8512].
  • CEがソフトワイヤーで使用するための1つ以上のIPv6プレフィックスを取得できるようにするための、IPv6の転送とルーティングの設定。ルーティング管理のためのYANGモジュールは[RFC8349]で説明されています。
  • 設定したソフトワイヤーを介して到達可能な1つ以上のIPv4宛先プレフィックスを追加するための、IPv4ルーティングの設定。ルーティング管理のためのYANGモジュールは[RFC8349]で説明されています。
  • ポートセット（ポートセット識別子（PSID））をその長さとともにオプションで指定するための、ステートフルNAT44/NAPTの管理。NAT管理のためのYANGモジュールは[RFC8512]で説明されています。
  • ソフトワイヤーの変換に基づくメカニズムで必要となる、ステートレスNAT46の管理（つまり、IPv4/IPv6変換に使用するネットワーク固有プレフィックスの割り当て）。NAT管理のためのYANGモジュールは[RFC8512]で説明されています。

As YANG modules for the above functions are already defined in other documents, their functionality is not duplicated here and they should be referred to, as needed. Appendix A.3 provides XML examples of how these modules can be used together.

上記の機能のためのYANGモジュールは他の文書ですでに定義されているため、ここではその機能を重複して定義せず、必要に応じてそれらを参照してください。Appendix A.3では、これらのモジュールを組み合わせて使用する方法のXMLの例を示します。

The CE must already have minimal IPv6 configuration in place so it is reachable by the NETCONF client to obtain softwire configuration. If additional IPv6-specific configuration is necessary, the YANG modules defined in [RFC8344] and [RFC8349] may be used.

CEは、ソフトワイヤーの設定を取得するためにNETCONFクライアントから到達可能となるよう、最小限のIPv6設定をあらかじめ備えている必要があります。IPv6に固有の追加の設定が必要な場合は、[RFC8344]と[RFC8349]で定義されているYANGモジュールを使用できます。

4.1. CEのツリー図

4.2. Softwire CE Tree Diagram Description

4.2. ソフトワイヤーCEのツリー図の説明

Additional information related to the operation of a CE element is provided below:

CE要素の動作に関する追加情報を以下に示します。

  • softwire-payload-mtu:
    optionally used to set the IPv4 Maximum Transmission Unit (MTU) for the softwire. Needed if the softwire implementation is unable to correctly calculate the correct IPv4 MTU size automatically.
    softwire-path-mru:
    optionally used to set the maximum IPv6 softwire packet size that can be received, including the encapsulation/translation overhead. Needed if the softwire implementation is unable to correctly calculate the correct IPv4 payload Maximum Receive Unit (MRU) size automatically (see Section 3.2 of [RFC4213]).
    ce-type:
    provides a choice statement allowing the binding or algorithmic softwire mechanisms to be selected.
  • softwire-payload-mtu:
    ソフトワイヤーのIPv4最大転送単位（MTU）を設定するためにオプションで使用します。ソフトワイヤーの実装が正しいIPv4 MTUサイズを自動的に正しく計算できない場合に必要です。
    softwire-path-mru:
    受信可能なIPv6ソフトワイヤーパケットの最大サイズを、カプセル化／変換のオーバーヘッドを含めて設定するためにオプションで使用します。ソフトワイヤーの実装が正しいIPv4ペイロードの最大受信単位（MRU）サイズを自動的に正しく計算できない場合に必要です（[RFC4213]のSection 3.2を参照）。
    ce-type:
    バインディング方式またはアルゴリズム方式のソフトワイヤーメカニズムを選択できるようにするchoice文を提供します。

Further details relevant to binding softwire elements are as follows:

バインディング方式のソフトワイヤー要素に関係するさらなる詳細は次のとおりです。

  • binding-ipv6info:
    used to set the IPv6 binding prefix type to identify which IPv6 address to use as the tunnel source. It can be 'ipv6-prefix' or 'ipv6-address'.
    br-ipv6-addr:
    sets the IPv6 address of the remote BR.
  • binding-ipv6info:
    IPv6バインディングプレフィックスの種類を設定し、どのIPv6アドレスをトンネルの送信元として使用するかを識別するために使用します。「ipv6-prefix」または「ipv6-address」のいずれかです。
    br-ipv6-addr:
    リモートBRのIPv6アドレスを設定します。

Additional details relevant to some of the important algorithmic elements are provided below:

アルゴリズム方式の重要な要素のいくつかに関する追加の詳細を以下に示します。

  • algo-versioning:
    optionally used to associate a version number and/or timestamp to the algorithm. This can be used for logging/data retention purposes [RFC7422]. The version number is selected to uniquely identify the algorithm configuration and a new value written whenever a change is made to the algorithm or a new algo-instance is created.
    forwarding:
    specifies whether the rule can be used as a Forwarding Mapping Rule (FMR). If not set, this rule is a Basic Mapping Rule (BMR) only and must not be used for forwarding. Refer to Section 4.1 of [RFC7598].
    ea-len:
    used to set the length of the Embedded-Address (EA), which is defined in the mapping rule for a MAP domain.
    data-plane:
    provides a choice statement for either encapsulation (MAP-E) or translation (MAP-T).
    br-ipv6-addr:
    defines the IPv6 address of the BR. This information is valid for MAP-E.
    dmr-ipv6-prefix:
    defines the Default Mapping Rule (DMR) IPv6 prefix of the BR. This information is valid for MAP-T.
  • algo-versioning:
    アルゴリズムにバージョン番号やタイムスタンプを関連付けるためにオプションで使用します。これは、ログ記録やデータ保持の目的[RFC7422]に使用できます。バージョン番号は、アルゴリズムの設定を一意に識別するように選択し、アルゴリズムに変更が加えられるたび、または新しいalgo-instanceが作成されるたびに新しい値を書き込みます。
    forwarding:
    そのルールを転送マッピングルール（FMR）として使用できるかどうかを指定します。設定されていない場合、このルールは基本マッピングルール（BMR）専用であり、転送に使用してはなりません。[RFC7598]のSection 4.1を参照してください。
    ea-len:
    埋め込みアドレス（EA: Embedded-Address）の長さを設定するために使用します。これはMAPドメインのマッピングルールで定義されます。
    data-plane:
    カプセル化（MAP-E）または変換（MAP-T）のいずれかを選ぶchoice文を提供します。
    br-ipv6-addr:
    BRのIPv6アドレスを定義します。この情報はMAP-Eで有効です。
    dmr-ipv6-prefix:
    BRのデフォルトマッピングルール（DMR）のIPv6プレフィックスを定義します。この情報はMAP-Tで有効です。

Additional information on the notification node is listed below:

通知ノードに関する追加情報を以下に示します。

  • ce-binding-ipv6-addr-change:
    if the CE's binding IPv6 address changes for any reason, the NETCONF client will be notified.
  • ce-binding-ipv6-addr-change:
    何らかの理由でCEのバインディングIPv6アドレスが変更された場合に、NETCONFクライアントに通知されます。

5.2. Softwire BR Tree Diagram Description

5.2. ソフトワイヤーBRのツリー図の説明

The descriptions for leaves that are common with the CE module are provided in Section 4.2. Descriptions for additional elements are provided below:

CEモジュールと共通のリーフの説明はSection 4.2に記載しています。追加の要素の説明を以下に示します。

  • binding-table-versioning:
    optionally used to associate a version number and/or timestamp to the binding table. This can be used for logging or data retention purposes [RFC7422]. The version number is selected to uniquely identify the binding table configuration and a new timestamp value written whenever a change is made to the contents of the binding table or a new binding table list is created.
    binding-entry:
    used to define the binding relationship between 3-tuples {lwB4's IPv6 address/prefix, the allocated IPv4 address, restricted port-set}.  For detailed information, please refer to [RFC7596].
    softwire-num-max:
    used to set the maximum number of softwire binding rules that can be created on the lw4o6 element simultaneously. This parameter must not be set to zero because this is equivalent to disabling the BR instance.
    active-softwire-num:
    holds the number of softwires currently provisioned on the BR element.
  • binding-table-versioning:
    バインディングテーブルにバージョン番号やタイムスタンプを関連付けるためにオプションで使用します。これは、ログ記録やデータ保持の目的[RFC7422]に使用できます。バージョン番号は、バインディングテーブルの設定を一意に識別するように選択し、バインディングテーブルの内容に変更が加えられるたび、または新しいバインディングテーブルのリストが作成されるたびに新しいタイムスタンプ値を書き込みます。
    binding-entry:
    3つ組 {lwB4のIPv6アドレス／プレフィックス、割り当てられたIPv4アドレス、制限されたポートセット} の間のバインディング関係を定義するために使用します。詳細については、[RFC7596]を参照してください。
    softwire-num-max:
    lw4o6要素上で同時に作成できるソフトワイヤーのバインディングルールの最大数を設定するために使用します。このパラメーターはBRインスタンスを無効にすることと同等になるため、0に設定してはなりません。
    active-softwire-num:
    BR要素上で現在プロビジョニングされているソフトワイヤーの数を保持します。

Additional information on some of the important notification nodes is listed below:

重要な通知ノードのいくつかに関する追加情報を以下に示します。

  • invalid-entry, added-entry, modified-entry:
    used to notify the NETCONF client that a specific binding entry or MAP rule has expired, been invalidated, added, or modified.
  • invalid-entry, added-entry, modified-entry:
    特定のバインディングエントリーまたはMAPルールが期限切れになった、無効化された、追加された、または変更されたことをNETCONFクライアントに通知するために使用します。

9. Security Considerations

9. セキュリティーに関する考慮事項

The YANG modules defined in this document are designed to be accessed via network management protocols such as NETCONF [RFC6241] or RESTCONF [RFC8040]. The lowest NETCONF layer is the secure transport layer, and the mandatory-to-implement secure transport is Secure Shell (SSH) [RFC6242]. The lowest RESTCONF layer is HTTPS, and the mandatory-to-implement secure transport is TLS [RFC8446].

この文書で定義するYANGモジュールは、NETCONF[RFC6241]やRESTCONF[RFC8040]などのネットワーク管理プロトコルを介してアクセスされるように設計されています。NETCONFの最下層はセキュアなトランスポート層であり、実装必須のセキュアなトランスポートはセキュアシェル（SSH）[RFC6242]です。RESTCONFの最下層はHTTPSであり、実装必須のセキュアなトランスポートはTLS[RFC8446]です。

The Network Configuration Access Control Model (NACM) [RFC8341] provides the means to restrict access for particular NETCONF or RESTCONF users to a preconfigured subset of all available NETCONF or RESTCONF protocol operations and content.

ネットワーク構成アクセス制御モデル（NACM）[RFC8341]は、特定のNETCONFユーザーやRESTCONFユーザーのアクセスを、利用可能なすべてのNETCONFプロトコル操作やRESTCONFプロトコル操作とコンテンツのうち、事前に設定されたサブセットに制限する手段を提供します。

All data nodes defined in the YANG modules which can be created, modified, and deleted (i.e., config true, which is the default) are considered sensitive. Write operations (e.g., edit-config) to these data nodes without proper protection can have a negative effect on network operations. An attacker who is able to access the BR can undertake various attacks, such as:

これらのYANGモジュールで定義されているデータノードのうち、作成、変更、削除が可能なもの（つまり、デフォルトであるconfig trueのもの）はすべて機密性が高いと考えられます。適切な保護なしにこれらのデータノードに対して書き込み操作（たとえば、edit-config）を行うと、ネットワークの運用に悪影響を及ぼす可能性があります。BRにアクセスできる攻撃者は、次のようなさまざまな攻撃を実行できます。

  • Setting the value of 'br-ipv6-addr' on the CE to point to an illegitimate BR so that it can intercept all the traffic sent by a CE. Illegitimately intercepting users' traffic is an attack with severe implications on privacy.
  • Setting the MTU to a low value, which may increase the number of fragments ('softwire-payload-mtu').
  • Disabling hairpinning (i.e., setting 'enable-hairpinning' to 'false') to prevent communications between CEs.
  • Setting 'softwire-num-max' to an arbitrary high value, which may be exploited by a misbehaving user to perform a DoS on the binding BR by mounting a massive number of softwires.
  • Setting 'icmpv4-rate' or 'icmpv6-rate' to a low value, which may lead to the deactivation of ICMP messages handling.
  • Instructing the BR to install entries, which, in turn, will induce a DDoS attack by means of the notifications generated by the BR. This DDoS can be softened by defining a notification interval, but given that this interval parameter can be disabled or set to a low value by the misbehaving entity, the same problem will be observed.
  • CE上の「br-ipv6-addr」の値を不正なBRを指すように設定し、CEが送信するすべてのトラフィックを傍受できるようにする。ユーザーのトラフィックを不正に傍受することは、プライバシーに深刻な影響を及ぼす攻撃です。
  • MTUを小さな値に設定し、フラグメントの数を増やす可能性がある（「softwire-payload-mtu」）。
  • ヘアピン（hairpinning）を無効にして（つまり、「enable-hairpinning」を「false」に設定して）、CE間の通信を妨げる。
  • 「softwire-num-max」を任意の大きな値に設定する。これは、不正な動作をするユーザーが大量のソフトワイヤーを確立することで、バインディングBRに対してDoSを行うために悪用される可能性があります。
  • 「icmpv4-rate」または「icmpv6-rate」を小さな値に設定する。これにより、ICMPメッセージの処理が無効になる可能性があります。
  • BRにエントリーをインストールするよう指示し、その結果、BRが生成する通知によってDDoS攻撃を引き起こす。このDDoSは通知間隔を定義することで緩和できますが、不正な動作をするエンティティーがこの間隔パラメーターを無効にしたり小さな値に設定したりできるため、同じ問題が発生します。

Some of the readable data nodes in this YANG module may be considered sensitive or vulnerable in some network environments. It is thus important to control read access (e.g., via get, get-config, or notification) to these data nodes. These subtrees and data nodes can be misused to track the activity of a host:

このYANGモジュールの読み取り可能なデータノードの一部は、一部のネットワーク環境では機密性が高い、または脆弱であると考えられる場合があります。そのため、これらのデータノードへの読み取りアクセス（たとえば、get、get-config、通知を介したもの）を制御することが重要です。次のサブツリーとデータノードは、ホストの活動を追跡するために悪用される可能性があります。

  • the binding Table (/br-instances/binding/bind-instance/binding-table)
  • the algorithm configuration (/br-instances/algorithm/algo-instance/)
  • バインディングテーブル（/br-instances/binding/bind-instance/binding-table）
  • アルゴリズムの設定（/br-instances/algorithm/algo-instance/）

Security considerations related to lw4o6, MAP-T, and MAP-E are discussed in [RFC7596], [RFC7597], and [RFC7599] respectively.

lw4o6、MAP-T、MAP-Eに関するセキュリティーに関する考慮事項は、それぞれ[RFC7596]、[RFC7597]、[RFC7599]で説明されています。

Security considerations given in [RFC7950] are also applicable here.

[RFC7950]に記載されているセキュリティーに関する考慮事項も、ここに適用されます。

A.2. MAP-E BRの設定例
