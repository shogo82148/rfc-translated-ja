RFC 927

TACACS User Identification Telnet Option

RFC 927

TACACSユーザー識別Telnetオプション

Status of This Memo

このメモのステータス

This RFC suggests a proposed protocol for the ARPA-Internet community, and requests discussion and suggestions for improvements. Distribution of this memo is unlimited.

このRFCは、ARPAインターネットコミュニティーのためのプロトコルを提案し、改善のための議論と提案を求めるものです。このメモの配布は無制限です。

Introduction

はじめに

The following is the description of a TELNET option designed to facilitate double login avoidance. It is intended primarily for TAC connections to target hosts on behalf of TAC users, but it can be used between any two consenting hosts. For example, all hosts at one site (e.g., BBN) can use this option to avoid double login when TELNETing to one another.

以下は、二重ログインを避けやすくするために設計されたTELNETオプションの説明です。主にTACユーザーに代わって対象ホストへ接続するTACのコネクションを想定していますが、合意した任意の2つのホストの間で使うこともできます。たとえば、あるサイト（たとえばBBN）のすべてのホストが、互いにTELNETで接続するときに二重ログインを避けるためにこのオプションを使うことができます。

1. Command name and code

1. コマンド名とコード

TUID 26

TUID 26

2. Command Meanings

2. コマンドの意味

IAC WILL TUID
The sender (the TELNET user) proposes to authenticate the user and send the identifing UUID; or, the sender (the TELNET user) agrees to authenticate the user on whose behalf the connection is initiated.
IAC WON'T TUID
The sender (the TELNET user) refuses to authenticate the user on whose behalf the connection is initiated.
IAC DO TUID
The sender (the TELNET server) proposes that the recipient (the TELNET user) authenticate the user and send the identifing UUID; or, the sender (the TELNET server) agrees to accept the recipient's (the TELNET user's) authentication of the user identified by his UUID.
IAC DON'T TUID
The sender (the TELNET server) refuses to accept the recipient's (the TELNET user) authentication of the user.
IAC SB TUID <uuid> IAC SE
The sender (the TELNET user) sends the UUID <uuid> of the user on whose behalf the connection is established to the host to which he is connected. The <uuid> is a 32 bit binary number.
IAC WILL TUID
送信者（TELNETユーザー）は、ユーザーを認証して識別用のUUIDを送信することを提案します。または、送信者（TELNETユーザー）は、コネクションを開始する代理元のユーザーを認証することに同意します。
IAC WON'T TUID
送信者（TELNETユーザー）は、コネクションを開始する代理元のユーザーを認証することを拒否します。
IAC DO TUID
送信者（TELNETサーバー）は、受信者（TELNETユーザー）がユーザーを認証して識別用のUUIDを送信することを提案します。または、送信者（TELNETサーバー）は、UUIDで識別されるユーザーについての受信者（TELNETユーザー）による認証を受け入れることに同意します。
IAC DON'T TUID
送信者（TELNETサーバー）は、受信者（TELNETユーザー）によるユーザーの認証を受け入れることを拒否します。
IAC SB TUID <uuid> IAC SE
送信者（TELNETユーザー）は、コネクションを確立した代理元のユーザーのUUID <uuid>を、接続先のホストへ送信します。<uuid>は32ビットの2進数です。

3. Default

3. デフォルト

WON'T TUID
A TELNET user host (the initiator of a TELNET connection) not implementing or using the TUID option will reply WON'T TUID to a DO TUID.
DON'T TUID
A TELNET server host (the recipient of a TELNET connection) not implementing or using the TUID option reply DON'T TUID to a WILL TUID.
WON'T TUID
TUIDオプションを実装していない、または使用しないTELNETユーザーホスト（TELNETコネクションの開始者）は、DO TUIDに対してWON'T TUIDで応答します。
DON'T TUID
TUIDオプションを実装していない、または使用しないTELNETサーバーホスト（TELNETコネクションの受信者）は、WILL TUIDに対してDON'T TUIDで応答します。

4. Motivation for the Option

4. このオプションの動機

Under TACACS (the TAC Access Control System) a user must be authenticated (give a correct name/password pair) to a TAC before he can connect to a host via the TAC. To avoid a second authentication by the target host, the TAC can pass along the user's proven identity (his UUID) to the that host. Hosts may accept the TAC's authentication of the user or not, at their option.

TACACS（TAC Access Control System）のもとでは、ユーザーはTACを介してホストに接続する前に、TACに対して認証される（正しい名前とパスワードの組を与える）必要があります。対象ホストによる2回目の認証を避けるため、TACは、証明済みのユーザーの身元（UUID）をそのホストに引き渡すことができます。ホストは、TACによるユーザーの認証を受け入れるかどうかを任意に選択できます。

The same option can be used between any pair of cooperating hosts for the purpose of double login avoidance.

同じオプションは、二重ログインを避ける目的で、協調する任意の2つのホストの間で使うことができます。

5. Description for the Option

5. このオプションの説明

At the time that a host establishes a TELNET connection for a user to another host, if the latter supports the TUID option and wants to receive the user's UUID, it sends an IAC DO TUID to the the user's host. If the user's host supports the TUID option and wants to authenticate the user by sending the user's UUID, it responds IAC WILL TUID; otherwise it responds with IAC WON'T TUID. If both the user and server TELNETs agree, the user TELNET will then send the UUID to the server TELNET by sub-negotiation.

あるホストがユーザーのために別のホストへのTELNETコネクションを確立するとき、後者がTUIDオプションをサポートしていて、ユーザーのUUIDを受け取りたい場合は、ユーザーのホストへIAC DO TUIDを送信します。ユーザーのホストがTUIDオプションをサポートしていて、ユーザーのUUIDを送信してユーザーを認証したい場合は、IAC WILL TUIDで応答します。そうでなければIAC WON'T TUIDで応答します。ユーザー側とサーバー側の両方のTELNETが合意した場合、ユーザー側のTELNETはサブネゴシエーションによってUUIDをサーバー側のTELNETへ送信します。

6. Examples

6. 例

There are two possible negotiations that result in the double login avoidance authentication of a user. Both the server and the user TELNET support the TUID option.

二重ログインを避けるユーザーの認証に至るネゴシエーションには、2通りがあります。どちらも、サーバー側とユーザー側の両方のTELNETがTUIDオプションをサポートしている場合です。

   S = Server, U = User

   Case 1:

      S-> IAC DO TUID
      U-> IAC WILL TUID
      U-> IAC SB TUID <32-bit UUID> IAC SE

   Case 2:

      U-> IAC WILL TUID
      S-> IAC DO TUID
      U-> IAC SB TUID <32-bit UUID> IAC SE

   S = Server, U = User

   Case 1:

      S-> IAC DO TUID
      U-> IAC WILL TUID
      U-> IAC SB TUID <32-bit UUID> IAC SE

   Case 2:

      U-> IAC WILL TUID
      S-> IAC DO TUID
      U-> IAC SB TUID <32-bit UUID> IAC SE

There are also two possible negoitiations that do not result in the authentication of a user. In the first example the server supports TUID and the user TELNET doesn't. In the second example the user TELNET supports TUID but the server TELNET doesn't.

ユーザーの認証に至らないネゴシエーションも2通りあります。1つ目の例では、サーバーはTUIDをサポートしていますが、ユーザー側のTELNETはサポートしていません。2つ目の例では、ユーザー側のTELNETはTUIDをサポートしていますが、サーバー側のTELNETはサポートしていません。

   S = Server, U = User

   Case 3:

      S-> IAC DO TUID
      U-> IAC WONT TUID

   Case 4:

      U-> IAC WILL TUID
      S-> IAC DONT TUID

   S = Server, U = User

   Case 3:

      S-> IAC DO TUID
      U-> IAC WONT TUID

   Case 4:

      U-> IAC WILL TUID
      S-> IAC DONT TUID

The TUID is transmitted with the subnegotiation command. For example, if the UUID had the value 1 the following string of octets would be transmitted:

TUIDはサブネゴシエーションコマンドで送信されます。たとえば、UUIDの値が1の場合は、次のオクテット列が送信されます。

   IAC SB TUID 0 0 0 1 IAC SE

   IAC SB TUID 0 0 0 1 IAC SE

If the UUID had the value 255 the following string of octets would be transmitted:

UUIDの値が255の場合は、次のオクテット列が送信されます。

   IAC SB TUID 0 0 0 IAC IAC IAC SE

   IAC SB TUID 0 0 0 IAC IAC IAC SE

If the UUID had the value of all ones the following string of octets would be transmitted:

UUIDの値がすべて1の場合は、次のオクテット列が送信されます。

   IAC SB TUID IAC IAC IAC IAC IAC IAC IAC IAC IAC SE

   IAC SB TUID IAC IAC IAC IAC IAC IAC IAC IAC IAC SE
