Definitions of Managed Objects for IEEE 802.3 Medium Attachment Units (MAUs) using SMIv2

RFC 2239

SMIv2を使用したIEEE 802.3媒体接続装置（MAU）のための管理オブジェクトの定義

Abstract

概要

This memo defines an portion of the Management Information Base (MIB) for use with network management protocols in the Internet community. In particular, it defines objects for managing 10 and 100 Mb/second Medium Attachment Units (MAUs) based on IEEE Std 802.3 Section 30, "10 & 100 Mb/s Management," October 26, 1995.

このメモは、インターネットコミュニティーのネットワーク管理プロトコルで使用するための管理情報ベース（Management Information Base: MIB）の一部を定義します。特に、IEEE Std 802.3 Section 30「10 & 100 Mb/s Management」（1995年10月26日）に基づいて、10 Mb/秒および100 Mb/秒の媒体接続装置（Medium Attachment Unit: MAU）を管理するためのオブジェクトを定義します。

1. The SNMPv2 Network Management Framework

1. SNMPv2ネットワーク管理フレームワーク

The SNMPv2 Network Management Framework presently consists of three major components. They are:

SNMPv2ネットワーク管理フレームワークは、現在、3つの主要なコンポーネントで構成されています。それらは次のとおりです。

  • the SMI, described in RFC 1902 [6] - the mechanisms used for describing and naming objects for the purpose of management.
  • the MIB-II, STD 17, RFC 1213 [5] - the core set of managed objects for the Internet suite of protocols.
  • the protocol, STD 15, RFC 1157 [10] and/or RFC 1905 [9] - the protocol used for accessing managed information.
  • SMI。RFC 1902 [6]で説明されており、管理の目的でオブジェクトを記述し命名するために使用される仕組みです。
  • MIB-II。STD 17、RFC 1213 [5]で説明されており、インターネットプロトコルスイートのための管理オブジェクトの中核となる集合です。
  • プロトコル。STD 15、RFC 1157 [10]とRFC 1905 [9]の両方またはいずれかで説明されており、管理情報にアクセスするために使用されるプロトコルです。

Textual conventions are defined in RFC 1903 [7], and conformance statements are defined in RFC 1904 [8].

テキスト規約はRFC 1903 [7]で定義され、準拠性ステートメントはRFC 1904 [8]で定義されています。

The Framework permits new objects to be defined for the purpose of experimentation and evaluation.

このフレームワークでは、実験と評価の目的で新しいオブジェクトを定義できます。

1.1. Object Definitions

1.1. オブジェクトの定義

Managed objects are accessed via a virtual information store, termed the Management Information Base or MIB. Objects in the MIB are defined using the subset of Abstract Syntax Notation One (ASN.1) defined in the SMI. In particular, each object type is named by an OBJECT IDENTIFIER, an administratively assigned name. The object type together with an object instance serves to uniquely identify a specific instantiation of the object. For human convenience, we often use a textual string, termed the descriptor, to refer to the object type.

管理オブジェクトには、管理情報ベース（MIB）と呼ばれる仮想的な情報ストアを介してアクセスします。MIBのオブジェクトは、SMIで定義された抽象構文記法1（Abstract Syntax Notation One: ASN.1）のサブセットを使用して定義されます。特に、各オブジェクトタイプは、管理上割り当てられた名前であるOBJECT IDENTIFIERによって命名されます。オブジェクトタイプとオブジェクトインスタンスを合わせることで、オブジェクトの特定のインスタンス化を一意に識別します。人間にとっての便宜のため、オブジェクトタイプを参照する際には、記述子（descriptor）と呼ばれるテキスト文字列をよく使用します。

2. Overview

2. 概要

2.1. Relationship to RFC 1515

2.1. RFC 1515との関係

This MIB is intended to be a superset of that defined by RFC 1515 [11], which will go to historic status. This MIB includes all of the objects contained in that MIB, plus several new ones which provide additional capabilities. Implementors are encouraged to support all applicable conformance groups in order to make the best use of the new functionality provided by this MIB. The new objects provide management support for:

このMIBは、RFC 1515 [11]で定義されたもののスーパーセットとなることを意図しており、RFC 1515は歴史的（historic）ステータスになる予定です。このMIBには、そのMIBに含まれるすべてのオブジェクトに加えて、追加の機能を提供するいくつかの新しいオブジェクトが含まれています。このMIBが提供する新しい機能を最大限に活用するため、実装者には、適用可能なすべての適合性グループをサポートすることが推奨されます。新しいオブジェクトは、次のものに対する管理のサポートを提供します。

  • management of 100 Mb/s devices
  • auto-negotiation on interface MAUs
  • jack management
  • 100 Mb/sのデバイスの管理
  • インターフェースMAUでのオートネゴシエーション
  • ジャックの管理

2.2. MAU Management

2.2. MAUの管理

Instances of these object types represent attributes of an IEEE 802.3 MAU. Several types of MAUs are defined in the IEEE 802.3 CSMA/CD standard [1] and [2]. These MAUs may be connected to IEEE 802.3 repeaters or to 802.3 (Ethernet-like) interfaces. For convenience this document refers to these devices as "repeater MAUs" and "interface MAUs."

これらのオブジェクトタイプのインスタンスは、IEEE 802.3 MAUの属性を表します。IEEE 802.3 CSMA/CD標準[1]および[2]では、いくつかの種類のMAUが定義されています。これらのMAUは、IEEE 802.3リピーターまたは802.3（イーサネットに類似した）インターフェースに接続される場合があります。便宜上、この文書ではこれらのデバイスを「リピーターMAU」および「インターフェースMAU」と呼びます。

The definitions presented here are based on Section 30.5, "Layer Management for 10 & 100 Mb/s Medium Attachment Units (MAUs)", and Annex 30A, "GDMO Specifications for 802.3 managed objects" of IEEE Std 802.3u-1995. That specification includes definitions for both 10Mb/s and 100Mb/s devices, and is essentially a superset of the 10Mb/s definitions given by IEEE 802.3 Section 20. This specification is intended to serve the same purpose: to provide for management of both 10Mb/s and 100Mb/s MAUs.

ここで示す定義は、IEEE Std 802.3u-1995のSection 30.5「Layer Management for 10 & 100 Mb/s Medium Attachment Units (MAUs)」とAnnex 30A「GDMO Specifications for 802.3 managed objects」に基づいています。その仕様には10Mb/sと100Mb/sの両方のデバイスの定義が含まれており、本質的にはIEEE 802.3 Section 20で示された10Mb/sの定義のスーパーセットです。この仕様も同じ目的、つまり10Mb/sと100Mb/sの両方のMAUの管理を提供することを意図しています。

2.3. Relationship to Other MIBs

2.3. 他のMIBとの関係

It is assumed that an agent implementing this MIB will also implement (at least) the 'system' group defined in MIB-II [5]. The following sections identify other MIBs that such an agent should implement.

このMIBを実装するエージェントは、（少なくとも）MIB-II [5]で定義されている「system」グループも実装することを前提としています。以降のセクションでは、そのようなエージェントが実装すべき他のMIBを特定します。

2.3.1. Relationship to the MIB-II 'interfaces' group

2.3.1. MIB-IIの「interfaces」グループとの関係

The sections of this document that define interface MAU-related objects specify an extension to the 'interfaces' group of MIB-II. An agent implementing these interface-MAU related objects must also implement the 'interfaces' group of MIB-II. The value of the object ifMauIfIndex is the same as the value of 'ifIndex' used to instantiate the interface to which the given MAU is connected.

この文書のうちインターフェースMAUに関連するオブジェクトを定義するセクションは、MIB-IIの「interfaces」グループの拡張を規定します。これらのインターフェースMAUに関連するオブジェクトを実装するエージェントは、MIB-IIの「interfaces」グループも実装しなければなりません。オブジェクトifMauIfIndexの値は、特定のMAUが接続されているインターフェースをインスタンス化するために使用される「ifIndex」の値と同じです。

It is expected that an agent implementing the interface-MAU related objects in this MIB will also implement the Ethernet- like Interfaces MIB, RFC 1650.

このMIBのインターフェースMAUに関連するオブジェクトを実装するエージェントは、イーサネット類似インターフェースMIB（RFC 1650）も実装することが期待されます。

(Note that repeater ports are not represented as interfaces in the sense of MIB-II's 'interfaces' group.)

（リピーターのポートは、MIB-IIの「interfaces」グループの意味でのインターフェースとしては表されないことに注意してください。）

2.3.2. Relationship to the 802.3 Repeater MIB

2.3.2. 802.3リピーターMIBとの関係

The section of this document that defines repeater MAU-related objects specifies an extension to the 802.3 Repeater MIB defined in [4]. An agent implementing these repeater-MAU related objects must also implement the 802.3 Repeater MIB.

この文書のうちリピーターMAUに関連するオブジェクトを定義するセクションは、[4]で定義されている802.3リピーターMIBの拡張を規定します。これらのリピーターMAUに関連するオブジェクトを実装するエージェントは、802.3リピーターMIBも実装しなければなりません。

The values of 'rpMauGroupIndex' and 'rpMauPortIndex' used to instantiate a repeater MAU variable shall be the same as the values of 'rptrPortGroupIndex' and 'rptrPortIndex' used to instantiate the port to which the given MAU is connected.

リピーターMAUの変数をインスタンス化するために使用される「rpMauGroupIndex」と「rpMauPortIndex」の値は、特定のMAUが接続されているポートをインスタンス化するために使用される「rptrPortGroupIndex」と「rptrPortIndex」の値と同じでなければなりません。

2.4. Management of Internal MAUs

2.4. 内部MAUの管理

In some situations, a MAU can be "internal" -- i.e., its functionality is implemented entirely within a device. For example, a managed repeater may contain an internal repeater- MAU and/or an internal interface-MAU through which management communications originating on one of the repeater's external ports pass in order to reach the management agent associated with the repeater. Such internal MAUs may or may not be managed. If they are managed, objects describing their attributes should appear in the appropriate MIB subtree:

状況によっては、MAUが「内部」、つまりその機能が完全にデバイス内で実装されている場合があります。たとえば、管理対象のリピーターには、内部のリピーターMAUと内部のインターフェースMAUの両方またはいずれかが含まれている場合があります。リピーターの外部ポートの1つから発信された管理通信は、リピーターに関連付けられた管理エージェントに到達するために、それらを通過します。そのような内部MAUは、管理される場合もされない場合もあります。管理される場合、その属性を記述するオブジェクトは、適切なMIBサブツリーに現れるべきです。

dot3RpMauBasicGroup for internal repeater-MAUs and dot3IfMauBasicGroup for internal interface-MAUs.

内部のリピーターMAUについてはdot3RpMauBasicGroup、内部のインターフェースMAUについてはdot3IfMauBasicGroupです。

    SYNTAX     INTEGER {
                   other(1),
                   unknown(2),
                   operational(3),
                   standby(4),
                   shutdown(5),
                   reset(6)
               }
    MAX-ACCESS read-write
    STATUS     current
    DESCRIPTION
            "The current state of the MAU.  This object may be
            implemented as a read-only object by those agents
            and MAUs that do not implement software control of
            the MAU state.  Some agents may not support
            setting the value of this object to some of the
            enumerated values.

            The value other(1) is returned if the MAU is in a

            being initialized.

            functional, operates, and passes signals to its

6. Security Considerations

6. セキュリティーに関する考慮事項

Certain management information defined in this MIB may be considered sensitive in some network environments. Therefore, authentication of received SNMP requests and controlled access to management information should be employed in such environments. The method for this authentication is a function of the SNMP Administrative Framework, and has not been expanded by this MIB.

このMIBで定義されている一部の管理情報は、ネットワーク環境によっては機密とみなされる場合があります。したがって、そのような環境では、受信したSNMPリクエストの認証と、管理情報へのアクセス制御を用いるべきです。この認証の方法はSNMP管理フレームワーク（SNMP Administrative Framework）の機能であり、このMIBによって拡張されてはいません。

Several objects in this MIB allow write access. Setting these objects can have a serious effect on the operation of the network, including enabling or disabling a MAU, changing a MAU's default type, enabling, disabling or restarting autonegotiation, or modifying the capabilities that a MAU advertizes during autonegotiation. It is recommended that implementers seriously consider whether set operations should be allowed without providing, at a minimum, authentication of request origin.

このMIBのいくつかのオブジェクトは書き込みアクセスを許可しています。これらのオブジェクトを設定すると、MAUの有効化や無効化、MAUのデフォルトタイプの変更、オートネゴシエーションの有効化、無効化、または再開始、MAUがオートネゴシエーションの間に広告する機能の変更など、ネットワークの運用に重大な影響を与える可能性があります。実装者は、少なくともリクエストの発信元の認証を提供せずにset操作を許可すべきかどうかを真剣に検討することが推奨されます。
