RFC 8161

Benchmarking the Neighbor Discovery Protocol

RFC 8161

近隣探索プロトコルのベンチマーク

Abstract

概要

This document provides benchmarking procedures for the Neighbor Discovery Protocol (NDP). It also proposes metrics by which an NDP implementation's scaling capabilities can be measured.

この文書は、近隣探索プロトコル（Neighbor Discovery Protocol、NDP）のベンチマーク手順を規定します。また、NDP実装のスケーリング能力を測定するためのメトリックも提案します。

1. Introduction

1. はじめに

When an IPv6 node forwards a packet, it executes the following procedure:

IPv6ノードはパケットを転送するとき、次の手順を実行します。

  • Identifies the outbound interface and IPv6 next hop.
  • Queries a local Neighbor Cache (NC) to determine the IPv6 next hop's link-layer address.
  • Encapsulates the packet in a link-layer header. The link-layer header includes the IPv6 next hop's link-layer address.
  • Forwards the packet to the IPv6 next hop.
  • 送出インターフェイスとIPv6ネクストホップを特定します。
  • ローカルの近隣キャッシュ（Neighbor Cache、NC）に問い合わせて、IPv6ネクストホップのリンク層アドレスを決定します。
  • パケットをリンク層ヘッダーでカプセル化します。リンク層ヘッダーには、IPv6ネクストホップのリンク層アドレスが含まれます。
  • パケットをIPv6ネクストホップに転送します。

IPv6 nodes use the Neighbor Discovery Protocol (NDP) [RFC4861] to maintain the NC. Operational experience [RFC6583] shows that when an implementation cannot maintain a sufficiently complete NC, its ability to forward packets is impaired.

IPv6ノードは、NCを維持するために近隣探索プロトコル（Neighbor Discovery Protocol、NDP）[RFC4861]を使用します。運用経験[RFC6583]によれば、実装が十分に完全なNCを維持できない場合、そのパケット転送能力は損なわれます。

NDP, like any other protocol, consumes processing, memory, and bandwidth resources. Its ability to maintain a sufficiently complete NC depends upon the availability of the above-mentioned resources.

NDPは、ほかのどのプロトコルとも同様に、処理、メモリー、帯域幅のリソースを消費します。十分に完全なNCを維持するNDPの能力は、上記のリソースが利用可能かどうかに依存します。

This document provides benchmarking procedures for NDP. Benchmarking procedures include a Baseline Test and an NDP Scaling Test. In both tests, the Device Under Test (DUT) is an IPv6 router. Two physical links (A and B) connect the DUT to a Tester. The Tester sends traffic through Link A to the DUT. The DUT forwards that traffic, through Link B, back to the Tester.

この文書は、NDPのベンチマーク手順を規定します。ベンチマーク手順には、ベースラインテスト（Baseline Test）とNDPスケーリングテスト（NDP Scaling Test）が含まれます。どちらのテストでも、被試験デバイス（Device Under Test、DUT）はIPv6ルーターです。2つの物理リンク（AとB）がDUTをテスターに接続します。テスターは、リンクAを通じてDUTにトラフィックを送信します。DUTはそのトラフィックを、リンクBを通じてテスターに転送して戻します。

The above-mentioned traffic stream contains one or more interleaved flows. An IPv6 Destination Address uniquely identifies each flow. Or, said another way, every packet within a flow has the same IPv6 Destination Address.

上記のトラフィックストリームには、交互に配置された1つ以上のフローが含まれます。各フローは、IPv6の宛先アドレス（Destination Address）によって一意に識別されます。言い換えると、1つのフロー内のすべてのパケットは同じIPv6宛先アドレスを持ちます。

In the Baseline Test, the traffic stream contains exactly one flow. Because every packet in the stream has the same IPv6 Destination Address, the DUT can forward the entire stream using exactly one NC entry. NDP is exercised minimally, and no packet loss should be observed.

ベースラインテストでは、トラフィックストリームにはちょうど1つのフローが含まれます。ストリーム内のすべてのパケットが同じIPv6宛先アドレスを持つため、DUTはちょうど1つのNCエントリーを使用してストリーム全体を転送できます。NDPの動作は最小限であり、パケット損失は観測されないはずです。

The NDP Scaling Test is identical to the Baseline Test, except that the traffic stream contains many flows. In order to forward the stream without loss, the DUT must maintain one NC entry for each flow. If the DUT cannot maintain one NC entry for each flow, packet loss will be observed and attributed to NDP scaling limitations.

NDPスケーリングテストは、トラフィックストリームに多数のフローが含まれることを除いて、ベースラインテストと同一です。ストリームを損失なく転送するには、DUTはフローごとに1つのNCエントリーを維持しなければなりません。DUTがフローごとに1つのNCエントリーを維持できない場合、パケット損失が観測され、それはNDPのスケーリングの限界に起因するものとみなされます。

This document proposes an NDP scaling metric, called NDP-MAX-NEIGHBORS. NDP-MAX-NEIGHBORS is the maximum number of neighbors to which an IPv6 node can send traffic during periods of high NDP activity.

この文書は、NDP-MAX-NEIGHBORSと呼ぶNDPのスケーリングのメトリックを提案します。NDP-MAX-NEIGHBORSは、NDPの活動が活発な期間中に、IPv6ノードがトラフィックを送信できる近隣の最大数です。

The procedures described herein reveal how many IPv6 neighbors an NDP implementation can discover. They also provide a rough estimate of the time required to discover those neighbors. However, that estimate does not reflect the maximum rate at which the implementation can discover neighbors. Maximum rate discovery is a topic for further exploration.

ここで説明する手順は、NDP実装が何個のIPv6近隣を発見できるかを明らかにします。また、それらの近隣を発見するのに必要な時間の大まかな見積もりも得られます。ただし、その見積もりは、実装が近隣を発見できる最大レートを反映するものではありません。最大レートの発見は、今後の検討課題です。

The test procedures described herein assume that NDP does not compete with other applications for resources on the DUT. When NDP competes for resources, its scaling characteristics may differ from those reported by the benchmarks described and may vary over time.

ここで説明するテスト手順は、DUT上のリソースをめぐってNDPがほかのアプリケーションと競合しないことを前提としています。NDPがリソースをめぐって競合する場合、そのスケーリング特性は、ここで説明するベンチマークによって報告されるものとは異なる可能性があり、時間とともに変化する可能性もあります。

2. Test Setup

2. テストのセットアップ

The DUT is an IPv6 router. Two links (A and B) connect the DUT to the Tester. Link A capabilities must be identical to Link B capabilities. For example, if the interface to Link A is a 10 Gigabit Ethernet port, the interface to Link B must also be a 10 Gigabit Ethernet port.

DUTはIPv6ルーターです。2つのリンク（AとB）がDUTをテスターに接続します。リンクAの能力は、リンクBの能力と同一でなければなりません。たとえば、リンクAへのインターフェイスが10ギガビットイーサネットのポートであれば、リンクBへのインターフェイスも10ギガビットイーサネットのポートでなければなりません。

2.1. Device Under Test (DUT)

2.1. 被試験デバイス（DUT）

2.1.1. Interfaces

2.1.1. インターフェイス

DUT interfaces are numbered as follows:

DUTのインターフェイスには、次のようにアドレスを割り当てます。

  • Link A - 2001:2:0:0::2/64
  • Link B - 2001:2:0:1::1/64
  • リンクA - 2001:2:0:0::2/64
  • リンクB - 2001:2:0:1::1/64

Both DUT interfaces should be configured with a 1500-byte MTU. However, if they cannot support a 1500-byte MTU, they may be configured with a 1280-byte MTU.

DUTのインターフェイスはどちらも、1500バイトのMTUで設定すべきです。ただし、1500バイトのMTUをサポートできない場合は、1280バイトのMTUで設定してもかまいません。

2.1.2. Neighbor Discovery Protocol (NDP)

2.1.2. 近隣探索プロトコル（NDP）

NDP is enabled on both DUT interfaces. Therefore, the DUT emits both solicited and unsolicited Router Advertisement (RA) messages. The DUT emits an RA message at least once every 600 seconds and no more frequently than once every 200 seconds.

NDPはDUTの両方のインターフェイスで有効になっています。したがって、DUTは要請されたルーター広告（Router Advertisement、RA）メッセージと要請されていないRAメッセージの両方を送出します。DUTは、少なくとも600秒に1回、かつ200秒に1回を超えない頻度でRAメッセージを送出します。

When the DUT sends an RA message, it includes the following information:

DUTはRAメッセージを送信するとき、次の情報を含めます。

  • Router Lifetime - 1800 seconds
  • Reachable Time - 0 seconds
  • Retrans Time - 0 seconds
  • Source Link-Layer Address - link-layer address of DUT interface
  • M-bit is clear (0)
  • O-bit is clear (0)
  • Router Lifetime - 1800秒
  • Reachable Time - 0秒
  • Retrans Time - 0秒
  • Source Link-Layer Address - DUTのインターフェイスのリンク層アドレス
  • Mビットはクリア（0）
  • Oビットはクリア（0）

The above-mentioned values are chosen because they are the default values specified in RFC 4861.

上記の値は、RFC 4861で規定されたデフォルト値であるため選択しています。

NDP manages the NC. Each NC entry represents an on-link neighbor and is identified by the neighbor's on-link unicast IP address. As per RFC 4861, each NC entry needs to be refreshed periodically. NDP refreshes NC entries by exchanging Neighbor Solicitation (NS) and Neighbor Advertisement (NA) messages.

NDPはNCを管理します。各NCエントリーはオンリンクの近隣を表し、その近隣のオンリンクのユニキャストIPアドレスによって識別されます。RFC 4861に従い、各NCエントリーは定期的にリフレッシュする必要があります。NDPは、近隣要請（Neighbor Solicitation、NS）メッセージと近隣広告（Neighbor Advertisement、NA）メッセージを交換することによって、NCエントリーをリフレッシュします。

No static NC entries are configured on the DUT.

DUTには静的なNCエントリーを設定しません。

2.1.3. Routing

2.1.3. ルーティング

The DUT maintains a direct route to 2001:2:0:0/64 through Link A. It also maintains a direct route to 2001:2:0:1/64 through Link B. No static routes or dynamic routing protocols are configured on the DUT.

DUTは、リンクAを経由する2001:2:0:0/64への直接経路を維持します。また、リンクBを経由する2001:2:0:1/64への直接経路も維持します。DUTには、静的経路も動的ルーティングプロトコルも設定しません。

2.2. Tester

2.2. テスター

2.2.1. Interfaces

2.2.1. インターフェイス

Interfaces are numbered as follows:

インターフェイスには、次のようにアドレスを割り当てます。

  • Link A - 2001:2:0:0::1/64
  • Link B - Multiple addresses are configured on Link B. These addresses are drawn sequentially from the 2001:2:0:1::/64 address block. The first address is 2001:2:0:1::2/64. Subsequent addresses are 2001:2:0:1::3/64, 2001:2:0:1::4/64, 2001:2:0:1::5/64, etc. The number of configured addresses should be the expected value of NDP-MAX-NEIGHBORS times 1.1.
  • リンクA - 2001:2:0:0::1/64
  • リンクB - リンクBには複数のアドレスを設定します。これらのアドレスは、2001:2:0:1::/64アドレスブロックから順番に割り当てます。最初のアドレスは2001:2:0:1::2/64です。後続のアドレスは、2001:2:0:1::3/64、2001:2:0:1::4/64、2001:2:0:1::5/64などです。設定するアドレスの数は、NDP-MAX-NEIGHBORSの予想値の1.1倍にすべきです。

Both Tester interfaces should be configured with a 1500-byte MTU. However, if they cannot support a 1500-byte MTU, they may be configured with a 1280-byte MTU.

テスターのインターフェイスはどちらも、1500バイトのMTUで設定すべきです。ただし、1500バイトのMTUをサポートできない場合は、1280バイトのMTUで設定してもかまいません。

2.2.2. Neighbor Discovery Protocol (NDP)

2.2.2. 近隣探索プロトコル（NDP）

NDP is enabled on both Tester interfaces. Therefore, upon initiation, the Tester sends Router Solicitation (RS) messages and waits for Router Advertisement (RA) messages. The Tester also exchanges Neighbor Solicitation (NS) and Neighbor Advertisement (NA) messages with the DUT.

NDPはテスターの両方のインターフェイスで有効になっています。したがって、テスターは起動時にルーター要請（Router Solicitation、RS）メッセージを送信し、ルーター広告（RA）メッセージを待ちます。テスターはまた、DUTと近隣要請（NS）メッセージおよび近隣広告（NA）メッセージを交換します。

No static NC entries are configured on the Tester.

テスターには静的なNCエントリーを設定しません。

2.2.3. Routing

2.2.3. ルーティング

The Tester maintains a direct route to 2001:2:0:0/64 through Link A. It also maintains a direct route to 2001:2:0:1/64 through Link B. No static routes or dynamic routing protocols are configured on the Tester.

テスターは、リンクAを経由する2001:2:0:0/64への直接経路を維持します。また、リンクBを経由する2001:2:0:1/64への直接経路も維持します。テスターには、静的経路も動的ルーティングプロトコルも設定しません。

2.2.4. Test Traffic

2.2.4. テストトラフィック

The Tester sends a stream of test traffic through Link A to the DUT. The test traffic stream contains one or more interleaved flows. Flows are numbered 1 through N, sequentially.

テスターは、リンクAを通じてDUTにテストトラフィックのストリームを送信します。テストトラフィックのストリームには、交互に配置された1つ以上のフローが含まれます。フローには1からNまで順番に番号を付けます。

Within each flow, each packet contains an IPv6 header, and each IPv6 header contains the following information:

各フロー内の各パケットにはIPv6ヘッダーが含まれ、各IPv6ヘッダーには次の情報が含まれます。

  • Version - 6
  • Traffic Class - 0
  • Flow Label - 0
  • Payload Length - 0
  • Next Header - IPv6-NoNxt (59)
  • Hop Limit - 255
  • Source Address - 2001:2:0:0::1
  • Destination Address - The first 64 bits of the Destination Address are 2001:2:0:1::. The next 64 are uniquely associated with the flow. Every packet in the first flow carries the Destination Address 2001:2:0:1::2. Every subsequent flow has an IP address one greater than the last (i.e., 2001:2:0:1::3, 2001:2:0:1::4, etc.).
  • Version - 6
  • Traffic Class - 0
  • Flow Label - 0
  • Payload Length - 0
  • Next Header - IPv6-NoNxt（59）
  • Hop Limit - 255
  • Source Address - 2001:2:0:0::1
  • Destination Address - 宛先アドレスの最初の64ビットは2001:2:0:1::です。続く64ビットは、そのフローに一意に対応付けられます。最初のフローのすべてのパケットは、宛先アドレス2001:2:0:1::2を運びます。後続の各フローは、直前のフローより1大きいIPアドレスを持ちます（つまり、2001:2:0:1::3、2001:2:0:1::4など）。

In order to avoid link congestion, test traffic is offered at a rate not to exceed 50% of available link bandwidth. In order to avoid burstiness and buffer occupancy, every packet in the stream is exactly 40 bytes long (i.e., the length of an IPv6 header with no IPv6 payload). Furthermore, the gap between packets is identical.

リンクの輻輳を避けるため、テストトラフィックは利用可能なリンク帯域幅の50%を超えないレートで送出します。バースト性とバッファー占有を避けるため、ストリーム内のすべてのパケットはちょうど40バイトの長さ（つまり、IPv6ペイロードのないIPv6ヘッダーの長さ）にします。さらに、パケット間の間隔は同一にします。

During the course of a test, the number of flows that the test stream contains may increase. When this occurs, the rate at which test traffic is offered remains constant. For example, assume that a test stream is offered at a rate of 1,000 packets per second. This stream contains two flows, each contributing 500 packets per second to the 1,000 packet per second aggregate. When a third stream is added to the flow, all three streams must contribute 333 packets per second in order to maintain the 1,000 packet per second limit. (As in this example, rounding error is acceptable.)

テストの過程で、テストストリームに含まれるフローの数が増えることがあります。この場合でも、テストトラフィックを送出するレートは一定のままです。たとえば、テストストリームを毎秒1,000パケットのレートで送出すると仮定します。このストリームには2つのフローが含まれ、それぞれが合計毎秒1,000パケットのうち毎秒500パケットを占めます。3つ目のストリームがフローに追加されると、毎秒1,000パケットの上限を維持するために、3つのストリームのすべてがそれぞれ毎秒333パケットを占めなければなりません。（この例のように、丸め誤差は許容されます。）

The DUT attempts to forward every packet in the test stream through Link B to the Tester. It does this because:

DUTは、テストストリーム内のすべてのパケットを、リンクBを通じてテスターに転送しようとします。DUTがこのようにするのは、次の理由によります。

  • Every packet in the test stream has a Destination Address drawn from the 2001:2:0:1::/64 address block.
  • The DUT has a direct route to 2001:2:0:1/64 through Link B.
  • テストストリーム内のすべてのパケットは、2001:2:0:1::/64アドレスブロックから割り当てられた宛先アドレスを持ちます。
  • DUTは、リンクBを経由する2001:2:0:1/64への直接経路を持ちます。

2.2.5. Counters

2.2.5. カウンター

On the Tester, two counters are configured for each flow. One counter, configured on Link A, increments when the Tester sends a packet belonging to the flow. The other counter, configured on Link B, increments when the Tester receives a packet from the flow. In order for a packet to be associated with a flow, the following conditions must all be true:

テスターでは、フローごとに2つのカウンターを設定します。一方のカウンターはリンクAで設定し、テスターがそのフローに属するパケットを送信したときに増加します。もう一方のカウンターはリンクBで設定し、テスターがそのフローのパケットを受信したときに増加します。パケットがフローに対応付けられるためには、次の条件がすべて真でなければなりません。

  • The IPv6 Destination Address must be that of the flow.
  • The IPv6 Next Header must be IPv6-NoNxt (59).
  • IPv6の宛先アドレスが、そのフローの宛先アドレスでなければなりません。
  • IPv6のNext HeaderがIPv6-NoNxt（59）でなければなりません。

The following counters also are configured on both Tester Interfaces:

テスターの両方のインターフェイスには、次のカウンターも設定します。

  • RS packets sent
  • RA packets received
  • NS packets sent
  • NS packets received
  • NA packets sent
  • NA packets received
  • Total packets sent
  • Total packets received
  • 送信したRSパケット
  • 受信したRAパケット
  • 送信したNSパケット
  • 受信したNSパケット
  • 送信したNAパケット
  • 受信したNAパケット
  • 送信したパケットの総数
  • 受信したパケットの総数

3. Tests

3. テスト

3.1. Baseline Test

3.1. ベースラインテスト

The purpose of the Baseline Test is to ensure that the DUT can forward every packet in the test stream, without loss, when NDP is minimally exercised and not operating near its scaling limit.

ベースラインテストの目的は、NDPの動作が最小限で、スケーリングの限界付近で動作していないときに、DUTがテストストリーム内のすべてのパケットを損失なく転送できることを確かめることです。

3.1.1. Procedure

3.1.1. 手順

  • On the DUT, clear the NC.
  • On the Tester, clear all counters.
  • On the Tester, set a timer to expire in 60 seconds.
  • On the Tester, start the test stream with exactly one flow (i.e., IPv6 Destination Address equals 2001:2:0:1::2).
  • Wait for either the timer to expire or the packets-received counter associated with the flow to increment.
  • If the timer expires, stop the test stream and end the test.
  • If the packets-received counter increments, pause the traffic stream, log the initial counter values, clear the counters, reset the timer to expire in 1800 seconds, and restart the traffic stream.
  • When the timer expires, stop the test stream, wait sufficient time for any queued packets to exit, log the final counter values, and end the test.
  • DUTで、NCをクリアします。
  • テスターで、すべてのカウンターをクリアします。
  • テスターで、60秒後に満了するタイマーを設定します。
  • テスターで、ちょうど1つのフロー（つまり、IPv6宛先アドレスが2001:2:0:1::2）でテストストリームを開始します。
  • タイマーが満了するか、フローに対応付けられたpackets-receivedカウンターが増加するのを待ちます。
  • タイマーが満了した場合は、テストストリームを停止し、テストを終了します。
  • packets-receivedカウンターが増加した場合は、トラフィックストリームを一時停止し、カウンターの初期値を記録し、カウンターをクリアし、タイマーを1800秒後に満了するようにリセットし、トラフィックストリームを再開します。
  • タイマーが満了したら、テストストリームを停止し、キューに入っているパケットが出ていくのに十分な時間待ってから、カウンターの最終値を記録し、テストを終了します。

3.1.2. Baseline Test Procedure Flow Chart

3.1.2. ベースラインテストの手順のフローチャート

3.1.3. Results

3.1.3. 結果

The log contains initial and final values for the following counters:

ログには、次のカウンターの初期値と最終値が含まれます。

  • packets-sent
  • packets-received
  • packets-sent
  • packets-received

The initial values of packets-sent and packets-received may be equal to one another. If these values are identical, none of the initial packets belonging to the flow were lost. However, if the initial value of packets-sent is greater than the initial value of packets-received, initial packets were lost. This loss of initial packets is acceptable.

packets-sentとpackets-receivedの初期値は互いに等しいことがあります。これらの値が同一であれば、そのフローに属する最初のパケットはどれも失われていません。しかし、packets-sentの初期値がpackets-receivedの初期値より大きい場合は、最初のパケットが失われています。この最初のパケットの損失は許容されます。

The final values of packets-sent and packets-received should be equal to one another. If they are not, an error has occurred. Because this error is likely to affect Scaling Test results, the error must be corrected before the Scaling Test is executed.

packets-sentとpackets-receivedの最終値は、互いに等しくなるはずです。等しくない場合は、エラーが発生しています。このエラーはスケーリングテストの結果に影響を与える可能性が高いため、スケーリングテストを実行する前にエラーを修正しなければなりません。

3.2. Scaling Test

3.2. スケーリングテスト

The purpose of the Scaling Test is to discover the number of neighbors to which an IPv6 node can send traffic during periods of high NDP activity. We call this number NDP-MAX-NEIGHBORS.

スケーリングテストの目的は、NDPの活動が活発な期間中に、IPv6ノードがトラフィックを送信できる近隣の数を発見することです。この数をNDP-MAX-NEIGHBORSと呼びます。

3.2.1. Procedure

3.2.1. 手順

Execute the following procedure:

次の手順を実行します。

  • On the DUT, clear the NC.
  • On the Tester, clear all counters.
  • On the Tester, set a timer to expire in 60 seconds.
  • On the Tester, start the test stream with exactly one flow (i.e., IPv6 Destination Address equals 2001:2:0:1::2).
  • Wait for either the timer to expire or the packets-received counter associated with the flow to increment.
  • If the timer expires, stop the test stream and end the test.

  • If the packets-received counter increments, execute the following procedure N times, starting at 2 and ending at the expected value of NDP-MAX-NEIGHBORS times 1.1.

    • Pause the test stream.
    • Log the time and the value of N minus one.
    • Clear the packets-sent and packets-received counters associated with the previous flow (i.e., N minus one).
    • Reset the timer to expire in 60 seconds.
    • Add the next flow to the test stream (i.e., IPv6 Destination Address is a function of N).
    • Restart the test stream.
    • Wait for either the timer to expire or the packets-received counter associated with the new flow to increment.
  • DUTで、NCをクリアします。
  • テスターで、すべてのカウンターをクリアします。
  • テスターで、60秒後に満了するタイマーを設定します。
  • テスターで、ちょうど1つのフロー（つまり、IPv6宛先アドレスが2001:2:0:1::2）でテストストリームを開始します。
  • タイマーが満了するか、フローに対応付けられたpackets-receivedカウンターが増加するのを待ちます。
  • タイマーが満了した場合は、テストストリームを停止し、テストを終了します。

  • packets-receivedカウンターが増加した場合は、Nを2から始めてNDP-MAX-NEIGHBORSの予想値の1.1倍で終わるまで、次の手順をN回実行します。

    • テストストリームを一時停止します。
    • 時刻とN-1の値を記録します。
    • 直前のフロー（つまり、N-1）に対応付けられたpackets-sentカウンターとpackets-receivedカウンターをクリアします。
    • タイマーを60秒後に満了するようにリセットします。
    • 次のフローをテストストリームに追加します（つまり、IPv6宛先アドレスはNの関数です）。
    • テストストリームを再開します。
    • タイマーが満了するか、新しいフローに対応付けられたpackets-receivedカウンターが増加するのを待ちます。

After the procedure described above has been executed N times, clear the timer and reset it to expire in 1800 seconds. When the timer expires, stop the stream, log all counters, and end the test (after waiting sufficient time for any queued packets to exit).

上記の手順をN回実行したら、タイマーをクリアし、1800秒後に満了するようにリセットします。タイマーが満了したら、ストリームを停止し、すべてのカウンターを記録し、（キューに入っているパケットが出ていくのに十分な時間待ってから）テストを終了します。

3.2.2. Scaling Test Procedure Flow Chart

3.2.2. スケーリングテストの手順のフローチャート

3.2.3. Results

3.2.3. 結果

The test report includes the following:

テストの報告には、次のものを含めます。

  • A description of the DUT (make, model, processor, memory, and interfaces)
  • Rate at which the Tester offers test traffic to the DUT (measured in packets per second)
  • A log that records the time at which each flow was introduced to the test stream and the final value of all counters
  • The expected value of NDP-MAX-NEIGHBORS
  • The actual value of NDP-MAX-NEIGHBORS
  • DUTの説明（メーカー、モデル、プロセッサー、メモリー、インターフェイス）
  • テスターがDUTにテストトラフィックを送出するレート（毎秒のパケット数で測定）
  • 各フローがテストストリームに導入された時刻と、すべてのカウンターの最終値を記録したログ
  • NDP-MAX-NEIGHBORSの予想値
  • NDP-MAX-NEIGHBORSの実際の値

NDP-MAX-NEIGHBORS is equal to the number of counter pairs where packets-sent is equal to packets-received. Two counters are members of a pair if they are both associated with the same flow. If packets-sent is equal to packets-received for every counter pair, the test should be repeated with a larger expected value of NDP-MAX-NEIGHBORS.

NDP-MAX-NEIGHBORSは、packets-sentがpackets-receivedと等しいカウンターのペアの数に等しくなります。2つのカウンターは、どちらも同じフローに対応付けられている場合にペアの構成要素となります。すべてのカウンターのペアでpackets-sentがpackets-receivedと等しい場合は、NDP-MAX-NEIGHBORSの予想値をより大きくしてテストを繰り返すべきです。

If an implementation abides by the recommendation of Section 7.1 of RFC 6583, for any given counter pair, packets-received will either be equal to zero or packets-sent.

実装がRFC 6583のセクション7.1の推奨に従っている場合、どのカウンターのペアでも、packets-receivedは0かpackets-sentのどちらかに等しくなります。

The log documents the time at which each flow was introduced to the test stream. This log reveals the effect of NC size to the time required to discover a new IPv6 neighbor.

ログには、各フローがテストストリームに導入された時刻が記録されます。このログから、新しいIPv6近隣の発見に必要な時間に対してNCのサイズが与える影響がわかります。

4. Measurements Explicitly Excluded

4. 明示的に除外する測定

These measurements aren't recommended because of the itemized reasons below:

これらの測定は、以下に項目別に示す理由により推奨しません。

4.1. DUT CPU Utilization

4.1. DUTのCPU使用率

This measurement relies on the DUT to provide utilization information, which is not externally observable (not black-box). However, some testing organizations may find the CPU utilization is useful auxiliary information specific to the DUT model, etc.

この測定は、DUTが使用率の情報を提供することに依存しますが、その情報は外部から観測できません（ブラックボックスではありません）。ただし、テストを行う組織によっては、CPU使用率がDUTのモデルなどに固有の有用な補助情報であると考えるかもしれません。

4.2. Malformed Packets

4.2. 不正な形式のパケット

This benchmarking test is not intended to test DUT behavior in the presence of malformed packets.

このベンチマークテストは、不正な形式のパケットが存在する場合のDUTの振る舞いをテストすることを意図していません。

6. Security Considerations

6. セキュリティーに関する考慮事項

Benchmarking activities as described in this memo are limited to technology characterization using controlled stimuli in a laboratory environment, with dedicated address space and the constraints specified in the sections above.

このメモで説明するベンチマーク活動は、専用のアドレス空間と上記のセクションで規定した制約のもと、実験室環境で制御された刺激を用いて行う技術の特性評価に限定されます。

The benchmarking network topology will be an independent test setup and MUST NOT be connected to devices that may forward the test traffic into a production network or misroute traffic to the test management network.

ベンチマークのネットワークトポロジーは独立したテスト環境であり、テストトラフィックを本番ネットワークに転送したり、トラフィックをテスト管理ネットワークに誤ってルーティングしたりする可能性のあるデバイスに接続してはなりません（MUST NOT）。

Further, benchmarking is performed on a "black-box" basis, relying solely on measurements observable external to the DUT or System Under Test (SUT). Special capabilities SHOULD NOT exist in the DUT/SUT specifically for benchmarking purposes.

さらに、ベンチマークは「ブラックボックス」ベースで実施され、DUTまたは被試験システム（System Under Test、SUT）の外部から観測可能な測定のみに依存します。ベンチマークの目的に特化した特別な機能がDUT/SUTに存在すべきではありません（SHOULD NOT）。

Any implications for network security arising from the DUT/SUT SHOULD be identical in the lab and in production networks.

DUT/SUTに起因するネットワークセキュリティーへの影響は、実験室でも本番ネットワークでも同一であるべきです（SHOULD）。
