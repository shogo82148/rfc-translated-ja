RFC 1469

IP Multicast over Token-Ring Local Area Networks

RFC 1469

トークンリングLAN上のIPマルチキャスト

Abstract

概要

This document specifies a method for the transmission of IP multicast datagrams over Token-Ring Local Area Networks. Although an interim solution has emerged and is currently being used, it is the intention of this document to specify a more efficient means of transmission using an assigned Token-Ring functional address.

この文書は、トークンリング（Token-Ring）LAN上でIPマルチキャストデータグラムを伝送する方法を規定します。暫定的な解決策が登場し、現在使用されていますが、この文書は、割り当てられたトークンリングの機能アドレス（functional address）を使用する、より効率的な伝送手段を規定することを意図しています。

Introduction

はじめに

IP multicasting provides a means of transmitting IP datagrams to a group of hosts. A group IP address is used as the destination address in the IP datagram as documented in STD 5, RFC 1112 [1]. These group addresses, also referred to as Class D addresses, fall in the range from 224.0.0.0 to 239.255.255.255. A standard method of mapping IP multicast addresses to media types such as ethernet and fddi exist in [1] and RFC 1188 [2]. This document attempts to define the mapping for an IP multicast address to the corresponding Token-Ring MAC address.

IPマルチキャストは、ホストのグループにIPデータグラムを送信する手段を提供します。STD 5、RFC 1112[1]に記載されているように、グループIPアドレスはIPデータグラムの宛先アドレスとして使用されます。これらのグループアドレスはクラスDアドレスとも呼ばれ、224.0.0.0から239.255.255.255の範囲にあります。IPマルチキャストアドレスをイーサネットやFDDIなどのメディアタイプにマッピングする標準的な方法は、[1]とRFC 1188[2]にあります。この文書は、IPマルチキャストアドレスから、対応するトークンリングのMACアドレスへのマッピングを定義しようとするものです。

Background

背景

The Token-Ring Network Architecture Reference [3] provides several types of addressing mechanisms. These include both individual (unicast) and group addresses (multicast). A special subtype of group addresses are called functional addresses and are indicated by a bit in the destination MAC address. They were designed for widely used functions such as ring monitoring, NETBIOS, Bridge, and Lan Manager frames. There are a limited number of functional addresses, 31 in all, and therefore several unrelated functions must share the same functional address.

Token-Ring Network Architecture Reference[3]は、いくつかの種類のアドレス指定の仕組みを提供しています。これには、個別アドレス（ユニキャスト）とグループアドレス（マルチキャスト）の両方が含まれます。グループアドレスの特別なサブタイプは機能アドレスと呼ばれ、宛先MACアドレス内のビットによって示されます。機能アドレスは、リングの監視、NETBIOS、ブリッジ、LAN Managerのフレームなど、広く使用される機能のために設計されました。機能アドレスの数は限られており、全部で31個しかありません。そのため、互いに無関係な複数の機能が同じ機能アドレスを共有しなければなりません。

It would be most desirable if Token-Ring could use the same mapping as ethernet and fddi for IP multicast to hardware multicast addressing. However, current implementations of Token-Ring controller chips cannot support this. To see why, we must first examine the Destination MAC address format.

IPマルチキャストからハードウェアマルチキャストへのアドレス指定について、トークンリングがイーサネットやFDDIと同じマッピングを使用できれば最も望ましいでしょう。しかし、トークンリングのコントローラーチップの現在の実装では、これをサポートできません。その理由を理解するために、まず宛先MACアドレスの形式を調べなければなりません。

Destination Address Format

宛先アドレスの形式

The destination MAC address consists of six octets. In the following diagram of a MAC address, the order of transmission of the octets is from top to bottom (octet 0 to octet 5), and the order of transmission of the bits within each octet is from right to left (bit 0 to bit 7). This is the so-called "canonical" bit order for IEEE 802.2 addresses. Addresses supplied to or received from token ring interfaces are usually laid out in memory with the bits of each octet in the opposite order from that illustrated, i.e., with bit 0 in the high-order (leftmost) position within the octet.

宛先MACアドレスは6オクテットで構成されます。以下のMACアドレスの図では、オクテットの送信順序は上から下（オクテット0からオクテット5）であり、各オクテット内のビットの送信順序は右から左（ビット0からビット7）です。これは、IEEE 802.2アドレスのいわゆる「正規（canonical）」ビット順序です。トークンリングのインターフェイスに渡されるアドレスや、トークンリングのインターフェイスから受信されるアドレスは、通常、各オクテットのビットが図とは逆の順序で、すなわちビット0がオクテット内の上位（最も左）の位置に来るようにメモリー上に配置されます。

       |   |   |   |   |   |   |   |   |       octet 3

The low order bit of the high order octet is called the I/G bit. It signifies whether the address is an individual address (0) or a group address (1). This is comparable to the multicast bit in the DIX Ethernet addressing format.

上位オクテットの下位ビットはI/Gビットと呼ばれます。このビットは、そのアドレスが個別アドレス（0）であるかグループアドレス（1）であるかを示します。これは、DIXイーサネットのアドレス形式におけるマルチキャストビットに相当します。

Bit position 1 of the high order octet, called the U/L bit, specifies whether the address is universally administered (0) or locally administered (1). Universally administered addresses are those specified by a standards organization such as the IEEE.

上位オクテットのビット位置1はU/Lビットと呼ばれ、そのアドレスがユニバーサルに管理されている（0）か、ローカルに管理されている（1）かを示します。ユニバーサルに管理されたアドレスとは、IEEEなどの標準化団体によって指定されるアドレスです。

If the I/G bit is set to 1 and the U/L bit is 0, the address must be a universally administered group address. If the I/G bit is 1 and the U/L bit is a 1, the address may be either a local administered group address or a functional address. This distinction is determined by the Functional Address Indicator (FAI) bit located in bit position 0 of octet 2. If the FAI bit is 0, the address is considered a functional address. And if the FAI bit is 1, this indicates a locally administered group address.

I/Gビットが1に設定され、U/Lビットが0の場合、そのアドレスはユニバーサルに管理されたグループアドレスでなければなりません。I/Gビットが1で、U/Lビットが1の場合、そのアドレスはローカルに管理されたグループアドレスか機能アドレスのいずれかです。この区別は、オクテット2のビット位置0にある機能アドレス指示子（FAI：Functional Address Indicator）ビットによって決まります。FAIビットが0の場合、そのアドレスは機能アドレスとみなされます。そしてFAIビットが1の場合は、ローカルに管理されたグループアドレスであることを示します。

Different functional addresses are made by setting one of the remaining 31 bits in the address field. These bits include the 7 remaining bits in octet 2 as well as the 8 bits in octets 3, 4, and 5. It is not possible to create more functional addresses by setting more than one of these bits at a time.

異なる機能アドレスは、アドレスフィールドの残りの31ビットのうち1つを設定することで作られます。これらのビットには、オクテット2の残りの7ビットと、オクテット3、4、5の8ビットずつが含まれます。これらのビットを同時に2つ以上設定して、さらに多くの機能アドレスを作ることはできません。

Three methods exist for mapping between an IP multicast address and a hardware address. These include:

IPマルチキャストアドレスとハードウェアアドレスの間のマッピングには、3つの方法があります。それは次のとおりです。

  1. The all rings broadcast address
  2. The assigned functional address
  3. The existing IEEE assigned IP Multicast group addresses
  1. 全リングブロードキャストアドレス
  2. 割り当てられた機能アドレス
  3. IEEEが割り当てた既存のIPマルチキャストグループアドレス

In order to insure interoperability, all systems supporting IP multicasting on each physical ring must agree on the hardware address to be used. Therefore, the method used should be configurable on a given interface. Bridges may provide a means to translate between different methods for each physical ring that is being bridged. Method (3) is recommended but due to hardware limitations of Token-Ring controller chips, may not be possible. In this case, Method (2) is preferred over Method (1). For backward compatibility, systems that support (2) MUST also support (1). And systems that support (3) MUST also support (2) and therefore (1). In the absence of configuration information, the default should be to use the assigned functional address (2).

相互運用性を確保するために、各物理リング上でIPマルチキャストをサポートするすべてのシステムは、使用するハードウェアアドレスについて合意しなければなりません。したがって、使用する方法は、インターフェイスごとに設定可能であるべきです。ブリッジは、ブリッジされる物理リングごとに、異なる方法の間で変換する手段を提供してもかまいません。方法（3）が推奨されますが、トークンリングのコントローラーチップのハードウェアの制限により、実現できない場合があります。その場合は、方法（1）よりも方法（2）が優先されます。後方互換性のために、（2）をサポートするシステムは（1）もサポートしなければなりません（MUST）。また、（3）をサポートするシステムは（2）、したがって（1）もサポートしなければなりません（MUST）。設定情報がない場合、デフォルトでは割り当てられた機能アドレス（2）を使用すべきです。

IP Multicast Functional Address

IPマルチキャストの機能アドレス

Because there is a shortage of Token-Ring functional addresses, all IP multicast addresses have been mapped to a single Token-Ring functional address. In canonical form, this address is 03-00-00-20-00-00. In non-canonical form, it is C0-00-00-04-00-00. It should be noted that since there are only 31 possible functional addresses, there may be other protocols that are assigned this functional address as well. Therefore, just because a frame is sent to the functional address 03-00-00-20-00-00 does not mean that it is an IP multicast frame.

トークンリングの機能アドレスは不足しているので、すべてのIPマルチキャストアドレスは単一のトークンリングの機能アドレスにマッピングされています。このアドレスは、正規形式では03-00-00-20-00-00です。非正規形式では、C0-00-00-04-00-00です。機能アドレスは31個しかありえないので、他のプロトコルにもこの機能アドレスが割り当てられている可能性があることに注意すべきです。したがって、フレームが機能アドレス03-00-00-20-00-00に送信されたからといって、それがIPマルチキャストのフレームであるとは限りません。
