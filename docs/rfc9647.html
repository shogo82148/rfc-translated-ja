1. Introduction

1. はじめに

This document defines a data model for the [RFC8966]. The data model is defined using [RFC7950] and is compatible with [RFC8342]. It is based on the [RFC9046]. The data model only includes data nodes that are useful for managing Babel over IPv6.

この文書は、[RFC8966]のためのデータモデルを定義します。データモデルは[RFC7950]を使用して定義されており、[RFC8342]と互換性があります。このデータモデルは[RFC9046]に基づいています。データモデルには、IPv6上のBabelを管理するのに役立つデータノードだけが含まれています。

1.1. Requirements Language

1.1. 要件言語

The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 [RFC2119] [RFC8174] when, and only when, they appear in all capitals, as shown here.

キーワード「しなければなりません（MUST）」、「してはなりません（MUST NOT）」、 「要求されています（REQUIRED）」、 「することになります（SHALL）」、「することはありません（SHALL NOT）」、 「すべきです（SHOULD）」、「すべきではありません（SHOULD NOT）」、 「推奨されます（RECOMMENDED）」、「推奨されません（NOT RECOMMENDED）」、 「してもよいです（MAY）」、「選択できます（OPTIONAL）」は、 BCP 14 [RFC2119] [RFC8174]に記載されているとおりに解釈されるものとします。 ただし、ここに示すようにすべて大文字で表示される場合に限ります。

2. Babel Module

2. Babelモジュール

This document defines a [RFC7950] data model for the configuration and management of Babel. The YANG module is based on the [RFC9046].

この文書は、Babelの設定と管理のための[RFC7950]データモデルを定義します。このYANGモジュールは[RFC9046]に基づいています。

2.1. Information Model

2.1. 情報モデル

It's worth noting a few differences between the Babel information model and this data module. The information model mandates the definition of some of the attributes, e.g., "babel-implementation-version" or the "babel-self-router-id". These attributes are marked as read-only objects in the information module as well as in this data module. However, there is no way in the data module to mandate that a read-only attribute be present. It is up to the implementation of this data module to make sure that the attributes that are marked "read only" and are mandatory are indeed present.

Babel情報モデルとこのデータモジュールとの間のいくつかの違いについて述べておく価値があります。情報モデルは、たとえば "babel-implementation-version" や "babel-self-router-id" のように、いくつかの属性の定義を必須としています。これらの属性は、情報モジュールでもこのデータモジュールでも読み取り専用のオブジェクトとしてマークされています。しかし、データモジュールでは、読み取り専用の属性が存在することを 必須にする方法がありません。"read only" とマークされていて必須である属性が実際に存在することを確実にするのは、このデータモジュールの実装の責任です。

The "interfaces" subtree describes attributes such as the "interface" object that is being referenced; the type of link, e.g., wired, wireless, or tunnel, as enumerated by "metric-algorithm" and "split-horizon"; and whether the interface is enabled or not.

"interfaces" サブツリーは、参照される "interface" オブジェクト、"metric-algorithm" と "split-horizon" によって列挙されるリンクの種類（たとえば、有線、無線、トンネル）、インターフェースが有効かどうか、などの属性を記述します。

The "constants" subtree describes the UDP port used for sending and receiving Babel messages and the multicast group used to send and receive announcements on IPv6.

"constants" サブツリーは、Babelメッセージの送受信に使用するUDPポートと、IPv6上でアナウンスメントを送受信するために使用するマルチキャストグループを記述します。

The "routes" subtree describes objects such as the prefix for which the route is advertised, a reference to the neighboring route, and the "next-hop" address.

"routes" サブツリーは、経路が広告されるプレフィックス、隣接する経路への参照、"next-hop" アドレスなどのオブジェクトを記述します。

Finally, for security, two subtrees are defined to contain Message Authentication Code (MAC) keys and DTLS certificates. The "mac-key-set" subtree contains keys used with the MAC security mechanism. The boolean flag "default-apply" indicates whether the set of MAC keys is automatically applied to new interfaces. The "dtls" subtree contains certificates used with the DTLS security mechanism. Similar to the MAC mechanism, the boolean flag "default-apply" indicates whether the set of DTLS certificates is automatically applied to new interfaces.

最後に、セキュリティーのために、メッセージ認証コード（MAC）鍵とDTLS証明書を格納する2つのサブツリーが定義されています。"mac-key-set" サブツリーには、MACセキュリティーメカニズムで使用する鍵が含まれます。真偽値フラグ "default-apply" は、MAC鍵のセットを新しいインターフェースに自動的に適用するかどうかを示します。"dtls" サブツリーには、DTLSセキュリティーメカニズムで使用する証明書が含まれます。MAC メカニズムと同様に、真偽値フラグ "default-apply" は、DTLS証明書のセットを新しいインターフェースに自動的に適用するかどうかを示します。

2.3. YANG Module

2.3. YANGモジュール

This YANG module augments the YANG routing management module [RFC8349] to provide a common framework for all routing subsystems. By augmenting the module, it provides a common building block for routes and Routing Information Bases (RIBs). It also has a reference to an interface defined by "A YANG Data Model for Interface Management" [RFC8343].

このYANGモジュールは、YANGルーティング管理モジュール[RFC8349]を拡張（augment）して、すべてのルーティングサブシステムに共通のフレームワークを提供します。このモジュールを拡張することで、経路とルーティング情報ベース（RIB）のための 共通の構成要素を提供します。また、「A YANG Data Model for Interface Management」[RFC8343]で定義されているインターフェースへの参照も持っています。

A router running the Babel routing protocol can sometimes determine the parameters it needs to use for an interface based on the interface name. For example, it can detect that eth0 is a wired interface and that wlan0 is a wireless interface. This is not true for a tunnel interface, where the link parameters need to be configured explicitly.

Babelルーティングプロトコルを実行しているルーターは、インターフェース名に基づいて、そのインターフェースで使用する必要があるパラメーターを判断できる場合があります。たとえば、eth0は有線インターフェースであり、 wlan0は無線インターフェースであることを検出できます。トンネルインターフェースではこれは当てはまらず、リンクパラメーターを明示的に設定する必要があります。

For a wired interface, it will assume "two-out-of-three" is set for "metric-algorithm" and "split-horizon" is set to true. On the other hand, for a wireless interface, it will assume "etx" is set for "metric-algorithm" and "split-horizon" is set to false. However, if the wired link is connected to a wireless radio, the values can be overridden by setting "metric-algorithm" to "etx" and "split-horizon" to false. Similarly, an interface that is a metered 3G link and is used for fallback connectivity needs much higher default time constants, e.g., "mcast-hello-interval" and "update-interval", in order to avoid carrying control traffic as much as possible.

有線インターフェースの場合、ルーターは "metric-algorithm" に "two-out-of-three" が設定され、"split-horizon" がtrueに設定されているとみなします。一方、無線インターフェースの場合、 "metric-algorithm" に "etx" が設定され、"split-horizon" がfalseに設定されているとみなします。しかし、有線リンクが無線機に接続されている場合は、"metric-algorithm" を "etx" に、 "split-horizon" をfalseに設定することで、値を上書きできます。同様に、従量課金制の3Gリンクで、フォールバック接続に使用されるインターフェースでは、制御トラフィックをできるだけ運ばないようにするために、"mcast-hello-interval" や "update-interval" などのデフォルトの時間定数をずっと大きくする必要があります。

In addition to the modules used above, this module imports definitions from "Common YANG Data Types" [RFC6991] and references "HMAC: Keyed-Hashing for Message Authentication" [RFC2104], "Using HMAC-SHA-256, HMAC-SHA-384, and HMAC-SHA-512 with IPsec" [RFC4868], "Textual Encodings of PKIX, PKCS, and CMS Structures" [RFC7468], "The BLAKE2 Cryptographic Hash and Message Authentication Code (MAC)" [RFC7693], "Network Configuration Access Control Model" [RFC8341], "The Babel Routing Protocol" [RFC8966], "MAC Authentication for the Babel Routing Protocol" [RFC8967], "Babel Information Model" [RFC9046], "The Datagram Transport Layer Security (DTLS) Protocol Version 1.3" [RFC9147], and "YANG Data Types and Groupings for Cryptography" [RFC9640].

上記で使用したモジュールに加えて、このモジュールは「Common YANG Data Types」[RFC6991]から 定義をインポートし、「HMAC: Keyed-Hashing for Message Authentication」[RFC2104]、「Using HMAC-SHA-256, HMAC-SHA-384, and HMAC-SHA-512 with IPsec」[RFC4868]、「Textual Encodings of PKIX, PKCS, and CMS Structures」[RFC7468]、「The BLAKE2 Cryptographic Hash and Message Authentication Code (MAC)」[RFC7693]、「Network Configuration Access Control Model」[RFC8341]、「The Babel Routing Protocol」[RFC8966]、 「MAC Authentication for the Babel Routing Protocol」[RFC8967]、「Babel Information Model」[RFC9046]、「The Datagram Transport Layer Security (DTLS) Protocol Version 1.3」[RFC9147]、「YANG Data Types and Groupings for Cryptography」[RFC9640]を参照しています。

4. Security Considerations

4. セキュリティーに関する考慮事項

This section is modeled after the template defined in Section 3.7.1 of [RFC8407].

このセクションは、[RFC8407]のSection 3.7.1で定義されているテンプレートに倣っています。

The "ietf-babel" YANG module defines a data model that is designed to be accessed via YANG-based management protocols, such as NETCONF [RFC6241] and RESTCONF [RFC8040]. These protocols have mandatory-to-implement secure transport layers (e.g., Secure Shell (SSH) [RFC4252], TLS [RFC8446], and QUIC [RFC9000]) and mandatory-to-implement mutual authentication.

"ietf-babel" YANGモジュールは、NETCONF [RFC6241]やRESTCONF [RFC8040]などのYANGベースの管理プロトコルを介してアクセスされるように設計されたデータモデルを定義します。これらの プロトコルには、実装必須の安全なトランスポート層（たとえば、Secure Shell（SSH）[RFC4252]、TLS [RFC8446]、QUIC [RFC9000]）と、実装必須の相互認証があります。

The [RFC8341] provides the means to restrict access for particular NETCONF users to a preconfigured subset of all available NETCONF protocol operations and content.

[RFC8341]は、特定のNETCONFユーザーのアクセスを、利用可能なすべてのNETCONF プロトコル操作とコンテンツのうち、あらかじめ設定されたサブセットに制限する手段を提供します。

The security considerations outlined here are specific to the YANG data model and do not cover security considerations of the Babel protocol or its security mechanisms in "The Babel Routing Protocol" [RFC8966], "MAC Authentication for the Babel Routing Protocol" [RFC8967], and "Babel Routing Protocol over Datagram Transport Layer Security" [RFC8968]. Each of these has its own Security Considerations section for considerations that are specific to it.

ここで概説するセキュリティーに関する考慮事項は、YANGデータモデルに固有のものであり、「The Babel Routing Protocol」[RFC8966]、「MAC Authentication for the Babel Routing Protocol」[RFC8967]、「Babel Routing Protocol over Datagram Transport Layer Security」[RFC8968]にあるBabelプロトコルやそのセキュリティーメカニズムのセキュリティーに関する考慮事項は扱いません。これらの文書には、それぞれに固有の考慮事項を扱うセキュリティーに関する考慮事項のセクションがあります。

There are a number of data nodes defined in the YANG module that are writable/created/deleted (i.e., config true, which is the default). These data nodes may be considered sensitive or vulnerable in some network environments. These are the subtrees and data nodes and their sensitivity/vulnerability from a config true perspective:

このYANGモジュールで定義されているデータノードのうち、書き込み・作成・削除が可能な（つまり、デフォルトであるconfig trueの）ものが多数あります。これらのデータノードは、一部のネットワーク環境では機密性が高い、 または脆弱であるとみなされる場合があります。適切な保護なしにこれらのデータノードへの書き込み操作（たとえば、<edit-config>）を行うと、ネットワーク運用に悪影響を及ぼす可能性があります。 config trueの観点から見た サブツリーとデータノード、およびそれらの機密性・脆弱性は次のとおりです。

'babel':
This container includes an 'enable' parameter that can be used to enable or disable use of Babel on a router.
'babel/constants':
This container includes configuration parameters that can prevent reachability if misconfigured.
'babel/interfaces':
This leaf-list has configuration parameters that can enable/disable security mechanisms and change performance characteristics of the Babel protocol. For example, enabling logging of packets and giving unintended access to the log files gives an attacker detailed knowledge of the network and allows it to launch an attack on the traffic traversing the network device.
'babel/hmac' and 'babel/dtls':
These contain security credentials that influence whether incoming packets are trusted and whether outgoing packets are produced in such a way that the receiver will treat them as trusted.
'babel':
このコンテナーには、ルーターでのBabelの使用を有効または無効にするために使用できる 'enable' パラメーターが含まれています。
'babel/constants':
このコンテナーには、誤って設定すると到達性を妨げる可能性がある設定パラメーターが含まれています。
'babel/interfaces':
このleaf-listには、セキュリティーメカニズムを有効または無効にしたり、Babelプロトコルの性能特性を変更したりできる設定パラメーターがあります。たとえば、パケットのログ記録を有効にし、意図せずログファイルへのアクセスを許すと、攻撃者はネットワークに関する詳細な知識を得て、ネットワークデバイスを通過するトラフィックに対する攻撃を仕掛けられるようになります。

Some of the RPC operations in this YANG module may be considered sensitive or vulnerable in some network environments. It is thus important to control access to these operations. These are the operations and their sensitivity/vulnerability from an RPC operation perspective:

このYANGモジュールのRPC操作の一部は、一部のネットワーク環境では機密性が高い、または脆弱であるとみなされる場合があります。したがって、これらの操作へのアクセスを制御することが重要です。RPC操作の観点から見た 操作とそれらの機密性・脆弱性は次のとおりです。

This model defines two actions. Resetting the statistics within an interface container would be visible to any monitoring processes, which should be designed to account for the possibility of such a reset. The "test" action allows for validation that a MAC key and MAC algorithm have been properly configured. The MAC key is a sensitive piece of information, and it is important to prevent an attacker that does not know the MAC key from being able to determine the MAC value by trying different input parameters. The "test" action has been designed to not reveal such information directly. Such information might also be revealed indirectly due to side channels such as the time it takes to produce a response to the action. Implementations SHOULD use a constant-time comparison between the input MAC and the locally generated MAC value for comparison in order to avoid such side channel leakage.

このモデルは2つのアクションを定義します。インターフェースコンテナー内の統計をリセットすると、すべての監視プロセスから見えるようになるため、監視プロセスはそのようなリセットの可能性を考慮するように設計すべきです。"test" アクションは、MAC鍵とMACアルゴリズムが適切に設定されていることを検証できるようにします。 MAC鍵は機密性の高い情報であり、MAC鍵を知らない攻撃者が、さまざまな入力パラメーターを試すことによってMAC値を割り出せないようにすることが重要です。"test" アクションは、そのような情報を直接明らかにしないように設計されています。そのような情報は、アクションに対するレスポンスを生成するのにかかる時間などのサイドチャネルによって間接的に明らかになる可能性もあります。実装は、そのようなサイドチャネルによる漏洩を避けるために、入力されたMACとローカルで生成したMAC値の比較に定数時間比較を使用すべきです（SHOULD）。

A.2. Statistics Gathering Enabled

A.2. 統計収集の有効化

In this example, interface eth0 is being configured for routing protocol Babel, and statistics gathering is enabled. For security, HMAC-SHA256 is supported. Every sent Babel packet is signed with the key value provided, and every received Babel packet is verified with the same key value.

この例では、インターフェースeth0がルーティングプロトコルBabel用に設定されており、統計収集が有効になっています。セキュリティーのために、HMAC-SHA256がサポートされています。送信されるすべてのBabelパケットは 指定された鍵の値で署名され、受信されるすべてのBabelパケットは同じ鍵の値で検証されます。

A.5. Configuring Other Properties

A.5. その他のプロパティーの設定

In this example, two interfaces are configured for babeld:

この例では、babeld用に2つのインターフェースが設定されています。

  • interface eth0
  • interface ppp0 hello-interval 30 update-interval 120
  • interface eth0
  • interface ppp0 hello-interval 30 update-interval 120

Here, ppp0 is a metered 3G link used for fallback connectivity. It runs with much higher than default time constants in order to avoid control traffic as much as possible.
