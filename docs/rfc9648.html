YANG Data Model for TCP

RFC 9648

TCPのためのYANGデータモデル

Abstract

概要

This document specifies a minimal YANG data model for TCP on devices that are configured and managed by network management protocols. The YANG data model defines a container for all TCP connections and groupings of authentication parameters that can be imported and used in TCP implementations or by other models that need to configure TCP parameters. The model also includes basic TCP statistics. The model is compliant with Network Management Datastore Architecture (NMDA) (RFC 8342).

この文書は、ネットワーク管理プロトコルによって設定および管理されるデバイス上のTCPのための、最小限のYANGデータモデルを規定します。 このYANGデータモデルは、すべてのTCPコネクションのためのコンテナーと、TCP実装やTCPパラメーターを設定する必要がある他のモデルがインポートして使用できる認証パラメーターのグルーピングを定義します。 このモデルには、基本的なTCP統計も含まれます。 このモデルは、ネットワーク管理データストアアーキテクチャー（NMDA）（RFC 8342）に準拠しています。

1. Introduction

1. はじめに

The Transmission Control Protocol (TCP) [RFC9293] is used by many applications in the Internet, including control and management protocols. As such, TCP is implemented on network elements that can be configured and managed via network management protocols such as Network Configuration Protocol (NETCONF) [RFC6241] or RESTCONF [RFC8040].

Transmission Control Protocol（TCP）[RFC9293]は、制御プロトコルや管理プロトコルを含め、インターネット上の多くのアプリケーションで使用されています。 そのため、TCPは、Network Configuration Protocol（NETCONF）[RFC6241]やRESTCONF [RFC8040]などのネットワーク管理プロトコルを介して設定および管理できるネットワーク要素に実装されています。

This document specifies a minimal YANG 1.1 [RFC7950] data model for configuring and managing TCP on network elements that support YANG, a TCP connection table, a TCP listener table containing information about a particular TCP listener, and an augmentation of the YANG data model for key chains [RFC8177] to support authentication. The YANG module specified in this document is compliant with Network Management Datastore Architecture (NMDA) [RFC8342].

この文書は、YANGをサポートするネットワーク要素上でTCPを設定および管理するための最小限のYANG 1.1 [RFC7950]データモデル、TCPコネクションテーブル、特定のTCPリスナーに関する情報を含むTCPリスナーテーブル、および認証をサポートするための鍵チェーン用YANGデータモデル[RFC8177]の拡張（augmentation）を規定します。 この文書で規定するYANGモジュールは、ネットワーク管理データストアアーキテクチャー（NMDA）[RFC8342]に準拠しています。

The YANG module has a narrow scope and focuses on a subset of fundamental TCP functions and basic statistics. It defines a container for a list of TCP connections that includes definitions from "YANG Groupings for TCP Clients and TCP Servers" [RFC9643]. The model adheres to the recommendation in "BGP/MPLS IP Virtual Private Networks (VPNs)" [RFC4364]. Therefore, it allows enabling of TCP Authentication Option (TCP-AO) [RFC5925] and accommodates the installed base that makes use of MD5. The module can be augmented or updated to address more advanced or implementation-specific TCP features in the future.

このYANGモジュールの範囲は狭く、TCPの基本的な機能の一部と基本的な統計に焦点を当てています。 このモジュールは、「YANG Groupings for TCP Clients and TCP Servers」[RFC9643]の定義を含む、TCPコネクションのリストのためのコンテナーを定義します。 このモデルは、「BGP/MPLS IP Virtual Private Networks (VPNs)」[RFC4364]の推奨事項に従っています。 したがって、このモデルはTCP認証オプション（TCP-AO）[RFC5925]の有効化を可能にし、MD5を使用している既存の導入環境にも対応します。 このモジュールは、将来、より高度なTCP機能や実装固有のTCP機能に対応するために、拡張または更新できます。

This specification does not deprecate the Management Information Base (MIB) for the Transmission Control Protocol (TCP) [RFC4022]. The basic statistics defined in this document follow the model of the TCP MIB. A TCP extended statistics MIB [RFC4898] is also available, but this document does not cover such extended statistics. The YANG module also omits some selected parameters included in TCP MIB, most notably Retransmission Timeout (RTO) configuration and a maximum connection limit. This is a conscious decision as these parameters hardly matter in a state-of-the-art TCP implementation. It would also be possible to translate a MIB into a YANG module, for instance, using "Translation of Structure of Management Information Version 2 (SMIv2) MIB Modules to YANG Modules" [RFC6643]. However, this approach is not used in this document, because a translated model would not be up-to-date.

この仕様は、Transmission Control Protocol（TCP）のための管理情報ベース（MIB）[RFC4022]を非推奨にするものではありません。 この文書で定義する基本的な統計は、TCP MIBのモデルに従っています。 TCP拡張統計MIB [RFC4898]も利用できますが、この文書ではそのような拡張統計は扱いません。 また、このYANGモジュールでは、TCP MIBに含まれる一部のパラメーター、特に再送タイムアウト（RTO）の設定と最大コネクション数の制限を省略しています。 これらのパラメーターは最新のTCP実装ではほとんど意味を持たないため、これは意図的な判断です。 また、たとえば「Translation of Structure of Management Information Version 2 (SMIv2) MIB Modules to YANG Modules」[RFC6643]を使用して、MIBをYANGモジュールに変換することも可能です。 しかし、変換したモデルは最新の状態にならないため、この文書ではこの方法を使用しません。

There are other existing TCP-related YANG data models, which are orthogonal to this specification. Examples are:

TCPに関連する既存のYANGデータモデルはほかにもありますが、それらはこの仕様とは直交しています。 例を次に示します：

  • TCP header attributes are modeled in other security-related models, such as those described in "YANG Data Model for Network Access Control Lists (ACLs)" [RFC8519], "Distributed Denial-of-Service Open Threat Signaling (DOTS) Data Channel Specification" [RFC8783], "I2NSF Capability YANG Data Model" [NSF-CAP-YANG], or "I2NSF Network Security Function-Facing Interface YANG Data Model" [NSF-FACING-YANG].
  • TCP-related configuration of a NAT (e.g., NAT44, NAT64, or Destination NAT) is defined in "A YANG Module for Network Address Translation (NAT) and Network Prefix Translation (NPT)" [RFC8512] and "A YANG Data Model for Dual-Stack Lite (DS-Lite)" [RFC8513].
  • TCP-AO and TCP MD5 configuration for Layer 3 VPNs is modeled in "A YANG Network Data Model for Layer 3 VPNs" [RFC9182]. This model assumes that TCP-AO-specific parameters are preconfigured in addition to the key chain parameters.
  • TCPヘッダーの属性は、「YANG Data Model for Network Access Control Lists (ACLs)」[RFC8519]、「Distributed Denial-of-Service Open Threat Signaling (DOTS) Data Channel Specification」[RFC8783]、「I2NSF Capability YANG Data Model」[NSF-CAP-YANG]、「I2NSF Network Security Function-Facing Interface YANG Data Model」[NSF-FACING-YANG]で説明されているものなど、セキュリティーに関連する他のモデルでモデル化されています。
  • NAT（たとえば、NAT44、NAT64、宛先NAT）のTCP関連の設定は、「A YANG Module for Network Address Translation (NAT) and Network Prefix Translation (NPT)」[RFC8512]と「A YANG Data Model for Dual-Stack Lite (DS-Lite)」[RFC8513]で定義されています。
  • レイヤー3 VPNのためのTCP-AOとTCP MD5の設定は、「A YANG Network Data Model for Layer 3 VPNs」[RFC9182]でモデル化されています。 このモデルは、鍵チェーンのパラメーターに加えて、TCP-AO固有のパラメーターが事前に設定されていることを前提としています。

3. YANG Module Overview

3. YANGモジュールの概要

3.1. Scope

3.1. 範囲

TCP is implemented on different system architectures. As a result, there are many different and often implementation-specific ways to configure parameters of the TCP engine. In addition, in many TCP/IP stacks, configuration exists for different scopes:

TCPはさまざまなシステムアーキテクチャー上に実装されています。 その結果、TCPエンジンのパラメーターを設定する方法は多種多様で、多くの場合、実装固有のものになっています。 さらに、多くのTCP/IPスタックでは、さまざまなスコープの設定が存在します：

  • System-wide configuration: Many TCP implementations have configuration parameters that affect all TCP connections from or to this TCP stack. Typical examples include enabling or disabling optional protocol features. For instance, many implementations can turn on or off use of window scaling (defined in "Transmission Control Protocol (TCP)" [RFC9293]) for all TCP connections.
  • Interface configuration: It can be useful to use different TCP parameters on different interfaces, e.g., different device ports or IP interfaces. In that case, TCP parameters can be part of the interface configuration. Typical examples are the Maximum Segment Size (MSS) or configuration related to hardware offloading.
  • Connection parameters: Many implementations have means to influence the behavior of each TCP connection, e.g., on the programming interface used by applications. Typical examples are socket options in the socket API, such as disabling the Nagle algorithm (as described in "Transmission Control Protocol (TCP)" [RFC9293]) by TCP_NODELAY. If an application uses such an interface, it is possible that the configuration of the application or application protocol includes TCP-related parameters. An example is the BGP YANG module for service provider networks [BGP-MODEL].
  • Application preferences: Setting of TCP parameters can also be part of application preferences, templates, or profiles. An example would be the preferences defined in "An Abstract Application Layer Interface to Transport Services" [TAPS-INTERFACE].
  • システム全体の設定：多くのTCP実装には、このTCPスタックから発信される、またはこのTCPスタックに着信するすべてのTCPコネクションに影響を与える設定パラメーターがあります。 典型的な例には、オプションのプロトコル機能の有効化や無効化があります。 たとえば、多くの実装では、すべてのTCPコネクションに対して、（「Transmission Control Protocol (TCP)」[RFC9293]で定義されている）ウィンドウスケーリングの使用をオンまたはオフにできます。
  • インターフェイスの設定：インターフェイスごと（たとえば、デバイスのポートごとやIPインターフェイスごと）に異なるTCPパラメーターを使用すると便利な場合があります。 その場合、TCPパラメーターはインターフェイスの設定の一部にすることができます。 典型的な例は、最大セグメントサイズ（MSS）や、ハードウェアオフロードに関連する設定です。
  • コネクションパラメーター：多くの実装には、たとえばアプリケーションが使用するプログラミングインターフェイス上で、各TCPコネクションの動作に影響を与える手段があります。 典型的な例は、ソケットAPIのソケットオプションで、たとえばTCP_NODELAYによって（「Transmission Control Protocol (TCP)」[RFC9293]で説明されている）Nagleアルゴリズムを無効にするものがあります。 アプリケーションがそのようなインターフェイスを使用する場合、アプリケーションやアプリケーションプロトコルの設定にTCP関連のパラメーターが含まれる可能性があります。 その例として、サービスプロバイダーネットワークのためのBGP YANGモジュール[BGP-MODEL]があります。
  • アプリケーションの設定項目：TCPパラメーターの設定は、アプリケーションの設定項目、テンプレート、またはプロファイルの一部にすることもできます。 その例として、「An Abstract Application Layer Interface to Transport Services」[TAPS-INTERFACE]で定義されている設定項目（preferences）があります。

As a result, there is no ground truth for setting certain TCP parameters, and generally different TCP implementations have used different modeling approaches. For instance, one implementation may define a given configuration parameter globally, while another one uses per-interface settings, and both approaches work well for the corresponding use cases. Also, different systems may use different default values. In addition, TCP can be implemented in different ways and design choices by the protocol engine often affect configuration options.

その結果、特定のTCPパラメーターの設定について決まった正解はなく、一般に、TCP実装ごとに異なるモデル化の手法が使われてきました。 たとえば、ある実装ではある設定パラメーターをグローバルに定義し、別の実装ではインターフェイスごとの設定を使用しており、どちらの手法も対応するユースケースではうまく機能します。 また、システムによって異なるデフォルト値を使用する場合もあります。 さらに、TCPはさまざまな方法で実装でき、プロトコルエンジンにおける設計上の選択が設定オプションに影響することもよくあります。

Nonetheless, a number of TCP stack parameters require configuration by YANG data models. This document therefore defines a minimal YANG data model with fundamental parameters. An important use case is the TCP configuration on network elements, such as routers, which often use YANG data models. The model therefore specifies TCP parameters that are important on such TCP stacks.

それでもなお、TCPスタックのパラメーターのいくつかは、YANGデータモデルによる設定を必要とします。 したがって、この文書では、基本的なパラメーターを含む最小限のYANGデータモデルを定義します。 重要なユースケースは、ルーターなど、YANGデータモデルを使用することが多いネットワーク要素上のTCP設定です。 したがって、このモデルでは、そのようなTCPスタックで重要なTCPパラメーターを規定します。

In particular, this applies to the support of the TCP Authentication Option (TCP-AO) [RFC5925] and the corresponding cryptographic algorithms [RFC5926]. TCP-AO is used on routers to secure routing protocols such as BGP. In that case, a YANG data model for TCP-AO configuration is required. The model defined in this document includes the required parameters for TCP-AO configuration, such as the values of SendID and RecvID. The key chain for TCP-AO can be modeled by the YANG data model for key chains [RFC8177]. The groupings defined in this document can be imported and used as part of such a preconfiguration.

これは特に、TCP認証オプション（TCP-AO）[RFC5925]と、対応する暗号アルゴリズム[RFC5926]のサポートに当てはまります。 TCP-AOは、BGPなどのルーティングプロトコルを保護するためにルーター上で使用されます。 その場合、TCP-AOの設定のためのYANGデータモデルが必要になります。 この文書で定義するモデルには、SendIDやRecvIDの値など、TCP-AOの設定に必要なパラメーターが含まれています。 TCP-AOの鍵チェーンは、鍵チェーン用のYANGデータモデル[RFC8177]でモデル化できます。 この文書で定義するグルーピングは、そのような事前設定の一部としてインポートして使用できます。

Given an installed base, the model also allows enabling of the legacy TCP MD5 [RFC2385] signature option. The TCP MD5 signature option was obsoleted by TCP-AO in 2010. If current implementations require TCP authentication, it is RECOMMENDED to use TCP-AO [RFC5925].

既存の導入環境を考慮して、このモデルでは、レガシーなTCP MD5 [RFC2385]署名オプションの有効化も可能にしています。 TCP MD5署名オプションは、2010年にTCP-AOによって廃止されました。 現在の実装でTCP認証が必要な場合は、TCP-AO [RFC5925]を使用することが推奨されます（RECOMMENDED）。

Similar to the TCP MIB [RFC4022], this document also specifies basic statistics, a TCP connection list, and a TCP listener list.

TCP MIB [RFC4022]と同様に、この文書でも、基本的な統計、TCPコネクションリスト、TCPリスナーリストを規定します。

  • Statistics: Counters for the number of active/passive opens, sent and received TCP segments, errors, and possibly other detailed debugging information.
  • TCP connection list: Access to status information for all TCP connections. Note that the connection table is modeled as a list that is readable and writable, even though a connection cannot be created by adding entries to the table. Similarly, deletion of connections from this list is implementation-specific.
  • TCP listener list: A list containing information about TCP listeners, i.e., applications willing to accept connections.
  • 統計：アクティブオープンとパッシブオープンの数、送信および受信したTCPセグメントの数、エラーの数のカウンター、および場合によっては他の詳細なデバッグ情報。
  • TCPコネクションリスト：すべてのTCPコネクションのステータス情報へのアクセス。 テーブルにエントリーを追加してもコネクションを作成することはできませんが、コネクションテーブルは読み書き可能なリストとしてモデル化されていることに注意してください。 同様に、このリストからのコネクションの削除は実装固有です。
  • TCPリスナーリスト：TCPリスナー、すなわちコネクションを受け入れる意思のあるアプリケーションに関する情報を含むリスト。

This allows implementations of TCP MIB [RFC4022] to migrate to the YANG data model defined in this memo. Note that the TCP MIB does not include means to reset statistics, which are defined in this document. This is not a major addition, as a reset can simply be implemented by storing offset values for the counters.

これにより、TCP MIB [RFC4022]の実装は、このメモで定義するYANGデータモデルに移行できます。 TCP MIBには統計をリセットする手段が含まれていませんが、この文書ではそれを定義していることに注意してください。 リセットはカウンターのオフセット値を保存するだけで簡単に実装できるため、これは大きな追加ではありません。

This version of the module does not model details of Multipath TCP [RFC8684]. This could be addressed in a later version of this document.

このバージョンのモジュールでは、マルチパスTCP [RFC8684]の詳細はモデル化していません。 これは、この文書の今後のバージョンで対応される可能性があります。

3.2. Model Design

3.2. モデルの設計

The YANG data model defined in this document includes definitions from "YANG Groupings for TCP Clients and TCP Servers" [RFC9643]. Similar to that model, this specification defines YANG groupings. This allows reuse of these groupings in different YANG data models. It is intended that these groupings will be used either standalone or for TCP-based protocols as part of a stack of protocol-specific configuration models. An example could be the one described in "YANG Model for Border Gateway Protocol (BGP-4)" [BGP-MODEL].

6. Security Considerations

6. セキュリティーに関する考慮事項

This section is modeled after the template defined in Section 3.7.1 of [RFC8407].

このセクションは、[RFC8407]のSection 3.7.1で定義されているテンプレートに基づいています。

The "ietf-tcp" YANG module defines a schema for data that is designed to be accessed via YANG-based management protocols, such as NETCONF [RFC6241] and RESTCONF [RFC8040]. These protocols have mandatory-to-implement secure transport layers (e.g., Secure Shell (SSH) [RFC4252], TLS [RFC8446], and QUIC [RFC9000]) and mandatory-to-implement mutual authentication.

「ietf-tcp」YANGモジュールは、NETCONF [RFC6241]やRESTCONF [RFC8040]などのYANGベースの管理プロトコルを介してアクセスされるように設計されたデータのスキーマを定義します。 これらのプロトコルには、実装必須のセキュアなトランスポート層（たとえば、Secure Shell（SSH）[RFC4252]、TLS [RFC8446]、QUIC [RFC9000]）と、実装必須の相互認証があります。

The Network Configuration Access Control Model (NACM) [RFC8341] provides the means to restrict access for particular NETCONF or RESTCONF users to a preconfigured subset of all available NETCONF or RESTCONF protocol operations and content.

ネットワーク設定アクセス制御モデル（NACM）[RFC8341]は、特定のNETCONFユーザーまたはRESTCONFユーザーのアクセスを、利用可能なすべてのNETCONFまたはRESTCONFのプロトコル操作とコンテンツのうち、事前に設定されたサブセットに制限する手段を提供します。

There are a number of data nodes defined in this YANG module that are writable/creatable/deletable (i.e., "config true", which is the default). These data nodes may be considered sensitive or vulnerable in some network environments. Write operations (e.g., edit-config) to these data nodes without proper protection can have a negative effect on network operations. These are the subtrees and data nodes and their sensitivity/vulnerability:

このYANGモジュールでは、書き込み可能、作成可能、削除可能な（つまり、デフォルトである「config true」の）データノードが多数定義されています。 これらのデータノードは、一部のネットワーク環境では機密性が高い、または脆弱であるとみなされる場合があります。 適切な保護なしにこれらのデータノードに対して書き込み操作（たとえば、edit-config）を行うと、ネットワークの運用に悪影響を及ぼす可能性があります。 サブツリーとデータノード、およびその機密性・脆弱性は次のとおりです：

  • Common configuration included from NETCONF client and server models [RFC9643]. Unrestricted access to all the nodes, e.g., keepalive idle timer, can cause connections to fail or to timeout prematurely.
  • Authentication configuration. Unrestricted access to the nodes under authentication configuration can prevent the use of authenticated communication and cause connection setups to fail. This can result in massive security vulnerabilities and service disruption for the traffic requiring authentication.
  • NETCONFクライアントおよびサーバーのモデル[RFC9643]から取り込んだ共通の設定。 すべてのノード（たとえば、キープアライブのアイドルタイマー）への無制限のアクセスにより、コネクションが失敗したり、早期にタイムアウトしたりする可能性があります。
  • 認証の設定。 認証の設定配下のノードへの無制限のアクセスにより、認証された通信が使用できなくなり、コネクションの確立が失敗する可能性があります。 これにより、認証を必要とするトラフィックに対して、重大なセキュリティー脆弱性やサービスの中断が生じる可能性があります。

Some of the readable data nodes in this YANG module may be considered sensitive or vulnerable in some network environments. It is thus important to control read access (e.g., via get, get-config, or notification) to these data nodes. These are the subtrees and data nodes and their sensitivity/vulnerability:

このYANGモジュールの読み取り可能なデータノードの一部は、一部のネットワーク環境では機密性が高い、または脆弱であるとみなされる場合があります。 したがって、これらのデータノードへの読み取りアクセス（たとえば、get、get-config、または通知を介したもの）を制御することが重要です。 サブツリーとデータノード、およびその機密性・脆弱性は次のとおりです：

  • Unrestricted access to connection information of the client or server can be used by a malicious user to launch an attack.
  • Similarly, unrestricted access to statistics of the client or server can be used by a malicious user to exploit any vulnerabilities of the system.
  • クライアントまたはサーバーのコネクション情報への無制限のアクセスは、悪意のあるユーザーによって攻撃を仕掛けるために利用される可能性があります。
  • 同様に、クライアントまたはサーバーの統計への無制限のアクセスは、悪意のあるユーザーによってシステムの脆弱性を悪用するために利用される可能性があります。

Some of the RPC operations in this YANG module may be considered sensitive or vulnerable in some network environments. It is thus important to control access to these operations. These are the operations and their sensitivity/vulnerability:

このYANGモジュールのRPC操作の一部は、一部のネットワーク環境では機密性が高い、または脆弱であるとみなされる場合があります。 したがって、これらの操作へのアクセスを制御することが重要です。 操作とその機密性・脆弱性は次のとおりです：

  • The YANG module allows for the statistics to be cleared by executing the reset action. This action should be restricted to users with the right permission.
  • このYANGモジュールでは、resetアクションを実行することで統計をクリアできます。 このアクションは、適切な権限を持つユーザーに制限すべきです。

The module specified in this document supports MD5 to basically accommodate the installed BGP base. MD5 suffers from the security weaknesses discussed in Section 2 of [RFC6151] or Section 2.1 of [RFC6952].

この文書で規定するモジュールは、主に既存のBGPの導入環境に対応するためにMD5をサポートしています。 MD5には、[RFC6151]のSection 2や[RFC6952]のSection 2.1で説明されているセキュリティー上の弱点があります。
