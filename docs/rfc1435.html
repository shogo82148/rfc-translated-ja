RFC 1435

IESG Advice from Experience with Path MTU Discovery

RFC 1435

パスMTU探索の経験に基づくIESGの助言

Abstract

概要

In the course of reviewing the MTU Discovery protocol for possible elevation to Draft Standard, a specific operational problem was uncovered. The problem results from the optional suppression of ICMP messages implemented in some routers. This memo outlines a modification to this practice to allow the correct functioning of MTU Discovery.

MTU探索プロトコルをドラフト標準（Draft Standard）に昇格させる可能性について検討する中で、特定の運用上の問題が明らかになりました。この問題は、一部のルーターに実装されている、ICMPメッセージを任意で抑止する機能に起因します。このメモでは、MTU探索が正しく機能するようにするための、この運用方法の修正について概説します。

Advice on the Deployment of Path MTU Discovery Protocol

パスMTU探索プロトコルの導入に関する助言

While reviewing the Path MTU Discovery Protocol for Draft Standard [RFC1191], the Internet Engineering Steering Group (IESG) became aware from the reports of various implementors that some vendors have added to their routers the ability to disable ICMP messages generated by the router. This is to protect older BSD hosts, which would drop all connections to a host it found an ICMP message on any of the connections, even if it was a non-fatal ICMP message. While this protects older BSD hosts, it causes MTU discovery to fail in a silent, hard to diagnose way.

パスMTU探索プロトコル[RFC1191]をドラフト標準として検討していた際、Internet Engineering Steering Group（IESG）は、さまざまな実装者からの報告によって、一部のベンダーが、ルーター自身が生成するICMPメッセージを無効にする機能をルーターに追加していることを知りました。これは古いBSDホストを保護するためのものです。古いBSDホストは、あるホストとのいずれかのコネクションでICMPメッセージを受け取ると、それが致命的でないICMPメッセージであっても、そのホストとのすべてのコネクションを切断してしまいます。この機能は古いBSDホストを保護する一方で、MTU探索を、表面に現れず診断の難しい形で失敗させてしまいます。

From the descriptions the IESG has obtained, adjusting the routers to continue to send ICMP message Type 3 code 4 (destination unreachable, don't fragment (DF) bit sent and fragmentation required) even when they have their "don't send ICMP messages" switch turned on would allow path MTU discovery to work but not effect older BSD hosts, since they never set the DF bit in their packets.

IESGが得た説明によれば、「ICMPメッセージを送信しない」スイッチがオンになっている場合でも、ICMPメッセージのタイプ3コード4（宛先到達不能、フラグメント禁止（DF）ビットが設定されていてフラグメント化が必要）は引き続き送信するようにルーターを調整すれば、パスMTU探索は機能するようになり、しかも古いBSDホストには影響しません。古いBSDホストはパケットにDFビットを設定することがないからです。
