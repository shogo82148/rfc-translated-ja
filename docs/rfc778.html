RFC 778

DCNET Internet Clock Service

RFC 778

DCNETインターネット時刻サービス

Introduction

はじめに

Following is a description of the Internet Clock Service (ICS) provided by all DCNET hosts. The service, intended primarily for clock synchronization and one-way delay measurements with cooperating internet hosts, is provided using the Timestamp and Timestamp Reply messages of the proposed Internet Control Message Protocol (ICMP). In addition, in order to maintain compatability with present systems, this service will be provided for a limited time using the Echo and Echo Reply messages of the Gateway-Gateway Protocol (GGP).

以下は、すべてのDCNETホストが提供するインターネット時刻サービス（Internet Clock Service、ICS）の説明です。このサービスは、主に協力関係にあるインターネットホストとの間の時計の同期と片方向遅延の測定を目的としたもので、提案中のインターネット制御メッセージプロトコル（Internet Control Message Protocol、ICMP）のTimestampメッセージとTimestamp Replyメッセージを使って提供されます。加えて、現行のシステムとの互換性を保つため、このサービスはしばらくの間、ゲートウェイ間プロトコル（Gateway-Gateway Protocol、GGP）のEchoメッセージとEcho Replyメッセージを使っても提供されます。

It should be understood that ICMP and GGP datagrams are normally considered tightly bound to the Internet Protocol (IP) itself and not directly accessable to the user on a TOPS-20 system, for example. These datagrams are treated somewhat differently from user datagrams in gateways and DCNET hosts in that certain internal queueing mechanisms are bypassed. Thus, they can be a useful tool in providing the most accurate and stable time reference. The prime motivation for this note is to promote the development of this service in other internet hosts and gateways so that the feasibility for its use thoughout the community can be assessed.

ICMPやGGPのデータグラムは、通常、インターネットプロトコル（IP）そのものと密接に結び付いたものとみなされ、たとえばTOPS-20システムのユーザーが直接アクセスすることはできないことを理解しておいてください。これらのデータグラムは、ゲートウェイやDCNETホストの内部のキューイング機構の一部を迂回する点で、ユーザーのデータグラムとは多少異なる扱いを受けます。そのため、これらは最も正確で安定した時刻基準を提供するのに役立つ道具になりえます。このノートの主な動機は、ほかのインターネットホストやゲートウェイでのこのサービスの開発を促し、コミュニティー全体でこれを使うことの実現可能性を評価できるようにすることです。

ICS Datagrams and Timestamps

ICSデータグラムとタイムスタンプ

At present, the ICS is provided using either ICMP or GGP datagrams. The only difference between these is that ICMP uses protocol number 1 and GGP uses protocol number 3. In the following these will be referred to interchangably as ICS datagrams. ICS datagrams include an internet header followed by an ICS header in the following format:

現在、ICSはICMPデータグラムかGGPデータグラムのどちらかを使って提供されています。両者の唯一の違いは、ICMPがプロトコル番号1を、GGPがプロトコル番号3を使うことです。以下では、これらを区別せずにICSデータグラムと呼びます。ICSデータグラムは、インターネットヘッダーと、それに続く次の形式のICSヘッダーで構成されます。

The originator fills in all three timestamp fields just before the datagram is forwarded to the net. Each of these fields contain the local time at origination. Although the last two are redundant, they allow roundtrip delay measurements to be made using remote hosts without timestamping facilities. The "Type" field can be either 8 (GGP Echo) or 13 (ICMP Timestamp). The "Code" field should be zero. The "Sequence" field can contain either zero or an optional sequence number provided by the user. The length of the datagram is thus 36 octets inclusive of the 20-octet internet header and exclusive of the local-network leader.

送信元は、データグラムをネットに転送する直前に、3つのタイムスタンプフィールドをすべて埋めます。これらのフィールドにはいずれも送信時のローカル時刻が入ります。後ろの2つは冗長ですが、これによってタイムスタンプ機能を持たないリモートホストを使って往復遅延を測定できます。「Type」フィールドは8（GGP Echo）か13（ICMP Timestamp）のどちらかです。「Code」フィールドは0にすべきです。「Sequence」フィールドには、0か、ユーザーが指定する任意のシーケンス番号を入れられます。したがって、データグラムの長さは、20オクテットのインターネットヘッダーを含み、ローカルネットワークのリーダーを含まずに36オクテットになります。

The host or gateway receiving an ICS datagram fills in the "Receive Timestamp" field just as the datagram is received from the net and the "Transmit Timestamp" just as it is forwarded back to the sender. It also sets the "Type" field to 0 (GGP Echo Reply), if the original value was 8, or 14 (ICMP Timestamp Reply), if it was 13. The remaining fields are unchanged.

ICSデータグラムを受信したホストまたはゲートウェイは、ネットからデータグラムを受信した時点で「Receive Timestamp」フィールドを埋め、送信者に送り返す時点で「Transmit Timestamp」を埋めます。また、「Type」フィールドを、元の値が8であれば0（GGP Echo Reply）に、13であれば14（ICMP Timestamp Reply）に設定します。残りのフィールドは変更しません。

The timestamp values are in milliseconds from midnight UT and are stored right-justified in the 32-bit fields shown above. Ordinarily, all time calculations are performed modulo-24 hours in milliseconds. This provides a convenient match to those operating systems which maintain a system clock in ticks past midnight. The specified timestamp unit of milliseconds is consistent with the accuracy of existing radio clocks and the errors expected in the timestamping process itself.

タイムスタンプの値はUTの午前0時からのミリ秒数で、上に示した32ビットのフィールドに右詰めで格納されます。通常、時刻の計算はすべて、ミリ秒単位で24時間を法として行います。これは、午前0時からのティック数でシステムクロックを保持しているオペレーティングシステムにとって都合のよい対応になっています。タイムスタンプの単位をミリ秒と定めたのは、既存の電波時計の精度や、タイムスタンプを付ける処理自体で予想される誤差に見合うものです。

Delay Measurements

遅延の測定

Delay measurements can be made with any DCNET host by simply sending an ICS datagram in the above format to it and processing the reply. Let t1, t2 and t3 represent the three timestamp fields of the reply in order and t4 the time of arrival at the original sender. Then the delays, exclusive of internal processing within the DCNET host, are simply (t2 - t1) to the DCNET host, (t4 - t3) for the return and (t2 - t1) + (t4 - t3) for the roundtrip. Note that, in the case of the roundtrip, the clock offsets between the sending host and DCNET host cancel.

上記の形式のICSデータグラムをDCNETホストに送り、その応答を処理するだけで、どのDCNETホストとの間でも遅延を測定できます。応答の3つのタイムスタンプフィールドを順にt1、t2、t3とし、元の送信者への到着時刻をt4とします。すると、DCNETホスト内部の処理を除いた遅延は、DCNETホストへの往路が(t2 - t1)、復路が(t4 - t3)、往復が(t2 - t1) + (t4 - t3)となります。往復の場合は、送信ホストとDCNETホストの間の時計のずれが相殺されることに注意してください。

Although ICS datagrams are returned by all DCNET hosts regardless of other connections that may be in use by that host at any given time, the most useful host will probably be the COMSAT-WWV virtual host at internet address [29,0,9,2], which is also the internet echo virtual host formerly called COMSAT-ECH. This virtual host is resident in the COMSAT-GAT physical host at internet address [29,0,1,2], which is connected to the ARPANET via the COMSAT Gateway, Clarksburg SIMP and a 4800-bps line to IMP 71 at BBN. The roundtrip delay via this path between the COMSAT-GAT host and the BBN Gateway is typically 550 milliseconds as the ICS datagram flies.

ICSデータグラムは、そのホストがその時点で使用しているほかの接続にかかわらず、すべてのDCNETホストから返されますが、最も役に立つホストはおそらく、インターネットアドレス[29,0,9,2]にあるCOMSAT-WWV仮想ホストでしょう。これは、以前COMSAT-ECHと呼ばれていたインターネットエコー仮想ホストでもあります。この仮想ホストは、インターネットアドレス[29,0,1,2]にあるCOMSAT-GAT物理ホストに常駐しています。COMSAT-GATは、COMSAT Gateway、Clarksburg SIMP、BBNのIMP 71への4800bpsの回線を経由してARPANETに接続されています。この経路でのCOMSAT-GATホストとBBN Gatewayの間の往復遅延は、ICSデータグラムで測ると通常550ミリ秒です。

As in the case of all DCNET hosts, if the COMSAT-WWV virtual host is down (in this case possible only if the Spectracom radio clock is down or misbehaving) a "host not reachable" GGP datagram is returned. In unusual circumstances a "net not reachable" or "source quench" GGP datagram could be returned. Note that the references to "GGP" here will be read "ICMP" at some appropriate future time.

すべてのDCNETホストと同様に、COMSAT-WWV仮想ホストがダウンしている場合（この場合、それが起こるのはSpectracomの電波時計がダウンしているか異常動作している場合だけです）、「host not reachable」のGGPデータグラムが返されます。まれな状況では、「net not reachable」や「source quench」のGGPデータグラムが返されることもあります。ここでの「GGP」は、将来の適当な時期に「ICMP」と読み替えられることに注意してください。

Local Offset Corrections

ローカルなずれの補正

All DCNET timestamps are referenced to a designated virtual host called COMSAT-WWV (what else?) with internet address [29,0,9,2]. This host is equipped with a Spectracom radio clock which normally provides WWVB time and date to within a millisecond. The clock synchronization mechanism provides offset and drift corrections for other hosts relative to this host; however, offsets up to an appreciable fraction of a second routinely occur due to the difficulty of tracking with power-line clocks in some machines. A table of the current offsets can be obtained using the following procedure.

DCNETのタイムスタンプはすべて、インターネットアドレス[29,0,9,2]にあるCOMSAT-WWV（ほかに何と呼べましょう？）という指定の仮想ホストを基準にしています。このホストにはSpectracomの電波時計が備わっており、通常は1ミリ秒以内の精度でWWVBの時刻と日付を提供します。時計の同期機構は、ほかのホストに対して、このホストを基準としたずれとドリフトの補正を提供します。しかし、一部のマシンでは電源周波数を使うクロックでの追従が難しいため、1秒のかなりの割合に及ぶずれが日常的に生じます。現在のずれの表は、次の手順で取得できます。

  1. Connect to COMSAT-GAT host at internet address [29,0,1,2] using TELNET and local echo.
  2. Send the command SET HOST HOST. A table with one line per DCNET host should be returned. Note the entry under the "Offset" column for the WWV host. This contains the offset in milliseconds that should be added to all timestamps generated by either the COMSAT-GAT or COMSAT-WWV hosts to yield the correct time as broadcast by WWVB.

  3. Send the command SET WWV SHOW. A summary of datagram traffic is returned along with an entry labelled "NBS time." The string following this is the last reply received from the Spectracom unit in the format:

                      <code>  DDD HH:MM:SS  TZ=00

    where <code> is normally <SP> in case the WWVB signal is being received correctly or ? in case it is not. The DDD represents the day of the year and HH:MM:SS the time past UT midnight. The two digits following TZ= represent the time zone, here 00 for UT.

  4. Close the connection (please!).
  1. TELNETとローカルエコーを使って、インターネットアドレス[29,0,1,2]にあるCOMSAT-GATホストに接続します。
  2. SET HOST HOSTコマンドを送ります。DCNETホストごとに1行の表が返されるはずです。WWVホストの「Offset」列の項目に注目してください。これには、COMSAT-GATホストまたはCOMSAT-WWVホストが生成したすべてのタイムスタンプに加算すべきミリ秒単位のずれが入っており、加算するとWWVBで放送される正しい時刻が得られます。

  3. SET WWV SHOWコマンドを送ります。データグラムのトラフィックの概要が、「NBS time.」というラベルの付いた項目とともに返されます。これに続く文字列は、Spectracomの装置から受信した最後の応答で、次の形式をしています。

                      <code>  DDD HH:MM:SS  TZ=00

    ここで<code>は、通常、WWVBの信号を正しく受信している場合は<SP>、そうでない場合は?です。DDDは年内の通算日を、HH:MM:SSはUTの午前0時からの時刻を表します。TZ=に続く2桁はタイムゾーンを表し、ここではUTを表す00です。

  4. 接続を閉じます（お願いします！）。

以下は、ICSヘッダーをPDP11のコードで規定したものです。

;
; GGP/ICMP Header
;
 .       =       0
GH.TYP:  .BLKB   1               ;Message type
GC.RPY   =       0               ;Echo reply
GC.UPD   =       1               ;Routing update
GC.ACK   =       2               ;Positive acknowledgment
GC.DNR   =       3               ;Destination unreachable
GC.SQN   =       4               ;Source quench
GC.RDR   =       5               ;Redirect
GC.ECH   =       10              ;Echo
GC.STA   =       11              ;Net interface status
GC.NAK   =       12              ;Negative acknowledgment
GC.TIM   =       15              ;Timestamp
GC.TRP   =       16              ;Timestamp Reply
GH.COD:  .BLKB   1               ;Message code
GH.SEQ:  .BLKW   1               ;Sequence number
GH.HDR   =       .               ;Beginning of original
                                 ;internet header
GH.ORG:  .BLKW   2               ;Originating timestamp
GH.REC:  .BLKW   2               ;Received timestamp
GH.XMT:  .BLKW   2               ;Transmitted timestamp
GH.LEN   =       .               ;End of timestamp header

;
; GGP/ICMPヘッダー
;
 .       =       0
GH.TYP:  .BLKB   1               ;メッセージタイプ
GC.RPY   =       0               ;エコー応答
GC.UPD   =       1               ;ルーティング更新
GC.ACK   =       2               ;肯定応答
GC.DNR   =       3               ;宛先到達不能
GC.SQN   =       4               ;送信元抑制
GC.RDR   =       5               ;リダイレクト
GC.ECH   =       10              ;エコー
GC.STA   =       11              ;ネットインターフェイスの状態
GC.NAK   =       12              ;否定応答
GC.TIM   =       15              ;タイムスタンプ
GC.TRP   =       16              ;タイムスタンプ応答
GH.COD:  .BLKB   1               ;メッセージコード
GH.SEQ:  .BLKW   1               ;シーケンス番号
GH.HDR   =       .               ;元のインターネットヘッダーの
                                 ;先頭
GH.ORG:  .BLKW   2               ;送信時のタイムスタンプ
GH.REC:  .BLKW   2               ;受信時のタイムスタンプ
GH.XMT:  .BLKW   2               ;転送時のタイムスタンプ
GH.LEN   =       .               ;タイムスタンプヘッダーの終わり

Note that all PDP11 word fields (.BLKW above) are "byte-swapped," that is, the order of byte transmission is the high-order byte followed by the low-order byte of the PDP11 word.

PDP11のワードのフィールド（上記の.BLKW）はすべて「バイトスワップ」されていることに注意してください。つまり、バイトの送信順序は、PDP11のワードの上位バイトの後に下位バイトが続く順になります。
